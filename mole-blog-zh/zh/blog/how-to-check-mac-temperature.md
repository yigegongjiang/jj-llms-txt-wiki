# 如何查看 Mac 温度与风扇转速

> 用系统工具检查负载和散热状态，用兼容的传感器工具查看温度与风扇转速，再结合机型和使用情况判断是否异常。

Published: 2026-07-19 | Updated: 2026-09-24

想看 Mac 的温度，可以打开 [Mole 的状态页面](https://mole.fit/zh/mac-system-monitor)，查看当前机型支持的 CPU 温度和风扇转速。不同机型能读取的传感器不同，无风扇的 MacBook Air 也没有风扇转速可显示；活动监视器能帮你找出高负载的软件，但不显示温度。

macOS 没有内建的 CPU 温度和风扇转速面板，但会告诉你系统是否正承受散热压力、是否开始限制性能，第三方工具可以显示传感器读数，不过名称、位置和正常范围都会随机型变化。

Apple 也提醒这些读数不是机身表面温度，不能单独用来诊断硬件，脱离工作负载和变化趋势只看一个温度，很容易误判。

**遇到 `powermetrics: unrecognized sampler: smc`？** 在 Apple 芯片 Mac 上，这表示该命令没有提供 SMC 采样器，并不说明传感器损坏。要判断是否降频，可看 macOS 的散热状态；要看具名读数，则需要支持当前机型的传感器工具。

## 几种检查方式，各自能回答什么

| 方式 | 能给你 | 给不了 | 代价 |
|---|---|---|---|
| 活动监视器 | 是哪个进程在发热、能耗影响 | 任何温度、任何风扇转速 | 无，系统自带 |
| `pmset -g therm` | macOS 有没有记录到散热或性能压力 | 具体度数、传感器名称 | 无，不要管理员权限 |
| `sudo powermetrics` | 一次有限采样的功耗与散热压力细节 | Apple 芯片上稳定的 CPU 或 GPU 温度 | 要管理员密码 |
| 传感器监控工具 | 机型支持范围内的具名读数和风扇转速 | 一个能搬到别的 Mac 上的阈值 | 装第三方应用，且分机型 |
| Apple 诊断 | 来自 Apple 自己测试的硬件结论 | 实时监控 | 重启一次 |

顺序比工具更要紧，负载解释了大部分热量，压力告诉你 macOS 有没有已经在反应，而一个度数只有在你知道前两件事之后才读得懂。

## 活动监视器能看到什么

「活动监视器」位于「应用程序 > 实用工具」，打开 CPU 页并按 %CPU 排序，就能看到谁在让 Mac 发热，它还会显示内存压力和能耗影响。

这里不显示温度或风扇 RPM，它能找到热量来源，却不是温度计，如果高占用进程看不懂，可以参考[Mac 常见后台进程分别做什么](https://mole.fit/zh/blog/mac-processes-explained)。

## 先看负载和散热压力

无需管理员权限，即可查看 macOS 记录的散热状态：

```
pmset -g therm
```

没有记录到相关警告时，可能看到下面的输出；它不等于温度测量，也不能排除所有硬件层面的性能限制：

```
Note: No thermal warning level has been recorded
Note: No performance warning level has been recorded
Note: No CPU power status has been recorded
```

一旦真的记录到压力，那是系统自己的控制判断，通常比拿某个传感器与网上的通用阈值比较更有用。

需要更多功耗与散热上下文时，取一次有限采样：

```
sudo powermetrics --samplers thermal,cpu_power -n 1
```

只在需要诊断时跑它，用空载和一段可重复的负载做对照，而不是让一个特权采样器一直开着。`powermetrics` 自己标明功耗数字是估算值，所以不要拿它的绝对值去比较两台不同的 Mac。

## Apple 芯片为何读不到统一温度

在一些较老的 Intel 版本 macOS 上，`sudo powermetrics --samplers smc` 能吐出传感器读数，而在现在的 Apple 芯片机器上这个采样器已经没有了，拒绝也很干脆，不是给你一片空输出：

```
powermetrics --samplers smc
# powermetrics: unrecognized sampler: smc
```

`powermetrics` 仍然能报散热压力，但不会给出一个稳定的 CPU 或 GPU 摄氏度。Apple 芯片上没有公开且免特权的接口提供统一的传感器映射，这也是第三方工具必须逐机型适配的原因。

如果你是照着旧的 Intel 教程找过来的，别想办法把这个采样器强行弄回来。稳妥的做法就是上面那个顺序，一共三步：先用 pmset 看 macOS 记录下来的散热和性能压力，再在可重复的负载下做一次有限的散热与功耗采样，真需要具名的度数时，再用支持你这台机型的传感器应用。网上那些在这条命令的输出里 grep 隐藏芯片温度的偏方靠不住，它们依赖的正是现在系统拒绝的 SMC 采样器。不要关闭 SIP，也不要运行强行写入风扇或 SMC 的脚本，这两样都不会让 macOS 打印出它本来就不提供的温度，关闭 SIP 还白白丢掉一层真实的保护。Mole 的状态页面按 Apple 芯片的代际选用对应机型的传感器键，走的是其他监控工具也在用的非公开 SMC 和 IOHID 接口，如果你的 Mac 一个已知的键都没有提供，它就不显示温度，而不是猜一个数。

## 为什么不同工具的读数会不同

Mac 的散热管理把计算单元、存储、电池等位置附近的传感器与功耗、风扇控制放在一起，Intel 和 Apple 芯片暴露的传感器键不同，部分 MacBook Air 机型没有风扇。第三方监控用的是分机型或非公开接口，所以两个工具挂着同样的「CPU 温度」标签，读的可能是不同的传感器，而转速只在有风扇并且暴露转速计的机型上才有意义。

## 风扇转速怎么读，以及它说明不了什么

风扇转速是这份清单里最容易读反的数字，因为它的含义和直觉相反：风扇转起来是散热系统在工作，不是机器出了问题；持续满负载而风扇一声不响，那才是值得查的读数。常见的就三种情况：

- **根本没有风扇。** M1 之后的 MacBook Air 全系无风扇，靠机身导热，所以没有转速可读，负载下机身发烫是设计如此。
- **负载时升起来，之后落下去。** 这是预期形状，真正该问的是负载撤掉之后多久降下来，而不是峰值转到了多少。
- **空载却一直满转。** 这一种要处理，先查有没有跑飞的进程，再查进风口是不是被挡住，最后才怀疑传感器故障，顺序别反。

风扇曲线归固件管，保持默认是对的。手动控制可以在一段已知的持续负载里拿噪音换余量，但它修不好被挡住的风道、坏掉的传感器，也修不好一个空载时就在发热的源头。

## 怎样判断读数是否异常

没有一个适用于所有 Mac、所有传感器的「安全 CPU 温度」。要记就四件事一起记：传感器名称、当时的负载、散热压力，以及性能或风扇行为有没有变化。编译时短暂冲高很正常，空载时读数一路往上又找不到主人，才是更有价值的证据。

如果温度真的要紧，就留一份自己的基线：同一个具名传感器、同样的环境、同样的电源模式、同样的风扇状态和散热压力，分别记下空载和一段可重复负载下的数字，以后只跟这份基线比。别的机型、别的传感器名称、别的室温下得到的数字，都不是这台机器的界限。

Apple 唯一公开的数字是房间而不是芯片，它的[工作温度说明](https://support.apple.com/102336)把正常环境温度定在 10 到 35 摄氏度之间，并建议轻负载下发热时先看 CPU 活动，把机器放在通风的稳固表面上用。

## 真的发烫时，按这个顺序来

1. **先找到高占用进程。** 在活动监视器的 CPU 页按 %CPU 排序，确认是否有不需要的任务持续占用资源；保存工作后退出，再观察负载和温度是否回落。
2. **结合散热压力判断。** `pmset -g therm` 可以查看系统记录的散热或性能警告，没有记录不代表一定没有降频，还要结合负载、性能变化和其他散热指标。
3. **先排除物理原因。** 软表面、被挡住的出风口、太阳直射、超过 35 度的房间、正在充电，这些都会先把底噪抬上去，再谈软件解释。
4. **只跟自己的基线比。** 同一个传感器、同一段负载、同一个房间，另一台机型的数字不是这台机器的证据。
5. **该问硬件就问硬件。** 反复关机、轻负载就报散热警告、风扇有异响或从不转、什么都没跑还一直烫，这些是送修信号。在认定「清个缓存」或「自定义风扇曲线」能解决之前，先跑一次 Apple 诊断。

## 一套可重复的温度检查

先记下空载时的负载与散热状态，跑一段固定的工作负载，取一次有限的压力采样，再对照冷却过程。如果用传感器监控，就在同一台 Mac 上比同一个具名传感器，而不是把别的机型的阈值搬过来。趋势、限速、噪音和负载归属，都比单独一个温度数字说明更多。

## 常见问题

### Mac 多少度算太高？

没有适用于所有机型和传感器的统一上限，网上的数值要先确认机型、传感器和测量条件。`pmset -g therm` 能显示系统记录的散热警告，但没记录到警告也不能排除降频。Apple 在这里给出的 10 到 35 摄氏度指环境温度，不是芯片温度。

### 为什么我的 MacBook Air 读不到风扇转速？

M1 之后的 MacBook Air 按设计就没有风扇，靠机身散热，没有转速计可报，所以监控工具在这些机型上不显示 RPM 是对的，不是坏了。

### 查温度需要管理员密码吗？

最有用的那两步不需要。活动监视器和 `pmset -g therm` 什么都不用，只有 `powermetrics` 要 `sudo`，这也是它值得只取一次有限采样、而不是一直开着的原因。

### 为什么两个监控软件显示的 CPU 温度不一样？

可能是传感器选择不同，也可能是采样时间、平均方式不同。先确认两个工具是否在同一时间读取同一个传感器；无法确认时，用同一工具在同一台 Mac 上观察趋势更可靠。

### 风扇很响是不是坏了？

单看响不是。负载下风扇加速正是散热在正常工作；真正需要排查的是空载时持续满转、出现异响，或者有风扇的机型在发烫时从来不转。
