# 启动磁盘快满了：空间到底去哪了

> 先测量真实可用空间，检查废纸篓和用户可控的大文件；只有原本的保存、复制或更新仍失败时，才考虑系统管理的快照。

Published: 2026-08-09 | Updated: 2026-09-05

提示总在最不该来的时候弹出，正在导出视频、安装更新，或保存一份文档，macOS 就会打断过来，弹出 **启动磁盘几乎已满**。下意识会打开「下载」开始删，通常能腾出几个 GB，提示隔天又回来，什么也没搞明白。

macOS 在说的是，这个卷给交换空间、更新和临时文件留的工作余量已经不够了，那些还能回收但仍被钉住的空间，会跟真实文件一样算进占用，所以删看得见的文件，有时数字会动，有时完全不动。

**短答：** 先查清楚空间去哪了再动手删，用 `df -h /` 看可用空间，再打开 **系统设置 › 通用 › 储存空间**。删了大文件却没有腾出预期空间时，先核对它原来在哪个卷、是否仍在废纸篓，以及统计是否已刷新，不要直接归因于快照。

## 这条提示真正在说什么

macOS 会在启动卷上留一块储备，用来放虚拟内存交换空间、系统更新时的安装暂存、应用工作时写的临时文件，以及 APFS 自己的记账，可用空间掉到这块储备附近，系统就会警告。

Apple 没有公布确切的触发阈值，它会随卷的大小和当时系统在做什么而变，把这条提示当成余量信号即可，不要当成一个能反推回去的精确测量。

比数字更要紧的是两件事：

- 磁盘空间不够时，Mac 会先变慢，再真正出问题，交换空间没处写，内存压力就会上去，系统开始拼命压缩和换页。
- macOS 更新即使安装包看起来比可用空间小，也可能拒绝安装，因为它会先完整暂存一份再动手。

## 先量清楚再删

先看文件系统，别先看 Finder，因为 Finder 报的空间已经把可回收池折进去了。

```
df -h /
```

一台标称 1 TB 的 Mac 上，输出大概是这样：

```
Filesystem        Size    Used   Avail Capacity   Mounted on
/dev/disk3s1s1   926Gi    12Gi   299Gi     4%     /
```

`Used` 那一列很小，因为 `/` 是密封的系统快照，不是数据卷，`Size` 显示 926Gi，硬盘卖的是 1 TB，因为 `df` 按二进制吉字节计，Apple 按十进制 GB 计，字节并没少，同一堆字节用了两套单位。

看整个容器，改问 `diskutil`：

```
diskutil info / | grep -i "Container"
```

```
   Container Total Space:     994.6 GB (994610155520 Bytes)
   Container Free Space:      321.0 GB (321045377024 Bytes)
```

现在有了一个真实基线，把可用空间这个数字记下来，下面每一步都看这个数字动没动。

## 空间通常都在哪

个人 Mac 的启动磁盘满了，通常落在下面六类。按可确认的文件先查，不要把快照排在真实文件前面。

| 可疑项 | 怎么确认 | 去哪处理 |
|---|---|---|
| 照片图库 | 通常是个人文件夹里最大的单项 | [给照片腾出空间](https://mole.fit/zh/blog/how-to-free-up-photos-storage-mac) |
| iOS 设备备份 | `~/Library/Application Support/MobileSync/Backup` | [删除旧的 iPhone 备份](https://mole.fit/zh/blog/how-to-delete-iphone-backups-mac) |
| 邮件下载 | 邮件的账户数据持续增长 | [减小邮件占用](https://mole.fit/zh/blog/how-to-reduce-mail-storage-mac) |
| 开发数据 | Xcode、Docker、Homebrew、node 包仓库 | [清理开发缓存](https://mole.fit/zh/blog/how-to-clear-dev-caches-mac) |
| 忘记的大文件 | 旧导出、磁盘映像、下载 | [找出大文件](https://mole.fit/zh/blog/how-to-find-large-files-on-mac) |
| 本地 Time Machine 快照 | 只有真实文件解释不了失败任务时再考虑 | [理解本地快照](https://mole.fit/zh/blog/how-to-delete-local-time-machine-snapshots-mac) |

macOS 会把其中好几项折进储存空间设置里的 **系统数据**，所以那根条看起来又大又说不清。它是分类剩余项，不是一个能打开的文件夹，见[系统数据里到底有什么](https://mole.fit/zh/blog/what-is-system-data-on-mac)。

## 删了文件空间却没回来

先确认文件原本位于启动卷，而且废纸篓已经清空。给储存空间设置一点刷新时间，再用删除前记录的同一种测量方式复查。分类条还没有重绘，不等于那些块仍不可用。

APFS 快照可能继续引用已删除文件的块，但“列出了快照”本身不是容量故障。Apple 说明本地快照空间会计入可用空间，快照变旧或系统需要容量时会自动删除。下面的命令只用于只读检查：

```
tmutil listlocalsnapshots /
```

如果出现条目，先读 Apple 的[现行本地快照说明](https://support.apple.com/102154)。只有原本的保存、复制或更新仍然失败，而且真实文件解释不了容量差额时，才继续调查快照。

## 储存空间设置该怎么用

**系统设置 > 通用 > 储存空间** 有两处用得上：分类条能看出这个卷的大致形状，建议面板会把本来要到处翻的控件露出来，包括自动清空废纸篓和查看大文件。

拿它当测量就不太行，分类会重叠，改完之后数字落得很慢，系统数据还会吞掉分类器拿不准的一切，用它来导航，用 `df` 和 `diskutil` 来量。

## 不要做这些事

- **不要为了腾地方去删 `/System`、`/Library` 或 `/private` 里的文件。** 近几版 macOS 上系统卷是密封只读的，能写的那些部分都是承重的。
- **不要按日程清空缓存。** 清掉还会长回来的缓存马上就回来了，扫完之后每个应用第一次启动都会变慢，见 [哪些可以安全清理](https://mole.fit/zh/blog/how-to-clear-cache-on-mac)。
- **不要信那种承诺能清出固定数量可清除空间的工具。** 可清除是一堆混合池的上限，不是一份清单。
- **不要在 Finder 里直接删照片图库、邮件数据或备份文件夹** 来腾空间，走所属应用，数据库才不会乱。

## 要的是稳定余量，不是一个大数字

目标是让保存、更新和日常工作有足够余量，不是一次清出最大的数字。磁盘空闲多了，不代表内存压力和换页也会消失，两者还要分别观察。

到这个状态通常靠一次结构性调整，而不是很多次小删除：把照片图库或视频归档挪到外置磁盘，给大型图库打开「优化 Mac 储存空间」，或卸掉已经不用的开发工具链，其中任何一件，都比一下午删截图更经得住。

## 检查工具适合放在哪一步

[Mole](https://mole.fit/zh/) 会先量再提出删除，按真实磁盘占用把这个卷摊开，删之前先说明每个候选项是什么，并且移到废纸篓而不是直接删掉，选错了还能挽回，它不会承诺一个自己证明不了的可清除数字。

## 操作顺序

1. 用 `df -h /` 和 `diskutil info /` 记录基线。
2. 确认废纸篓状态，先在个人文件夹里找最大的真实占用。
3. 做一次结构性调整，重新测量，并重试原本失败的任务。
4. 只有仍有无法解释的差额时，才检查 Time Machine 快照。
5. 正常保存和更新已有余量时就停，不追求一个看着舒服的清理总数。

## 常见问题

### 为什么删完文件第二天提示又回来了？

因为删除没有改变持续增长的大项。照片图库、设备备份、开发数据或下载队列都可能很快吃掉刚腾出的余量。先比较前后测量，不要在没有证据时把回弹归因于快照。

### Mac 要留多少可用空间？

Apple 没有给出统一百分比。实际目标是足够一次完整 macOS 更新暂存，再为日常负载下的交换空间留出余量。

### 这条提示说明磁盘快坏了吗？

不是。它报告的是容量，不是磁盘健康。那是另一类问题，也有不同的症状。

### 可以先不管它吗？

短时间内系统可能靠回收继续工作，但保存或更新已经失败时就不该忽略。按上面的顺序找出可控的大项。
