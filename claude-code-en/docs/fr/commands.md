# Commandes

> Référence complète des commandes disponibles dans Claude Code, y compris les commandes intégrées et les skills fournis.

Les commandes contrôlent Claude Code depuis l'intérieur d'une session. Elles offrent un moyen rapide de changer de modèle, de gérer les permissions, d'effacer le contexte, d'exécuter un workflow, et bien plus.

Tapez `/` pour voir toutes les commandes disponibles pour vous, ou tapez `/` suivi de lettres pour filtrer.

Une commande n'est reconnue qu'au début de votre message. Le texte qui suit le nom de la commande lui est transmis en tant qu'arguments. À partir de la v2.1.199, les [skills](/docs/fr/skills#pass-arguments-to-skills) font exception : une invocation de skill suivie d'autres skills, comme `/skill-a /skill-b do XYZ`, charge chaque skill nommé au début et transmet le texte restant à chacun en tant qu'arguments. Jusqu'à six skills peuvent être chaînés.

Si vous envoyez une commande pendant que Claude répond, elle est mise en file d'attente et s'exécute après la fin du tour actuel. Certaines commandes, telles que `/status`, `/tasks` et `/usage`, s'exécutent immédiatement sans interrompre la réponse.

<h2 id="commands-across-a-typical-workflow">
  Commandes au cours d'un workflow typique
</h2>

La plupart des commandes sont utiles à un moment spécifique d'une session, de la configuration d'un projet à la livraison d'une modification.

**Première session dans un référentiel.** Exécutez `/init` pour générer un `CLAUDE.md` de démarrage, puis `/memory` pour l'affiner. Utilisez `/mcp` pour configurer les serveurs dont le projet a besoin, demandez à Claude de créer les [sous-agents](/docs/fr/sub-agents) que vous souhaitez, et exécutez `/permissions` pour définir vos règles d'approbation.

**Pendant une tâche.** `/plan` bascule en mode plan avant une modification importante. `/model` et `/effort` ajustent le modèle que vous utilisez et le raisonnement qu'il applique. Lorsque la conversation devient longue, `/context` montre ce qui remplit la fenêtre et `/compact` la résume pour libérer de l'espace. Utilisez `/btw` pour une remarque rapide qui ne devrait pas s'ajouter à l'historique de la conversation.

**Exécution du travail en parallèle.** Claude délègue les tâches secondaires aux [sous-agents](/docs/fr/sub-agents), et `/tasks` répertorie le travail en arrière-plan de la session actuelle, y compris les sous-agents qui ont terminé. `/background` détache la session entière pour continuer à s'exécuter en tant qu'[agent en arrière-plan](/docs/fr/agent-view) et libère votre terminal. Pour une modification importante qui s'étend sur la base de code, `/batch` la décompose en unités indépendantes et exécute chacune dans son propre [worktree](/docs/fr/worktrees). Consultez [Exécuter des agents en parallèle](/docs/fr/agents) pour comprendre comment ces approches se rapportent.

**Avant de livrer.** `/diff` montre ce qui a changé, `/code-review` vérifie la diff pour les bugs de correction et les nettoyages et peut appliquer les résultats avec `--fix`, `/review` exécute un examen rapide en lecture seule d'une demande de tirage GitHub, `/code-review <level> <pr#>` exécute un examen multi-agents d'une demande de tirage, et `/security-review` vérifie la diff pour les vulnérabilités de sécurité. `/code-review ultra` exécute un examen multi-agents dans le cloud.

**Entre les sessions.** `/clear` démarre une nouvelle tâche tout en conservant la mémoire du projet. `/resume` et `/branch` vous permettent de revenir à ou de forker une conversation antérieure. `/teleport` extrait une session web dans ce terminal, et `/remote-control` vous permet de continuer cette session locale depuis un autre appareil.

**Quand quelque chose ne va pas.** `/rewind` ramène le code et la conversation à un point de contrôle, ou résume une partie de la conversation. `/doctor` exécute une vérification de configuration qui diagnostique les problèmes d'installation et de configuration et peut les corriger, `/debug` diagnostique les problèmes d'exécution, et `/feedback` signale un bug avec le contexte de la session joint.

<h2 id="all-commands">
  Toutes les commandes
</h2>

Le tableau ci-dessous répertorie toutes les commandes incluses dans Claude Code. La plupart sont des commandes intégrées dont le comportement est codé dans le CLI. Deux types d'entrées sont marqués :

* **[Skill](/docs/fr/skills#bundled-skills)** : une skill fournie. Elle fonctionne comme les skills que vous écrivez vous-même : une invite remise à Claude, que Claude peut également invoquer automatiquement si pertinent.
* **[Workflow](/docs/fr/workflows#bundled-workflows)** : un [workflow dynamique](/docs/fr/workflows) fourni qui se déploie sur plusieurs sous-agents et s'exécute en arrière-plan.

Pour ajouter vos propres commandes, consultez [skills](/docs/fr/skills).

Dans le tableau ci-dessous, `<arg>` indique un argument obligatoire et `[arg]` indique un argument facultatif.

<Note>
  Toutes les commandes ne s'affichent pas pour tous les utilisateurs. La disponibilité dépend de votre plateforme, de votre plan et de votre environnement. Par exemple, `/desktop` ne s'affiche que sur macOS et Windows lorsque vous êtes connecté avec un abonnement Claude, et `/upgrade` ne s'affiche que sur les plans Pro et Max.
</Note>
