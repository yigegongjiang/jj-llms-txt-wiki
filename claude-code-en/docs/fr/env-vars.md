# Variables d'environnement

> Référence pour les variables d'environnement qui contrôlent le comportement de Claude Code.

Les variables d'environnement peuvent contrôler le comportement de Claude Code, comme la sélection du modèle, l'authentification, le routage des requêtes et les bascules de fonctionnalités. Beaucoup des mêmes comportements peuvent également être configurés via un [fichier de paramètres](/docs/fr/settings), un [drapeau CLI](/docs/fr/cli-reference) ou une commande en session comme `/model`.

Cette page couvre comment :

* [Définir les variables d'environnement](#set-environment-variables) dans votre shell ou dans un fichier de paramètres
* [Vérifier quelle valeur s'applique](#precedence) quand un comportement peut être défini de plusieurs façons
* [Consulter les variables que Claude Code lit](#variables)
* [Voir quelles fonctionnalités cessent de fonctionner](#features-that-need-feature-flag-fetching) quand une variable désactive la récupération des drapeaux de fonctionnalités

<h2 id="set-environment-variables">
  Définir les variables d'environnement
</h2>

Une variable que vous définissez dans votre shell dure pendant cette session de terminal, tandis qu'une variable dans un fichier de paramètres s'applique chaque fois que `claude` s'exécute.

<h3 id="in-your-shell">
  Dans votre shell
</h3>

Définissez la variable avant de lancer `claude` :

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Pour la définir pour chaque session, ajoutez la ligne `export` à `~/.bashrc`, `~/.zshrc`, ou le fichier de profil de votre shell.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Pour la définir pour chaque session, exécutez `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` et ouvrez un nouveau terminal.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Pour la définir pour chaque session, exécutez `setx API_TIMEOUT_MS "1200000"` et ouvrez un nouveau terminal.
  </Tab>
</Tabs>

La ligne d'assignation n'affiche rien en cas de succès, donc confirmez que la variable est définie en l'affichant dans le même shell avant d'exécuter `claude` :

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    echo $API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    echo $env:API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    echo %API_TIMEOUT_MS%
    ```
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  Dans les fichiers de paramètres
</h3>

Ajoutez les variables sous la clé `env` dans un fichier `settings.json`, en créant le fichier s'il n'existe pas. Claude Code les lit directement depuis le fichier, donc elles prennent effet peu importe comment `claude` a été lancé. Une session en cours applique les valeurs nouvelles et modifiées à son environnement lorsque vous enregistrez le fichier, mais une fonctionnalité qui lit ses variables une seule fois au démarrage, comme [la surveillance OpenTelemetry](/docs/fr/monitoring-usage), conserve ses valeurs de démarrage jusqu'à ce que vous relancez. Supprimer une variable du fichier ne la désactive pas dans une session en cours ; la suppression prend effet la prochaine fois que vous lancez `claude`.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

Le fichier que vous choisissez contrôle à qui les variables s'appliquent :

| Fichier                       | S'applique à                                                                                                                                             |
| :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | Vous, dans chaque projet                                                                                                                                 |
| `.claude/settings.json`       | Tous ceux qui travaillent dans le projet, archivé dans le contrôle de source                                                                             |
| `.claude/settings.local.json` | Vous, dans ce projet uniquement, ignoré par git lorsque Claude Code enregistre un paramètre ; ajoutez-le à votre gitignore si vous le créez manuellement |
| Paramètres gérés              | Tous les membres de votre organisation, déployés par un administrateur                                                                                   |

Consultez [Fichiers de paramètres](/docs/fr/settings#where-settings-live) pour savoir où se trouve chaque fichier et [Précédence des paramètres](/docs/fr/settings#settings-precedence) pour savoir comment ils se combinent lorsque plusieurs définissent la même variable.

<h2 id="precedence">
  Précédence
</h2>

Certains comportements ont à la fois une variable d'environnement et une clé de paramètres dédiée, et celle que Claude Code lit en premier diffère selon la clé. Pour `ANTHROPIC_MODEL` et `CLAUDE_CODE_AUTO_CONNECT_IDE`, Claude Code lit d'abord la variable et utilise le paramètre `model` ou `autoConnectIde` uniquement lorsque la variable n'est pas définie. Pour la paire que vous définissez, vérifiez la ligne de la variable ci-dessous et l'entrée de la clé sur la [référence des paramètres](/docs/fr/settings-reference).

Lorsque la même variable est définie à la fois dans votre shell et dans un bloc `env` du fichier de paramètres, la valeur du fichier de paramètres s'applique. Claude Code écrit chaque entrée `env` dans l'environnement du processus, en remplaçant la valeur héritée du shell. Le [paramètre `env`](/docs/fr/settings-reference#when-claude-code-applies-env-values) indique quand il les applique. Quelques variables sont traitées de manière spéciale ; le [paramètre `env`](/docs/fr/settings-reference#env) énumère les exceptions.

Dans un fichier de paramètres, vous pouvez définir une variable mais vous ne pouvez pas en supprimer une. Pour remplacer une variable que vous ne pouvez pas désactiver, comme une `CLAUDE_CODE_USE_VERTEX` obsolète exportée par un profil de shell que vous ne contrôlez pas, définissez-la sur une chaîne vide dans le bloc `env` : `"CLAUDE_CODE_USE_VERTEX": ""`. Claude Code traite la valeur vide comme non définie pour la sélection du fournisseur. Les sous-processus héritent toujours de la valeur vide.

Entre les fichiers de paramètres, les valeurs `env` suivent la [précédence des paramètres](/docs/fr/settings#settings-precedence), de sorte qu'une entrée de paramètres gérée remplace la même variable dans les paramètres utilisateur ou projet.

La façon dont une variable d'environnement interagit avec les drapeaux CLI et les commandes en session varie selon la fonctionnalité : `--model` et `/model` remplacent `ANTHROPIC_MODEL`, tandis que `CLAUDE_CODE_EFFORT_LEVEL` remplace `--effort` et `/effort`. Lorsqu'une variable interagit avec une autre source de configuration, sa ligne dans la liste [Variables](#variables) indique la précédence ou établit un lien vers la page qui la documente.

Claude Code lit les variables d'environnement du shell au démarrage, de sorte que les modifications apportées à celles-ci prennent effet la prochaine fois que vous lancez `claude`. Les variables définies sous la clé `env` dans les fichiers de paramètres sont réappliquées à une session en cours lorsque le fichier change, à l'exception du démarrage uniquement décrite dans [Dans les fichiers de paramètres](#in-settings-files).

<h2 id="variables">
  Variables
</h2>

Les variables numériques telles que les délais d'expiration, les budgets de jetons et les nombres de tentatives acceptent la notation scientifique et les orthographes avec séparateurs de chiffres en plus des chiffres simples, sauf si la ligne d'une variable indique qu'elle n'accepte que des chiffres simples. Par exemple, Claude Code lit `2e3` comme 2000 et `64_000` comme 64000. Avant la v2.1.211, ces orthographes pouvaient définir silencieusement une valeur beaucoup plus petite, comme `1e6` définissant un délai d'expiration à 1.

<Note>
  Pour les variables qui activent ou désactivent un comportement, définissez `1` ou `true` pour l'activer et `0` ou `false` pour le désactiver, dans n'importe quelle casse.

  Certaines variables ne lisent que si vous les avez définies, donc toute valeur non vide, y compris `0`, active le comportement, et vous désactivez le comportement en désactivant la variable ou en la définissant sur une valeur vide. Ces variables fonctionnent de cette façon :

  * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
  * `DISABLE_TELEMETRY`
  * `DISABLE_ERROR_REPORTING`
  * `CLAUDE_CODE_TMUX_TRUECOLOR`
  * `FALLBACK_FOR_ALL_PRIMARY_MODELS`
  * `IS_DEMO`

  Une autre variable a sa propre règle : `FORCE_HYPERLINK` lit un nombre, donc seul `0` la désactive. La ligne de chaque variable énonce également sa propre règle.
</Note>

<h2 id="features-that-need-feature-flag-fetching">
  Fonctionnalités nécessitant la récupération de feature flags
</h2>

Claude Code active certaines fonctionnalités via des feature flags qu'il récupère auprès d'Anthropic. Claude Code ignore cette récupération dans ces sessions :

* Une session où vous définissez `DISABLE_GROWTHBOOK`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK`, ou `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` ; la ligne de chaque variable dans le [tableau des variables](#variables) indique quelles valeurs désactivent la récupération
* Une session sur un [fournisseur tiers](/docs/fr/third-party-integrations), tel qu'Amazon Bedrock, Claude Platform sur AWS, Agent Platform de Google Cloud, ou Microsoft Foundry, sauf si une plateforme hôte qui intègre Claude Code définit `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
* Une session de [passerelle d'applications Claude](/docs/fr/claude-apps-gateway)

Avec la récupération désactivée, vous ne pouvez pas :

* [Démarrer les sessions en mode auto par défaut](/docs/fr/permission-modes#which-mode-a-session-starts-in) sur les plans Pro, Max et Team
* Faire en sorte que l'extension VS Code [lise les fichiers de paramètres pour le mode de permission de démarrage](/docs/fr/permission-modes#switch-permission-modes)
* Exécuter [`/auto-mode-setup`](/docs/fr/auto-mode-config#generate-environment-entries) pour rédiger les entrées `autoMode.environment`
* Utiliser [Remote Control](/docs/fr/remote-control#requirements)
* [Envoyer des messages aux sessions au-delà de cette machine](/docs/fr/cross-session-messaging#message-sessions-on-other-machines) ; la messagerie entre les sessions sur cette machine fonctionne avec la récupération désactivée
* Exécuter [`claude import` ou la commande `/import`](/docs/fr/cli-reference#cli-commands)
* Exécuter [`/skill-doctor`](/docs/fr/skills#find-unused-skills) ou ouvrir son rapport dans l'onglet **Stats** de `/plugin`

* Lire ou répondre aux [commentaires sur un artifact](/docs/fr/artifacts#collect-comments-on-an-artifact)

<h3 id="first-session-after-an-install-or-upgrade">
  Première session après une installation ou une mise à jour
</h3>

Lors de votre première session après l'installation de Claude Code, ou la mise à jour vers une version qui ajoute une fonctionnalité, une [fonctionnalité contrôlée par flag](#features-that-need-feature-flag-fetching) peut être manquante, et la session peut démarrer en mode Manuel sur un plan qui démarre autrement en mode auto. Claude Code récupère les flags lors de cette session, donc les deux sont présents dans votre session suivante.

Après une installation propre, dans une session non-interactive telle que `claude -p`, le SDK Agent, ou l'extension VS Code, Claude Code peut toujours récupérer les flags avant de [choisir le mode de permission de démarrage](/docs/fr/permission-modes#which-mode-a-session-starts-in).
