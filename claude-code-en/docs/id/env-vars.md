# Variabel lingkungan

> Referensi untuk variabel lingkungan yang mengontrol perilaku Claude Code.

Variabel lingkungan dapat mengontrol perilaku Claude Code seperti pemilihan model, autentikasi, perutean permintaan, dan pengalihan fitur. Banyak perilaku yang sama juga dapat dikonfigurasi melalui bidang [file pengaturan](/docs/id/settings), [bendera CLI](/docs/id/cli-reference), atau perintah dalam sesi seperti `/model`.

Halaman ini mencakup cara untuk:

* [Menetapkan variabel lingkungan](#set-environment-variables) di shell Anda atau di file pengaturan
* [Memeriksa nilai mana yang berlaku](#precedence) ketika perilaku dapat diatur lebih dari satu cara
* [Mencari variabel yang dibaca Claude Code](#variables)
* [Melihat fitur mana yang berhenti berfungsi](#features-that-need-feature-flag-fetching) ketika variabel mematikan pengambilan bendera fitur

<h2 id="set-environment-variables">
  Atur variabel lingkungan
</h2>

Variabel yang Anda atur di shell Anda berlaku untuk sesi terminal tersebut, sementara variabel dalam file pengaturan berlaku setiap kali `claude` dijalankan.

<h3 id="in-your-shell">
  Di shell Anda
</h3>

Atur variabel sebelum meluncurkan `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Untuk mengaturnya untuk setiap sesi, tambahkan baris `export` ke `~/.bashrc`, `~/.zshrc`, atau file profil shell Anda.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Untuk mengaturnya untuk setiap sesi, jalankan `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` dan buka terminal baru.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Untuk mengaturnya untuk setiap sesi, jalankan `setx API_TIMEOUT_MS "1200000"` dan buka terminal baru.
  </Tab>
</Tabs>

Baris penugasan tidak mencetak apa pun saat berhasil, jadi konfirmasi variabel diatur dengan mencetaknya di shell yang sama sebelum Anda menjalankan `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    echo $API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    echo $env:API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    echo %API_TIMEOUT_MS%
    ```
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  Di file pengaturan
</h3>

Tambahkan variabel di bawah kunci `env` dalam file `settings.json`, buat file jika belum ada. Claude Code membacanya langsung dari file, jadi variabel tersebut berlaku tidak peduli bagaimana `claude` diluncurkan. Sesi yang sedang berjalan menerapkan nilai baru dan yang diubah ke lingkungannya saat Anda menyimpan file, tetapi fitur yang membaca variabelnya sekali saat startup, seperti [pemantauan OpenTelemetry](/docs/id/monitoring-usage), mempertahankan nilai startupnya sampai Anda meluncurkan kembali. Menghapus variabel dari file tidak membatalkan pengaturannya dalam sesi yang sedang berjalan; penghapusan berlaku saat berikutnya Anda meluncurkan `claude`.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

File yang Anda pilih mengontrol siapa variabel berlaku untuk:

| File                          | Berlaku untuk                                                                                                                                             |
| :---------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | Anda, di setiap proyek                                                                                                                                    |
| `.claude/settings.json`       | Semua orang yang bekerja di proyek, diperiksa ke kontrol sumber                                                                                           |
| `.claude/settings.local.json` | Anda, di proyek ini saja, diabaikan git saat Claude Code menyimpan pengaturan ke dalamnya; tambahkan ke gitignore Anda jika Anda membuatnya dengan tangan |
| Pengaturan terkelola          | Semua orang di organisasi Anda, digunakan oleh admin                                                                                                      |

Lihat [File pengaturan](/docs/id/settings#where-settings-live) untuk mengetahui di mana setiap file berada dan [Prioritas pengaturan](/docs/id/settings#settings-precedence) untuk mengetahui bagaimana mereka bergabung saat lebih dari satu mengatur variabel yang sama.

<h2 id="precedence">
  Urutan Prioritas
</h2>

Beberapa perilaku memiliki baik variabel lingkungan maupun kunci pengaturan khusus, dan mana yang dibaca Claude Code terlebih dahulu berbeda per kunci. Untuk `ANTHROPIC_MODEL` dan `CLAUDE_CODE_AUTO_CONNECT_IDE`, Claude Code membaca variabel terlebih dahulu dan hanya menggunakan pengaturan `model` atau `autoConnectIde` ketika variabel tidak diatur. Untuk pasangan yang Anda atur, periksa baris variabel di bawah ini dan entri kunci pada [referensi pengaturan](/docs/id/settings-reference).

Ketika variabel yang sama diatur di shell Anda dan blok `env` file pengaturan, nilai file pengaturan berlaku. Claude Code menulis setiap entri `env` ke dalam lingkungan proses, menggantikan nilai yang diwarisi dari shell. [Pengaturan `env`](/docs/id/settings-reference#when-claude-code-applies-env-values) mengatakan kapan pengaturan tersebut diterapkan. Beberapa variabel adalah kasus khusus; [pengaturan `env`](/docs/id/settings-reference#env) mencantumkan pengecualiannya.

Dalam file pengaturan Anda dapat mengatur variabel tetapi Anda tidak dapat menghapusnya. Untuk mengganti variabel yang tidak dapat Anda batalkan, seperti `CLAUDE_CODE_USE_VERTEX` yang sudah usang yang diekspor oleh profil shell yang tidak Anda kontrol, atur ke string kosong dalam blok `env`: `"CLAUDE_CODE_USE_VERTEX": ""`. Claude Code memperlakukan nilai kosong sebagai tidak diatur untuk pemilihan penyedia. Subproses masih mewarisi nilai kosong.

Antara file pengaturan, nilai `env` mengikuti [urutan prioritas pengaturan](/docs/id/settings#settings-precedence), jadi entri pengaturan yang dikelola mengganti variabel yang sama dalam pengaturan pengguna atau proyek.

Bagaimana variabel lingkungan berinteraksi dengan bendera CLI dan perintah dalam sesi bervariasi per fitur: `--model` dan `/model` mengganti `ANTHROPIC_MODEL`, sementara `CLAUDE_CODE_EFFORT_LEVEL` mengganti `--effort` dan `/effort`. Ketika variabel berinteraksi dengan sumber konfigurasi lain, barisnya dalam daftar [Variabel](#variables) menyatakan urutan prioritas atau menautkan ke halaman yang mendokumentasikannya.

Claude Code membaca variabel lingkungan shell saat startup, jadi perubahan pada variabel tersebut berlaku saat Anda meluncurkan `claude` berikutnya. Variabel yang diatur di bawah kunci `env` dalam file pengaturan diterapkan kembali ke sesi yang sedang berjalan ketika file berubah, dengan pengecualian startup-only yang dijelaskan dalam [Dalam file pengaturan](#in-settings-files).

<h2 id="variables">
  Variabel
</h2>

Variabel numerik seperti timeout, anggaran token, dan jumlah percobaan ulang menerima notasi ilmiah dan ejaan pemisah digit selain digit biasa, kecuali di mana baris variabel mencatat bahwa variabel hanya menerima digit biasa. Misalnya, Claude Code membaca `2e3` sebagai 2000 dan `64_000` sebagai 64000. Sebelum v2.1.211, ejaan ini dapat secara diam-diam menetapkan nilai yang jauh lebih kecil, seperti `1e6` menetapkan timeout ke 1.

<Note>
  Untuk variabel yang mengaktifkan atau menonaktifkan perilaku, atur `1` atau `true` untuk mengaktifkannya dan `0` atau `false` untuk menonaktifkannya, dalam huruf apa pun.

  Beberapa variabel hanya membaca apakah Anda menetapkannya sama sekali, jadi nilai apa pun yang tidak kosong termasuk `0` mengaktifkan perilaku, dan Anda menonaktifkan perilaku dengan membatalkan penetapan variabel atau menetapkannya ke nilai kosong. Variabel-variabel ini bekerja dengan cara itu:

  * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
  * `DISABLE_TELEMETRY`
  * `DISABLE_ERROR_REPORTING`
  * `CLAUDE_CODE_TMUX_TRUECOLOR`
  * `FALLBACK_FOR_ALL_PRIMARY_MODELS`
  * `IS_DEMO`

  Satu variabel lainnya memiliki aturannya sendiri: `FORCE_HYPERLINK` membaca angka, jadi hanya `0` yang menonaktifkannya. Setiap baris variabel juga menyatakan aturannya sendiri.
</Note>

<h2 id="features-that-need-feature-flag-fetching">
  Fitur yang memerlukan pengambilan feature-flag
</h2>

Claude Code mengaktifkan beberapa fitur melalui feature flag yang diambilnya dari Anthropic. Claude Code melewati pengambilan tersebut dalam sesi-sesi ini:

* Sesi di mana Anda menetapkan `DISABLE_GROWTHBOOK`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK`, atau `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`; baris setiap variabel dalam [tabel variabel](#variables) mengatakan nilai mana yang mematikan pengambilan
* Sesi pada [penyedia pihak ketiga](/docs/id/third-party-integrations), seperti Amazon Bedrock, Claude Platform di AWS, Agent Platform Google Cloud, atau Microsoft Foundry, kecuali platform host yang menyematkan Claude Code menetapkan `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
* Sesi [gateway aplikasi Claude](/docs/id/claude-apps-gateway)

Dengan pengambilan dimatikan, Anda tidak dapat:

* [Memulai sesi dalam mode auto secara default](/docs/id/permission-modes#which-mode-a-session-starts-in) pada paket Pro, Max, dan Team
* Memiliki ekstensi VS Code [membaca file pengaturan untuk mode izin awal](/docs/id/permission-modes#switch-permission-modes)
* Menjalankan [`/auto-mode-setup`](/docs/id/auto-mode-config#generate-environment-entries) untuk membuat draf entri `autoMode.environment`
* Menggunakan [Remote Control](/docs/id/remote-control#requirements)
* [Mengirim pesan sesi di luar mesin ini](/docs/id/cross-session-messaging#message-sessions-on-other-machines); pesan antar sesi di mesin ini berfungsi dengan pengambilan dimatikan
* Menjalankan [`claude import` atau perintah `/import`](/docs/id/cli-reference#cli-commands)
* Menjalankan [`/skill-doctor`](/docs/id/skills#find-unused-skills) atau membuka laporannya di tab **Stats** `/plugin`
* Mensinkronkan [skills](/docs/id/skills#where-synced-skills-load) dan [plugins](/docs/id/plugins-reference#synced-plugins) yang diaktifkan untuk akun claude.ai Anda ke dalam sesi terminal Anda
* Menggunakan [alat penasihat](/docs/id/advisor#requirements)
* Membaca atau membalas [komentar pada artefak](/docs/id/artifacts#collect-comments-on-an-artifact)
* Memiliki Claude Code menyelidiki server konektor claude.ai untuk [revisi protokol MCP 2026-07-28](/docs/id/mcp#mcp-client-runtimes) kecuali Anda menetapkan `MCP_PROTOCOL_NEGOTIATION=auto`
* Mendapatkan [alat PowerShell](/docs/id/tools-reference#powershell-tool) secara default untuk akun claude.ai dan Console di Windows dengan Git Bash terinstal; Claude Code merutekan perintah shell melalui Git Bash kecuali Anda menetapkan `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`. Di Windows tanpa Git Bash, alat tetap aktif
* Mendapatkan [umpan balik yang dibuat Claude](/docs/id/tools-reference#sendfeedback-tool-behavior), yang Claude Code aktifkan melalui flag yang diambil
* Memiliki Claude [memperlakukan pasta besar sebagai teks yang ditempel daripada teks yang diketik](/docs/id/terminal-config#how-claude-treats-pasted-text); konten di balik placeholder `[Pasted text #N]` mencapai Claude tanpa tanda
* Memiliki Claude Code [mengecualikan alat MCP yang skema inputnya akan ditolak API](/docs/id/mcp#tools-with-invalid-input-schemas); ia mengirim skema bagaimanapun, dan permintaan yang menyertakannya gagal dengan [kesalahan 400 yang menyebutkan alat berdasarkan posisinya](/docs/id/errors#tool-input-schema-is-invalid)

<h3 id="first-session-after-an-install-or-upgrade">
  Sesi pertama setelah instalasi atau upgrade
</h3>

Dalam sesi pertama Anda setelah Anda menginstal Claude Code, atau upgrade ke versi yang menambahkan fitur, [fitur yang gated-flag](#features-that-need-feature-flag-fetching) dapat hilang, dan sesi dapat dimulai dalam mode Manual pada paket yang sebaliknya dimulai dalam mode auto. Claude Code mengambil flag selama sesi itu, jadi keduanya ada di sesi berikutnya Anda.

Setelah instalasi segar, dalam sesi non-interaktif seperti `claude -p`, Agent SDK, atau ekstensi VS Code, Claude Code masih dapat mengambil flag sebelum ia [memilih mode izin awal](/docs/id/permission-modes#which-mode-a-session-starts-in).
