# CLI-Referenz

> Vollständige Referenz für die Claude Code Befehlszeilenschnittstelle, einschließlich Befehle und Flags.

<h2 id="cli-commands">

Wenn Sie einen Unterbefehl falsch eingeben, schlägt Claude Code die nächste Übereinstimmung vor und beendet sich, ohne eine Sitzung zu starten. Zum Beispiel gibt `claude udpate` `Did you mean claude update?` aus.

Ab v2.1.199 führt `claude --dangerously-skip-permissions daemon <subcommand>` den `daemon` Unterbefehl aus. Frühere Versionen behandelten `daemon <subcommand>` als den Prompt für eine neue interaktive Sitzung, sodass der Unterbefehl nie ausgeführt wurde, wenn das Flag zuerst kam, ein häufiges Setup, wenn `claude` mit dem Flag aliasiert ist. Nur ein führendes `--dangerously-skip-permissions` oder `--allow-dangerously-skip-permissions` leitet auf diese Weise zu `daemon` weiter; jedes andere führende Flag startet immer noch eine interaktive Sitzung.

<h3 id="system-prompt-flags">
  System-Prompt-Flaggen
</h3>

Claude Code bietet fünf Flaggen zum Anpassen des System-Prompts. Vier setzen seinen Text, und mit `--system-prompt-snapshot` kontrollieren Sie, ob eine Konversation den Text behält, mit dem sie begonnen hat. Alle fünf funktionieren sowohl im interaktiven als auch im nicht-interaktiven Modus.

| Flag                          | Verhalten                                                                                                                                                                                                | Beispiel                                                                   |
| :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| `--system-prompt`             | Ersetzt den gesamten Standard-Prompt                                                                                                                                                                     | `claude --system-prompt "You are a Python expert"`                         |
| `--system-prompt-file`        | Ersetzt mit Dateiinhalten                                                                                                                                                                                | `claude --system-prompt-file ./prompts/review.txt`                         |
| `--append-system-prompt`      | Fügt an den Standard-Prompt an                                                                                                                                                                           | `claude --append-system-prompt "Always use TypeScript"`                    |
| `--append-system-prompt-file` | Fügt Dateiinhalte an den Standard-Prompt an                                                                                                                                                              | `claude --append-system-prompt-file ./style-rules.txt`                     |
| `--system-prompt-snapshot`    | Mit `off` wird der Prompt bei jeder Anfrage neu erstellt. Mit `on`, dem Standard, wird ein aufgezeichneter Prompt wiederverwendet, wo [Aufzeichnung gilt](#system-prompt-flags-in-resumed-conversations) | `claude --append-system-prompt "Draft rules" --system-prompt-snapshot off` |

`--system-prompt` und `--system-prompt-file` schließen sich gegenseitig aus. Die Append-Flaggen können mit einer der Ersetzungsflaggen kombiniert werden.

Wenn der Ersetzungstext Anweisungen kombiniert, die bei jedem Lauf gleich sind, mit Kontext, der sich pro Lauf ändert, fügen Sie eine Zeile ein, die nur `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` enthält, zwischen den Anweisungen und dem Kontext. Claude Code teilt den Prompt an der ersten solchen Zeile auf und entfernt diese Zeile, sodass der Teil darüber zwischengespeichert bleibt, während sich der Teil darunter ändert. Erfordert Claude Code v2.1.275 oder später. [Zwischengespeichern Sie den statischen Teil eines benutzerdefinierten Prompts](/docs/de/agent-sdk/modifying-system-prompts#cache-the-static-part-of-a-custom-prompt) listet die Konfigurationen auf, wo die Aufteilung gilt.

Wählen Sie basierend darauf, ob Claudes Standard-Identität immer noch zu Ihrer Aufgabe passt. Verwenden Sie eine Append-Flagge, wenn Claude ein Coding-Assistent bleiben sollte, der auch Ihre zusätzlichen Regeln befolgt: Pro-Aufruf-Anweisungen, Ausgabeformatierung oder Domänenkontext für ein `-p`-Skript. Das Anhängen bewahrt die Standard-Tool-Anleitung, Sicherheitsanweisungen und Coding-Konventionen, daher müssen Sie nur das liefern, was sich unterscheidet. Verwenden Sie eine Ersetzungsflagge, wenn sich die Oberfläche, Identität oder das Berechtigungsmodell von Claude Code unterscheidet, wie ein nicht-Coding-Agent in einer Pipeline, die kein Mensch überwacht. Das Ersetzen lässt den gesamten Standard-Prompt fallen, einschließlich Tool-Anleitung und Sicherheitsanweisungen, daher übernehmen Sie die Verantwortung für das, was Ihre Aufgabe noch benötigt.

Für persistente Personas, die Sie zwischen ihnen wechseln und über ein Projekt hinweg teilen können, verwenden Sie [Ausgabestile](/docs/de/output-styles). Für Projektkonventionen, die Claude immer befolgen sollte, verwenden Sie [CLAUDE.md](/docs/de/memory). Der [Agent SDK-Leitfaden zu System-Prompts](/docs/de/agent-sdk/modifying-system-prompts#decide-on-a-starting-point) behandelt die gleiche Entscheidung ausführlicher.

<h4 id="system-prompt-flags-in-resumed-conversations">
  System-Prompt-Flaggen in fortgesetzten Konversationen
</h4>

Standardmäßig erstellt Claude Code den System-Prompt einmal, bei der ersten Anfrage einer Konversation, mit dem Text aus allen angewendeten System-Prompt-Flaggen, und zeichnet ihn in der Sitzung auf. Bis die Konversation komprimiert wird, verwendet jede spätere Anfrage diesen aufgezeichneten Prompt, auch nachdem Sie zur Konversation mit `--resume` oder `--continue` zurückkehren. Wenn Sie beim späteren Start unterschiedlichen System-Prompt-Flag-Text übergeben oder keinen, tritt er in Kraft, sobald die Konversation komprimiert wird oder wenn Sie eine neue Konversation starten.

Außerhalb von [Cloud-Sitzungen](/docs/de/cloud-environments) startet Claude Code im [Bare-Modus](/docs/de/headless#start-faster-with-bare-mode) durch Übergabe von `--bare` oder Setzen von `CLAUDE_CODE_SIMPLE=1`, die Aufzeichnung bleibt aus, es sei denn, Sie übergeben `--system-prompt-snapshot on`. Vor v2.1.268 erstellten Sitzungen, die [Feature-Flags nicht abrufen](/docs/de/env-vars#features-that-need-feature-flag-fetching), einschließlich Sitzungen auf Amazon Bedrock, Google Cloud's Agent Platform und Microsoft Foundry, den Prompt bei jeder Anfrage neu und `--system-prompt-snapshot` hatte keine Auswirkung.

Um den Prompt bei jeder Anfrage neu zu erstellen, z. B. während Sie seine Formulierung über `--continue`-Läufe hinweg iterieren, übergeben Sie `--system-prompt-snapshot off`. Vor v2.1.265 schaltete das Übergeben einer der System-Prompt-Flaggen auch die Aufzeichnung aus, es sei denn, Sie übergaben `--system-prompt-snapshot on`.
