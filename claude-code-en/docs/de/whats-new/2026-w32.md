<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Sitzungsübergreifendes Messaging</span>
    <span className="digest-feature-pill">v2.1.224</span>
  </div>

  <p className="digest-feature-lede">Ihre Claude Code-Sitzungen können sich jetzt gegenseitig Nachrichten senden. Claude entdeckt Ihre anderen Sitzungen mit dem Tool <code>ListAgents</code> und sendet mit <code>SendMessage</code>, entweder wenn Sie es darum bitten oder von selbst, z. B. nachdem eine Änderung in einer Sitzung Auswirkungen auf das hat, woran eine andere arbeitet. Eine Nachricht ist Text, den Claude für die andere Sitzung schreibt, niemals Ihr Gesprächsverlauf oder Dateien. Verfügbar auf macOS und Linux. Erfordert v2.1.224 oder später.</p>

  <Frame>
    <video autoPlay muted loop playsInline className="w-full" src="https://mintcdn.com/claude-code/N3yEaTYPXMXFrF6k/images/whats-new/cross-session-messaging.mp4?fit=max&auto=format&n=N3yEaTYPXMXFrF6k&q=85&s=8f33c3390f78660a4a26dc980f46159f" data-path="images/whats-new/cross-session-messaging.mp4" />
  </Frame>

  <p className="digest-feature-try">Bitten Sie mit zwei offenen Sitzungen auf demselben Computer eine davon, etwas weiterzuleiten:</p>

  ```text title="Claude Code" wrap theme={null}
  Tell the session working on the payments API that users.name is now users.display_name
  ```

  <p className="digest-feature-try">Die andere Sitzung zeigt eine Zeile <code>Message from</code> an, sobald Claude die Nachricht gelesen hat; drücken Sie <code>Ctrl+O</code>, um sie zu erweitern. Um zu sehen, welche Sitzungen Claude erreichen kann, führen Sie <code>/list-agents</code> aus.</p>

  <a className="digest-feature-link" href="/docs/de/cross-session-messaging#message-another-session">Eine andere Sitzung benachrichtigen</a>
</div>

<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Selbstgehostete Umgebungen</span>
    <span className="digest-feature-pill">v2.1.224</span>
  </div>

  <p className="digest-feature-lede">Selbstgehostete Umgebungen führen Claude Code-Cloud-Sitzungen auf der eigenen Infrastruktur Ihrer Organisation aus, in öffentlicher Beta auf Team- und Enterprise-Plänen. Führen Sie <code>claude self-hosted-runner</code> auf Ihren Maschinen oder Containern aus, um sie in Runner umzuwandeln. Wenn jemand Ihre Umgebung beim Starten einer Sitzung von claude.ai, den mobilen oder Desktop-Apps oder `claude --cloud` auswählt, wird diese Sitzung in Ihrem Netzwerk ausgeführt und hat Zugriff auf Ihre internen Services. Ein Owner aktiviert zunächst <strong>Allow self-hosted environments</strong> in den <a href="https://claude.ai/admin-settings/cloud-environments">Admin-Einstellungen</a>.</p>

  <Frame>
    <img className="w-full" src="https://mintcdn.com/claude-code/N3yEaTYPXMXFrF6k/images/whats-new/self-hosted-environments.jpg?fit=max&auto=format&n=N3yEaTYPXMXFrF6k&q=85&s=ae9152cb1670c8af517d1aee57689b14" alt="Die Admin-Seite für selbstgehostete Umgebungen mit einer Liste von Umgebungen wie linux-dev und macos-prod mit ihrem Status und aktiven Sitzungszahlen" width="2048" height="1152" data-path="images/whats-new/self-hosted-environments.jpg" />
  </Frame>

  <p className="digest-feature-try">Führen Sie als Owner angemeldet das geführte Setup aus, das Sie durch die Erstellung der Umgebung führt und einen Runner startet:</p>

  ```bash terminal theme={null}
  claude self-hosted-runner setup
  ```

  <p className="digest-feature-try">Die Umgebung zeigt <strong>Healthy</strong> in den Admin-Einstellungen an, sobald sich der Runner registriert.</p>

  <a className="digest-feature-link" href="/docs/de/self-hosted-environments-quickstart#set-up-an-environment-and-runner">Schnellstart für selbstgehostete Umgebungen</a>

<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Auto-Modus wird zum Standard</span>
    <span className="digest-feature-pill">CLI</span>
  </div>

  <p className="digest-feature-lede">Ab dem 14. August ist der Auto-Modus der Standard-Berechtigungsmodus für neue Sitzungen auf Pro-, Max- und Team-Plänen. Wenn Sie selbst einen Standard-Modus festgelegt haben, bleibt dieser bestehen, es sei denn, Sie akzeptieren die einmalige Umschalt-Aufforderung, und ein Standard, den Ihre Organisation verwaltet, ändert sich nicht. Sie können jederzeit zwischen Modi wechseln. Bereits in Kraft auf diesen Plänen: Die Klassifizierer-Aufrufe, die der Auto-Modus durchführt, zählen nicht mehr zu Ihren Nutzungslimits.</p>

  <p className="digest-feature-try">Um jede Sitzung vor dem Wechsel im Auto-Modus zu starten, legen Sie ihn als Standard in Ihren Benutzereinstellungen fest:</p>

  ```json ~/.claude/settings.json {3} theme={null}
  {
    "permissions": {
      "defaultMode": "auto"
    }
  }
  ```

  <p className="digest-feature-try">Neue Sitzungen zeigen dann <code>auto mode on</code> in der Statusleiste an.</p>

  <a className="digest-feature-link" href="/docs/de/permission-modes#eliminate-prompts-with-auto-mode">Anforderungen und Steuerelemente für Auto-Modus</a>
</div>

    <div>Die VS Code-Erweiterung erhält <a href="/docs/de/vs-code#extension-settings">Focus-Ansicht</a>, die Tool-Aktivität hinter einer erweiterbaren Zeile pro Zug verbirgt; schalten Sie sie über das Befehlsmenü oder mit <code>Ctrl+Alt+F</code> (<code>Ctrl+Option+F</code> auf Mac) um</div>
    <div>Sandbox-Anmeldedatendateien akzeptieren <a href="/docs/de/sandboxing#mask-credential-files"><code>mode: "mask"</code></a> auf Linux und WSL2, sodass Sandbox-Befehle eine Sentinel-Kopie lesen, während der Sandbox-Proxy den echten Wert beim Ausgang ersetzt; die Maskierung von Anmeldedaten erhält auch <code>extract</code>, JWT-bewusste <code>decode</code> und AWS SigV4-Neusignierungsoptionen</div>
    <div>Marketplaces können ein Plugin als <a href="/docs/de/plugins/marketplace-reference#archive-plugin-source">ZIP-Archiv</a> mit der neuen <code>archive</code>-Quelle verteilen, heruntergeladen über HTTPS mit optionalem SHA-256-Pin, sodass Installationen ohne git oder npm funktionieren</div>
    <div><code>/review</code> ist jetzt ein Alias von <a href="/docs/de/code-review#review-a-diff-locally"><code>/code-review</code></a>, und <code>/code-review</code> ohne Aufwandsstufe verwendet die Stufe, die Sie zuletzt eingegeben haben</div>
    <div>Eine Sitzung, die Sie mit <a href="/docs/de/agent-view#copy-the-session-with-%2Ffork"><code>/fork</code></a> kopieren, nimmt ihre Code-Änderungen jetzt in einem eigenen Worktree vor, anstatt im Checkout der ursprünglichen Sitzung</div>
    <div>Plugins, die Sie von <a href="/docs/de/plugins/install#install-a-plugin"><code>/plugin</code></a> installieren, werden in der aktuellen Sitzung aktiviert, wenn es sicher ist; die Installationszusammenfassung meldet <code>Plugin is now active.</code> oder teilt Ihnen mit, dass Sie <code>/reload-plugins</code> ausführen sollen</div>
    <div><a href="/docs/de/agent-view#how-file-edits-are-isolated">Hintergrund-Sitzungen</a>, die Code in einem Worktree geändert haben, committen und pushen jetzt vor dem Beenden, öffnen einen Draft-Pull-Request nur, wenn die Aufgabe dies erfordert, und folgen den Git-Anweisungen in Ihrer <code>CLAUDE.md</code></div>
    <div>Die Obergrenze von 200 Subagenten pro Sitzung wird entfernt, sodass lange laufende Sitzungen keine neuen Subagenten mehr ablehnen; die <a href="/docs/de/sub-agents#concurrent-subagent-limit">Parallelitäts-</a> und Tiefenlimits gelten weiterhin</div>
    <div>Die eingecheckten Einstellungen eines Repositorys können <a href="/docs/de/remote-control#enable-remote-control-for-all-sessions">Remote Control Auto-Connect</a> nicht mehr aktivieren; legen Sie <code>remoteControlAtStartup</code> stattdessen in Ihren Benutzer- oder verwalteten Einstellungen fest, und Projekt- und lokale Einstellungen können es nur deaktivieren</div>
    <div><a href="/docs/de/worktrees#how-claude-code-enforces-isolation">Worktree-Isolation</a> blockiert jetzt nicht nur Dateibearbeitungen, sondern auch Bash-Befehle und Git-Umleitungen, die den Haupt-Checkout erreichen, in jedem Sitzungstyp und in den Subagenten der Sitzung</div>
    <div>Ein Bash-Befehl kann sich nicht mehr vor Berechtigungsprüfungen verbergen, und Tab- oder unsichtbare Unicode-Auffüllung verbirgt nicht mehr einen Teil eines Befehls vor dem Genehmigungsdialog</div>
    <div>PreToolUse-Auto-Allow-Hooks umgehen nicht mehr Tool-Einschränkungen in Claude Codes internen Nebenaufgaben wie Zusammenfassungen und Komprimierung</div>
    <div>Die <a href="/docs/de/ultraplan">Ultraplan</a>-Forschungsvorschau wird entfernt, einschließlich des Befehls <code>/ultraplan</code> und des Schlüsselworts <code>ultraplan</code>; verwenden Sie stattdessen Plan Mode oder Claude Code im Web</div>
