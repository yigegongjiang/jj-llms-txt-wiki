<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Auto-Modus auf Amazon Bedrock, Google Cloud's Agent Platform und Microsoft Foundry</span>
    <span className="digest-feature-pill">v2.1.158</span>
  </div>

  <p className="digest-feature-lede">Der Auto-Modus ist jetzt auf Amazon Bedrock, Google Cloud's Agent Platform und Microsoft Foundry für Opus 4.7 und Opus 4.8 verfügbar und ersetzt Berechtigungsaufforderungen durch Sicherheitsprüfungen im Hintergrund bei Drittanbieter-Providern. Aktivieren Sie ihn durch Setzen von <code>CLAUDE\_CODE\_ENABLE\_AUTO\_MODE=1</code>.</p>

  <p className="digest-feature-try">Aktivieren Sie ihn bei einem Drittanbieter-Provider und wechseln Sie dann mit Shift+Tab zum Auto-Modus:</p>

  ```bash terminal theme={null}
  export CLAUDE_CODE_ENABLE_AUTO_MODE=1
  ```

  <a className="digest-feature-link" href="/docs/docs/de/permission-modes#enable-auto-mode-on-bedrock-agent-platform-or-foundry">Auto-Modus bei Drittanbieter-Providern</a>
</div>

<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Sicherere automatische Bearbeitungen</span>
    <span className="digest-feature-pill">v2.1.160</span>
  </div>

  <p className="digest-feature-lede">Claude Code fordert jetzt vor dem Schreiben von Dateien auf, die Code ausführen können, auch im <code>acceptEdits</code>-Modus. Der geschützte Satz umfasst Shell-Startdateien wie <code>.zshenv</code> und <code>.bash\_login</code>, Git-Konfiguration unter <code>\~/.config/git/</code> und Build-Tool-Konfigurationen wie <code>.npmrc</code>, <code>.bazelrc</code> und <code>.pre-commit-config.yaml</code>. Diese Schreibvorgänge werden in keinem Modus außer <code>bypassPermissions</code> automatisch genehmigt.</p>

  <p className="digest-feature-try">Arbeiten Sie im acceptEdits-Modus; Claude pausiert jetzt vor dem Schreiben dieser Dateien:</p>

  ```bash terminal theme={null}
  claude --permission-mode acceptEdits
  ```

  <a className="digest-feature-link" href="/docs/docs/de/permission-modes#protected-paths">Geschützte Pfade</a>
</div>

<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Installierte Plugins mit /plugin list auflisten</span>
    <span className="digest-feature-pill">v2.1.163</span>
  </div>

  <p className="digest-feature-lede">Der neue <code>/plugin list</code>-Befehl gibt Ihre installierten Plugins inline aus, ohne das <code>/plugin</code>-Menü zu öffnen, und ist auch als <code>claude plugin list</code> aus der Shell verfügbar. In der interaktiven Form fügen Sie `--enabled` oder `--disabled` hinzu, um nur Plugins in diesem Zustand anzuzeigen.</p>

  <p className="digest-feature-try">Listen Sie die Plugins auf, die derzeit aktiviert sind:</p>

  ```text Claude Code theme={null}
  > /plugin list --enabled
  ```

  <a className="digest-feature-link" href="/docs/docs/de/plugins-reference#plugin-list">Plugin-Befehle</a>
</div>

<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Versionsanforderungen für verwaltete Bereitstellungen</span>
    <span className="digest-feature-pill">v2.1.163</span>
  </div>

  <p className="digest-feature-lede">Zwei verwaltete Einstellungen, <code>requiredMinimumVersion</code> und <code>requiredMaximumVersion</code>, ermöglichen es Ihrer Organisation, einen genehmigten Claude-Code-Versionsbereich zu erfordern. Ein Client außerhalb des Bereichs wird beim Start beendet und teilt dem Benutzer mit, dass er ein Update über die Methode der Organisation durchführen soll. <code>claude update</code>, <code>claude install</code> und <code>claude doctor</code> funktionieren weiterhin, damit Benutzer sich immer noch erholen können.</p>

  <p className="digest-feature-try">Fügen Sie eine Untergrenze zu Ihren verwalteten Einstellungen hinzu, damit ältere Clients sich weigern zu starten:</p>

  ```json managed-settings.json theme={null}
  {
    "requiredMinimumVersion": "2.1.163"
  }
  ```

  <a className="digest-feature-link" href="/docs/docs/de/admin-setup#decide-what-to-enforce">Entscheiden Sie, was Sie durchsetzen möchten</a>
</div>

<div className="digest-wins">
  <p className="digest-wins-title">Weitere Verbesserungen</p>

  <div className="digest-wins-grid">
    <div>Das Trigger-Schlüsselwort für <a href="/docs/docs/de/workflows">dynamische Workflows</a> wurde von <code>workflow</code> zu <code>ultracode</code> geändert; das Anfordern eines Workflows in Ihren eigenen Worten funktioniert immer noch, und das Schlüsselwort wird in der Eingabeaufforderung in Violett hervorgehoben</div>
    <div><a href="/docs/docs/de/hooks">Stop- und SubagentStop-Hooks</a> können <code>hookSpecificOutput.additionalContext</code> zurückgeben, um Claude Feedback zu geben und den Zug am Laufen zu halten, anstatt als Fehler behandelt zu werden</div>
    <div><code>claude mcp</code> list, get und add geben keine Geheimnisse mehr aus: Umgebungsvariablenverweise werden nicht erweitert, und Anmeldeinformationen-Header und URL-Geheimnisse werden redigiert</div>
    <div>Ein fehlgeschlagener Bash-Befehl in einem parallelen Tool-Batch bricht die anderen nicht mehr ab; jedes Tool gibt sein eigenes Ergebnis unabhängig zurück</div>
    <div>Das Bearbeiten einer Datei benötigt nicht mehr zuerst einen separaten Read, wenn Sie sie mit einem einzelnen <code>grep</code>, <code>egrep</code> oder <code>fgrep</code> angesehen haben</div>
    <div>Das Klicken auf einen Befehl im Autocomplete-Menü füllt ihn jetzt in Ihre Eingabeaufforderung ein, anstatt ihn sofort auszuführen; drücken Sie Enter, um ihn auszuführen</div>
    <div>Das Auflisten von <code>Grep</code> oder <code>Glob</code> in `--tools` stellt jetzt die dedizierten Suchtools auf nativen Builds mit eingebetteter Suche bereit, anstatt diese Namen stillschweigend zu ignorieren</div>
    <div><code>/effort</code> bestätigt jetzt, wenn Ihre gewählte Stufe als Standard für neue Sitzungen beibehalten wird</div>
    <div><code>OTEL\_RESOURCE\_ATTRIBUTES</code>-Werte werden jetzt als Beschriftungen auf Metrik-Datenpunkten angehängt, sodass Sie Nutzungsmetriken nach benutzerdefinierten Dimensionen wie Team oder Repo aufteilen können</div>
    <div>Windsurf wird in <code>/ide</code>, <code>/terminal-setup</code> und <code>/scroll-speed</code> in Devin Desktop umbenannt, gemäß der Umbenennung des Editors</div>
    <div><code>/btw</code> erhält eine <code>c zum Kopieren</code>-Verknüpfung, die die rohe Markdown-Antwort in die Zwischenablage kopiert</div>
  </div>
</div>
