# Befehle

> Vollständige Referenz für Befehle in Claude Code, einschließlich integrierter Befehle und gebündelter Skills.

Befehle steuern Claude Code innerhalb einer Sitzung. Sie bieten eine schnelle Möglichkeit, Modelle zu wechseln, Berechtigungen zu verwalten, den Kontext zu löschen, einen Workflow auszuführen und vieles mehr.

Geben Sie `/` ein, um jeden verfügbaren Befehl anzuzeigen, oder geben Sie `/` gefolgt von Buchstaben ein, um zu filtern.

Ein Befehl wird nur am Anfang Ihrer Nachricht erkannt. Text, der dem Befehlsnamen folgt, wird als Argumente an ihn übergeben. Ab v2.1.199 sind [Skills](/docs/de/skills#pass-arguments-to-skills) die Ausnahme: Ein Skill-Aufruf gefolgt von weiteren Skills, wie z. B. `/skill-a /skill-b do XYZ`, lädt jeden Skill am Anfang und übergibt den nachfolgenden Text als Argumente an jeden. Bis zu sechs Skills können verkettet werden.

Wenn Sie einen Befehl senden, während Claude antwortet, wird er in die Warteschlange eingereiht und nach Abschluss des aktuellen Durchgangs ausgeführt. Einige Befehle, wie z. B. `/status`, `/tasks` und `/usage`, werden sofort ausgeführt, ohne die Antwort zu unterbrechen.

<h2 id="commands-across-a-typical-workflow">
  Befehle in einem typischen Workflow
</h2>

Die meisten Befehle sind an einem bestimmten Punkt in einer Sitzung nützlich, vom Einrichten eines Projekts bis zum Versand einer Änderung.

**Erste Sitzung in einem Repository.** Führen Sie `/init` aus, um eine Starter-`CLAUDE.md` zu generieren, dann `/memory`, um sie zu verfeinern. Verwenden Sie `/mcp`, um alle Server einzurichten, die das Projekt benötigt, bitten Sie Claude, alle [Subagenten](/docs/de/sub-agents) zu erstellen, die Sie möchten, und führen Sie `/permissions` aus, um Ihre Genehmigungsregeln festzulegen.

**Während einer Aufgabe.** `/plan` wechselt vor einer großen Änderung in den Plan-Modus. `/model` und `/effort` passen an, welches Modell Sie verwenden, und wie viel Reasoning es anwendet. Wenn das Gespräch lang wird, zeigt `/context`, was das Fenster ausfüllt, und `/compact` fasst es zusammen, um Platz freizugeben. Verwenden Sie `/btw` für eine schnelle Nebenbemerkung, die die Gesprächshistorie nicht aufblähen sollte.

**Parallele Arbeit ausführen.** Claude delegiert Nebenaufgaben an [Subagenten](/docs/de/sub-agents), und `/tasks` listet die aktuelle Sitzung's Hintergrundarbeit auf, einschließlich Subagenten, die fertig sind. `/background` trennt die gesamte Sitzung ab, um als [Hintergrund-Agent](/docs/de/agent-view) weiter zu laufen, und gibt Ihr Terminal frei. Für eine große Änderung, die sich über die Codebasis erstreckt, zerlegt `/batch` sie in unabhängige Einheiten und führt jede in ihrem eigenen [Worktree](/docs/de/worktrees) aus. Siehe [Agenten parallel ausführen](/docs/de/agents), um zu verstehen, wie diese Ansätze zusammenhängen.

**Bevor Sie versenden.** `/diff` zeigt, was sich geändert hat, `/code-review` überprüft das Diff auf Korrektheitsfehler und Bereinigungen und kann die Erkenntnisse mit `--fix` anwenden, `/review` führt eine schnelle einmalige, schreibgeschützte Überprüfung eines GitHub-Pull-Requests durch, `/code-review <level> <pr#>` führt eine Multi-Agent-Überprüfung eines durch, und `/security-review` überprüft das Diff auf Sicherheitslücken. `/code-review ultra` führt eine Multi-Agent-Überprüfung in der Cloud aus.

**Zwischen Sitzungen.** `/clear` startet frisch bei einer neuen Aufgabe, während die Projektmemory erhalten bleibt. `/resume` und `/branch` ermöglichen es Ihnen, zu einem früheren Gespräch zurückzukehren oder es zu verzweigen. `/teleport` zieht eine Web-Sitzung in dieses Terminal, und `/remote-control` ermöglicht es Ihnen, diese lokale Sitzung von einem anderen Gerät fortzusetzen.

**Wenn etwas schief geht.** `/rewind` setzt Code und Gespräch zu einem Checkpoint zurück, oder fasst einen Teil des Gesprächs zusammen. `/doctor` führt eine Setup-Überprüfung durch, die Installations- und Konfigurationsprobleme diagnostiziert und beheben kann, `/debug` diagnostiziert Laufzeitprobleme, und `/feedback` meldet einen Fehler mit Sitzungskontext an.

<h2 id="all-commands">
  Alle Befehle
</h2>

Die folgende Tabelle listet alle in Claude Code enthaltenen Befehle auf. Die meisten sind integrierte Befehle, deren Verhalten in die CLI codiert ist. Zwei Arten von Einträgen sind gekennzeichnet:

* **[Skill](/docs/de/skills#bundled-skills)**: ein gebündelter Skill. Er funktioniert wie Skills, die Sie selbst schreiben: eine Eingabeaufforderung, die Claude übergeben wird und die Claude auch automatisch aufrufen kann, wenn relevant.
* **[Workflow](/docs/de/workflows#bundled-workflows)**: ein gebündelter [dynamischer Workflow](/docs/de/workflows), der Arbeit über viele Subagenten verteilt und im Hintergrund läuft.

Um Ihre eigenen Befehle hinzuzufügen, siehe [Skills](/docs/de/skills).

In der folgenden Tabelle gibt `<arg>` ein erforderliches Argument an und `[arg]` ein optionales.

<Note>
  Nicht jeder Befehl wird für jeden Benutzer angezeigt. Die Verfügbarkeit hängt von Ihrer Plattform, Ihrem Plan und Ihrer Umgebung ab. Beispielsweise wird `/desktop` nur auf macOS und Windows angezeigt, wenn Sie mit einem Claude-Abonnement angemeldet sind, und `/upgrade` wird nur in Pro- und Max-Plänen angezeigt.
</Note>
