# Befehle

> Vollständige Referenz für Befehle in Claude Code, einschließlich integrierter Befehle und gebündelter Skills.

Befehle steuern Claude Code innerhalb einer Sitzung. Sie bieten eine schnelle Möglichkeit, Modelle zu wechseln, Berechtigungen zu verwalten, den Kontext zu löschen, einen Workflow auszuführen und vieles mehr.

Geben Sie `/` ein, um die für Sie verfügbaren Befehle anzuzeigen, oder geben Sie `/` gefolgt von Buchstaben ein, um zu filtern. [Wie das Befehlsmenü das Eingegebene abgleicht](#how-the-command-menu-matches-what-you-type) behandelt Hervorhebung, Tippfehler und die wenigen Befehle, die Claude Code im Menü verbirgt, bis Sie ihren vollständigen Namen eingeben.

Ein Befehl wird nur am Anfang Ihrer Nachricht erkannt. Text, der dem Befehlsnamen folgt, wird zu seinen Argumenten. Ab v2.1.199 sind [Skills](/docs/de/skills#pass-arguments-to-skills) die Ausnahme: Eine Skill-Invokation gefolgt von weiteren Skills, wie z. B. `/skill-a /skill-b do XYZ`, lädt jeden Skill am Anfang und übergibt den nachfolgenden Text jedem als Argumente. Bis zu sechs Skills können verkettet werden.

Wenn Sie einen Befehl senden, während Claude antwortet, stellt Claude Code ihn in die Warteschlange und führt ihn aus, nachdem der aktuelle Zug beendet ist. Claude Code führt einige Befehle sofort aus, ohne die Antwort zu unterbrechen, wie z. B. `/status`, `/tasks` und `/usage`. In [Vollbilddarstellung](/docs/de/fullscreen) öffnet Claude Code auch Dialogbefehle wie `/theme` und `/help` sofort. Vor v2.1.234 stellte Claude Code diese Dialoge in die Warteschlange, bis der Zug beendet war.

<h2 id="commands-across-a-typical-workflow">
  Befehle in einem typischen Arbeitsablauf
</h2>

Die meisten Befehle sind an einem bestimmten Punkt in einer Sitzung nützlich, vom Einrichten eines Projekts bis zum Versand einer Änderung.

**Erste Sitzung in einem Repository.** Führen Sie `/init` aus, um eine Starter-`CLAUDE.md` zu generieren, dann `/memory`, um sie zu verfeinern. Verwenden Sie `/mcp`, um alle Server einzurichten, die das Projekt benötigt, bitten Sie Claude, alle [Subagenten](/docs/de/sub-agents) zu erstellen, die Sie möchten, und führen Sie `/permissions` aus, um Ihre Genehmigungsregeln festzulegen.

**Während einer Aufgabe.** `/plan` wechselt vor einer großen Änderung in den Plan Mode. `/model` und `/effort` passen das Modell an, das Sie verwenden, und wie viel Reasoning es anwendet. Wenn das Gespräch lang wird, zeigt `/context`, was das Fenster ausfüllt, und `/compact` fasst es zusammen, um Platz freizugeben. Verwenden Sie `/btw` für eine Nebenfrage, die nicht zum Gesprächsverlauf hinzugefügt werden sollte.

**Arbeiten parallel ausführen.** Claude delegiert Nebenaufgaben an [Subagenten](/docs/de/sub-agents), und `/tasks` listet die Hintergrundarbeiten der aktuellen Sitzung auf, einschließlich Subagenten, die fertig sind. `/background` trennt die gesamte Sitzung ab, um als [Hintergrund-Agent](/docs/de/agent-view) weiter zu laufen, und gibt Ihr Terminal frei. Für eine große Änderung, die sich über die Codebasis erstreckt, zerlegt `/batch` sie in unabhängige Einheiten und führt jede in ihrem eigenen [Worktree](/docs/de/worktrees) aus. Siehe [Agenten parallel ausführen](/docs/de/agents), um zu verstehen, wie diese Ansätze zusammenhängen.

**Bevor Sie versenden.** `/diff` zeigt, was sich geändert hat. `/code-review` überprüft den aktuellen Diff auf Korrektheitsfehler und kann die Ergebnisse mit `--fix` anwenden; übergeben Sie eine PR-Nummer, z. B. `/code-review high 1234`, um stattdessen einen Pull Request zu überprüfen. `/review` ist ein Alias. `/code-review ultra` führt eine Multi-Agent-Überprüfung in der Cloud aus. `/security-review` überprüft den Diff auf Sicherheitslücken.

**Zwischen Sitzungen.** `/clear` startet eine neue Aufgabe neu, während die Projektmemory erhalten bleibt. `/resume` kehrt zu einem früheren Gespräch zurück, `/branch` verzweigt das aktuelle, um eine andere Richtung zu versuchen, und `/fork` kopiert es in eine neue [Hintergrund-Sitzung](/docs/de/agent-view). `/teleport` zieht eine Cloud-Sitzung in dieses Terminal, und `/remote-control` ermöglicht es Ihnen, diese lokale Sitzung von einem anderen Gerät aus fortzusetzen.

**Wenn etwas nicht stimmt.** `/rewind` setzt Code und Gespräch auf einen Checkpoint zurück oder fasst einen Teil des Gesprächs zusammen. `/doctor` führt eine Setup-Überprüfung durch, die Installations- und Konfigurationsprobleme diagnostiziert und beheben kann, `/debug` diagnostiziert Laufzeitprobleme, und `/feedback` meldet einen Fehler mit angehängtem Sitzungskontext.

<h2 id="all-commands">
  Alle Befehle
</h2>

Die folgende Tabelle listet alle Befehle auf, die in Claude Code enthalten sind. Die meisten sind integrierte Befehle, deren Verhalten in der CLI codiert ist. Zwei Arten von Einträgen sind gekennzeichnet:

* **[Skill](/docs/de/skills#bundled-skills)**: ein gebündelter Skill. Er funktioniert wie Skills, die Sie selbst schreiben: ein Prompt, der an Claude übergeben wird.
  * `/verify` wird nur ausgeführt, wenn Sie ihn aufrufen. Vor v2.1.215 konnte Claude `/verify` auch von selbst ausführen.
* **[Workflow](/docs/de/workflows#bundled-workflows)**: ein gebündelter [dynamischer Workflow](/docs/de/workflows), der Arbeit über viele Subagenten verteilt und im Hintergrund ausgeführt wird.
  * `/deep-research` wird nur ausgeführt, wenn Sie ihn aufrufen. Vor v2.1.218 konnte Claude ihn auch von selbst starten.

Um Ihre eigenen Befehle hinzuzufügen, siehe [Skills](/docs/de/skills).

In der folgenden Tabelle zeigt `<arg>` ein erforderliches Argument und `[arg]` ein optionales an.

<Note>
  Nicht jeder Befehl ist für jeden Benutzer verfügbar. Die Verfügbarkeit hängt von Ihrer Plattform, Ihrem Plan und Ihrer Umgebung ab. Beispielsweise wird `/desktop` nur auf macOS und x64 Windows angezeigt, wenn Sie mit einem Claude-Abonnement angemeldet sind, und `/upgrade` wird nicht in Enterprise-Plänen angezeigt.
</Note>

<h2 id="how-the-command-menu-matches-what-you-type">
  Wie das Befehlsmenü mit Ihrer Eingabe übereinstimmt
</h2>

Claude Code filtert das `/`-Menü während Sie tippen. Jeder Punkt unten behandelt eine Sache, die Ihnen beim Filtern auffallen könnte:

* **Hervorhebung**: Claude Code hebt nur den obersten Vorschlag hervor, wenn die Buchstaben nach dem `/` mit dem Namen oder Alias eines Befehls übereinstimmen, vom Anfang des Namens oder von einem Wort darin, wobei die Trennzeichen `:`, `_` und `-` ignoriert werden. Die Eingabe von `/adddir` hebt `/add-dir` hervor, und die Eingabe von `/new` hebt `/clear` durch seinen Alias hervor. Drücken Sie `Enter`, um den hervorgehobenen Vorschlag auszuführen. Diese Hervorhebungsregeln erfordern Claude Code v2.1.236 oder später.
* **Nach einem Tippfehler**: Claude Code hebt nichts hervor. Die nahen Übereinstimmungen bleiben aufgelistet, und Sie können eine mit `Tab` oder den Pfeiltasten auswählen, aber `Enter` sendet Ihren Text wie eingegeben und meldet [Unbekannter Befehl](/docs/de/errors#unknown-command).
* **Befehle, die für Sie nicht verfügbar sind**: Claude Code lässt sie aus dem Menü weg. Wenn nichts übereinstimmt, zeigt Claude Code `No commands match "/name"` an. Die meisten nicht verfügbaren Befehle geben [Unbekannter Befehl](/docs/de/errors#unknown-command) zurück, wenn Sie sie absenden; einige, wie [`/schedule` auf einem Console API-Schlüssel](/docs/de/routines#schedule-returns-unknown-command), antworten stattdessen mit ihrer eigenen Verfügbarkeitsmitteilung. Einige Befehle antworten auch mit einer eigenen Mitteilung, wenn die Richtlinie Ihrer Organisation sie deaktiviert.
* **Verborgene Befehle**: Claude Code behält einige verfügbare Befehle, wie `/heapdump`, absichtlich aus dem Menü heraus. Ein Teilname bringt niemals einen verborgenen Befehl ins Menü: Wenn die Teilübereinstimmung nichts Sichtbares trifft, zeigt Claude Code die gleiche Keine-Übereinstimmung-Meldung an. Claude Code listet den Befehl nur auf, wenn Sie seinen vollständigen Namen eingegeben haben, und das Absenden des vollständigen Namens führt ihn aus.
