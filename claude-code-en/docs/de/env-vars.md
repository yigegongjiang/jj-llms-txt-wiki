# Umgebungsvariablen

> Referenz für Umgebungsvariablen, die das Verhalten von Claude Code steuern.

Umgebungsvariablen können das Verhalten von Claude Code steuern, z. B. Modellauswahl, Authentifizierung, Anfragerouting und Funktionsschalter. Viele der gleichen Verhaltensweisen können auch über ein [Einstellungsfeld](/docs/de/settings), ein [CLI-Flag](/docs/de/cli-reference) oder einen In-Session-Befehl wie `/model` konfiguriert werden.

Diese Seite behandelt folgende Themen:

* [Umgebungsvariablen festlegen](#set-environment-variables) in Ihrer Shell oder in einer Einstellungsdatei
* [Überprüfen, welcher Wert gilt](#precedence), wenn ein Verhalten auf mehr als eine Weise festgelegt werden kann
* [Die Variablen nachschlagen, die Claude Code liest](#variables)
* [Sehen Sie, welche Funktionen nicht mehr funktionieren](#features-that-need-feature-flag-fetching), wenn eine Variable das Abrufen von Funktionsflags deaktiviert

<h2 id="set-environment-variables">
  Umgebungsvariablen festlegen
</h2>

Eine Variable, die Sie in Ihrer Shell festlegen, gilt für diese Terminalsitzung, während eine Variable in einer Einstellungsdatei jedes Mal gilt, wenn `claude` ausgeführt wird.

<h3 id="in-your-shell">
  In Ihrer Shell
</h3>

Legen Sie die Variable vor dem Starten von `claude` fest:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Um sie für jede Sitzung festzulegen, fügen Sie die `export`-Zeile zu `~/.bashrc`, `~/.zshrc` oder der Profilldatei Ihrer Shell hinzu.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Um sie für jede Sitzung festzulegen, führen Sie `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` aus und öffnen Sie ein neues Terminal.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Um sie für jede Sitzung festzulegen, führen Sie `setx API_TIMEOUT_MS "1200000"` aus und öffnen Sie ein neues Terminal.
  </Tab>
</Tabs>

Die Zuweisungszeile gibt bei erfolgreicher Ausführung nichts aus. Bestätigen Sie daher, dass die Variable festgelegt ist, indem Sie sie in derselben Shell ausdrucken, bevor Sie `claude` ausführen:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    echo $API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    echo $env:API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    echo %API_TIMEOUT_MS%
    ```
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  In Einstellungsdateien
</h3>

Fügen Sie Variablen unter dem Schlüssel `env` in einer `settings.json`-Datei hinzu und erstellen Sie die Datei, falls sie nicht vorhanden ist. Claude Code liest sie direkt aus der Datei, sodass sie wirksam werden, unabhängig davon, wie `claude` gestartet wurde. Eine laufende Sitzung wendet neue und geänderte Werte auf ihre Umgebung an, wenn Sie die Datei speichern. Ein Feature, das seine Variablen einmalig beim Start liest, wie z. B. [OpenTelemetry-Überwachung](/docs/de/monitoring-usage), behält seine Startwerte bei, bis Sie neu starten. Das Entfernen einer Variable aus der Datei hebt sie in einer laufenden Sitzung nicht auf. Die Entfernung wird wirksam, wenn Sie `claude` das nächste Mal starten.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

Die Datei, die Sie wählen, bestimmt, für wen die Variablen gelten:

| Datei                         | Gilt für                                                                                                                                                        |
| :---------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | Sie, in jedem Projekt                                                                                                                                           |
| `.claude/settings.json`       | Alle, die im Projekt arbeiten, eingecheckt in die Versionskontrolle                                                                                             |
| `.claude/settings.local.json` | Sie, nur in diesem Projekt, gitignored, wenn Claude Code eine Einstellung darin speichert; fügen Sie es zu Ihrer gitignore hinzu, wenn Sie es manuell erstellen |
| Verwaltete Einstellungen      | Alle in Ihrer Organisation, bereitgestellt von einem Administrator                                                                                              |

Siehe [Einstellungsdateien](/docs/de/settings#where-settings-live) für den Speicherort jeder Datei und [Einstellungspriorität](/docs/de/settings#settings-precedence) für die Kombination, wenn mehr als eine dieselbe Variable festlegt.

<h2 id="precedence">
  Vorrang
</h2>

Einige Verhaltensweisen haben sowohl eine Umgebungsvariable als auch einen dedizierten Einstellungsschlüssel, und welche Claude Code zuerst liest, unterscheidet sich je nach Schlüssel. Für `ANTHROPIC_MODEL` und `CLAUDE_CODE_AUTO_CONNECT_IDE` liest Claude Code zuerst die Variable und verwendet die Einstellung `model` oder `autoConnectIde` nur, wenn die Variable nicht gesetzt ist. Für das Paar, das Sie einstellen, überprüfen Sie die Zeile der Variable unten und den Eintrag des Schlüssels in der [Einstellungsreferenz](/docs/de/settings-reference).

Wenn dieselbe Variable sowohl in Ihrer Shell als auch in einem Einstellungsdatei-`env`-Block gesetzt ist, gilt der Wert der Einstellungsdatei. Claude Code schreibt jeden `env`-Eintrag in die Prozessumgebung und ersetzt den Wert, der von der Shell geerbt wird. Die [`env`-Einstellung](/docs/de/settings-reference#when-claude-code-applies-env-values) gibt an, wann sie angewendet werden. Einige Variablen sind Sonderfälle; die [`env`-Einstellung](/docs/de/settings-reference#env) listet die Ausnahmen auf.

In einer Einstellungsdatei können Sie eine Variable setzen, aber Sie können sie nicht entfernen. Um eine Variable zu überschreiben, die Sie nicht aufheben können, z. B. eine veraltete `CLAUDE_CODE_USE_VERTEX`, die von einem Shell-Profil exportiert wird, das Sie nicht kontrollieren, setzen Sie sie im `env`-Block auf eine leere Zeichenkette: `"CLAUDE_CODE_USE_VERTEX": ""`. Claude Code behandelt den leeren Wert als nicht gesetzt für die Anbieterauswahl. Unterprozesse erben weiterhin den leeren Wert.

Zwischen Einstellungsdateien folgen `env`-Werte dem [Einstellungsvorrang](/docs/de/settings#settings-precedence), sodass ein verwalteter Einstellungseintrag dieselbe Variable in Benutzer- oder Projekteinstellungen überschreibt. Projekt- und lokale Einstellungen können einige Variablen nicht setzen, z. B. `CLAUDE_CONFIG_DIR` und die OpenTelemetry-Exporter-Variablen. [Variablen, die Claude Code in `env` ignoriert](/docs/de/settings-reference#variables-claude-code-ignores-in-env) listet sie auf, zusammen mit den OpenTelemetry-Ausschaltungswerten, die weiterhin gelten.

Wie eine Umgebungsvariable mit CLI-Flags und In-Session-Befehlen interagiert, variiert je nach Funktion: `--model` und `/model` überschreiben `ANTHROPIC_MODEL`, während `CLAUDE_CODE_EFFORT_LEVEL` `--effort` und `/effort` überschreibt. Wenn eine Variable mit einer anderen Konfigurationsquelle interagiert, gibt ihre Zeile in der Liste [Variablen](#variables) den Vorrang an oder verlinkt auf die Seite, die ihn dokumentiert.

Claude Code liest Shell-Umgebungsvariablen beim Start, sodass Änderungen daran beim nächsten Start von `claude` wirksam werden. Variablen, die unter dem `env`-Schlüssel in Einstellungsdateien gesetzt sind, werden erneut auf eine laufende Sitzung angewendet, wenn sich die Datei ändert, mit der Ausnahme beim Start, die in [In Einstellungsdateien](#in-settings-files) beschrieben ist.

<h2 id="variables">
  Variablen
</h2>

Numerische Variablen wie Timeouts, Token-Budgets und Wiederholungsanzahlen akzeptieren wissenschaftliche Notation und Ziffern-Trennzeichen-Schreibweisen zusätzlich zu einfachen Ziffern, außer wo die Zeile einer Variablen anmerkt, dass sie nur einfache Ziffern akzeptiert. Zum Beispiel liest Claude Code `2e3` als 2000 und `64_000` als 64000. Vor v2.1.211 konnten diese Schreibweisen stillschweigend einen viel kleineren Wert setzen, wie `1e6` das Timeout auf 1 setzen.

<Note>
  Für Variablen, die ein Verhalten ein- oder ausschalten, setzen Sie `1` oder `true`, um es einzuschalten, und `0` oder `false`, um es auszuschalten, in beliebiger Groß-/Kleinschreibung.

  Einige Variablen lesen nur, ob Sie sie überhaupt gesetzt haben, daher schaltet jeder nicht-leere Wert einschließlich `0` das Verhalten ein, und Sie schalten das Verhalten aus, indem Sie die Variable nicht setzen oder auf einen leeren Wert setzen. Diese Variablen funktionieren auf diese Weise:

  * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
  * `DISABLE_TELEMETRY`
  * `DISABLE_ERROR_REPORTING`
  * `CLAUDE_CODE_TMUX_TRUECOLOR`
  * `FALLBACK_FOR_ALL_PRIMARY_MODELS`
  * `IS_DEMO`

  Eine andere Variable hat ihre eigene Regel: `FORCE_HYPERLINK` liest eine Zahl, daher schaltet nur `0` sie aus. Jede Variablenzeile gibt auch ihre eigene Regel an.
</Note>

<h2 id="features-that-need-feature-flag-fetching">
  Funktionen, die das Abrufen von Feature-Flags erfordern
</h2>

Claude Code aktiviert einige Funktionen durch Feature-Flags, die von Anthropic abgerufen werden. Claude Code überspringt diesen Abruf in diesen Sitzungen:

* Eine Sitzung, in der Sie `DISABLE_GROWTHBOOK`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK` oder `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` setzen; die Zeile jeder Variablen in der [Variablentabelle](#variables) gibt an, welche Werte das Abrufen deaktivieren
* Eine Sitzung auf einem [Drittanbieter-Provider](/docs/de/third-party-integrations), wie Amazon Bedrock, Claude Platform auf AWS, Google Clouds Agent Platform oder Microsoft Foundry, es sei denn, eine Host-Plattform, die Claude Code einbettet, setzt `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
* Eine [Claude-Apps-Gateway](/docs/de/claude-apps-gateway)-Sitzung

Wenn das Abrufen deaktiviert ist, können Sie nicht:

* [Sitzungen standardmäßig im Auto-Modus starten](/docs/de/permission-modes#which-mode-a-session-starts-in) auf Pro-, Max- und Team-Plänen
* Die VS Code-Erweiterung [Einstellungsdateien für den Startberechtigungsmodus lesen lassen](/docs/de/permission-modes#switch-permission-modes)
* [`/auto-mode-setup`](/docs/de/auto-mode-config#generate-environment-entries) ausführen, um `autoMode.environment`-Einträge zu entwerfen
* [Remote Control](/docs/de/remote-control#requirements) verwenden
* [Sitzungen über diese Maschine hinaus Nachrichten senden](/docs/de/cross-session-messaging#message-sessions-on-other-machines); das Messaging zwischen Sitzungen auf dieser Maschine funktioniert mit deaktiviertem Abrufen
* [`claude import` oder den `/import`-Befehl](/docs/de/cli-reference#cli-commands) ausführen
* [`/skill-doctor`](/docs/de/skills#find-unused-skills) ausführen oder seinen Bericht in der `/plugin` **Stats**-Registerkarte öffnen
* Die [Skills](/docs/de/skills#where-synced-skills-load) und [Plugins](/docs/de/plugins/loading#synced-plugins) synchronisieren, die für Ihr claude.ai-Konto aktiviert sind, in Ihre Terminal-Sitzungen
* [Das Advisor-Tool](/docs/de/advisor#requirements) verwenden
* [Kommentare zu einem Artefakt](/docs/de/artifacts#collect-comments-on-an-artifact) lesen oder beantworten
* Claude Code Sonden auf claude.ai-Connector-Servern für [MCP-Protokollrevision 2026-07-28](/docs/de/mcp#mcp-client-runtimes) durchführen lassen, es sei denn, Sie setzen `MCP_PROTOCOL_NEGOTIATION=auto`
* Das [PowerShell-Tool](/docs/de/tools-reference#powershell-tool) standardmäßig für claude.ai und Console-Konten unter Windows mit installiertem Git Bash abrufen; Claude Code leitet Shell-Befehle durch Git Bash weiter, es sei denn, Sie setzen `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`. Unter Windows ohne Git Bash bleibt das Tool aktiviert
* [Von Claude entworfenes Feedback](/docs/de/tools-reference#sendfeedback-tool-behavior) abrufen, das Claude Code durch ein abgerufenes Flag aktiviert
* Claude [große Einfügungen als eingefügt statt als eingegeben behandeln lassen](/docs/de/terminal-config#how-claude-treats-pasted-text); der Inhalt hinter einem `[Pasted text #N]`-Platzhalter erreicht Claude unmarkiert
* Claude Code [MCP-Tools ausschließen, deren Eingabeschema die API ablehnen würde](/docs/de/mcp#tools-with-invalid-input-schemas); es sendet das Schema trotzdem, und eine Anfrage, die es enthält, schlägt mit [einem 400-Fehler fehl, der das Tool nach seiner Position benennt](/docs/de/errors#tool-input-schema-is-invalid)

<h3 id="first-session-after-an-install-or-upgrade">
  Erste Sitzung nach einer Installation oder einem Upgrade
</h3>

In Ihrer ersten Sitzung nach der Installation von Claude Code oder dem Upgrade auf eine Version, die eine Funktion hinzufügt, kann eine [Flag-gesteuerte Funktion](#features-that-need-feature-flag-fetching) fehlen, und die Sitzung kann im manuellen Modus auf einem Plan starten, der ansonsten im Auto-Modus startet. Claude Code ruft die Flags während dieser Sitzung ab, sodass beide in Ihrer nächsten Sitzung vorhanden sind.

Nach einer Neuinstallation kann Claude Code in einer nicht-interaktiven Sitzung wie `claude -p`, dem Agent SDK oder der VS Code-Erweiterung die Flags immer noch abrufen, bevor es [den Startberechtigungsmodus wählt](/docs/de/permission-modes#which-mode-a-session-starts-in).
