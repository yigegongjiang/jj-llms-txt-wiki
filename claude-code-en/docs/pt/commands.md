# Comandos

> Referência completa para comandos disponíveis no Claude Code, incluindo comandos integrados e skills agrupadas.

Os comandos controlam o Claude Code dentro de uma sessão. Eles fornecem uma maneira rápida de alternar modelos, gerenciar permissões, limpar contexto, executar um fluxo de trabalho e muito mais.

Digite `/` para ver os comandos disponíveis para você, ou digite `/` seguido de letras para filtrar. [Como o menu de comandos corresponde ao que você digita](#how-the-command-menu-matches-what-you-type) aborda realce, erros de digitação e os poucos comandos que o Claude Code oculta do menu até que você digite seu nome completo.

Um comando é reconhecido apenas no início da sua mensagem. O texto que segue o nome do comando se torna seus argumentos. A partir da v2.1.199, [skills](/docs/pt/skills#pass-arguments-to-skills) são a exceção: uma invocação de skill seguida por mais skills, como `/skill-a /skill-b do XYZ`, carrega cada skill nomeada no início e passa o texto final para cada uma como argumentos. Até seis skills podem ser encadeadas.

Se você enviar um comando enquanto Claude está respondendo, o Claude Code o coloca na fila e o executa após o turno atual terminar. O Claude Code executa alguns comandos imediatamente sem interromper a resposta, como `/status`, `/tasks` e `/usage`. Em [renderização em tela cheia](/docs/pt/fullscreen), o Claude Code também abre comandos de diálogo como `/theme` e `/help` imediatamente. Antes da v2.1.234, o Claude Code colocava esses diálogos na fila até que o turno terminasse.

<h2 id="commands-across-a-typical-workflow">
  Comandos em um fluxo de trabalho típico
</h2>

A maioria dos comandos é útil em um ponto específico de uma sessão, desde a configuração de um projeto até o envio de uma alteração.

**Primeira sessão em um repositório.** Execute `/init` para gerar um `CLAUDE.md` inicial, depois `/memory` para refiná-lo. Use `/mcp` para configurar quaisquer servidores que o projeto necessite, peça ao Claude para criar quaisquer [subagentes](/docs/pt/sub-agents) que você deseje, e execute `/permissions` para definir suas regras de aprovação.

**Durante uma tarefa.** `/plan` muda para o modo de plano antes de uma grande alteração. `/model` e `/effort` ajustam qual modelo você está usando e quanto raciocínio ele aplica. Quando a conversa fica longa, `/context` mostra o que está preenchendo a janela e `/compact` a resume para liberar espaço. Use `/btw` para uma pergunta lateral que não deve ser adicionada ao histórico de conversa.

**Execute trabalho em paralelo.** Claude delega tarefas secundárias para [subagentes](/docs/pt/sub-agents), e `/tasks` lista o trabalho em segundo plano da sessão atual, incluindo subagentes que terminaram. `/background` desanexa a sessão inteira para continuar executando como um [agente em segundo plano](/docs/pt/agent-view) e libera seu terminal. Para uma grande alteração que abrange a base de código, `/batch` a decompõe em unidades independentes e executa cada uma em sua própria [worktree](/docs/pt/worktrees). Veja [Executar agentes em paralelo](/docs/pt/agents) para entender como essas abordagens se relacionam.

**Antes de você enviar.** `/diff` mostra o que mudou. `/code-review` verifica o diff atual quanto a bugs de correção e pode aplicar as descobertas com `--fix`; passe um número de PR, como `/code-review high 1234`, para revisar uma solicitação de pull. `/review` é um alias. `/code-review ultra` executa uma revisão multi-agente na nuvem. `/security-review` verifica o diff quanto a vulnerabilidades de segurança.

**Entre sessões.** `/clear` começa do zero em uma nova tarefa mantendo a memória do projeto. `/resume` retorna a uma conversa anterior, `/branch` ramifica a atual para tentar uma direção diferente, e `/fork` a copia em uma nova [sessão em segundo plano](/docs/pt/agent-view). `/teleport` puxa uma sessão web para este terminal, e `/remote-control` permite que você continue esta sessão local de outro dispositivo.

**Quando algo está errado.** `/rewind` reverte o código e a conversa para um checkpoint, ou resume parte da conversa. `/doctor` executa uma verificação de configuração que diagnostica problemas de instalação e configuração e pode corrigi-los, `/debug` diagnostica problemas em tempo de execução, e `/feedback` relata um bug com contexto de sessão anexado.

<h2 id="all-commands">
  Todos os comandos
</h2>

A tabela abaixo lista todos os comandos incluídos no Claude Code. A maioria são comandos integrados cujo comportamento é codificado na CLI. Dois tipos de entradas são marcados:

* **[Skill](/docs/pt/skills#bundled-skills)**: uma skill agrupada. Funciona como skills que você escreve: um prompt entregue ao Claude.
  * `/verify` é executado apenas quando você o invoca. Antes da v2.1.215, Claude também podia executar `/verify` por conta própria.
* **[Workflow](/docs/pt/workflows#bundled-workflows)**: um [workflow dinâmico](/docs/pt/workflows) agrupado que distribui trabalho entre muitos subagentes e é executado em segundo plano.
  * `/deep-research` é executado apenas quando você o invoca. Antes da v2.1.218, Claude também podia iniciá-lo por conta própria.

Para adicionar seus próprios comandos, consulte [skills](/docs/pt/skills).

Na tabela abaixo, `<arg>` indica um argumento obrigatório e `[arg]` indica um opcional.

<Note>
  Nem todo comando aparece para todos os usuários. A disponibilidade depende da sua plataforma, plano e ambiente. Por exemplo, `/desktop` aparece apenas em macOS e Windows x64 quando conectado com uma assinatura Claude, e `/upgrade` não aparece em planos Enterprise.
</Note>

<h2 id="how-the-command-menu-matches-what-you-type">
  Como o menu de comandos corresponde ao que você digita
</h2>

Claude Code filtra o menu `/` conforme você digita. Cada ponto abaixo cobre uma coisa que você pode notar ao filtrar:

* **Destaque**: Claude Code destaca apenas a sugestão principal quando as letras após o `/` correspondem ao nome ou alias de um comando, desde o início do nome ou de uma palavra dentro dele, ignorando os separadores `:`, `_` e `-`. Digitar `/adddir` destaca `/add-dir`, e digitar `/new` destaca `/clear` através de seu alias. Pressione `Enter` para executar a sugestão destacada. Essas regras de destaque exigem Claude Code v2.1.236 ou posterior.
* **Após um erro de digitação**: Claude Code não destaca nada. As correspondências próximas permanecem listadas, e você pode escolher uma com `Tab` ou as teclas de seta, mas `Enter` envia seu texto conforme digitado e relata [Unknown command](/docs/pt/errors#unknown-command).
* **Comandos que não estão disponíveis para você**: Claude Code os deixa de fora do menu. Quando nada corresponde, Claude Code mostra `No commands match "/name"`. A maioria dos comandos indisponíveis retorna [Unknown command](/docs/pt/errors#unknown-command) quando você os envia; alguns, como [`/schedule` em uma chave Console API](/docs/pt/routines#schedule-returns-unknown-command), respondem com sua própria mensagem de disponibilidade. Alguns comandos também respondem com uma mensagem própria quando a política da sua organização os desativa.
* **Comandos ocultos**: Claude Code mantém alguns comandos disponíveis, como `/heapdump`, fora do menu por design. Um nome parcial nunca traz um comando oculto para o menu: se a correspondência parcial não corresponder a nada visível, Claude Code mostra a mesma mensagem de não correspondência. Claude Code lista o comando apenas depois que você digitou seu nome completo, e enviar o nome completo o executa.
