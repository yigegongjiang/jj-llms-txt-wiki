# Variáveis de ambiente

> Referência para variáveis de ambiente que controlam o comportamento do Claude Code.

Variáveis de ambiente podem controlar o comportamento do Claude Code, como seleção de modelo, autenticação, roteamento de requisições e alternâncias de recursos. Muitos dos mesmos comportamentos também podem ser configurados através de um [campo de arquivo de configurações](/docs/pt/settings), um [sinalizador CLI](/docs/pt/cli-reference) ou um comando em sessão como `/model`.

Esta página aborda como:

* [Definir variáveis de ambiente](#set-environment-variables) em seu shell ou em um arquivo de configurações
* [Verificar qual valor se aplica](#precedence) quando um comportamento pode ser definido de mais de uma forma
* [Procurar as variáveis que Claude Code lê](#variables)
* [Ver quais recursos deixam de funcionar](#features-that-need-feature-flag-fetching) quando uma variável desativa a busca de sinalizadores de recursos

<h2 id="set-environment-variables">
  Definir variáveis de ambiente
</h2>

Uma variável que você define no seu shell dura para essa sessão de terminal, enquanto uma variável em um arquivo de configurações se aplica toda vez que `claude` é executado.

<h3 id="in-your-shell">
  No seu shell
</h3>

Defina a variável antes de iniciar `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Para defini-la para cada sessão, adicione a linha `export` a `~/.bashrc`, `~/.zshrc`, ou ao arquivo de perfil do seu shell.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Para defini-la para cada sessão, execute `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` e abra um novo terminal.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Para defini-la para cada sessão, execute `setx API_TIMEOUT_MS "1200000"` e abra um novo terminal.
  </Tab>
</Tabs>

A linha de atribuição não imprime nada em caso de sucesso, então confirme se a variável está definida imprimindo-a no mesmo shell antes de executar `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    echo $API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    echo $env:API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    echo %API_TIMEOUT_MS%
    ```
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  Em arquivos de configurações
</h3>

Adicione variáveis sob a chave `env` em um arquivo `settings.json`, criando o arquivo se ele não existir. Claude Code as lê diretamente do arquivo, então elas entram em vigor independentemente de como `claude` foi iniciado. Uma sessão em execução aplica valores novos e alterados ao seu ambiente quando você salva o arquivo, mas um recurso que lê suas variáveis uma vez na inicialização, como [monitoramento OpenTelemetry](/docs/pt/monitoring-usage), mantém seus valores de inicialização até que você reinicie. Remover uma variável do arquivo não a desativa em uma sessão em execução; a remoção entra em vigor na próxima vez que você iniciar `claude`.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

O arquivo que você escolhe controla a quem as variáveis se aplicam:

| Arquivo                       | Aplica-se a                                                                                                                                           |
| :---------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | Você, em cada projeto                                                                                                                                 |
| `.claude/settings.json`       | Todos que trabalham no projeto, verificado no controle de origem                                                                                      |
| `.claude/settings.local.json` | Você, apenas neste projeto, ignorado pelo git quando Claude Code salva uma configuração nele; adicione-o ao seu gitignore se você o criar manualmente |
| Configurações gerenciadas     | Todos na sua organização, implantados por um administrador                                                                                            |

Veja [Arquivos de configurações](/docs/pt/settings#where-settings-live) para saber onde cada arquivo fica e [Precedência de configurações](/docs/pt/settings#settings-precedence) para saber como eles se combinam quando mais de um define a mesma variável.

<h2 id="precedence">
  Precedência
</h2>

Alguns comportamentos têm tanto uma variável de ambiente quanto uma chave de configurações dedicada, e qual delas Claude Code lê primeiro difere por chave. Para `ANTHROPIC_MODEL` e `CLAUDE_CODE_AUTO_CONNECT_IDE`, Claude Code lê a variável primeiro e usa a configuração `model` ou `autoConnectIde` apenas quando a variável não está definida. Para o par que você está configurando, verifique a linha da variável abaixo e a entrada da chave na [referência de configurações](/docs/pt/settings-reference).

Quando a mesma variável está definida tanto no seu shell quanto em um bloco `env` do arquivo de configurações, o valor do arquivo de configurações se aplica. Claude Code escreve cada entrada `env` no ambiente do processo, substituindo o valor herdado do shell. A [configuração `env`](/docs/pt/settings-reference#when-claude-code-applies-env-values) diz quando ela se aplica. Algumas variáveis são casos especiais; a [configuração `env`](/docs/pt/settings-reference#env) lista as exceções.

Em um arquivo de configurações você pode definir uma variável, mas não pode remover uma. Para substituir uma variável que você não pode desativar, como uma `CLAUDE_CODE_USE_VERTEX` obsoleta exportada por um perfil de shell que você não controla, defina-a como uma string vazia no bloco `env`: `"CLAUDE_CODE_USE_VERTEX": ""`. Claude Code trata o valor vazio como não definido para seleção de provedor. Subprocessos ainda herdam o valor vazio.

Entre arquivos de configurações, os valores `env` seguem a [precedência de configurações](/docs/pt/settings#settings-precedence), então uma entrada de configurações gerenciada substitui a mesma variável nas configurações de usuário ou projeto.

Como uma variável de ambiente interage com sinalizadores CLI e comandos em sessão varia por recurso: `--model` e `/model` substituem `ANTHROPIC_MODEL`, enquanto `CLAUDE_CODE_EFFORT_LEVEL` substitui `--effort` e `/effort`. Quando uma variável interage com outra fonte de configuração, sua linha na lista [Variáveis](#variables) declara a precedência ou vincula à página que a documenta.

Claude Code lê variáveis de ambiente do shell na inicialização, então as alterações nelas entram em vigor na próxima vez que você inicia `claude`. As variáveis definidas sob a chave `env` em arquivos de configurações são reaplicadas a uma sessão em execução quando o arquivo muda, com a exceção somente na inicialização descrita em [Em arquivos de configurações](#in-settings-files).

<h2 id="variables">
  Variáveis
</h2>

Variáveis numéricas como timeouts, orçamentos de tokens e contagens de tentativas aceitam notação científica e grafias com separadores de dígitos além de dígitos simples, exceto onde a linha de uma variável observa que ela aceita apenas dígitos simples. Por exemplo, Claude Code lê `2e3` como 2000 e `64_000` como 64000. Antes da v2.1.211, essas grafias poderiam silenciosamente definir um valor muito menor, como `1e6` definindo um timeout para 1.

<Note>
  Para variáveis que ativam ou desativam um comportamento, defina `1` ou `true` para ativar e `0` ou `false` para desativar, em qualquer capitalização.

  Algumas variáveis leem apenas se você as definiu, então qualquer valor não vazio, incluindo `0`, ativa o comportamento, e você desativa o comportamento ao desconfigurar a variável ou defini-la como um valor vazio. Essas variáveis funcionam dessa forma:

  * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
  * `DISABLE_TELEMETRY`
  * `DISABLE_ERROR_REPORTING`
  * `CLAUDE_CODE_TMUX_TRUECOLOR`
  * `FALLBACK_FOR_ALL_PRIMARY_MODELS`
  * `IS_DEMO`

  Uma outra variável tem sua própria regra: `FORCE_HYPERLINK` lê um número, então apenas `0` a desativa. A linha de cada variável também declara sua própria regra.
</Note>

<h2 id="features-that-need-feature-flag-fetching">
  Recursos que precisam de busca de feature-flag
</h2>

Claude Code ativa alguns recursos através de feature flags que busca da Anthropic. Claude Code pula essa busca nestas sessões:

* Uma sessão onde você define `DISABLE_GROWTHBOOK`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK`, ou `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`; a linha de cada variável na [tabela de variáveis](#variables) diz quais valores desativam a busca
* Uma sessão em um [provedor de terceiros](/docs/pt/third-party-integrations), como Amazon Bedrock, Claude Platform na AWS, Agent Platform do Google Cloud, ou Microsoft Foundry, a menos que uma plataforma host que incorpora Claude Code defina `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
* Uma sessão de [gateway de aplicativos Claude](/docs/pt/claude-apps-gateway)

Com a busca desativada, você não pode:

* [Iniciar sessões em modo automático por padrão](/docs/pt/permission-modes#which-mode-a-session-starts-in) em planos Pro, Max e Team
* Ter a extensão VS Code [ler arquivos de configuração para o modo de permissão inicial](/docs/pt/permission-modes#switch-permission-modes)

<h3 id="first-session-after-an-install-or-upgrade">
  Primeira sessão após uma instalação ou atualização
</h3>

Na sua primeira sessão após instalar Claude Code, ou atualizar para uma versão que adiciona um recurso, um [recurso com gate de flag](#features-that-need-feature-flag-fetching) pode estar faltando, e a sessão pode iniciar em modo Manual em um plano que de outra forma iniciaria em modo automático. Claude Code busca as flags durante essa sessão, então ambas estão lá na sua próxima sessão.

Após uma instalação limpa, em uma sessão não interativa como `claude -p`, o Agent SDK, ou a extensão VS Code, Claude Code ainda pode pegar as flags antes de [escolher o modo de permissão inicial](/docs/pt/permission-modes#which-mode-a-session-starts-in).
