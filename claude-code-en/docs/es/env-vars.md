# Variables de entorno

> Referencia para variables de entorno que controlan el comportamiento de Claude Code.

Las variables de entorno pueden controlar el comportamiento de Claude Code, como la selección de modelo, autenticación, enrutamiento de solicitudes y alternadores de características. Muchos de los mismos comportamientos también se pueden configurar a través de un campo de [archivo de configuración](/docs/es/settings), una [bandera CLI](/docs/es/cli-reference) o un comando en sesión como `/model`.

Esta página cubre cómo:

* [Establecer variables de entorno](#set-environment-variables) en su shell o en un archivo de configuración
* [Verificar qué valor se aplica](#precedence) cuando un comportamiento se puede establecer de más de una manera
* [Buscar las variables que Claude Code lee](#variables)
* [Ver qué características dejan de funcionar](#features-that-need-feature-flag-fetching) cuando una variable desactiva la obtención de marcas de características

<h2 id="set-environment-variables">
  Establecer variables de entorno
</h2>

Una variable que establezca en su shell dura durante esa sesión de terminal, mientras que una variable en un archivo de configuración se aplica cada vez que se ejecuta `claude`.

<h3 id="in-your-shell">
  En su shell
</h3>

Establezca la variable antes de lanzar `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Para establecerla para cada sesión, agregue la línea `export` a `~/.bashrc`, `~/.zshrc`, o el archivo de perfil de su shell.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Para establecerla para cada sesión, ejecute `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` y abra una nueva terminal.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Para establecerla para cada sesión, ejecute `setx API_TIMEOUT_MS "1200000"` y abra una nueva terminal.
  </Tab>
</Tabs>

La línea de asignación no imprime nada en caso de éxito, así que confirme que la variable está establecida imprimiéndola en el mismo shell antes de ejecutar `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    echo $API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    echo $env:API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    echo %API_TIMEOUT_MS%
    ```
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  En archivos de configuración
</h3>

Agregue variables bajo la clave `env` en un archivo `settings.json`, creando el archivo si no existe. Claude Code las lee directamente del archivo, por lo que surten efecto sin importar cómo se haya lanzado `claude`. Una sesión en ejecución aplica valores nuevos y modificados a su entorno cuando guarda el archivo, pero una característica que lee sus variables una sola vez al inicio, como [monitoreo de OpenTelemetry](/docs/es/monitoring-usage), mantiene sus valores de inicio hasta que relance. Eliminar una variable del archivo no la desestablece en una sesión en ejecución; la eliminación surte efecto la próxima vez que lance `claude`.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

El archivo que elija controla a quién se aplican las variables:

| Archivo                       | Se aplica a                                                                                                                                       |
| :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| `~/.claude/settings.json`     | Usted, en cada proyecto                                                                                                                           |
| `.claude/settings.json`       | Todos los que trabajan en el proyecto, registrado en el control de fuente                                                                         |
| `.claude/settings.local.json` | Usted, solo en este proyecto, ignorado por git cuando Claude Code guarda una configuración en él; agréguelo a su gitignore si lo crea manualmente |
| Configuración administrada    | Todos en su organización, implementado por un administrador                                                                                       |

Consulte [Archivos de configuración](/docs/es/settings#where-settings-live) para saber dónde vive cada archivo y [Precedencia de configuración](/docs/es/settings#settings-precedence) para saber cómo se combinan cuando más de uno establece la misma variable.

<h2 id="precedence">
  Precedencia
</h2>

Algunos comportamientos tienen tanto una variable de entorno como una clave de configuración dedicada, y cuál lee primero Claude Code difiere según la clave. Para `ANTHROPIC_MODEL` y `CLAUDE_CODE_AUTO_CONNECT_IDE`, Claude Code lee primero la variable y utiliza la configuración `model` o `autoConnectIde` solo cuando la variable no está establecida. Para el par que está configurando, verifique la fila de la variable a continuación y la entrada de la clave en la [referencia de configuración](/docs/es/settings-reference).

Cuando la misma variable se establece tanto en su shell como en un bloque `env` de archivo de configuración, se aplica el valor del archivo de configuración. Claude Code escribe cada entrada `env` en el entorno del proceso, reemplazando el valor heredado del shell. La [configuración `env`](/docs/es/settings-reference#when-claude-code-applies-env-values) indica cuándo se aplica. Algunas variables tienen casos especiales; la [configuración `env`](/docs/es/settings-reference#env) enumera las excepciones.

En un archivo de configuración puede establecer una variable pero no puede eliminar una. Para anular una variable que no puede desestablecer, como una `CLAUDE_CODE_USE_VERTEX` obsoleta exportada por un perfil de shell que no controla, establézcala en una cadena vacía en el bloque `env`: `"CLAUDE_CODE_USE_VERTEX": ""`. Claude Code trata el valor vacío como no establecido para la selección de proveedor. Los subprocesos aún heredan el valor vacío.

Entre archivos de configuración, los valores `env` siguen la [precedencia de configuración](/docs/es/settings#settings-precedence), por lo que una entrada de configuración administrada anula la misma variable en la configuración de usuario o proyecto.

Cómo una variable de entorno interactúa con banderas CLI y comandos en sesión varía según la característica: `--model` y `/model` anulan `ANTHROPIC_MODEL`, mientras que `CLAUDE_CODE_EFFORT_LEVEL` anula `--effort` y `/effort`. Cuando una variable interactúa con otra fuente de configuración, su fila en la lista [Variables](#variables) indica la precedencia o vincula a la página que la documenta.

Claude Code lee las variables de entorno del shell al iniciar, por lo que los cambios en ellas surten efecto la próxima vez que inicia `claude`. Las variables establecidas bajo la clave `env` en archivos de configuración se reaplicarán a una sesión en ejecución cuando el archivo cambie, con la excepción de solo inicio descrita en [En archivos de configuración](#in-settings-files).

<h2 id="variables">
  Variables
</h2>

Las variables numéricas como tiempos de espera, presupuestos de tokens y conteos de reintentos aceptan notación científica y deletreos con separadores de dígitos además de dígitos simples, excepto donde la fila de una variable indica que solo acepta dígitos simples. Por ejemplo, Claude Code lee `2e3` como 2000 y `64_000` como 64000. Antes de v2.1.211, estos deletreos podían establecer silenciosamente un valor mucho más pequeño, como `1e6` estableciendo un tiempo de espera a 1.

<Note>
  Para variables que activan o desactivan un comportamiento, establezca `1` o `true` para activarlo y `0` o `false` para desactivarlo, en cualquier mayúscula.

  Algunas variables solo leen si las establece en absoluto, por lo que cualquier valor no vacío, incluido `0`, activa el comportamiento, y desactiva el comportamiento desestableciendo la variable o estableciéndola en un valor vacío. Estas variables funcionan de esa manera:

  * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
  * `DISABLE_TELEMETRY`
  * `DISABLE_ERROR_REPORTING`
  * `CLAUDE_CODE_TMUX_TRUECOLOR`
  * `FALLBACK_FOR_ALL_PRIMARY_MODELS`
  * `IS_DEMO`

  Otra variable tiene su propia regla: `FORCE_HYPERLINK` lee un número, por lo que solo `0` la desactiva. La fila de cada variable también establece su propia regla.
</Note>

<h2 id="features-that-need-feature-flag-fetching">
  Características que necesitan obtención de banderas de características
</h2>

Claude Code activa algunas características a través de banderas de características que obtiene de Anthropic. Claude Code omite esa obtención en estas sesiones:

* Una sesión donde usted establece `DISABLE_GROWTHBOOK`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK`, o `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`; la fila de cada variable en la [tabla de variables](#variables) indica qué valores desactivan la obtención
* Una sesión en un [proveedor de terceros](/docs/es/third-party-integrations), como Amazon Bedrock, Claude Platform en AWS, Agent Platform de Google Cloud, o Microsoft Foundry, a menos que una plataforma anfitriona que integre Claude Code establezca `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
* Una sesión de [puerta de enlace de aplicaciones Claude](/docs/es/claude-apps-gateway)

Con la obtención desactivada, usted no puede:

* [Iniciar sesiones en modo automático de forma predeterminada](/docs/es/permission-modes#which-mode-a-session-starts-in) en planes Pro, Max y Team
* Hacer que la extensión de VS Code [lea archivos de configuración para el modo de permiso inicial](/docs/es/permission-modes#switch-permission-modes)
* Ejecutar [`/auto-mode-setup`](/docs/es/auto-mode-config#generate-environment-entries) para redactar entradas de `autoMode.environment`
* Usar [Control Remoto](/docs/es/remote-control#requirements)
* [Enviar mensajes a sesiones más allá de esta máquina](/docs/es/cross-session-messaging#message-sessions-on-other-machines); la mensajería entre sesiones en esta máquina funciona con la obtención desactivada
* Ejecutar [`claude import` o el comando `/import`](/docs/es/cli-reference#cli-commands)
* Ejecutar [`/skill-doctor`](/docs/es/skills#find-unused-skills) o abrir su informe en la pestaña **Stats** de `/plugin`
* Sincronizar las [skills](/docs/es/skills#where-synced-skills-load) y [plugins](/docs/es/plugins-reference#synced-plugins) habilitados para su cuenta de claude.ai en sus sesiones de terminal
* Usar [la herramienta asesor](/docs/es/advisor#requirements)
* Leer o responder a [comentarios en un artefacto](/docs/es/artifacts#collect-comments-on-an-artifact)
* Hacer que Claude Code sondee servidores conectores de claude.ai para [revisión del protocolo MCP 2026-07-28](/docs/es/mcp#mcp-client-runtimes) a menos que usted establezca `MCP_PROTOCOL_NEGOTIATION=auto`
* Obtener [la herramienta PowerShell](/docs/es/tools-reference#powershell-tool) de forma predeterminada para cuentas de claude.ai y Console en Windows con Git Bash instalado; Claude Code enruta comandos de shell a través de Git Bash a menos que usted establezca `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`. En Windows sin Git Bash, la herramienta permanece activada
* Obtener [comentarios redactados por Claude](/docs/es/tools-reference#sendfeedback-tool-behavior), que Claude Code activa a través de una bandera obtenida
* Hacer que Claude [trate pastas grandes como texto pegado en lugar de texto escrito](/docs/es/terminal-config#how-claude-treats-pasted-text); el contenido detrás de un marcador de posición `[Pasted text #N]` llega a Claude sin marcar
* Hacer que Claude Code [excluya herramientas MCP cuyo esquema de entrada la API rechazaría](/docs/es/mcp#tools-with-invalid-input-schemas); envía el esquema de todas formas, y una solicitud que lo incluye falla con [un error 400 que nombra la herramienta por su posición](/docs/es/errors#tool-input-schema-is-invalid)

<h3 id="first-session-after-an-install-or-upgrade">
  Primera sesión después de una instalación o actualización
</h3>

En su primera sesión después de instalar Claude Code, o actualizar a una versión que añade una característica, una [característica protegida por bandera](#features-that-need-feature-flag-fetching) puede estar ausente, y la sesión puede iniciarse en modo Manual en un plan que de otro modo se iniciaría en modo automático. Claude Code obtiene las banderas durante esa sesión, por lo que ambas están presentes en su próxima sesión.

Después de una instalación nueva, en una sesión no interactiva como `claude -p`, el SDK del Agent, o la extensión de VS Code, Claude Code aún puede obtener las banderas antes de [elegir el modo de permiso inicial](/docs/es/permission-modes#which-mode-a-session-starts-in).
