# Variables de entorno

> Referencia para variables de entorno que controlan el comportamiento de Claude Code.

Las variables de entorno pueden controlar el comportamiento de Claude Code, como la selección de modelo, autenticación, enrutamiento de solicitudes y alternadores de características. Muchos de los mismos comportamientos también se pueden configurar a través de un [archivo de configuración](/docs/es/settings), una [bandera CLI](/docs/es/cli-reference) o un comando en sesión como `/model`.

Esta página cubre cómo:

* [Establecer variables de entorno](#set-environment-variables) en su shell o en un archivo de configuración
* [Verificar qué valor se aplica](#precedence) cuando un comportamiento se puede establecer de más de una manera
* [Buscar las variables que Lee Claude Code](#variables)

<h2 id="set-environment-variables">
  Establecer variables de entorno
</h2>

Una variable que establezca en su shell dura para esa sesión de terminal, mientras que una variable en un archivo de configuración se aplica cada vez que se ejecuta `claude`.

<h3 id="in-your-shell">
  En su shell
</h3>

Establezca la variable antes de lanzar `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Para establecerlo para cada sesión, agregue la línea `export` a `~/.bashrc`, `~/.zshrc` o el archivo de perfil de su shell.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Para establecerlo para cada sesión, ejecute `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` y abra una nueva terminal.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Para establecerlo para cada sesión, ejecute `setx API_TIMEOUT_MS "1200000"` y abra una nueva terminal.
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  En archivos de configuración
</h3>

Agregue variables bajo la clave `env` en un archivo `settings.json`. Claude Code las lee directamente del archivo al inicio, por lo que surten efecto sin importar cómo se lanzó `claude`.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

El archivo que elija controla a quién se aplican las variables:

| Archivo                       | Se aplica a                                                                    |
| :---------------------------- | :----------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | Usted, en cada proyecto                                                        |
| `.claude/settings.json`       | Todos los que trabajan en el proyecto, registrado en control de fuente         |
| `.claude/settings.local.json` | Usted, solo en este proyecto (agréguelo a su gitignore si lo crea manualmente) |
| Configuración administrada    | Todos en su organización, implementado por un administrador                    |

Consulte [Archivos de configuración](/docs/es/settings#settings-files) para saber dónde vive cada archivo y [Precedencia de configuración](/docs/es/settings#settings-precedence) para saber cómo se combinan cuando más de uno establece la misma variable.

<h2 id="precedence">
  Precedencia
</h2>

Cuando el mismo comportamiento tiene tanto una variable de entorno como un campo de configuración, la variable de entorno tiene precedencia. Por ejemplo, `ANTHROPIC_MODEL` anula la configuración `model`, y `CLAUDE_CODE_AUTO_CONNECT_IDE` anula `autoConnectIde`. El campo de configuración se aplica cuando la variable de entorno no está establecida.

Cuando la misma variable se establece tanto en su shell como en un archivo de configuración bloque `env`, se aplica el valor del archivo de configuración. Claude Code escribe cada entrada `env` en el entorno del proceso al inicio, reemplazando el valor heredado del shell. Algunas variables tienen casos especiales; la [configuración `env`](/docs/es/settings#available-settings) enumera las excepciones.

Entre archivos de configuración, los valores `env` siguen la [precedencia de configuración](/docs/es/settings#settings-precedence), por lo que una entrada de configuración administrada anula la misma variable en la configuración de usuario o proyecto.

Cómo una variable de entorno interactúa con banderas CLI y comandos en sesión varía por característica: `--model` y `/model` anulan `ANTHROPIC_MODEL`, mientras que `CLAUDE_CODE_EFFORT_LEVEL` anula `/effort`. Cuando una variable interactúa con otra fuente de configuración, su fila en la lista [Variables](#variables) indica la precedencia o vincula a la página que la documenta.

Claude Code lee variables de entorno al inicio, por lo que los cambios surten efecto la próxima vez que lance `claude`.
