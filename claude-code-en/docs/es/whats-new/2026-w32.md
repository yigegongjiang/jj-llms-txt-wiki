# Semana 32 · 3–7 de agosto de 2026

> Las sesiones de Claude Code se envían mensajes entre sí, los entornos autohospedados ejecutan sesiones en la nube en su infraestructura, y el modo automático se convierte en el modo de permiso predeterminado.

<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Mensajería entre sesiones</span>
    <span className="digest-feature-pill">v2.1.224</span>
  </div>

  <p className="digest-feature-lede">Sus sesiones de Claude Code ahora pueden enviarse mensajes entre sí. Claude descubre sus otras sesiones con la herramienta <code>ListAgents</code> y envía con <code>SendMessage</code>, ya sea cuando usted se lo pide o por su cuenta, como después de que un cambio en una sesión afecte lo que otra está haciendo. Un mensaje es texto que Claude escribe para la otra sesión, nunca su historial de conversación o archivos. Disponible en macOS y Linux. Requiere v2.1.224 o posterior.</p>

  <Frame>
    <video autoPlay muted loop playsInline className="w-full" src="https://mintcdn.com/claude-code/N3yEaTYPXMXFrF6k/images/whats-new/cross-session-messaging.mp4?fit=max&auto=format&n=N3yEaTYPXMXFrF6k&q=85&s=8f33c3390f78660a4a26dc980f46159f" data-path="images/whats-new/cross-session-messaging.mp4" />
  </Frame>

  <p className="digest-feature-try">Con dos sesiones abiertas en la misma máquina, pídale a una de ellas que transmita algo:</p>

  ```text title="Claude Code" wrap theme={null}
  Tell the session working on the payments API that users.name is now users.display_name
  ```

  <p className="digest-feature-try">La otra sesión muestra una fila <code>Message from</code> una vez que Claude ha leído el mensaje; presione <code>Ctrl+O</code> para expandirla. Para ver qué sesiones puede alcanzar Claude, ejecute <code>/list-agents</code>.</p>

  <a className="digest-feature-link" href="/docs/es/cross-session-messaging#message-another-session">Enviar mensaje a otra sesión</a>
</div>

<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">Entornos autohospedados</span>
    <span className="digest-feature-pill">v2.1.224</span>
  </div>

  <p className="digest-feature-lede">Los entornos autohospedados ejecutan sesiones en la nube de Claude Code en la infraestructura propia de su organización, en versión beta pública en planes Team y Enterprise. Ejecute <code>claude self-hosted-runner</code> en sus máquinas o contenedores para convertirlos en ejecutores. Cuando alguien elige su entorno al iniciar una sesión desde claude.ai, las aplicaciones móviles o de escritorio, o `claude --cloud`, esa sesión se ejecuta dentro de su red, con acceso a sus servicios internos. Un propietario activa <strong>Allow self-hosted environments</strong> en <a href="https://claude.ai/admin-settings/cloud-environments">configuración de administrador</a> primero.</p>

  <Frame>
    <img className="w-full" src="https://mintcdn.com/claude-code/N3yEaTYPXMXFrF6k/images/whats-new/self-hosted-environments.jpg?fit=max&auto=format&n=N3yEaTYPXMXFrF6k&q=85&s=ae9152cb1670c8af517d1aee57689b14" alt="La página de administrador de entornos autohospedados que enumera entornos como linux-dev y macos-prod con su estado y recuentos de sesiones activas" width="2048" height="1152" data-path="images/whats-new/self-hosted-environments.jpg" />
  </Frame>

  <p className="digest-feature-try">Iniciado sesión como propietario, ejecute la configuración guiada, que le guía a través de la creación del entorno e inicia un ejecutor:</p>

  ```bash terminal theme={null}
  claude self-hosted-runner setup
  ```

  <p className="digest-feature-try">El entorno muestra <strong>Healthy</strong> en la configuración de administrador una vez que el ejecutor se registra.</p>

  <a className="digest-feature-link" href="/docs/es/self-hosted-environments-quickstart#set-up-an-environment-and-runner">Guía rápida de entornos autohospedados</a>

<div className="digest-feature">
  <div className="digest-feature-header">
    <span className="digest-feature-title">El modo automático se convierte en el predeterminado</span>
    <span className="digest-feature-pill">CLI</span>
  </div>

  <p className="digest-feature-lede">A partir del 14 de agosto, el modo automático es el modo de permiso predeterminado para nuevas sesiones en planes Pro, Max y Team. Si establece un modo predeterminado usted mismo, permanece en su lugar a menos que acepte el mensaje de cambio único, y un predeterminado que su organización administra no cambia. Aún puede cambiar de modo en cualquier momento. Ya en vigor en esos planes: los clasificadores que el modo automático realiza ya no cuentan hacia sus límites de uso.</p>

  <p className="digest-feature-try">Para iniciar cada sesión en modo automático antes del cambio, establézcalo como predeterminado en su configuración de usuario:</p>

  ```json ~/.claude/settings.json {3} theme={null}
  {
    "permissions": {
      "defaultMode": "auto"
    }
  }
  ```

  <p className="digest-feature-try">Las nuevas sesiones entonces muestran <code>auto mode on</code> en la barra de estado.</p>

  <a className="digest-feature-link" href="/docs/es/permission-modes#eliminate-prompts-with-auto-mode">Requisitos y controles del modo automático</a>
</div>

<div className="digest-wins">
  <p className="digest-wins-title">Otros logros</p>

  <div className="digest-wins-grid">
    <div>La extensión de VS Code obtiene <a href="/docs/es/vs-code#extension-settings">Vista de enfoque</a>, que oculta la actividad de herramientas detrás de una fila expandible por turno; actívela desde el menú de comandos o con <code>Ctrl+Alt+F</code> (<code>Ctrl+Option+F</code> en Mac)</div>
    <div>Los archivos de credenciales de sandbox aceptan <a href="/docs/es/sandboxing#mask-credential-files"><code>mode: "mask"</code></a> en Linux y WSL2, por lo que los comandos en sandbox leen una copia centinela mientras el proxy de sandbox sustituye el valor real en la salida; el enmascaramiento de credenciales también gana opciones <code>extract</code>, <code>decode</code> consciente de JWT y re-firma de AWS SigV4</div>
    <div>Los mercados pueden distribuir un plugin como un <a href="/docs/es/plugins/marketplace-reference#archive-plugin-source">archivo zip</a> con la nueva fuente <code>archive</code>, descargada sobre HTTPS con un pin SHA-256 opcional, por lo que las instalaciones funcionan sin git o npm</div>
    <div><code>/review</code> ahora es un alias de <a href="/docs/es/code-review#review-a-diff-locally"><code>/code-review</code></a>, y <code>/code-review</code> sin nivel de esfuerzo reutiliza el nivel que escribió por última vez</div>
    <div>Una sesión que copia con <a href="/docs/es/agent-view#copy-the-session-with-%2Ffork"><code>/fork</code></a> ahora realiza sus cambios de código en un worktree propio en lugar del checkout de la sesión original</div>
    <div>Los plugins que instala desde <a href="/docs/es/plugins/install#install-a-plugin"><code>/plugin</code></a> se activan en la sesión actual cuando es seguro hacerlo; el resumen de instalación reporta <code>Plugin is now active.</code> o le dice que ejecute <code>/reload-plugins</code></div>
    <div><a href="/docs/es/agent-view#how-file-edits-are-isolated">Las sesiones en segundo plano</a> que cambiaron código en un worktree ahora confirman e impulsan antes de terminar, abren una solicitud de extracción de borrador solo cuando la tarea lo requiere, y siguen las instrucciones de git en su <code>CLAUDE.md</code></div>
    <div>Se elimina el límite de 200 subagentes por sesión, por lo que las sesiones de larga duración ya no rechazan nuevos subagentes; los límites de <a href="/docs/es/sub-agents#concurrent-subagent-limit">concurrencia</a> y profundidad aún se aplican</div>
    <div>La configuración registrada de un repositorio ya no puede activar <a href="/docs/es/remote-control#enable-remote-control-for-all-sessions">Conexión automática de control remoto</a>; establezca <code>remoteControlAtStartup</code> en su configuración de usuario o administrada en su lugar, y la configuración de proyecto y local solo puede desactivarla</div>
    <div><a href="/docs/es/worktrees#how-claude-code-enforces-isolation">El aislamiento de worktree</a> ahora bloquea no solo ediciones de archivos sino también comandos Bash y redirecciones de git que llegan al checkout principal, en cada tipo de sesión y en los subagentes de la sesión</div>
    <div>Un comando Bash ya no puede ocultar parte de sí mismo de las verificaciones de permisos, y el relleno de tabulación o Unicode invisible ya no oculta parte de un comando del diálogo de aprobación</div>
    <div>Los hooks de auto-permitir PreToolUse ya no omiten las restricciones de herramientas en las tareas internas de Claude Code, como resúmenes y compactación</div>
    <div>La <a href="/docs/es/ultraplan">vista previa de investigación de Ultraplan</a> se elimina, incluido el comando <code>/ultraplan</code> y la palabra clave <code>ultraplan</code>; use el modo de plan o Claude Code en la web en su lugar</div>
  </div>
</div>
