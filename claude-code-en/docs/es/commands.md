# Comandos

> Referencia completa de comandos disponibles en Claude Code, incluidos comandos integrados y skills incluidas.

Los comandos controlan Claude Code desde dentro de una sesión. Proporcionan una forma rápida de cambiar modelos, gestionar permisos, limpiar contexto, ejecutar un flujo de trabajo y más.

Escriba `/` para ver los comandos disponibles para usted, o escriba `/` seguido de letras para filtrar. [Cómo el menú de comandos coincide con lo que escribe](#how-the-command-menu-matches-what-you-type) cubre el resaltado, errores tipográficos y los pocos comandos que Claude Code oculta del menú hasta que escribe su nombre completo.

Un comando solo se reconoce al inicio de su mensaje. El texto que sigue al nombre del comando se convierte en sus argumentos. A partir de v2.1.199, [skills](/docs/es/skills#pass-arguments-to-skills) son la excepción: una invocación de skill seguida de más skills, como `/skill-a /skill-b do XYZ`, carga cada skill nombrada al inicio y pasa el texto final a cada una como argumentos. Se pueden encadenar hasta seis skills.

Si envía un comando mientras Claude está respondiendo, Claude Code lo pone en cola y lo ejecuta después de que termine el turno actual. Claude Code ejecuta algunos comandos inmediatamente sin interrumpir la respuesta, como `/status`, `/tasks` y `/usage`. En [fullscreen rendering](/docs/es/fullscreen), Claude Code también abre comandos de diálogo como `/theme` y `/help` inmediatamente. Antes de v2.1.234, Claude Code ponía esos diálogos en cola hasta que terminaba el turno.

<h2 id="commands-across-a-typical-workflow">
  Comandos en un flujo de trabajo típico
</h2>

La mayoría de los comandos son útiles en un punto específico de una sesión, desde la configuración de un proyecto hasta el envío de un cambio.

**Primera sesión en un repositorio.** Ejecute `/init` para generar un `CLAUDE.md` inicial, luego `/memory` para refinarlo. Use `/mcp` para configurar cualquier servidor que el proyecto necesite, pida a Claude que cree cualquier [subagente](/docs/es/sub-agents) que desee, y ejecute `/permissions` para establecer sus reglas de aprobación.

**Durante una tarea.** `/plan` cambia al modo plan antes de un cambio grande. `/model` y `/effort` ajustan qué modelo está utilizando y cuánto razonamiento aplica. Cuando la conversación se alarga, `/context` muestra qué está llenando la ventana y `/compact` la resume para liberar espacio. Use `/btw` para una pregunta secundaria que no debería agregarse al historial de conversación.

**Ejecutar trabajo en paralelo.** Claude delega tareas secundarias a [subagentes](/docs/es/sub-agents), y `/tasks` enumera el trabajo en segundo plano de la sesión actual, incluidos los subagentes que han terminado. `/background` desvincula toda la sesión para que continúe ejecutándose como un [agente en segundo plano](/docs/es/agent-view) y libera su terminal. Para un cambio grande que abarca la base de código, `/batch` lo descompone en unidades independientes y ejecuta cada una en su propio [worktree](/docs/es/worktrees). Consulte [Ejecutar agentes en paralelo](/docs/es/agents) para ver cómo se relacionan estos enfoques.

**Antes de enviar.** `/diff` muestra qué cambió. `/code-review` verifica el diff actual en busca de errores de corrección y puede aplicar los hallazgos con `--fix`; pase un número de PR, como `/code-review high 1234`, para revisar una solicitud de extracción en su lugar. `/review` es un alias. `/code-review ultra` ejecuta una revisión multiagente en la nube. `/security-review` verifica el diff en busca de vulnerabilidades de seguridad.

**Entre sesiones.** `/clear` comienza de nuevo en una nueva tarea mientras mantiene la memoria del proyecto. `/resume` regresa a una conversación anterior, `/branch` ramifica la actual para probar una dirección diferente, y `/fork` la copia en una nueva [sesión en segundo plano](/docs/es/agent-view). `/teleport` extrae una sesión web en esta terminal, y `/remote-control` le permite continuar esta sesión local desde otro dispositivo.

**Cuando algo está mal.** `/rewind` revierte el código y la conversación a un checkpoint, o resume parte de la conversación. `/doctor` ejecuta una verificación de configuración que diagnostica problemas de instalación y configuración y puede repararlos, `/debug` diagnostica problemas en tiempo de ejecución, y `/feedback` reporta un error con el contexto de la sesión adjunto.

<h2 id="all-commands">
  Todos los comandos
</h2>

La tabla siguiente enumera todos los comandos incluidos en Claude Code. La mayoría son comandos integrados cuyo comportamiento está codificado en la CLI. Dos tipos de entradas están marcadas:

* **[Skill](/docs/es/skills#bundled-skills)**: una skill agrupada. Funciona como las skills que escribes tú mismo: un prompt entregado a Claude.
  * `/verify` se ejecuta solo cuando lo invocas. Antes de v2.1.215, Claude también podía ejecutar `/verify` por su cuenta.
* **[Workflow](/docs/es/workflows#bundled-workflows)**: un [workflow dinámico](/docs/es/workflows) agrupado que distribuye el trabajo entre muchos subagentes y se ejecuta en segundo plano.
  * `/deep-research` se ejecuta solo cuando lo invocas. Antes de v2.1.218, Claude también podía iniciarlo por su cuenta.

Para agregar tus propios comandos, consulta [skills](/docs/es/skills).

En la tabla siguiente, `<arg>` indica un argumento requerido y `[arg]` indica uno opcional.

<Note>
  No todos los comandos aparecen para todos los usuarios. La disponibilidad depende de tu plataforma, plan y entorno. Por ejemplo, `/desktop` solo aparece en macOS y Windows x64 cuando has iniciado sesión con una suscripción de Claude, y `/upgrade` no aparece en planes Enterprise.
</Note>

<h2 id="how-the-command-menu-matches-what-you-type">
  Cómo el menú de comandos coincide con lo que escribe
</h2>

Claude Code filtra el menú `/` mientras escribe. Cada punto a continuación cubre una cosa que podría notar mientras filtra:

* **Resaltado**: Claude Code resalta la sugerencia superior solo cuando las letras después de `/` coinciden con el nombre o alias de un comando, desde el inicio del nombre o desde una palabra dentro de él, ignorando los separadores `:`, `_` y `-`. Escribir `/adddir` resalta `/add-dir`, y escribir `/new` resalta `/clear` a través de su alias. Presione `Enter` para ejecutar la sugerencia resaltada. Estas reglas de resaltado requieren Claude Code v2.1.236 o posterior.
* **Después de un error de escritura**: Claude Code no resalta nada. Las coincidencias cercanas permanecen listadas, y puede elegir una con `Tab` o las teclas de flecha, pero `Enter` envía su texto tal como está escrito e informa [Unknown command](/docs/es/errors#unknown-command).
* **Comandos que no están disponibles para usted**: Claude Code los excluye del menú. Cuando nada coincide, Claude Code muestra `No commands match "/name"`. La mayoría de los comandos no disponibles devuelven [Unknown command](/docs/es/errors#unknown-command) cuando los envía; algunos, como [`/schedule` en una clave de API de Console](/docs/es/routines#schedule-returns-unknown-command), responden con su propio mensaje de disponibilidad en su lugar. Algunos comandos también responden con un mensaje propio cuando la política de su organización los desactiva.
* **Comandos ocultos**: Claude Code mantiene algunos comandos disponibles, como `/heapdump`, fuera del menú por diseño. Un nombre parcial nunca trae un comando oculto al menú: si la coincidencia parcial no coincide con nada visible, Claude Code muestra el mismo mensaje de no coincidencia. Claude Code lista el comando solo una vez que ha escrito su nombre completo, y enviar el nombre completo lo ejecuta.
