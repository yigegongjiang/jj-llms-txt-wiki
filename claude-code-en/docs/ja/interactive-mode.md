# インタラクティブモード

> Claude Code セッションのキーボードショートカット、入力モード、インタラクティブ機能の完全なリファレンス。

<h2 id="keyboard-shortcuts">
  キーボードショートカット
</h2>

<Note>
  キーボードショートカットはプラットフォームとターミナルによって異なる場合があります。[フルスクリーンレンダリング](/docs/ja/fullscreen)では、トランスクリプトビューアで `?` を押すと、そこで利用可能なショートカットが表示されます。

  **macOS ユーザー**: Option/Alt キーショートカット（`Alt+B`、`Alt+F`、`Alt+D`、`Alt+Y`、`Alt+P`）を使用するには、ターミナルで Option を Meta として設定する必要があります。各ターミナルの設定については、[macOS で Option キーショートカットを有効にする](/docs/ja/terminal-config#enable-option-key-shortcuts-on-macos)を参照してください。
</Note>

<h3 id="make-ctrl-w-delete-back-to-whitespace">
  編集ショートカットの単語境界
</h3>

単語ショートカット `Alt+B`、`Alt+F`、`Alt+D`、`Option+Delete`、`Ctrl+Backspace` は、単語を文字と数字の実行として扱うため、`_`、`.`、`/` などの句読点は単語を分離します。プロンプトに `src/utils/foo.ts` がある場合、`Alt+B` を繰り返し押すと `ts`、`foo`、`utils`、`src` の開始で停止します。

`Ctrl+W` は異なります。句読点を無視して前の空白文字まで戻って削除するため、1 回のプレスで `src/utils/foo.ts` 全体を削除します。

中国語や日本語など、スペースなしで書かれたテキストでは、単語ショートカットは依然として 1 回に 1 単語移動または削除します。

これらの readline 規約は Claude Code v2.1.261 以降に適用されます。以前のバージョンでそれらをオンにした [`keybindingFlavor`](/docs/ja/settings-reference#keybindingflavor) 設定は非推奨であり、効果がありません。

これらのショートカットは[キーバインディング設定ファイル](/docs/ja/keybindings)で再マップできません。このファイルにはそれらのアクションがありません。

<h2 id="commands">
  コマンド
</h2>

Claude Code で `/` と入力すると、利用可能なコマンドが表示されます。または `/` の後に任意の文字を入力してフィルタリングできます。`/` メニューには、組み込みコマンド、バンドルされたユーザー作成の [skills](/docs/ja/skills)、および [plugins](/docs/ja/plugins/overview) と [MCP servers](/docs/ja/mcp#use-mcp-prompts-as-commands) によって提供されるコマンドが表示されます。すべての組み込みコマンドがすべてのユーザーに表示されるわけではありません。プラットフォームまたはプランに依存するコマンドもあり、[設計上、メニューから非表示になっているが、完全な名前を入力すると実行される利用可能なコマンドもいくつかあります](/docs/ja/commands#how-the-command-menu-matches-what-you-type)。

[フルスクリーンレンダリング](/docs/ja/fullscreen#use-the-mouse) では、`/` コマンドと `@` ファイル提案リストもマウスに応答します。行にマウスを置くとハイライトされ、クリックするとそれが選択されます。

Claude Code に含まれるコマンドの完全なリストについては、[コマンドリファレンス](/docs/ja/commands) を参照してください。

<h3 id="complete-a-command-mid-prompt">
  プロンプトの途中でコマンドを完成させる
</h3>

コマンド補完はプロンプトの途中でも機能します。スペースの後に `/` を入力し、その後に名前の最初の文字を入力します。例えば `run the tests, then /com` のようにします。名前がそれらの文字で始まるコマンドのみが一致するため、`/tmp/notes.md` のようなファイルパスではリストが開いたままになりません。Claude Code がコマンド自体を実行するのは、コマンドが [メッセージを開始する](/docs/ja/commands) 場合のみです。

* **[フルスクリーンレンダリング](/docs/ja/fullscreen) の場合**：入力中に一致するコマンドがリストとして開き、行がハイライトされていないため、`Enter` キーを押すとプロンプトがそのまま送信されます。`Tab` キーを押すと最上位の一致が挿入されます。または矢印キーと `Enter` キーで行を選択します。
* **フルスクリーン外の場合**：最上位の一致の残りがカーソルでゴーストテキストとして表示され、複数のコマンドが一致する場合は `+2` などのカウントが表示されます。`Tab` キーを押すと唯一の一致が挿入されるか、複数が一致する場合はリストが開き、矢印キーと `Enter` キーで行を選択します。

両方のレンダラーで、プロンプトの途中の裸の `/` で `Tab` キーを押すと、すべてのコマンドがリストされます。

プラグインスキルはその裸の名前でも一致するため、`/deploy` は `myplugin:deploy-app` という名前のスキルを見つけます。一致を挿入すると、Claude Code は完全な `/myplugin:deploy-app` を書き込みます。

<h2 id="vim-editor-mode">
  Vim エディタモード
</h2>

`/config` → Editor mode から vim スタイルの編集を有効にします。

Claude Code は、`Ctrl+O` で[トランスクリプトビューア](#transcript-viewer)を切り替えたり、`/config` などのパネルを開いたり閉じたりするときに、vim モードとカーソル位置を保持します。プロンプトを NORMAL モードのままにしておくと、戻ってきたときも NORMAL モードのままで、カーソルは置いた場所にあります。

<h3 id="remap-insert-mode-key-sequences">
  INSERT モードのキーシーケンスを再マップ
</h3>

[`vimInsertModeRemaps`](/docs/ja/settings-reference#viminsertmoderemaps) 設定は、2 キーの INSERT モードシーケンスを Escape にマップするため、`jj` のようなマッピングで NORMAL モードに戻ります。Claude Code v2.1.208 以降が必要です。

以下の `~/.claude/settings.json` の例は、vim モードをオンにして `jj` を Escape にマップします：

```json theme={null}
{
  "editorMode": "vim",
  "vimInsertModeRemaps": { "jj": "<Esc>" }
}
```

各キーは連続して入力される正確に 2 つの印字可能文字で、`"<Esc>"` は唯一サポートされているターゲットです。異なる長さまたはターゲットを持つエントリは無視されます。

シーケンスの最初の文字を入力すると、通常通り挿入されます。1 秒以内に 2 番目の文字を押すと、保留中の文字が削除され、NORMAL モードに切り替わり、入力に文字は残りません。1 秒のウィンドウの後、または異なるキーが続く場合、両方の文字はリテラルテキストとして残るため、2 つのキーの間で一時停止することで、シーケンスを含む単語を入力できます。

Claude Code は、ユーザー設定ファイル、`--settings` フラグ、および[マネージド設定](/docs/ja/managed-settings)からのみこの設定を読み込みます。プロジェクトの `.claude/settings.json` または `.claude/settings.local.json` のエントリは無視されるため、チェックアウトされたリポジトリはキーストロークを再マップできません。

<h2 id="command-history">
  コマンド履歴
</h2>

Claude Code はあなたが入力したプロンプトの履歴を保持し、上矢印キーでの呼び出しは同じプロジェクトの過去のセッションからプロンプトを取得します。

* 入力履歴は作業ディレクトリごとに保存されます
* `/clear` を実行すると新しいセッションが開始されます。呼び出しの際には新しいセッションのプロンプトが最初に表示され、その後に以前のセッションのプロンプトが表示されます。前のセッションの会話は保存され、再開することができます。
* 同じプロンプトを連続して 2 回送信すると、1 つの履歴エントリが記録されるため、上矢印キーを押すと前の異なるプロンプトにステップします
* 貼り付けたテキストを含むプロンプトを呼び出すと、再度送信する際に Claude Code は完全な貼り付けコンテンツを送信します。コンテンツが [自動的にクリーンアップ](/docs/ja/claude-directory#cleaned-up-automatically) されている場合、Claude Code は文字通りの `[Pasted text #N]` 文字列を送信しません。プロンプトに何が起こるかについては、[大きなコンテンツを貼り付ける](/docs/ja/terminal-config#paste-large-content) を参照してください
* `!` を使用した履歴展開はデフォルトで無効になっています

<h3 id="reverse-search-with-ctrl-r">
  Ctrl+R での逆方向検索
</h3>

`Ctrl+R` を押してコマンド履歴をインタラクティブに検索します。[フルスクリーンレンダリング](/docs/ja/fullscreen) では、`Ctrl+R` は検索ダイアログを開きます。入力してフィルタリングし、`Up` と `Down` を押してマッチを移動し、`Ctrl+S` を押してスコープをこのセッション、このプロジェクト、すべてのプロジェクトの間で循環させます。`Enter` または `Tab` を押してマッチをプロンプト入力に配置するか、`Esc` を押してキャンセルします。以下のステップは、クラシックレンダラーのインライン検索について説明しています。

1. **検索を開始**: `Ctrl+R` を押して逆方向履歴検索を有効にします
2. **クエリを入力**: 前のコマンドで検索するテキストを入力します。検索用語は一致する結果で強調表示されます
3. **マッチを移動**: `Ctrl+R` をもう一度押して、より古いマッチを循環させます
4. **検索スコープ**: インライン検索は常にすべてのプロジェクトからプロンプトを検索します
5. **マッチを受け入れる**:
   * `Tab` または `Esc` を押して現在のマッチを受け入れ、編集を続けます
   * `Enter` を押して受け入れ、コマンドを直ちに実行します
6. **検索をキャンセル**:
   * `Ctrl+C` を押してキャンセルし、元の入力を復元します
   * 空の検索で `Backspace` を押してキャンセルします

インライン検索は完全なプロンプト履歴をスキャンし、最新のものから順に、重複は最新の出現に折りたたまれます。フルスクリーン ダイアログは選択されたスコープ内の全プロンプト履歴を検索し、最新のものから順に、重複は最新の出現に折りたたまれます。最も最近のプロンプトが直ちに表示され、古いプロンプトからのマッチは Claude Code が残りの履歴を読み込むにつれて入力されます。マッチするプロンプトは検索用語が強調表示されて表示されるため、前の入力を見つけて再利用できます。

マッチを受け入れるか検索をキャンセルすると、Claude Code がまだ履歴を読み込んでいる場合でも、直ちに有効になります。

<h2 id="background-bash-commands">
  バックグラウンド Bash コマンド
</h2>

Claude Code はバックグラウンドで Bash コマンドを実行することをサポートしており、長時間実行されるプロセスが実行されている間も作業を続けることができます。

<h3 id="how-backgrounding-works">
  バックグラウンド実行の仕組み
</h3>

Claude Code がコマンドをバックグラウンドで実行する場合、コマンドを非同期で実行し、すぐにバックグラウンドタスク ID を返します。Claude Code は、コマンドがバックグラウンドで実行され続けている間、新しいプロンプトに応答できます。

コマンドをバックグラウンドで実行するには、以下のいずれかを実行できます。

* Claude Code にコマンドをバックグラウンドで実行するようプロンプトを送信する
* `Ctrl+B` を押して、通常の Bash ツール呼び出しをバックグラウンドに移動する。Tmux ユーザーは tmux のプリフィックスキーのため、`Ctrl+B` を 2 回押す必要があります。

**主な機能：**

* 出力はファイルに書き込まれ、Claude は Read ツールを使用してそれを取得できます
* バックグラウンドタスクには、追跡と出力取得のための一意の ID があります
* バックグラウンドタスクは、Claude Code が終了するときに自動的にクリーンアップされます。macOS と Linux では、[`/tasks`](/docs/ja/commands) からバックグラウンドタスクを停止するか、Claude Code が終了時に停止する場合、`setsid` または `timeout` の下で開始されたものなど、タスクのシェルから切り離されたプロセスも停止します
* セッションを終了する代わりにバックグラウンドにした場合、バックグラウンドタスクはバックグラウンドセッションで実行され続けます。[実行中のセッションをバックグラウンドにする](/docs/ja/agent-view#from-inside-a-session)を参照してください
* 出力が 5GB を超える場合、バックグラウンドタスクは自動的に終了され、stderr に理由を説明するメモが表示されます
* macOS と Linux では、セッションが少なくとも 30 分間アイドル状態にあり、ターンまたはサブエージェントが実行されていない場合、Claude Code はオペレーティングシステムがメモリプレッシャーを通知するときに実行中のバックグラウンドタスクを停止します。Claude Code v2.1.193 以降が必要です
  * [デバッグログ](/docs/ja/debug-your-config)は、タスクが停止された理由、またはプレッシャーイベントがそれらを実行し続けた理由を示します
  * [`CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP`](/docs/ja/env-vars) を `1` に設定してメモリプレッシャー停止をオフにします
* [サブエージェント](/docs/ja/sub-agents)が所有するバックグラウンドコマンドには時間制限がありません。ただし、フォアグラウンドで実行されているサブエージェントが所有するコマンドは、そのサブエージェントが最終応答を行うときに終了します。ツール参照の[バックグラウンドコマンド](/docs/ja/tools-reference#background-commands)を参照してください。v2.1.218 より前では、メモリプレッシャーリープも、サブエージェントコマンドに対する以前の 60 分制限も、`Ctrl+B` でバックグラウンドに移動されたコマンドをカバーしていませんでした

すべてのバックグラウンドタスク機能を無効にするには、`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` 環境変数を `1` に設定します。詳細は[環境変数](/docs/ja/env-vars)を参照してください。

**一般的なバックグラウンド実行コマンド：**

* ビルドツール（webpack、vite、make）
* パッケージマネージャー（npm、yarn、pnpm）
* テストランナー（jest、pytest）
* 開発サーバー
* 長時間実行プロセス（docker、terraform）

<h3 id="shell-mode-with-prefix">
  `!` プリフィックスを使用したシェルモード
</h3>

入力に `!` をプリフィックスとして付けることで、Claude を経由せずにシェルコマンドを直接実行します。

```bash theme={null}
! npm test
! git status
! ls -la
```

シェルモード：

* コマンドとその出力を会話コンテキストに追加します
* リアルタイムの進捗と出力を表示します
* 長時間実行コマンドに対して同じ `Ctrl+B` バックグラウンド実行をサポートします
* Claude がコマンドを解釈または承認する必要がありません
* 履歴ベースのオートコンプリートをサポートします。部分的なコマンドを入力して `Tab` を押すと、現在のプロジェクトの以前の `!` コマンドから補完されます
* v2.1.193 以降、すべてのプラットフォームでライブファイルパスオートコンプリートをサポートします。`./src/` または `~/` などのフォワードスラッシュを含むトークンを入力すると、一致するファイルとディレクトリのドロップダウンが表示され、`Tab` を押して受け入れます。Windows でもフォワードスラッシュを使用します。ドロップダウンは `/` でトリガーされ、`\` ではありません
* 空のプロンプトで `Escape`、`Backspace`、または `Ctrl+U` で終了します
* `!` で始まるテキストを空のプロンプトに貼り付けると、入力された `!` の動作と一致して、自動的にシェルモードに入ります

セッションが[厳密なサンドボックスモード](/docs/ja/sandboxing#the-unsandboxed-retry-escape-hatch)の下に記載されているもののいずれかでない限り、シェルモードで入力したコマンドは、サンドボックスを有効にしている場合でも[サンドボックス](/docs/ja/sandboxing)の外で実行されます。これは、サンドボックスが Claude が実行するコマンドに適用されるためです。

Claude はコマンド出力がトランスクリプトに到着すると自動的に応答するため、`! npm test` を実行して、2 番目のプロンプトなしで失敗の説明を取得できます。応答コストは通常のプロンプトを送信するのと同じです。出力がコンテキストに追加されるが応答がない以前の動作を復元するには、`settings.json` で [`respondToBashCommands`](/docs/ja/settings-reference#respondtobashcommands) を `false` に設定します。v2.1.186 より前では、シェルモードは常に応答なしでコンテキストに出力を追加していました。

<h2 id="queue-messages-while-claude-works">
  Claude が作業中にメッセージをキューに入れる
</h2>

Claude が作業中に、メッセージを入力して `Enter` キーを押すと、Claude Code はターンを中断する代わりにメッセージをキューに入れ、入力ボックスの上にキューに入れられたエントリを表示します。`!` [シェルコマンド](#shell-mode-with-prefix)と、ほとんどの[コマンド](/docs/ja/commands)をキューに入れることができます。ただし、Claude Code が送信直後に実行する `/status` などのコマンドは除きます。

送信されたメッセージとキューに入れられたメッセージは、Claude が応答を開始するまでグレーで表示されるため、Claude がまだ処理していないメッセージを判別できます。

<h3 id="when-claude-code-sends-what-you-queued">
  Claude Code がキューに入れたものを送信するタイミング
</h3>

キューに入れたエントリが Claude に到達するタイミングは、何をキューに入れたかによって異なります。

* メッセージ：Claude がツール呼び出しを実行している間にメッセージをキューに入れた場合、Claude Code はそれらのツール呼び出しが完了するとすぐに、同じターン内で Claude に渡します。ターンがメッセージがまだキューに入った状態で終了した場合、別のキープレスなしに送信され、入力した順序で送信されます。
* コマンドとシェルコマンド：Claude Code はターンが終了するまでそれらを保持し、その後 1 つずつ実行し、キューに入れた順序を保持します。

キューに入れたものをターンの終了を待たずに送信するには、`Ctrl+Enter` キーを押します。キューに入れたメッセージがすぐに送信され、入力していたドラフトがある場合はそれがその後ろにキューに入れられます。Claude Code v2.1.275 以降が必要です。

キューに入れた `!` シェルコマンドが メッセージの前にある場合、このキーはターンを中断します。それ以外の場合、ターンに何が起こるかは、キーを押したときに Claude が何をしているかによって異なります。

* シェルコマンド、サブエージェント、または[バックグラウンド](#background-bash-commands)に移動できるその他の作業を実行している：その作業はバックグラウンドに移動して実行を続け、Claude は同じターン内でメッセージを読みます。
* 応答を書き込むだけ、またはバックグラウンドに移動できないものを実行している：Claude Code はターンを中断し、メッセージを次に送信します。v2.1.281 より前では、このキーは両方の場合でターンを中断していました。

[シェルモード](#shell-mode-with-prefix)では、このキーはコマンドをキューに入れるだけです。拡張キーを報告しないターミナルでは、`Ctrl+Enter` は通常の `Enter` として到達し、ドラフトをキューに入れます。`Ctrl+X Ctrl+S` はどのターミナルでも機能します。どちらのキーも [`chat:sendNow` アクション](/docs/ja/keybindings#chat-actions)のバインディングです。

`Esc` キーを押してターンを中断し、ドラフトを送信しません。Claude Code はキューに入れたものを保持し、すぐに送信します。

Claude Code は、キューに入れる代わりに、送信直後に実行するコマンドがあります。その中には `/model`、`/effort`、`/fast` があります。これら 3 つはそれぞれ設定を変更します。モデル、努力レベル、またはファストモードです。Claude Code が新しい設定を Claude が既に作業しているターンに適用するか、次のターンからのみ適用するかは、コマンドによって異なります。

* [`/model`](/docs/ja/model-config#setting-your-model)：Claude Code が[キャッシュ警告](/docs/ja/prompt-caching#switching-models)を表示する場合は、確認後、Claude Code はそのターン内で次に行うリクエストに変更を適用します。
* [`/effort`](/docs/ja/model-config#adjust-effort-level)：Claude Code が[キャッシュ警告](/docs/ja/prompt-caching#changing-effort-level)を表示する場合は、確認後、Claude Code はそのターン内で次に行うリクエストに変更を適用します。
* [`/fast`](/docs/ja/fast-mode#toggle-fast-mode)：Claude Code はターンが開始されたときにアクティブだったファストモード設定を保持するため、速度の変更は次のターンから適用されます。現在のモデルがファストモードをサポートしていない場合、それをオンにすると[モデルも切り替わり](/docs/ja/prompt-caching#turning-on-fast-mode)、Claude Code はそのターン内で次に行うリクエストから新しいモデルを使用します。

<h3 id="take-back-what-you-queued">
  キューに入れたものを取り戻す
</h3>

入力ボックスの最初の行から `Up` キーを押すと、キューに入れたメッセージとコマンドを取り戻すことができます。Claude Code はそれらをキューから削除し、入力ボックスに 1 行に 1 つずつ、入力していたテキストの前に配置します。テキストを編集して `Enter` キーを押すと、1 つのエントリとして再度キューに入れられます。または、入力ボックスをクリアして削除します。

Claude Code は、入力ボックスが空で、キューに入れたものが他にない場合にのみ、キューに入れたシェルコマンドを取り戻し、その際に入力ボックスをシェルモードに切り替えます。それ以外の場合は、それらをキューに留めておき、`!` プレフィックス付きでリストし、ターンが終了した後に実行します。

<h2 id="prompt-suggestions">
  プロンプト提案
</h2>

セッションを最初に開くと、Claude Code はプロンプト入力に薄い灰色で表示されたコマンド例を表示して、開始を支援します。このコマンド例はプロジェクトの git 履歴から選択されるため、最近作業していたファイルが反映されます。

Claude が応答した後、Claude Code は会話履歴に基づいて次のプロンプトを提案できます。例えば、複数部分のリクエストからのフォローアップステップや、ワークフローの自然な続きなどです。

* `Tab` キーまたは `Right arrow` キーを押して提案をプロンプト入力に配置し、`Enter` キーを押して送信します
* 入力を開始して提案を閉じます

Claude Code は、これらの次のプロンプト提案を、セッションが使用しているのと同じモデルへのバックグラウンドリクエストで生成します。このリクエストはプランの使用制限または API コストにカウントされます。会話のプロンプトキャッシュを再利用するため、主にキャッシュ読み取りと少数の出力トークンで構成されるため、追加コストは最小限です。

<h3 id="when-claude-code-skips-suggestions">
  Claude Code が提案をスキップする場合
</h3>

インタラクティブモードでは、Claude Code はデフォルトでプロンプト提案をオフにし、`/config` の **Prompt suggestions** トグルを、[フィーチャーフラグを取得しないセッション](/docs/ja/env-vars#features-that-need-feature-flag-fetching)（サードパーティプロバイダー上のセッションや Claude アプリゲートウェイを通じたセッションなど）および[インストールまたはアップグレード後の最初のセッション](/docs/ja/env-vars#first-session-after-an-install-or-upgrade)（フラグがまだ到着していないセッション）で非表示にします。

Claude Code は、以下を含むいくつかの状況で個別の提案もスキップします。

* 不要なコストを避けるため、プロンプトキャッシュがコールドの場合
* 会話の最初のターンの後、一部のセッションで
* 前の応答がエラーで終了した場合
* Plan Mode にいる場合
* アカウントが使用制限に近い、またはその制限に達している場合。制限に達するまで提案をオンのままにするには、[`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](/docs/ja/env-vars) を `true` に設定します。v2.1.238 より前では、変数が `true` に設定されていても、Claude Code は制限に近い場合にそれらをスキップしていました
* [agent team](/docs/ja/agent-teams) では、デフォルトでチームメイトのセッションで。リーダーのセッションは提案を表示します

Print Mode では、Claude Code はデフォルトでは提案を生成しません。Claude Code が生成した各ターンの後に `prompt_suggestion` メッセージを出力するには、`-p "<prompt>" --output-format stream-json --verbose` で [`--prompt-suggestions`](/docs/ja/cli-reference#cli-flags) を渡します。ジェネレータはここでも非常に短い会話とコールドプロンプトキャッシュをスキップするため、単一の短い `-p` クエリは何も出力しない可能性があります。

<h3 id="turn-prompt-suggestions-off">
  プロンプト提案をオフにする
</h3>

プロンプト提案を完全に無効にするには、以下のいずれかを使用します。

* `/config` で **Prompt suggestions** をオフにします
* 設定ファイルで [`promptSuggestionEnabled`](/docs/ja/settings-reference#promptsuggestionenabled) を `false` に設定します
* [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](/docs/ja/env-vars) 環境変数を `false` に設定します。これは設定よりも優先されます。
  ```bash theme={null}
  export CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false
  ```

組織全体でプロンプト提案をオフにするには、[managed settings](/docs/ja/managed-settings) で `promptSuggestionEnabled` を `false` に設定します。また、ユーザーが独自の環境変数で再度有効にできないように、managed [`env`](/docs/ja/settings-reference#env) キーの下で `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` を `false` に設定します。

<h2 id="emoji-shortcodes">
  絵文字ショートコード
</h2>

プロンプト入力で `:` に続けて絵文字ショートコードを入力すると、絵文字が挿入されます。Claude Code v2.1.217 以降が必要です。

* `:heart:` などの完全なショートコードを入力すると、Claude Code は閉じる `:` を入力した直後に ❤️ に置き換えます
* `:` に加えて名前の少なくとも 2 文字を入力します（例：`:hea`）。提案ポップアップが開き、`Tab` または `Enter` を押してハイライトされた絵文字を挿入します

ショートコードは入力の開始時またはスペースの後に続く必要があります。単語または URL 内の `:` は提案を開きません。

この機能をオフにするには、`settings.json` で [`emojiCompletionEnabled`](/docs/ja/settings-reference#emojicompletionenabled) を `false` に設定します。これにより、提案ポップアップとインライン置換の両方が無効になります。

<h2 id="check-spelling-as-you-type">
  入力中にスペルチェックを実行する
</h2>

Claude Code は、入力中にプロンプト入力のスペルミスのある単語に下線を引くことができます。入力ボックス内のテキストのみをチェックし、Claude の返信やファイルはチェックしません。また、入力ボックスが [シェルモード](#shell-mode-with-prefix)、`Ctrl+R` 履歴検索、または [音声入力](/docs/ja/voice-dictation) にある場合は何もチェックしません。

スペルチェックはデフォルトでオフになっており、Claude Code は [スクリーンリーダーモード](/docs/ja/accessibility) では何もチェックしません。Claude Code v2.1.235 以降が必要です。

<h3 id="prerequisites">
  前提条件
</h3>

* [aspell](https://github.com/GNUAspell/aspell)、[hunspell](https://github.com/hunspell/hunspell)、または [ispell](https://en.wikipedia.org/wiki/Ispell) をインストールし、`PATH` に含まれていることを確認してください。Claude Code は、Windows の `.cmd` シムを含むすべてのプラットフォームで、見つかった 3 つのうち最初のものを実行します。
* プログラムが `PATH` にあることを確認するには、ターミナルで `aspell --version`、`hunspell --version`、または `ispell -v` を実行してください。「command not found」エラーが表示される場合は、まだ `PATH` に含まれていません。

<h3 id="turn-spell-checking-on-or-off">
  スペルチェックをオンまたはオフにする
</h3>

Claude Code は [`spellcheck`](/docs/ja/settings-reference#spellcheck) 設定を 3 つの場所から読み込み、プロジェクトの `.claude/settings.json` と `.claude/settings.local.json` では無視します。使用している場所からオンにしてください。

<Tabs>
  <Tab title="ユーザー設定">
    `~/.claude/settings.json` に `spellcheck` を追加してください。これは、[ユーザー設定](/docs/ja/settings#where-settings-live) の残りの部分と同様に、開くすべてのプロジェクトに適用されます。

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```
  </Tab>

  <Tab title="コマンドライン">
    `spellcheck.json` などの JSON ファイルに `spellcheck` を保存してください。

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```

    次に、ファイルを `--settings` に渡してください。これはそのセッションのみに適用されます。

    ```bash theme={null}
    claude --settings spellcheck.json
    ```
  </Tab>

  <Tab title="管理設定">
    組織の [管理設定ソース](/docs/ja/permissions#managed-settings) の 1 つに `spellcheck` を追加してください。これは、それらの設定を受け取るすべてのユーザーに適用され、ユーザーはそれをオフにすることはできません。

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```
  </Tab>
</Tabs>

スペルチェックがオンになっていることを確認するには、スペルミスのある単語とスペースを入力してください。Claude Code は単語に下線を引きます。下線が引かれない場合は、[Claude Code が何も下線を引かない場合](#when-claude-code-underlines-nothing) を参照してください。スペルチェックを再度オフにするには、同じ場所で `enabled` を `false` に設定するか、`spellcheck` を削除してください。

Claude Code が実行する 3 つのプログラムのうちどれを実行するか、どの辞書を使用するか、または下線の色を選択するには、同じ場所で `enabled` の隣に次のフィールドのいずれかを追加してください。

* `checker`: `aspell`、`hunspell`、または `ispell`。Claude Code は指定したチェッカーからフォールバックせず、他の値を `auto` として扱います。
* `language`: チェッカーの形式の辞書名（`en_GB` など）。Claude Code は、パスや空白を含む名前など、プレーンな辞書名ではない値を無視し、チェッカーはデフォルト辞書を使用します。
* `color`: `yellow` などの色名、または `#rrggbb`、`#rgb`、`rgb(r,g,b)`、`ansi256(n)`、または `ansi:<name>` 値。Claude Code はデフォルトではテーマのエラー色を使用し、認識しない値に対しても同様です。

例えば、この `spellcheck` 設定は hunspell を `en_GB` 辞書で実行し、単語を黄色で下線を引きます。`~/.claude/settings.json`、`--settings` に渡すファイル、および管理設定で同じように機能します。

```json theme={null}
{
  "spellcheck": {
    "enabled": true,
    "checker": "hunspell",
    "language": "en_GB",
    "color": "yellow"
  }
}
```

3 つの場所のうち複数に `spellcheck` 設定がある場合、Claude Code は 1 つだけを使用します。管理設定が最初に、次に `--settings`、次にユーザー設定です。2 つの場所からフィールドを組み合わせることはありません。例えば、`--settings` が `spellcheck` を設定する場合、ユーザー設定の `language` は効果がありません。

<h3 id="what-claude-code-underlines">
  Claude Code が下線を引く内容
</h3>

入力を一時停止した直後、Claude Code は辞書が認識しない単語に下線を引きます。入力中の単語はそれを超えるまで放置し、テキストを変更することはありません。また、コードのように見えるテキストもスキップします。

* `/help`、`@` メンション、URL、ファイルパス、`--verbose` などのフラグなどのコマンド
* 数字、アンダースコア、または最初の後に大文字を含む単語、およびバッククォート内のテキスト

Claude Code は、中国語、日本語、韓国語、タイ語、ラオ語、クメール語、およびミャンマー語のテキストもスキップします。

Claude Code には独自の単語リストがありません。単語がスペルミスであるかどうかは、チェッカーが判断します。Claude Code が単語に下線を引くのを停止するには、チェッカーのドキュメントに従って、チェッカーの個人辞書に単語を追加してください。Claude Code はそれを再起動した後、新しい単語を取得します。

<h3 id="when-claude-code-underlines-nothing">
  Claude Code が何も下線を引かない場合
</h3>

Claude Code がチェッカーを実行し続けることができない場合、何も下線を引きません。

* チェッカーがインストールされていない、または `checker` で指定したものが見つからない
* チェッカーが 2 回連続で失敗する（起動時またはセッション中）。Claude Code は最初の失敗後に再起動し、2 番目の失敗後はチェックを停止します（Claude Code を再起動するまで）
* チェッカーが 15 秒以上かかって回答する（3 回）。毎回、Claude Code は待機していた単語をマークしません。3 回目の後、Claude Code を再起動するまでチェックを停止します

これらのうちどれが起こったかを確認するには、スペルチェックをオンにして `claude --debug` を開始し、単語を入力してください。次に、`~/.claude/debug/<session-id>.txt` のデバッグログで `[spellcheck]` 行を探してください。1 行は Claude Code が開始したプログラムに名前を付けるか、探したが見つからなかったプログラムをリストします。後の行は停止した理由を説明します。そこの辞書欠落エラーは、チェッカーが `language` 値の辞書を持っていないか、`language` が設定されていない場合はデフォルトの辞書を持っていないことを意味します。1 つをインストールするか、`language` を持っている辞書に設定してください。

<h2 id="invisible-characters-in-prompts">
  プロンプト内の見えない文字
</h2>

貼り付けたテキストには、タグ文字、双方向制御、ゼロ幅スペースなど、ターミナルが何も描画しない Unicode 文字が含まれる可能性があるため、プロンプトには見えないテキストが含まれることがあります。コピーしたテキストがターミナルに描画されない命令を含まないようにするため、Claude Code は Enter キーを押すときにそれらの文字を削除してから、何かを送信します。プロンプトと、プロンプトに含まれる任意の折りたたまれた[貼り付けテキスト参照](/docs/ja/terminal-config#paste-large-content)の内容の両方をクリーンアップします。Claude Code はペルシア語とインド系スクリプトが書く結合文字と、絵文字シーケンス内のセレクタを保持します。

Claude Code が何かを削除した場合、その Enter は何も送信しません。クリーンアップされたプロンプトは、`Removed 3 invisible characters · review and press Enter to send` などの通知とともに入力ボックスに戻り、もう一度 Enter キーを押すと、表示されたテキストが送信されます。

`claude "fix the login bug"` のようにコマンドラインでプロンプトを渡すか、対話型セッションにパイプする場合、Claude Code は 2 番目の Enter を待ちません。文字を削除し、通知を表示し、クリーンアップされたプロンプトを送信します。クリーンアップされたプロンプトが `/` で始まる場合、Claude Code はそれを入力ボックスに入れて、確認して送信するようにします。

<h2 id="review-changes-with-/diff">
  /diff で変更内容を確認する
</h2>

`/diff` を実行して、Claude Code を離れることなく、ワーキングツリーの変更内容を確認できます。Claude がこれまでに行った編集と、コミットしていないその他の変更が表示されます。

`/diff` が git から読み取る変更では、サブモジュールは単一のエントリとして表示され、それもサブモジュールが指すコミットが変わった場合のみです。サブモジュール内のファイルへの編集はそこには表示されません。

[フルスクリーンレンダリング](/docs/ja/fullscreen)では、`/diff` は[diff パネル](#diff-panel)を会話の横に開き、作業を続ける間、パネルは開いたままで更新されます。クラシックレンダラーでは、`/diff` は[diff ビューアー](#diff-viewer)をプロンプトの代わりに開き、読み終わったら閉じます。

<h3 id="diff-panel">
  Diff パネル
</h3>

diff パネルは、変更されたファイルを追加行数と削除行数とともにリストアップし、リストの下に各ファイルの diff を表示します。Claude Code は、Claude がファイルを編集するか、シェルコマンドを実行するたびに、パネルを更新します。パネルを閉じるには、`/diff` を再度実行するか、ヘッダーの `✕` をクリックします。

パネルを使用するには、以下が必要です。

* [フルスクリーンレンダリング](/docs/ja/fullscreen)
* Git リポジトリ
* 少なくとも 110 列幅のターミナル
* Claude Code v2.1.260 以降

パネルが開けない場合、`/diff` は diff ビューアーを開くか、理由を表示します。

ターミナルが少なくとも 144 列幅の場合、Claude がファイルの編集を開始すると、パネルは自動的に開きます。`/diff` で自分で開いた後、後続のセッションでは、Claude がそれに適した幅のターミナルでファイルを編集するとすぐにパネルが開きます。パネルを閉じると、このセッションと後続のセッションでも閉じたままになり、`/diff` を再度実行するまで開きません。

パネルが開いている間、以下のことができます。

* **ファイルにジャンプする**：リストの行をクリックします。マウスホイールでパネルをスクロールします。ファイルリスト自体が長すぎて収まらない場合は、`Alt+Up` と `Alt+Down`、または `Ctrl+Up` と `Ctrl+Down` でスクロールします。
* **特定の行について Claude に質問する**：パネルでマウスを使用して行を選択します。Claude Code は選択内容を次のプロンプトに添付し、送信するまで入力の横に行数を表示します。
  * 選択内容なしでプロンプトを送信するには、カーソルを行数インジケーターの直後に移動し、`Backspace` を押して削除します。Claude Code v2.1.271 以降が必要です。
* **パネルが除外するファイルを表示する**：リストはテストファイルと生成されたファイルをスキップし、このセッション前の変更を下部の 1 行に折りたたみます。いずれかのカウント行をクリックして展開します。
* **パネルが比較する対象を変更する**：`Ctrl+X B` を押して、このセッションの変更から、コミットされていない変更を 1 つのリストとして、デフォルトブランチからの分岐以降のすべてに循環します。Claude Code は、各プロジェクトの選択を記憶します。

これらのアクションにキーをバインドするには、[Diff パネルアクション](/docs/ja/keybindings#diff-panel-actions)を参照してください。

<h3 id="diff-viewer">
  Diff ビューアー
</h3>

diff ビューアーは、閉じるまでプロンプトの代わりになります。その **Current** ビューは、git からのコミットされていない変更、または変更がない場合は、ブランチがデフォルトブランチから追加する内容を表示します。ビューアーには、Claude がファイルを編集した後の各ターンのターンビューもあり、その編集のみを表示します。Claude Code は、git ではなく Claude のファイル編集からターンビューを構築するため、Claude がシェルコマンドを通じて行った変更は Current の下にのみ表示されます。

ビューアーでこれらのキーを使用します。

* **左と右**：Current とターンビューの間を移動します。
* **上と下**：ファイルを選択します。
* **Enter**：選択したファイルの diff を開きます。上下、または PageUp と PageDown でスクロールします。
* **Esc**：ファイルの diff からリストに戻るか、リストからビューアーを閉じます。

これらのキーを再バインドするには、[Diff アクション](/docs/ja/keybindings#diff-actions)を参照してください。

<h2 id="side-questions-with-/btw">
  /btw で補足質問をする
</h2>

`/btw` を使用して、現在の作業に関する質問をしながら、会話履歴に追加しないようにします。

```
/btw what was the name of that config file again?
```

Claude は補足質問に対して、会話に既に含まれている内容から回答します。つまり、あなたのメッセージ、Claude の返信、および収集したツール結果から回答します。Claude が既に読んだコード、以前に下した決定、またはセッションの他の内容について質問できます。後の補足質問は、以前の補足質問も確認します。Claude Code は最新の 20 個のやり取りを各質問で再生します。これは、それらをクリアするまで続きます。質問と回答は会話履歴に入りません。ターミナルでは、却下可能なオーバーレイに表示されます。ターミナルはスレッドをメモリに保持します。`x` を押して以前のやり取りをクリアすると、Claude Code を終了するときに消えます。

[VS Code 拡張機能](/docs/ja/vs-code#use-the-prompt-box)のチャットパネルでは、`/btw` はこのセクションで説明するオーバーレイではなくパネルを開き、パネル内で直接フォローアップ質問をします。パネルのスレッドはウィンドウの再読み込みを通じて保持され、そのページで説明されている保持スケジュールに従います。拡張機能は v2.1.227 以降が必要です。以前の拡張機能バージョンは `/btw` を提供していません。

* **Claude が作業中に利用可能**：Claude が応答を処理している間でも `/btw` を実行できます。補足質問は独立して実行され、メインのターンを中断しません。これまでの会話のすべてが表示されます。ただし、Claude がまだ作成している返信は除きます。
* **ツールアクセスなし**：補足質問は既にコンテキストにあるものからのみ回答します。Claude は補足質問に回答する際に、ファイルを読み取ったり、コマンドを実行したり、検索したりすることはできません。Claude がテキストとしてツール呼び出しを書き出す場合でも、回答は何も実行されなかったというメモで終わります。
* **単一の応答**：オーバーレイにはフォローアップターンがありません。スレッドを続行するには、別の `/btw` 質問をしてください。ローカルセッションで完全なツールアクセスを続行するには、`f` を押してこの質問と回答を[バックグラウンドサブエージェント](/docs/ja/sub-agents#fork-the-current-conversation)にフォークします。
* **低コスト**：会話の[プロンプトキャッシュ](/docs/ja/prompt-caching)がウォーム状態の間、補足質問は回答自体を超えるコストはほとんどかかりません。

5 つの最新の以前の補足質問は、現在の回答の上に薄い色のリストとして表示され、古いものの数がカウントされます。これらは会話履歴から除外されます。

オーバーレイを却下した後に戻るには、質問なしで `/btw` を実行します。オーバーレイは最新のやり取りで再度開きます。v2.1.212 より前では、質問なしの `/btw` は代わりに使用メッセージを出力していました。

回答が表示されたら、オーバーレイはこれらのキーを受け入れます。

| キー                           | アクション                                                                                                                                                                                                                                                   |
| :--------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Space`、`Enter`、`Escape`     | 回答を却下してプロンプトに戻る                                                                                                                                                                                                                                         |
| `Up` / `Down`                | 回答をスクロール                                                                                                                                                                                                                                                |
| `Shift+Left` / `Shift+Right` | この回答と以前の `/btw` 回答の間をステップします。`Shift+Left` は古い回答に移動し、`Shift+Right` は現在の回答に戻ります。`[` と `]` も同じことを行い、ターミナルが矢印キーで `Shift` を報告しない場合に使用します。`Tab` / `Shift+Tab` は同じ回答をサイクルします。Claude Code v2.1.257 以降が必要です。v2.1.187 から v2.1.256 の間、キーはプレーン `Left` / `Right` でした |
| `c`                          | 回答をクリップボードに生の Markdown としてコピーします。マウス選択の代わりにこれを使用してください。マウス選択はソーステキストではなく、ハードラップされたターミナルレンダリングをキャプチャします                                                                                                                                                  |
| `f`                          | 親会話にこの質問と回答を継承する[フォークされたサブエージェント](/docs/ja/sub-agents#fork-the-current-conversation)を開始して、完全なツールアクセスで続行できるようにします。現在のセッションに留まり、プロンプトの下の[パネル](/docs/ja/sub-agents#observe-and-steer-running-forks)でフォークを見つけます。ローカルセッションでのみ利用可能                                      |
| `x`                          | 現在の回答の上に表示される以前の `/btw` やり取りのリストをクリア                                                                                                                                                                                                                    |

接続された[バックグラウンドセッション](/docs/ja/agent-view#attach-to-a-session)では、`Left` はデタッチしてエージェントビューに戻ります。これは、回答がまだ到着している間でも行われます。補足質問は、あなたが離れている間も実行を続けます。次回セッションに接続するときに、オーバーレイは補足質問、またはその回答で再度開きます。v2.1.257 より前では、`Left` はそこでデタッチしませんでした。

`/btw` はあなたの完全な会話を見ていますが、ツールはありません。[サブエージェント](/docs/ja/sub-agents)はツールを持ち、受け取るプロンプトから開始するか、[フォーク](/docs/ja/sub-agents#fork-the-current-conversation)の場合はこの会話のコピーから開始します。`/btw` を使用して、Claude がこのセッションから既に知っていることについて質問してください。サブエージェントを使用して、何か新しいことを見つけてください。

<h2 id="task-list">
  タスクリスト
</h2>

タスクリストは Claude のやることリストです。複数ステップの作業を計画するために Claude が作成したアイテムで、保留中、進行中、完了を示すインジケーターが付いています。バックグラウンドタスクビューとは別です。実行中のシェルとサブエージェントを確認するには、代わりに [`/tasks`](/docs/ja/commands) を使用してください。

リストは、タスク追跡ツールを持つセッションにのみ入力されます。Claude Code は [Claude 3.x モデル、Opus 4 から 4.7、Sonnet 4 から 4.6、Haiku 4.5](/docs/ja/tools-reference#task-tool-availability) でデフォルトでこれらのツールを提供します。他のモデル（Claude Code が認識しないモデル ID を含む）では、`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` でオプトインするか、[タスクツールの利用可能性](/docs/ja/tools-reference#task-tool-availability) の下にある他の方法のいずれかを使用しない限り、リストは空のままです。セッションにツールがある場合、タスクリストは次のように機能します。

* `Ctrl+T` を押してタスクリストビューを切り替えます。表示は一度に最大 5 つのタスクを表示します。Claude がまだチェックリストアイテムを作成していない場合、表示するものがないため、切り替えは目に見える効果がありません
* リストを展開したままにしておくと、Claude Code は `--resume` や `--continue` などでタスクがまだある セッションを起動する次回、展開されたビューを復元します。タスクリストが空の場合、Claude Code はそれを折りたたまれた状態で開始します
* すべてのタスクを表示したり、クリアしたりするには、Claude に直接尋ねてください。「すべてのタスクを表示して」または「すべてのタスクをクリアして」
* タスクはコンテキストコンパクション全体で保持され、Claude がより大規模なプロジェクトで整理された状態を保つのに役立ちます
* タスクリストをセッション間で共有するには、`CLAUDE_CODE_TASK_LIST_ID` を `~/.claude/tasks/` 内の名前付きディレクトリを使用するように設定します。`CLAUDE_CODE_TASK_LIST_ID=my-project claude`

<h2 id="session-recap">
  セッションの要約
</h2>

ターミナルから離れた後に戻ると、Claude Code はこれまでのセッションで何が起きたかの 1 行の要約を表示します。この要約は、最後に完了したターンから少なくとも 3 分が経過し、ターミナルがフォーカスされていない状態で、バックグラウンドで生成されるため、戻ってきたときに準備ができています。要約はセッションに少なくとも 3 ターンがある場合にのみ表示され、連続して 2 回表示されることはありません。

`/recap` を実行して、オンデマンドで要約を生成します。Claude Code は自動要約と `/recap` 出力の両方を 400 文字に制限しています。自動要約をオフにするには、`/config` を開いて **Session recap** をオフにします。

セッションの要約はすべてのプランとプロバイダーでデフォルトでオンになっています。この要約は非対話型モードでは常にスキップされます。

<h2 id="wait-for-a-usage-limit-to-reset">
  使用制限がリセットされるまで待機する
</h2>

claude.ai の[使用制限](/docs/ja/errors#youve-hit-your-session-limit)が Claude Code の途中でタスクを停止した場合、Claude Code はオープンセッションで待機し、制限がリセットされた後に自動的にタスクを続行します。自動続行は、claude.ai サブスクリプションでサインインしたインタラクティブセッションではデフォルトで有効です。Claude Code v2.1.234 以降が必要です。

Claude Code が待機している間、セッションの下部に続行される時刻を示す行が表示されます。

```text theme={null}
Usage limit reached · continuing automatically at 3:45pm · esc to cancel
```

セッションをオープンのままにしておいてください。その後の動作は、待機の終わり方によって異なります。

* **リセット時**：行は `continuing shortly` と表示され、その後 `Usage limit reset · continuing automatically` と表示されます。Claude Code は Claude に固定プロンプトを送信して、停止した場所からタスクを再開します。最後のメッセージは再送信されません。
* **コンピュータがスリープした後**：約 30 分以上スリープし、スリープ中に制限がリセットされた場合、行は `Your usage limit has reset · press enter to continue` と表示されます。`Enter` キーを押して続行してください。短いスリープの後は、Claude Code が自動的に続行します。
* **早期**：待機中に `/usage-credits` で[使用クレジットを追加](/docs/ja/costs#add-usage-credits-to-your-subscription)したり、`/upgrade` の後に再度サインインしたり、`/model` でモデルを切り替えたりした場合、Claude Code は使用可能な使用量があるかどうかを確認し、ある場合はすぐに続行します。ブラウザで自分で行ったアップグレードまたは購入の後は確認されません。[`opusplan`](/docs/ja/model-config#opusplan-model-setting) および他のモデル設定で異なるモデルでプランモードを実行する場合、Claude Code はリセットを待機します。

続行されたタスクは他のターンと同様に実行されます。Claude Code は通常通り[権限](/docs/ja/permissions)を要求するため、タスクはあなたが不在の間にプロンプトで停止する可能性があります。再度制限に達した場合、Claude Code は最大 2 回連続で待機を再度有効にしてから停止し、`Automatic continue stopped after repeated usage-limit hits · /rate-limit-options to try again` と表示します。

<h3 id="cancel-the-wait">
  待機をキャンセルする
</h3>

空のプロンプトで `Esc` キーを押すか、行が表示されている間に `Ctrl+C` を押すか、[`/rate-limit-options`](/docs/ja/commands#all-commands) を実行して**Don't continue automatically** を選択してください。Claude Code は `Automatic continue cancelled` で始まる行で確認します。

キャンセル後、プロンプトを送信するか、`/rate-limit-options` から**Wait here, then continue automatically** で始まる行を再度選択するまで、何も続行されません。Claude Code はそのリセットウィンドウに対して自動的に待機を開始しません。次のリセットウィンドウは新たに開始されます。

待機は以下の場合にもタスクを続行せずに終了します。

* **プロンプトを送信する**：Claude Code は待機する代わりにプロンプトを実行します。
* **Claude Code を終了する**：セッションを再開しても待機は再開されません。
* **会話の所有者が変わる**：`/login` でアカウントを切り替えたり、会話をクリアまたはリワインドしたり、`/resume` で別のセッションを再開したり、`/teleport` で取得したり、`/tui` で再起動したり、セッションを Claude Desktop、バックグラウンドセッション、またはクラウドに渡したりします。
* **設定がオフになるか、リセットが 24 時間を超える**：これは Claude Code が自動的に開始した待機のみを終了します。`/rate-limit-options` から選択した待機はカウントダウンを続けます。
* **続行がブロックされる**：続行プロンプトをブロックする[`UserPromptSubmit` フック](/docs/ja/hooks#userpromptsubmit)、またはモデルに到達する前の失敗により、待機が終了します。Claude Code は続行が実行されなかったことを通知します。プロンプトを送信して続行してください。

<h3 id="start-a-wait-yourself">
  自分で待機を開始する
</h3>

Claude Code は以下の場合に自動的に待機を開始しません。

* **リモートコントロールとエージェントチームメイトセッション**：そのターミナルにいる人は依然として開始できます。
* **24 時間以上先のリセット**：週単位の制限は数日先にリセットされる可能性があります。
* **そのファミリー外のモデルを実行している間の Opus または Sonnet 制限**：次のターン時にその制限に達しない可能性があります。[`opusplan`](/docs/ja/model-config#opusplan-model-setting) および制限されたファミリーでプランモードを実行する他のモデル設定はこの例外を取得しません。

これらの場合、および自動続行がオフの場合、Claude Code は自分のターミナルで制限に達したときに、リセットウィンドウごとに 1 回使用制限オプションメニューを開きます。**Wait here, then continue automatically** で始まる行を選択して待機を開始してください。[リモートコントロール](/docs/ja/remote-control)または[エージェントチーム](/docs/ja/agent-teams)メイトセッションでは、自分で `/rate-limit-options` を実行してメニューを開いてください。

Claude Code は以下の場合に待機をまったく提供しません。

* **バックグラウンドセッションと `-p` 実行**：メニュー行は利用できません。
* **API キー、クラウドプロバイダー、および使用量ベースの課金**：そこでの使用はリクエストごとにメーター化されるため、待機するリセットはありません。
* **保存された claude.ai ログインのない[LLM ゲートウェイ](/docs/ja/llm-gateway#subscriptions-and-gateways)**：Claude Code は保存された claude.ai ログインがアクティブな認証情報である場合にのみ待機を提供します。

<h3 id="turn-automatic-continue-off">
  自動続行をオフにする
</h3>

`/config` で**Continue automatically at usage limit** をオフにするか、ユーザー設定で [`autoContinueAtUsageLimit`](/docs/ja/settings-reference#autocontinueatusagelimit) を `false` に設定してください。`/config autoContinueAtUsageLimit=false` も機能します（`-p` を含む）が、`key=value` 形式は設定が無人実行を許可するため、オンに戻すことはできません。Claude Code がこのキーを読み込むどの設定ファイルかは、[設定リファレンス](/docs/ja/settings-reference#autocontinueatusagelimit)に記載されています。

<h2 id="pr-review-status">
  PR レビューステータス
</h2>

オープンなプルリクエストを持つブランチで作業している場合、Claude Code はフッターに「PR #446」などのクリック可能な PR リンクを表示します。リンクには、レビュー状態を示す色付きの下線があります：

* 緑：承認済み
* 黄：レビュー待ち
* 赤：変更をリクエスト
* グレー：ドラフト

プルリクエストがマージまたはクローズされると、バッジは消えます。

`Cmd+click`（macOS）または `Ctrl+click`（Windows/Linux）でリンクをクリックして、プルリクエストをブラウザで開きます。

ステータスは、`git push` または `gh pr create` や `gh pr merge` などのプルリクエストを変更する `gh pr` コマンドがセッションで成功するとすぐに更新されます。

Claude Code は、SSH または tmux 経由でよく発生するターミナルでハイパーリンクサポートを検出できない場合でも、バッジをハイパーリンクとしてレンダリングします。[`FORCE_HYPERLINK=0`](/docs/ja/env-vars) を設定して、バッジをプレーンテキストとしてレンダリングします。

[`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](/docs/ja/env-vars) を設定すると、Claude Code はプルリクエストまたはマージリクエストのステータスをチェックしません。

<Note>
  GitHub リポジトリの PR ステータスには GitHub トークンが必要です。Claude Code はリモートのホストに基づいてトークンを検出します：

  * **github.com**：`GH_TOKEN` または `GITHUB_TOKEN`、または `gh auth login` で保存されたトークン。トークンがない場合、フッターは `gh` CLI がインストールされていないときは `install gh for PR status` を表示し、インストールされているときは `gh auth login for PR status` を表示します
  * **`GH_HOST` として設定された GitHub Enterprise ホスト**：`GH_ENTERPRISE_TOKEN` または `GITHUB_ENTERPRISE_TOKEN`、または `gh auth login --hostname <host>` で保存されたトークン。トークンがない場合、フッターは同じヒントを表示します
  * **その他の GitHub ホスト**：`gh auth login --hostname <host>` で保存されたトークン。トークンがない場合、Claude Code はバッジもヒントも表示しません
</Note>

<h3 id="gitlab-merge-requests">
  GitLab マージリクエスト
</h3>

オープンな GitLab マージリクエストを持つブランチで作業している場合、Claude Code はフッタースロットに `MR !N` バッジを表示します。このスロットは通常 GitHub PR リンクを保持しています。`!N` は GitLab 独自のマージリクエスト番号 N の参照構文です。色付きの下線はマージリクエストの状態を示します：

* 緑：GitLab がマージリクエストをマージ可能として報告
* 黄：その他のオープン状態
* グレー：ドラフト

マージリクエストがマージまたはクローズされると、バッジは消えます。

`git push` または `glab mr create` や `glab mr merge` などのマージリクエストを変更する `glab mr` コマンドがセッションで成功するとすぐに更新されます。

バッジを取得するには、以下が必要です：

* Claude Code v2.1.234 以降
* gitlab.com またはセルフマネージドインスタンスのいずれかを指す、GitLab ホストへのリポジトリリモート
* `PATH` 上の [`glab` CLI](https://gitlab.com/gitlab-org/cli)。`glab auth login` で認証済み

Claude Code はステータスをチェックするときに `glab` のトークン環境変数（`GITLAB_TOKEN` など）を無視するため、エクスポートされたトークンだけではバッジが取得されません。Claude Code はまた、セッションごとに 1 回 `glab` とそのログインを探すため、`glab` をインストールした後または `glab auth login` を実行した後に Claude Code を再起動してください。

<h2 id="issue-reference-links">
  Issue 参照リンク
</h2>

Claude が `owner/repo#123` という形式で issue を言及する場合、ターミナルがハイパーリンクをサポートしていれば、その参照をクリックして開くことができます。Claude Code がターミナルのハイパーリンクサポートを検出できない場合は、[`FORCE_HYPERLINK`](/docs/ja/env-vars) を `1` に設定してリンクをオンにするか、`0` に設定して参照をプレーンテキストのままにしておくことができます。

リンクは 2 部構成の `owner/repo#123` 形式でのみ取得できます。以下は プレーンテキストのままです：

* 単独の `#123`
* `group/subgroup/project#123` などのネストされた GitLab パス
* コードスパンまたはコードブロック内の任意の参照

Claude Code は、参照が指すリポジトリではなく、git remote から識別したリポジトリのホストに対してリンクを構築します：

| リポジトリのホスト                                           | `owner/repo#123` のリンク先                       |
| :-------------------------------------------------- | :------------------------------------------- |
| github.com、GitHub Enterprise ホスト、または以下にリストされていないホスト | `https://<host>/owner/repo/issues/123`       |
| gitlab.com                                          | `https://gitlab.com/owner/repo/-/issues/123` |
| bitbucket.org、codeberg.org、または gitea.com            | リンクなし；参照はプレーンテキストのままです                       |
