# Claude がプロジェクトで進行中の作業を調整する

> 関連する作業の本体を 1 つの会話で Claude に提供し、リポジトリ、指示、メモリを共有する並列クラウドセッションを調整させます。

<Note>
  Projects は Pro および Max プランで公開ベータ版であり、段階的にロールアウト中です。[クラウドセッション](/docs/ja/claude-code-on-the-web) を使用したアカウントで、claude.ai チャットまたは Cowork に既存のプロジェクトがないアカウントから始まり、段階的にロールアウト中です。Team または Enterprise プランではまだ利用できません。[claude.ai/code](https://claude.ai/code) のサイドバーまたは [デスクトップアプリ](/docs/ja/desktop) の Code タブに **Projects** が表示されない場合、ロールアウトがまだアカウントに到達していません。その場合は [ウェイトリストに参加](https://claude.com/form/projects) できます。[エージェントを並列実行する](/docs/ja/agents) で、その間に利用可能なオプションを確認してください。
</Note>

プロジェクトは、Claude が関連する作業のストリームを調整する 1 つの進行中の会話です。実行する必要があることを Claude に伝えると、各タスクのスレッドを開始します。

各スレッドは通常、[クラウドセッション](/docs/ja/claude-code-on-the-web) です。Claude Code がマシンではなくクラウドで実行されます。タスクがコンピュータにしかないものが必要な場合は、Claude に [リモートコントロール](/docs/ja/remote-control) を通じてそのスレッドをコンピュータで実行するよう依頼できます。スレッドは並列実行され、スマートフォンからスレッドをチェックして操舵することができます。クラウドスレッドはラップトップを閉じた後も実行を続けます。

プロジェクトなしで複数のセッションを実行する場合、調整は自分で行う必要があります。各セッションが何に取り組むかを決定し、各セッションの開始時に同じバックグラウンド情報を繰り返し、どのセッションが完了したか、または回答が必要かを確認します。プロジェクトを使用すると、代わりに以下のことができます。

* **作業を 1 つの場所に送信する**: バグレポート、スタックトレース、またはタスクのリストが発生するたびに会話に貼り付けます。Claude は各作業のスレッドを開始するか、その領域で既に作業しているスレッドに渡し、その場で簡単な質問に答えます。
* **コンテキストを 1 回設定する**: すべての新しいスレッドはプロジェクトの指示で開始されるため、対象ブランチなどの 1 回述べたルールがすべてのスレッドに到達します。
* **立ち去って完了した作業に戻る**: 1 時間後または翌朝に戻ると、**Overview** ペインに完了したスレッド、レビュー準備ができたプルリクエスト、回答を待っているスレッドが表示されます。

プロジェクトで実行する作業が既にわかっている場合は、[プロジェクトを作成する](#create-a-project) に直接進んでください。

<h2 id="when-to-use-a-project">
  プロジェクトを使用する場合
</h2>

プロジェクトは、作業に 1 つのセッションを超えて続く目標があり、タスクを生成し続ける場合に作成する価値があります。これらの種類の作業はプロジェクトに適しています。

* **多くのリポジトリにまたがる 1 つの目標**: 「すべてのサービスを新しい lint 設定に対応させる」。Claude はリポジトリごとに 1 つのスレッドを実行でき、各スレッドは独自のプルリクエストを持ち、[**Overview** ペイン](#see-what-needs-you-in-overview) にはどのスレッドがレビュー準備ができているかが表示されます。
* **継続的に供給する領域**: 1 つのサービスのバグ、スタックトレース、レビューリクエストが到達するたびに会話に貼り付けられます。1 つの修正後に Claude に覚えておくよう指示した落とし穴は、次のために [プロジェクトメモリ](#give-a-project-standing-context) に含まれます。
* **セッションより大きいビルドまたはマイグレーション**: 「`docs/spec.md` が説明していることをビルドする」または「アプリを非推奨の ORM から移動する」。作業は各部分を取得するスレッドに分割され、Claude に早期に覚えておくよう求めた決定は後のスレッドに到達し、ビルド中に見つかった仕様の変更とバグが同じ会話に入ります。
* **コードではない作業**: 「これらのチケットで最も一般的な 10 の統合ミスを見つける」など、新しい質問で何度も戻ってくる契約フォルダまたはサポートチケットエクスポート。リポジトリを追加する代わりにドキュメントをアップロードし、スレッドはプロジェクトの [**Library** タブ](#see-what-needs-you-in-overview) にファイルとして各レポートを配信します。

これらのいずれかで、タスクのバッチを送信し、Claude に確認を求めずに開始するよう指示し、立ち去り、戻ったときに [**Waiting on you**](#see-what-needs-you-in-overview) の下で必要なスレッドを見つけるか、Claude に作業の一部を [ルーチン](/docs/ja/routines) としてスケジュールに入れるよう求めることができます。これらのいずれかが状況に当てはまる場合は、[プロジェクトを作成してください](#create-a-project)。

<h3 id="when-something-else-fits-better">
  別のものがより適切な場合
</h3>

Cloud スレッドは GitHub リポジトリおよびプロジェクトにアップロードしたファイル、フォルダ、Google Drive フォルダで機能し、マシンにのみ存在するファイルやツールでは機能しません。タスクがマシンを必要とする場合は、[Remote Control](/docs/ja/remote-control) を通じてそのスレッドをそこで実行するよう Claude に依頼してください。[制限事項](#limitations) にはそれに必要なものが記載されています。これらの場合は別のものがより適切です。

* **セッションに収まる 1 つのタスク**: 「不安定なログインテストを修正する」。[クラウドセッション](/docs/ja/claude-code-on-the-web) を自分で開始します。
* **すべてのタスクがマシンを必要とする作業**: ローカルデータベース、デバイスエミュレータ、または VPN の背後にある API。ローカルセッションを使用するか、[エージェントビュー](/docs/ja/agent-view) を使用して複数を同時に実行します。作業がローカルファイルのみを必要とする場合は、代わりにプロジェクトにアップロードしてください。
* **スケジュールで繰り返される 1 つのタスク、その周りに会話がない**: 「毎週月曜日に依存関係レポートを投稿する」。[ルーチン](/docs/ja/routines) を単独で作成します。
* **複数の人が Claude に作業を与え、Slack チャネルで一緒に操舵する**: [Claude Tag](https://claude.com/docs/claude-tag/overview) を参照してください。

プロジェクトは他の Claude Code セッションと同じプラン制限を使用し、より速く使用します。[使用量とコスト](#usage-and-cost) はプランに何が影響するか、およびそれを低く保つ方法をカバーしています。

<h2 id="how-a-project-is-organized">
  プロジェクトの構成方法
</h2>

プロジェクトは Claude との 1 つの調整会話と、それが作業を行うために開始するスレッドです。これらはその部分です。

* **プロジェクト会話**: Claude がコーディネーターとして機能する 1 つの長時間実行セッション。送信したものを取得し、何がスレッドになるかを決定し、開始したすべてのスレッドを追跡します。スレッドが報告する内容を確認し、実行するすべてのステップは確認しません。
* **スレッド**: ワーカー。各スレッドは独自のコンテキストウィンドウを持つ個別のセッションで、1 つの作業を実行し、完了時に会話に報告します。クラウドスレッドは独自のブランチで作業し、作業が必要な場合はプルリクエストを開きます。
* **すべてのクラウドスレッドが開始する内容**:
  * プロジェクトのリポジトリとファイル、およびその [指示とメモリ](#give-a-project-standing-context)
  * `CLAUDE.md` とスキル、および [プロジェクトの各リポジトリ](#what-threads-pick-up-from-your-repositories) のスキル、および 1 つのリポジトリを持つプロジェクトでは、そのリポジトリの権限ルールと hooks も
  * [コネクタ](#get-skills-plugins-connectors-and-tools-into-threads) を claude.ai アカウントに
  * ネットワークアクセス、環境変数、API 認証情報、インストール済みツールを設定する [クラウド環境](#choose-an-environment-for-threads)
* **Overview ペイン**: [すべてのスレッドを一度に確認](#see-what-needs-you-in-overview) でき、どのスレッドが必要かを確認できる場所。その他のタブは、追加したファイルとスレッドが生成したファイルの **Library**、スレッドが開いたプルリクエストの **Pull requests**、プロジェクトのスケジュール作業の **Routines** です。

クラウドスレッドは、独自のマシンの Claude Code セットアップから何も取得しません。[スキル、プラグイン、コネクタ、ツールをスレッドに取得する](#get-skills-plugins-connectors-and-tools-into-threads) は、それらが不足しているものを提供する方法をカバーしています。

これは、会話を通じてスレッドが作業を行う方法と、**Overview** がその状態を追跡する方法です。

<h2 id="create-a-project">
  プロジェクトを作成する
</h2>

プロジェクトは [claude.ai/code](https://claude.ai/code)、デスクトップアプリの Code タブ、または [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) と [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude) 向けの Claude モバイルアプリで作成および使用します。ブラウザとデスクトップアプリでは、プロジェクトを開始する 2 つの方法があります。

* **ゼロから開始**：Claude に実行させたい作業の流れが決まっている場合は、**New project** ダイアログを開いて名前を付けます。[ゼロからプロジェクトを開始する](#start-a-new-project-from-scratch)でダイアログの手順を説明しています。
* **既に作業を行っているクラウドセッションから開始**：そのセッションのメニューから **Continue as a project** を選択すると、Claude がセッションで行っていた内容からプロジェクトのセットアップを提案します。[既存のクラウドセッションから開始する](#start-from-an-existing-cloud-session)を参照してください。

どちらの方法でも、まず [前提条件を確認](#check-the-prerequisites)してください。

<h3 id="check-the-prerequisites">
  前提条件を確認する
</h3>

プロジェクトを作成する前に、プランと GitHub のセットアップ、および作業が到達する必要があるものを確認してください。

* **プラン**：Pro または Max プランを利用しており、サイドバーに **Projects** が表示されている。
* **GitHub（プロジェクトがコードで作業する場合）**：コードが GitHub Enterprise Server、GitLab、または Bitbucket ではなく github.com にあり、接続された GitHub アカウントがそれへのプッシュアクセス権を持っており、Claude GitHub App がインストールされている。[`/web-setup`](/docs/ja/web-quickstart#connect-from-your-terminal)で GitHub を接続した場合、そのトークンは他のクラウドセッションがリポジトリに到達することを許可しますが、Claude GitHub App が必要なプロジェクトスレッドには十分ではありません。[GitHub アクセスをセットアップする](#set-up-github-access)に手順があります。
* **ネットワーク、認証情報、ツール**：これらはプロジェクトの [クラウド環境](#choose-an-environment-for-threads)から取得されます。デフォルト環境は既に [一般的なパッケージレジストリ](/docs/ja/cloud-environments#default-allowed-domains)に到達しているため、作業が他のドメイン、シークレット、またはプリインストールされていないツールを必要とする場合のみ確認してください。作業が MCP サーバーを必要とする場合は、[claude.ai connectors](https://claude.ai/customize/connectors)で接続済みとして表示されていることを確認してください。

<h3 id="start-a-new-project-from-scratch">
  ゼロからプロジェクトを開始する
</h3>

ゼロからプロジェクトを開始するとは、**New project** ダイアログを開き、作業の流れに名前を付け、オプションでゴールと作業対象のリポジトリおよびファイルを指定することを意味します。必須なのは名前だけなので、プロジェクトを最初に作成してから、作業が進むにつれて残りを入力できます。

<Steps>
  <Step title="Projects を開く">
    [claude.ai/code](https://claude.ai/code) またはデスクトップアプリの Code タブで、左側のサイドバーから **Projects** を選択し、**New project** を選択します。ブラウザでは [claude.ai/code/projects/browse](https://claude.ai/code/projects/browse) に直接移動することもできます。
  </Step>

  <Step title="New project ダイアログに入力する">
    プロジェクトを 1 つの作業の流れにスコープします。これは、1 つの API をレイテンシ目標の下に保つために必要なすべてのことなど、継続的に追加していくものです。[プロジェクトを使用する場合](#when-to-use-a-project)にさらに多くの例があります。次に、ダイアログのフィールドに入力します。

    * **Name**：**Projects** リストでプロジェクトがどのように表示されるか。
    * **Goal**（オプション）：「p95 API レイテンシを 200 ms 以下に保つ」など、達成しようとしていることの 1 行の説明。会話内の Claude はそれに向かって作業します。ゴールがない場合、Claude は送信したタスクから作業し、後で **Project settings > General** でゴールを追加できます。
    * **Context**（オプション）：このプロジェクトが作業する GitHub リポジトリ、およびスレッドが読むべきファイル、フォルダ、または Google Drive フォルダ。各項目に対して **Add** をクリックします。作業が触れる可能性のあるすべてのリポジトリではなく、ほとんどのタスクが必要とするリポジトリを追加します。[追加するリポジトリを決定する](#decide-which-repositories-to-add)で選択について説明しており、後で **Project settings > Environment** でさらに追加できます。

    スレッドがどのように機能すべきかについての常設ルールは [プロジェクト指示](#give-a-project-standing-context)に記載されており、プロジェクトが存在した後に設定します。
  </Step>

  <Step title="プロジェクトを作成する">
    **Create project** をクリックします。プロジェクトの会話が開き、下部にメッセージボックスが表示されます。ここで Claude に作業を説明します。

    最初のプロジェクトでは、最初にメッセージを送信しない限り、プロジェクトが作成されるとすぐに Claude が独自のターンを実行します。そのターンはプランを使用します。その中で Claude は以下を実行する可能性があります。

    * プロジェクトが読み取り可能なリポジトリを持っている場合、何も変更せずにリポジトリを探索し、次のステップを提案する 1 つのスレッドを開始します。
    * 最近のクラウドセッションから取得した **Setup recommendations** を投稿します。追加するリポジトリ、作成するルーチン、開始できるスレッド。推奨されるすべてのリポジトリとルーチンはデフォルトでオンになっています。不要なものはオフに切り替えてから **Update setup** をクリックして残りを追加するか、推奨事項を無視して自分で作業を説明します。
  </Step>
</Steps>

プロジェクトはサイドバーの **Projects** の下にリストされ、その会話が開いています。[最初のバッチ](#your-first-batch)では、作業を送信する前に何をセットアップするかについて説明しています。

<h3 id="start-from-an-existing-cloud-session">
  既存のクラウドセッションから開始する
</h3>

既にプロジェクトに属する作業を行っているクラウドセッションがある場合は、サイドバーのセッションのメニューを開いて **Continue as a project** または **Move to project** を選択します。

* **Continue as a project** はセッションにちなんで名付けられた新しいプロジェクトを作成して開きます。Claude はセッションを読み取り、確認するための **Setup recommendations** を会話に投稿します。元のセッションはセッションリストに残り、ターンの途中だった場合は実行を続けるため、両方が同時に作業するのを望まない場合は自分で停止してください。クラウドセッションのメッセージボックスの上に表示される可能性がある **Set up project** バナーを使用する場合、結果は同じですが、プロジェクトが開くとセッションの実行中のターンが停止します。
* **Move to project** はセッションの作業を既存のプロジェクトに持ち込みます。そのプロジェクトの会話にメッセージを投稿し、Claude にセッションを読み取って中断したところから再開するよう求め、新しい作業はプロジェクト独自のスレッドで続行されます。元のセッションはセッションリストに変更されずに残ります。

<h3 id="set-up-github-access">
  GitHub アクセスをセットアップする
</h3>

ほとんどの GitHub セットアップはプロジェクトごとではなく、1 回だけ行われます。GitHub アカウントを Claude に 1 回接続し、Claude GitHub App はリポジトリごとに 1 回、またはすべてのリポジトリを付与する場合は GitHub 組織全体に 1 回インストールされます。Claude GitHub App がまだカバーしていないリポジトリを追加する場合、または SSO を強制する GitHub 組織内のリポジトリを追加する場合は、これらの手順に戻ります。

<Steps>
  <Step title="GitHub アカウントを接続する">
    以前に claude.ai/code を使用していない場合、最初のアクセスで GitHub の接続を案内します。[GitHub を接続する](/docs/ja/web-quickstart#connect-github)を参照してください。それ以外の場合は、[GitHub 認証オプション](/docs/ja/claude-code-on-the-web#github-authentication-options)のいずれかを使用します。
  </Step>

  <Step title="Claude GitHub App をプロジェクトのリポジトリにインストールする">
    [Claude GitHub App](https://github.com/apps/claude) をインストールし、プロジェクトが使用するリポジトリを付与します。GitHub 組織が所有するリポジトリでは、組織の所有者のみがインストールを完了できます。所有者でない場合、GitHub は所有者にインストールリクエストを送信し、所有者が承認するまでプロジェクトはそのリポジトリを使用できません。
  </Step>

  <Step title="SSO を強制する組織の SSO を認可する">
    GitHub 組織が SAML SSO を強制する場合、GitHub を再接続し、その組織の Claude アプリを認可します。これを行うまで、その組織のプライベートリポジトリは **New project** ダイアログまたは **Project settings > Environment** に表示されません。
  </Step>
</Steps>

これらのステップのいずれかが不完全な場合、**New project** ダイアログとプロジェクトページは不足しているステップに名前を付け、それを完了する場所へのリンクを提供します。そこでステップを完了してから、ダイアログが提供する場合は **Check again** をクリックします。その後もリポジトリがリストに表示されない場合は、GitHub の Claude GitHub App のインストールを [github.com/settings/installations](https://github.com/settings/installations) で個人アカウント用に開き、**Repository access** の下にリポジトリがリストされていることを確認します。スレッドまたはプロジェクトがアクセスがまだ間違っている場合に報告するエラーメッセージについては、[リポジトリアクセスエラー](#repository-access-errors)を参照してください。

<h2 id="work-in-a-project">
  プロジェクトで作業する
</h2>

プロジェクト会話を通じて Claude に作業を与えます。一度に 1 つのタスク、または複数のタスクを同時に、さらに更新や思いついたことを送信します。Claude は各メッセージをルーティングし、スレッドが作業を実行して報告します。

<h3 id="your-first-batch">
  最初のバッチ
</h3>

プロジェクトに新しい作業バッチを送信する前に、最初のスレッドが希望する方法で戻ってくるようにセットアップします。

1. [プロジェクト指示を書く](#write-project-instructions)：すべてのスレッドが開始する簡潔な指示。対象とするブランチ、スレッドが作業をチェックする方法、あなたの承認が必要なものなどが含まれます。
2. 実際の作業の小さな部分を 1 つ送信するか、Claude が提案したスレッドの 1 つを開始し、スレッドが完了したときにスレッドを開いて、どのように報告し、ブランチで何を実行したかを確認します。間違った仮定をしたか、必要なものに到達できなかった場合は、[スレッドが尋ねる代わりに推測または停止した](#threads-guessed-or-stalled-instead-of-asking)で修正する場所をカバーしています。
3. **プロジェクト設定 > 一般**で**スレッドモデル**と**スレッド努力**を確認します。新しいプロジェクトはすべてのスレッドを Opus で高努力で実行します。これはあなたのプランを最も速く消費します。[モデルを選択して Claude にコンテキストを管理させる](#choose-models-and-let-claude-manage-context)は代替案をカバーしています。
4. Claude に[スレッドを開始する前に提案し、一度に数個実行する](#tune-how-claude-runs-a-project)ことを求め、数個のスレッドが希望する方法で戻ってきたら、それらの制限を削除します。

<h3 id="send-work-and-read-results">
  作業を送信して結果を読む
</h3>

Claude は会話で送信する各メッセージがどこに行くかを決定します。

* 簡単な質問は通常、会話で答えが得られます。
* 新しい作業は新しいスレッドまたはその領域で既に作業しているスレッドに送られ、Claude はどちらかを教えてくれます。新しい各スレッドはあなたのメッセージの下にカードとして表示されます。スレッドのタイトルとステータスを含むボックスで、クリックしてスレッドを開きます。
* 1 つのメッセージ内の複数の関連のないタスクは、別々のスレッドになります。

Claude がメッセージを希望と異なる方法でルーティングした場合は、そう言ってください。[Claude がプロジェクトを実行する方法を調整する](#tune-how-claude-runs-a-project)は、既存のスレッドをフォローアップに再利用するか、代わりにその場で回答するなど、Claude に伝えることができることをリストしています。

スレッドの完全な結果はスレッドに留まり、会話でそのカードを開いて読みます。スレッドが生成したファイルは、**概要**の**ライブラリ**タブにもあります。

時々 Claude はスレッドを開始する代わりに提案し、**提案されたスレッド**リストに表示されます。提案の矢印をクリックしてそのスレッドを開始します。複数がリストされている場合、リストの下のボタンはすべてを開始します。

<h3 id="review-a-thread’s-pull-request">
  スレッドのプルリクエストをレビューする
</h3>

クラウドスレッドがコードを変更する場合、別途指示しない限り、これが実行されます。

* **ブランチ**：リポジトリのデフォルトブランチから開始された新しいブランチで作業します。
* **プルリクエスト**：あなたが要求したときに開き、バグ修正または別の具体的な変更のために自動的に開くことができます。
* **開いた後**：[自動修正](/docs/ja/claude-code-on-the-web#auto-fix-pull-requests)をオンにしてプルリクエストを監視します。他のクラウドセッションで自動修正がオンかどうかに関わらず。CI が失敗したときに修正をプッシュし、レビューコメントに対処し、チェックが成功してプルリクエストがあなたの準備ができたときにスレッドで返信します。

スレッドがブランチをプッシュしたか、プルリクエストを開いた場合、会話でそのカードは次のステップのボタンを表示できます。

* **競合を解決**、**CI を修正**、**コメントに対処**、および**マージする**は、その指示をあなたからのメッセージとしてスレッドに送信します。プルリクエストに反応するのを待つ代わりに、スレッド自体にプロンプトを出すことができます。
* **PR をレビュー**は GitHub でプルリクエストを開きます。
* **PR を作成**は、アイドル状態のスレッドがブランチをプッシュしたが、プルリクエストを開いていない場合に表示されます。クリックすると、スレッドに開くように指示を送信するのではなく、そのブランチから直接プルリクエストを作成します。

スレッドがプルリクエストを開く時期を変更するには、たとえば要求したときのみ、またはどのブランチから開始するかを変更するには、タスクまたは[プロジェクト指示](#write-project-instructions)で言ってください。

<h3 id="see-what-needs-you-in-overview">
  概要で必要なものを確認する
</h3>

会話の横の**概要**ペインは、プロジェクトのスレッドを追跡します。新しいプロジェクトを初めて開いたときは既に開いています。プロジェクトヘッダーの**概要**ボタンはそれを閉じて再度開き、スレッドがあなたを待っているときにドットを表示します。

デスクトップアプリでは、Claude が会話に投稿したとき、スレッドがエラーに達したとき、またはスレッドがあなたの入力を必要とするときにデスクトップ通知も取得します。プロジェクトを開いたままにしておく必要はありません。スレッドが各ターンを完了するたびに 1 つ取得するか、プロジェクトの通知をオフにするには、プロジェクトのサイドバーメニューで**通知**を選択します。これらの通知はデスクトップのみです。ブラウザでは、**概要**ボタンのドットを確認してください。

ペインの**スレッド**タブはスレッドを状態でグループ化します。

| グループ         | 含まれるもの                                                                                                            |
| :----------- | :---------------------------------------------------------------------------------------------------------------- |
| **レビュー準備完了** | プルリクエストが開いており、レビューを待っているスレッド                                                                                      |
| **あなたを待機中**  | あなたの返信または承認が必要、または失敗したスレッド                                                                                        |
| **作業中**      | まだ実行中のスレッド                                                                                                        |
| **ランディング**   | プルリクエストが承認されたか、マージキューに入っているスレッド                                                                                   |
| **アイドル**     | 完了し、何も待っていないスレッド                                                                                                  |
| **解決済み**     | 完了としてマークされたスレッド。スレッドのメニューからあなたが、プルリクエストのマージなど最後のステップを実行した後に Claude が、または活動がない 1 週間後に自動的に。同じメニューから 1 つを再度開くことができます |

ペインの他のタブは、追加したファイルとフォルダ、およびスレッドが生成したファイルの**ライブラリ**、スレッドが開いたら**プルリクエスト**、およびこのプロジェクトから Claude が設定した[ルーチン](/docs/ja/routines)の**ルーチン**です。

<h3 id="open-a-thread-when-you-need-control">
  コントロールが必要なときにスレッドを開く
</h3>

会話でスレッドのカードをクリックするか、**概要**でその行をクリックして、概要ペインでそのトランスクリプトを開きます。そこから以下を実行できます。

* Claude が何をしたかをステップバイステップで読みます。
* スレッド独自のメッセージボックスに書き込んでタスクを操舵します。そこのメッセージはそのスレッドに直接送られ、プロジェクト会話でのフォローアップは Claude がフォローアップをそのスレッドと一致させるときにのみそれに到達します。
* スレッドが待機している権限プロンプトに答えます。
* **停止**でスレッドを中断します。これはスレッドが作業中に送信ボタンを置き換えるか、Esc を押します。

<h3 id="choose-models-and-let-claude-manage-context">
  モデルを選択して Claude にコンテキストを管理させる
</h3>

**プロジェクト設定 > 一般**でモデルと努力を設定します。新しいプロジェクトはすべての場所で Opus を実行し、スレッドの高[努力](/docs/ja/model-config#adjust-effort-level)と会話の低努力を実行します。

* **スレッドモデル**と**スレッド努力**はスレッドに適用されます。1 つのタスクに別のモデルを使用するには、タスクで要求します。既に実行中のスレッドの場合は、そのスレッドのモデルピッカーを使用します。
* **コーディネーターモデル**と**コーディネーター努力**は、プロジェクト会話で Claude に適用されます。

プロジェクトではコンテキストウィンドウを管理しません。スレッドは自動的にコンパクトになり、会話は最近のメッセージ、最近のスレッド、およびプロジェクトメモリから機能し、完全な履歴ではなく、プロジェクトが実行される限り続きます。[プロジェクトメモリ](#give-a-project-standing-context)に決して削除されてはいけないものを入れてください。1 つのスレッドがそのコンテキストを超える場合、[Claude はこのターンでコンテキストを使い果たしました](#context-limit)が表示されます。

<h3 id="tune-how-claude-runs-a-project">
  Claude がプロジェクトを実行する方法を調整する
</h3>

会話で Claude に、一度に実行するスレッド数、更新を投稿するタイミング、プルリクエストを開くタイミングを伝えます。Claude がコーディネートしている方法が希望と異なる場合は、そう言ってください。たとえば、以下のように言うことができます。

* 「スレッドを提案し、開始する前に私の承認を待ってください」または「これらを今すぐ開始してください。確認を求めないでください」
* 「一度に最大 2 つのスレッドを実行してください」または「同じ領域でのフォローアップに既存のスレッドを再利用してください」
* 「より短い更新を投稿してください」または「何かが完了またはブロックされたときのみ投稿してください」
* 「すべてのスレッドのステータス更新をください」
* 「このタスクをより小さいモデルで実行してください」
* 「計画を見るまでプルリクエストを開かないでください」
* 「これらのリポジトリで何が間違っているかを教えてください。まだ何も修正しないでください」。スレッドになる前に調査結果を確認したい場合
* 「代わりにここで答えてください」。Claude が簡単な質問として意図したものに対してスレッドを開始する場合

Claude はこのような設定を[プロジェクトメモリ](#give-a-project-standing-context)に自動的に保存し、後のスレッドでそれに従います。これらは Claude が守る指示であり、強制される設定ではないため、この方法で与えるスレッド制限はハードキャップではありません。最初からすべてのスレッドに正確に適用したい場合は、プロジェクト指示に 1 つを追加します。

<h3 id="unblock-a-thread-waiting-on-approval">
  承認を待機しているスレッドのブロックを解除する
</h3>

スレッドはスレッドのモデルがサポートしている場合、[自動モード](/docs/ja/permission-modes#eliminate-prompts-with-auto-mode)で実行されるため、ほとんどのツール呼び出しはあなたに尋ねずに実行されます。スレッドがあなたの承認を必要とする場合、プロンプトはそのスレッド内にあり、スレッドはあなたがそこで答えるまで待機します。プロジェクト会話で Claude に先に進むように伝えることはそれに到達しません。

各承認はそのプロンプト、またはより広いオプションを選択した場合はそのスレッドの残りをカバーします。すべてのスレッドが特定のコマンドを尋ねずに実行できるようにするか、いくつかをブロックするには、リポジトリの`.claude/settings.json`に[権限ルール](/docs/ja/permissions)を追加します。クラウドスレッドはそれらを 1 つのリポジトリを持つプロジェクトでのみ適用します。[スレッドがリポジトリから何を取得するか](#what-threads-pick-up-from-your-repositories)を参照してください。

<h2 id="give-a-project-standing-context">
  プロジェクトに常時コンテキストを付与する
</h2>

プロジェクトメモリ、プロジェクト指示、およびプロジェクトのリポジトリ、ファイル、環境は、スレッド全体でコンテキストを保持します。各項目を 1 回設定すると、すべての新しいスレッドに適用されます。

| コンテキスト        | 保持される内容                                                                                                             | 設定方法                                                                                                                 |
| :------------ | :------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------- |
| プロジェクトメモリ     | Claude がプロジェクトについて保持するメモ（要件、決定、落とし穴など）をファイルとして保存します。すべてのクラウドスレッドは開始時にインデックスファイル `MEMORY.md` を読み込み、必要に応じて他のファイルを開きます | プロジェクト会話またはクラウドスレッド内で Claude に要件、決定、落とし穴を記憶するよう依頼するか、忘れるよう依頼します。**プロジェクト設定 > メモリ** でファイルを読み込み、編集、削除します               |
| プロジェクト指示      | 各新しいスレッドおよびプロジェクト会話内の Claude に送信されるテキスト（最大 16,000 文字）。[プロジェクト指示を書く](#write-project-instructions) に記載内容を説明しています      | **プロジェクト設定 > メモリ > プロジェクト指示**、または会話内で Claude に指示の変更を依頼します                                                            |
| リポジトリ、ファイル、環境 | すべてのクラウドスレッドがクローンするリポジトリ、すべてのクラウドスレッドが `/mnt/project-files` の下で読み取ることができるフォルダとファイル、およびクラウドスレッドが実行されるクラウド環境          | **プロジェクト設定 > 環境** のリポジトリと環境、または会話内で Claude にリポジトリをプロジェクトに追加するよう依頼します。**概要** の **ライブラリ** タブの **追加** からファイルとフォルダを追加します |

**プロジェクト設定 > メモリ** は、これらのファイルを **自動メモリ** の下にリストしています。これは Claude がプロジェクト内で作業する際に自分で書き込むためです。これらは、Claude Code があなたのマシンで保持する [自動メモリ](/docs/ja/memory) とは別です。両方とも `MEMORY.md` インデックスを使用していますが、プロジェクトメモリはプロジェクトのリポジトリ内の `CLAUDE.md` ファイルとは別です。各クラウドスレッドは開始時にクローンからこれらの `CLAUDE.md` ファイルを読み込むため、リポジトリに関する指示をその `CLAUDE.md` に、プロジェクトに関するメモをプロジェクトメモリに記載してください。

<h3 id="write-project-instructions">
  プロジェクト指示を書く
</h3>

プロジェクト指示は、各新しいスレッドが開始する際の指示書です。プロジェクトヘッダーのギアアイコンをクリックして **プロジェクト設定** を開き、**メモリ > プロジェクト指示** に移動します。有用な指示書には以下が含まれます：

* プロジェクトの目的
* 作業が行われる場所：どのリポジトリ、どのブランチから開始するか、プルリクエストの命名方法
* スレッドが作業完了と判断する前に自分の作業をチェックする方法
* 必要なものが見つからない場合の対応方法
* あなたの承認が必要な事項

例：

```text theme={null}
このプロジェクトは、payments API の p95 レイテンシを 200 ms 以下に保ちます：プロファイリング、クエリとキャッシング修正、およびそれに伴う依存関係のアップグレードを payments-api リポジトリで行います。

- main からブランチを作成し、スレッドごとに 1 つのドラフトプルリクエストを開きます。
- 作業完了と判断する前に、`make test` と `make lint` を実行し、最終メッセージに概要行を貼り付けます。
- リポジトリ、シークレット、API、コネクタなど、必要なものに到達できない場合は、最初のメッセージで正確に何が不足しているかを述べて停止します。代替案を提案したり、モックを作成したり、推測したりしないでください。
- マージ、強制プッシュ、CI 設定の変更は、スレッド内で私に確認してから行ってください。
```

1 つのリポジトリに関するルール（ビルドコマンドなど）は、そのリポジトリの `CLAUDE.md` に属します。このファイルは、リポジトリがプロジェクトの一部である場合、すべてのクラウドスレッドが開始時に読み込みます。作業が進行中の場合、スレッドを修正するときは、Claude にその修正を記憶するよう依頼してください。修正は [プロジェクトメモリ](#give-a-project-standing-context) に記録され、後のクラウドスレッドはそれを使用して開始します。

<h3 id="decide-which-repositories-to-add">
  追加するリポジトリを決定する
</h3>

プロジェクトに追加するリポジトリは、すべてのクラウドスレッドでそれらに含まれるすべてのもの（コード、`CLAUDE.md`、スキル）を持ってきます。追加しないリポジトリにもアクセスできます：クラウドスレッドがタスクで必要な場合、自分自身にリポジトリを追加できます。ほとんどのプロジェクトは両方を使用します：

* **プロジェクトに追加します**。**新規プロジェクト** ダイアログ、**プロジェクト設定 > 環境**、または会話内で Claude にプロジェクトに追加するよう依頼します。その後のすべてのクラウドスレッドは、タスクがそれに触れるかどうかに関わらず、それをクローンして `CLAUDE.md` とスキルを読み込んで開始します。1 つのリポジトリから複数のリポジトリに移行すると、各リポジトリの `.claude/settings.json` からスレッドが取得するものも変わります。[スレッドがリポジトリから取得するもの](#what-threads-pick-up-from-your-repositories) を参照してください。
* **オフのままにして、スレッドが必要な場合に追加させます。** タスクがプロジェクトにないリポジトリを必要とするクラウドスレッドは、自分自身にそれを追加でき、スレッド内のメモはそれがこのスレッドのみに追加されたことを示します。クローンはタスクの途中で発生するため、そのリポジトリの `CLAUDE.md` とスキルはスレッド開始時には存在しません。次のスレッドは再度それなしで開始します。スレッドが追加するリポジトリは、プロジェクトリポジトリと同じ [前提条件](#check-the-prerequisites) が必要です：Claude GitHub App がインストールされていることと、GitHub アカウントからのプッシュアクセスです。

プロジェクトはリポジトリをまったく必要としません。そのクラウドスレッドは、研究、ドキュメント作成、独自のサンドボックスでのコード作成と実行を行うことができ、**ライブラリ** タブにファイルを配信します。そこのクラウドスレッドは、タスクが必要な場合、自分自身にリポジトリを追加することもできます。

プロジェクトにリポジトリがある場合、Claude はプロジェクトが既に使用している GitHub オーナーからのみリポジトリを追加できます。プロジェクトに追加するか、スレッドが自分自身に追加するかに関わらず同じです。別のオーナーからリポジトリを持ってくるには、**プロジェクト設定 > 環境** で自分でプロジェクトに追加してください。

サーバー、ウェブ、モバイル、デスクトップコードを持つ機能など、多くのリポジトリにまたがるプロジェクトの場合、ほぼすべてのタスクが触れる 1 つまたは 2 つのリポジトリを追加し、[プロジェクト指示](#write-project-instructions) で他のリポジトリに名前を付けて、Claude が残りのコードがどこにあるかを知るようにします。クラウドスレッドは小さく開始し、それらが必要なタスクに対してのみ他のリポジトリを取得します。

<h3 id="what-threads-pick-up-from-your-repositories">
  スレッドがリポジトリから取得するもの
</h3>

各クラウドスレッドはプロジェクト内のすべてのリポジトリをクローンし、すべてのリポジトリから `CLAUDE.md` とスキルを読み込みます。権限ルール、フック、`env` は、スレッドが開始するディレクトリ内の `.claude/settings.json` からのみ取得されます：プロジェクトが 1 つのリポジトリを持つ場合はリポジトリ内、複数のリポジトリを持つ場合はクローンの上で、リポジトリのファイルはそれらに対して読み込まれません。

| 各リポジトリ内                                       | 1 つのリポジトリ                                                                                                 | 複数のリポジトリ                                           |
| :-------------------------------------------- | :-------------------------------------------------------------------------------------------------------- | :------------------------------------------------- |
| `CLAUDE.md`                                   | スレッド開始時に読み込まれます                                                                                           | スレッド開始時にすべてのリポジトリから読み込まれます                         |
| `.claude/` の下のスキル、エージェント、コマンド                 | 読み込まれます                                                                                                   | すべてのリポジトリから読み込まれます                                 |
| `.claude/settings.json` で有効化されたプラグイン          | 読み込まれません。代わりに **プロジェクト設定 > プラグイン** でプラグインを追加してください                                                        | 読み込まれません。代わりに **プロジェクト設定 > プラグイン** でプラグインを追加してください |
| `.claude/settings.json` で定義された権限ルール、フック、`env` | スレッドに適用されます。ただし、[クラウドセッションが認識しない](/docs/ja/cloud-environments#what-carries-over-from-your-setup) `env` キーは除きます | 適用されません                                            |

複数のリポジトリを持つプロジェクトでは、各クローンは `CLAUDE.md` 読み込みが有効になった [追加ディレクトリ](/docs/ja/memory#load-from-additional-directories) としてスレッドに接続されます。これが、スレッドがそれらの上で開始されるにもかかわらず、すべてのリポジトリの `CLAUDE.md` とスキルが開始時に読み込まれる理由です。このようなプロジェクトでは、スタンディングルールをプロジェクト指示に記載し、[クラウド環境](#choose-an-environment-for-threads) を通じてスレッドに環境変数を提供してください。

<h3 id="choose-an-environment-for-threads">
  スレッドの環境を選択する
</h3>

すべての新しいクラウドスレッドはプロジェクトの [クラウド環境](/docs/ja/cloud-environments) で開始します。環境は、スレッドが到達できるドメイン、スレッドが持つ環境変数、リクエストに追加される API 認証情報、Claude が開始する前にセットアップスクリプトがインストールするものを設定します。クラウドスレッドは、**プロジェクト設定 > 環境** で選択するまで、デフォルトの Anthropic ホスト環境を使用します。

クラウドスレッドが内部 API またはプライベートパッケージレジストリに到達する必要がある場合、またはマシンが通常保持するトークンが必要な場合は、プロジェクトではなく環境を変更してください：[ネットワークアクセス](/docs/ja/cloud-environments#network-access)、[API 認証情報を追加](/docs/ja/cloud-environments#add-api-credentials)、[セットアップスクリプト](/docs/ja/cloud-environments#setup-scripts) を参照してください。

<h3 id="get-skills-plugins-connectors-and-tools-into-threads">
  スキル、プラグイン、コネクタ、ツールをスレッドに取得する
</h3>

クラウドスレッドはマシンにのみインストールされているスキル、MCP サーバー、プラグイン、ツールを持っていません。[Remote Control](/docs/ja/remote-control) を通じてマシン上で Claude が実行するスレッドは、そこにインストールされているものを使用します。これらのそれぞれをクラウドスレッドで利用可能にするには：

* スキル、サブエージェント、コマンド：プロジェクトに追加したリポジトリにコミットします。例えば、`.claude/skills/<skill-name>/SKILL.md` のスキル。各クラウドスレッドはプロジェクト内のすべてのリポジトリをクローンし、それぞれから `.claude/skills/`、`.claude/agents/`、`.claude/commands/` を読み込むため、1 つのリポジトリにコミットされたスキルはすべてのクラウドスレッドで利用可能です。クラウドスレッドは、claude.ai アカウントで有効化したスキルも読み込みます。
* プラグイン：**プロジェクト設定 > プラグイン** で追加します。各新しいクラウドスレッドに読み込まれます。リポジトリが `.claude/settings.json` で宣言するプラグインは、クラウドスレッドでは [読み込まれません](/docs/ja/cloud-environments#what-carries-over-from-your-setup)。
* MCP サーバー：クラウドスレッドは、claude.ai アカウントのコネクタから MCP ツールを取得します。これは、[claude.ai/customize/connectors](https://claude.ai/customize/connectors) で 1 回接続する MCP サーバーか、**プロジェクト設定 > 環境** の **コネクタを管理** リンクを通じて接続します。すべてのクラウドスレッドは、プロジェクト固有のセットアップなしでそれらすべてを使用できます。プロジェクト会話自体にはコネクタがないため、コネクタが必要な作業をクラウドスレッドのタスクとして送信してください。1 つのリポジトリを持つプロジェクトでは、クラウドスレッドはそのリポジトリの [`.mcp.json`](/docs/ja/cloud-environments#what-carries-over-from-your-setup) から MCP サーバーも読み込みます。[コネクタが Claude Code に到達する方法](/docs/ja/mcp#how-connectors-reach-claude-code) は、クラウドセッションのルールとコネクタをオフにする設定をリストしています。
* コマンドラインツールとパッケージ：環境の [セットアップスクリプト](/docs/ja/cloud-environments#setup-scripts) にインストールします。

実行中のクラウドスレッドが claude.ai/code でどのコネクタを持っているかを確認するには、スレッドを開き、メッセージボックスの横の **+** メニューから **コネクタ** を選択します。コネクタをそこでオフにすると、そのスレッドから削除され、アカウントのデフォルトとして保存されます。そのため、新しいスレッドと claude.ai チャットは、再度オンにするまでそれなしで開始します。クラウドスレッドは、送信後のメッセージで追加または再接続したコネクタを取得します。

<h2 id="project-settings-reference">
  プロジェクト設定リファレンス
</h2>

プロジェクト設定は `settings.json` ではなく claude.ai/code またはデスクトップアプリで変更します。プロジェクトのサイドバーメニューの **Settings** からまたはプロジェクトヘッダーのギアアイコンから **Project settings** を開きます。

設定は変更時に保存されます。目標や指示などの編集中のテキストフィールドには、そのフィールドを離れるまで **Save changes** と **Discard** が表示されます。**Project settings** の指示、リポジトリ、プラグイン、環境への変更は、既に実行中のスレッドではなく、新しいスレッドに到達します。

| 設定             | セクション       | 制御するもの                                                                                     |
| :------------- | :---------- | :----------------------------------------------------------------------------------------- |
| 名前、アイコン、目標     | General     | サイドバーのプロジェクトの名前とアイコン、およびその 1 行の目標                                                          |
| コーディネーターモデルと努力 | General     | プロジェクト会話の Claude のモデルと [努力レベル](/docs/ja/model-config#adjust-effort-level)                       |
| スレッドモデルと努力     | General     | スレッドのモデルと努力レベル                                                                             |
| プロジェクト指示       | Memory      | [立ち上がりルール](#give-a-project-standing-context) すべての新しいスレッドが受け取ります                            |
| プロジェクトリポジトリ    | Environment | 新しいスレッドがクローンするリポジトリ                                                                        |
| クラウド環境         | Environment | 新しいスレッドが実行する [クラウド環境](#choose-an-environment-for-threads)                                  |
| コネクタ           | Environment | claude.ai コネクタを管理するリンク。スレッドが取得します                                                          |
| プラグイン          | Plugins     | 各新しいスレッドに読み込まれるプラグイン                                                                       |
| 使用量            | Usage       | スレッドおよびモデル別の [トークン使用量](#usage-and-cost)                                                    |
| Memory         | Memory      | プロジェクトの [メモリファイル](#give-a-project-standing-context)                                        |
| Claude を再起動    | General     | [Claude が応答していない](#claude-hasnt-responded) 場合、プロジェクト会話を再起動します                              |
| 一時停止、アーカイブ、削除  | General     | プロジェクトを停止、非表示、削除します。[プロジェクトを一時停止、アーカイブ、削除する](#pause-archive-or-delete-a-project) を参照してください |

<h3 id="pause-archive-or-delete-a-project">
  プロジェクトを一時停止、アーカイブ、削除する
</h3>

3 つのコントロールはすべて **Project settings > General** の下部にあります。

* **Pause**: すべてを一度に停止します。実行中のすべてのスレッドと会話が中断され、新しいスレッドは開始されず、ルーチンは実行されず、プロジェクトは再開するまでメッセージを受け入れません。同じ場所またはプロジェクトのメッセージボックスの上のバナーで **Resume** をクリックします。一時停止されたスレッドはその後メッセージを送信すると続きます。
* **Archive**: プロジェクトをサイドバーから非表示にし、そのスレッドをアーカイブします。実行中またはプルリクエストを監視していたスレッドを停止します。プロジェクトがアーカイブされている間、プロジェクトのルーチンは実行されません。プロジェクトを戻すには、Projects ページから開き、**Unarchive** をクリックします。そのスレッドはセッションリストから個別にアーカイブ解除するまでアーカイブされたままです。
* **Delete**: プロジェクト、そのスレッド、メモリ、ファイルを永続的に削除し、プロジェクトのルーチンをオフにします。これは取り消せません。スレッドが GitHub にプッシュしたブランチとプルリクエストは影響を受けません。

<h2 id="usage-and-cost">
  使用状況とコスト
</h2>

プロジェクトの使用状況は、他の Claude Code セッションと同じ[プラン制限](/docs/ja/errors#youve-hit-your-session-limit)にカウントされ、プロジェクト自体がその制限を超えて使用することはできません。

スレッドがプランの制限に達すると、制限がリセットされるまで待機し、制限がリセットされると自動的に続行されるため、実行中のまま残した作業は、メッセージなしで次の使用期間を使用し始めます。[スレッドが使用制限に達した](#usage-limit-reached)では、表示される内容、停止方法、および待機しない 1 つのケースについて説明しています。

作業がプランの制限を超えるのは、アカウントで[使用クレジット](/docs/ja/costs#add-usage-credits-to-your-subscription)をオンにしている場合のみです。スレッドがあなたのためにそれをオンにすることはできません。

<h3 id="what-draws-on-your-plan">
  プランに対して何が消費されるか
</h3>

プロジェクトは単一のセッションよりも速くプランの制限を消費し、特に Pro プランでは、プロジェクトを実行する日には制限に到達するのが早くなることが予想されます。プロジェクトのプランを使用する部分は以下の通りです。

* **実行中のスレッド**: それぞれが完全なセッションであり、複数が同時に実行できます。固定数はなく、Claude は作業が必要とする数だけスレッドを開始し、[要求する](#tune-how-claude-runs-a-project)制限は上限ではなく優先度です。実施される制限は、プロジェクト全体で 1 日あたり 200 個の新しいスレッドです。
* **会話**: Claude はスレッドが報告する内容を読み、次に何をするかを決定するために独自のトークンを使用します。
* **プルリクエストを監視しているスレッド**: CI が失敗するか、プルリクエストにレビューコメントが到着すると、アイドル状態のスレッドが起動し、プランを再度使用します。これを停止するには、スレッドでプルリクエストの監視を停止するよう要求してください。

実行中のスレッドがなく、監視されているプルリクエストがなく、新しいメッセージがないプロジェクトは、アイドル状態で待機している間はプランを使用しません。アーカイブされたプロジェクトも同様です。

<h3 id="see-and-reduce-a-project’s-usage">
  プロジェクトの使用状況を確認して削減する
</h3>

**プロジェクト設定**で**使用状況**を開くと、スレッド別およびモデル別のトークン使用状況、およびプロジェクト会話に使用された量を確認できます。削減するには、以下の方法があります。

* [キャッシュ有効期間](/docs/ja/prompt-caching#cache-lifetime)より長くアイドル状態にあったスレッドにルーティングされたフォローアップは、Pro および Max ではプランの制限内で 1 時間であり、何かを実行する前にそのスレッドの会話全体を再度読み込みます。新しい作業の場合、Claude に新しいスレッドを開始するよう要求すると、大きな古いスレッドを復活させるよりも少ないトークンを使用できます。
* 最大のモデルを必要としない作業の場合、スレッド、会話、またはその両方に対して[より小さいモデルまたはより低い努力レベルを選択](#choose-models-and-let-claude-manage-context)してください。
* プロジェクト会話で Claude に、一度に実行するスレッド数を減らすか、スレッドを開始する代わりに小さな質問に自分で答えるよう要求してください。

<h2 id="how-projects-relate-to-other-claude-code-features">
  プロジェクトと他の Claude Code 機能の関係
</h2>

複数の Claude Code 機能により、複数のセッションを同時に実行できるため、並列で作業を実行することだけがプロジェクトの目的ではありません。プロジェクトでは、Claude があなたの代わりにセッションを開始して追跡し、各セッションは同じ指示から開始します。各隣接機能がプロジェクトにどのように接続するかは以下の通りです。

* **Claude Tag**: [Claude Tag](https://claude.com/docs/claude-tag/overview) は Team および Enterprise プランでチームの Slack チャネルに存在する Claude です。チャネル内の誰もが作業を割り当てることができ、チャネル内の全員がそれを見て操作でき、管理者がそのチャネル用に設定した接続を使用します。プロジェクトはあなただけのものです。作業を送信したり、スレッドを見たりするのはあなただけで、独自の GitHub アクセスとコネクタを使用し、Pro および Max で利用できます。[Claude Tag が Cowork および Claude Code とどのように異なるか](https://claude.com/docs/claude-tag/concepts/how-it-works#how-claude-tag-differs-from-cowork-and-claude-code)に並べて比較があります。
* **Cloud sessions**: すべてのスレッドは [cloud session](/docs/ja/claude-code-on-the-web) です。ただし、Claude にマシン上で実行するよう要求する場合を除きます。どちらの場合でも、Claude があなたの代わりにそれを開始して追跡します。自分で開始した cloud session は、[**Continue as a project** または **Move to project**](#start-from-an-existing-cloud-session) を通じてプロジェクトになるか、プロジェクトにフィードすることができます。
* **Routines**: プロジェクトでスケジュール済みの作業を要求すると、Claude はそのプロジェクト内のスレッドとして実行され、その **Routines** タブに表示される [routine](/docs/ja/routines) を作成します。プロジェクト外で作成した Routines は独立して動作し続けます。
* **Local sessions と agent view**: ターミナル、IDE、またはデスクトップアプリのローカル環境で自分で開始したセッションはプロジェクトに追加できません。プロジェクトは [Remote Control](/docs/ja/remote-control) を通じてスレッドをそこで実行することによってのみマシンに到達します。[Agent view](/docs/ja/agent-view) は自分で開始した複数のローカルセッションを追跡するための画面です。コーディネーターはありません。
* **Worktrees**: [worktree](/docs/ja/worktrees) は各ローカルセッションにリポジトリの独自の作業コピーを提供するため、マシン上の並列セッションが互いに上書きしません。Cloud スレッドはそれらを必要としません。各スレッドはリポジトリを独自のクラウドサンドボックスにクローンし、独自のブランチで作業します。
* **Agent teams**: [agent team](/docs/ja/agent-teams) は、マシン上またはクラウドセッション内で単一のタスク用にチームメイトセッションを開始し、そのタスクで終了する 1 つのセッションです。
* **Projects in claude.ai chat and Cowork**: [以前の Projects エクスペリエンス](https://support.claude.com/en/articles/9517075-what-are-projects)。これはスレッドやコーディネーターなしで会話と参照ファイルをグループ化します。これらのプロジェクトは、再設計されたエクスペリエンスがそれらに到達するまで、今日のように動作し続けます。

[Run agents in parallel](/docs/ja/agents) はこれらのオプションを並べて比較します。

<h2 id="limitations">
  制限事項
</h2>

* プロジェクトは claude.ai/code、デスクトップアプリ、Claude モバイルアプリで利用可能です。ターミナル CLI、Amazon Bedrock、Google Cloud の Agent Platform、または Microsoft Foundry では利用できません。CLI の [`claude project`](/docs/ja/cli-reference) コマンドはディレクトリの Claude Code ローカル状態を管理するもので、関連がありません。
* プロジェクトスレッドは [クラウドセッション](/docs/ja/claude-code-on-the-web) です。または [Remote Control](/docs/ja/remote-control) を通じてお客様のマシン上のセッションです。どちらの場合も Anthropic がモデルプロバイダーです。[セキュリティ](/docs/ja/security) および [データ使用](/docs/ja/data-usage) はクラウドセッションがどのように分離され、何が保持されるかをカバーしています。また [接続とセキュリティ](/docs/ja/remote-control#connection-and-security) はお客様のマシン上のスレッドがどのように接続され、何が保存されるかをカバーしています。
* お客様のマシン上で自分で開始したセッションをプロジェクトに追加することはできません。プロジェクトがお客様のマシン上でスレッドを実行できるようにするには、[Remote Control](/docs/ja/remote-control#requirements) を通じてそれが機能すべきフォルダを接続してください。Claude デスクトップアプリの **Settings > Claude Code** で Remote Control をオンにするか、フォルダで `claude remote-control` を実行して実行したままにしてください。そのマシンは Claude Code v2.1.280 以降が必要です。また、claude.ai 設定で **Require trusted devices** がオンの場合、プロジェクトはお客様のマシン上でスレッドを実行することもできません。
* クラウドスレッドのサンドボックスはターン間で一時停止し、スレッドが続くときに再開されます。サンドボックスを再開できない場合、スレッドは新しいクローンから続きます。コミットされていない変更は失われる可能性があります。長いタスクでは、Claude にコミットしてプログレス作業をプッシュするよう求めてください。
* プロジェクトは 1 人のユーザーに属します。プロジェクトまたはそのスレッドを別のユーザーと共有することはできず、スレッドトランスクリプトは他のクラウドセッションが持つ共有オプションを持ちません。ベータ中、プロジェクトの組織レベルコントロールはありません。
* スレッドはそれを開始した 1 つのプロジェクトに属します。スレッドを別のプロジェクトに移動またはコピーすることはできず、それを単独で移動することはできません。[**Move to project**](#start-from-an-existing-cloud-session) は別の方向のみです。クラウドセッションの作業をプロジェクトに持ち込みます。

<h2 id="troubleshooting">
  トラブルシューティング
</h2>

**新規プロジェクト**ダイアログの GitHub セットアップ プロンプトについては、[GitHub アクセスのセットアップ](#set-up-github-access)を参照してください。

<h3 id="a-thread-looks-stuck">
  スレッドがハングしているように見える
</h3>

Claude は、スレッドが実行する各ステップを投稿しないため、プロジェクト会話に新しいメッセージがない実行中として表示されるスレッドは、通常、まだ動作しています。新しいクラウド スレッドは、Claude が開始する前に、その[クラウド環境](/docs/ja/cloud-environments)もプロビジョニングするため、最初の更新には少し時間がかかります。スレッドを開いて、そのトランスクリプトを読んでください。スレッドが権限プロンプトを待機している場合は、そこで応答してください。

<h3 id="threads-guessed-or-stalled-instead-of-asking">
  スレッドが尋ねる代わりに推測または停止した
</h3>

複数のスレッドが間違った仮定をしたり、アクセスの欠落を回避したり、「ブロック」で停止して戻ってきた場合、原因は通常、各タスクの問題ではなく、プロジェクトのセットアップの同じギャップです。何かを修正する前に、どのスレッドが正常であるかを確認してください。

1. 会話で Claude に「すべてのオープン スレッドについて、それを何をするよう求めたか、何を仮定したか、または到達できなかったか、そして何を待機しているかをリストアップしてください」と尋ねます。Claude は各スレッドを読み、会話で応答します。
2. 間違った仮定から開始したスレッドについては、**概要**からスレッドを開き、そのメニューから解決済みとしてマークするか、メッセージ ボックスで代わりに何をするかを指示します。そのブランチと任意のプル リクエストは、削除するまで GitHub に残ります。
3. [プロジェクト指示](#give-a-project-standing-context)または[環境](#choose-an-environment-for-threads)でギャップを 1 回修正してから、残りの作業を新しいスレッドとして再度送信する前に、1 つのスレッドを送信します。

<h3 id="claude-hasnt-responded">
  Claude が応答していない
</h3>

Claude が実行中だが、その返信がプロジェクトに到達していない場合、プロジェクト会話に「Claude が応答していません」バナーが表示されます。バナーの**Claude を再起動**をクリックするか、**プロジェクト設定 > 一般**に移動して、**Claude を再起動**行の**再起動**をクリックします。Claude は会話に再接続します。書き込み中だった返信は失われ、スレッドは影響を受けません。

<h3 id="repository-access-errors">
  リポジトリ アクセス エラー
</h3>

3 つのメッセージは、スレッドまたはプロジェクトがそのリポジトリの 1 つに到達できないことを意味します。プロジェクトのクラウド スレッドは、他のクラウド セッションが同じリポジトリを問題なく複製する場合でも、[GitHub の前提条件](#check-the-prerequisites)が必要です。

* \*\*「セッションを開始できませんでした — Claude はこのプロジェクトのリポジトリへの GitHub アクセス権がありません」\*\*は、Claude GitHub App がそのリポジトリにインストールされていない場合、一時停止されている場合、または接続した GitHub アカウントにリンクされていない場合、スレッドが開始される前に報告されます。
* \*\*「リポジトリにアクセスできません」\*\*は、複製が失敗したときにスレッドによって報告されます。GitHub が複製を拒否した場合、リポジトリがプロジェクトが持つ名前の下で見つからなかった場合、またはスレッドが開始するよう求められたブランチが存在しない場合です。
* **「Claude がアクセスできません」**リポジトリは、**新規プロジェクト**ダイアログまたは**プロジェクト設定**でリポジトリを保存するときに表示されます。メッセージは、インストール リンクと再接続リンクで続きます。Claude GitHub App がそのリポジトリにない場合はインストール リンクを使用し、ある場合は再接続リンクを使用します。GitHub App は GitHub にインストールされていても、Claude に接続したアカウントにリンクされていない可能性があるためです。メッセージが GitHub App が一時停止されているか、このリポジトリを含まないと言っている場合は、そのリンクをたどって GitHub でそれを修正してください。

これらのいずれかを修正するには、メッセージが提供するボタン（**GitHub App をインストール**または**GitHub で リポジトリを選択**など）をクリックしてから、**再度確認**をクリックします。ブロックが GitHub 組織側にある場合（アプリを承認していないオーナーや Claude を除外する IP 許可リストなど）、メッセージは代わりに**修正方法を確認**リンクを表示します。ボタンがない場合は、[GitHub アクセスのセットアップ](#set-up-github-access)に従い、別のメッセージを送信して再試行してください。

<h3 id="usage-limit-reached">
  スレッドが使用制限に達した
</h3>

スレッドまたはプロジェクト会話がプランの 5 時間または週間制限に達すると、自動的に再試行を続け、制限がリセットされると続行されます。待機中、スレッドは「Claude はまだ再試行中で、自動的に続行されます」という**サービスがビジー状態です**を表示します。作業を続行するために何もする必要はありません。次の使用ウィンドウを使用しないようにしたい場合は、スレッドの**停止**をクリックするか、[プロジェクトを一時停止](#pause-archive-or-delete-a-project)してすべてのスレッドを保留にします。ルーチンが開始したスレッドは待機しません。そのターンは制限エラーで停止し、制限がリセットされた後にメッセージを送信します。

[使用制限エラー](/docs/ja/errors#youve-hit-your-session-limit)は、制限と制限がリセットされるタイミングを説明しています。

<h3 id="additional-usage-credits-are-required">
  追加の使用クレジットが必要です
</h3>

スレッドまたはプロジェクト会話が、プランが使用クレジットでのみカバーするリクエスト（プランに含まれていないモデルまたはコンテキスト サイズへのリクエストなど）を行い、使用クレジットがアカウントに対して有効になっていません。[サブスクリプションに使用クレジットを追加](/docs/ja/costs#add-usage-credits-to-your-subscription)は、各プランでそれらを有効にするか購入できるユーザーをカバーしています。クレジットが利用可能になったら、別のメッセージを送信して再試行してください。

<h3 id="context-limit">
  その他のメッセージ
</h3>

これらのメッセージは、独自の原因に名前を付けます。テーブルは、各メッセージの次のステップを示しています。

| メッセージ                                                        | 実行する操作                                                                                                                                       |
| :----------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- |
| 「リポジトリに接続できません」と「Claude はリポジトリをフェッチするために GitHub に到達できませんでした」 | 少し待ってから、別のメッセージを送信して再試行してください                                                                                                                |
| 「リポジトリに接続できません」と「Claude はリポジトリまたは環境にアクセスできませんでした」            | GitHub アカウントはリポジトリへのプッシュ アクセスが必要で、環境はまだ存在する必要があります。**プロジェクト設定 > 環境**で両方を確認してから、再試行してください                                                     |
| 「セットアップ提案を表示できませんでした」                                        | 開いているアプリは、Claude が送信した**セットアップの推奨事項**より古いです。ページを更新するか、デスクトップ アプリを再起動するか、Claude にセットアップを再度提案するよう求めてください                                       |
| 「プロジェクトの環境が削除されました」                                          | **プロジェクト設定 > 環境**で別の環境を選択します。変更は新しいスレッドに適用されます                                                                                               |
| 「セットアップ スクリプトが失敗しました」                                        | エラーの**セットアップ スクリプトを編集**をクリックし、環境でスクリプトを修正してから、別のメッセージを送信します。[セットアップ スクリプトが失敗しました](/docs/ja/web-quickstart#setup-script-failed)は一般的な原因をリストアップしています |
| 「Claude ran out of context on this turn」                     | スレッドがコンテキスト ウィンドウを満たしました。メッセージがスレッドが新しいセッションで続行されると言っている場合、それは自動的に続行されます。そうでない場合は、プロジェクト会話で Claude に残りの作業のための新しいスレッドを開始するよう求めてください           |
| 「Reached the turn limit」                                     | スレッドは [`CLAUDE_CODE_MAX_TURNS`](/docs/ja/env-vars)が設定するエージェント ターンの上限に達しました。別のメッセージを送信して続行するか、その変数を設定されている場所で引き上げるか削除してください                        |
