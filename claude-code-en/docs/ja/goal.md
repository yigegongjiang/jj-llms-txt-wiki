# Claude をゴールに向かって動作させ続ける

> /goal でコンプリーション条件を設定すると、Claude はターン間でプロンプトなしに条件が満たされるまで動作し続けます。モデルが不可能と判断するか、修正が必要なエラーが発生するとゴールがクリアされます。

`/goal` コマンドはコンプリーション条件を設定し、Claude はあなたが各ステップをプロンプトすることなく、その条件に向かって動作し続けます。各ターンの後、小さく高速なモデルが条件が成立しているかどうかをチェックします。成立していない場合、Claude はあなたに制御を返す代わりに別のターンを開始します。ゴールは条件が満たされると自動的にクリアされます。モデルが条件を満たすことが不可能と判断した場合、または [修正が必要なエラー](#errors-you-have-to-fix-clear-the-goal) が発生した場合もクリアされます。

実質的な作業で検証可能な終了状態がある場合にゴールを使用します。

* モジュールを新しい API に移行し、すべてのコールサイトがコンパイルされてテストが成功するまで
* デザインドキュメントを実装し、すべての受け入れ基準が満たされるまで
* 大きなファイルをフォーカスされたモジュールに分割し、各モジュールがサイズ予算以下になるまで
* ラベル付きの問題バックログを処理し、キューが空になるまで

<h2 id="compare-ways-to-keep-a-session-running">
  セッションを実行し続ける方法の比較
</h2>

3 つのアプローチが、プロンプト間で現在のセッションを実行し続けます。次のターンを開始するべき内容に基づいて選択します。

| アプローチ                                                               | 次のターンが開始される時期                                                                                                                    | 停止する時期                                                                                                                                 |
| :------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------- |
| `/goal`                                                             | 前のターンが終了するか、インタラクティブセッションで[アイドルチェックイン](#background-work-defers-evaluation)または[自動再試行](#other-errors-retry-or-pause-the-goal)が発生する | モデルが条件が満たされたことを確認するか、それが不可能であると判断するか、[修正が必要なエラー](#errors-you-have-to-fix-clear-the-goal)でターンが失敗するか、[`/goal clear`](#clear-a-goal)を実行する |
| [`/loop`](/docs/ja/scheduled-tasks#run-a-prompt-repeatedly-with-%2Floop) | 時間間隔が経過する                                                                                                                        | あなたが停止するか、Claude が作業が完了したと判断する                                                                                                         |
| [Stop hook](/docs/ja/hooks-guide#prompt-based-hooks)                     | 前のターンが終了する                                                                                                                       | あなた自身のスクリプトまたはプロンプトが判断する                                                                                                               |

`/goal` と Stop hook は両方とも、すべてのターンの後に実行されます。`/goal` はセッションスコープのショートカットです。条件を入力すると、現在のセッションでのみアクティブになります。Stop hook はあなたの設定ファイルに存在し、そのスコープ内のすべてのセッションに適用され、決定論的なチェックのためにスクリプトを実行するか、モデルで評価されたチェックのためにプロンプトを実行できます。

[自動モード](/docs/ja/auto-mode-config)は、単一のターン内でツール呼び出しを承認しますが、新しいターンを開始しません。Claude は作業が完了したと判断すると停止します。`/goal` は、すべてのターンの後にあなたの条件をチェックする別の評価器を追加するため、コンプリーションは作業を行っているモデルではなく、新しいモデルによって決定されます。この 2 つは相互に補完的です。自動モードはツールごとのプロンプトを削除し、`/goal` はターンごとのプロンプトを削除します。

<Tip>
  上記のアプローチは、現在のセッションを実行し続けます。また、夜間テストや朝のトリアージなど、開いているセッションとは無関係に実行される作業をスケジュールすることもできます。クラウドルーチンとデスクトップスケジュール済みタスクについては、[スケジューリング オプション](/docs/ja/scheduled-tasks#compare-scheduling-options)を参照してください。
</Tip>

<h2 id="use-/goal">
  `/goal` を使用する
</h2>

1 つのセッションで 1 つのゴールがアクティブになります。同じコマンドは引数に応じてゴールを設定、確認、クリアします。

<h3 id="set-a-goal">
  ゴールを設定する
</h3>

`/goal` の後に満たしたい条件を実行します。ゴールがすでにアクティブな場合、新しいゴールがそれを置き換えます。

```text theme={null}
/goal all tests in test/auth pass and the lint step is clean
```

ゴールを設定すると、条件自体をディレクティブとして、すぐにターンが開始されます。別のプロンプトを送信する必要はありません。ゴールがアクティブな間、`◎ /goal active` インジケーターがゴールの実行時間を表示します。

ゴールは権限モードを変更しません。ゴールターンが無人で実行されるようにするには、[オートモード](/docs/ja/auto-mode-config)で `/goal` を実行します。[マニュアルモード](/docs/ja/permission-modes)では、テストコマンドなど、設定で既に許可されていないツール呼び出しの前に、Claude はまだ確認を求めます。

ゴールがアクティブな間、トランスクリプトは評価者が返す各判定を表示し、Ctrl+O を押すと、その背後にある理由を確認できます。ステータスビューは最新の理由も表示するため、Claude が次に何に向かって作業しているかを確認できます。

<h3 id="write-an-effective-condition">
  効果的な条件を書く
</h3>

[評価者](#how-evaluation-works)は、Claude が会話で提示した内容に対して条件を判定します。独立してコマンドを実行したりファイルを読み取ったりしないため、Claude 自身の出力が実証できるものとして条件を書いてください。「`test/auth` のすべてのテストが合格する」は、Claude がテストを実行し、結果がトランスクリプトに表示されて評価者が読むことができるため、機能します。

多くのターンにわたって成立する条件には、通常以下が含まれます。

* **1 つの測定可能な終了状態**: テスト結果、ビルド終了コード、ファイル数、空のキュー
* **明記されたチェック**: Claude がそれをどのように証明すべきか。例えば「`npm test` が 0 で終了する」または「`git status` がクリーンである」
* **重要な制約**: そこに到達する途中で変更してはならないもの。例えば「他のテストファイルは変更されない」

条件は最大 4,000 文字です。

ゴールの実行時間を制限するには、条件に `or stop after 20 turns` などのターンまたは時間句を含めます。Claude は各ターンでその句に対する進捗を報告し、評価者は会話からそれを判定します。

<h3 id="check-status">
  ステータスを確認する
</h3>

引数なしで `/goal` を実行して、現在の状態を確認します。

```text theme={null}
/goal
```

ゴールがアクティブな場合、ステータスは以下を表示します。

* 条件
* 実行時間
* 評価されたターン数
* 現在のトークン支出
* 評価者の最新の理由

ターン数と最新の理由は、最初の評価が実行された後に表示されます。

ゴールがアクティブではないが、セッションの前半で達成された場合、ステータスは達成された条件とその期間、ターン数、トークン支出を表示します。

<h3 id="clear-a-goal">
  ゴールをクリアする
</h3>

`/goal clear` を実行して、解決前にアクティブなゴールを削除します。

```text theme={null}
/goal clear
```

Claude は `Goal cleared:` の後に条件を出力して確認するか、何もアクティブでない場合は `No goal set` を出力します。

`stop`、`off`、`reset`、`none`、`cancel` は `clear` のエイリアスとして受け入れられます。`/clear` を実行して新しい会話を開始すると、アクティブなゴールも削除されます。

<h3 id="resume-with-an-active-goal">
  アクティブなゴールで再開する
</h3>

セッションを再開すると、Claude Code はセッションが終了したときにまだアクティブだったゴールを復元します。Claude Code はすべての再開ルートで復元します。`--continue`、セッション ID、名前、または[トランスクリプトファイルパス](/docs/ja/sessions#resume-a-session)を使用した `--resume`、および[セッションピッカー](/docs/ja/sessions#use-the-session-picker)です。v2.1.239 より前では、Claude Code は `claude --resume` ピッカーを除くすべてのルートでゴールを復元していました。

Claude Code は条件を引き継ぎますが、ターン数、タイマー、トークン支出ベースラインをリセットします。既に達成またはクリアされたゴールは復元しません。

<h3 id="run-non-interactively">
  非対話的に実行する
</h3>

`/goal` は[非対話的モード](/docs/ja/headless)、[デスクトップアプリ](/docs/ja/desktop)、および[リモートコントロール](/docs/ja/remote-control)で機能します。`-p` でゴールを設定すると、ループが単一の呼び出しで完了まで実行されます。

```bash theme={null}
claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"
```

デフォルトのテキスト出力では、実行が終了するまで何も出力されないため、多くのターンを実行するゴールは停止しているように見える場合があります。`--output-format stream-json --verbose` を追加して、ループの実行時に各メッセージを出力します。

Ctrl+C でプロセスを中断して、解決前に非対話的なゴールを停止します。

<h2 id="how-evaluation-works">
  評価の仕組み
</h2>

`/goal` は、セッションスコープの[プロンプトベースの Stop hook](/docs/ja/hooks#prompt-based-hooks)のラッパーです。Claude がターンを終了するたびに、Claude Code は条件と会話をこれまでのところ、あなたが設定した[小さく高速なモデル](/docs/ja/model-config)に送信します。デフォルトは Claude API の Haiku です。サードパーティプロバイダーの場合は、[プロバイダーページ](/docs/ja/third-party-integrations)でプラットフォームのデフォルトを確認してください。モデルは 3 つの判定のいずれかを返します。各判定には短い理由が付きます。

* **まだ満たされていない**: Claude は作業を続け、理由を次のターンのガイダンスとして受け取ります。
* **満たされた**: Claude Code はゴールをクリアし、トランスクリプトに達成されたエントリを記録します。
* **不可能**: 評価器は条件を満たすことができないと判断しました。Claude Code はゴールをクリアし、理由とともにトランスクリプトに失敗したエントリを記録します。自分でクリアする必要はありません。

Claude が評価器に答え続けても進捗がない場合（複数のターンで連続してツール使用がない場合）、Claude Code はループを停止し、警告を出力し、ゴールがまだ設定された状態で制御をあなたに返します。評価は次のプロンプトの後に再開されます。[hooks ガイド](/docs/ja/hooks-guide#stop-hook-hits-the-block-cap)は基礎となるメカニズムについて説明しています。

<h3 id="when-a-turn-fails">
  ターンが失敗した場合
</h3>

ターンが失敗した場合、Claude Code はエラーが修正する必要があるものである場合、ゴールをクリアします。その他のエラーの後、ゴールは設定されたままです。

<h4 id="errors-you-have-to-fix-clear-the-goal">
  修正する必要があるエラーはゴールをクリアします
</h4>

修正するまでクリアされないエラーでターンが失敗した場合、Claude Code はゴールをクリアし、原因を名前で指定する警告を出力します。警告は `Goal cleared after an unrecoverable error` で始まり、`Run /goal again to continue` で終わります。原因を修正してから、`/goal <condition>` で[ゴールを再度設定](#set-a-goal)してください。4 つの種類の失敗がゴールをクリアします。

* 認証失敗。Claude Code が独自の認証情報を管理する場合。デスクトップアプリ、VS Code 拡張機能、または[クラウドセッション](/docs/ja/claude-code-on-the-web)など、ホストが認証情報を管理する場合、Claude Code はホストが独自にアクセスを復元するため、ゴールをアクティブなままにします。
* クレジット残高の枯渇
* [自動コンパクション](/docs/ja/model-config#set-the-auto-compact-window)がクリアできないコンテキストオーバーフロー
* 利用できないモデル

<h4 id="other-errors-retry-or-pause-the-goal">
  その他のエラーはゴールを再試行または一時停止します
</h4>

その他の失敗の後、ゴールは設定されたままです。Claude Code v2.1.269 以降の対話型セッションでは、Claude Code は原因を名前で指定する行を出力し、独自に再試行するか、あなたを待ちます。

* **再試行**: サーバーの過負荷や接続の切断など、独自にクリアされる傾向がある失敗の後、`Goal still active` で始まる通知は次の試行までの待機時間を表示します。3 回の自動再試行の後、ゴールは代わりに一時停止します。
* **一時停止**: API レート制限、claude.ai [使用制限](/docs/ja/errors#youve-hit-your-session-limit)、またはターンを終了した hook など、再試行が繰り返すだけの失敗の後、`Goal paused` で始まる通知は原因を名前で指定します。セッションが[使用制限がリセットされるときに自動的に続行するのを待機している](/docs/ja/interactive-mode#wait-for-a-usage-limit-to-reset)場合、Claude はその後ゴールに向かって作業を再開します。

任意の時点でメッセージを送信して、次のターンをすぐに開始してください。自動再試行をオフにするには、[`CLAUDE_CODE_GOAL_CHECKIN_MINUTES`](/docs/ja/env-vars)を `0` に設定します。これにより、[チェックイン](#background-work-defers-evaluation)もオフになります。

<h3 id="background-work-defers-evaluation">
  バックグラウンド作業は評価を遅延させます
</h3>

サブエージェントまたはバックグラウンドシェルコマンドがターン終了時に実行中の場合、Claude Code はそのターンの評価をスキップします。バックグラウンド作業が実行されていない状態で終了する次のターンの終了時に評価します。バックグラウンド作業が完了すると、Claude Code は結果を新しいターンとして Claude に配信するため、プロンプトを入力する必要はありません。

バックグラウンド作業がゴールを 30 分間待たせた後、チェックインが必要です。チェックインでは、Claude Code は実行中のタスクをリストアップし、Claude に出力を読むよう求め、進捗がある場合は待機を続け、スタックしているものを修正または停止するよう求めます。最初のチェックインの後、Claude Code は各後続チェックインの前に 2 倍の時間待機します。最初の間隔の最大 4 倍まで。デフォルトでは、最初のチェックインの 1 時間後、その後 2 時間ごと。Claude Code は期限が来たチェックイン（最初のものを含む）を 2 つの方法のいずれかで配信します。

* **ターンが終了するとき**: Claude Code は作業がまだ実行中の状態で終了する次のターンの終了時にチェックインを配信します。`-p` で開始されたものなど、非対話型セッションでは、これが Claude Code がチェックインを配信する唯一の方法です。
* **セッションがアイドル状態のとき**: 対話型セッションでは、Claude Code はあなたの次のプロンプトを待つ代わりに、チェックインを配信するために独自にターンを開始します。バックグラウンド作業が結果を報告せずに停止した場合、Claude Code は Claude にゴールに向かって続行するよう求めます。Claude Code はあなたのプロンプト間のゴールごとに最大 3 つのアイドルチェックインを開始します。3 番目のアイドルチェックインでは、Claude Code はアイドルチェックインが別のプロンプトを送信するまで一時停止されていることを示します。v2.1.246 より前では、アイドルチェックインは無制限でした。アイドルチェックインには Claude Code v2.1.236 以降が必要です。

v2.1.239 より前では、アイドルチェックインのみがこの方法でバックオフしました。ターン終了時に配信されたチェックインは最初の間隔で再発生しました。

最初の間隔を変更するには、[`CLAUDE_CODE_GOAL_CHECKIN_MINUTES`](/docs/ja/env-vars)を設定してください。Claude Code はあなたの値を 30 分間隔の代わりに使用し、後続の間隔をそれでスケーリングします。チェックインをオフにするには `0` に設定してください。[自動再試行](#other-errors-retry-or-pause-the-goal)もオフになります。

チェックインには Claude Code v2.1.234 以降が必要です。

<h3 id="evaluation-model-and-cost">
  評価モデルとコスト
</h3>

別のモデルで評価するには、[`ANTHROPIC_DEFAULT_HAIKU_MODEL`](/docs/ja/model-config#environment-variables)を設定してください。

<Warning>
  Claude Code は小さく高速なモデルを使用するすべての場所で `ANTHROPIC_DEFAULT_HAIKU_MODEL` を読み取ります。`/goal` 評価のみではありません。設定すると、Claude Code は[`haiku` エイリアス](/docs/ja/model-config#model-aliases)をそのモデルに解決し、会話要約などの[バックグラウンド機能](/docs/ja/costs#background-token-usage)をそれで実行します。
</Warning>

評価器は、セッションが設定されているプロバイダーで実行されます。ツールを呼び出さないため、Claude が既に会話で表示した内容のみを判断できます。

<Note>
  評価トークンは、プロバイダー用に設定された小さく高速なモデルで課金され、通常はメインターン支出と比べて無視できます。
</Note>

<h2 id="requirements">
  要件
</h2>

Claude Code は、評価器がフック システムの一部であるため、[ワークスペース信頼ルール（設定ファイル内のフックと同じ）](/docs/ja/permissions#what-runs-before-you-trust-a-folder)の下で `/goal` を利用可能にします。[`disableAllHooks`](/docs/ja/hooks#disable-or-remove-hooks) が `true` の場合（設定の優先順位が適用された後）、または [`allowManagedHooksOnly`](/docs/ja/settings-reference#allowmanagedhooksonly) が管理設定で設定されている場合、`/goal` は利用できません。いずれの場合も、コマンドは何もしないのではなく、理由を伝えます。
