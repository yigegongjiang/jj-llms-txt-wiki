# フルスクリーンレンダリング

> マウスサポートと安定したメモリ使用量を備えた、より滑らかでちらつきのないレンダリングモードを有効にします。長い会話でも安定した動作を実現します。

<Note>
  フルスクリーンレンダリングは[リサーチプレビュー](#research-preview)です。[フルスクリーンで開始するか、クラシックレンダラーで開始するか](#fullscreen-by-default)はセットアップによって異なります。現在の会話で `/tui fullscreen` または `/tui default` を実行して切り替えてください。フィードバックに基づいて動作が変わる可能性があります。
</Note>

フルスクリーンレンダリングは Claude Code CLI の代替レンダリングパスで、ちらつきを排除し、長い会話でもメモリ使用量を一定に保ち、マウスサポートを追加します。`vim` や `htop` のようにターミナルの代替スクリーンバッファにインターフェースを描画し、現在表示されているメッセージのみをレンダリングします。これにより、各更新時にターミナルに送信されるデータ量が削減されます。

この違いは、VS Code 統合ターミナル、tmux、iTerm2 など、レンダリングスループットがボトルネックになるターミナルエミュレータで最も顕著です。Claude が作業中にターミナルのスクロール位置が上部にジャンプしたり、ツール出力がストリーミングされるときに画面がフラッシュしたりする場合、このモードがそれに対応します。

<Note>
  フルスクリーンという用語は、`vim` のようにターミナルの描画サーフェスを Claude Code が占有する方法を説明しています。ターミナルウィンドウを最大化することとは関係なく、任意のウィンドウサイズで動作します。
</Note>

<h2 id="enable-fullscreen-rendering">
  フルスクリーンレンダリングを有効にする
</h2>

Claude Code の会話内で `/tui fullscreen` を実行してください。CLI は [`tui` 設定](/docs/ja/settings-reference#tui)を保存し、会話をそのままにしてフルスクリーンで再起動するため、コンテキストを失わずにセッション中に切り替えることができます。`/tui default` を実行してクラシックレンダラーに戻すか、引数なしで `/tui` を実行してどのレンダラーがアクティブかを確認してください。

[スクリーンリーダーモード](/docs/ja/accessibility)では、Claude Code は常にクラシックレンダラーを使用します。ただし、アタッチされた[バックグラウンドセッション](/docs/ja/agent-view)は引き続きフルスクリーンでレンダリングされます。他のセッションで `/tui fullscreen` を実行した場合、Claude Code は切り替えの代わりに説明を出力し、保存された `tui` 設定を変更しません。

Claude Code は、再起動されたセッションに以下を引き継ぎます。

* 画面に表示されているとおりの会話。[`/rewind`](/docs/ja/checkpointing#rewind-and-summarize)の後、これは以下を意味します。
  * セッションの前の方で巻き戻した場合、Claude Code はディスクに保存されている長いトランスクリプトではなく、巻き戻されたポイントから再起動されます。たとえば、最後の 3 つのメッセージを超えて巻き戻した場合、再起動されたセッションはそれらなしで開きます
  * 最初のメッセージの前に巻き戻した場合、Claude Code は空の会話で再起動されます
* [権限モード](/docs/ja/permission-modes)と[努力レベル](/docs/ja/model-config#adjust-effort-level)
* [`/model`](/docs/ja/model-config#setting-your-model)で最後に選択したモデル
* [`--allowed-tools` または `--disallowed-tools`](/docs/ja/cli-reference#cli-flags)で渡したルール、および `--agent`、`--agents`、`--append-system-prompt`、および `--system-prompt-snapshot` フラグ

Claude Code は、再起動されたプロセスに渡すことができない制限がセッションにある場合、再起動を拒否します。渡すことができない制限には以下が含まれます。

* [`--system-prompt`](/docs/ja/cli-reference#cli-flags)置換、[`--tools`](/docs/ja/cli-reference#cli-flags)許可リスト、または [`--setting-sources`](/docs/ja/cli-reference#cli-flags)などの起動フラグ
* [hook または SDK 権限更新](/docs/ja/hooks#permission-update-entries)がこのセッションのみに追加した拒否またはアスク ルール

その場合、Claude Code は [`Cannot switch renderers in this session`](/docs/ja/errors#cannot-switch-renderers-in-this-session)を理由とともに出力します。切り替えたり、何かを保存したりしません。

Claude Code を起動する前に `CLAUDE_CODE_NO_FLICKER` 環境変数を設定することもできます。

```bash theme={null}
CLAUDE_CODE_NO_FLICKER=1 claude
```

[`tui`](/docs/ja/settings-reference#tui)設定と変数の両方が設定されている場合にそれらがどのように組み合わされるかについては、設定のエントリを参照してください。[フルスクリーン開始に失敗した](#fullscreen-renderer-didnt-finish-starting)後、Claude Code は変数を引き続き尊重しますが、設定は尊重しません。`/tui` コマンドは再起動されたプロセスから `CLAUDE_CODE_NO_FLICKER` をクリアして、書き込まれた設定が有効になるようにします。

<h3 id="fullscreen-by-default">
  デフォルトでフルスクリーン
</h3>

アタッチされた[バックグラウンドセッション](/docs/ja/agent-view)はフルスクリーンでレンダリングされ、[スクリーンリーダーモード](/docs/ja/accessibility)の他のセッションはクラシックレンダラーを使用します。それ以外の場合、Claude Code はセットアップに一致するこのテーブルの最初の行のレンダラーで開始されます。

| あなたの状況                                                                                                                                | 開始するレンダラー    |
| :------------------------------------------------------------------------------------------------------------------------------------ | :----------- |
| [`CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`](/docs/ja/env-vars)または `CLAUDE_CODE_NO_FLICKER=0` を設定した                                          | クラシック        |
| `CLAUDE_CODE_NO_FLICKER=1` を設定した                                                                                                      | フルスクリーン      |
| Claude Code がこのマシンで[フルスクリーン開始に失敗した](#fullscreen-renderer-didnt-finish-starting)後にフルスクリーンをオフにした                                        | クラシック        |
| iTerm2 の [`tmux -CC` 統合モード](#use-with-tmux)にいるか、Windows で実行されている Claude Code に SSH 経由で接続している                                          | クラシック        |
| [`tui` 設定](/docs/ja/settings-reference#tui)を保存した                                                                                           | 設定が指定するレンダラー |
| セッションが Anthropic から[機能フラグをフェッチしない](/docs/ja/env-vars#features-that-need-feature-flag-fetching)、および Claude Code がこのマシンでスタートアップダイアログの提供を停止した | クラシック        |
| セッションが Anthropic から機能フラグをフェッチしない、およびこのマシンの最初の Claude Code 起動が v2.1.239 以降を実行した                                                        | フルスクリーン      |
| セッションが Anthropic から機能フラグをフェッチし、Claude Code を 2026 年 5 月 6 日以降に初めて使用した                                                                 | フルスクリーン      |
| その他                                                                                                                                   | クラシック        |

機能フラグをフェッチしないセッションには、[Amazon Bedrock](/docs/ja/amazon-bedrock)、[Google Cloud の Agent Platform](/docs/ja/google-vertex-ai)、または [Microsoft Foundry](/docs/ja/microsoft-foundry)を通じたセッション、およびテレメトリがオフになっているセッションが含まれます。

クラシックレンダラーで開始し、`tui` 設定を保存していない場合、Claude Code は起動時にスイッチを提供するダイアログを開く可能性があります。

* 受け入れた場合、Claude Code は `/tui fullscreen` と同じ方法で再起動され、同じセッション状態を保持し、再起動されたセッションが[正常に開始](#fullscreen-renderer-didnt-finish-starting)されたら設定を保存します。
* **Not now** を選択した場合、Claude Code はこのマシンで再度提供しません。
* Claude Code は、3 回の起動でダイアログを表示した後、応答したかどうかに関わらず提供を停止します。

<h2 id="what-changes">
  変更内容
</h2>

フルスクリーンレンダリングは CLI がターミナルに描画する方法を変更します。入力ボックスは出力がストリーミングされるときに移動するのではなく、画面の下部に固定されたままになります。Claude が作業中に入力が固定されたままの場合、フルスクリーンレンダリングがアクティブです。レンダーツリーに保持されるのは表示されているメッセージのみなので、会話の長さに関係なくメモリは一定に保たれます。

会話がターミナルのスクロールバックではなく代替スクリーンバッファに存在するため、いくつかの点で動作が異なります。

| 以前                               | 現在                                                     | 詳細                                                    |
| :------------------------------- | :----------------------------------------------------- | :---------------------------------------------------- |
| `Cmd+f` または tmux 検索でテキストを検索      | `Ctrl+o` でトランスクリプトモードに入り、`/` で検索するか `[` でスクロールバックに書き込む | [会話を検索およびレビューする](#search-and-review-the-conversation) |
| ターミナルのネイティブなクリックアンドドラッグで選択およびコピー | アプリ内選択、マウスリリース時に自動的にコピー                                | [マウスを使用する](#use-the-mouse)                            |
| `Cmd` クリックで URL を開く              | macOS では `Cmd` クリック、その他では `Ctrl` クリック                  | [マウスを使用する](#use-the-mouse)                            |

マウスキャプチャがワークフローに干渉する場合、ちらつきのないレンダリングを保持しながら[オフにする](#keep-native-text-selection)ことができます。

<h2 id="use-the-mouse">
  マウスを使用する
</h2>

フルスクリーンレンダリングはマウスイベントをキャプチャし、Claude Code 内で処理します。

* **プロンプト入力をクリック**して、入力しているテキスト内の任意の場所にカーソルを配置します。
* **`/` コマンドまたは `@` ファイルリストの候補をクリック**して受け入れます。ホバーするとカーソルの下の行がハイライトされます。
* **選択メニューのオプションをクリック**して選択します。これは権限モード、`/model`、`/config`、およびオプションのリストを表示する他のダイアログに適用されます。ホバーするとカーソルの下の行にポインタが表示されます。
* **複数選択メニューのオプションをクリック**してトグルし、送信ボタンをクリックして選択を確認します。複数選択質問の `Other` 行など、自由形式のテキスト行をクリックすると、その入力フィールドにフォーカスが当たり、回答を入力できます。Claude Code v2.1.208 以降が必要です。
* **`/config` パネルの設定値をクリック**して変更し、マウスホイールで設定リストをスクロールします。Claude Code v2.1.271 以降が必要です。
* **選択メニューまたは複数選択メニューをマウスホイールでスクロール**します。一度に表示されるより多くのオプションがある場合（短いターミナルウィンドウの `/model` リストなど）。ポインタがそのオプション上にある間、ホイールはリストをスクロールします。Claude Code v2.1.280 以降が必要です。
* **折りたたまれたツール結果をクリック**して展開し、完全な出力を表示します。もう一度クリックすると折りたたまれます。ツール呼び出しとその結果は一緒に展開されます。表示する内容がある場合のみ、メッセージはクリック可能です。
  * クリックすると、`!` シェルコマンドの出力も展開されます。これは古い切り詰められた結果でも、コマンド実行中のライブ進捗行でも同じです。Claude Code v2.1.257 以降が必要です。
* **macOS では `Cmd` を、Linux と Windows では `Ctrl` を押しながら URL またはファイルパスをクリック**して開きます。プレーンな `http://` および `https://` URL はブラウザで開き、Edit または Write の後に出力されたものなどのツール出力内のファイルパスはデフォルトアプリケーションで開きます。修飾キーなしのプレーンクリックはリンクを開きません。これはネイティブターミナルの動作と一致します。
  * Claude Code は `\\server\share\file.ts` などのネットワーク（UNC）パスをリンクなしのプレーンテキストとしてレンダリングします。これはネットワークパスを開くと Windows 認証情報をそれが指すホストに送信する可能性があるためです。
  * 一部の macOS ターミナルは `Cmd` + クリックを実行中のアプリに転送し、ターミナルマウスプロトコルには `Cmd` キーをエンコードする方法がないため、Claude Code はプレーンクリックを受け取ります。Ghostty および macOS 上の Warp では、Claude Code はこれを検出し、リンク上のプレーンクリックで開くことができ、`Cmd` を押しながらでも機能します。
  * VS Code 統合ターミナルおよび同様の xterm.js ベースのターミナルでは、Claude Code はターミナル独自のリンクハンドラに従い、同じジェスチャを使用します。
* **クリックしてドラッグ**して、会話内の任意の場所でテキストを選択します。ダブルクリックで単語を選択します。これは iTerm2 の単語境界と一致するため、ファイルパスは 1 つのユニットとして選択されます。URL をダブルクリックすると、スキームを含む URL 全体が選択されます。トリプルクリックで行を選択します。
* **マウスホイールでスクロール**して会話を移動します。

選択したテキストはマウスリリース時に自動的にクリップボードにコピーされます。これをオフにするには、`/config` で Copy on select をトグルします。

Copy on select がオフの場合、`Ctrl+Shift+c` を押して手動でコピーします。kitty、WezTerm、Ghostty、iTerm2 などの kitty キーボードプロトコルをサポートするターミナルでは、`Cmd+c` も機能します。選択がアクティブな場合、`Ctrl+c` はキャンセルの代わりにコピーします。

選択がアクティブな場合、`Shift` を押しながら矢印キーを押してキーボードから拡張します。`Shift+↑` および `Shift+↓` は、選択がビューポートの上端または下端に達したときにビューポートをスクロールします。`Shift+Home` および `Shift+End` は現在の行の開始または終了に拡張します。

通常のプロンプトビューでは、アクティブな選択に対して何が起こるかは、押すキーによって異なります。

* **`Esc`**: Claude Code はキーの通常のアクション（実行中の応答を中断したり、開いているダイアログを閉じたりするなど）を実行し、選択はハイライトされたままです。
* **`PgUp`、`PgDn`、`Ctrl+Home`、`Ctrl+End`、または `Shift`、`Alt` または `Option`、または `Cmd`、`Win` または `Super` と矢印、`Home`、または `End` キー**: 選択は保持されます。
* **プレーン矢印キー、`Enter`、および入力された文字を含む他のキー**: Claude Code は選択をクリアします。
* **[`selection:clear`](/docs/ja/keybindings#scroll-actions) にバインドされたキー**: Claude Code は選択をクリアします。これは `Esc` または選択を保持する他のキーの場合でも同じです。このアクションにはデフォルトバインディングがありません。

[トランスクリプトモード](#search-and-review-the-conversation)では、そこにリストされているナビゲーションおよび検索キーも選択を保持します。

<h2 id="scroll-the-conversation">
  会話をスクロールする
</h2>

フルスクリーンレンダリングはアプリ内のスクロールを処理します。以下のショートカットを使用してナビゲートしてください。

| ショートカット         | アクション                      |
| :-------------- | :------------------------- |
| `PgUp` / `PgDn` | 画面の半分だけ上下にスクロール            |
| `Ctrl+Home`     | 会話の開始位置にジャンプ               |
| `Ctrl+End`      | 最新メッセージにジャンプして自動フォローを再度有効化 |
| マウスホイール         | 一度に数行スクロール                 |

[コンパクション](/docs/ja/context-window#what-survives-compaction)後でも、セッションの開始位置までスクロールバックできます。Claude はコンパクション要約から作業を続けますが、Claude Code は繰り返されるコンパクション全体で、フルスクリーンスクロールバック内のすべての以前のメッセージを保持します。

MacBook キーボードのような専用の `PgUp`、`PgDn`、`Home`、`End` キーがないキーボードでは、`Fn` キーを矢印キーと一緒に押してください。`Fn+↑` は `PgUp` を送信し、`Fn+↓` は `PgDn` を送信し、`Fn+←` は `Home` を送信し、`Fn+→` は `End` を送信します。`Ctrl+Fn+→` は macOS の Claude Code に到達しないため、MacBook キーボードはデフォルトでは下部へのジャンプコードが機能しません。代わりに、以下のいずれかのオプションを使用してください。

* [下部へジャンプボタン](#auto-follow)をクリック。
* マウスホイールで下部までスクロールしてフォローを再開。
* `scroll:bottom` を、キーボードが送信できるコードに再バインド。

これらのアクションは再バインド可能です。アクション名の完全なリスト（デフォルトバインディングがない半ページおよび全ページバリアントを含む）については、[スクロールアクション](/docs/ja/keybindings#scroll-actions)を参照してください。

スクロールアップ中は、会話の上部に薄いヘッダー行が表示され、ビューの上にスクロールした最新のプロンプトが表示されます。その行をクリックしてそのプロンプトにジャンプしてください。

<h3 id="auto-follow">
  自動フォロー
</h3>

上にスクロールすると自動フォローが一時停止され、新しい出力があなたを下部に戻さなくなります。スクロールアップ中は、トランスクリプトの下部エッジに `下部へジャンプ` ボタンが浮かび、新しい出力が到着すると `3 件の新しいメッセージ` などのカウントが表示されます。クリックするか、`Ctrl+End` を押すか、下部までスクロールしてフォローを再開してください。

自動フォローが一時停止されている間、レスポンスのストリーミングが終了すると、ビューはスクロールした場所に留まります。

ボタンのキーボードヒントは、キーボードが送信できるものを反映します。macOS では、`Ctrl+End` が Mac キーボードから Claude Code に到達しないため、クリックするか `Fn+↓` でスクロールすることを提案します。[`scroll:bottom`](/docs/ja/keybindings#scroll-actions)を再バインドすると、ボタンはすべてのプラットフォームでコードを表示します。

ターミナルが完全なラベルに対して狭すぎる場合、ボタンはトランスクリプト行の下にラップするのではなく、ヒントを短縮します。

自動フォローを完全にオフにして、ビューがあなたが残した場所に留まるようにするには、`/config` を開き、自動スクロールをオフに設定してください。自動スクロールが無効になっている場合、ビューは自動的に下部にジャンプしません。権限プロンプトおよび応答が必要なその他のダイアログは、この設定に関係なく、ビューにスクロールします。

<h3 id="mouse-wheel-scrolling">
  マウスホイールスクロール
</h3>

マウスホイールスクロールでは、ターミナルがマウスイベントを Claude Code に転送する必要があります。ほとんどのターミナルは、アプリケーションがそれを要求するたびにこれを行います。iTerm2 はそれをプロファイルごとの設定にします。ホイールが何もしないが `PgUp` と `PgDn` が機能する場合は、設定 → プロファイル → ターミナルを開き、マウスレポートを有効にしてください。同じ設定は、クリックして展開およびテキスト選択が機能するためにも必要です。

マウスホイールスクロールが遅く感じられる場合、ターミナルは物理的なノッチごとに 1 つのスクロールイベントを乗数なしで送信している可能性があります。Ghostty や高速スクロールが有効な iTerm2 などの一部のターミナルは、既にホイールイベントを増幅しています。VS Code 統合ターミナルを含む他のターミナルは、ノッチごとに正確に 1 つのイベントを送信します。Claude Code はどちらであるかを検出できません。

`CLAUDE_CODE_SCROLL_SPEED` を設定して、基本スクロール距離を乗算してください。

```bash theme={null}
export CLAUDE_CODE_SCROLL_SPEED=3
```

値 `3` は `vim` および同様のアプリケーションのデフォルトと一致します。この設定は、0.25 などの 1 未満の小数値を含む、20 までの任意の正の値を受け入れます。これにより、既にホイールイベントを増幅するターミナルで加速されたトラックパッドおよびホイールスクロールを遅くできます。

スクロール速度をインタラクティブに調整するには、`/scroll-speed` を実行してください。ダイアログは、開いている間スクロールできるルーラーを表示するため、変更をすぐに感じることができます。`←` と `→` を押して速度を調整し、`r` を押してオートディテクトされたデフォルトにリセットし、`Enter` を押して保存してください。ダイアログは 10 までの整数でステップし、より細かい制御をサポートするターミナルでは、0.25 までの 4 分の 1 ステップも提供します。

このコマンドは、`CLAUDE_CODE_SCROLL_SPEED` 環境変数が設定するのと同じ値を書き込み、`~/.claude/settings.json` に永続化されます。ダイアログの最大値は 10 です。環境変数を通じてより高い値を設定した場合、ダイアログは 10 を表示し、ダイアログから保存すると 10 が永続化されます。このコマンドは JetBrains IDE ターミナルでは利用できません。

基本速度とは別に、Claude Code はホイールを素早く回転させるとスクロール速度を加速するため、高速スピンは同じ数の遅いノッチよりも多くの距離をカバーします。加速をオフにして、ノッチごとに一定の速度を保つには、[`settings.json`](/docs/ja/settings-reference#all-settings)で `wheelScrollAccelerationEnabled` を `false` に設定してください。この設定には Claude Code v2.1.174 以降が必要です。

<h3 id="scroll-in-the-jetbrains-ide-terminal">
  JetBrains IDE ターミナルでのスクロール
</h3>

JetBrains IDE ターミナルでは、Claude Code は独自のスクロール処理を適用し、`CLAUDE_CODE_SCROLL_SPEED` を無視します。ターミナルは他のエミュレータよりもはるかに高いレートでスクロールイベントを送信するため、他の場所で調整された乗数はここでオーバーシュートします。

2025.2 では、ターミナルにはスクロールホイールバグもあり、偽のアローキーと間違った方向のイベントが発生します。Claude Code はこれを実行時に検出し、自動的に軽減するため、トラックパッドおよびマウスホイールスクロールは設定なしで機能します。最高のスクロール体験を得るには、2025.3 以降にアップグレードしてください。Claude Code はバグを検出した場合、初回スクロール時にヒントを表示します。

<h2 id="search-and-review-the-conversation">
  会話を検索してレビューする
</h2>

`Ctrl+o` は通常のプロンプトとトランスクリプトモード間を切り替えます。

最後のプロンプト、ツール呼び出しの 1 行の概要と編集 diffstats、および最終的な応答のみを表示する、より静かなビューについては、`/focus` を実行してください。この設定はセッション全体で保持されます。`/focus` をもう一度実行してオフにします。

トランスクリプトモードは `less` スタイルのナビゲーションと検索を備えています。

| キー                                    | アクション                                                            |
| :------------------------------------ | :--------------------------------------------------------------- |
| `/`                                   | 検索を開きます。マッチを見つけるために入力し、`Enter` で受け入れ、`Esc` でキャンセルしてスクロール位置を復元します |
| `n` / `N`                             | 次または前のマッチにジャンプします。検索バーを閉じた後に機能します                                |
| `j` / `k` または `↑` / `↓`               | 1 行スクロールします                                                      |
| `g` / `G` または `Home` / `End`          | トップまたはボトムにジャンプします                                                |
| `{` / `}`                             | 前または次のプロンプトにジャンプします                                              |
| `Ctrl+u` / `Ctrl+d`                   | ページの半分スクロールします                                                   |
| `Ctrl+b` / `Ctrl+f` または `Space` / `b` | ページ全体をスクロールします                                                   |
| `Ctrl+o`、`Esc`、または `q`                | トランスクリプトモードを終了してプロンプトに戻ります                                       |

ターミナルの `Cmd+f` と tmux 検索は、会話が代替スクリーンバッファに存在し、ネイティブスクロールバックに存在しないため、会話を見ることができません。コンテンツをターミナルに戻すには、まず `Ctrl+o` を押してトランスクリプトモードに入り、その後以下を実行してください。

* **`[`**: すべてのツール出力が展開された完全な会話をターミナルのネイティブスクロールバッファに書き込みます。会話はターミナル内の通常のテキストになるため、`Cmd+f`、tmux コピーモード、およびその他のネイティブツールで検索または選択できます。長いセッションでは、これが発生している間、一瞬一時停止する場合があります。これは `Esc` または `q` でトランスクリプトモードを終了するまで続き、フルスクリーンレンダリングに戻ります。次の `Ctrl+o` は新しく開始します。
* **`v`**: 会話を一時ファイルに書き込み、`$VISUAL` または `$EDITOR` で開きます。

<h2 id="watch-your-changes-in-the-diff-panel">
  diff パネルで変更を監視する
</h2>

フルスクリーン レンダリングでは、[`/diff`](/docs/ja/interactive-mode#review-changes-with-%2Fdiff) はビューアーを閉じる必要がある代わりに、会話の横にパネルを開くため、Claude が作業している間に変更が蓄積されるのを監視できます。幅の広いターミナルでは、Claude がファイルの編集を開始すると、パネルが自動的に開くこともあります。[Diff パネル](/docs/ja/interactive-mode#diff-panel)は、それが表示する内容、パネルを閉じたままにする方法、および比較対象を変更する方法について説明しています。

<h2 id="clear-the-conversation">
  会話をクリアする
</h2>

`/clear` を実行して新しい会話を開始します。

表示がおかしく見えたり、部分的に空白になっている場合は、`Ctrl+L` を押してスクリーンを再描画します。再描画により、会話と入力内容がそのまま保持されます。

ターミナルが `Cmd+K` を Claude Code に渡す場合、`Cmd+K` は `Ctrl+L` と同じ動作をします。iTerm2 と Terminal.app は `Cmd+K` を自身で処理してスクリーン自体をクリアし、Claude Code はクリアされたスクリーンを検出して会話を再描画します。v2.1.280 より前では、v2.1.260 以降、`Ctrl+L` または Claude Code に到達する `Cmd+K` を押すと、フルスクリーン描画でスクリーンがクリアされました。v2.1.238 より前では、2 秒以内に `Ctrl+L` を 2 回押すと `/clear` が実行されました。

<h2 id="use-with-tmux">
  tmux での使用
</h2>

フルスクリーン レンダリングは tmux 内で動作しますが、3 つの注意点があります。

マウス ホイール スクロールには tmux のマウス モードが必要です。`~/.tmux.conf` でまだ有効になっていない場合は、この行を追加して設定をリロードしてください。

```bash theme={null}
set -g mouse on
```

マウス モードがない場合、ホイール イベントは Claude Code ではなく tmux に送られます。`PgUp` と `PgDn` を使用したキーボード スクロールはどちらの場合でも機能します。Claude Code は、マウス モードがオフの tmux を検出した場合、起動時に 1 回限りのヒントを出力します。

フルスクリーン レンダリングは iTerm2 の tmux 統合モード（`tmux -CC` で入るモード）と互換性がありません。統合モードでは、iTerm2 は各 tmux ペインをネイティブ分割としてレンダリングし、tmux がターミナルに描画することはできません。代替スクリーン バッファとマウス トラッキングはそこで正しく機能しません。マウス ホイールは何もしませんし、ダブルクリックはターミナル状態を破損する可能性があります。`tmux -CC` セッションではフルスクリーン レンダリングを有効にしないでください。iTerm2 内の通常の tmux（`-CC` なし）は正常に機能します。

tmux 3.6 シリーズまでのリリースは同期出力を実装していないため、これらのバージョンでは Claude Code をターミナルで直接実行する場合よりも再描画時にちらつきが多く見られる可能性があります。Claude Code は起動時にターミナルの同期出力サポートをプローブし、ターミナルがそれを報告する場合に使用します。tmux でちらつきが見られる場合は、最新の tmux にアップグレードするか、Claude Code を tmux の外の独自のターミナル タブで実行してください。

<h2 id="keep-native-text-selection">
  ネイティブなテキスト選択を保持する
</h2>

マウスキャプチャは、特に SSH 経由またはtmux 内での最も一般的な摩擦点です。Claude Code がマウスイベントをキャプチャすると、ターミナルのネイティブなコピーオンセレクト機能が機能しなくなります。クリックアンドドラッグで行った選択は Claude Code 内に存在し、ターミナルの選択バッファには存在しないため、tmux コピーモード、Kitty ヒント、および同様のツールはそれを認識しません。

Claude Code は選択内容をシステムクリップボードに書き込み、使用するパスはセットアップによって異なります。ローカルセッションではネイティブクリップボードツールを実行します。

* **macOS**: `pbcopy`
* **Linux**: Wayland では `wl-copy`、X11 では `xclip` または `xsel`（インストールされている方）。Claude Code はクリップボードと PRIMARY 選択の両方に書き込むため、中央クリックペーストが機能します。
* **Windows と WSL**: PowerShell の `Set-Clipboard`

tmux 内では、tmux ペーストバッファにも書き込みます。SSH 経由では OSC 52 エスケープシーケンスにフォールバックします。GNU screen 内では、Claude Code は長い選択もクリップボードにコピーします。v2.1.219 より前では、約 570 文字より長い選択をコピーした場合、GNU screen は base64 テキストをウィンドウに出力していました。Claude Code は各コピー後にトーストを表示し、使用したパスを通知します。

一部のターミナルは OSC 52 をデフォルトでブロックします。iTerm2 は Settings → General → Selection → Applications in terminal may access clipboard をオンにするまでブロックします。iTerm2 で [`/terminal-setup`](/docs/ja/terminal-config) を実行すると、これが自動的に有効になります。

1 回限りのネイティブ選択の場合、使用するキーはターミナルによって異なります。

* **Terminal.app**: `Fn`
* **iTerm2**: `Option`
* **VS Code、Cursor、Devin Desktop**: `Shift`、または macOS で `terminal.integrated.macOptionClickForcesSelection` 設定が有効な場合は `Option`
* **その他のほとんどのターミナル**: `Shift`

そのキーを押しながらクリックしてドラッグします。ターミナルが選択を自身で処理し、Claude Code に渡さないため、`Cmd+C` などのコピーショートカットが選択内容に対して機能します。Claude Code は画面上のヒントに正しいキーも表示します。

SSH 経由または tmux 内では、Claude Code は接続元のターミナルを常に検出できるとは限らないため、ヒントは候補キーのリストを表示します。

ネイティブ選択に常に依存する場合は、`CLAUDE_CODE_DISABLE_MOUSE=1` を設定して、ちらつきのないレンダリングとフラットなメモリを保持しながらマウスキャプチャをオプトアウトします。

```bash theme={null}
CLAUDE_CODE_NO_FLICKER=1 CLAUDE_CODE_DISABLE_MOUSE=1 claude
```

マウスキャプチャが無効な場合、`PgUp`、`PgDn`、`Ctrl+Home`、`Ctrl+End` を使用したキーボードスクロールは引き続き機能し、ターミナルはネイティブに選択を処理します。クリックでカーソルを配置、クリックでツール出力を展開、URL クリック、Claude Code 内でのホイールスクロールが失われます。

ホイールスクロールは保持しながらクリック、ドラッグ、ホバー処理をオフにするには、代わりに `CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1` を設定します。Claude Code v2.1.195 以降が必要です。両方の変数が設定されている場合、`CLAUDE_CODE_DISABLE_MOUSE` が優先されます。

クリックが無効な場合、Claude Code はまだマウスをキャプチャするため、ホイールとタッチパッドは会話をスクロールしますが、Claude Code 内では左クリックは何もしません。ネイティブなクリックアンドドラッグ選択のためにターミナルのキーを押し続ける必要があります。右クリックと中央クリックペーストは、それをサポートするターミナルで引き続き機能します。

<h2 id="troubleshooting">
  トラブルシューティング
</h2>

<h3 id="stale-or-misplaced-text-on-screen">
  画面上に古いテキストまたは配置ずれたテキストが表示される
</h3>

フルスクリーン レンダリングは、フレーム間で変更されたセルのみを送信します。Windows Terminal や他の ConPTY ベースのホストなど、一部のターミナルではこれらの位置指定書き込みが正しく統合されず、ウィンドウをリサイズするまで以前の出力の断片が画面に残ります。

[`CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1`](/docs/ja/env-vars) を設定して、増分更新を送信する代わりに、フレームごとにすべてのセルを再描画します。

Windows PowerShell の場合：

```powershell theme={null}
$env:CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT = "1"
claude
```

macOS または Linux の場合：

```bash theme={null}
CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1 claude
```

Windows では、Claude Code はバックグラウンド セッションと [agent view](/docs/ja/agent-view) に対して既に自動的にフル リペイントを有効にしているため、直接起動したインタラクティブ フルスクリーン セッションに対してのみ変数を設定する必要があります。

<h3 id="fullscreen-renderer-didnt-finish-starting">
  起動時に「Claude Code's fullscreen renderer didn't finish starting last time」が表示される
</h3>

このマシン上のフルスクリーン セッションが正常に開始する前にクラッシュした場合、Claude Code は次のセッションをクラシック レンダラーで開始し、2 つの行のいずれかを出力します。セッションは、最初のフレームを描画してから 10 秒間稼働し続けるか、`/exit`、Ctrl+C、または Ctrl+D で終了した後に正常に開始されたと見なされます。表示される行は、このセッション後に Claude Code が実行する処理を示しています。

* 1 回の失敗した開始後、「Claude Code's fullscreen renderer didn't finish starting last time on this machine」が表示されます。Claude Code は次に開始するセッションでフルスクリーン レンダリングを再度試みます
* 2 回の失敗した開始後、「Claude Code's fullscreen renderer has repeatedly failed to start on this machine」が表示されます。Claude Code は Claude Code を更新するか `/tui fullscreen` を実行するまでクラシック レンダラーを使用し続け、その後のセッションでは何も出力しません

失敗した開始がクラシック レンダラーを使用している理由であることを確認するには、引数なしで `/tui` を実行します。失敗した開始が理由である間、`Current renderer` 行がそのことを示しています。

クラシック レンダラーを保持するには、`/tui default` を実行して、`tui` 設定を再起動せずに保存します。フルスクリーン レンダリングを再度試みるには、`/tui fullscreen` を実行します。そのセッションも開始に失敗した場合は、[問題を報告してください](#research-preview)。

v2.1.236 より前では、Claude Code は失敗した開始後もセッションをフルスクリーン レンダリングで開始し続けていました。

<h4 id="how-claude-code-counts-failed-starts">
  Claude Code が失敗した開始をカウントする方法
</h4>

* カウントされるセッション：`tui` 設定によってフルスクリーン レンダリングで開始されたセッション、[スタートアップ ダイアログ](#fullscreen-by-default) を受け入れたセッション、または Claude Code がデフォルトでフルスクリーンで開始するセッションのみ
* `CLAUDE_CODE_NO_FLICKER=1`：設定した場合、Claude Code は失敗した開始後でもそのセッションをフルスクリーンでレンダリングし、カウントしません
* カウント リセット：Claude Code は Claude Code バージョンごとに失敗した開始をカウントし、フルスクリーン開始の成功によってカウントがリセットされます
* スタートアップ ダイアログ：ダイアログを受け入れて再起動されたセッションがクラッシュした場合、Claude Code は行を出力せず、この Claude Code バージョンではダイアログを再度表示しません

<h2 id="research-preview">
  リサーチプレビュー
</h2>

フルスクリーンレンダリングはリサーチプレビュー機能です。一般的なターミナルエミュレータでテストされていますが、あまり一般的でないターミナルや異常な設定では、レンダリングの問題が発生する可能性があります。

問題が発生した場合は、Claude Code 内で `/feedback` を実行して報告するか、[claude-code GitHub リポジトリ](https://github.com/anthropics/claude-code/issues)で issue を開いてください。ターミナルエミュレータの名前とバージョンを含めてください。

フルスクリーンレンダリングをオフにするには、`/tui default` を実行するか、その方法で有効にした場合は `CLAUDE_CODE_NO_FLICKER` を設定解除してください。`/tui default` で戻すと、Claude Code は最初にオプションのフィードバックプロンプトを表示し、何があなたに切り替えさせたのかを尋ねる場合があります。理由を入力して `Enter` キーを押して送信するか、`Esc` キーを押してスキップしてください。どちらの場合でも、CLI はクラシックレンダラーに再起動します。保存された `tui` 設定に関係なくクラシックレンダラーを強制するには、`CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1` を設定してください。クラシックレンダラーは、ターミナルのネイティブスクロールバックに会話を保持するため、`Cmd+f` と tmux コピーモードは通常どおり機能します。

[エージェントビュー](/docs/ja/agent-view)または `claude attach` から開かれたバックグラウンドセッションは、常にフルスクリーンレンダリングを使用します。アタッチするターミナルは、セッションを表示するために代替スクリーンバッファに入り、クラシックレンダラーはそこではスクロールバックまたはマウス処理がないため、`tui` 設定と `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN` はそれらに適用されません。
