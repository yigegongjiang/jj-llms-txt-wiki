# Commands

> Riferimento completo per i comandi disponibili in Claude Code, inclusi i comandi integrati e le skills in bundle.

I comandi controllano Claude Code dall'interno di una sessione. Forniscono un modo rapido per cambiare modelli, gestire le autorizzazioni, cancellare il contesto, eseguire un flusso di lavoro e altro ancora.

Digita `/` per visualizzare i comandi disponibili, oppure digita `/` seguito da lettere per filtrare. [Come il menu dei comandi corrisponde a quello che digiti](#how-the-command-menu-matches-what-you-type) copre l'evidenziazione, gli errori di battitura e i pochi comandi che Claude Code nasconde dal menu finché non digiti il loro nome completo.

Un comando viene riconosciuto solo all'inizio del tuo messaggio. Il testo che segue il nome del comando diventa i suoi argomenti. A partire dalla v2.1.199, le [skills](/docs/it/skills#pass-arguments-to-skills) sono l'eccezione: un'invocazione di skill seguita da più skill, come `/skill-a /skill-b do XYZ`, carica ogni skill denominata all'inizio e passa il testo finale a ciascuna come argomenti. È possibile concatenare fino a sei skill.

Se invii un comando mentre Claude sta rispondendo, Claude Code lo mette in coda e lo esegue dopo il completamento del turno corrente. Claude Code esegue alcuni comandi immediatamente senza interrompere la risposta, come `/status`, `/tasks` e `/usage`. Nel [rendering a schermo intero](/docs/it/fullscreen), Claude Code apre anche i comandi di dialogo come `/theme` e `/help` immediatamente. Prima della v2.1.234, Claude Code metteva in coda questi dialoghi fino al completamento del turno.

<h2 id="commands-across-a-typical-workflow">
  Comandi in un flusso di lavoro tipico
</h2>

La maggior parte dei comandi sono utili in un momento specifico di una sessione, dalla configurazione di un progetto al rilascio di una modifica.

**Prima sessione in un repository.** Eseguire `/init` per generare un file `CLAUDE.md` iniziale, quindi `/memory` per perfezionarlo. Utilizzare `/mcp` per configurare eventuali server di cui il progetto ha bisogno, chiedere a Claude di creare eventuali [subagenti](/docs/it/sub-agents) desiderati ed eseguire `/permissions` per impostare le regole di approvazione.

**Durante un'attività.** `/plan` passa alla modalità piano prima di una modifica di grandi dimensioni. `/model` e `/effort` regolano quale modello si sta utilizzando e quanto ragionamento applica. Quando la conversazione diventa lunga, `/context` mostra cosa sta riempiendo la finestra e `/compact` la riassume per liberare spazio. Utilizzare `/btw` per una domanda laterale che non dovrebbe aggiungersi alla cronologia della conversazione.

**Eseguire il lavoro in parallelo.** Claude delega i compiti laterali ai [subagenti](/docs/it/sub-agents), e `/tasks` elenca il lavoro in background della sessione corrente, inclusi i subagenti che hanno terminato. `/background` scollega l'intera sessione per continuare l'esecuzione come [agente in background](/docs/it/agent-view) e libera il terminale. Per una modifica di grandi dimensioni che si estende su tutto il codebase, `/batch` la scompone in unità indipendenti ed esegue ciascuna nel proprio [worktree](/docs/it/worktrees). Vedere [Eseguire agenti in parallelo](/docs/it/agents) per come questi approcci si relazionano.

**Prima di rilasciare.** `/diff` mostra cosa è cambiato. `/code-review` controlla il diff corrente per bug di correttezza e può applicare i risultati con `--fix`; passare un numero di PR, come `/code-review high 1234`, per rivedere una pull request. `/review` è un alias. `/code-review ultra` esegue una revisione multi-agente nel cloud. `/security-review` controlla il diff per vulnerabilità di sicurezza.

**Tra le sessioni.** `/clear` inizia da zero su un nuovo compito mantenendo la memoria del progetto. `/resume` ritorna a una conversazione precedente, `/branch` crea un ramo di quella corrente per provare una direzione diversa, e `/fork` la copia in una nuova [sessione in background](/docs/it/agent-view). `/teleport` estrae una sessione web in questo terminale, e `/remote-control` consente di continuare questa sessione locale da un altro dispositivo.

**Quando qualcosa non va.** `/rewind` ripristina il codice e la conversazione a un checkpoint, o riassume parte della conversazione. `/doctor` esegue un controllo di configurazione che diagnostica i problemi di installazione e configurazione e può risolverli, `/debug` diagnostica i problemi di runtime, e `/feedback` segnala un bug con il contesto della sessione allegato.

<h2 id="all-commands">
  Tutti i comandi
</h2>

La tabella seguente elenca tutti i comandi inclusi in Claude Code. La maggior parte sono comandi integrati il cui comportamento è codificato nella CLI. Due tipi di voci sono contrassegnate:

* **[Skill](/docs/it/skills#bundled-skills)**: una skill in bundle. Funziona come le skill che scrivete voi stessi: un prompt consegnato a Claude.
  * `/verify` viene eseguito solo quando lo richiamate. Prima della v2.1.215, Claude poteva anche eseguire `/verify` autonomamente.
* **[Workflow](/docs/it/workflows#bundled-workflows)**: un [workflow dinamico](/docs/it/workflows) in bundle che distribuisce il lavoro su molti subagent e viene eseguito in background.
  * `/deep-research` viene eseguito solo quando lo richiamate. Prima della v2.1.218, Claude poteva anche avviarlo autonomamente.

Per aggiungere i vostri comandi, consultate [skills](/docs/it/skills).

Nella tabella seguente, `<arg>` indica un argomento obbligatorio e `[arg]` indica uno facoltativo.

<Note>
  Non tutti i comandi sono disponibili per ogni utente. La disponibilità dipende dalla vostra piattaforma, dal piano e dall'ambiente. Ad esempio, `/desktop` viene visualizzato solo su macOS e Windows x64 quando siete connessi con un abbonamento Claude, e `/upgrade` non viene visualizzato sui piani Enterprise.
</Note>

<h2 id="how-the-command-menu-matches-what-you-type">
  Come il menu dei comandi corrisponde a quello che digitate
</h2>

Claude Code filtra il menu `/` mentre digitate. Ogni punto sottostante copre una cosa che potreste notare durante il filtraggio:

* **Evidenziazione**: Claude Code evidenzia il suggerimento principale solo quando le lettere dopo `/` corrispondono al nome o all'alias di un comando, dall'inizio del nome o da una parola al suo interno, ignorando i separatori `:`, `_` e `-`. Digitando `/adddir` viene evidenziato `/add-dir`, e digitando `/new` viene evidenziato `/clear` attraverso il suo alias. Premete `Enter` per eseguire il suggerimento evidenziato. Queste regole di evidenziazione richiedono Claude Code v2.1.236 o successivo.
* **Dopo un errore di digitazione**: Claude Code non evidenzia nulla. Le corrispondenze prossime rimangono elencate e potete sceglierne una con `Tab` o i tasti freccia, ma `Enter` invia il vostro testo così come digitato e segnala [Unknown command](/docs/it/errors#unknown-command).
* **Comandi che non sono disponibili per voi**: Claude Code li esclude dal menu. Quando nulla corrisponde, Claude Code mostra `No commands match "/name"`. La maggior parte dei comandi non disponibili restituisce [Unknown command](/docs/it/errors#unknown-command) quando li inviate; alcuni, come [`/schedule` su una chiave Console API](/docs/it/routines#schedule-returns-unknown-command), rispondono invece con il loro messaggio di disponibilità. Alcuni comandi rispondono anche con un messaggio proprio quando la politica della vostra organizzazione li disabilita.
* **Comandi nascosti**: Claude Code mantiene alcuni comandi disponibili, come `/heapdump`, fuori dal menu per progettazione. Un nome parziale non porta mai un comando nascosto nel menu: se la corrispondenza parziale non corrisponde a nulla di visibile, Claude Code mostra lo stesso messaggio di mancata corrispondenza. Claude Code elenca il comando solo una volta che avete digitato il suo nome completo, e l'invio del nome completo lo esegue.
