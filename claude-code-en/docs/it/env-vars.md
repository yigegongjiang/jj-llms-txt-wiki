# Variabili d'ambiente

> Riferimento per le variabili d'ambiente che controllano il comportamento di Claude Code.

Le variabili d'ambiente possono controllare il comportamento di Claude Code come la selezione del modello, l'autenticazione, l'instradamento delle richieste e gli interruttori di funzionalità. Molti degli stessi comportamenti possono essere configurati anche tramite un [file di impostazioni](/docs/it/settings), un [flag CLI](/docs/it/cli-reference) o un comando in-sessione come `/model`.

Questa pagina illustra come:

* [Impostare le variabili d'ambiente](#set-environment-variables) nella shell o in un file di impostazioni
* [Verificare quale valore si applica](#precedence) quando un comportamento può essere impostato in più di un modo
* [Cercare le variabili che Claude Code legge](#variables)
* [Vedere quali funzionalità smettono di funzionare](#features-that-need-feature-flag-fetching) quando una variabile disattiva il recupero dei flag di funzionalità

<h2 id="set-environment-variables">
  Impostare variabili di ambiente
</h2>

Una variabile che imposti nella tua shell dura per quella sessione di terminale, mentre una variabile in un file di impostazioni si applica ogni volta che `claude` viene eseguito.

<h3 id="in-your-shell">
  Nella tua shell
</h3>

Imposta la variabile prima di avviare `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Per impostarla per ogni sessione, aggiungi la riga `export` a `~/.bashrc`, `~/.zshrc`, o al file di profilo della tua shell.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Per impostarla per ogni sessione, esegui `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` e apri un nuovo terminale.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Per impostarla per ogni sessione, esegui `setx API_TIMEOUT_MS "1200000"` e apri un nuovo terminale.
  </Tab>
</Tabs>

La riga di assegnazione non stampa nulla in caso di successo, quindi conferma che la variabile è impostata stampandola nella stessa shell prima di eseguire `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    echo $API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    echo $env:API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    echo %API_TIMEOUT_MS%
    ```
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  Nei file di impostazioni
</h3>

Aggiungi variabili sotto la chiave `env` in un file `settings.json`, creando il file se non esiste. Claude Code le legge direttamente dal file, quindi hanno effetto indipendentemente da come `claude` è stato avviato. Una sessione in esecuzione applica i valori nuovi e modificati al suo ambiente quando salvi il file, ma una funzionalità che legge le sue variabili una sola volta all'avvio, come il [monitoraggio OpenTelemetry](/docs/it/monitoring-usage), mantiene i suoi valori di avvio fino a quando non riavvii. Rimuovere una variabile dal file non la annulla in una sessione in esecuzione; la rimozione ha effetto la prossima volta che avvii `claude`.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

Il file che scegli controlla a chi si applicano le variabili:

| File                          | Si applica a                                                                                                                              |
| :---------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | Te, in ogni progetto                                                                                                                      |
| `.claude/settings.json`       | Tutti coloro che lavorano nel progetto, archiviati nel controllo del codice sorgente                                                      |
| `.claude/settings.local.json` | Te, solo in questo progetto, ignorato da git quando Claude Code salva un'impostazione; aggiungilo al tuo gitignore se lo crei manualmente |
| Impostazioni gestite          | Tutti nella tua organizzazione, distribuiti da un amministratore                                                                          |

Vedi [File di impostazioni](/docs/it/settings#where-settings-live) per sapere dove si trova ogni file e [Precedenza delle impostazioni](/docs/it/settings#settings-precedence) per come si combinano quando più di uno imposta la stessa variabile.

<h2 id="precedence">
  Precedenza
</h2>

Alcuni comportamenti hanno sia una variabile di ambiente che una chiave di impostazioni dedicata, e quale Claude Code legge per primo differisce per chiave. Per `ANTHROPIC_MODEL` e `CLAUDE_CODE_AUTO_CONNECT_IDE`, Claude Code legge prima la variabile e utilizza l'impostazione `model` o `autoConnectIde` solo quando la variabile non è impostata. Per la coppia che state impostando, controllate la riga della variabile di seguito e la voce della chiave nel [riferimento delle impostazioni](/docs/it/settings-reference).

Quando la stessa variabile è impostata sia nella vostra shell che in un blocco `env` del file di impostazioni, il valore del file di impostazioni si applica. Claude Code scrive ogni voce `env` nell'ambiente del processo, sostituendo il valore ereditato dalla shell. L'[impostazione `env`](/docs/it/settings-reference#when-claude-code-applies-env-values) indica quando la applica. Alcune variabili sono trattate come casi speciali; l'[impostazione `env`](/docs/it/settings-reference#env) elenca le eccezioni.

In un file di impostazioni potete impostare una variabile ma non potete rimuoverne una. Per sovrascrivere una variabile che non potete annullare, come una `CLAUDE_CODE_USE_VERTEX` obsoleta esportata da un profilo di shell che non controllate, impostatela su una stringa vuota nel blocco `env`: `"CLAUDE_CODE_USE_VERTEX": ""`. Claude Code tratta il valore vuoto come non impostato per la selezione del provider. I sottoprocessi ereditano comunque il valore vuoto.

Tra i file di impostazioni, i valori `env` seguono la [precedenza delle impostazioni](/docs/it/settings#settings-precedence), quindi una voce di impostazioni gestite sovrascrive la stessa variabile nelle impostazioni utente o progetto.

Il modo in cui una variabile di ambiente interagisce con i flag CLI e i comandi in-session varia per funzionalità: `--model` e `/model` sovrascrivono `ANTHROPIC_MODEL`, mentre `CLAUDE_CODE_EFFORT_LEVEL` sovrascrive `--effort` e `/effort`. Quando una variabile interagisce con un'altra fonte di configurazione, la sua riga nell'elenco [Variabili](#variables) dichiara la precedenza o rimanda alla pagina che la documenta.

Claude Code legge le variabili di ambiente della shell all'avvio, quindi le modifiche ad esse hanno effetto la prossima volta che avviate `claude`. Le variabili impostate sotto la chiave `env` nei file di impostazioni vengono riapplicate a una sessione in esecuzione quando il file cambia, con l'eccezione di avvio-solo descritta in [Nei file di impostazioni](#in-settings-files).

<h2 id="variables">
  Variabili
</h2>

Le variabili numeriche come timeout, budget di token e conteggi di tentativi accettano notazione scientifica e ortografia con separatori di cifre oltre alle cifre semplici, tranne dove la riga di una variabile nota che accetta solo cifre semplici. Ad esempio, Claude Code legge `2e3` come 2000 e `64_000` come 64000. Prima della v2.1.211, queste ortografie potevano impostare silenziosamente un valore molto più piccolo, come `1e6` che impostava un timeout a 1.

<Note>
  Per le variabili che attivano o disattivano un comportamento, impostare `1` o `true` per attivarlo e `0` o `false` per disattivarlo, in qualsiasi maiuscola.

  Alcune variabili leggono solo se le avete impostate, quindi qualsiasi valore non vuoto incluso `0` attiva il comportamento, e disattivate il comportamento non impostando la variabile o impostandola su un valore vuoto. Queste variabili funzionano in questo modo:

  * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
  * `DISABLE_TELEMETRY`
  * `DISABLE_ERROR_REPORTING`
  * `CLAUDE_CODE_TMUX_TRUECOLOR`
  * `FALLBACK_FOR_ALL_PRIMARY_MODELS`
  * `IS_DEMO`

  Un'altra variabile ha la sua regola: `FORCE_HYPERLINK` legge un numero, quindi solo `0` la disattiva. La riga di ogni variabile dichiara anche la sua regola.
</Note>

<h2 id="features-that-need-feature-flag-fetching">
  Funzionalità che richiedono il recupero dei feature flag
</h2>

Claude Code attiva alcune funzionalità tramite feature flag che recupera da Anthropic. Claude Code salta questo recupero in queste sessioni:

* Una sessione in cui impostate `DISABLE_GROWTHBOOK`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK`, o `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`; la riga di ogni variabile nella [tabella delle variabili](#variables) indica quali valori disattivano il recupero
* Una sessione su un [provider di terze parti](/docs/it/third-party-integrations), come Amazon Bedrock, Claude Platform su AWS, Agent Platform di Google Cloud, o Microsoft Foundry, a meno che una piattaforma host che incorpora Claude Code non imposti `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
* Una sessione di [gateway delle app Claude](/docs/it/claude-apps-gateway)

Con il recupero disattivato, non potete:

* [Avviare sessioni in modalità auto per impostazione predefinita](/docs/it/permission-modes#which-mode-a-session-starts-in) sui piani Pro, Max e Team
* Far [leggere all'estensione VS Code i file di impostazioni per la modalità di autorizzazione iniziale](/docs/it/permission-modes#switch-permission-modes)
* Eseguire [`/auto-mode-setup`](/docs/it/auto-mode-config#generate-environment-entries) per elaborare le voci `autoMode.environment`
* Utilizzare [Remote Control](/docs/it/remote-control#requirements)
* [Inviare messaggi alle sessioni oltre questa macchina](/docs/it/cross-session-messaging#message-sessions-on-other-machines); la messaggistica tra sessioni su questa macchina funziona con il recupero disattivato
* Eseguire [`claude import` o il comando `/import`](/docs/it/cli-reference#cli-commands)
* Eseguire [`/skill-doctor`](/docs/it/skills#find-unused-skills) o aprire il suo rapporto nella scheda **Stats** di `/plugin`
* Sincronizzare le [skill](/docs/it/skills#where-synced-skills-load) e i [plugin](/docs/it/plugins-reference#synced-plugins) abilitati per il vostro account claude.ai nelle vostre sessioni di terminale
* Utilizzare [lo strumento advisor](/docs/it/advisor#requirements)
* Leggere o rispondere ai [commenti su un artefatto](/docs/it/artifacts#collect-comments-on-an-artifact)
* Avere Claude Code sondare i server del connettore claude.ai per [la revisione del protocollo MCP 2026-07-28](/docs/it/mcp#mcp-client-runtimes) a meno che non impostiate `MCP_PROTOCOL_NEGOTIATION=auto`
* Ottenere lo [strumento PowerShell](/docs/it/tools-reference#powershell-tool) per impostazione predefinita per gli account claude.ai e Console su Windows con Git Bash installato; Claude Code instrada i comandi della shell attraverso Git Bash a meno che non impostiate `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`. Su Windows senza Git Bash, lo strumento rimane attivo
* Ottenere il [feedback elaborato da Claude](/docs/it/tools-reference#sendfeedback-tool-behavior), che Claude Code attiva tramite un flag recuperato
* Far [trattare a Claude i grandi incollamenti come testo incollato piuttosto che digitato](/docs/it/terminal-config#how-claude-treats-pasted-text); il contenuto dietro un segnaposto `[Pasted text #N]` raggiunge Claude senza marcatura
* Avere Claude Code [escludere i tool MCP il cui schema di input l'API rifiuterebbe](/docs/it/mcp#tools-with-invalid-input-schemas); invia comunque lo schema, e una richiesta che lo include fallisce con [un errore 400 che nomina il tool in base alla sua posizione](/docs/it/errors#tool-input-schema-is-invalid)

<h3 id="first-session-after-an-install-or-upgrade">
  Prima sessione dopo un'installazione o un aggiornamento
</h3>

Nella vostra prima sessione dopo aver installato Claude Code, o aggiornato a una versione che aggiunge una funzionalità, una [funzionalità con gate flag](#features-that-need-feature-flag-fetching) può mancare, e la sessione può avviarsi in modalità Manual su un piano che altrimenti si avvia in modalità auto. Claude Code recupera i flag durante quella sessione, quindi entrambi sono presenti nella vostra sessione successiva.

Dopo un'installazione pulita, in una sessione non interattiva come `claude -p`, l'Agent SDK, o l'estensione VS Code, Claude Code può comunque recuperare i flag prima di [scegliere la modalità di autorizzazione iniziale](/docs/it/permission-modes#which-mode-a-session-starts-in).
