# Riferimento CLI

Se digiti male un sottocomando, Claude Code suggerisce la corrispondenza più vicina e esce senza avviare una sessione. Ad esempio, `claude udpate` stampa `Did you mean claude update?`.

A partire da v2.1.199, `claude --dangerously-skip-permissions daemon <subcommand>` esegue il sottocomando `daemon`. Le versioni precedenti trattavano `daemon <subcommand>` come il prompt per una nuova sessione interattiva, quindi il sottocomando non veniva mai eseguito quando il flag veniva per primo, una configurazione comune quando `claude` è aliasato per includere il flag. Solo un `--dangerously-skip-permissions` o `--allow-dangerously-skip-permissions` iniziale instrada a `daemon` in questo modo; qualsiasi altro flag iniziale avvia comunque una sessione interattiva.

<h3 id="system-prompt-flags">
  Flag del prompt di sistema
</h3>

Claude Code fornisce cinque flag per personalizzare il prompt di sistema. Quattro impostano il suo testo, e con `--system-prompt-snapshot` controlli se una conversazione mantiene il testo con cui ha iniziato. Tutti e cinque funzionano sia in modalità interattiva che non interattiva.

| Flag                          | Comportamento                                                                                                                                                                                    | Esempio                                                                    |
| :---------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| `--system-prompt`             | Sostituisce l'intero prompt predefinito                                                                                                                                                          | `claude --system-prompt "You are a Python expert"`                         |
| `--system-prompt-file`        | Sostituisce con il contenuto del file                                                                                                                                                            | `claude --system-prompt-file ./prompts/review.txt`                         |
| `--append-system-prompt`      | Aggiunge al prompt predefinito                                                                                                                                                                   | `claude --append-system-prompt "Always use TypeScript"`                    |
| `--append-system-prompt-file` | Aggiunge il contenuto del file al prompt predefinito                                                                                                                                             | `claude --append-system-prompt-file ./style-rules.txt`                     |
| `--system-prompt-snapshot`    | Con `off`, ricostruisce il prompt su ogni richiesta. Con `on`, il predefinito, riutilizza un prompt registrato dove [la registrazione si applica](#system-prompt-flags-in-resumed-conversations) | `claude --append-system-prompt "Draft rules" --system-prompt-snapshot off` |

`--system-prompt` e `--system-prompt-file` si escludono a vicenda. I flag di aggiunta possono essere combinati con uno dei flag di sostituzione.

Quando il testo di sostituzione combina istruzioni che sono le stesse su ogni esecuzione con contesto che cambia per esecuzione, aggiungi una riga contenente solo `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` tra le istruzioni e il contesto. Claude Code divide il prompt alla prima riga di questo tipo e rimuove quella riga, quindi la parte sopra rimane memorizzata nella cache mentre la parte sotto cambia. Richiede Claude Code v2.1.275 o successivo. [Memorizza nella cache la parte statica di un prompt personalizzato](/docs/it/agent-sdk/modifying-system-prompts#cache-the-static-part-of-a-custom-prompt) elenca le configurazioni dove la divisione si applica.

Scegli in base al fatto che l'identità predefinita di Claude Code si adatti ancora al tuo compito. Usa un flag di aggiunta quando Claude dovrebbe rimanere un assistente di codifica che segue anche le tue regole extra: istruzioni per invocazione, formattazione dell'output, o contesto di dominio per uno script `-p`. L'aggiunta preserva la guida dello strumento predefinito, le istruzioni di sicurezza e le convenzioni di codifica, quindi fornisci solo quello che differisce. Usa un flag di sostituzione quando la superficie, l'identità, o il modello di permesso differisce da quello di Claude Code, come un agente non di codifica in una pipeline che nessun umano guarda. La sostituzione elimina l'intero prompt predefinito, inclusa la guida dello strumento e le istruzioni di sicurezza, quindi assumi la responsabilità di qualsiasi cosa il tuo compito abbia ancora bisogno.

Per persone persistenti che puoi alternare e condividere tra un progetto, usa gli [stili di output](/docs/it/output-styles). Per le convenzioni di progetto che Claude dovrebbe sempre seguire, usa [CLAUDE.md](/docs/it/memory). La [guida dell'Agent SDK sui prompt di sistema](/docs/it/agent-sdk/modifying-system-prompts#decide-on-a-starting-point) copre la stessa decisione in maggiore profondità.

<h4 id="system-prompt-flags-in-resumed-conversations">
  Flag del prompt di sistema nelle conversazioni riprese
</h4>

Per impostazione predefinita, Claude Code costruisce il prompt di sistema una volta, sulla prima richiesta di una conversazione, con il testo da qualsiasi flag di prompt di sistema applicato, e lo registra nella sessione. Fino a quando la conversazione non viene compattata, ogni richiesta successiva utilizza quel prompt registrato, incluso dopo che torni alla conversazione con `--resume` o `--continue`. Se passi un testo di flag di prompt di sistema diverso, o nessuno, su quel lancio successivo, ha effetto una volta che la conversazione viene compattata o quando inizi una nuova conversazione.

Al di fuori delle [sessioni cloud](/docs/it/cloud-environments), se avvii Claude Code in [modalità bare](/docs/it/headless#start-faster-with-bare-mode) passando `--bare` o impostando `CLAUDE_CODE_SIMPLE=1`, la registrazione rimane disattivata a meno che tu non passi `--system-prompt-snapshot on`. Prima di v2.1.268, le sessioni che non [recuperano i flag di funzionalità](/docs/it/env-vars#features-that-need-feature-flag-fetching), incluse le sessioni su Amazon Bedrock, Google Cloud's Agent Platform, e Microsoft Foundry, ricostruivano il prompt su ogni richiesta e `--system-prompt-snapshot` non aveva effetto.

Per ricostruire il prompt su ogni richiesta invece, ad esempio mentre iteri sulla sua formulazione tra le esecuzioni `--continue`, passa `--system-prompt-snapshot off`. Prima di v2.1.265, passare uno qualsiasi dei flag di prompt di sistema disattivava anche la registrazione a meno che tu non passassi `--system-prompt-snapshot on`.
