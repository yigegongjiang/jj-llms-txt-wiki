# Claude가 프로젝트로 진행 중인 작업을 조율하도록 하기

> Claude에게 한 대화에서 관련된 작업 모음을 제공하고 저장소, 지침 및 메모리를 공유하는 병렬 클라우드 세션을 조율하도록 합니다.

<Note>
  프로젝트는 Pro 및 Max 플랜에서 공개 베타 상태이며 [클라우드 세션](/docs/ko/claude-code-on-the-web)을 사용했으며 claude.ai 채팅 또는 Cowork에 기존 프로젝트가 없는 계정부터 시작하여 점진적으로 출시되고 있습니다. 아직 Team 또는 Enterprise 플랜에서는 사용할 수 없습니다. [claude.ai/code](https://claude.ai/code)의 사이드바 또는 [데스크톱 앱](/docs/ko/desktop)의 Code 탭에 **프로젝트**가 나타나지 않으면 출시가 계정에 아직 도달하지 않았으며 [대기 목록에 참여](https://claude.com/form/projects)할 수 있습니다. [병렬로 에이전트 실행](/docs/ko/agents)에서 그 동안 사용할 수 있는 것을 나열합니다.
</Note>

프로젝트는 Claude가 관련된 작업 흐름을 조율하는 하나의 진행 중인 대화입니다. 사용자가 수행해야 할 작업을 알려주면 Claude는 각 작업에 대한 스레드를 시작합니다.

각 스레드는 보통 [클라우드 세션](/docs/ko/claude-code-on-the-web)입니다. Claude Code가 사용자의 머신이 아닌 클라우드에서 실행됩니다. 작업에 컴퓨터에만 있는 것이 필요한 경우 Claude에게 [원격 제어](/docs/ko/remote-control)를 통해 해당 스레드를 컴퓨터에서 실행하도록 요청할 수 있습니다. 스레드는 병렬로 실행되며 휴대폰에서 스레드를 확인하고 조율할 수 있습니다. 클라우드 스레드는 노트북을 닫은 후에도 계속 진행됩니다.

프로젝트가 없으면 여러 세션을 실행하는 것은 직접 조율해야 합니다. 각 세션이 수행할 작업을 결정하고, 각 세션의 시작 부분에서 동일한 배경을 반복하고, 어느 것이 완료되었거나 답변이 필요한지 확인하기 위해 다시 확인합니다. 프로젝트를 사용하면 대신:

* **한 곳으로 작업 전송**: 버그 보고서, 스택 추적 또는 작업 목록을 대화에 붙여넣으면 Claude가 각 작업에 대한 스레드를 시작하거나 이미 해당 영역에서 작업 중인 스레드로 전달하고 빠른 질문에 즉시 답변합니다.
* **컨텍스트를 한 번 설정**: 모든 새 스레드는 프로젝트의 지침으로 시작하므로 대상 분기와 같이 한 번 명시한 규칙이 모든 스레드에 도달합니다.
* **떠났다가 완료된 작업으로 돌아오기**: 한 시간 후 또는 다음 아침에 돌아오면 **개요** 창에 어느 스레드가 완료되었는지, 어느 풀 요청이 검토 준비가 되었는지, 어느 스레드가 사용자의 답변을 기다리고 있는지 표시됩니다.

이미 프로젝트가 실행하기를 원하는 작업을 알고 있다면 [프로젝트 생성](#create-a-project)으로 바로 이동하세요.

<h2 id="when-to-use-a-project">
  프로젝트를 사용할 때
</h2>

프로젝트는 한 세션보다 오래 지속되고 계속 작업을 생성하는 목표가 있을 때 생성할 가치가 있습니다. 이러한 종류의 작업이 프로젝트에 적합합니다:

* **많은 저장소에 걸친 하나의 목표**: "모든 서비스를 새 lint 구성으로 업그레이드합니다." Claude는 저장소당 하나의 스레드를 실행할 수 있으며, 각각 자체 풀 요청을 가지고 있고, [**Overview** 창](#see-what-needs-you-in-overview)에 어느 것이 검토 준비가 되었는지 표시됩니다.
* **계속 공급하는 영역**: 한 서비스에 대한 버그, 스택 추적 및 검토 요청을 대화에 붙여넣으면 도달합니다. 한 수정 후 Claude에게 기억하도록 말한 함정은 다음 수정을 위해 [프로젝트 메모리](#give-a-project-standing-context)에 있습니다.
* **세션보다 큰 빌드 또는 마이그레이션**: "`docs/spec.md`가 설명하는 것을 빌드합니다" 또는 "앱을 더 이상 사용되지 않는 ORM에서 이동합니다." 작업은 각각 일부를 수행하는 스레드로 분할되고, Claude에게 초기에 기억하도록 요청한 결정이 나중 스레드에 도달하며, 빌드 중에 발견한 사양 변경 및 버그가 동일한 대화로 이동합니다.
* **코드가 아닌 작업**: 계약 폴더 또는 지원 티켓 내보내기를 계속 돌아와서 새로운 질문을 하는 경우, 예를 들어 "이 티켓에서 가장 일반적인 10가지 통합 실수를 찾습니다." 저장소를 추가하는 대신 문서를 업로드하고, 스레드는 프로젝트의 [**Library** 탭](#see-what-needs-you-in-overview)에 각 작성물을 파일로 제공합니다.

이 중 어느 것이든 작업 배치를 보내고, Claude에게 확인을 요청하지 않고 시작하도록 말하고, 떠났다가 돌아올 때 [**Waiting on you**](#see-what-needs-you-in-overview) 아래에서 필요한 스레드를 찾거나, Claude에게 작업의 일부를 [루틴](/docs/ko/routines)으로 일정에 따라 실행하도록 요청할 수 있습니다. 이 중 하나가 상황이라면 [프로젝트를 생성](#create-a-project)하세요.

<h3 id="when-something-else-fits-better">
  다른 것이 더 잘 맞을 때
</h3>

Cloud 스레드는 GitHub 저장소와 프로젝트에 업로드한 파일, 폴더 및 Google Drive 폴더에서 작동하며, 머신에만 존재하는 파일이나 도구에서는 작동하지 않습니다. 작업에 머신이 필요하면 [Remote Control](/docs/ko/remote-control)을 통해 Claude에게 해당 스레드를 머신에서 실행하도록 요청하세요. [Limitations](#limitations)에서 필요한 것을 나열합니다. 다음 경우에는 다른 것이 더 잘 맞습니다:

* **세션에 맞는 하나의 작업**: "불안정한 로그인 테스트를 수정합니다." [클라우드 세션](/docs/ko/claude-code-on-the-web)을 직접 시작하세요.
* **모든 작업이 머신이 필요한 작업**: 로컬 데이터베이스, 디바이스 에뮬레이터, 또는 VPN 뒤의 API입니다. 로컬 세션을 사용하거나, [agent view](/docs/ko/agent-view)를 사용하여 여러 개를 동시에 실행하세요. 작업에 로컬 파일만 필요하면 대신 프로젝트에 업로드하세요.
* **대화 없이 일정에 따라 반복되는 하나의 작업**: "매주 월요일 종속성 보고서를 게시합니다." 자체적으로 [루틴](/docs/ko/routines)을 생성하세요.
* **여러 사람이 Claude에게 작업을 제공하고 Slack 채널에서 함께 조율**: [Claude Tag](https://claude.com/docs/claude-tag/overview)를 참조하세요.

프로젝트는 다른 Claude Code 세션과 동일한 플랜 제한을 사용하며 더 빠르게 사용합니다. [사용 및 비용](#usage-and-cost)에서 플랜을 사용하는 것과 이를 줄이는 방법을 다룹니다.

<h2 id="how-a-project-is-organized">
  프로젝트가 어떻게 구성되는지
</h2>

프로젝트는 Claude와의 하나의 조율 대화와 그것이 작업을 수행하기 위해 시작하는 스레드입니다. 이것이 그 부분들입니다:

* **프로젝트 대화**: Claude가 조율자 역할을 하는 하나의 장기 실행 세션입니다. 사용자가 보내는 것을 받아서 무엇이 스레드가 될지 결정하고 시작한 모든 스레드를 추적합니다. 스레드가 보고하는 것을 보지만 스레드가 취하는 모든 단계를 보지는 않습니다.
* **스레드**: 작업자입니다. 각각은 자신의 컨텍스트 윈도우를 가진 별도의 세션으로, 한 가지 작업을 수행하고 완료되면 대화에 보고합니다. 클라우드 스레드는 자신의 브랜치에서 작업하고 작업이 필요할 때 풀 리퀘스트를 엽니다.
* **모든 클라우드 스레드가 시작할 때 가지는 것**:
  * 프로젝트의 저장소와 파일, 그리고 [지침과 메모리](#give-a-project-standing-context)
  * [프로젝트의 각 저장소](#what-threads-pick-up-from-your-repositories)의 `CLAUDE.md`와 스킬, 그리고 하나의 저장소를 가진 프로젝트에서는 그 저장소의 권한 규칙과 훅도 포함
  * claude.ai 계정의 [커넥터](#get-skills-plugins-connectors-and-tools-into-threads)
  * 네트워크 액세스, 환경 변수, API 자격 증명, 설치된 도구를 설정하는 [클라우드 환경](#choose-an-environment-for-threads)
* **개요 창**: [모든 스레드를 한 번에 보고](#see-what-needs-you-in-overview) 어느 것이 사용자를 필요로 하는지 보는 곳입니다. 다른 탭은 추가한 파일과 스레드가 생성한 파일을 위한 **라이브러리**, 스레드가 열은 풀 리퀘스트를 위한 **풀 리퀘스트**, 프로젝트의 예약된 작업을 위한 **루틴**입니다.

클라우드 스레드는 자신의 머신에 있는 Claude Code 설정에서 아무것도 선택하지 않습니다. [스레드에 스킬, 플러그인, 커넥터, 도구 가져오기](#get-skills-plugins-connectors-and-tools-into-threads)는 그들이 다른 방법으로 누락될 것들을 어떻게 제공하는지 다룹니다.

대화를 통해 사용자에서 작업을 수행하는 스레드까지 이러한 부분들이 어떻게 연결되는지, **개요**가 그들의 상태를 추적하는 방식입니다:

<h2 id="create-a-project">
  프로젝트 만들기
</h2>

[claude.ai/code](https://claude.ai/code)에서 또는 데스크톱 앱의 Code 탭에서, 그리고 [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) 및 [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude)용 Claude 모바일 앱에서 프로젝트를 만들고 사용합니다. 브라우저와 데스크톱 앱에서 프로젝트를 시작하는 방법은 두 가지입니다:

* **처음부터 시작**: Claude가 실행할 작업 흐름을 알고 있을 때 **새 프로젝트** 대화상자를 열고 이름을 지정합니다. [처음부터 새 프로젝트 시작하기](#start-a-new-project-from-scratch)에서 대화상자를 안내합니다.
* **이미 작업 중인 클라우드 세션에서**: 해당 세션의 메뉴에서 **프로젝트로 계속하기**를 선택하면 Claude가 세션이 수행 중이던 작업을 바탕으로 프로젝트 설정을 제안합니다. [기존 클라우드 세션에서 시작하기](#start-from-an-existing-cloud-session)를 참조하세요.

어느 쪽이든 먼저 [필수 조건 확인하기](#check-the-prerequisites)를 확인하세요.

<h3 id="check-the-prerequisites">
  필수 조건 확인하기
</h3>

프로젝트를 만들기 전에 플랜, GitHub 설정 및 작업이 도달해야 할 사항을 확인하세요:

* **플랜**: Pro 또는 Max를 사용 중이며 사이드바에 **프로젝트**가 표시됩니다.
* **GitHub(프로젝트가 코드에서 작업할 경우)**: 코드가 GitHub Enterprise Server, GitLab 또는 Bitbucket이 아닌 github.com에 있고, 연결된 GitHub 계정이 코드에 대한 푸시 액세스 권한을 가지고 있으며, Claude GitHub App이 설치되어 있습니다. [`/web-setup`](/docs/ko/web-quickstart#connect-from-your-terminal)으로 GitHub를 연결한 경우, 해당 토큰을 사용하면 다른 클라우드 세션이 리포지토리에 도달할 수 있지만 Claude GitHub App이 필요한 프로젝트의 클라우드 스레드에는 충분하지 않습니다. [GitHub 액세스 설정하기](#set-up-github-access)에 단계가 나와 있습니다.
* **네트워크, 자격 증명 및 도구**: 클라우드 스레드의 경우, 이들은 프로젝트의 [클라우드 환경](#choose-an-environment-for-threads)에서 제공됩니다. 기본 환경은 이미 [일반적인 패키지 레지스트리](/docs/ko/cloud-environments#default-allowed-domains)에 도달하므로, 작업이 다른 도메인, 시크릿 또는 사전 설치되지 않은 도구가 필요한 경우에만 확인하세요. 작업이 MCP 서버가 필요한 경우, [claude.ai 커넥터](https://claude.ai/customize/connectors)에서 연결된 것으로 표시되는지 확인하세요.

<h3 id="start-a-new-project-from-scratch">
  처음부터 새 프로젝트 시작하기
</h3>

처음부터 프로젝트를 시작한다는 것은 **새 프로젝트** 대화상자를 열고, 작업 흐름의 이름을 지정하고, 선택적으로 목표와 작업할 리포지토리 및 파일을 제공하는 것을 의미합니다. 이름만 필수이므로 먼저 프로젝트를 만들고 작업이 진행되면서 나머지를 채울 수 있습니다.

<Steps>
  <Step title="프로젝트 열기">
    [claude.ai/code](https://claude.ai/code)에서 또는 데스크톱 앱의 Code 탭에서 왼쪽 사이드바의 **프로젝트**를 선택한 다음 **새 프로젝트**를 선택합니다. 브라우저에서는 [claude.ai/code/projects/browse](https://claude.ai/code/projects/browse)로 직접 이동할 수도 있습니다.
  </Step>

  <Step title="새 프로젝트 대화상자 채우기">
    프로젝트를 계속 추가할 하나의 작업 흐름으로 범위를 지정합니다. 예를 들어 하나의 API를 지연 시간 목표 이내로 유지하는 데 필요한 모든 것입니다. [프로젝트를 사용할 때](#when-to-use-a-project)에 더 많은 예시가 있습니다. 그런 다음 대화상자의 필드를 채웁니다:

    * **이름**: **프로젝트** 목록에 프로젝트가 표시되는 방식입니다.
    * **목표** (선택 사항): "p95 API 지연 시간을 200ms 이하로 유지"와 같이 달성하려는 작업의 한 줄입니다. 대화에서 Claude는 이를 향해 작업합니다. 목표가 없으면 Claude는 사용자가 보내는 작업에서 작업하며, 나중에 **프로젝트 설정 > 일반**에서 목표를 추가할 수 있습니다.
    * **컨텍스트** (선택 사항): 이 프로젝트가 작업할 GitHub 리포지토리와 스레드가 읽어야 할 파일, 폴더 또는 Google Drive 폴더입니다. 각각에 대해 **추가**를 클릭합니다. 작업이 만질 수 있는 모든 리포지토리가 아닌 대부분의 작업이 필요로 하는 리포지토리를 추가합니다. [추가할 리포지토리 결정하기](#decide-which-repositories-to-add)에서 선택 사항을 다룹니다. 나중에 **프로젝트 설정 > 환경**에서 더 추가할 수 있습니다.

    스레드가 어떻게 작동해야 하는지에 대한 상시 규칙은 [프로젝트 지침](#give-a-project-standing-context)에 들어가며, 이는 프로젝트가 존재한 후에 설정합니다.
  </Step>

  <Step title="프로젝트 만들기">
    **프로젝트 만들기**를 클릭합니다. 프로젝트의 대화가 열리고 하단에 메시지 상자가 있으며, 여기서 Claude를 위한 작업을 설명합니다.

    첫 번째 프로젝트에서는 먼저 메시지를 보내지 않는 한 프로젝트가 만들어지자마자 Claude가 자신의 차례를 가집니다. 그 차례는 플랜을 사용합니다. 그 과정에서 Claude는 다음을 수행할 수 있습니다:

    * 리포지토리를 읽을 수 있는 프로젝트가 있는 경우 리포지토리를 탐색하는 하나의 스레드를 시작하고 아무것도 변경하지 않으며 다음 단계를 제안합니다.
    * 최근 클라우드 세션에서 도출한 **설정 권장 사항**을 게시합니다: 추가할 리포지토리, 만들 루틴 및 시작할 수 있는 스레드입니다. 권장되는 모든 리포지토리와 루틴은 기본적으로 켜져 있습니다. 원하지 않는 것은 끄고 **설정 업데이트**를 클릭하여 나머지를 추가하거나, 권장 사항을 무시하고 직접 작업을 설명합니다.
  </Step>
</Steps>

프로젝트는 이제 사이드바의 **프로젝트** 아래에 나열되고 대화가 열려 있습니다. [첫 번째 배치](#your-first-batch)에서는 작업을 보내기 전에 설정할 사항을 다룹니다.

<h3 id="start-from-an-existing-cloud-session">
  기존 클라우드 세션에서 시작하기
</h3>

이미 프로젝트에 속해야 하는 작업을 수행 중인 클라우드 세션이 있는 경우, 사이드바에서 세션의 메뉴를 열고 **프로젝트로 계속하기** 또는 **프로젝트로 이동**을 선택합니다:

* **프로젝트로 계속하기**는 세션의 이름을 따서 새 프로젝트를 만들고 엽니다. Claude는 세션을 읽고 대화에 **설정 권장 사항**을 게시하여 확인하도록 합니다. 원본 세션은 세션 목록에 남아 있고, 차례 중간에 있었다면 계속 실행되므로 둘 다 동시에 작동하지 않으려면 직접 중지하세요. 클라우드 세션의 메시지 상자 위에 나타날 수 있는 **프로젝트 설정** 배너를 대신 사용하면 결과는 동일하지만, 프로젝트가 열리면 세션의 실행 중인 차례가 중지됩니다.
* **프로젝트로 이동**은 세션의 작업을 기존 프로젝트로 가져옵니다. 해당 프로젝트의 대화에 Claude가 세션을 읽고 중단한 부분부터 계속하도록 요청하는 메시지를 게시하고, 새 작업은 프로젝트의 자체 스레드에서 계속됩니다. 원본 세션은 세션 목록에 남아 있으며 변경되지 않습니다.

<h3 id="set-up-github-access">
  GitHub 액세스 설정하기
</h3>

대부분의 GitHub 설정은 프로젝트당이 아닌 한 번만 발생합니다. GitHub 계정을 Claude에 한 번 연결하고, Claude GitHub App은 리포지토리당 한 번 또는 모든 리포지토리를 제공하는 경우 전체 GitHub 조직에 대해 한 번 설치됩니다. Claude GitHub App이 아직 다루지 않는 리포지토리를 추가하거나 SSO를 적용하는 GitHub 조직의 리포지토리를 추가할 때 이 단계로 돌아옵니다.

<Steps>
  <Step title="GitHub 계정 연결하기">
    이전에 claude.ai/code를 사용하지 않았다면, 첫 방문 시 GitHub 연결을 안내합니다. [GitHub 연결하기](/docs/ko/web-quickstart#connect-github)를 참조하세요. 그렇지 않으면 [GitHub 인증 옵션](/docs/ko/claude-code-on-the-web#github-authentication-options) 중 하나를 사용합니다.
  </Step>

  <Step title="프로젝트의 리포지토리에 Claude GitHub App 설치하기">
    [Claude GitHub App](https://github.com/apps/claude)을 설치하고 프로젝트가 사용할 리포지토리에 대한 액세스 권한을 부여합니다. GitHub 조직이 소유한 리포지토리에서는 조직 소유자만 설치를 완료할 수 있습니다. 소유자가 아닌 경우 GitHub는 소유자에게 설치 요청을 보내고 소유자가 승인할 때까지 프로젝트는 리포지토리를 사용할 수 없습니다.
  </Step>

  <Step title="SSO를 적용하는 조직에 대해 SSO 승인하기">
    GitHub 조직이 SAML SSO를 적용하는 경우, GitHub를 다시 연결하고 해당 조직에 대해 Claude 앱을 승인합니다. 이를 수행할 때까지 해당 조직의 비공개 리포지토리는 **새 프로젝트** 대화상자 또는 **프로젝트 설정 > 환경**에 나타나지 않습니다.
  </Step>
</Steps>

이 단계 중 하나가 완료되지 않으면 **새 프로젝트** 대화상자와 프로젝트 페이지에서 누락된 단계를 이름 지정하고 완료할 위치로 연결합니다. 거기서 단계를 완료한 다음, 대화상자에서 제공하는 경우 **다시 확인**을 클릭합니다. 그 후에도 리포지토리가 목록에서 여전히 누락된 경우, [github.com/settings/installations](https://github.com/settings/installations)에서 개인 계정의 Claude GitHub App 설치를 열고, **리포지토리 액세스** 아래에 리포지토리가 나열되어 있는지 확인합니다. 액세스가 여전히 잘못된 경우 스레드 또는 프로젝트가 보고하는 오류 메시지는 [리포지토리 액세스 오류](#repository-access-errors)를 참조하세요.

<h2 id="work-in-a-project">
  프로젝트에서 작업
</h2>

프로젝트 대화를 통해 Claude에게 작업을 제공합니다: 한 번에 하나의 작업 또는 여러 개, 그리고 업데이트 및 느슨한 생각이 나타나면서 업데이트합니다. Claude는 각 메시지를 라우팅하고 스레드가 작업을 수행하고 다시 보고합니다.

<h3 id="your-first-batch">
  첫 번째 배치
</h3>

새 프로젝트에 작업 배치를 보내기 전에 첫 번째 스레드가 원하는 방식으로 돌아오도록 설정하세요:

1. [프로젝트 지침 작성](#write-project-instructions): 대상 분기, 스레드가 자신의 작업을 확인하는 방법, 무엇이 승인이 필요한지와 같은 모든 스레드가 시작하는 간단한 설명입니다.
2. 실제 작업의 작은 부분을 하나 보내거나, Claude가 제안한 스레드 중 하나를 시작하고, 완료되면 스레드를 열어 어떻게 보고하는지 그리고 분기에서 무엇을 했는지 확인합니다. 잘못된 것을 가정했거나 필요한 것에 도달할 수 없었다면 [스레드가 묻는 대신 추측하거나 정체](#threads-guessed-or-stalled-instead-of-asking)에서 수정할 위치를 다룹니다.
3. **Project settings > General**에서 **Thread model** 및 **Thread effort**를 확인합니다. 새 프로젝트는 모든 스레드를 높은 노력으로 Opus에서 실행하며, 이는 플랜을 가장 빠르게 사용합니다. [모델 선택 및 Claude가 컨텍스트 관리하도록 하기](#choose-models-and-let-claude-manage-context)에서 대안을 다룹니다.
4. Claude에게 [스레드를 시작하기 전에 제안하고 한 번에 몇 개만 실행](#tune-how-claude-runs-a-project)하도록 요청하고, 몇 개의 스레드가 원하는 방식으로 돌아오면 이러한 제한을 제거합니다.

<h3 id="send-work-and-read-results">
  작업 보내기 및 결과 읽기
</h3>

Claude는 대화에서 보내는 각 메시지가 어디로 가는지 결정합니다:

* 빠른 질문은 보통 대화에서 답변을 받습니다.
* 새 작업은 새 스레드 또는 이미 해당 영역에서 작업 중인 스레드로 이동하고, Claude는 어느 것인지 알려줍니다. 각 새 스레드는 메시지 아래에 카드로 표시됩니다: 스레드의 제목과 상태가 있는 상자로, 클릭하여 스레드를 엽니다.
* 한 메시지의 여러 관련 없는 작업은 별도의 스레드가 됩니다.

Claude가 원하는 것과 다르게 라우팅하면 말하세요. [프로젝트 실행 방식 조정](#tune-how-claude-runs-a-project)에서 기존 스레드를 후속 작업에 재사용하거나 대신 제자리에서 답변하도록 하는 것과 같이 말할 수 있는 것들을 나열합니다.

스레드의 전체 결과는 스레드에 남아 있고, 대화에서 카드를 열어 읽습니다. 스레드가 생성한 파일도 **Overview**의 **Library** 탭에 있습니다.

때때로 Claude는 스레드를 시작하는 대신 **Suggested threads** 목록에서 스레드를 제안합니다. 제안의 화살표를 클릭하여 해당 스레드를 시작합니다. 여러 개가 나열되면 목록 아래의 버튼이 모두 시작합니다.

<h3 id="review-a-thread’s-pull-request">
  스레드의 풀 요청 검토
</h3>

스레드가 코드를 변경할 때, 다르게 말하지 않으면 이것이 수행하는 것입니다:

* **Branch**: 저장소의 기본 분기에서 시작한 새 분기에서 작동합니다.
* **Pull request**: 요청할 때 열고, 버그 수정 또는 다른 구체적인 변경을 위해 자체적으로 열 수 있습니다.
* **열린 후**: 다른 클라우드 세션에 대해 자동 수정이 켜져 있는지 여부에 관계없이 [자동 수정](/docs/ko/claude-code-on-the-web#auto-fix-pull-requests)이 켜져 있는 풀 요청을 감시합니다. CI가 실패하면 수정을 푸시하고, 검토 의견을 처리하고, 검사가 통과하고 풀 요청이 검토 준비가 되면 스레드에서 회신합니다.

대화의 스레드 카드는 다음 단계에 대한 버튼을 표시할 수 있습니다:

* **Resolve conflicts**, **Fix CI**, **Address comments**, 및 **Merge it**은 해당 지침을 메시지로 스레드에 전송하므로 스레드가 풀 요청에 반응할 때까지 기다리는 대신 직접 스레드에 메시지를 보낼 수 있습니다.
* **Review PR**은 GitHub에서 풀 요청을 엽니다.
* **Create PR**은 유휴 스레드가 분기를 푸시했지만 풀 요청을 열지 않았을 때 나타납니다. 클릭하면 스레드에 풀 요청을 열도록 지시하는 대신 해당 분기에서 직접 풀 요청을 생성합니다.

스레드가 풀 요청을 열 때를 변경하려면, 예를 들어 요청할 때만 또는 시작할 분기를 변경하려면 작업 또는 [프로젝트 지침](#write-project-instructions)에서 말하세요.

<h3 id="see-what-needs-you-in-overview">
  Overview에서 필요한 것 확인
</h3>

**Overview** 창은 프로젝트의 스레드를 추적합니다. 새 프로젝트를 처음 열 때 이미 열려 있습니다. 프로젝트 헤더의 **Overview** 버튼은 닫고 다시 열며, 스레드가 대기 중일 때 점을 표시합니다.

데스크톱 앱에서는 Claude가 대화에 게시할 때, 스레드가 오류에 도달할 때 또는 스레드가 입력이 필요할 때 데스크톱 알림을 받으므로 프로젝트를 열어 두고 찾을 필요가 없습니다. 스레드가 차례를 완료할 때마다 하나를 받거나 프로젝트에 대해 끄려면 프로젝트의 사이드바 메뉴에서 **Notifications**를 선택합니다. 이 알림은 데스크톱 전용입니다: 브라우저에서는 **Overview** 버튼의 점을 확인합니다.

창의 **Threads** 탭은 상태별로 스레드를 그룹화합니다:

| 그룹                   | 포함된 것                                                                                                          |
| :------------------- | :------------------------------------------------------------------------------------------------------------- |
| **Ready for review** | 풀 요청이 열려 있고 검토 대기 중인 스레드                                                                                       |
| **Waiting on you**   | 회신 또는 승인이 필요하거나 실패한 스레드                                                                                        |
| **Working**          | 여전히 실행 중인 스레드                                                                                                  |
| **Landing**          | 풀 요청이 승인되거나 병합 대기 중인 스레드                                                                                       |
| **Idle**             | 완료되고 아무것도 기다리지 않는 스레드                                                                                          |
| **Resolved**         | 완료로 표시된 스레드: 스레드의 메뉴에서 사용자가, 풀 요청 병합과 같은 마지막 단계를 수행한 후 Claude가, 또는 활동이 없는 일주일 후 자동으로. 동일한 메뉴에서 하나를 다시 열 수 있습니다 |

창의 다른 탭은 추가한 파일과 폴더 및 스레드가 생성한 파일을 위한 **Library**, 스레드가 열었을 때 **Pull requests**, 이 프로젝트의 [루틴](/docs/ko/routines)을 위한 **Routines**입니다.

<h3 id="open-a-thread-when-you-need-control">
  제어가 필요할 때 스레드 열기
</h3>

대화의 스레드 카드 또는 **Overview**의 행을 클릭하여 Overview 창에서 스레드의 기록을 엽니다. 거기서 다음을 수행할 수 있습니다:

* Claude가 수행한 작업을 단계별로 읽습니다.
* 스레드의 자체 메시지 상자에 작성하여 작업을 조율합니다. 거기의 메시지는 해당 스레드로 직접 이동하는 반면, 프로젝트 대화의 후속 작업은 Claude가 후속 작업을 해당 스레드와 일치시킬 때만 도달합니다.
* 스레드가 대기 중인 권한 프롬프트에 답변합니다.
* **Stop**으로 스레드를 중단합니다. 이는 스레드가 작동하는 동안 전송 버튼을 대체하거나 Esc를 눌러 중단합니다.

<h3 id="choose-models-and-let-claude-manage-context">
  모델 선택 및 Claude가 컨텍스트 관리하도록 하기
</h3>

**Project settings > General**에서 모델 및 노력을 설정합니다. 새 프로젝트는 모든 곳에서 Opus를 실행하며, 스레드에 대해 높은 [노력](/docs/ko/model-config#adjust-effort-level), 대화에 대해 낮은 노력을 합니다:

* **Thread model** 및 **Thread effort**는 스레드에 적용됩니다. 하나의 작업에 다른 모델을 사용하려면 작업에서 요청하세요. 이미 실행 중인 스레드의 경우 해당 스레드의 모델 선택기를 사용합니다.
* **Coordinator model** 및 **Coordinator effort**는 프로젝트 대화의 Claude에 적용됩니다.

프로젝트에서 컨텍스트 윈도우를 관리하지 않습니다. 스레드는 자동으로 압축되고, 대화는 최근 메시지, 최근 스레드 및 프로젝트 메모리가 아닌 전체 기록에서 작동하므로 프로젝트가 실행되는 한 계속됩니다. 절대 삭제되지 않아야 하는 모든 것을 [프로젝트 메모리](#give-a-project-standing-context)에 넣으세요. 하나의 스레드가 컨텍스트를 초과하면 [Claude가 이 차례에서 컨텍스트를 초과했습니다](#context-limit)를 표시합니다.

<h3 id="tune-how-claude-runs-a-project">
  프로젝트 실행 방식 조정
</h3>

대화에서 Claude에게 한 번에 실행할 스레드 수, 업데이트를 게시할 때, 풀 요청을 열 때를 알려줍니다. Claude가 원하지 않는 방식으로 조율하고 있으면 말하세요. 예를 들어 다음과 같이 말할 수 있습니다:

* "스레드를 제안하고 시작하기 전에 승인을 기다립니다" 또는 "확인을 요청하지 않고 지금 시작합니다"
* "한 번에 최대 2개의 스레드를 실행합니다" 또는 "동일한 영역의 후속 작업에 기존 스레드를 재사용합니다"
* "더 짧은 업데이트를 게시합니다" 또는 "무언가가 완료되거나 차단될 때만 게시합니다"
* "모든 스레드에 상태 업데이트를 제공합니다"
* "이 작업을 더 작은 모델로 수행합니다"
* "풀 요청을 열지 마세요. 계획을 본 후에 열어주세요"
* "이 저장소에서 무엇이 잘못되었는지 알려주세요. 아직 수정하지 마세요", 스레드가 되기 전에 발견 사항을 검토하려고 할 때
* "대신 여기서 답변하세요", Claude가 빠른 질문으로 의도한 것에 대해 스레드를 시작할 때

Claude는 이러한 선호도를 [프로젝트 메모리](#give-a-project-standing-context)에 자동으로 저장하고 나중 스레드에서 따릅니다. 이것들은 Claude가 지키는 지침이지 적용된 설정이 아니므로, 이런 방식으로 제공하는 스레드 제한은 하드 캡이 아닙니다. 정확하게 표현되고 처음부터 모든 스레드에 적용되기를 원할 때 프로젝트 지침에 하나를 추가합니다.

<h3 id="unblock-a-thread-waiting-on-approval">
  승인 대기 중인 스레드 차단 해제
</h3>

스레드는 스레드의 모델이 지원할 때 [자동 모드](/docs/ko/permission-modes#eliminate-prompts-with-auto-mode)에서 실행되므로 대부분의 도구 호출은 요청 없이 실행됩니다. 스레드가 승인이 필요하면 프롬프트는 해당 스레드 내부에 있고 스레드는 거기서 답변할 때까지 기다립니다. 프로젝트 대화에서 Claude에게 진행하도록 말하는 것은 도달하지 않습니다.

각 승인은 해당 프롬프트 또는 더 광범위한 옵션을 선택하면 해당 스레드의 나머지를 다룹니다. 모든 스레드가 특정 명령을 요청 없이 실행하도록 하거나 일부를 차단하려면 저장소의 `.claude/settings.json`에 [권한 규칙](/docs/ko/permissions)을 추가합니다. 스레드는 하나의 저장소가 있는 프로젝트에서만 적용합니다. [스레드가 저장소에서 선택하는 것](#what-threads-pick-up-from-your-repositories)을 참조하세요.

<h2 id="give-a-project-standing-context">
  프로젝트에 상황 맥락 제공하기
</h2>

프로젝트 메모리, 프로젝트 지침, 그리고 프로젝트의 저장소, 파일, 환경은 스레드 전체에서 맥락을 유지합니다. 각 항목을 한 번 설정하면 됩니다.

| 맥락          | 포함되는 내용                                                                                                               | 설정 방법                                                                                                              |
| :---------- | :-------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------- |
| 프로젝트 메모리    | Claude가 프로젝트에 대해 유지하는 메모(요구사항, 결정사항, 주의사항 등)로, 파일로 저장됩니다. 모든 클라우드 스레드는 시작할 때 인덱스 파일 `MEMORY.md`를 읽고, 필요할 때 다른 파일을 엽니다 | 프로젝트 대화 또는 모든 클라우드 스레드에서 Claude에게 요구사항, 결정사항, 주의사항을 기억하거나 잊도록 요청합니다. **프로젝트 설정 > 메모리**에서 파일을 읽고, 편집하고, 삭제합니다       |
| 프로젝트 지침     | 모든 새로운 스레드와 프로젝트 대화의 Claude에게 전송되는 텍스트로, 최대 16,000자입니다. [프로젝트 지침 작성하기](#write-project-instructions)에서 포함할 내용을 다룹니다    | **프로젝트 설정 > 메모리 > 프로젝트 지침**, 또는 Claude에게 대화에서 지침을 변경하도록 요청합니다                                                      |
| 저장소, 파일, 환경 | 모든 클라우드 스레드가 복제하는 저장소, 모든 스레드가 `/mnt/project-files` 아래에서 읽을 수 있는 폴더와 파일, 그리고 클라우드 환경이 실행되는 곳                          | **프로젝트 설정 > 환경**의 저장소와 환경, 또는 대화에서 Claude에게 저장소를 프로젝트에 추가하도록 요청합니다. **개요**의 **라이브러리** 탭에서 **추가**를 통해 파일과 폴더를 추가합니다 |

**프로젝트 설정 > 메모리**는 이러한 파일을 **자동 메모리** 아래에 나열합니다. Claude가 프로젝트에서 작업할 때 자동으로 작성하기 때문입니다. 이는 Claude Code가 머신에서 유지하는 [자동 메모리](/docs/ko/memory)와는 별개이며, 둘 다 `MEMORY.md` 인덱스를 사용하지만 다릅니다. 프로젝트 메모리는 또한 프로젝트의 저장소에 있는 `CLAUDE.md` 파일과도 별개입니다. 각 클라우드 스레드는 시작할 때 복제본에서 이러한 `CLAUDE.md` 파일을 읽으므로, 저장소에 대한 지침은 해당 `CLAUDE.md`에 넣고 프로젝트에 대한 메모는 프로젝트 메모리에 넣습니다.

<h3 id="write-project-instructions">
  프로젝트 지침 작성하기
</h3>

프로젝트 지침은 모든 새로운 스레드가 시작하는 기본 지침입니다. 프로젝트 헤더의 톱니바퀴 아이콘을 클릭하여 **프로젝트 설정**을 열고, **메모리 > 프로젝트 지침**으로 이동합니다. 유용한 지침은 다음을 포함합니다:

* 프로젝트의 목적
* 작업이 진행되는 위치: 어느 저장소, 어느 브랜치에서 시작할지, 풀 요청의 이름을 어떻게 지을지
* 스레드가 작업을 완료하기 전에 자신의 작업을 확인하는 방법
* 필요한 것이 누락되었을 때 할 일
* 먼저 승인이 필요한 것

예를 들어:

```text theme={null}
이 프로젝트는 payments API의 p95 지연 시간을 200ms 이하로 유지합니다: 프로파일링, 쿼리 및 캐싱 수정, 그리고 이에 따른 의존성 업그레이드를 payments-api 저장소에서 수행합니다.

- main에서 브랜치를 만들고 스레드당 하나의 드래프트 풀 요청을 엽니다.
- 작업을 완료하기 전에 `make test`와 `make lint`를 실행하고 최종 메시지에 요약 줄을 붙여넣습니다.
- 저장소, 시크릿, API, 또는 커넥터와 같이 필요한 것에 도달할 수 없으면, 첫 번째 메시지에서 정확히 무엇이 누락되었는지 말하고 멈춥니다. 대체하거나, 모의하거나, 추측하지 마세요.
- 내 승인 없이 병합하거나, 강제 푸시하거나, CI 구성을 변경하지 마세요.
```

한 저장소에 대한 규칙(예: 빌드 명령)은 해당 저장소의 `CLAUDE.md`에 속하며, 저장소가 프로젝트의 일부일 때 모든 클라우드 스레드가 시작할 때 읽습니다. 작업이 진행 중일 때 스레드를 수정하면, Claude에게 수정 사항을 기억하도록 말하세요: 이는 [프로젝트 메모리](#give-a-project-standing-context)로 이동하고 이후 클라우드 스레드는 이를 가지고 시작합니다.

<h3 id="decide-which-repositories-to-add">
  추가할 저장소 결정하기
</h3>

프로젝트에 추가하는 저장소는 코드, `CLAUDE.md`, 스킬을 포함한 모든 것이 모든 클라우드 스레드에 포함됩니다. 추가하지 않은 저장소도 여전히 접근 가능합니다: 클라우드 스레드는 작업에 필요할 때 자신에게 저장소를 추가할 수 있습니다. 대부분의 프로젝트는 둘 다 사용합니다:

* **프로젝트에 추가합니다**, **새 프로젝트** 대화에서, **프로젝트 설정 > 환경**에서, 또는 대화에서 Claude에게 프로젝트에 추가하도록 요청합니다. 그 이후 모든 클라우드 스레드는 작업이 이를 건드리든 아니든 이를 복제하고 `CLAUDE.md`와 스킬을 로드하여 시작합니다. 한 저장소에서 여러 저장소로 이동하면 각 저장소의 `.claude/settings.json`에서 스레드가 가져오는 것도 변경됩니다; [저장소에서 스레드가 가져오는 것](#what-threads-pick-up-from-your-repositories)을 참조하세요.
* **이를 제외하고 스레드가 필요할 때 추가하도록 합니다.** 프로젝트가 없는 저장소가 필요한 작업을 가진 클라우드 스레드는 자신에게 저장소를 추가할 수 있으며, 스레드의 메모는 이 스레드에만 추가되었음을 나타냅니다. 복제는 작업 중간에 발생하므로 해당 저장소의 `CLAUDE.md`와 스킬은 스레드가 시작할 때 없었습니다. 다음 스레드는 다시 이를 없이 시작합니다. 스레드가 추가하는 저장소는 프로젝트 저장소와 동일한 [전제조건](#check-the-prerequisites)이 필요합니다: 설치된 Claude GitHub App과 GitHub 계정의 푸시 액세스.

프로젝트는 저장소가 전혀 필요하지 않을 수 있습니다. 클라우드 스레드는 여전히 조사하고, 문서를 작성하고, 자신의 샌드박스에서 코드를 작성하고 실행할 수 있으며, **라이브러리** 탭에 파일을 전달합니다. 거기의 모든 클라우드 스레드는 작업이 필요할 때 자신에게 저장소를 추가할 수도 있습니다.

프로젝트에 저장소가 있으면, Claude는 프로젝트가 이미 사용하는 GitHub 소유자의 저장소만 추가할 수 있습니다. 프로젝트에 추가하든 스레드가 자신에게 추가하든 상관없습니다. 다른 소유자의 저장소를 가져오려면 **프로젝트 설정 > 환경**에서 직접 프로젝트에 추가하세요.

서버, 웹, 모바일, 데스크톱 코드가 있는 기능과 같이 많은 저장소에 걸친 프로젝트의 경우, 거의 모든 작업이 건드리는 저장소 1\~2개를 추가하고 [프로젝트 지침](#write-project-instructions)에서 나머지 코드가 어디에 있는지 이름을 지으세요. 그러면 클라우드 스레드는 작게 시작하고 필요한 작업에만 다른 저장소를 가져옵니다.

<h3 id="what-threads-pick-up-from-your-repositories">
  저장소에서 스레드가 가져오는 것
</h3>

각 클라우드 스레드는 프로젝트의 모든 저장소를 복제하고 모든 저장소에서 `CLAUDE.md`와 스킬을 로드합니다. 권한 규칙, 훅, `env`는 스레드가 시작하는 디렉토리의 `.claude/settings.json`에서만 옵니다: 프로젝트가 하나일 때는 저장소 내부, 여러 개일 때는 복제본 위에서, 저장소의 파일이 읽히지 않는 곳입니다.

| 각 저장소에서                                       | 한 저장소                                                                                                      | 여러 저장소                                       |
| :-------------------------------------------- | :--------------------------------------------------------------------------------------------------------- | :------------------------------------------- |
| `CLAUDE.md`                                   | 스레드가 시작할 때 로드됨                                                                                             | 스레드가 시작할 때 모든 저장소에서 로드됨                      |
| `.claude/` 아래의 스킬, 에이전트, 명령                   | 로드됨                                                                                                        | 모든 저장소에서 로드됨                                 |
| `.claude/settings.json`에서 활성화된 플러그인           | 로드되지 않음. 대신 **프로젝트 설정 > 플러그인**에서 플러그인을 추가하세요                                                               | 로드되지 않음. 대신 **프로젝트 설정 > 플러그인**에서 플러그인을 추가하세요 |
| `.claude/settings.json`에서 정의된 권한 규칙, 훅, `env` | 스레드에 적용됩니다. 단, [클라우드 세션이 인정하지 않는](/docs/ko/cloud-environments#what-carries-over-from-your-setup) `env` 키는 제외됩니다 | 적용되지 않음                                      |

여러 저장소가 있는 프로젝트에서, 각 복제본은 스레드에 [추가 디렉토리](/docs/ko/memory#load-from-additional-directories)로 첨부되며 `CLAUDE.md` 로드가 켜져 있습니다. 이것이 스레드가 위에서 시작하더라도 모든 저장소의 `CLAUDE.md`와 스킬이 시작할 때 로드되는 이유입니다. 이러한 프로젝트에서는 프로젝트 지침에 상시 규칙을 넣고 [클라우드 환경](#choose-an-environment-for-threads)을 통해 스레드에 환경 변수를 제공하세요.

<h3 id="choose-an-environment-for-threads">
  스레드의 환경 선택하기
</h3>

모든 새로운 클라우드 스레드는 프로젝트의 [클라우드 환경](/docs/ko/cloud-environments)에서 시작합니다. 환경은 스레드가 도달할 수 있는 도메인, 스레드가 가진 환경 변수, 요청에 추가되는 API 자격증명, 그리고 Claude가 시작하기 전에 설정 스크립트가 설치하는 것을 설정합니다. 클라우드 스레드는 **프로젝트 설정 > 환경**에서 선택할 때까지 기본 Anthropic 호스팅 환경을 사용합니다.

클라우드 스레드가 내부 API 또는 프라이빗 패키지 레지스트리에 도달해야 하거나 머신이 일반적으로 보유한 토큰이 필요하면, 프로젝트가 아닌 환경을 변경하세요: [네트워크 액세스](/docs/ko/cloud-environments#network-access), [API 자격증명 추가](/docs/ko/cloud-environments#add-api-credentials), [설정 스크립트](/docs/ko/cloud-environments#setup-scripts)를 참조하세요.

<h3 id="get-skills-plugins-connectors-and-tools-into-threads">
  스킬, 플러그인, 커넥터, 도구를 스레드에 가져오기
</h3>

클라우드 스레드는 머신에만 설치된 스킬, MCP 서버, 플러그인, 도구가 없습니다. [Remote Control](/docs/ko/remote-control)을 통해 Claude가 머신에서 실행하는 스레드는 거기에 설치된 것을 사용합니다. 이들 각각을 클라우드 스레드에서 사용 가능하게 하려면:

* 스킬, 서브에이전트, 명령: 프로젝트에 추가한 저장소에 커밋합니다. 예를 들어 `.claude/skills/<skill-name>/SKILL.md`의 스킬입니다. 각 클라우드 스레드는 프로젝트의 모든 저장소를 복제하고 각 저장소에서 `.claude/skills/`, `.claude/agents/`, `.claude/commands/`를 로드하므로, 한 저장소에 커밋된 스킬은 모든 클라우드 스레드에서 사용 가능합니다. 클라우드 스레드는 또한 claude.ai 계정에 대해 활성화한 스킬을 로드합니다.
* 플러그인: **프로젝트 설정 > 플러그인**에서 추가합니다; 각 새로운 클라우드 스레드에 로드됩니다. 저장소가 `.claude/settings.json`에서 선언하는 플러그인은 클라우드 스레드이기 때문에 [클라우드 스레드에 로드되지 않습니다](/docs/ko/cloud-environments#what-carries-over-from-your-setup).
* MCP 서버: 클라우드 스레드는 claude.ai 계정의 커넥터에서 MCP 도구를 가져옵니다. 커넥터는 [claude.ai/customize/connectors](https://claude.ai/customize/connectors)에서 한 번 연결하거나 **프로젝트 설정 > 환경**의 **커넥터 관리** 링크를 통해 연결하는 MCP 서버입니다. 모든 클라우드 스레드는 프로젝트별 설정 없이 모두 사용할 수 있습니다. 프로젝트 대화 자체는 커넥터가 없으므로 커넥터가 필요한 작업을 클라우드 스레드의 작업으로 보냅니다. 한 저장소가 있는 프로젝트에서, 클라우드 스레드는 또한 해당 저장소의 [`.mcp.json`](/docs/ko/cloud-environments#what-carries-over-from-your-setup)에서 MCP 서버를 로드합니다. [커넥터가 Claude Code에 도달하는 방법](/docs/ko/mcp#how-connectors-reach-claude-code)은 클라우드 세션의 규칙과 커넥터를 끄는 설정을 나열합니다.
* 명령줄 도구 및 패키지: 환경의 [설정 스크립트](/docs/ko/cloud-environments#setup-scripts)에 설치합니다.

실행 중인 클라우드 스레드가 claude.ai/code에서 가진 커넥터를 보려면, 스레드를 열고 메시지 상자 옆의 **+** 메뉴에서 **커넥터**를 선택합니다. 거기서 커넥터를 끄면 해당 스레드에서 제거되고 계정 기본값으로 저장되므로, 다시 켤 때까지 새로운 클라우드 스레드와 claude.ai 채팅이 이를 없이 시작합니다. 클라우드 스레드는 다음 메시지를 보낸 후 추가하거나 다시 연결한 커넥터를 가져옵니다.

<h2 id="project-settings-reference">
  프로젝트 설정 참조
</h2>

프로젝트 설정을 `settings.json`이 아닌 claude.ai/code 또는 데스크톱 앱에서 변경합니다. 프로젝트의 사이드바 메뉴의 **Settings**에서 또는 프로젝트 헤더의 기어 아이콘에서 **Project settings**를 엽니다.

설정은 변경할 때 저장됩니다. 목표 또는 지침과 같이 편집 중인 텍스트 필드는 떠날 때까지 **Save changes** 및 **Discard**를 표시합니다. **Project settings**의 지침, 저장소, 플러그인 및 환경 변경은 이미 실행 중인 스레드가 아닌 새 스레드에 도달합니다.

| 설정                  | 섹션          | 제어하는 것                                                                                  |
| :------------------ | :---------- | :-------------------------------------------------------------------------------------- |
| 이름, 아이콘 및 목표        | General     | 사이드바의 프로젝트 이름 및 아이콘, 그리고 한 줄 목표                                                         |
| Coordinator 모델 및 노력 | General     | 프로젝트 대화의 Claude에 대한 모델 및 [노력 수준](/docs/ko/model-config#adjust-effort-level)                  |
| Thread 모델 및 노력      | General     | 스레드에 대한 모델 및 노력 수준                                                                      |
| 프로젝트 지침             | Memory      | [기본 규칙](#give-a-project-standing-context) 모든 새 스레드가 수신                                  |
| 프로젝트 저장소            | Environment | 새 스레드가 복제하는 저장소                                                                         |
| 클라우드 환경             | Environment | 새 스레드가 실행하는 [클라우드 환경](#choose-an-environment-for-threads)                               |
| 커넥터                 | Environment | claude.ai 커넥터를 관리하는 링크 스레드가 가져옴                                                         |
| 플러그인                | Plugins     | 각 새 스레드에 로드되는 플러그인                                                                      |
| 사용                  | Usage       | 스레드 및 모델별 [토큰 사용](#usage-and-cost)                                                      |
| Memory              | Memory      | 프로젝트의 [메모리 파일](#give-a-project-standing-context)                                        |
| Claude 다시 시작        | General     | Claude가 [거기서 응답을 중지](#claude-hasnt-responded)할 때 프로젝트 대화를 다시 시작합니다                      |
| 일시 중지, 보관, 삭제       | General     | 프로젝트를 중지, 숨기거나 제거합니다. [프로젝트 일시 중지, 보관 또는 삭제](#pause-archive-or-delete-a-project)를 참조하세요 |

<h3 id="pause-archive-or-delete-a-project">
  프로젝트 일시 중지, 보관 또는 삭제
</h3>

세 가지 제어 모두 **Project settings > General**의 하단에 있습니다:

* **Pause**: 모든 것을 한 번에 중지합니다. 모든 실행 중인 스레드 및 대화가 중단되고, 새 스레드가 시작되지 않으며, 루틴이 실행되지 않고, 프로젝트는 다시 시작할 때까지 메시지를 수락하지 않습니다. 동일한 위치 또는 프로젝트의 메시지 상자 위의 배너에서 **Resume**을 클릭합니다. 일시 중지된 스레드는 그 후 메시지를 보낼 때 계속됩니다.
* **Archive**: 사이드바에서 프로젝트를 숨기고 스레드를 보관합니다. 이는 실행 중이거나 풀 요청을 감시하는 모든 스레드를 중지합니다. 프로젝트가 보관되는 동안 프로젝트의 루틴은 실행되지 않습니다. 프로젝트를 다시 가져오려면 Projects 페이지에서 열고 **Unarchive**를 클릭합니다. 스레드는 세션 목록에서 개별적으로 보관 해제할 때까지 보관된 상태로 유지됩니다.
* **Delete**: 프로젝트, 스레드, 메모리 및 파일을 영구적으로 제거하고 프로젝트의 루틴을 끕니다. 이것은 실행 취소할 수 없습니다. 스레드가 GitHub에 푸시한 분기 및 풀 요청은 영향을 받지 않습니다.

<h2 id="usage-and-cost">
  사용량 및 비용
</h2>

프로젝트 사용량은 다른 Claude Code 세션과 동일한 [플랜 한도](/docs/ko/errors#youve-hit-your-session-limit)에 포함되며, 프로젝트는 자체적으로 해당 한도를 초과할 수 없습니다.

플랜 한도에 도달한 스레드는 대기했다가 한도가 초기화되면 자동으로 계속 진행되므로, 실행 중인 작업은 사용자의 메시지 없이 다음 사용 기간에 자동으로 시작됩니다. [스레드가 사용량 한도에 도달함](#usage-limit-reached)에서는 표시되는 내용, 중지 방법, 그리고 대기하지 않는 한 가지 경우를 다룹니다.

작업이 플랜 한도를 초과하는 경우는 계정에 [사용량 크레딧](/docs/ko/costs#add-usage-credits-to-your-subscription)을 활성화한 경우에만 가능합니다. 스레드는 사용자를 위해 이를 활성화할 수 없습니다.

<h3 id="what-draws-on-your-plan">
  플랜을 사용하는 항목
</h3>

프로젝트는 단일 세션보다 한도를 더 빠르게 사용하며, 특히 Pro 플랜에서는 프로젝트를 실행하는 날에 한도에 더 빨리 도달할 것으로 예상해야 합니다. 다음은 플랜을 사용하는 프로젝트의 부분입니다:

* **실행 중인 스레드**: 각각은 전체 세션이며, 여러 개가 동시에 실행될 수 있습니다. 고정된 개수는 없으며, Claude는 작업에 필요한 만큼 많은 스레드를 시작하고, [요청한](#tune-how-claude-runs-a-project) 한도는 상한이 아닌 선호도입니다. 적용되는 한도는 프로젝트 전체에서 하루에 200개의 새로운 스레드입니다.
* **대화**: Claude는 스레드가 보고하는 내용을 읽고 다음에 할 일을 결정하기 위해 자체 토큰을 사용합니다.
* **pull request를 감시하는 스레드**: 유휴 스레드는 CI가 실패하거나 pull request에 검토 의견이 도착하면 깨어나서 플랜을 다시 사용합니다. 이를 중지하려면 스레드에서 pull request 감시를 중지하도록 요청하세요.

실행 중인 스레드가 없고, 감시 중인 pull request가 없으며, 새로운 메시지가 없는 프로젝트는 유휴 상태일 때 플랜을 사용하지 않으며, 보관된 프로젝트도 마찬가지입니다.

<h3 id="see-and-reduce-a-project’s-usage">
  프로젝트의 사용량 확인 및 감소
</h3>

**프로젝트 설정**에서 **사용량**을 열어 스레드별 및 모델별 토큰 사용량과 프로젝트 대화에 사용된 양을 확인하세요. 사용량을 줄이려면:

* [캐시 수명](/docs/ko/prompt-caching#cache-lifetime)보다 오래 유휴 상태인 스레드로 라우팅된 후속 작업(Pro 및 Max에서는 플랜 한도 내에서 1시간)은 작업을 수행하기 전에 해당 스레드의 전체 대화를 다시 읽습니다. 새로운 작업의 경우, Claude에게 새로운 스레드를 시작하도록 요청하면 큰 이전 스레드를 복구하는 것보다 적은 토큰을 사용할 수 있습니다.
* 가장 큰 모델이 필요하지 않은 작업의 경우, 스레드, 대화 또는 둘 다에 대해 [더 작은 모델 또는 더 낮은 노력 수준을 선택](#choose-models-and-let-claude-manage-context)하세요.
* 프로젝트 대화에서 Claude에게 한 번에 더 적은 스레드를 실행하거나, 스레드를 시작하는 대신 작은 질문에 직접 답하도록 요청하세요.

<h2 id="how-projects-relate-to-other-claude-code-features">
  프로젝트가 다른 Claude Code 기능과 어떻게 연결되는지
</h2>

여러 Claude Code 기능을 통해 한 번에 둘 이상의 세션이 작동할 수 있으므로, 병렬로 작업을 실행하는 것 자체가 프로젝트의 목적은 아닙니다. 프로젝트에서는 Claude가 세션을 시작하고 추적하며, 각 세션은 동일한 지시사항에서 시작합니다. 각 인접 기능이 프로젝트와 어떻게 연결되는지는 다음과 같습니다:

* **Claude Tag**: [Claude Tag](https://claude.com/docs/claude-tag/overview)는 Team 및 Enterprise 플랜의 팀 Slack 채널에 있는 Claude입니다. 채널의 누구나 작업을 할당할 수 있고, 채널의 모든 사람이 이를 보고 조정할 수 있으며, 관리자가 해당 채널을 위해 설정한 연결을 사용합니다. 프로젝트는 개인 전용입니다: 사용자만 작업을 할당하거나 스레드를 볼 수 있으며, 자신의 GitHub 액세스 및 커넥터를 사용하고, Pro 및 Max에서 사용 가능합니다. [Claude Tag가 Cowork 및 Claude Code와 어떻게 다른지](https://claude.com/docs/claude-tag/concepts/how-it-works#how-claude-tag-differs-from-cowork-and-claude-code)에서 나란히 비교한 내용을 확인할 수 있습니다.
* **클라우드 세션**: 모든 스레드는 Claude에게 머신에서 실행하도록 요청하지 않는 한 [클라우드 세션](/docs/ko/claude-code-on-the-web)입니다. 어느 쪽이든 Claude가 세션을 시작하고 추적합니다. 직접 시작한 클라우드 세션은 [**프로젝트로 계속하기** 또는 **프로젝트로 이동**](#start-from-an-existing-cloud-session)을 통해 프로젝트가 되거나 프로젝트에 피드될 수 있습니다.
* **루틴**: 프로젝트에서 예약된 작업을 요청하면 Claude는 해당 프로젝트의 스레드로 실행되고 **루틴** 탭에 표시되는 [루틴](/docs/ko/routines)을 생성합니다. 프로젝트 외부에서 생성한 루틴은 계속 독립적으로 작동합니다.
* **로컬 세션 및 에이전트 뷰**: 터미널, IDE 또는 데스크톱 앱의 로컬 환경에서 직접 시작한 세션은 프로젝트에 추가할 수 없습니다. 프로젝트는 [원격 제어](/docs/ko/remote-control)를 통해 스레드를 실행하여 머신에만 도달합니다. [에이전트 뷰](/docs/ko/agent-view)는 직접 시작한 여러 로컬 세션을 추적하기 위한 화면이며, 조정자가 없습니다.
* **Worktrees**: [worktree](/docs/ko/worktrees)는 각 로컬 세션에 리포지토리의 자체 작업 복사본을 제공하므로 머신의 병렬 세션이 서로 덮어쓰지 않습니다. 클라우드 스레드는 이를 필요로 하지 않습니다: 각 스레드는 리포지토리를 자체 클라우드 샌드박스에 복제하고 자체 브랜치에서 작동합니다.
* **에이전트 팀**: [에이전트 팀](/docs/ko/agent-teams)은 머신 또는 클라우드 세션 내에서 단일 작업을 위해 팀원 세션을 시작하고 해당 작업으로 끝나는 하나의 세션입니다.
* **claude.ai 채팅 및 Cowork의 프로젝트**: 스레드나 조정자 없이 대화 및 참조 파일을 그룹화하는 [이전 프로젝트 경험](https://support.claude.com/en/articles/9517075-what-are-projects)입니다. 이러한 프로젝트는 재설계된 경험이 도달할 때까지 현재대로 계속 작동합니다.

[에이전트를 병렬로 실행](/docs/ko/agents)에서 이러한 옵션을 나란히 비교합니다.

<h2 id="limitations">
  제한 사항
</h2>

* 프로젝트는 claude.ai/code, 데스크톱 앱 및 Claude 모바일 앱에서 사용 가능하며, 터미널 CLI 또는 Amazon Bedrock, Google Cloud의 Agent Platform 또는 Microsoft Foundry를 통해서는 사용할 수 없습니다. CLI의 [`claude project`](/docs/ko/cli-reference) 명령은 디렉토리에 대한 로컬 Claude Code 상태를 관리하며 관련이 없습니다.
* 프로젝트 스레드는 [클라우드 세션](/docs/ko/claude-code-on-the-web)이거나, [Remote Control](/docs/ko/remote-control)을 통한 자신의 머신의 세션이며, 두 경우 모두 Anthropic이 모델 제공자입니다. [보안](/docs/ko/security) 및 [데이터 사용](/docs/ko/data-usage)은 클라우드 세션이 어떻게 격리되고 무엇이 유지되는지를 다루며, [연결 및 보안](/docs/ko/remote-control#connection-and-security)은 머신의 스레드가 어떻게 연결되고 무엇이 저장되는지를 다룹니다.
* 자신의 머신에서 직접 시작한 세션을 프로젝트에 추가할 수 없습니다. 프로젝트가 머신에서 스레드를 실행하도록 하려면, [Remote Control](/docs/ko/remote-control#requirements)을 통해 작업해야 할 폴더를 연결합니다: Claude 데스크톱 앱의 **설정 > Claude Code**에서 Remote Control을 켜거나, 폴더에서 `claude remote-control`을 실행하고 실행 상태로 유지합니다. 해당 머신에는 Claude Code v2.1.280 이상이 필요합니다. 또한 claude.ai 설정에서 **신뢰할 수 있는 기기 필요**가 켜져 있으면 프로젝트가 머신에서 스레드를 실행할 수 없습니다.
* 클라우드 스레드의 샌드박스는 차례 사이에 일시 중지되고 스레드가 계속될 때 다시 시작됩니다. 샌드박스를 다시 시작할 수 없으면 스레드는 새 복제에서 계속되므로 커밋되지 않은 변경 사항이 손실될 수 있습니다. 긴 작업에서 Claude에게 진행 중인 작업을 커밋하고 푸시하도록 요청합니다.
* 프로젝트는 한 사용자에게 속합니다. 프로젝트 또는 스레드를 다른 사용자와 공유할 수 없으며, 스레드 기록에는 다른 클라우드 세션이 가진 공유 옵션이 없습니다. 베타 중에는 프로젝트에 대한 조직 수준 제어가 없습니다.
* 스레드는 시작한 하나의 프로젝트에 속합니다. 스레드를 다른 프로젝트로 이동하거나 복사할 수 없으며, 독립적으로 이동할 수 없습니다. [**Move to project**](#start-from-an-existing-cloud-session)는 다른 방향으로만 이동합니다: 클라우드 세션의 작업을 프로젝트로 가져옵니다.

<h2 id="troubleshooting">
  문제 해결
</h2>

**새 프로젝트** 대화상자의 GitHub 설정 프롬프트에 대해서는 [GitHub 액세스 설정](#set-up-github-access)을 참조하십시오.

<h3 id="a-thread-looks-stuck">
  스레드가 멈춘 것처럼 보임
</h3>

Claude는 스레드가 수행하는 각 단계를 게시하지 않으므로, 프로젝트 대화에서 실행 중이지만 새 메시지가 없는 것으로 표시되는 스레드는 일반적으로 여전히 작동 중입니다. 새 클라우드 스레드는 Claude가 시작하기 전에 [클라우드 환경](/docs/ko/cloud-environments)을 프로비저닝하므로, 첫 번째 업데이트에는 시간이 걸립니다. 스레드를 열어 트랜스크립트를 읽으십시오. 스레드가 권한 프롬프트를 기다리고 있으면 거기서 답변하십시오.

<h3 id="threads-guessed-or-stalled-instead-of-asking">
  스레드가 묻지 않고 추측하거나 정체됨
</h3>

여러 스레드가 잘못된 것을 가정하거나, 누락된 액세스를 해결하거나, "차단됨"으로 중지된 경우, 원인은 일반적으로 각 작업의 문제가 아니라 프로젝트 설정의 동일한 간격입니다. 무엇을 수정하기 전에 어떤 스레드가 건전한지 정렬하십시오:

1. 대화에서 Claude에게 묻기: "모든 열린 스레드에 대해, 당신에게 무엇을 하도록 요청했는지, 무엇을 가정했거나 도달할 수 없었는지, 무엇을 기다리고 있는지 나열하십시오." Claude는 각 스레드를 읽고 대화에서 답변합니다.
2. 잘못된 가정에서 시작된 스레드의 경우, **개요**에서 스레드를 열고 메뉴에서 해결됨으로 표시하거나, 메시지 상자에서 대신 수행할 작업을 알려주십시오. 해당 분기와 모든 풀 요청은 삭제할 때까지 GitHub에 남아 있습니다.
3. [프로젝트 지침](#give-a-project-standing-context) 또는 [환경](#choose-an-environment-for-threads)에서 간격을 한 번 수정한 후, 나머지 작업을 새 스레드로 다시 보내기 전에 한 스레드를 보내십시오.

<h3 id="claude-hasnt-responded">
  Claude가 응답하지 않음
</h3>

프로젝트 대화는 Claude가 실행 중이지만 해당 응답이 프로젝트에 도달하지 않을 때 "Claude가 응답하지 않음" 배너를 표시합니다. 배너에서 **Claude 다시 시작**을 클릭하거나, **프로젝트 설정 > 일반**으로 이동하여 **Claude 다시 시작** 행에서 **다시 시작**을 클릭하십시오. Claude는 대화에 다시 연결됩니다. 작성 중이던 모든 응답은 손실되며, 스레드는 영향을 받지 않습니다.

<h3 id="repository-access-errors">
  저장소 액세스 오류
</h3>

세 가지 메시지는 스레드 또는 프로젝트가 해당 저장소 중 하나에 도달할 수 없음을 의미합니다. 프로젝트의 클라우드 스레드는 다른 클라우드 세션이 동일한 저장소를 문제 없이 복제하는 경우에도 [GitHub 필수 조건](#check-the-prerequisites)이 필요합니다.

* **"세션을 시작할 수 없음 — Claude가 이 프로젝트의 저장소에 대한 GitHub 액세스 권한이 없음"**, 스레드가 시작되기 전에 보고됨. Claude GitHub 앱이 해당 저장소에 설치되지 않았거나, 일시 중단되었거나, 연결한 GitHub 계정에 연결되지 않았을 때입니다.
* **"저장소에 액세스할 수 없음"**, 스레드가 복제에 실패할 때 보고됨: GitHub가 복제를 거부했거나, 저장소를 프로젝트가 가진 이름으로 찾을 수 없거나, 스레드가 시작하도록 요청받은 분기가 존재하지 않습니다.
* **"Claude가 저장소에 액세스할 수 없음"**, **새 프로젝트** 대화상자 또는 **프로젝트 설정**에서 저장소를 저장할 때 표시됩니다. 메시지는 설치 링크와 다시 연결 링크로 계속됩니다. Claude GitHub 앱이 해당 저장소에 없으면 설치 링크를 사용하고, 있으면 다시 연결 링크를 사용하십시오. GitHub 앱은 GitHub에 설치될 수 있지만 Claude에 연결한 계정에 연결되지 않을 수 있기 때문입니다. 메시지에서 GitHub 앱이 일시 중단되었거나 이 저장소를 포함하지 않는다고 하면, 해당 링크를 따라 GitHub에서 수정하십시오.

이들을 수정하려면 메시지가 제공하는 버튼(예: **GitHub 앱 설치** 또는 **GitHub에서 저장소 선택**)을 클릭한 후 **다시 확인**을 클릭하십시오. 블록이 GitHub 조직 측에 있는 경우(예: 앱을 승인하지 않은 소유자 또는 Claude를 제외하는 IP 허용 목록), 메시지는 대신 **수정 방법 보기** 링크를 표시합니다. 버튼이 없으면 [GitHub 액세스 설정](#set-up-github-access)을 따르고 다시 시도하려면 다른 메시지를 보내십시오.

<h3 id="usage-limit-reached">
  스레드가 사용 한도에 도달함
</h3>

스레드 또는 프로젝트 대화가 계획의 5시간 또는 주간 한도에 도달하면, 자동으로 재시도를 계속하고 한도가 재설정될 때 계속됩니다. 기다리는 동안 스레드는 **서비스가 바쁨**을 표시하며 "Claude가 여전히 재시도 중이며 자동으로 계속됩니다."라고 표시됩니다. 작업이 계속되려면 아무것도 할 필요가 없습니다. 다음 사용 기간을 사용하지 않으려면 스레드에서 **중지**를 클릭하거나, [프로젝트를 일시 중지](#pause-archive-or-delete-a-project)하여 모든 스레드를 보류하십시오. 루틴이 시작한 스레드는 기다리지 않습니다: 해당 차례는 한도 오류로 중지되며, 한도가 재설정된 후 메시지를 보냅니다.

[사용 한도 오류](/docs/ko/errors#youve-hit-your-session-limit)는 한도와 재설정 시기를 설명합니다.

<h3 id="additional-usage-credits-are-required">
  추가 사용 크레딧이 필요함
</h3>

스레드 또는 프로젝트 대화가 계획이 사용 크레딧으로만 포함하는 요청(예: 계획이 포함하지 않는 모델 또는 컨텍스트 크기에 대한 요청)을 했으며, 사용 크레딧이 계정에 대해 켜져 있지 않습니다. [구독에 사용 크레딧 추가](/docs/ko/costs#add-usage-credits-to-your-subscription)는 각 계획에서 누가 켜거나 구매할 수 있는지를 다룹니다. 크레딧을 사용할 수 있게 되면 다시 시도하려면 다른 메시지를 보내십시오.

<h3 id="context-limit">
  기타 메시지
</h3>

이 메시지들은 자신의 원인을 명시합니다. 표는 각각에 대한 다음 단계를 제공합니다.

| 메시지                                                         | 수행할 작업                                                                                                                           |
| :---------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------- |
| "저장소에 연결할 수 없음"과 함께 "Claude가 저장소를 가져오기 위해 GitHub에 도달할 수 없음" | 잠시 기다린 후 다시 시도하려면 다른 메시지를 보내십시오                                                                                                  |
| "저장소에 연결할 수 없음"과 함께 "Claude가 저장소 또는 환경에 액세스할 수 없음"          | GitHub 계정은 저장소에 대한 푸시 액세스가 필요하며, 환경은 여전히 존재해야 합니다. **프로젝트 설정 > 환경**에서 둘 다 확인한 후 다시 시도하십시오                                        |
| "설정 제안을 표시할 수 없음"                                           | 열려 있는 앱이 Claude가 보낸 **설정 권장 사항**보다 오래되었습니다. 페이지를 새로 고치거나 데스크톱 앱을 다시 시작하거나, Claude에게 설정을 다시 제안하도록 요청하십시오                          |
| "프로젝트의 환경이 제거됨"                                             | **프로젝트 설정 > 환경**에서 다른 환경을 선택하십시오. 변경 사항은 새 스레드에 적용됩니다                                                                            |
| "설정 스크립트 실패"                                                | 오류에서 **설정 스크립트 편집**을 클릭하고, 환경에서 스크립트를 수정한 후, 다른 메시지를 보내십시오. [설정 스크립트 실패](/docs/ko/web-quickstart#setup-script-failed)는 일반적인 원인을 나열합니다 |
| "Claude가 이 차례에 컨텍스트를 모두 사용함"                                | 스레드가 컨텍스트 윈도우를 채웠습니다. 메시지에서 스레드가 새 세션에서 계속된다고 하면, 자동으로 계속됩니다. 그렇지 않으면 프로젝트 대화에서 Claude에게 남은 작업에 대해 새 스레드를 시작하도록 요청하십시오           |
| "차례 한도에 도달"                                                 | 스레드가 [`CLAUDE_CODE_MAX_TURNS`](/docs/ko/env-vars)가 설정한 에이전트 차례의 상한에 도달했습니다. 다시 시도하려면 다른 메시지를 보내거나, 설정된 위치에서 해당 변수를 높이거나 제거하십시오        |

<h2 id="related-resources">
