# ultrareview로 버그 찾기

> /code-review ultra를 사용하여 클라우드에서 심층적인 다중 에이전트 코드 리뷰를 실행하여 병합 전에 버그를 찾고 검증합니다.

<Note>
  Ultrareview는 연구 미리보기 기능입니다. 기능, 가격 책정 및 가용성은 피드백에 따라 변경될 수 있습니다. 명령어는 `/code-review ultra`입니다. Ultrareview를 사용할 수 있는 계정에서는 `/ultrareview`가 별칭입니다.
</Note>

Ultrareview는 [클라우드 세션](/docs/ko/claude-code-on-the-web)으로 Anthropic의 인프라에서 실행되는 심층 코드 리뷰입니다. `/code-review ultra`를 실행하면 Claude Code는 클라우드 샌드박스에서 리뷰어 에이전트 플릿을 시작하여 브랜치 또는 풀 요청의 버그를 찾습니다.

로컬 `/code-review`와 비교하여 ultrareview는 다음을 제공합니다:

* **더 높은 신호**: 보고된 모든 발견 사항이 독립적으로 재현되고 검증되므로 결과는 스타일 제안보다는 실제 버그에 초점을 맞춥니다
* **더 광범위한 범위**: 더 큰 리뷰어 에이전트 플릿이 변경 사항을 병렬로 탐색하므로 로컬 리뷰에서 놓칠 수 있는 문제를 표면화합니다
* **로컬 리소스 사용 없음**: 리뷰가 클라우드 샌드박스에서 완전히 실행되므로 실행 중에 터미널이 다른 작업을 위해 자유로워집니다

Ultrareview는 Anthropic의 인프라에서 클라우드 세션으로 실행되기 때문에 claude.ai 계정으로 인증이 필요합니다. API 키만으로 로그인한 경우 `/login`을 실행하고 먼저 claude.ai로 인증하세요. Ultrareview는 Amazon Bedrock, Google Cloud의 Agent Platform 또는 Microsoft Foundry와 함께 Claude Code를 사용할 때 사용할 수 없으며, Zero Data Retention을 활성화한 조직에서도 사용할 수 없습니다. Ultrareview를 사용할 수 없는 경우 `/code-review ultra`는 대신 세션에서 로컬 리뷰를 실행합니다.

<h2 id="run-ultrareview-from-the-cli">
  CLI에서 ultrareview 실행
</h2>

모든 git 저장소에서 리뷰를 시작합니다:

```text theme={null}
/code-review ultra
```

인수 없이 ultrareview는 현재 브랜치와 기본 브랜치 간의 차이를 검토하며, 커밋되지 않은 변경 사항과 스테이징된 변경 사항을 포함합니다. `.env` 및 `*.tfvars` 파일과 같이 자격 증명 또는 키처럼 명명된 파일의 커밋되지 않은 변경 사항의 경우 Claude Code는 [로컬 저장소를 클라우드 세션에 업로드하기](/docs/ko/claude-code-on-the-web#send-local-repositories-without-github)에 대한 규칙을 따릅니다.

브랜치 리뷰의 경우 Claude Code는 저장소 상태를 번들로 묶고 클라우드 샌드박스에 업로드합니다. [풀 요청을 검토](#review-a-pull-request)할 때 Claude Code는 머신에서 아무것도 업로드하지 않습니다.

시작하기 전에 Claude Code는 리뷰 범위, 남은 무료 실행 횟수 및 예상 비용이 포함된 확인 대화를 표시합니다. 브랜치 리뷰의 경우 범위에는 파일 및 라인 수가 포함됩니다. 확인한 후 리뷰는 백그라운드에서 계속되며 세션을 계속 사용할 수 있습니다.

명령은 `/code-review ultra`로 호출할 때만 실행됩니다. Claude는 자동으로 ultrareview를 시작하지 않습니다.

<h3 id="review-against-a-different-base">
  다른 기본에 대해 검토
</h3>

기본 브랜치 이외의 기본에 대해 비교하려면 브랜치 이름을 전달합니다. 이 예제는 현재 브랜치를 `develop` 대신에 검토합니다:

```text theme={null}
/code-review ultra develop
```

기본 브랜치는 로컬 클론에 존재할 필요가 없습니다. Claude Code는 `origin`에서 가져옵니다. 이름에 오타가 있으면 Claude Code는 오류에서 가장 가까운 브랜치 이름을 제안합니다.

커밋 ID 또는 태그도 기본으로 작동하며, 리뷰는 해당 커밋 이후 브랜치의 변경 사항을 다룹니다.

<h3 id="review-a-pull-request">
  풀 요청 검토
</h3>

로컬 브랜치 대신 GitHub 풀 요청을 검토하려면 PR 번호를 전달합니다:

```text theme={null}
/code-review ultra 1234
```

명령은 또한 `#1234`, `PR 1234` 및 붙여넣은 PR URL을 허용합니다. 붙여넣은 URL은 현재 디렉토리의 저장소를 가리켜야 합니다.

PR 모드에서 클라우드 샌드박스는 로컬 작업 트리를 번들로 묶는 대신 호스트에서 직접 풀 요청을 복제합니다. PR 모드는 `github.com`의 저장소 및 관리자가 Claude Code에 연결한 [GitHub Enterprise Server](/docs/ko/github-enterprise-server) 인스턴스에서 작동합니다.

`github.com`의 저장소의 경우 샌드박스는 Claude 계정에 연결된 GitHub 계정으로 복제하므로 계정이 PR의 저장소를 읽을 수 있어야 합니다. Claude Code는 [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](/docs/ko/env-vars#variables)을 설정하지 않은 경우 클라우드 세션을 생성하기 전에 이를 확인하고 [계정이 연결되지 않았거나](/docs/ko/errors#no-github-account-is-connected-to-your-claude-account) [계정이 저장소를 볼 수 없을 때](/docs/ko/errors#your-connected-github-account-cant-see-the-repository) 시작을 거부합니다. 거부는 수정 사항을 명시합니다. v2.1.248 이전에는 Claude Code가 시작 전에 이를 확인하지 않았습니다.

GitHub CLI 로그인을 Claude 계정에 연결하려면 [`/web-setup`](/docs/ko/web-quickstart#connect-from-your-terminal)을 실행합니다.

<h3 id="post-findings-to-the-pull-request">
  풀 요청에 결과 게시
</h3>

Claude Code v2.1.227 이상에서 `github.com`의 풀 요청을 검토할 때 Claude가 완료된 결과를 PR에 자신의 GitHub 계정에서 단일 일반 댓글로 게시하도록 할 수 있습니다. 댓글은 리뷰나 승인이 아니며 "Generated by Claude Code" 메모로 끝납니다. 브랜치 또는 GitHub Enterprise Server 풀 요청을 검토할 때 Claude Code는 세션에만 결과를 표시합니다.

Claude Code는 해당 실행에서 선택하지 않는 한 게시하지 않으며 `--no-post`가 기본값입니다. 게시는 각 실행에 대해 선택하는 사항입니다:

* **대화형**: 시작 대화에서 **PR에 결과를 나로 게시하고 실행**을 선택합니다. `/code-review ultra 1234 --post`와 같이 명령에 `--post`를 추가하면 Claude Code는 해당 선택을 미리 선택하고 시작하기 전에 여전히 묻습니다.
* **비대화형**: `--post`를 사용하여 [`claude ultrareview` 하위 명령](#run-ultrareview-non-interactively)을 실행합니다. 플래그를 사용하여 하위 명령을 실행하면 게시에 동의하므로 Claude Code는 묻지 않고 게시합니다. `claude -p '/code-review ultra'` 실행에서 Claude Code는 결과가 도착하기 전에 종료되므로 아무것도 게시하지 않습니다. 대신 하위 명령을 사용합니다.

Claude Code는 머신에서 게시하지 않습니다. 리뷰의 세션 ID를 Anthropic API로 보내며, 이는 Claude에 연결한 GitHub 계정을 통해 리뷰의 저장된 결과를 댓글로 게시합니다. 게시하려면 리뷰 자체와 동일한 claude.ai 로그인이 필요하며, 타사 제공자에서 또는 [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](/docs/ko/env-vars)을 설정할 때 사용할 수 없습니다.

대화형 세션에서 Claude Code는 결과가 도착할 때 게시를 시작하므로 리뷰가 완료될 때까지 세션을 열어 두십시오. Claude Code는 해당 세션에서만 게시 선택을 유지합니다. 리뷰가 완료되기 전에 세션이 종료되면 나중에 대화를 재개하더라도 Claude Code는 아무것도 게시하지 않습니다.

게시가 완료되면 Claude는 결과를 알려줍니다:

* **게시됨**: Claude는 댓글에 대한 링크를 제공합니다.
* **이미 게시됨**: 동일한 리뷰의 이전 게시가 이미 PR에 댓글을 올렸으므로 Claude는 다시 게시하는 대신 풀 요청에 링크합니다.
* **실패**: Claude는 이유를 알려주며, 결과는 터미널에 남아 있어 수동으로 게시할 수 있습니다.

<h3 id="pass-a-request-in-plain-words">
  일반 단어로 요청 전달
</h3>

Claude Code v2.1.218 이상에서는 일반 단어로 작업 중인 내용을 설명할 수도 있습니다:

```text theme={null}
/code-review ultra check my auth changes
```

리뷰는 여전히 현재 브랜치를 다루며 인수 없이 실행하는 것과 동일한 범위입니다. Claude는 텍스트를 메모로 유지하며 시작 대화에 표시되고 결과가 도착할 때 이와 관련됩니다.

Claude Code는 텍스트에 두 개 이상의 단어가 있고 브랜치 이름이나 PR 참조가 아닐 때만 메모로 취급합니다. 단일 단어를 브랜치 이름이나 PR 참조로 읽으므로 오타가 있는 브랜치 이름은 [다른 기본에 대해 검토](#review-against-a-different-base)의 가장 가까운 브랜치 오류를 받습니다. 텍스트가 `check PR 123 again`과 같은 다른 단어와 PR 참조를 결합하면 Claude Code도 시작하지 않습니다. 대신 PR 번호만으로 다시 실행하여 해당 PR을 검토하거나 참조 없이 현재 브랜치를 검토하도록 요청합니다.

<Tip>
  저장소가 너무 커서 번들로 묶을 수 없는 경우 Claude Code는 대신 PR 모드를 사용하도록 요청합니다. 브랜치를 푸시하고 초안 PR을 열고 `/code-review ultra <PR-number>`를 실행합니다.
</Tip>

<h3 id="diff-limits-and-fallbacks">
  차이 제한 및 폴백
</h3>

Ultrareview는 리뷰 작업이 실행되기 전에 차이를 확인하고 그대로 검토할 수 없을 때 알려줍니다:

* **차이가 너무 큼**: 브랜치 리뷰는 기본적으로 최대 500개의 변경된 파일과 8,000개의 변경된 라인을 포함할 수 있습니다. 정확한 값은 변경될 수 있으며 [거부](/docs/ko/errors#diff-is-too-large-for-ultrareview)는 적용 중인 값, 차이의 크기 및 가장 많이 변경된 라인이 있는 파일을 명시합니다. Claude Code는 너무 큰 풀 요청을 동일한 방식으로 거부하며 파일 및 라인 수를 명시하지만 파일별 분석은 명시하지 않습니다.
* **검토할 항목 없음**: 기본에 대한 차이가 비어 있으면 ultrareview는 거부하고 비교한 브랜치 또는 커밋을 명시하며 기본 브랜치 자체에 있고 커밋되지 않은 항목이 없거나 커밋이 모두 기본의 일부인 브랜치와 같은 경우를 명시합니다. 또한 해당 경우에 대한 해결 방법을 제안합니다. 예를 들어 작업이 있는 브랜치로 전환하거나, 로컬 편집을 스테이징하거나 커밋하거나, 다른 기본을 전달합니다.
* **첫 번째 커밋**: 저장소의 첫 번째 커밋은 비교할 이전 항목이 없으므로 시작 대화에서 확인한 후 ultrareview는 그 이후의 모든 파일을 검토합니다. 추적되지 않은 파일이 있으면 대신 거부하고 검토하려는 파일을 `git add`하도록 알려줍니다. 동일한 크기 제한이 적용됩니다.

  첫 번째 커밋은 해당 확인 후에만 전체적으로 검토되므로 `claude ultrareview` 하위 명령 및 `claude -p`는 이를 거부하고 대화형 세션을 대신 사용하도록 지시합니다. Claude Code v2.1.277 이상 필요
* **병합 기본 없음**: 브랜치가 기본 브랜치와 기록을 공유하지 않으면 또는 저장소에 비교할 기본 브랜치가 없으면 ultrareview는 저장소의 모든 추적된 파일을 대신 검토합니다. 폴백에는 전체 클론이 필요하며 동일한 크기 제한을 적용합니다. 시작 대화에서 확인하거나 `claude ultrareview` 하위 명령을 직접 실행할 때만 시작됩니다. `claude -p` 및 둘 다 발생하지 않는 다른 곳에서는 ultrareview가 거부하고 리뷰가 모든 파일을 다룰 것이라고 말하며 대화형 세션을 지시합니다.

  분기나 다른 참조가 없는 체크아웃에서(예: URL을 가져온 후 `FETCH_HEAD`를 체크아웃하여 생성된 분리된 HEAD), Claude Code는 [리뷰를 거부](/docs/ko/errors#your-checkout-has-no-branches)하고 먼저 브랜치를 생성할 것을 제안합니다.

<h2 id="pricing-and-free-runs">
  가격 책정 및 무료 실행
</h2>

Ultrareview는 플랜의 포함된 사용량이 아닌 사용량 크레딧에 대해 청구되는 프리미엄 기능입니다.

| 플랜                | 포함된 무료 실행 | 무료 실행 후                                                                                            |
| ----------------- | --------- | -------------------------------------------------------------------------------------------------- |
| Pro               | 3회 무료 실행  | [사용량 크레딧](https://support.claude.com/ko/articles/12429409-extra-usage-for-paid-claude-plans)으로 청구됨 |
| Max               | 3회 무료 실행  | [사용량 크레딧](https://support.claude.com/ko/articles/12429409-extra-usage-for-paid-claude-plans)으로 청구됨 |
| Team 및 Enterprise | 없음        | [사용량 크레딧](https://support.claude.com/ko/articles/12429409-extra-usage-for-paid-claude-plans)으로 청구됨 |

* **무료 실행**: Pro 및 Max의 3회 실행은 계정당 일회성 할당이며 새로 고쳐지지 않습니다.
* **리뷰당 비용**: 무료 실행을 모두 사용한 후 일반적으로 변경 사항의 크기에 따라 $5에서 $25의 사용량 크레딧이 소요되며, 각 실행 전에 시작 대화 상자에 표시되는 예상 비용과 일치합니다.
* **실행이 계산되는 시점**: 클라우드 세션이 시작되면입니다. 조기에 중단하거나 완료되지 않은 리뷰도 무료 실행을 사용합니다. 유료 리뷰의 경우 사용량 크레딧은 실행된 부분에 대해서만 청구됩니다.

Ultrareview는 항상 무료 실행 외에 사용량 크레딧으로 청구되기 때문에 계정 또는 조직은 유료 리뷰를 시작하기 전에 사용량 크레딧을 활성화해야 합니다. 사용량 크레딧이 활성화되지 않은 경우 Claude Code는 시작을 차단하며, 켤 수 있는 방법은 청구 액세스 권한에 따라 다릅니다.

* 계정의 청구를 관리할 수 있는 경우 Claude Code는 사용량 크레딧을 켤 수 있는 청구 설정으로 연결합니다.
* Team 및 Enterprise 플랜에서 청구 액세스 권한이 없는 구성원은 CLI에서 관리자에게 사용량 크레딧을 켜도록 요청하는 요청을 보냅니다.

`/usage-credits`를 실행하여 사용량 크레딧 설정을 확인하거나 변경할 수도 있습니다.

Claude Code는 대화당 한 번 사용량 크레딧 청구를 확인하도록 요청합니다. 예를 들어 `/clear`로 새 대화를 시작할 때 Claude Code는 다음 유료 리뷰에 대해 확인을 다시 표시합니다.

<h2 id="track-a-running-review">
  실행 중인 리뷰 추적
</h2>

리뷰는 일반적으로 5\~10분이 소요됩니다. 리뷰는 백그라운드 작업으로 실행되므로 세션에서 계속 작업하고, 다른 명령을 시작하거나, 터미널을 완전히 닫을 수 있습니다. [발견 사항을 풀 요청에 게시](#post-findings-to-the-pull-request)하도록 선택한 경우 리뷰가 완료될 때까지 세션을 열어 두십시오. 세션이 먼저 종료되면 Claude Code는 아무것도 게시하지 않습니다.

`/tasks`를 사용하여 실행 중이고 완료된 리뷰를 보고, 리뷰의 상세 보기를 열거나, 진행 중인 리뷰를 중지합니다. 리뷰를 중지하면 Claude Code는 클라우드 세션을 보관하고 부분 발견 사항은 반환하지 않습니다.

리뷰가 완료되면 Claude Code는 검증된 발견 사항을 세션의 알림으로 표시합니다. 각 발견 사항에는 파일 위치와 문제에 대한 설명이 포함되어 있으므로 Claude에 직접 수정을 요청할 수 있습니다.

<h2 id="run-ultrareview-non-interactively">
  비대화형으로 ultrareview 실행
</h2>

`claude ultrareview` 하위 명령을 사용하여 대화형 세션 없이 CI 또는 스크립트에서 ultrareview를 시작합니다. 하위 명령은 `/code-review ultra`와 동일한 리뷰를 시작하고, 원격 리뷰가 완료될 때까지 차단하고, 발견 사항을 stdout으로 인쇄합니다.

```bash theme={null}
claude ultrareview
claude ultrareview 1234
claude ultrareview origin/main
```

인수 없이 하위 명령은 현재 브랜치와 기본 브랜치 간의 차이를 검토하며, 병합 기반이 없을 때 `/code-review ultra`와 동일한 [전체 저장소 폴백](#diff-limits-and-fallbacks)을 사용합니다. PR 번호를 전달하여 풀 요청을 검토하거나, 기본 브랜치를 전달하여 해당 브랜치에 대해 검토합니다. [기본 브랜치 처리](#review-against-a-different-base)는 대화형 명령과 일치합니다.

하위 명령을 실행하면 전체 저장소 폴백과 청구 및 약관 프롬프트에 동의하므로 입력을 기다리지 않고 실행이 시작됩니다. 직접 실행하는 것이 동의로 간주됩니다. Claude가 예를 들어 Bash 도구를 통해 대신 하위 명령을 실행할 때 Claude Code는 전체 저장소 리뷰를 거부합니다.

Claude Code v2.1.218 이상에서는 비대화형 세션에서 `/code-review ultra`를 실행하여 클라우드 리뷰를 시작할 수도 있습니다(예: `claude -p '/code-review ultra'`). Claude Code는 리뷰를 시작하고 발견 사항을 기다리지 않고 추적 링크를 인쇄합니다. 이는 발견 사항이 도착할 때까지 차단하는 `claude ultrareview`와 다릅니다. 리뷰가 사용량 크레딧을 청구할 때 Claude Code는 시작하기 전에 중지하고 `claude ultrareview`를 가리킵니다. 청구 확인에는 대화형 세션이 필요하기 때문입니다. v2.1.218 이전에는 비대화형 세션에서 `/code-review ultra`가 로컬 리뷰를 실행했습니다.

진행 메시지 및 라이브 세션 URL은 stderr로 이동하므로 stdout은 구문 분석 가능한 상태로 유지됩니다. 이 플래그를 사용하여 출력, 시간 초과 및 발견 사항 게시 여부를 제어합니다:

| 플래그                   | 설명                                                                                                                                                                                           |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--json`              | 형식이 지정된 발견 사항 대신 원본 `bugs.json` 페이로드를 인쇄합니다                                                                                                                                                  |
| `--timeout <minutes>` | 리뷰가 완료될 때까지 기다릴 최대 분 수입니다. 기본값은 45입니다                                                                                                                                                        |
| `--post`              | [발견 사항을 풀 요청에 게시](#post-findings-to-the-pull-request)하여 GitHub 계정에서 하나의 일반 댓글로 게시합니다. `github.com` 풀 요청 대상에서 작동합니다. 다른 대상에서는 Claude Code가 플래그를 무시하고 그렇게 말합니다. Claude Code v2.1.227 이상이 필요합니다 |
| `--no-post`           | 발견 사항을 게시하지 않습니다. 이것이 기본값이며, 두 플래그를 모두 전달하면 Claude Code는 게시하지 않습니다. Claude Code v2.1.227 이상이 필요합니다                                                                                           |

`claude ultrareview` 실행은 `/code-review ultra`와 동일한 인증 및 사용량 크레딧 구성이 필요합니다.

하위 명령은 다음 세 가지 코드 중 하나로 종료됩니다:

* **0**: 리뷰가 완료되었으며, 발견 사항이 있거나 없습니다
* **1**: 리뷰가 시작되지 않았거나, 클라우드 세션에 오류가 발생했거나, 시간 초과가 경과했습니다
* **130**: Ctrl-C로 하위 명령을 중단했습니다

하위 명령을 중단하면 원격 리뷰는 계속 실행됩니다. stderr로 인쇄된 세션 URL을 따라 브라우저에서 시청합니다.

`--post`를 사용하면 하위 명령은 발견 사항을 인쇄한 직후 게시를 시작합니다. 링크를 stderr로 인쇄합니다.

* 실행이 실패하거나, 시간 초과가 되거나, 중단하면 하위 명령은 아무것도 게시하지 않습니다.
* 리뷰가 완료되었지만 댓글이 게시되지 않으면 Claude Code는 이유를 stderr로 인쇄하고, 발견 사항은 stdout에 유지되므로 수동으로 게시할 수 있습니다.

GitHub 풀 요청에 대한 자동 리뷰의 경우, [Code Review](/docs/ko/code-review)는 저장소와 직접 통합되고 CLI 단계 없이 발견 사항을 인라인 PR 댓글로 게시합니다.

<h2 id="how-ultrareview-compares-to-/code-review">
  ultrareview와 /code-review의 비교
</h2>

두 검토 모두 코드를 검토하지만 워크플로우의 다른 단계에서 사용합니다.

|       | `/code-review`              | `/code-review ultra`         |
| ----- | --------------------------- | ---------------------------- |
| 대상    | 작업 중인 diff, 풀 요청, 브랜치 또는 경로 | 작업 중인 diff 또는 풀 요청           |
| 실행    | 세션에서 로컬로                    | 클라우드 샌드박스에서                  |
| 깊이    | 노력 인수에 따라 확장                | 독립적 검증이 있는 다중 에이전트 플릿        |
| 기간    | 몇 초에서 몇 분                   | 대략 5\~10분                    |
| 비용    | 일반 사용량으로 계산됨                | 무료 실행, 그 후 대략 $5~$25 사용량 크레딧 |
| 최적 용도 | 반복하는 동안 빠른 피드백              | 실질적인 변경 사항을 병합하기 전에 신뢰도 향상   |

작업하는 동안 빠른 피드백을 위해 `/code-review`를 사용하거나, PR 번호를 전달하여 승인하기 전에 팀원의 풀 요청을 검토합니다. 로컬 검토에서 놓칠 수 있는 문제를 포착하는 더 깊은 패스를 원할 때 실질적인 변경 사항을 병합하기 전에 `/code-review ultra`를 사용합니다.
