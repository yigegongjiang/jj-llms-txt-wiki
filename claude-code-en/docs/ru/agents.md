# Запуск агентов параллельно

> Сравните способы, которыми Claude Code может выполнять несколько задач одновременно: подагенты, представление агентов, команды агентов, динамические рабочие процессы и проекты.

Claude Code имеет пять способов работать над несколькими задачами одновременно: [subagents](/docs/ru/sub-agents), [agent view](/docs/ru/agent-view), [agent teams](/docs/ru/agent-teams), [dynamic workflows](/docs/ru/workflows) и [projects](/docs/ru/claude-projects). Они отличаются тем, насколько вы остаетесь вовлечены, от управления каждым разговором самостоятельно до того, чтобы позволить Claude координировать группу работников, и тем, работает ли работа на вашей машине или в облаке.

| Подход                             | Что вы получаете                                                                                                                                                                                                                                                                    | Используйте, когда                                                                                                                                                                                                                       |
| :--------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Subagents](/docs/ru/sub-agents)        | Делегированные работники в одном сеансе, которые выполняют побочную задачу в своем собственном контексте и возвращают резюме                                                                                                                                                        | Побочная задача заполнит ваш основной разговор результатами поиска, логами или содержимым файлов, на которые вы больше не будете ссылаться                                                                                               |
| [Agent view](/docs/ru/agent-view)       | Один экран для отправки и мониторинга сеансов, работающих в фоновом режиме, открывается с помощью `claude agents`. Предварительный просмотр исследования                                                                                                                            | У вас есть несколько независимых задач, и вы хотите их передать, проверить статус с первого взгляда и вмешаться только когда один из них нуждается в вас                                                                                 |
| [Agent teams](/docs/ru/agent-teams)     | Несколько координируемых сеансов с общим списком задач и обменом сообщениями между агентами, управляемые лидером. Экспериментальная функция и отключена по умолчанию                                                                                                                | Вы хотите, чтобы Claude разделил проект на части, назначил их и держал работников в синхронизации                                                                                                                                        |
| [Projects](/docs/ru/claude-projects)    | Один текущий разговор на claude.ai/code или в приложении для рабочего стола. Claude запускает параллельные облачные сеансы, называемые потоками, дает каждому репозитории проекта, инструкции и память, и показывает вам, какие из них нуждаются в вас. Публичная бета на Pro и Max | Работа охватывает множество задач в течение дней или недель, должна продолжаться, когда ваша машина выключена, и вы предпочитаете описать это один раз, чем отправлять и отслеживать каждый сеанс                                        |
| [Dynamic workflows](/docs/ru/workflows) | Скрипт, который запускает множество подагентов и проверяет их результаты, для работы, которая слишком велика для координации за один ход или которая требует более одного прохода                                                                                                   | Задача слишком велика для нескольких подагентов, или вы хотите, чтобы результаты были проверены друг против друга: аудит всей кодовой базы, миграция 500 файлов, перепроверенное исследование или план, разработанный с нескольких углов |

В каждом подходе работники — это сеансы Claude. Чтобы задействовать другой инструмент, предоставьте его Claude как [MCP server](/docs/ru/mcp).

Три дополнительных инструмента поддерживают эту работу, не являясь способом запуска агентов:

* [Worktrees](/docs/ru/worktrees) дают каждому сеансу отдельный git checkout, поэтому параллельные сеансы никогда не редактируют одни и те же файлы. Используйте их для сеансов, которые вы запускаете сами. Сеанс, который вы отправляете из agent view, [переходит в свой собственный worktree перед редактированием файлов](/docs/ru/agent-view#how-file-edits-are-isolated), и подагенты, которых вы порождаете, могут получить свой собственный.
* [Cross-session messaging](/docs/ru/cross-session-messaging) позволяет Claude перечислять и отправлять сообщения вашим другим сеансам Claude Code на этой машине, на другой машине или [в облаке](/docs/ru/claude-code-on-the-web), поэтому сеансы, которые вы запускаете сами, могут передавать результаты и статус между собой.
* [`/batch`](/docs/ru/commands) — это [skill](/docs/ru/skills), который заставляет Claude разделить одно большое изменение на 5–30 worktree-изолированных подагентов. Это упакованное использование подагентов и worktrees, а не отдельный стиль координации.

Несколько других функций запускают Claude без того, чтобы вы управляли каждым шагом, но они решают другую проблему, чем разделение работы между агентами:

* [Фоновая bash команда](/docs/ru/interactive-mode#background-bash-commands) запускает одну команду оболочки без блокировки разговора. Она не порождает агента.
* [Разветвленный подагент](/docs/ru/sub-agents#fork-the-current-conversation) — это подагент, который наследует полный контекст вашего разговора вместо того, чтобы начинать с нуля. Это способ порождения подагента, а не отдельная поверхность. Запустите его с помощью `/subtask`. Claude также порождает его сам, когда [режим fork](/docs/ru/sub-agents#turn-fork-mode-on-or-off) включен. Чтобы скопировать весь сеанс в новый [фоновый сеанс](/docs/ru/agent-view#from-inside-a-session), который работает параллельно с ним, используйте `/fork`. При [отключенном agent view](/docs/ru/agent-view#turn-off-agent-view) команда разветвленного подагента — это `/fork` вместо этого, и `/subtask` недоступна.
* [Routine](/docs/ru/routines) запускает сеанс по расписанию в облаке, а не параллельно на вашей машине.

<Note>
  Запуск нескольких сеансов или подагентов одновременно увеличивает использование токенов. Подробнее см. [Costs](/docs/ru/costs) для информации об использовании и ограничениях скорости.
</Note>

<h2 id="choose-an-approach">
  Выберите подход
</h2>

Правильный подход зависит от того, кто координирует работу, нужны ли работникам общаться и редактируют ли они одни и те же файлы:

* **Кто координирует работу?**
  * Claude делегирует и собирает результаты в одном разговоре: [subagents](/docs/ru/sub-agents)
  * Вы передаёте независимые задачи и проверяете их позже: [agent view](/docs/ru/agent-view)
  * Claude планирует, назначает и контролирует группу работников: [agent teams](/docs/ru/agent-teams), экспериментальная функция, отключена по умолчанию
  * Скрипт держит координацию вместо пошагового суждения Claude: [dynamic workflows](/docs/ru/workflows). См. [как workflows сравниваются с subagents и skills](/docs/ru/workflows#when-to-use-a-workflow)
* **Нужны ли работникам общаться друг с другом?** Claude может передавать результаты с помощью [cross-session messaging](/docs/ru/cross-session-messaging) между сеансами, которые вы запускаете сами, включая сеансы, которые вы отправляете из agent view. Subagents сообщают результаты обратно в разговор, который их породил, а сеансы agent view сообщают результаты только вам. Товарищи по команде в команде агентов обмениваются сообщениями напрямую и, когда они [имеют инструменты Task](/docs/ru/tools-reference#task-tool-availability), делят список задач.
* **Затрагивают ли задачи одни и те же файлы?** Изолируйте работу с помощью [worktrees](/docs/ru/worktrees). Subagents и сеансы, которые вы запускаете сами, могут каждый использовать отдельный worktree. Agent teams не изолируют товарищей по команде в worktrees, поэтому [разделите работу](/docs/ru/agent-teams#avoid-file-conflicts) так, чтобы каждый товарищ по команде владел другим набором файлов.

<h2 id="check-on-running-work">
  Проверьте выполняемую работу
</h2>

Команда для проверки выполняемой работы зависит от того, какой подход вы использовали:

* Для фоновых сеансов `claude agents` открывает [agent view](/docs/ru/agent-view): один экран, показывающий каждый сеанс, его состояние и какие из них нуждаются в вашем вводе.
* Для подагентов в текущем сеансе именованные фоновые подагенты появляются в typeahead @-упоминания с их статусом. Начиная с версии 2.1.198, `/agents` больше не открывает панель; он выводит уведомление, указывающее на расположение файлов подагентов. Чтобы [создавать и редактировать пользовательские подагенты](/docs/ru/sub-agents#configure-subagents), попросите Claude или отредактируйте файлы напрямую. Несмотря на похожее имя, `/agents` отделен от `claude agents`.
* Для всего, что работает в фоновом режиме текущего сеанса, `/tasks` перечисляет каждый элемент и позволяет вам проверить, присоединиться или остановить его. Список также включает подагентов, которые завершили работу.
* Для динамических рабочих процессов `/workflows` перечисляет запущенные и завершенные запуски, фазу, в которой находится каждый из них, и сколько агентов завершило работу.

Для представления на рабочем столе всех ваших сеансов см. [параллельные сеансы в приложении для рабочего стола](/docs/ru/desktop#work-in-parallel-with-sessions).

<h2 id="learn-more">
  Узнайте больше
</h2>

Каждое руководство ниже охватывает настройку и конфигурацию для одного подхода:

* [Create custom subagents](/docs/ru/sub-agents): определите переиспользуемых специалистов и контролируйте, какие инструменты они могут использовать.
* [Manage agents with agent view](/docs/ru/agent-view): отправляйте сеансы, наблюдайте их состояние и присоединяйтесь, когда один из них нуждается в вас.
* [Orchestrate agent teams](/docs/ru/agent-teams): установите лидера и товарищей по команде, назначьте задачи и проверьте их работу.
* [Orchestrate dynamic workflows](/docs/ru/workflows): запустите объединённый workflow или позвольте Claude написать один, который запускает множество subagents и проверяет их результаты друг против друга.
* [Run parallel sessions with worktrees](/docs/ru/worktrees): запустите Claude в изолированном checkout, контролируйте, что копируется, и очищайте после этого.
