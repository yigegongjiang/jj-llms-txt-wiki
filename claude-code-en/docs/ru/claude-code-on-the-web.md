# Использование Claude Code в облаке

> Запускайте сессии Claude Code в облаке из браузера, телефона, настольного приложения или терминала, перемещайте их с помощью --cloud и --teleport, а также автоматически исправляйте pull requests.

<Note>
  Облачные сессии доступны в планах Pro, Max и Team, а также для пользователей Enterprise с премиум-местами или местами Chat + Claude Code.
</Note>

Облачная сессия — это сессия Claude Code, которая запускается на облачной инфраструктуре вместо вашей машины. По умолчанию она запускается на инфраструктуре, управляемой Anthropic, или в [самостоятельно размещённом окружении](/docs/ru/self-hosted-environments) вашей организации, когда маршрутизируется туда. Сессия продолжает работать после того, как вы закроете ноутбук, и вы можете проверить её или управлять ею с любого устройства.

Вы можете запустить облачную сессию с любой из этих поверхностей:

* **Браузер**: [claude.ai/code](https://claude.ai/code), также называется Claude Code в веб-интерфейсе
* **Мобильное устройство**: вкладка **Code** в [приложении Claude](/docs/ru/mobile)
* **Настольное приложение**: выберите **Cloud** вместо **Local** при [запуске сессии](/docs/ru/desktop#run-long-running-tasks-in-the-cloud)
* **Терминал**: [`claude --cloud`](#from-terminal-to-cloud)
* **Routines**: [запланированные и активируемые запуски](/docs/ru/routines) каждый запуск выполняется как облачная сессия

Чтобы Claude запустил и отслеживал множество облачных сессий для одного набора работ, используйте [проект](/docs/ru/claude-projects). Сессия в вашем терминале, вашей IDE или настольном приложении с выбранным **Local** запускается на вашей собственной машине. Чтобы управлять одной из этих локальных сессий с вашего телефона или браузера, используйте [Remote Control](/docs/ru/remote-control).

<Tip>
  Новичок в облачных сессиях? Начните с [Начало работы](/docs/ru/web-quickstart) для подключения вашего аккаунта GitHub и отправки вашей первой задачи.
</Tip>

<h2 id="cloud-environments">
  Облачные окружения
</h2>

Каждая облачная сессия запускается в [облачном окружении](/docs/ru/cloud-environments), сохранённой конфигурации, которая контролирует сетевой доступ, переменные окружения и скрипты установки. Если у вас ещё нет окружения, подключение настраивает окружение **Default** с [**Trusted** сетевым доступом](/docs/ru/cloud-environments#access-levels), либо создав его для вас, либо попросив вас создать его. См. [The Default environment](/docs/ru/cloud-environments#the-default-environment) для того, какой из этих вариантов происходит на вашем плане и как сессии выбирают окружение, когда у вас есть более одного.

Те же окружения применяются везде, где вы запускаете облачную сессию: в веб-интерфейсе, в терминале, [Claude Tag](https://claude.com/docs/claude-tag/overview), [routines](/docs/ru/routines) и в мобильном и Desktop приложениях. Сессии канала Claude Tag используют только окружения уровня организации, либо [общие окружения](/docs/ru/cloud-environments#organization-shared-environments), либо [самостоятельно размещённые окружения](/docs/ru/self-hosted-environments).

См. [Configure cloud environments](/docs/ru/cloud-environments) для изменения того, что позволяет окружение, установки переменных или добавления скрипта установки, и [Installed tools](/docs/ru/cloud-environments#installed-tools) для того, что сессии включают без какой-либо конфигурации.

<h2 id="github-authentication-options">
  Варианты аутентификации GitHub
</h2>

Облачным сессиям нужен доступ к вашим репозиториям GitHub для клонирования кода и отправки веток. Вы можете предоставить доступ двумя способами:

| Метод            | Как вы подключаетесь                                                                                          | Репозитории, к которым могут получить доступ сессии                                                                             | Лучше всего для                                                                        |
| :--------------- | :------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------- |
| **GitHub App**   | Авторизуйте приложение Claude GitHub во время [веб-подключения](/docs/ru/web-quickstart)                           | Любой открытый репозиторий и приватные репозитории, на которых установлено приложение Claude GitHub                             | Веб-подключение в браузере; команды, которые хотят [Auto-fix](#auto-fix-pull-requests) |
| **`/web-setup`** | Запустите `/web-setup` в вашем терминале для отправки вашего локального токена `gh` CLI на ваш аккаунт Claude | Любой репозиторий, к которому может получить доступ ваш токен `gh`, независимо от того, установлено ли приложение Claude GitHub | Отдельные разработчики, которые уже используют `gh`                                    |

Установка приложения Claude GitHub на репозиторий также включает [Auto-fix](#auto-fix-pull-requests) для pull-запросов в нём.

Потоки в [проекте](/docs/ru/claude-projects) требуют установки приложения Claude GitHub на каждом репозитории, который они клонируют, независимо от того, каким методом вы подключились. См. [Set up GitHub access](/docs/ru/claude-projects#set-up-github-access).

Для информации о том, как `/schedule` проверяет доступ к репозиторию перед созданием routine, см. [Repositories and branch permissions](/docs/ru/routines#repositories-and-branch-permissions). См. [Connect from your terminal](/docs/ru/web-quickstart#connect-from-your-terminal) для пошагового руководства `/web-setup`, включая то, что хранит `/web-setup` и как его удалить.

Quick web setup — это параметр организации, который позволяет членам подключать GitHub с помощью `/web-setup`, пропускает запрос на установку Claude GitHub App во время веб-подключения в браузере и заставляет веб-подключение создать [**Default** окружение](/docs/ru/cloud-environments#the-default-environment) для них вместо отображения формы окружения. На планах Team и Enterprise он отключен по умолчанию, что скрывает `/web-setup`. [Owner](/docs/ru/server-managed-settings#access-control) включает его с помощью переключателя **Quick web setup** в [**Admin settings > Claude Code**](https://claude.ai/admin-settings/claude-code).

<Note>
  Организации с включённым [Zero Data Retention](/docs/ru/zero-data-retention) не могут использовать `/web-setup` или другие функции облачных сессий.
</Note>

<h2 id="move-tasks-between-terminal-and-cloud">
  Перемещение задач между терминалом и облаком
</h2>

Эти рабочие процессы требуют [Claude Code CLI](/docs/ru/quickstart), вошедшего в один и тот же аккаунт claude.ai. Вы можете запускать новые облачные сессии из вашего терминала или вытягивать облачные сессии в ваш терминал для продолжения локально. Облачные сессии сохраняются даже если вы закроете ваш ноутбук, и вы можете мониторить их откуда угодно, включая мобильное приложение Claude.

<Note>
  Из CLI передача сессии односторонняя: вы можете вытягивать облачные сессии в ваш терминал с помощью `--teleport`, но вы не можете отправить существующую сессию терминала в облако. Флаг `--cloud` с описанием задачи создаёт новую облачную сессию для вашего текущего репозитория; с `-p` и ID сессии или URL claude.ai/code он вместо этого [ставит сообщение в очередь в эту существующую сессию](/docs/ru/claude-code-on-the-web#send-follow-ups-from-the-cli). [Desktop app](/docs/ru/desktop#continue-in-another-surface) предоставляет меню **Continue in**, которое может отправить локальную сессию в облако.
</Note>

<h3 id="from-terminal-to-cloud">
  От терминала к облаку
</h3>

Запустите облачную сессию из командной строки с флагом `--cloud`:

```bash theme={null}
claude --cloud "Fix the authentication bug in src/auth/login.ts"
```

Это создаёт новую облачную сессию на claude.ai. Облачная виртуальная машина клонирует удалённый GitHub вашего текущего каталога в вашей текущей ветке, а не ваш локальный checkout, поэтому сначала отправьте, если у вас есть локальные коммиты. См. [Отправляйте локальные репозитории без GitHub](#send-local-repositories-without-github) для случаев, когда Claude Code загружает ваш локальный репозиторий вместо клонирования.

`--cloud` работает с одним репозиторием за раз. Задача запускается в облаке, пока вы продолжаете работать локально. Старое написание `--remote` всё ещё работает как устаревший псевдоним для `--cloud`.

Пока облачный контейнер запускается, CLI показывает живой чек-лист шагов настройки, таких как клонирование репозитория и запуск вашего [скрипта установки](/docs/ru/cloud-environments#setup-scripts). Он ставит в очередь сообщения, которые вы вводите во время подготовки, и отправляет их после того, как сессия будет готова.

<Note>
  `--cloud` создаёт облачные сессии. `--remote-control` не связан: он позволяет вам мониторить и управлять локальной сессией CLI из claude.ai или приложения Claude. См. [Remote Control](/docs/ru/remote-control).
</Note>

Откройте сессию на claude.ai или в мобильном приложении Claude для проверки прогресса или прямого взаимодействия. Оттуда вы можете управлять Claude, предоставлять обратную связь или отвечать на вопросы, как в любом другом разговоре.

Если Claude задаёт вопрос и сессия остаётся неактивной, вы всё ещё можете ответить, когда вернётесь, вплоть до [истечения окружения](#environment-expired), и сессия продолжится с вашего ответа.

<h4 id="tips-for-cloud-tasks">
  Советы для облачных задач
</h4>

**Планируйте локально, выполняйте в облаке**: для сложных задач начните Claude в режиме плана для совместной работы над подходом, затем отправьте работу в облако:

```bash theme={null}
claude --permission-mode plan
```

В режиме плана Claude читает файлы, запускает команды для исследования и предлагает план без редактирования исходного кода. Когда вы будете довольны, сохраните план в репозиторий, зафиксируйте и отправьте, чтобы облачная виртуальная машина могла его клонировать. Затем запустите облачную сессию для автономного выполнения:

```bash theme={null}
claude --cloud "Execute the migration plan in docs/migration-plan.md"
```

**Запускайте задачи параллельно**: каждая команда `--cloud` создаёт свою собственную облачную сессию, которая запускается независимо. Вы можете запустить несколько задач, и они все будут запускаться одновременно в отдельных сессиях:

```bash theme={null}
claude --cloud "Fix the flaky test in auth.spec.ts"
claude --cloud "Update the API documentation"
claude --cloud "Refactor the logger to use structured output"
```

Когда сессия завершится, вы можете создать PR из claude.ai/code или [телепортировать](#from-cloud-to-terminal) сессию в ваш терминал для продолжения работы.

<h4 id="send-local-repositories-without-github">
  Отправляйте локальные репозитории без GitHub
</h4>

Когда вы запускаете `claude --cloud` из репозитория, который не имеет git remote, или из репозитория github.com, на котором Claude GitHub App не установлено, Claude Code упаковывает ваш локальный репозиторий и загружает его непосредственно в облачную сессию. Это применяется даже если вы подключили GitHub с помощью `/web-setup`. Пакет включает вашу полную историю репозитория во всех ветках, плюс незафиксированные изменения отслеживаемых файлов.

На macOS, Linux и WSL Claude Code исключает незафиксированные изменения файлов, названных как учётные данные или ключи, из загрузки и называет файлы, которые он исключил. Это охватывает файлы `.env`, Terraform файлы `*.tfvars` и файлы ключей, такие как `id_rsa` и `*.pem`. Сессия начинается с зафиксированной версии каждого, или без файла, если ничего не зафиксировано. В связанном worktree, подмодуле или аналогичной раскладке Claude Code загружает эти изменения с остальным и называет файлы, которые он загружает.

Чтобы загрузить пакет даже когда Claude Code иначе клонировал бы с удалённого сервера, установите `CCR_FORCE_BUNDLE=1`:

```bash theme={null}
CCR_FORCE_BUNDLE=1 claude --cloud "Run the test suite and fix any failures"
```

Упакованные репозитории должны соответствовать этим ограничениям:

* Каталог должен быть git репозиторием с по крайней мере одним коммитом
* Упакованный репозиторий должен быть менее 100 МБ. Большие репозитории переходят к упаковке только текущей ветки, затем к одному сжатому снимку рабочего дерева и не пройдут только если снимок всё ещё слишком большой
* Неотслеживаемые файлы не включены; запустите `git add` на файлы, которые вы хотите, чтобы облачная сессия видела
* Сессии, созданные из пакета, могут отправляться обратно на удалённый GitHub только когда ваше [подключение GitHub](#github-authentication-options) имеет доступ на отправку к этому репозиторию

<h3 id="send-follow-ups-from-the-cli">
  Отправляйте follow-ups из CLI
</h3>

Когда облачная сессия запущена, где бы она ни выполнялась, отправьте ей follow-up сообщение из CLI `claude` на любой машине, где вы вошли с помощью `claude auth login`. CLI аутентифицируется с помощью учётных данных вашего аккаунта Anthropic и не отправляет локальное состояние сессии, поэтому команду не обязательно запускать с машины, которая запустила сессию, и она одинакова в каждой оболочке, включая PowerShell.

Команда публикует одно сообщение и выходит:

```bash theme={null}
claude -p "your message" --cloud <session-id>
```

CLI ставит сообщение в очередь в сессию и выходит без ожидания ответа. Используйте это для управления долгоживущей сессией, постановки в очередь следующего шага, пока текущий всё ещё завершается, или отправки follow-ups из [CI скрипта](/docs/ru/self-hosted-environments-testing#run-the-test-loop). Вы также можете передать сообщение на stdin вместо передачи его в качестве аргумента: `echo "your message" | claude -p --cloud <session-id>`.

Для `<session-id>` передайте голый ID, такой как `session_...` или `cse_...`, или URL сессии `claude.ai/code/<id>`, с или без схемы или строки запроса. Найдите ID в списке сессий на claude.ai/code.

<Note>
  `--cloud` требует аккаунта Anthropic. Он недоступен, когда Claude Code настроен для Amazon Bedrock, Google Cloud's Agent Platform или другого поставщика третьей стороны. [LLM gateway](/docs/ru/llm-gateway), настроенный только через `ANTHROPIC_BASE_URL`, не считается поставщиком третьей стороны для этой проверки, но вам всё ещё нужно войти с помощью `claude auth login`. Политика `allow_remote_sessions` вашей организации также должна быть включена. Owner может включить её в параметрах администратора Claude Code на claude.ai/admin-settings/claude-code.
</Note>

<h4 id="output-and-errors">
  Вывод и ошибки
</h4>

При успехе команда выводит ID сессии и ссылку для просмотра сессии:

```
Sent to cloud session.
Session ID: session_01DiUkqY2kzbUbDmW1w96rfi
View: https://claude.ai/code/session_01DiUkqY2kzbUbDmW1w96rfi?from=cli&m=0
```

Передайте `--output-format json` для машиночитаемого результата: `{ok, session_id, url}` при успехе, или `{ok: false, session_id, error}` когда отправка не пройдёт, например когда сессия отсутствует или архивирована. Ошибки конфигурации, такие как неподдерживаемый поставщик или отключённая политика организации, выводятся в stderr без JSON. `--output-format stream-json` не поддерживается с `--cloud <session-id>`.

CLI добавляет префикс к ошибкам с `Error: `. Неудачная доставка обёрнута как `failed to send message to cloud session <id>: <reason>`.

| Сообщение                                                                                                                   | Что это означает                                                                                                                                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cloud sessions aren't available with <provider>. They run on Anthropic's infrastructure and require an Anthropic account.` | Claude Code настроен для поставщика третьей стороны. Сообщение называет поставщика с меткой, которую использует ваша конфигурация, такой как `Amazon Bedrock` или `Google Vertex AI`. Удалите конфигурацию этого поставщика, например отменив `CLAUDE_CODE_USE_BEDROCK`, и войдите с аккаунтом Anthropic (`claude auth login`). |
| `Cloud sessions are disabled by your organization's policy. Contact your organization admin to enable them.`                | Политика организации `allow_remote_sessions` отключена.                                                                                                                                                                                                                                                                         |
| `Couldn't verify your organization's policy for cloud sessions. Check your network connection and try again.`               | Claude Code не смог получить политику вашей организации, поэтому он отказывает в отправке, а не предполагает, что облачные сессии разрешены. Проверьте подключение к сети и повторите попытку.                                                                                                                                  |
| `Attaching to an existing cloud session is not enabled for your account.`                                                   | Вы запустили `--cloud <session-id>` без `-p`. Отправьте сообщение с помощью `claude -p "your message" --cloud <session-id>`.                                                                                                                                                                                                    |
| `Session not found: <id>`                                                                                                   | ID или URL не совпадает с сессией, к которой вы можете получить доступ. Проверьте его по URL claude.ai/code сессии.                                                                                                                                                                                                             |
| `cloud session <id> is archived and cannot accept new messages`                                                             | Сессия была архивирована. Запустите новую сессию вместо этого.                                                                                                                                                                                                                                                                  |

<h3 id="from-cloud-to-terminal">
  От облака к терминалу
</h3>

Вытягивайте облачную сессию в ваш терминал, используя любое из этих:

* **Используя `--teleport`**: из командной строки запустите `claude --teleport` для интерактивного выбора сессии, или `claude --teleport <session-id>` для прямого возобновления конкретной сессии. Если у вас есть незафиксированные изменения, вам будет предложено сначала их спрятать.
* **Используя `/teleport`**: внутри существующей сессии CLI запустите `/teleport` или `/tp` для открытия того же выбора сессии без перезагрузки Claude Code.
* **Из `/tasks`**: запустите `/tasks` для просмотра ваших фоновых сессий, затем нажмите `t` для телепортирования в одну из них.
* **Из claude.ai/code**: выберите **Open in > Terminal** из меню сессии для копирования команды, которую вы можете вставить в ваш терминал.
* **Из облачной сессии**: введите `/teleport` и Claude Code ответит точной командой `claude --teleport <session-id>` для этой сессии, готовой к запуску из checkout репозитория. Требует Claude Code v2.1.223 или более поздней версии в окружении сессии.

Когда вы телепортируете сессию, Claude проверяет, что вы находитесь в правильном репозитории, получает и извлекает ветку из облачной сессии и загружает полную историю разговора в ваш терминал. Терминал получает свою собственную копию сессии: новая работа там остаётся локальной и не появляется в облачной сессии на claude.ai или в мобильном приложении Claude. Чтобы продолжить управление со своего телефона после телепортирования, запустите [`/remote-control`](/docs/ru/remote-control) в локальной сессии.

`--teleport` отличается от `--resume`. `--resume` переоткрывает разговор из локальной истории этой машины и не перечисляет облачные сессии; `--teleport` вытягивает облачную сессию и её ветку.

<h4 id="teleport-requirements">
  Требования для телепортирования
</h4>

Телепортирование проверяет эти требования перед возобновлением сессии. Если какое-либо требование не выполнено, вы увидите ошибку или будете приглашены разрешить проблему.

| Требование             | Детали                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Чистое состояние git   | Ваш рабочий каталог должен не иметь незафиксированных изменений. Телепортирование предложит вам спрятать изменения, если необходимо.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Правильный репозиторий | Вы должны запустить `--teleport` из checkout того же репозитория, не форка. Если вы запустите его из checkout другого репозитория, Claude Code показывает ошибку, которая называет как репозиторий сессии, так и репозиторий вашего checkout. До версии 2.1.219 ошибка не называла репозиторий вашего checkout. Если Claude Code не может разобрать ваш удалённый сервер в имя хоста, например псевдоним SSH хоста, такой как `git@work:owner/repo.git`, он просит вас подтвердить, и принимает checkout, когда владелец и имя репозитория удалённого сервера совпадают с репозиторием сессии. |
| Доступность ветки      | Ветка из облачной сессии должна быть отправлена на удалённый сервер. Телепортирование автоматически получает и извлекает её.                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Один и тот же аккаунт  | Вы должны быть аутентифицированы на том же аккаунте claude.ai, который использовался в облачной сессии.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

<h4 id="teleport-is-unavailable">
  `--teleport` недоступен
</h4>

Телепортирование требует аутентификации подписки claude.ai. Если вы аутентифицированы через API ключ, запустите `/login` для входа с вашим аккаунтом claude.ai вместо этого. Если ошибка называет вашего поставщика, облачные сессии недоступны через поставщиков третьей стороны; см. [таблицу ошибок](#output-and-errors). Если вы уже вошли через claude.ai и `--teleport` всё ещё недоступен, ваша организация может отключить облачные сессии.

<h2 id="work-with-sessions">
  Работа с сеансами
</h2>

Сеансы отображаются на боковой панели на claude.ai/code. Оттуда вы можете просмотреть изменения, поделиться с коллегами, архивировать завершённую работу или окончательно удалить сеансы.

<h3 id="take-back-a-queued-message">
  Отмена поставленного в очередь сообщения
</h3>

Если вы отправляете сообщение, пока Claude работает, сообщение ставится в очередь до тех пор, пока Claude его не прочитает. Чтобы отменить поставленное в очередь сообщение, нажмите на ✕. Текст вернётся в поле сообщения, чтобы вы могли его отредактировать или отправить что-то другое.

Если Claude уже прочитал сообщение, оно остаётся в беседе.

<h3 id="manage-context">
  Управление контекстом
</h3>

Облачные сеансы поддерживают [встроенные команды](/docs/ru/commands), которые выводят текстовый результат. Команды, которые работают только в интерфейсе терминала, такие как `/plugin` или `/resume`, недоступны. Команды, которые открывают средство выбора или панель в терминале, ведут себя иначе в облачных сеансах:

* **`/model`, `/effort`, `/color` и `/rename`**: передайте значение как аргумент, например `/model sonnet`, вместо открытия средства выбора терминала или ползунка. Формы аргументов требуют Claude Code v2.1.205 или более поздней версии в окружении сеанса и следуют [примечаниям доступности](/docs/ru/commands#all-commands) каждой команды.
* **`/fast`**: переключает [быстрый режим](/docs/ru/fast-mode#use-fast-mode-in-cloud-sessions) для сеанса, когда быстрый режим [доступен в вашей учётной записи](/docs/ru/fast-mode#requirements). Требует Claude Code v2.1.271 или более поздней версии в окружении сеанса.
* **`/config`**: в веб-версии открывает раздел Claude Code ваших параметров вместо установки значения, и текст после команды, включая `key=value`, игнорируется. Чтобы изменить параметр облачного сеанса, установите [переменную окружения](/docs/ru/cloud-environments#set-environment-variables) в окружении или в сеансе с одним репозиторием зафиксируйте ключ в файле `.claude/settings.json` этого репозитория. [Параметры в облачных сеансах](/docs/ru/settings#settings-in-cloud-sessions) перечисляет, что читает каждый сеанс.

Для управления контекстом в частности:

| Команда    | Работает в облачных сеансах | Примечания                                                                                                                         |
| :--------- | :-------------------------- | :--------------------------------------------------------------------------------------------------------------------------------- |
| `/compact` | Да                          | Суммирует беседу для освобождения контекста. Принимает необязательные инструкции фокуса, такие как `/compact keep the test output` |
| `/context` | Да                          | Показывает, что находится в окне контекста                                                                                         |
| `/clear`   | Нет                         | Вместо этого запустите новый сеанс с боковой панели                                                                                |

Автоматическое сжатие выполняется автоматически, когда окно контекста приближается к ёмкости. Облачные сеансы устанавливают [`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`](/docs/ru/env-vars) самостоятельно, поэтому сжатие срабатывает на полпути через [окно автоматического сжатия](/docs/ru/model-config#set-the-auto-compact-window), а не когда окно заполняется. Это значение переопределяет то, которое вы добавляете в ваши [переменные окружения](/docs/ru/cloud-environments#set-environment-variables), поэтому добавление переменной туда не изменяет, когда срабатывает сжатие.

Чтобы вместо этого изменить окно автоматического сжатия, установите [`CLAUDE_CODE_AUTO_COMPACT_WINDOW`](/docs/ru/env-vars) в ваши переменные окружения или запустите [`/autocompact`](/docs/ru/commands#all-commands) с количеством токенов в сеансе, где переменная не установлена.

[Подагенты](/docs/ru/sub-agents) работают так же, как локально. Claude может порождать их с помощью инструмента Agent для разгрузки исследований или параллельной работы в отдельное окно контекста, сохраняя основную беседу более лёгкой. Подагенты, определённые в `.claude/agents/` вашего репозитория, подхватываются автоматически.

[Команды агентов](/docs/ru/agent-teams) отключены по умолчанию, но могут быть включены путём добавления `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` в ваши [переменные окружения](/docs/ru/cloud-environments#set-environment-variables).

<h3 id="permission-modes-in-cloud-sessions">
  Режимы разрешений в облачных сеансах
</h3>

Вы выбираете [режим разрешений](/docs/ru/permission-modes) облачного сеанса из [раскрывающегося списка режима](/docs/ru/permission-modes#switch-permission-modes), как при создании задачи, так и во время выполнения сеанса. Когда вы повторно открываете сеанс, чьё размещённое на Anthropic [окружение истекло](#environment-expired), или отправляете сообщение в сеанс, который самостоятельно размещённый runner [освободил во время простоя](/docs/ru/self-hosted-environments-reference#runner-cli-flags), Claude Code возобновляет сеанс в режиме разрешений, в котором он находился.

<h3 id="review-changes">
  Просмотр изменений
</h3>

Каждый сеанс показывает индикатор diff с добавленными и удалёнными строками, например `+42 -18`. Выберите его, чтобы открыть представление diff, оставить встроенные комментарии к определённым строкам и отправить их Claude со следующим сообщением.

Представление diff сравнивает изменения сеанса с его базовой веткой по умолчанию. Чтобы сравнить с любой другой веткой в репозитории, выберите **Compare against** и выберите одну.

Claude Code вычисляет эти diffs, включая diffs для каждого файла, показанные при редактировании Claude, из необработанного содержимого git blob, поэтому драйверы diff и фильтры `textconv`, настроенные в репозитории, не применяются. Для файла в репозитории, который не является одной из собственных рабочих копий сеанса, например клонированного в рабочее пространство во время сеанса, diff для каждого файла показывает само редактирование Claude, а не сравнение git.

Полное пошаговое руководство, включая создание PR, см. в разделе [Просмотр и итерация](/docs/ru/web-quickstart#review-and-iterate). Чтобы Claude автоматически отслеживал PR на предмет сбоев CI и комментариев рецензии, см. [Автоматическое исправление pull requests](#auto-fix-pull-requests).

<h3 id="share-sessions">
  Совместное использование сеансов
</h3>

Чтобы поделиться сеансом, переключите его видимость в соответствии с типами учётных записей ниже. После этого поделитесь ссылкой на сеанс как есть. Получатели видят последнее состояние при открытии ссылки, но их представление не обновляется в реальном времени.

<h4 id="share-from-an-enterprise-or-team-account">
  Совместное использование из учётной записи Enterprise или Team
</h4>

Для учётных записей Enterprise и Team есть два варианта видимости: **Private** и **Team**. Видимость Team делает сеанс видимым для других членов вашей организации claude.ai. Сеансы [Claude в Slack](/docs/ru/slack) автоматически совместно используются с видимостью Team.

Проверка доступа к репозиторию включена по умолчанию на основе учётной записи GitHub, подключённой к учётной записи получателя. Отображаемое имя вашей учётной записи видно всем получателям с доступом.

<h4 id="share-from-a-max-or-pro-account">
  Совместное использование из учётной записи Max или Pro
</h4>

Для учётных записей Max и Pro есть два варианта видимости: **Private** и **Public**. Видимость Public делает сеанс видимым для любого пользователя, вошедшего в claude.ai.

Проверьте свой сеанс на наличие конфиденциального содержимого перед совместным использованием. Сеансы могут содержать код и учётные данные из приватных репозиториев GitHub. Проверка доступа к репозиторию не включена по умолчанию.

Чтобы потребовать от получателей наличие доступа к репозиторию или скрыть своё имя из совместно используемых сеансов, перейдите в [**Settings > Claude Code > Sharing settings**](https://claude.ai/settings/claude-code).

<h3 id="archive-sessions">
  Архивирование сеансов
</h3>

Вы можете архивировать сеансы, чтобы организовать список сеансов. Архивированные сеансы скрыты из списка сеансов по умолчанию, но могут быть просмотрены путём фильтрации архивированных сеансов.

Чтобы архивировать сеанс, наведите указатель на сеанс на боковой панели и выберите значок архива.

<h3 id="delete-sessions">
  Удаление сеансов
</h3>

Удаление сеанса окончательно удаляет сеанс и его данные. Это действие невозможно отменить. Вы можете удалить сеанс двумя способами:

* **С боковой панели**: отфильтруйте архивированные сеансы, затем наведите указатель на сеанс, который вы хотите удалить, и выберите значок удаления
* **Из меню сеанса**: откройте сеанс, выберите раскрывающееся меню рядом с названием сеанса и выберите **Delete**

Вам будет предложено подтвердить перед удалением сеанса.

<h2 id="auto-fix-pull-requests">
  Auto-fix pull requests
</h2>

Claude может наблюдать за pull request и автоматически реагировать на сбои CI и комментарии рецензентов. Claude подписывается на активность GitHub в PR, и когда проверка не пройдена или рецензент оставляет комментарий, Claude исследует и отправляет исправление, если оно очевидно.

<Note>
  Auto-fix требует установки приложения Claude GitHub в вашем репозитории. Если вы ещё этого не сделали, установите его со [страницы приложения GitHub](https://github.com/apps/claude).
</Note>

Есть несколько способов включить auto-fix в зависимости от того, откуда пришёл PR и какое устройство вы используете:

* **PR, созданные в облачной сессии**: откройте сессию на claude.ai/code, откройте строку статуса CI и выберите **Auto-fix**
* **Из вашего терминала**: запустите [`/autofix-pr`](/docs/ru/commands) на ветке PR. Claude Code обнаруживает открытый PR с помощью `gh`, порождает облачную сессию и включает auto-fix в один шаг
* **Из мобильного приложения**: скажите Claude автоматически исправить PR, например "watch this PR and fix any CI failures or review comments"
* **Любой существующий PR**: вставьте URL PR в сессию и скажите Claude автоматически исправить его

Auto-fix — это переключатель для каждого PR. Чтобы остановить мониторинг, откройте строку статуса CI в сессии на claude.ai/code и отключите переключатель **Auto-fix**, или скажите Claude прекратить наблюдение за PR.

<h3 id="how-claude-responds-to-pr-activity">
  Как Claude реагирует на активность PR
</h3>

Когда auto-fix активен, Claude получает события GitHub для PR, включая новые комментарии рецензентов и сбои проверок CI. Для каждого события Claude исследует и решает, как действовать:

* **Очевидные исправления**: если Claude уверен в исправлении и оно не конфликтует с более ранними инструкциями, Claude вносит изменение, отправляет его и объясняет, что было сделано в сессии
* **Неоднозначные запросы**: если комментарий рецензента может быть интерпретирован несколькими способами или касается чего-то архитектурно значимого, Claude спрашивает вас перед действием
* **Дублирующиеся или события без действия**: если событие является дубликатом или не требует изменений, Claude отмечает это в сессии и продолжает

GitHub не отправляет webhook, когда базовая ветка продвигается вперёд и создаёт конфликт слияния, поэтому auto-fix не может реагировать на конфликты самостоятельно. Чтобы разрешить конфликт, откройте сессию и попросите Claude выполнить rebase.

Claude может отвечать на потоки комментариев рецензентов на GitHub как часть их разрешения. Эти ответы публикуются с использованием вашего аккаунта GitHub, поэтому они появляются под вашим именем пользователя, но каждый ответ помечен как исходящий от Claude Code, чтобы рецензенты знали, что он был написан агентом, а не вами напрямую.

<Warning>
  Если ваш репозиторий использует автоматизацию, запускаемую комментариями, такую как Atlantis, Terraform Cloud или пользовательские GitHub Actions, которые запускаются на событиях `issue_comment`, имейте в виду, что Claude может отвечать от вашего имени, что может запустить эти рабочие процессы. Проверьте автоматизацию вашего репозитория перед включением auto-fix и рассмотрите отключение auto-fix для репозиториев, где комментарий PR может развернуть инфраструктуру или запустить привилегированные операции.
</Warning>

<h2 id="security-and-isolation">
  Безопасность и изоляция
</h2>

Каждая облачная сессия отделена от вашей машины и от других сессий через несколько слоёв:

* **Изолированные виртуальные машины**: каждая сессия запускается в изолированной, управляемой Anthropic виртуальной машине. Сессии, которые ваша организация маршрутизирует в [самостоятельно размещённое окружение](/docs/ru/self-hosted-environments), запускаются на вашей собственной инфраструктуре вместо этого, где изоляция — это ответственность вашего развёртывания
* <span id="default-allowed-domains" />**Элементы управления сетевым доступом**: в окружениях, размещённых Anthropic, сетевой доступ ограничен по умолчанию и может быть отключен. См. [Сетевой доступ](/docs/ru/cloud-environments#network-access) для уровней доступа, [доменов, разрешённых по умолчанию](/docs/ru/cloud-environments#default-allowed-domains), и трафика, который не проходит через список разрешений. В самостоятельно размещённом окружении вы ограничиваете исходящий трафик сессии на вашей собственной границе сети. При запуске с отключённым сетевым доступом Claude Code всё ещё может общаться с API Anthropic, что может позволить данным выйти из виртуальной машины.
* **Защита учётных данных**: в окружениях, размещённых Anthropic, учётные данные git и ключи подписи остаются вне песочницы, и прокси аутентифицирует от имени сессии с ограниченными учётными данными. В самостоятельно размещённом окружении ваше развёртывание предоставляет учётные данные git; см. [Configure git](/docs/ru/self-hosted-environments-deploy#configure-git)
* **API учётные данные**: в окружениях, размещённых Anthropic, на планах Pro и Max, ключи, которые вы [добавляете в облачное окружение](/docs/ru/cloud-environments#add-api-credentials), остаются вне песочницы так же, прикреплённые к совпадающим запросам после того, как они покидают сессию. Самостоятельно размещённое окружение не имеет API учётных данных, и планы Team и Enterprise их ещё не имеют
* **Безопасный анализ**: код анализируется и изменяется в изолированной среде сессии перед созданием PR

<h2 id="troubleshooting">
  Устранение неполадок
</h2>

Для ошибок API времени выполнения, которые появляются в разговоре, такие как `API Error: 500`, `529 Overloaded`, `429` или `Prompt is too long`, см. [Error reference](/docs/ru/errors). Эти ошибки и их исправления общие с CLI и Desktop app. Разделы ниже охватывают проблемы, специфичные для облачных сессий.

<h3 id="session-creation-failed">
  Session creation failed
</h3>

Если новая сессия не запускается с `Session creation failed` или зависает при подготовке, Claude Code не смог выделить виртуальную машину для сессии.

* Проверьте [status.claude.com](https://status.claude.com) на предмет инцидентов облачных сессий
* Повторите попытку через минуту, так как ёмкость подготавливается по требованию
* Подтвердите, что ваше подключение GitHub может достичь репозитория, следуя [No repositories appear after connecting GitHub](/docs/ru/web-quickstart#no-repositories-appear-after-connecting-github)

<h3 id="unable-to-get-organization-uuid">
  Unable to get organization UUID
</h3>

`claude --cloud` и `claude --teleport` требуют входа с аккаунтом claude.ai. Если вы аутентифицируетесь с помощью API ключа, или ваши сохранённые данные аккаунта устарели, эти команды не пройдут с `Unable to get organization UUID` или сообщением, что аутентификация API ключа недостаточна. При аутентификации API ключа или устаревших данных аккаунта, запуск `claude --teleport` без ID сессии показывает `Error loading Claude Code sessions` в выборе сессии вместо любого сообщения, и то же исправление применяется.

Запустите `/login` для входа с вашим аккаунтом claude.ai, затем повторите команду. Если ошибка называет вашего поставщика, см. [таблицу ошибок](#output-and-errors): облачные сессии недоступны через поставщиков третьей стороны.

<h3 id="remote-control-session-expired-or-access-denied">
  Remote Control session expired or access denied
</h3>

`--teleport` подключается через ту же инфраструктуру сессии Remote Control, которую используют облачные сессии, поэтому ошибки аутентификации и истечения сессии появляются с формулировкой Remote Control. Вы можете увидеть `Remote Control session expired` или `Access denied`. Токен соединения имеет короткий срок действия и ограничен вашим аккаунтом.

* Запустите `/login` локально для обновления ваших учётных данных, затем переподключитесь
* Подтвердите, что вы вошли в один и тот же аккаунт, который владеет сессией
* Если вы видите `Remote Control may not be available for this organization`, Owner не включил облачные сессии для вашей организации

<h3 id="environment-expired">
  Environment expired
</h3>

Облачные сессии останавливаются после периода неактивности и виртуальная машина сессии отзывается. Сессия считается неактивной, пока она ждёт вас для одобрения вызова инструмента [MCP connector](/docs/ru/cloud-environments#network-access) или для входа на сервер MCP, и она может истечь во время этого ожидания.

Переоткройте сессию из [claude.ai/code](https://claude.ai/code) для подготовки свежей виртуальной машины с восстановленной историей разговора. Фоновая работа, которая всё ещё выполнялась, когда виртуальная машина была отозвана, такая как subagents и shell команды, не восстанавливается.

<h2 id="limitations">
  Ограничения
</h2>

Перед тем как полагаться на облачные сессии для рабочего процесса, учтите эти ограничения:

* **Ограничения скорости**: облачные сессии делят ограничения скорости со всеми другими использованиями Claude и Claude Code в вашем аккаунте. Запуск нескольких задач параллельно потребляет больше ограничений скорости пропорционально. Нет отдельной платы за вычисления для облачной виртуальной машины.
* **Аутентификация репозитория**: вы можете перемещать облачную сессию в ваш терминал только когда вы аутентифицированы на одном и том же аккаунте
* **Ограничения платформы**: клонирование репозитория и создание pull request требуют GitHub. Самостоятельно размещённые экземпляры [GitHub Enterprise Server](/docs/ru/github-enterprise-server) поддерживаются для планов Team и Enterprise. Вы можете отправить репозиторий GitLab, Bitbucket или другой не-GitHub репозиторий в облачную сессию как [локальный пакет](#send-local-repositories-without-github), установив `CCR_FORCE_BUNDLE=1`, но сессия не может отправлять результаты обратно на удалённый сервер
* **Список разрешений IP организации**: облачные сессии вызывают API Anthropic из инфраструктуры, управляемой Anthropic, а не из вашей сети, пока сессии в [самостоятельно размещённом окружении](/docs/ru/self-hosted-environments) вызывают его из вашей собственной сети. Если ваша организация имеет [IP allowlisting](https://support.claude.com/en/articles/13200993-restrict-access-to-claude-with-ip-allowlisting) включённый, каждая облачная сессия, размещённая Anthropic, не пройдёт с ошибкой аутентификации. То же самое применяется к [Code Review](/docs/ru/code-review) и к [routines](/docs/ru/routines), которые запускаются на окружениях, размещённых Anthropic; routine, маршрутизированная в самостоятельно размещённое окружение, вызывает API из вашей собственной сети. Свяжитесь с [поддержкой Anthropic](https://support.claude.com/), чтобы список разрешений IP вашей организации не распространялся на размещённые Anthropic сервисы.
