# Держите Claude в работе над целью

> Установите условие завершения с помощью /goal, и Claude будет работать над его достижением, пока условие не будет выполнено, модель не сочтет его невозможным или ошибка, которую вам нужно исправить, не очистит цель.

Команда `/goal` устанавливает условие завершения, и Claude продолжает работать над его достижением без необходимости в ваших подсказках на каждом шаге. После каждого хода небольшая быстрая модель проверяет, выполняется ли условие. Если модель определит, что условие еще не выполнено, Claude начинает еще один ход вместо того, чтобы вернуть управление вам. Цель автоматически очищается после выполнения условия, если модель сочтет условие невозможным для удовлетворения или если ход завершится с [ошибкой, которую вам нужно исправить](#errors-you-have-to-fix-clear-the-goal).

Используйте цель для значительной работы с проверяемым конечным состоянием:

* Миграция модуля на новый API до тех пор, пока каждый вызов компилируется и тесты проходят
* Реализация документа дизайна до тех пор, пока все критерии приемки выполнены
* Разделение большого файла на сфокусированные модули до тех пор, пока каждый находится в пределах бюджета размера
* Работа через очередь помеченных проблем до тех пор, пока очередь не будет пуста

<h2 id="compare-ways-to-keep-a-session-running">
  Сравнение способов поддержания сеанса в работе
</h2>

Три подхода поддерживают текущий сеанс в работе между подсказками. Выбирайте в зависимости от того, что должно начать следующий ход:

| Подход                                                              | Следующий ход начинается когда                                                                                                                                                                    | Останавливается когда                                                                                                                                                                                                         |
| :------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/goal`                                                             | Предыдущий ход завершается, или, в интерактивном сеансе, наступает [проверка неактивности](#background-work-defers-evaluation) или [автоматический повтор](#other-errors-retry-or-pause-the-goal) | Модель подтверждает, что условие выполнено, или судит его невозможным, или ход завершается с [ошибкой, которую вы должны исправить](#errors-you-have-to-fix-clear-the-goal), или вы запускаете [`/goal clear`](#clear-a-goal) |
| [`/loop`](/docs/ru/scheduled-tasks#run-a-prompt-repeatedly-with-%2Floop) | Истекает временной интервал                                                                                                                                                                       | Вы его остановите, или Claude решит, что работа завершена                                                                                                                                                                     |
| [Stop hook](/docs/ru/hooks-guide#prompt-based-hooks)                     | Предыдущий ход завершается                                                                                                                                                                        | Ваш собственный скрипт или подсказка решает                                                                                                                                                                                   |

`/goal` и Stop hook оба срабатывают после каждого хода. `/goal` — это сокращение в области сеанса: вы вводите условие, и оно активно только для текущего сеанса. Stop hook находится в вашем файле настроек, применяется к каждому сеансу в его области и может запустить скрипт для детерминированных проверок или подсказку для оцениваемых моделью.

[Автоматический режим](/docs/ru/auto-mode-config) сам по себе одобряет вызовы инструментов в одном ходе, но не начинает новый. Claude останавливается, когда судит, что работа завершена. `/goal` добавляет отдельный оценщик, который проверяет ваше условие после каждого хода, поэтому завершение решается свежей моделью, а не той, которая выполняет работу. Эти два подхода дополняют друг друга: автоматический режим удаляет подсказки для каждого инструмента, а `/goal` удаляет подсказки для каждого хода.

<Tip>
  Описанные выше подходы поддерживают текущий сеанс в работе. Вы также можете планировать работу, которая выполняется независимо от любого открытого сеанса, например ночные тесты или утреннюю сортировку. См. [варианты планирования](/docs/ru/scheduled-tasks#compare-scheduling-options) для облачных процедур и запланированных задач на рабочем столе.
</Tip>

<h2 id="use-/goal">
  Использование `/goal`
</h2>

За сеанс может быть активна одна цель. Одна и та же команда устанавливает, проверяет и очищает ее в зависимости от аргумента.

<h3 id="set-a-goal">
  Установка цели
</h3>

Запустите `/goal` с условием, которое вы хотите выполнить. Если цель уже активна, новая заменит ее.

```text theme={null}
/goal all tests in test/auth pass and the lint step is clean
```

Установка цели немедленно начинает ход с самим условием в качестве директивы. Вам не нужно отправлять отдельную подсказку. Пока цель активна, индикатор `◎ /goal active` показывает, как долго цель работает.

Цель не изменяет режим разрешений. Чтобы позволить ходам цели работать без присмотра, запустите `/goal` в [режиме автоматизации](/docs/ru/auto-mode-config). В [ручном режиме](/docs/ru/permission-modes) Claude все еще запрашивает разрешение перед вызовами инструментов, которые ваши настройки еще не разрешают, например команда теста выше.

Пока цель активна, стенограмма показывает каждый вердикт, который возвращает оценщик, и вы можете нажать Ctrl+O, чтобы увидеть причину этого. Представление статуса также показывает самую последнюю причину, поэтому вы можете видеть, над чем Claude будет работать дальше.

<h3 id="write-an-effective-condition">
  Написание эффективного условия
</h3>

[Оценщик](#how-evaluation-works) судит ваше условие по тому, что Claude выявил в разговоре. Он не запускает команды и не читает файлы независимо, поэтому напишите условие как что-то, что может продемонстрировать собственный результат Claude. "Все тесты в `test/auth` проходят" работает, потому что Claude запускает тесты и результат попадает в стенограмму для оценщика.

Условие, которое выполняется на протяжении многих ходов, обычно имеет:

* **Одно измеримое конечное состояние**: результат теста, код выхода сборки, количество файлов, пустая очередь
* **Указанную проверку**: как Claude должен это доказать, например "`npm test` выходит 0" или "`git status` чист"
* **Ограничения, которые имеют значение**: все, что не должно изменяться на пути туда, например "никакой другой файл теста не изменяется"

Условие может быть до 4000 символов.

Чтобы ограничить, как долго работает цель, включите в условие пункт о ходе или времени, например `or stop after 20 turns`. Claude сообщает о прогрессе по этому пункту на каждом ходе, и оценщик судит его из разговора.

<h3 id="check-status">
  Проверка статуса
</h3>

Запустите `/goal` без аргументов, чтобы увидеть текущее состояние.

```text theme={null}
/goal
```

Если цель активна, статус показывает:

* Условие
* Как долго оно работает
* Сколько ходов было оценено
* Текущие затраты токенов
* Самое последнее объяснение оценщика

Количество ходов и самое последнее объяснение появляются после первого запуска оценки.

Если цель не активна, но одна была достигнута ранее в сеансе, статус показывает достигнутое условие вместе с его продолжительностью, количеством ходов и затратами токенов.

<h3 id="clear-a-goal">
  Очистка цели
</h3>

Запустите `/goal clear`, чтобы удалить активную цель до выполнения ее условия.

```text theme={null}
/goal clear
```

Claude выводит `Goal cleared:` с последующим условием для подтверждения или `No goal set`, если ничего не было активно.

`stop`, `off`, `reset`, `none` и `cancel` принимаются как псевдонимы для `clear`. Запуск `/clear` для начала нового разговора также удаляет любую активную цель.

<h3 id="resume-with-an-active-goal">
  Возобновление с активной целью
</h3>

Когда вы возобновляете сеанс, Claude Code восстанавливает цель, которая была еще активна при завершении сеанса. Claude Code восстанавливает ее на каждом маршруте возобновления: `--continue`, `--resume` с идентификатором сеанса, именем или [путем файла стенограммы](/docs/ru/sessions#resume-a-session), и [средство выбора сеанса](/docs/ru/sessions#use-the-session-picker). До версии 2.1.239 Claude Code восстанавливал цель на каждом маршруте, кроме средства выбора `claude --resume`.

Claude Code переносит условие, но сбрасывает количество ходов, таймер и базовую линию затрат токенов. Он не восстанавливает цель, которая уже была достигнута или очищена.

<h3 id="run-non-interactively">
  Запуск неинтерактивно
</h3>

`/goal` работает в [неинтерактивном режиме](/docs/ru/headless), в [приложении для рабочего стола](/docs/ru/desktop) и через [Remote Control](/docs/ru/remote-control). Установка цели с `-p` запускает цикл до завершения в одном вызове:

```bash theme={null}
claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"
```

При выводе текста по умолчанию ничего не выводится до завершения выполнения, поэтому цель, которая работает много ходов, может выглядеть зависшей. Добавьте `--output-format stream-json --verbose`, чтобы выводить каждое сообщение по мере выполнения цикла.

Прервите процесс с помощью Ctrl+C, чтобы остановить неинтерактивную цель до выполнения условия.

<h2 id="how-evaluation-works">
  Как работает оценка
</h2>

`/goal` — это оболочка вокруг [prompt-based Stop hook](/docs/ru/hooks#prompt-based-hooks) в области сеанса. Каждый раз, когда Claude завершает ход, Claude Code отправляет условие и разговор до сих пор на ваш настроенный [небольшой быстрый модель](/docs/ru/model-config), который по умолчанию является Haiku на Claude API; у поставщика третьей стороны проверьте вашу [страницу поставщика](/docs/ru/third-party-integrations) для получения стандартного значения платформы. Модель возвращает один из трёх вердиктов, каждый с кратким объяснением:

* **Ещё не выполнено**: Claude продолжает работу и принимает объяснение в качестве руководства для следующего хода.
* **Выполнено**: Claude Code очищает цель и записывает достигнутую запись в стенограмму.
* **Невозможно**: оценщик определил, что условие никогда не может быть выполнено. Claude Code очищает цель и записывает неудачную запись в стенограмму вместе с объяснением. Вам не нужно очищать её самостоятельно.

Если Claude продолжает отвечать оценщику без прогресса (отсутствие использования инструментов в течение нескольких ходов подряд), Claude Code останавливает цикл, выводит предупреждение и возвращает управление вам с установленной целью. Оценка возобновляется после вашего следующего запроса. [Руководство по hooks](/docs/ru/hooks-guide#stop-hook-hits-the-block-cap) объясняет основной механизм.

<h3 id="when-a-turn-fails">
  Когда ход завершается ошибкой
</h3>

Когда ход завершается ошибкой, Claude Code очищает цель, если ошибка — это та, которую вы должны исправить. После любой другой ошибки цель остаётся установленной.

<h4 id="errors-you-have-to-fix-clear-the-goal">
  Ошибки, которые вы должны исправить, очищают цель
</h4>

Если ход завершается ошибкой, которая не будет очищена, пока вы её не исправите, Claude Code очищает цель и выводит предупреждение, называя причину. Предупреждение начинается с `Goal cleared after an unrecoverable error` и заканчивается с `Run /goal again to continue`. Исправьте причину, затем [установите цель снова](#set-a-goal) с помощью `/goal <condition>`. Четыре вида отказа очищают цель:

* Ошибка аутентификации, когда Claude Code управляет своими собственными учётными данными. Когда хост управляет ими для вас, например в приложении для рабочего стола, расширении VS Code или [облачном сеансе](/docs/ru/claude-code-on-the-web), Claude Code оставляет цель активной, потому что хост восстанавливает доступ самостоятельно.
* Исчерпанный баланс кредитов
* Переполнение контекста, которое [auto-compact](/docs/ru/model-config#set-the-auto-compact-window) не смог очистить
* Модель, которая недоступна

<h4 id="other-errors-retry-or-pause-the-goal">
  Другие ошибки повторяют попытку или приостанавливают цель
</h4>

После любого другого отказа цель остаётся установленной. В интерактивном сеансе на Claude Code v2.1.269 или позже Claude Code также выводит строку, называющую причину, и либо повторяет попытку самостоятельно, либо ждёт вас:

* **Повторить попытку**: после отказа, который имеет тенденцию очищаться самостоятельно, например перегруженный сервер или разорванное соединение, уведомление, начинающееся с `Goal still active`, показывает ожидание перед следующей попыткой. После трёх автоматических повторных попыток цель вместо этого приостанавливается.
* **Приостановить**: после отказа, который повторная попытка только повторит, например ограничение скорости API, [лимит использования](/docs/ru/errors#youve-hit-your-session-limit) claude.ai или hook, который завершил ход, уведомление, начинающееся с `Goal paused`, называет причину. Если сеанс [ожидает автоматического продолжения при сбросе лимита использования](/docs/ru/interactive-mode#wait-for-a-usage-limit-to-reset), Claude возобновляет работу над целью тогда.

Отправьте сообщение в любое время, чтобы начать следующий ход немедленно. Чтобы отключить автоматические повторные попытки, установите [`CLAUDE_CODE_GOAL_CHECKIN_MINUTES`](/docs/ru/env-vars) на `0`, что также отключает [проверки](#background-work-defers-evaluation).

<h3 id="background-work-defers-evaluation">
  Фоновая работа откладывает оценку
</h3>

Если подагент или фоновая команда shell всё ещё выполняется, когда ход заканчивается, Claude Code пропускает оценку для этого хода. Он оценивает в конце следующего хода, который завершается без выполнения фоновой работы. Когда фоновая работа завершается, Claude Code доставляет результат Claude как новый ход, поэтому вам не нужно отправлять запрос.

Как только фоновая работа удерживает цель в ожидании в течение 30 минут, требуется проверка. При проверке Claude Code перечисляет выполняющиеся задачи и просит Claude прочитать их вывод, продолжить ожидание, если они прогрессируют, и исправить или остановить любые, которые застряли. После первой проверки Claude Code ждёт в два раза дольше перед каждой последующей проверкой, вплоть до четырёхкратного первого интервала: с значением по умолчанию, 1 час после первой проверки, затем каждые 2 часа. Claude Code доставляет должную проверку, первая включена, одним из двух способов:

* **Когда ход заканчивается**: Claude Code доставляет проверку в конце следующего хода, который завершается с выполняющейся работой. В неинтерактивном сеансе, например запущенном с `-p`, это единственный способ доставки проверок Claude Code.
* **Пока сеанс неактивен**: в интерактивном сеансе Claude Code также запускает ход самостоятельно для доставки проверки вместо ожидания вашего следующего запроса. Если фоновая работа остановилась без сообщения результата, Claude Code просит Claude продолжить работу над целью. Claude Code запускает максимум три неактивные проверки на цель между вашими запросами. При третьей неактивной проверке Claude Code говорит, что неактивные проверки приостановлены до тех пор, пока вы не отправите другой запрос. До v2.1.246 неактивные проверки были неограниченными. Неактивные проверки требуют Claude Code v2.1.236 или позже.

До v2.1.239 только неактивные проверки отступали таким образом; проверка, доставленная в конце хода, повторялась с первым интервалом.

Чтобы изменить первый интервал, установите [`CLAUDE_CODE_GOAL_CHECKIN_MINUTES`](/docs/ru/env-vars). Claude Code использует ваше значение вместо 30-минутного интервала и масштабирует более поздние интервалы с ним. Установите его на `0`, чтобы отключить проверки и [автоматические повторные попытки](#other-errors-retry-or-pause-the-goal).

Проверки требуют Claude Code v2.1.234 или позже.

<h3 id="evaluation-model-and-cost">
  Модель оценки и стоимость
</h3>

Чтобы оценить на другой модели, установите [`ANTHROPIC_DEFAULT_HAIKU_MODEL`](/docs/ru/model-config#environment-variables).

<Warning>
  Claude Code читает `ANTHROPIC_DEFAULT_HAIKU_MODEL` везде, где он использует небольшую быструю модель, не только для оценки `/goal`. Когда вы устанавливаете его, Claude Code также разрешает [alias `haiku`](/docs/ru/model-config#model-aliases) этой модели и запускает [фоновую функциональность](/docs/ru/costs#background-token-usage), такую как суммирование разговора, на ней.
</Warning>

Оценщик работает на любом поставщике, на котором настроен ваш сеанс. Он не вызывает инструменты, поэтому может судить только то, что Claude уже выявил в разговоре.

<Note>
  Токены оценки выставляются на счет небольшой быстрой модели, настроенной для вашего поставщика, и обычно незначительны по сравнению с основными затратами хода.
</Note>

<h2 id="requirements">
  Требования
</h2>

Claude Code делает `/goal` доступным в соответствии с тем же [правилом доверия рабочей области, что и для hooks в файлах параметров](/docs/ru/permissions#what-runs-before-you-trust-a-folder), потому что оценщик является частью системы hooks. `/goal` также недоступен, когда [`disableAllHooks`](/docs/ru/hooks#disable-or-remove-hooks) имеет значение `true` после применения приоритета параметров, или когда [`allowManagedHooksOnly`](/docs/ru/settings-reference#allowmanagedhooksonly) установлен в управляемых параметрах. В каждом случае команда сообщает вам причину вместо того, чтобы молча ничего не делать.
