# Настройте ваш терминал для Claude Code

> Исправьте Shift+Enter для новых строк, получайте звуковой сигнал терминала при завершении Claude, настройте tmux, сопоставьте цветовую схему и включите режим Vim в CLI Claude Code.

Claude Code работает в любом терминале без конфигурации. Эта страница предназначена для случаев, когда что-то конкретное ведёт себя не так, как вы ожидаете. Найдите вашу проблему ниже. Если всё уже работает правильно, вам не нужна эта страница.

* [Shift+Enter отправляет вместо вставки новой строки](#enter-multiline-prompts)
* [Сочетания клавиш с Option на macOS ничего не делают](#enable-option-key-shortcuts-on-macos)
* [Нет звука или оповещения при завершении Claude](#get-a-terminal-bell-or-notification)
* [Вы запускаете Claude Code внутри tmux](#configure-tmux)
* [Backspace удаляет целое слово на Windows](#fix-backspace-deleting-a-whole-word-on-windows)
* [Дисплей мерцает или прокрутка истории прыгает](#switch-to-fullscreen-rendering)
* [Вы хотите использовать клавиши Vim в приглашении](#edit-prompts-with-vim-keybindings)

Эта страница посвящена тому, чтобы ваш терминал отправлял правильные сигналы в Claude Code. Чтобы изменить, на какие клавиши реагирует сам Claude Code, см. вместо этого [сочетания клавиш](/docs/ru/keybindings).

<h2 id="enter-multiline-prompts">
  Ввод многострочных подсказок
</h2>

Нажатие Enter отправляет ваше сообщение. Чтобы добавить разрыв строки без отправки, нажмите Ctrl+J или введите `\` и затем нажмите Enter. Оба способа работают в любом терминале без настройки.

В большинстве терминалов вы также можете нажать Shift+Enter, но поддержка зависит от эмулятора терминала:

| Терминал                                                                                              | Shift+Enter для новой строки                                     |
| :---------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------- |
| Ghostty, Kitty, iTerm2, WezTerm, Warp, Apple Terminal, Windows Terminal                               | Работает без настройки                                           |
| Другие терминалы, поддерживающие протокол клавиатуры kitty, такие как foot и Alacritty 0.16 или позже | Работает без настройки. Требуется Claude Code v2.1.269 или позже |
| VS Code, Cursor, Devin Desktop, Alacritty до версии 0.16, Zed                                         | Запустите `/terminal-setup` один раз                             |
| gnome-terminal, JetBrains IDEs такие как PyCharm и Android Studio                                     | Недоступно; используйте Ctrl+J или `\` затем Enter               |

Для VS Code, Cursor, Devin Desktop, Alacritty до версии 0.16 и Zed, `/terminal-setup` записывает сочетание клавиш Shift+Enter в файл конфигурации терминала. При первом запуске вы видите подтверждение, например `Installed VSCode terminal Shift+Enter key binding`. Существующие сочетания клавиш остаются на месте; если вы видите сообщение, например `VSCode terminal Shift+Enter key binding already configured`, изменений не было внесено. Запустите `/terminal-setup` непосредственно в хост-терминале, а не внутри tmux или screen, так как ему нужно записать в конфигурацию хост-терминала.

В VS Code, Cursor и Devin Desktop, `/terminal-setup` также обновляет два параметра редактора: он устанавливает `terminal.integrated.gpuAcceleration` на `"off"` для предотвращения искажённого текста в интегрированном терминале и устанавливает `terminal.integrated.mouseWheelScrollSensitivity` для более плавной прокрутки в [полноэкранном режиме](/docs/ru/fullscreen). Чтобы отменить изменение ускорения GPU, установите его обратно на `"auto"` и перезагрузите окно редактора.

В Zed, `/terminal-setup` обновляет ваш `keymap.json` на месте:

* Если keymap уже содержит сочетания клавиш и ни одно из них не является Terminal `shift-enter`, Claude Code сначала создаёт его резервную копию в том же каталоге, например `keymap.json.1a2b3c4d.bak`, затем объединяет сочетание клавиш Shift+Enter в ваш keymap, сохраняя ваши другие сочетания клавиш и комментарии
* Если Claude Code не может прочитать или разобрать keymap, не может создать резервную копию или не может проверить объединённый результат, он [оставляет файл без изменений и выводит блок сочетания клавиш для добавления вручную](/docs/ru/errors#terminal-setup-left-your-zed-keymap-unchanged)

Если вы работаете внутри tmux, Shift+Enter также требует [конфигурацию tmux ниже](#configure-tmux) даже когда внешний терминал её поддерживает.

Чтобы привязать новую строку к другой клавише или поменять поведение так, чтобы Enter вставлял новую строку, а Shift+Enter отправлял, сопоставьте действия `chat:newline` и `chat:submit` в вашем [файле сочетаний клавиш](/docs/ru/keybindings).

<h2 id="enable-option-key-shortcuts-on-macos">
  Включение сочетаний клавиш с клавишей Option на macOS
</h2>

Некоторые сочетания клавиш Claude Code используют клавишу Option, например Option+Enter для новой строки или Option+P для переключения моделей. На macOS большинство терминалов по умолчанию не отправляют Option в качестве модификатора, поэтому эти сочетания клавиш не работают, пока вы их не включите. Параметр терминала для этого обычно называется "Use Option as Meta Key"; Meta — это историческое название Unix для клавиши, которая теперь называется Option или Alt.

<Tabs>
  <Tab title="Apple Terminal">
    Откройте Settings → Profiles → Keyboard и установите флажок "Use Option as Meta Key".

    Если вы приняли приглашение Claude Code для первоначальной настройки терминала, это уже сделано. Это приглашение запускает `/terminal-setup` для вас, что включает Option как Meta и отключает звуковой сигнал в вашем профиле Apple Terminal.

    В [режиме чтения с экрана](/docs/ru/accessibility) `/terminal-setup` оставляет параметр звонка без изменений, чтобы звонок терминала оставался слышимым. До версии 2.1.211 `/terminal-setup` отключал звонок даже в режиме чтения с экрана. Если более ранний запуск отключил звонок, включите его снова в Settings → Profiles → Advanced → "Audible bell".
  </Tab>

  <Tab title="iTerm2">
    Откройте Settings → Profiles → Keys → General и установите Left Option key и Right Option key на "Esc+".

    Запуск `/terminal-setup` в iTerm2 включает "Applications in terminal may access clipboard" в Settings → General → Selection, чтобы команда `/copy` могла писать в буфер обмена вашей системы. Команда обнаруживает iTerm2 даже при запуске изнутри tmux. Перезагрузите iTerm2, чтобы изменение вступило в силу.
  </Tab>

  <Tab title="VS Code">
    Добавьте `"terminal.integrated.macOptionIsMeta": true` в ваши параметры VS Code.
  </Tab>
</Tabs>

Для Ghostty, Kitty и других терминалов ищите параметр Option-as-Alt или Option-as-Meta в файле конфигурации терминала.

<h2 id="get-a-terminal-bell-or-notification">
  Получение звонка терминала или уведомления
</h2>

Когда Claude завершает задачу или ждёт разрешения, и вы, похоже, отошли от терминала, он отправляет событие уведомления. Смотрите [когда срабатывает каждый тип уведомления](/docs/ru/hooks#notification) для точного времени. Отображение этого как звонка терминала или уведомления рабочего стола позволяет вам переключиться на другую работу, пока выполняется длительная задача.

По умолчанию Claude Code отправляет уведомление рабочего стола только в Ghostty, Kitty и iTerm2. В других терминалах установите [`preferredNotifChannel`](/docs/ru/settings-reference#preferrednotifchannel) на `"terminal_bell"` для звонка терминала, или настройте [Notification hook](#play-a-sound-with-a-notification-hook) для пользовательского звука или команды. Следующая запись параметров включает звонок терминала:

```json ~/.claude/settings.json theme={null}
{
  "preferredNotifChannel": "terminal_bell"
}
```

Уведомление рабочего стола достигает вашей локальной машины через SSH, поэтому удалённый сеанс всё ещё может вас оповестить. Ghostty и Kitty перенаправляют его в центр уведомлений вашей ОС без дополнительной настройки. iTerm2 требует включения перенаправления:

<Steps>
  <Step title="Откройте параметры уведомлений iTerm2">
    Перейдите в Settings → Profiles → Terminal.
  </Step>

  <Step title="Включите оповещения">
    Установите флажок "Notification Center Alerts", затем нажмите "Filter Alerts" и включите "Send escape sequence-generated alerts".
  </Step>
</Steps>

Если уведомления по-прежнему не появляются, убедитесь, что приложение вашего терминала имеет разрешение на уведомления в параметрах ОС, и если вы работаете внутри tmux, [включите passthrough](#configure-tmux).

<h3 id="play-a-sound-with-a-notification-hook">
  Воспроизведение звука с помощью Notification hook
</h3>

В любом терминале вы можете настроить [Notification hook](/docs/ru/hooks-guide#get-notified-when-claude-needs-input) для воспроизведения звука или запуска пользовательской команды, когда Claude нуждается в вашем внимании. Hooks работают наряду со встроенным уведомлением, а не заменяют его, поэтому терминалы, которые не получают уведомление рабочего стола, такие как Warp или встроенный терминал VS Code, могут использовать hook или установить `preferredNotifChannel` на `"terminal_bell"` вместо этого.

Пример ниже воспроизводит системный звук на macOS. Связанное руководство содержит команды уведомлений рабочего стола для macOS, Linux и Windows.

```json ~/.claude/settings.json theme={null}
{
  "hooks": {
    "Notification": [
      {
        "hooks": [{ "type": "command", "command": "afplay /System/Library/Sounds/Glass.aiff" }]
      }
    ]
  }
}
```

<h2 id="configure-tmux">
  Настройка tmux
</h2>

Когда Claude Code работает внутри tmux, по умолчанию Shift+Enter отправляет вместо вставки новой строки, и уведомления рабочего стола и [индикатор прогресса](/docs/ru/settings-reference#terminalprogressbarenabled) никогда не достигают внешнего терминала. Добавьте эти строки в `~/.tmux.conf`, затем запустите `tmux source-file ~/.tmux.conf`, чтобы применить их к работающему серверу:

```bash ~/.tmux.conf theme={null}
set -g allow-passthrough on
set -s extended-keys on
set -as terminal-features 'xterm*:extkeys'
```

Строка `allow-passthrough` позволяет уведомлениям и обновлениям прогресса достигать внешнего терминала вместо того, чтобы быть поглощенными tmux. Строки `extended-keys` позволяют tmux различать Shift+Enter и простой Enter, чтобы сочетание клавиш для новой строки работало.

<h2 id="fix-backspace-deleting-a-whole-word-on-windows">
  Исправление удаления целого слова при нажатии Backspace на Windows
</h2>

На Windows Claude Code читает Backspace, поступающий как `^H`, как Ctrl+Backspace, который [удаляет предыдущее слово](/docs/ru/interactive-mode#text-editing), за исключением случаев, когда `TERM_PROGRAM` имеет значение `mintty` или `TERM` имеет значение `cygwin`. На macOS и Linux Claude Code читает его как обычный Backspace.

Если каждое нажатие Backspace удаляет целое слово, ваш терминал отправляет `^H` для обычного Backspace. Установите [`CLAUDE_CODE_BS_AS_CTRL_BACKSPACE=0`](/docs/ru/env-vars). Backspace и Ctrl+H затем стирают по одному символу каждый. Если Ctrl+Backspace стирает только один символ на macOS или Linux, потому что ваш терминал отправляет `^H` для него, установите переменную на `1` вместо этого.

<h2 id="match-the-color-theme">
  Подберите цветовую тему
</h2>

Используйте команду `/theme` или средство выбора темы в `/config`, чтобы выбрать тему Claude Code, которая соответствует вашему терминалу. Выбор опции auto автоматически определяет светлый или тёмный фон вашего терминала, поэтому тема следует изменениям внешнего вида ОС всякий раз, когда это делает ваш терминал. Claude Code не контролирует собственную цветовую схему терминала, которая устанавливается приложением терминала.

Чтобы настроить, что отображается в нижней части интерфейса, настройте [пользовательскую строку состояния](/docs/ru/statusline), которая показывает текущую модель, рабочий каталог, ветку git или другой контекст.

<h3 id="create-a-custom-theme">
  Создайте пользовательскую тему
</h3>

Помимо встроенных предустановок, `/theme` отображает все определённые вами пользовательские темы и любые темы, предоставленные установленными [plugins](/docs/ru/plugins/components#themes-and-output-styles). Выберите **New custom theme…** в конце списка, чтобы создать её интерактивно: вы назовёте тему, а затем выберете отдельные цветовые токены для переопределения. Нажмите `Ctrl+E`, пока выделена пользовательская тема, чтобы отредактировать её.

Каждая пользовательская тема — это JSON-файл в `~/.claude/themes/`. Имя файла без расширения `.json` — это слаг темы, а выбор темы сохраняет `custom:<slug>` как ваше предпочтение темы. Файл имеет три необязательных поля:

| Поле        | Тип    | Описание                                                                                                                                                       |
| :---------- | :----- | :------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`      | string | Метка отображения, показываемая в `/theme`. По умолчанию используется слаг имени файла                                                                         |
| `base`      | string | Встроенная предустановка, с которой начинается тема: `dark`, `light`, `dark-daltonized`, `light-daltonized`, `dark-ansi` или `light-ansi`. По умолчанию `dark` |
| `overrides` | object | Карта имён цветовых токенов на значения цветов. Токены, не указанные здесь, переходят к базовой предустановке                                                  |

Значения цветов принимают `#rrggbb`, `#rgb`, `rgb(r,g,b)`, `ansi256(n)` или `ansi:<name>`, где `<name>` — одно из 16 стандартных имён цветов ANSI, таких как `red` или `cyanBright`. Неизвестные токены и недопустимые значения цветов игнорируются, поэтому опечатка не может нарушить отрисовку.

Следующий пример определяет тему, которая сохраняет тёмную предустановку, но перекрашивает акцент приглашения, текст ошибки и текст успеха:

```json ~/.claude/themes/dracula.json theme={null}
{
  "name": "Dracula",
  "base": "dark",
  "overrides": {
    "claude": "#bd93f9",
    "error": "#ff5555",
    "success": "#50fa7b"
  }
}
```

Claude Code отслеживает `~/.claude/themes/` и перезагружается при добавлении или изменении файла, поэтому изменения, внесённые в вашем редакторе, применяются к работающему сеансу без перезагрузки. Если папка `~/.claude/themes/` не существовала при запуске Claude Code, перезагрузитесь один раз после создания первого файла темы. После этого изменения применяются без перезагрузки.

Справочник ниже охватывает токены, которые вы можете установить в `overrides`. Интерактивный редактор в `/theme` показывает те же токены с живым предпросмотром, плюс несколько специализированных акцентов, таких как цвета экрана адаптации, которые здесь опущены.

<Accordion title="Справочник цветовых токенов">
  Следующий пример объединяет токены из нескольких групп ниже: фирменный акцент, границу режима плана, фоны diff и фон сообщения.

  ```json ~/.claude/themes/midnight.json theme={null}
  {
    "name": "Midnight",
    "base": "dark",
    "overrides": {
      "claude": "#a78bfa",
      "planMode": "#38bdf8",
      "diffAdded": "#14532d",
      "diffRemoved": "#7f1d1d",
      "userMessageBackground": "#1e1b4b"
    }
  }
  ```

  <h4 id="fullscreen-mode">
    Полноэкранный режим
  </h4>

  Claude Code рисует `userMessageBackground`, `bashMessageBackgroundColor` и `memoryBackgroundColor` как в средстве отрисовки по умолчанию, так и в полноэкранном. Он использует `userMessageBackgroundHover` и `selectionBg` только в [режиме полноэкранной отрисовки](/docs/ru/fullscreen).

  | Токен                        | Управляет                                            |
  | :--------------------------- | :--------------------------------------------------- |
  | `userMessageBackground`      | Фон позади ваших сообщений в стенограмме             |
  | `userMessageBackgroundHover` | Фон позади сообщения при наведении или развёртывании |
  | `bashMessageBackgroundColor` | Фон позади записей команд оболочки `!` в стенограмме |
  | `memoryBackgroundColor`      | Фон позади записей памяти `#` в стенограмме          |
  | `selectionBg`                | Фон текста, выбранного мышью                         |

  <h4 id="usage-meter-and-speaker-labels">
    Счётчик использования и метки динамика
  </h4>

  Отрегулируйте полосу, показываемую в представлении `/usage`, и метки, которые отличают ваши сообщения от сообщений Claude.

  | Токен              | Управляет                                   |
  | :----------------- | :------------------------------------------ |
  | `rate_limit_fill`  | Заполненная часть счётчика использования    |
  | `rate_limit_empty` | Незаполненная часть счётчика использования  |
  | `briefLabelYou`    | Цвет метки `You` на ваших сообщениях        |
  | `briefLabelClaude` | Цвет метки `Claude` на сообщениях помощника |

  <h4 id="shimmer-variants-and-subagent-colors">
    Варианты shimmer и цвета подагентов
  </h4>

  Несколько токенов имеют парный вариант shimmer, который предоставляет более светлый цвет, используемый в анимированном градиенте спиннера. Переопределите shimmer вместе с его базовым токеном, если анимация выглядит несовместимой.

  * `claude` и `claudeShimmer`
  * `warning` и `warningShimmer`
  * `permission` и `permissionShimmer`
  * `promptBorder` и `promptBorderShimmer`
  * `inactive` и `inactiveShimmer`
  * `fastMode` и `fastModeShimmer`

  Каждый [subagent](/docs/ru/sub-agents) и параллельная задача отображаются в одном из восьми именованных цветов, чтобы вы могли отличить их в стенограмме. Имена токенов следуют шаблону `<color>_FOR_SUBAGENTS_ONLY`, где `<color>` — это `red`, `blue`, `green`, `yellow`, `purple`, `orange`, `pink` или `cyan`. Переопределите их, чтобы изменить внешний вид каждого именованного цвета. Например, подагент с `color: blue` в его определении отрисовывается с использованием значения `blue_FOR_SUBAGENTS_ONLY`.

  Claude Code отрисовывает ключевое слово [`ultrathink`](/docs/ru/model-config#use-ultrathink-for-one-off-deep-reasoning) во входных данных приглашения с семицветным радужным градиентом. Имена токенов следуют шаблону `rainbow_<color>` и `rainbow_<color>_shimmer`, где `<color>` — это `red`, `orange`, `yellow`, `green`, `blue`, `indigo` или `violet`.
</Accordion>

<h2 id="switch-to-fullscreen-rendering">
  Переключение на полноэкранный рендеринг
</h2>

В [режиме чтения с экрана](/docs/ru/accessibility) этот раздел не применяется. Claude Code всегда отображается как обычный прокручиваемый текст, кроме присоединённых [фоновых сеансов](/docs/ru/agent-view), и если вы запустите `/tui fullscreen` в любом другом сеансе, Claude Code выведет объяснение вместо переключения.

Если дисплей мерцает или позиция прокрутки прыгает во время работы Claude, переключитесь на [режим полноэкранного рендеринга](/docs/ru/fullscreen). В этом режиме вы прокручиваете с помощью мыши или PageUp внутри Claude Code, а не с помощью встроенной прокрутки вашего терминала; см. [страницу полноэкранного режима](/docs/ru/fullscreen#search-and-review-the-conversation) для получения информации о поиске и копировании.

Если мерцание — единственная проблема и ваш терминал поддерживает синхронизированный вывод, но не определяется автоматически, например Emacs `eat`, установите [`CLAUDE_CODE_FORCE_SYNC_OUTPUT=1`](/docs/ru/env-vars), чтобы остановить мерцание без изменения рендеров.

Запустите `/tui fullscreen` для переключения и сохранения предпочтения. Ваш разговор перезапустится в целости и сохранности, и будущие сеансы начнутся в полноэкранном режиме, если только [полноэкранный запуск не завершится ошибкой](/docs/ru/fullscreen#fullscreen-renderer-didnt-finish-starting). Вы также можете установить переменную окружения `CLAUDE_CODE_NO_FLICKER` перед запуском Claude Code:

<CodeGroup>
  ```bash Bash and Zsh theme={null}
  CLAUDE_CODE_NO_FLICKER=1 claude
  ```

  ```powershell PowerShell theme={null}
  $env:CLAUDE_CODE_NO_FLICKER = "1"; claude
  ```

  ```json ~/.claude/settings.json theme={null}
  {
    "env": {
      "CLAUDE_CODE_NO_FLICKER": "1"
    }
  }
  ```
</CodeGroup>

<h2 id="paste-large-content">
  Вставка большого содержимого
</h2>

Когда вы вставляете более 800 символов или более трёх строк в подсказку, Claude Code сворачивает ввод в заполнитель, например `[Pasted text #1 +120 lines]`, чтобы поле ввода оставалось удобным для использования, и по-прежнему отправляет полное содержимое при отправке. Для очень больших входных данных, таких как целые файлы или длинные журналы, запишите содержимое в файл и попросите Claude прочитать его вместо вставки. Стенограмма разговора остаётся читаемой, и Claude может ссылаться на файл по пути в более поздних ходах. Интегрированный терминал VS Code также может отбросить символы из очень больших вставок, прежде чем они достигнут Claude Code, поэтому используйте там файл.

Если вставка содержит [невидимые символы Unicode](/docs/ru/interactive-mode#invisible-characters-in-prompts), Claude Code удаляет их при нажатии Enter и возвращает очищенную подсказку в поле ввода для отправки с помощью другого Enter.

<h3 id="how-claude-treats-pasted-text">
  Как Claude обрабатывает вставленный текст
</h3>

При отправке Claude видит содержимое за каждым заполнителем `[Pasted text #N]`, отмеченным как текст, который вы вставили откуда-то, а не напечатали. Claude сообщается, что вставка может содержать инструкции, которые вы не писали, и следовать инструкциям внутри неё только там, где сообщение, которое вы напечатали, это просит. В сеансах, которые не [получают флаги функций](/docs/ru/env-vars#features-that-need-feature-flag-fetching), вставки не отмечаются.

<h3 id="delete-and-restore-a-collapsed-paste">
  Удаление и восстановление свёрнутой вставки
</h3>

Когда вы удаляете с помощью сочетания клавиш для слова или строки, такого как `Ctrl+W` или `Ctrl+K`, или с помощью удаления vim через движение `f`/`t`, такое как `df]`, и удаляемый диапазон достигает внутри заполнителя `[Pasted text #N]`, Claude Code удаляет заполнитель целиком. Чтобы восстановить его, вставьте удаление обратно с помощью [`Ctrl+Y`](/docs/ru/interactive-mode#text-editing) после сочетания клавиш для слова или строки, или с помощью [`p` в режиме NORMAL](/docs/ru/interactive-mode#editing-normal-mode) после удаления vim.

<h3 id="recall-a-prompt-that-had-pasted-text">
  Вызов подсказки с вставленным текстом
</h3>

Claude Code хранит содержимое за каждым заполнителем `[Pasted text #N]` в `~/.claude/paste-cache/`, поэтому когда вы вызываете подсказку из [истории команд](/docs/ru/interactive-mode#command-history) и повторно отправляете её, полное вставленное содержимое отправляется снова, включая в более позднем сеансе.

Файлы кэша старше [`cleanupPeriodDays`](/docs/ru/settings-reference#cleanupperioddays) удаляются в соответствии с [правилами развёртки очистки](/docs/ru/claude-directory#cleaned-up-automatically), поэтому вызванная подсказка может ссылаться на вставленный текст, который больше не существует. Когда вы отправляете такую подсказку, Claude Code никогда не отправляет буквальную строку `[Pasted text #N]` и показывает уведомление с названием отсутствующей вставки:

* В простой подсказке с оставшимся текстом Claude Code удаляет заполнитель и отправляет оставшийся текст.
* В [команде режима shell](/docs/ru/interactive-mode#shell-mode-with-prefix) или команде `/`, где удаление изменило бы то, что выполняется, и в любой подсказке, где удаление оставляет пусто, Claude Code отменяет отправку и сохраняет исходный текст в вводе с заполнителем, всё ещё находящимся в нём. Удалите заполнитель или отредактируйте команду, затем повторно отправьте.

<h2 id="edit-prompts-with-vim-keybindings">
  Редактирование подсказок с сочетаниями клавиш Vim
</h2>

Claude Code включает режим редактирования в стиле Vim для ввода подсказок. Включите его через `/config` → Editor mode или установив [`editorMode`](/docs/ru/settings-reference#editormode) на `"vim"` в `~/.claude/settings.json`. Установите Editor mode обратно на `normal`, чтобы отключить его.

Режим Vim поддерживает подмножество движений и операторов режимов NORMAL и VISUAL, таких как навигация `hjkl`, выделение `v`/`V` и `d`/`c`/`y` с текстовыми объектами. Полную таблицу клавиш см. в [справочнике режима редактора Vim](/docs/ru/interactive-mode#vim-editor-mode).

Движения Vim не переназначаются через файл сочетаний клавиш. Чтобы сопоставить двухклавишную последовательность режима INSERT, такую как `jj`, с Escape, установите [`vimInsertModeRemaps`](/docs/ru/interactive-mode#remap-insert-mode-key-sequences) в параметрах пользователя.

Нажатие Enter по-прежнему отправляет вашу подсказку в режиме INSERT, в отличие от стандартного Vim. Используйте `o` или `O` в режиме NORMAL или Ctrl+J, чтобы вставить новую строку.
