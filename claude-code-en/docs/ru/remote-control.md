# Продолжайте локальные сеансы с любого устройства с помощью Remote Control

> Продолжайте локальный сеанс Claude Code со своего телефона, планшета или любого браузера, используя Remote Control. Работает с claude.ai/code и мобильным приложением Claude.

<Note>
  Remote Control доступен на всех планах. На планах Team и Enterprise он отключен по умолчанию до тех пор, пока владелец не включит переключатель Remote Control в [параметрах администратора Claude Code](https://claude.ai/admin-settings/claude-code).
</Note>

Remote Control подключает [claude.ai/code](https://claude.ai/code) или приложение Claude для [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) и [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude) к сеансу Claude Code, работающему на вашем компьютере. Начните задачу за столом, а затем продолжите её со своего телефона на диване или в браузере на другом компьютере.

Когда вы запускаете сеанс Remote Control на своем компьютере, Claude продолжает работать локально всё время, поэтому выполнение кода и доступ к файловой системе остаются на вашем компьютере. С помощью Remote Control вы можете:

* **Использовать полную локальную среду удалённо**: ваша файловая система, [MCP servers](/docs/ru/mcp), инструменты и конфигурация проекта остаются доступными, и ввод `@` автоматически дополняет пути файлов из вашего локального проекта.
* **Работать с обеих поверхностей одновременно**: беседа и прогресс [subagents](/docs/ru/sub-agents) и [dynamic workflows](/docs/ru/workflows) остаются синхронизированными на всех подключённых устройствах, поэтому вы можете отправлять сообщения из терминала, браузера и телефона взаимозаменяемо.
* **Отправлять изображения и файлы со своего телефона или браузера**: прикрепляйте фотографию или файл в приложение Claude или на claude.ai/code с подписью или без неё. Claude видит прикреплённые фотографии непосредственно как часть вашего сообщения. Claude Code загружает другие файлы на ваш компьютер и передаёт их Claude как ссылки на файлы `@`.
* **Пережить перебои**: если ваш ноутбук перейдёт в режим сна или сетевое соединение разорвётся, Claude Code автоматически переподключится, когда ваш компьютер вернётся в сеть. Во время восстановления соединения Claude Code ставит в очередь сообщения, запросы разрешений и обновления статуса от subagents и workflows, и доставляет их после восстановления соединения.

В отличие от [Claude Code в веб-версии](/docs/ru/claude-code-on-the-web), которая работает на облачной инфраструктуре, сеансы Remote Control работают непосредственно на вашем компьютере и взаимодействуют с вашей локальной файловой системой. Веб- и мобильные интерфейсы — это просто окно в этот локальный сеанс.

На этой странице рассматриваются настройка, способы запуска и подключения к сеансам, а также сравнение Remote Control с Claude Code в веб-версии.

<h2 id="requirements">
  Требования
</h2>

Перед использованием Remote Control убедитесь, что ваша среда соответствует этим условиям:

* **Подписка**: доступна на планах Pro, Max, Team и Enterprise. API ключи не поддерживаются. На планах Team и Enterprise владелец должен сначала включить переключатель Remote Control в [параметрах администратора Claude Code](https://claude.ai/admin-settings/claude-code).
* **Аутентификация**: запустите `claude` и используйте `/login` для входа через claude.ai, если вы ещё этого не сделали. Без подходящей учётной записи `claude remote-control` завершится с ошибкой, в то время как `claude --remote-control` всё ещё запустит интерактивный сеанс и покажет уведомление об ошибке Remote Control вскоре после запуска.
* **Конечная точка API**: недоступна в любой из этих конфигураций:
  * Вы используете Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry.
  * Вы указываете [`ANTHROPIC_BASE_URL`](/docs/ru/env-vars) на хост, отличный от `api.anthropic.com`, например на [LLM gateway](/docs/ru/llm-gateway) или прокси. Отключите переменную, чтобы использовать Remote Control. До версии 2.1.196 Claude Code позволял использовать Remote Control с пользовательским `ANTHROPIC_BASE_URL`.
  * Вы входите через корпоративный [Claude apps gateway](/docs/ru/claude-apps-gateway).
* **Оценка флага функции**: [`DISABLE_TELEMETRY`, `DO_NOT_TRACK`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` и `DISABLE_GROWTHBOOK`](/docs/ru/env-vars) каждая отключает оценку флага функции, от которой зависит доступность Remote Control. Отключите переменную везде, где она установлена, в переменных окружения вашей оболочки или в блоке `env` файла [`settings.json`](/docs/ru/settings-reference#all-settings), чтобы использовать Remote Control.
* **Доверие рабочей области**: запустите `claude` в каталоге вашего проекта хотя бы один раз, чтобы принять диалог доверия рабочей области. Диалог доверия при запуске никогда не сохраняет доверие для вашего домашнего каталога, поэтому запустите Remote Control из каталога проекта.

<h2 id="start-a-remote-control-session">
  Запуск сеанса Remote Control
</h2>

Вы можете запустить сеанс Remote Control из CLI или расширения VS Code. CLI предлагает три режима вызова; VS Code использует команду `/remote-control`.

<Tabs>

Ответьте `y`, чтобы принять и запустить сервер. Если вы отклоните, Claude Code выходит без запуска сервера и спросит снова в следующий раз, когда вы запустите команду.

    ```text theme={null}
    /remote-control
    ```

<h3 id="check-connection-status">
  Проверка статуса подключения
</h3>

В интерактивном сеансе, пока Remote Control подключён, терминал показывает индикатор `/rc active`, который ссылается на сеанс на claude.ai. Индикатор скрывается, когда терминал слишком узкий, чтобы его вместить. Чтобы увидеть URL сеанса и QR-код для [подключения с другого устройства](#connect-from-another-device), запустите `/remote-control` снова, чтобы открыть панель статуса. Панель также позволяет вам отключить Remote Control, пока ваш локальный сеанс продолжает работу.

<span id="session-ended-elsewhere" />Если подключение не удаётся в интерактивном сеансе, индикатор изменяется, чтобы показать сбой, и Claude Code показывает причину в уведомлении и добавляет её в беседу. Запустите `/remote-control` для переподключения, если только причина не говорит, что сеанс был перехвачен или завершён в другом месте:

* **Another connection took over this session**: другое устройство или сеанс Claude Code теперь имеет его. Запустите `/remote-control` только если вы хотите вернуть его.
* **This session was ended or archived from another device or app**: запустите `/remote-control` только если вы хотите его вернуть. Claude Code повторно открывает архивированный сеанс.
* **The server no longer reports this session**: он мог быть удалён с другого устройства или приложения.

<h3 id="session-url-reminders">
  Напоминания об URL сеанса
</h3>

Пока Remote Control подключён, Claude Code напоминает вам об URL сеанса при переключении на ваш телефон или браузер, что помогает больше всего, поэтому вам не нужно искать ссылку в `/remote-control`. Напоминание появляется над полем подсказки в одном из этих моментов:

* **Длительный ход**: когда ход выполняется дольше, чем настроенный на сервере порог, Claude Code показывает уведомление **Still working** со ссылкой **Check in from your phone**, чтобы вы могли следить за ходом со своего телефона или браузера вместо ожидания в терминале. Claude Code удаляет его, когда ход завершается.
* **Повторяющиеся подсказки разрешений**: после того как вы ответите на несколько [подсказок разрешений](/docs/ru/permissions) в сеансе, появляется уведомление **Approve tool calls from your phone** с URL сеанса. Claude Code удаляет его, когда начинается ваш следующий ход.

Напоминания могут появляться в любом подключённом сеансе, включая те, где Remote Control [подключается автоматически](#enable-remote-control-for-all-sessions). Они не появляются каждый раз, когда возникают эти условия, и каждое появляется только несколько раз в целом по сеансам. Вы не можете их настраивать или отключать; каждое очищается самостоятельно.

<h3 id="connect-from-another-device">
  Подключение с другого устройства
</h3>

После активации сеанса Remote Control у вас есть несколько способов подключиться с другого устройства:

* **Откройте URL сеанса** в любом браузере, чтобы перейти непосредственно к сеансу на [claude.ai/code](https://claude.ai/code).
* **Отсканируйте QR-код**, показанный рядом с URL сеанса, чтобы открыть его непосредственно в приложении Claude. С помощью `claude remote-control` нажмите пробел, чтобы переключить отображение QR-кода.
* **Откройте [claude.ai/code](https://claude.ai/code) или приложение Claude** и найдите сеанс по имени в списке сеансов. В мобильном приложении Claude нажмите **Code** в навигации, чтобы перейти к списку сеансов. Сеансы Remote Control показывают значок компьютера с зелёной точкой статуса при подключении.

Когда вы подключаетесь, устройство показывает любых подагентов и рабочие процессы, которые сеанс уже имеет, работающие в фоновом режиме. Остановите один из них с устройства, и Claude Code остановит эту задачу на вашем компьютере.

Название удалённого сеанса выбирается в следующем порядке:

1. Имя, которое вы передали в `--name`, `--remote-control` или `/remote-control`
2. Название, которое вы установили с помощью `/rename`
3. Последнее значимое сообщение в существующей истории беседы
4. Автоматически сгенерированное имя вроде `myhost-graceful-unicorn`, где `myhost` — это имя хоста вашего компьютера или префикс, который вы установили с помощью `--remote-control-session-name-prefix`

Если вы не установили явное имя, Claude Code обновляет название, чтобы отразить вашу подсказку после её отправки. Claude Code сопоставляет автоматически сгенерированные названия с языком вашей беседы, или с параметром [`language`](/docs/ru/settings-reference#language), если он настроен.

Когда вы переименовываете сеанс из claude.ai или приложения Claude, Claude Code также обновляет локальное название, показанное в `claude --resume`. Claude Code применяет то же переименование к названию сеанса, показанному на панели подсказки, и в списке `claude agents`, когда сеанс [работает в фоновом режиме](/docs/ru/agent-view). До версии 2.1.221 переименование из списка сеансов на claude.ai или в приложении Claude обновляло только название, а CLI сохранял своё предыдущее имя сеанса; `/rename`, который работает в самом CLI, устанавливает имя на любой версии.

Если у вас ещё нет приложения Claude, используйте команду `/mobile` внутри Claude Code, чтобы показать QR-код для [claude.ai/mobile](https://claude.ai/mobile), который открывает правильный магазин приложений для вашего телефона.

<h3 id="what-connected-devices-see">
  Что видят подключённые устройства
</h3>

Подключённое устройство показывает беседу в вашем терминале по мере её развития. Эти случаи выходят за рамки обычных сообщений:

* **Компактирование и `/clear`**: пока Claude Code [компактирует беседу](/docs/ru/context-window#what-survives-compaction), подключённые устройства показывают прогресс, а затем где была компактирована беседа. Когда вы запускаете `/clear`, беседа сбрасывается и на подключённых устройствах тоже.
* **Переключение бесед с помощью `/resume`**: подключённое устройство не получает название переключённой беседы или её более раннюю историю, но новые сообщения в обе стороны идут в ту беседу, которая открыта в вашем терминале, и из неё. Чтобы снова работать с исходной беседой с устройства, запустите `/resume` в вашем терминале и переключитесь обратно на неё.
* **Извлечение сеанса с помощью `/teleport`**: когда вы извлекаете [сеанс Claude Code в веб-версии](/docs/ru/claude-code-on-the-web#from-cloud-to-terminal) в свой терминал с помощью `/teleport`, подключённое устройство не получает более раннюю историю извлечённой беседы. Новые сообщения в обе стороны идут в извлечённую беседу, которая теперь открыта в вашем терминале.
* **Сообщения из ваших других сеансов**: с [кросс-сеансовой передачей сообщений](/docs/ru/cross-session-messaging) одно и то же соединение переносит сообщения между вашими собственными сеансами на разных машинах и из ваших [сеансов Claude Code в веб-версии](/docs/ru/claude-code-on-the-web), через серверы Anthropic, как и остальной трафик Remote Control. [Отправка сообщений в сеансы на других машинах](/docs/ru/cross-session-messaging#message-sessions-on-other-machines) охватывает правила доставки, а [Управление входящими сообщениями](/docs/ru/cross-session-messaging#control-inbound-messages) охватывает управление входящими. Требует Claude Code версии 2.1.224 или позже.
* **Подсказки, которые вы отправляете в середине хода**: когда вы отправляете подсказку с подключённого устройства до завершения текущего хода, Claude Code ставит её в очередь и сохраняет её в стенограмме устройства после завершения этого хода.
* **Diff ваших изменений**: когда каталог сеанса находится в репозитории git, панель diff подключённого устройства показывает ваши изменения. Устройство запрашивает diff по соединению, и Claude Code вычисляет его на вашем компьютере. На ветке, которая имеет коммиты впереди ветви по умолчанию репозитория, панель показывает изменения с момента расхождения ветви, включая ваши незафиксированные правки. На самой ветви по умолчанию или на ветви, которая не впереди неё, панель показывает только ваши незафиксированные изменения. До версии 2.1.247 Claude Code сообщал diff подключённым устройствам только в сеансах, обслуживаемых `claude remote-control`.
* **Модель**: когда вы выбираете [модель](/docs/ru/model-config) с подключённого устройства, Claude Code запускает сеанс на этой модели. Средство выбора `/model` терминала, `/status` и `/config` показывают эту модель. Требует Claude Code версии 2.1.238 или позже.
  * Модель, которую вы выбираете из управления моделью устройства, применяется только к текущему сеансу. Когда вы отправляете `/model <name>` с устройства в интерактивный сеанс, Claude Code также устанавливает вашу стандартную модель для новых сеансов.
  * Если вы отправляете имя, которое Claude Code не распознаёт, например отображаемое имя, где ожидается ID модели, Claude Code [отказывает в выборе](/docs/ru/errors#model-is-not-a-recognized-model-id) и сеанс сохраняет свою текущую модель. До версии 2.1.260 Claude Code сохранял нераспознанный выбор из управления моделью устройства, и ваше следующее сообщение не удавалось.
* **Уровень усилий**: когда вы устанавливаете [уровень усилий](/docs/ru/model-config#adjust-effort-level) с подключённого устройства, с помощью `/effort` или управления усилиями устройства, Claude Code применяет его к сеансу на вашем компьютере, и claude.ai/code показывает уровень, который использует сеанс. Если вы закрепили уровень с помощью `CLAUDE_CODE_EFFORT_LEVEL`, сеанс сохраняет этот уровень, и Claude Code отказывает в другом выборе из управления усилиями. Выбор уровня из управления усилиями требует Claude Code версии 2.1.234 или позже на вашем компьютере.
* **Переподключение после сбоя подключения**: запустите `/remote-control` для переподключения. Если компактирование переписало беседу или вы переключили беседы с помощью `/resume` в то же время, Claude Code архивирует сеанс сервера, который он использовал, вместо того чтобы оставлять его в списке сеансов. Вы всё ещё можете найти его, [фильтруя архивированные сеансы](/docs/ru/claude-code-on-the-web#archive-sessions). Переключение бесед, пока устройство всё ещё подключено, не архивирует сеанс.

<h3 id="enable-remote-control-for-all-sessions">
  Включение Remote Control для всех сеансов
</h3>

Remote Control активируется только при явном запуске `claude remote-control`, `claude --remote-control` или `/remote-control`, если не включена автоподключение. Чтобы включить автоподключение для каждого интерактивного сеанса, запустите `/config` внутри Claude Code и установите **Enable Remote Control for all sessions**. Переключатель принимает три значения:

* **`true`**: подключаться автоматически при запуске интерактивного сеанса.
* **`false`**: отключить автоподключение, хотя `true` из [управляемых параметров](/docs/ru/managed-settings) имеет приоритет, потому что Claude Code сохраняет выбор в ваши пользовательские параметры. `false` в параметрах проекта или локальных параметрах (`.claude/settings.json`, `.claude/settings.local.json`) отключает автоподключение даже над управляемым `true`.
* **`default`**: очистить ваш выбор и следовать стандартному значению администратора вашей организации, если оно установлено, иначе текущему стандартному значению Claude Code.

Тот же переключатель появляется вне CLI:

* **Приложение Desktop**: **Settings > Claude Code > Enable remote control by default**.
* **Расширение VS Code**: **Enable Remote Control for all sessions** в разделе Settings [меню команд](/docs/ru/vs-code#use-the-prompt-box). Требует Claude Code версии 2.1.203 или позже.

Чтобы включить автоподключение из файла параметров вместо этого, установите [`remoteControlAtStartup`](/docs/ru/settings-reference#remotecontrolatstartup) на `true` в вашем пользовательском файле `~/.claude/settings.json` или в [управляемых параметрах](/docs/ru/managed-settings). В параметрах проекта или локальных параметрах (`.claude/settings.json`, `.claude/settings.local.json`) Claude Code соблюдает `false` и отключает автоподключение для этого репозитория, но игнорирует `true`, поэтому зафиксированный файл не может включить Remote Control для всех, кто открывает репозиторий.

Автоподключение входит с вашей собственной учётной записью claude.ai, поэтому сеанс, который оно запускает, появляется только в приложениях Claude вашей собственной учётной записи и не предоставляет доступ никому другому.

С этой настройкой каждый интерактивный процесс Claude Code регистрирует один удалённый сеанс. Если вы запустите несколько экземпляров, каждый получит свой собственный удалённый сеанс. Чтобы запустить несколько одновременных сеансов из одного процесса, используйте [режим сервера](#start-a-remote-control-session) вместо этого.

<h3 id="resume-sessions-after-stopping-the-server">
  Возобновление сеансов после остановки сервера
</h3>

Когда вы останавливаете `claude remote-control` с помощью Ctrl+C, сеансы, которые он обслуживал, перестают отвечать с вашего телефона или браузера. Пока вы не запускали другой `claude remote-control` в том же каталоге и не запустили этот с `--no-create-session-in-dir`, Claude Code их не архивирует. Чтобы вернуть их, запустите одну из этих команд в том же каталоге:

* **`claude remote-control`**: возвращает каждый сеанс, который обслуживал сервер.
* **`claude remote-control --continue`**: возвращает только сеанс, который сервер запустил, и выходит, когда этот сеанс завершается. Если в этом каталоге нет записи, Claude Code использует самый новый из других git worktrees этого репозитория.
* **`claude remote-control --session-id <id>`**: возвращает только сеанс, чей ID вы передали, и выходит, когда этот сеанс завершается. ID — это часть URL сеанса на claude.ai/code между `/code/` и любым `?`.

Эти команды работают примерно четыре часа после остановки сервера. После этого запустите `claude remote-control` для запуска нового сеанса. Если вы архивировали сеанс в то же время, `--continue` и `--session-id` разархивируют его на Claude Code версии 2.1.228 или позже.

Чтобы вернуть сеанс, который вы запустили с помощью `claude --remote-control` или `/remote-control`, возобновите беседу с помощью `claude --continue` или `claude --resume`. Переподключится ли Claude Code и к какому сеансу, зависит от [записи переподключения](#resume-outcomes) беседы.

Если вы возобновляете беседу во втором терминале, пока первый всё ещё имеет Remote Control включённым, Claude Code выводит уведомление во втором терминале и оставляет Remote Control отключённым там вместо того чтобы забирать сеанс с первого. Пока Remote Control остаётся отключённым там, Claude в этом терминале не видит [ваши сеансы на других машинах](/docs/ru/cross-session-messaging#see-which-sessions-claude-can-reach), и они не могут его достичь. Запустите `/remote-control` во втором терминале, чтобы переместить Remote Control туда.

Когда вы возобновляете беседу в Claude Desktop или расширении IDE, которое имело Remote Control включённым, Claude Code переподключает его к существующему сеансу claude.ai вместо добавления нового в список сеансов.

<h2 id="connection-and-security">
  Подключение и безопасность
</h2>

Ваш локальный сеанс Claude Code выполняет только исходящие HTTPS запросы и никогда не открывает входящие порты на вашем компьютере. Когда вы запускаете Remote Control, он регистрируется в API Anthropic и опрашивает работу. Когда вы подключаетесь с другого устройства, сервер маршрутизирует сообщения между веб-клиентом или мобильным клиентом и вашим локальным сеансом через потоковое соединение.

Весь трафик проходит через API Anthropic через TLS, тот же транспортный протокол безопасности, что и любой сеанс Claude Code. Соединение использует несколько краткосрочных учётных данных, каждое из которых ограничено одной целью и истекает независимо. Когда учётные данные регистрации сервера `claude remote-control` истекают, сервер снова регистрируется в API Anthropic и продолжает обслуживать свои сеансы.

Пока Remote Control подключен, стенограмма сеанса, включая ваши сообщения, ответы Claude и активность инструментов, хранится на серверах Anthropic. Сохраненная стенограмма синхронизирует беседу на всех ваших устройствах и позволяет сеансу переподключиться после разрыва сети. Выполнение и доступ к файловой системе остаются на вашем компьютере, а сохраненные стенограммы хранятся в соответствии с политикой [Использование данных](/docs/ru/data-usage).

Чтобы полностью отключить Remote Control, используйте параметр [`disableRemoteControl`](/docs/ru/settings-reference#disableremotecontrol). Организации с требованиями соответствия, такими как Zero Data Retention, не могут включить Remote Control.

<h2 id="trusted-devices">
  Доверенные устройства
</h2>

<Note>
  Доверенные устройства в настоящее время находятся в бета-версии. Функции и возможности могут развиваться по мере совершенствования опыта.

  Доверенные устройства доступны на планах Pro, Max, Team и Enterprise и отключены по умолчанию. На планах Team и Enterprise владелец включает эту функцию для организации. На планах Pro и Max вы сами включаете **Require trusted devices** в своих параметрах на странице Cowork или Account.
</Note>

Доверенные устройства требуют от каждого члена вашей организации или только от вас на плане Pro или Max проверить своё устройство перед тем, как они смогут просматривать или управлять сеансами Remote Control из claude.ai, мобильных приложений Claude или Claude Desktop. Это связывает доступ Remote Control с известным устройством и недавней аутентификацией, а не просто с подписанной учётной записью.

Когда параметр включен, взаимодействие с сеансом Remote Control требует обоих следующих условий:

* **Зарегистрированное устройство**: каждый браузер, телефон или приложение для рабочего стола, которое член использует для Remote Control, регистрирует свои собственные учётные данные. Регистрация предлагается только вскоре после полного входа, поэтому устройство присоединяется к списку доверенных как часть реальной аутентификации, а не молча в фоновом режиме.
* **Недавний вход**: вход члена должен быть не старше 18 часов. Вместо входа каждый день члены подтверждают присутствие с помощью Face ID, Touch ID, Windows Hello или passkey. Этот биометрический шаг повышения уровня немедленно обновляет сеанс.

Биометрические проверки выполняются на устройстве через операционную систему или браузер, тот же механизм, что и вход с passkey. Anthropic никогда не получает и не хранит отпечатки пальцев, данные лица или любую другую биометрическую информацию. Хранятся только открытый ключ устройства и основные метаданные, такие как отображаемое имя, платформа и время регистрации.

Параметр применяется только к Remote Control. Обычный чат Claude, Claude Code в терминале и использование API не затронуты.

<h3 id="enable-trusted-devices-for-your-organization">
  Включение доверенных устройств для организации Team или Enterprise
</h3>

Владелец включает параметр из параметров организации claude.ai.

<Steps>
  <Step title="Перейдите на страницу Capabilities">
    Перейдите на [**Organization settings > Capabilities > Remote sessions**](https://claude.ai/admin-settings/capabilities). Переключатель **Require trusted devices** появляется в этом разделе.
  </Step>

  <Step title="Включите Require trusted devices">
    Параметр применяется к каждому члену организации и к сеансам Remote Control, запущенным после включения переключателя. Сеансы, которые уже работали до включения переключателя, не защищены задним числом и продолжают работать без требования устройства до их завершения. Область действия для каждой команды или проекта недоступна.
  </Step>

  <Step title="Сообщите членам, чего ожидать">
    В первый раз, когда член просматривает или управляет новым сеансом Remote Control из браузера, телефона или приложения для рабочего стола после включения параметра, ему предлагается зарегистрировать это устройство. Предварительное уведомление избегает путаницы.
  </Step>
</Steps>

<h3 id="what-members-see">
  Что видят члены
</h3>

Регистрация — это одноразовый шаг для каждого устройства. После этого единственное видимое изменение — это случайный биометрический запрос.

* **Первое использование на каждом устройстве**: члену предлагается зарегистрировать устройство. Если его вход не свежий, он сначала входит через ваш обычный процесс, включая SSO, если настроен, а затем подтверждает регистрацию.
* **День за днём**: члены с зарегистрированным устройством и свежим входом не видят никаких запросов. Когда вход становится старше 18 часов, следующее взаимодействие Remote Control показывает один запрос Face ID, Touch ID, Windows Hello или passkey.
* **Незарегистрированные устройства**: сеансы Remote Control не могут быть просмотрены или управляться до регистрации устройства. Обычный чат Claude на этом устройстве не затронут.
* **Без аутентификатора платформы**: члены на машине без Face ID, Touch ID или Windows Hello могут использовать аппаратный ключ безопасности или войти снова вместо повышения уровня.
* **В терминале**: машина, на которой работает Claude Code, получает свои собственные учётные данные автоматически, когда разработчик входит в CLI. В терминале нет отдельного шага регистрации.

<h3 id="manage-enrolled-devices">
  Управление зарегистрированными устройствами
</h3>

Члены могут просматривать и отзывать свои собственные устройства из параметров учётной записи.

Откройте [claude.ai/settings/account](https://claude.ai/settings/account#trusted-devices) и найдите раздел **Trusted devices**, чтобы увидеть каждое зарегистрированное устройство с его именем, платформой и датой регистрации. Удаление устройства немедленно отзывает его учётные данные, и устройство может повторно зарегистрироваться позже после свежего входа. Учётные данные также истекают самостоятельно, если не обновляются, поэтому неиспользуемое устройство автоматически исчезает из списка доверенных.

Для потерянного или украденного устройства член удаляет его с этой страницы. Если член не может войти, администратор может использовать **Sign out everywhere** в консоли администратора, чтобы отозвать каждый сеанс и зарегистрированное устройство для этого члена, после чего член повторно регистрирует устройства, которые он всё ещё держит.

<h2 id="remote-control-vs-cloud-sessions">
  Remote Control в сравнении с облачными сеансами
</h2>

Remote Control и [облачные сеансы](/docs/ru/claude-code-on-the-web) оба используют интерфейс claude.ai/code. Ключевое различие заключается в том, где работает сеанс: Remote Control выполняется на вашем компьютере, поэтому ваши локальные MCP servers, инструменты и конфигурация проекта остаются доступными. Облачный сеанс выполняется в облачной инфраструктуре, управляемой Anthropic по умолчанию.

Используйте Remote Control, когда вы находитесь в процессе локальной работы и хотите продолжить с другого устройства. Используйте облачный сеанс, когда вы хотите начать задачу без какой-либо локальной настройки, работать с репозиторием, который у вас не клонирован, или запустить несколько задач параллельно.

<h2 id="mobile-push-notifications">
  Мобильные push-уведомления
</h2>

Когда Remote Control активен, Claude может отправлять push-уведомления на ваш телефон.

Claude решает, когда отправить уведомление. Обычно он отправляет одно, когда завершается долгоживущая задача или когда ему нужно решение от вас для продолжения. Вы также можете запросить push в своей подсказке, например `notify me when the tests finish`. Помимо двух переключателей включения/отключения ниже, нет конфигурации для каждого события.

Чтобы настроить мобильные push-уведомления:

<Steps>
  <Step title="Установите мобильное приложение Claude">
    Загрузите приложение Claude для [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) или [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude).
  </Step>

  <Step title="Войдите с помощью своей учётной записи Claude Code">
    Используйте ту же учётную запись и организацию, которые вы используете для Claude Code в терминале.
  </Step>

  <Step title="Разрешите уведомления">
    Примите запрос разрешения на уведомления от операционной системы.
  </Step>

  <Step title="Включите push в Claude Code">
    В вашем терминале запустите `/config` и включите **Push when Claude decides** для проактивных уведомлений, **Push when actions required** для запросов разрешений и вопросов или оба варианта.
  </Step>
</Steps>

Если уведомления не приходят:

* Если `/config` показывает **No mobile registered**, откройте приложение Claude на своем телефоне, чтобы оно могло обновить свой токен push. Предупреждение исчезает при следующем подключении Remote Control.
* На iOS режимы Focus и сводки уведомлений могут подавлять или задерживать push-уведомления. Проверьте Settings → Notifications → Claude.
* На Android агрессивная оптимизация батареи может задержать доставку. Исключите приложение Claude из оптимизации батареи в системных параметрах.

Claude Code пропускает мобильные push-уведомления, пока вы печатаете или сосредоточены на подключённом терминале. Начиная с версии v2.1.181, вы можете установить [`CLAUDE_CLIENT_PRESENCE_FILE`](/docs/ru/env-vars) на путь файла-маркера, чтобы расширить это на любое время, когда вы находитесь у машины, даже в другом окне: уведомления пропускаются, пока файл существует. Настройте прослушиватель блокировки экрана или аналогичный инструмент для создания файла при разблокировке экрана и удаления его при блокировке экрана.

<h2 id="limitations">
  Ограничения
</h2>

* **Один удалённый сеанс на интерактивный процесс**: вне режима сервера каждый экземпляр Claude Code поддерживает один удалённый сеанс одновременно. Используйте [режим сервера](#start-a-remote-control-session) для запуска нескольких одновременных сеансов из одного процесса.
* **Локальный процесс должен продолжать работать**: Remote Control работает как локальный процесс. Если вы закроете терминал, выйдете из VS Code или иным образом остановите процесс `claude`, сеанс перейдёт в автономный режим до тех пор, пока вы не [восстановите его](#resume-sessions-after-stopping-the-server). Если Claude не находится в процессе выполнения задачи, claude.ai и приложение Claude показывают сеанс как автономный в течение нескольких секунд после завершения процесса. Чтобы сеанс продолжал работать на удалённой машине после отключения от SSH, запустите его внутри `tmux` или `screen`.
* **Сбойные сеансы в режиме сервера**: если сеанс, обслуживаемый `claude remote-control`, дает сбой, отправьте ему сообщение с подключённого устройства. Claude Code обслужит его снова. Вам не нужно перезапускать сервер. Требуется Claude Code v2.1.238 или позже.
* **HTTP 403 отказы в подключённом сеансе**: после подключения интерактивного сеанса Claude Code продолжает повторные попытки в течение трёх минут, когда что-то между вашей машиной и серверами Anthropic отвечает с HTTP 403, что может произойти после изменения VPN или сети. Если отказы продолжаются дольше, Claude Code отключается, и причина указывает, что отказало: сетевой край или прокси, VPN или брандмауэр в вашей собственной сети.
* **Продолжительный сбой сети**: если ваша машина включена, но не может достичь сеть, то, что вы делаете дальше, зависит от режима:
  * **Режим сервера**: Claude Code сдаётся примерно через 10 минут и процесс `claude remote-control` завершается. Запустите `claude remote-control` снова, чтобы начать новый сеанс.
  * **Интерактивный сеанс**: продолжайте работать локально. Claude Code повторяет попытки столько, сколько длится сбой, и переподключается автоматически, когда сеть восстанавливается.
* **Сбой импульсов присутствия**: если интерактивный сеанс отключается с сообщением `could not reach the Remote Control server for about 30 minutes`, запустите `/remote-control` для переподключения. Claude Code показывает это сообщение только когда импульсы присутствия сеанса не работают, а остальная часть соединения остаётся активной; он повторно регистрирует сеанс примерно на 30 минут перед отключением.
* **Переданные диалоги истекают**: Claude Code держит подсказки разрешений и вопросы `AskUserQuestion` открытыми до тех пор, пока вы на них не ответите. Когда Claude Code передаёт другой вид диалога удалённому сеансу, например подсказку выбора модели, показываемую после отказа по соображениям безопасности, он ждёт пять минут по умолчанию, затем закрывает диалог и продолжает с действием по умолчанию диалога при отсутствии действия. Установите [`dialogExpiry`](/docs/ru/settings-reference#dialogexpiry) для настройки или отключения крайнего срока. Требуется Claude Code v2.1.224 или позже.
* **Подсказка согласия на использование кредитов Fable не передаётся**: Claude Code показывает подсказку согласия на использование кредитов [Fable](/docs/ru/model-config#fable-and-usage-credits) в середине сеанса только там, где работает сеанс, а не на вашем устройстве. Когда сеанс работает в терминале и никто там не отвечает до того, как Claude Code закроет подсказку, ход завершается без отправки запроса; см. [Подсказка подтверждения осталась без ответа](/docs/ru/errors#the-prompt-to-confirm-went-unanswered).
* **Некоторые команды работают только локально**: команды, которые работают только в интерфейсе терминала, такие как `/plugin` или `/resume`, работают только из локального CLI, независимо от того, передаёте ли вы аргумент или нет. Следующие команды работают с мобильных устройств и веб-браузеров:
  * Команды с текстовым выводом: `/compact`, `/clear`, `/context`, `/usage`, `/exit`, `/usage-credits`, `/recap` и `/reload-plugins`. `/usage-credits` выводит URL биллинга вместо открытия браузера. `/reload-plugins` работает только когда сеанс работает в интерактивном терминале; сеанс без него отклоняет его.
  * `/model`, `/effort`, `/fast`, `/color` и `/rename`: передайте значение как аргумент, например `/model sonnet` или `/effort high`. С мобильных устройств и веб-браузеров `/model` и `/effort` принимают аргумент вместо выбора в терминале или ползунка.
  * `/mcp`: с мобильного приложения возвращает текстовое резюме статуса сервера вместо открытия выбора. В веб-версии `/mcp` без аргументов открывает каталог [соединителей claude.ai](/docs/ru/mcp#use-mcp-servers-from-claude-ai) вместо возврата резюме. [Подкоманды](/docs/ru/commands#all-commands) `reconnect`, `enable` и `disable` работают в обоих случаях. В отличие от локального CLI, `/mcp reconnect` без имени сервера переподключает каждый сервер, который не работает или требует аутентификации.
  * `/config`: с мобильного приложения передайте `key=value` для установки параметра или запустите её без аргументов, чтобы вывести список ключей, которые вы можете установить. В веб-версии `/config` открывает раздел Claude Code ваших параметров и игнорирует текст после команды.
  * На Team и Enterprise `/usage-credits` с мобильного устройства или веб-браузера не отправляет [запрос на использование кредитов вашему администратору](/docs/ru/costs#add-usage-credits-to-your-subscription). Отправка требует подтверждения, которое появляется только в интерактивном CLI, поэтому команда говорит вам запустить её там. До версии 2.1.211 текстовая форма отправляла запрос без подтверждения.
  * `/autocompact`, начиная с версии 2.1.221: передайте размер окна как аргумент, например `/autocompact 500k`. Без аргумента он выводит текущий размер окна как текст вместо открытия диалога, который команда показывает в сеансе терминала.
  * `/advisor`, начиная с версии 2.1.260: передайте модель как аргумент, например `/advisor opus`, или передайте `off` для отключения советника. Обе формы применяются только к текущему сеансу и оставляют ваше сохранённое значение по умолчанию без изменений. Без аргумента он выводит текущего советника как текст вместо открытия выбора.
  * `/output-style`, начиная с версии 2.1.269: передайте имя стиля как аргумент, например `/output-style concise`, или запустите её без аргумента, чтобы вывести список стилей. С мобильных устройств и веб-браузеров вы можете выводить и выбирать только [встроенные стили](/docs/ru/output-styles#built-in-output-styles). Чтобы использовать [пользовательский стиль](/docs/ru/output-styles#create-a-custom-output-style), выберите его в самом сеансе.

<h2 id="troubleshooting">
  Troubleshooting
</h2>

<h3 id="remote-control-requires-a-claude-ai-subscription">
  "Remote Control requires a claude.ai subscription"
</h3>

Вы не вошли в учётную запись claude.ai, или другие учётные данные имеют приоритет над вашим входом. Сообщение принимает одну из этих форм:

* Вышли из системы, из `/remote-control` или `--remote-control`: `Remote Control requires a claude.ai subscription.` или `/remote-control requires a claude.ai subscription.`
* Вышли из системы, из `claude remote-control`: `You must be logged in to use Remote Control. Remote Control is only available with claude.ai subscriptions.`
* Вошли в систему, но используется ключ API или токен: `Remote Control requires claude.ai subscription auth.` с последующим указанием используемых учётных данных, таких как `ANTHROPIC_API_KEY is set, so this session is using API-key auth`. Параметр `apiKeyHelper` и `ANTHROPIC_AUTH_TOKEN` называются одинаково.

Запустите `claude auth login` и выберите опцию claude.ai. Если сообщение указывает на `ANTHROPIC_API_KEY` или `ANTHROPIC_AUTH_TOKEN`, удалите его везде, где он установлен: в переменных окружения вашей оболочки или в блоке `env` [файла параметров](/docs/ru/settings-reference#env). Если оно указывает на `apiKeyHelper`, удалите этот параметр.

До версии 2.1.206 запуск `/remote-control` при выходе из системы сообщал `Unknown command: /remote-control` вместо этого сообщения.

<h3 id="remote-control-requires-a-full-scope-login-token">
  "Remote Control requires a full-scope login token"
</h3>

Вы аутентифицированы с помощью долгоживущего токена из `claude setup-token` или переменной окружения `CLAUDE_CODE_OAUTH_TOKEN`. Эти токены могут только делать запросы к модели, поэтому они не могут устанавливать сеансы Remote Control. Запустите `claude auth login` для аутентификации с помощью токена сеанса полного объёма вместо этого.

<h3 id="unable-to-determine-your-organization-for-remote-control-eligibility">
  "Unable to determine your organization for Remote Control eligibility"
</h3>

Ваша кэшированная информация об учётной записи устарела или неполна. Запустите `claude auth login` для её обновления.

<h3 id="remote-control-isn’t-enabled-for-this-account">
  "Remote Control isn't enabled for this account"
</h3>

Claude Code проверил доступность Remote Control для учётной записи, в которую вы вошли, и проверка вернула отрицательный результат. Обычная причина — кэшированные права доступа, которые устарели после изменения плана. Запустите `claude auth logout`, а затем `claude auth login` для их обновления, и обновите Claude Code, если вы используете старую версию.

Запустите `claude doctor` для просмотра того, какая отдельная проверка прав доступа не прошла. Конфликты переменных окружения, недостижимые проверки и параметр Remote Control вашей организации каждый производят своё собственное сообщение, поэтому эта ошибка означает, что сама проверка на уровне учётной записи не прошла.

До версии 2.1.239 это сообщение гласило "Remote Control is not yet enabled for your account". До версии 2.1.154 переменная, которая отключает оценку флага функции, такая как `DISABLE_TELEMETRY` или `DO_NOT_TRACK`, также производила это сообщение; запись "Remote Control requires feature-flag evaluation" ниже охватывает эту конфигурацию.

<h3 id="couldn’t-verify-remote-control-eligibility">
  "Couldn't verify Remote Control eligibility"
</h3>

Claude Code не смог достичь сервиса флагов функций для проверки того, включён ли Remote Control для вашей учётной записи, обычно потому, что вы находитесь в автономном режиме или прокси блокирует запрос. Повторите попытку, когда у вас будет доступ в сеть, или запустите `claude doctor` для получения подробностей. Связанное сообщение "Couldn't verify your organization's Remote Control policy" означает, что Claude Code не смог прочитать эту политику, и имеет то же исправление. Оба сообщения были добавлены в версии 2.1.178.

<h3 id="remote-control-requires-feature-flag-evaluation">
  "Remote Control requires feature-flag evaluation"
</h3>

Одна из этих переменных установлена: [`DISABLE_TELEMETRY`, `DO_NOT_TRACK`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` или `DISABLE_GROWTHBOOK`](/docs/ru/env-vars). Каждая из них отключает оценку флага функции, от которой зависит доступность Remote Control, и полное сообщение называет переменную, которую нашёл Claude Code. Отмените установку этой переменной везде, где она установлена, в переменных окружения вашей оболочки или в блоке `env` [файла `settings.json`](/docs/ru/settings-reference#all-settings). В версиях до 2.1.154 та же конфигурация производит "Remote Control is not yet enabled for your account" вместо этого.

<h3 id="remote-control-is-only-available-when-using-claude-via-api-anthropic-com">
  "Remote Control is only available when using Claude via api.anthropic.com"
</h3>

Сеанс не разговаривает с API Anthropic напрямую, поэтому нет бэкенда claude.ai для сопряжения. Это происходит на Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry. Это также происходит, когда [`ANTHROPIC_BASE_URL`](/docs/ru/env-vars) указывает на хост, отличный от `api.anthropic.com`, такой как [LLM gateway](/docs/ru/llm-gateway) или прокси, даже если вы входите с помощью claude.ai. До версии 2.1.196 Claude Code не показывал это сообщение для пользовательского `ANTHROPIC_BASE_URL`. Смотрите [справочник ошибок](/docs/ru/errors#remote-control-requires-the-anthropic-api) для полного списка причин.

Сообщение называет то, что направило сеанс в сторону от API Anthropic, такое как `CLAUDE_CODE_USE_BEDROCK` или пользовательский `ANTHROPIC_BASE_URL`. Если у вас есть подходящий вход claude.ai, отмените установку названной переменной, удалите её из ключа `env` в [параметрах](/docs/ru/settings), если вы установили её там, и перезагрузите сеанс. До версии 2.1.219 сообщение было только предложением в заголовке этого раздела, поэтому в более старых версиях проверьте вашу среду самостоятельно на наличие переменных поставщика, таких как `CLAUDE_CODE_USE_BEDROCK` и `CLAUDE_CODE_USE_VERTEX`, и для `ANTHROPIC_BASE_URL`.

<h3 id="remote-control-is-disabled-by-your-organization’s-policy">
  "Remote Control is disabled by your organization's policy"
</h3>

Политика блокирует Remote Control, или Claude Code не смог загрузить политику вашей организации на этой машине и временно держит Remote Control отключённым. Проверьте эти причины по порядку:

* **Ошибка упоминает `disableRemoteControl`**: ваш администратор IT отключил Remote Control на этом устройстве через [управляемые параметры](/docs/ru/managed-settings), независимо от переключателя на уровне организации и от того, как вы вошли в систему.
* **Ваш план claude.ai — Pro или Max**: Claude Code по-прежнему вошёл в систему под организацией Team или Enterprise из более раннего входа, поэтому он проверяет политику Remote Control этой организации. Запустите `/status` для просмотра того, какой план и организацию использует ваш вход. Запустите `claude auth logout`, а затем `claude auth login` для повторного входа под вашим текущим планом.
* **Политика организации не загрузилась на этой машине**: запустите `claude doctor` и прочитайте строку `Organization policy`. Если строка показывает, что политика не загружена, это то, что держит Remote Control отключённым. До версии 2.1.261 `claude doctor` не печатал эту строку.
* **Сообщение не говорит обратиться к администратору вашей организации**: ваша организация имеет конфигурацию HIPAA, которая несовместима с Remote Control, и `/status` указывает `HIPAA` в своей строке `Compliance`. В этом состоянии переключатель Remote Control в панели администратора неактивен, поэтому Owner не может изменить его там. Обратитесь в службу поддержки Anthropic для обсуждения вариантов. До версии 2.1.267 этот случай показывал "Remote Control isn't available for your organization due to its compliance policy" вместо этого.
* **В противном случае Owner не включил его для вашей организации**: Remote Control отключён по умолчанию в планах Team и Enterprise. Owner может включить его на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code), включив переключатель **Remote Control**. Этот переключатель является параметром организации на стороне сервера.

<h3 id="remote-credentials-fetch-failed">
  "Remote credentials fetch failed"
</h3>

Claude Code не смог получить краткосрочные учётные данные из API Anthropic для установления соединения. Повторно запустите с `--verbose` для просмотра полной ошибки:

```bash theme={null}
claude remote-control --verbose
```

Распространённые причины:

* Не вошли в систему: запустите `claude` и используйте `/login` для аутентификации с помощью вашей учётной записи claude.ai. Аутентификация с помощью ключа API не поддерживается для Remote Control.
* Проблема с сетью или прокси: брандмауэр или прокси может блокировать исходящий запрос HTTPS. Remote Control требует доступа к API Anthropic на порту 443.
* Ошибка создания сеанса: если вы также видите `Session creation failed — see debug log`, ошибка произошла ранее в процессе настройки. Проверьте, что ваша подписка активна.

Устаревший токен входа не вызывает эту ошибку. Когда API Anthropic отклоняет сохранённый токен, например потому что другой процесс Claude Code уже обновил его, Claude Code обновляет токен и повторяет попытку самостоятельно. До версии 2.1.224 устаревший токен вызывал сбой запуска Remote Control с этим сообщением, поэтому сеансы, установленные на [автоматическое подключение](#enable-remote-control-for-all-sessions), могли периодически не запускаться при запуске.

<h3 id="couldn’t-reconnect-to-your-remote-control-session">
  "Couldn't reconnect to your Remote Control session"
</h3>

Когда вы возобновляете разговор с `claude --resume` или `claude --continue`, Claude Code переподключается к сеансу Remote Control, записанному в этом разговоре. Это сообщение означает, что переподключение не удалось по причине, которая может быть временной, такой как сетевой сбой или ошибка сервера, поэтому Claude Code не может подтвердить, существует ли удалённый сеанс.

Запустите `/remote-control` для повторной попытки подключения, или начните новый сеанс с `claude --remote-control` для создания нового сеанса Remote Control. Ваш локальный сеанс продолжает работать без Remote Control в то же время.

<span id="resume-outcomes" />Когда вы возобновляете, вы также можете получить один из этих результатов вместо этого сообщения:

* **Сервер сообщает, что записанный сеанс исчез, или запись переподключения называет другую учётную запись**: Claude Code руководствуется тем, что говорит запись переподключения разговора:
  * **Запись называет вашу вошедшую в систему учётную запись**: Claude Code запускает сеанс замены с автоматически сгенерированным именем и оставляет более ранние сообщения разговора вне его. Вы получаете это после удаления сеанса из claude.ai или приложения Claude, например.
  * **Запись называет другую учётную запись**: Claude Code запускает новый сеанс без более ранних сообщений разговора и без отображения сообщения, существует ли записанный сеанс или нет.
  * **Запись не говорит, какой учётной записи принадлежал сеанс, или Claude Code не может прочитать ваш сохранённый вход**: Claude Code показывает [`Previous session is unavailable — run /remote-control to start a new one`](#previous-session-is-unavailable) вместо этого сообщения, ничего не запускает и удаляет запись из разговора.
* **Вы отключили Remote Control перед возобновлением**: если приложение, в котором размещается Claude Code, не сообщило ему, что приложение владеет сеансом claude.ai, Claude Code удалил запись переподключения, когда вы отключили Remote Control из панели [status](#check-connection-status) CLI, расширения VS Code или хоста, построенного на [Agent SDK](/docs/ru/agent-sdk/overview), поэтому он не переподключается. Когда владеющее приложение отключило его, Claude Code сохранил запись и переподключается.
* **Другой Claude Code на этой машине по-прежнему имеет сеанс**: вы видите уведомление, которое начинается с `Remote Control not started here`, и Claude Code [оставляет Remote Control отключённым в возобновлённом сеансе](#resume-sessions-after-stopping-the-server). Запустите `/remote-control` там для его перемещения.

<span id="reconnect-history" />До версии 2.1.232 Claude Code отвечал по-другому, когда сервер сообщал, что записанный сеанс исчез. С версии 2.1.227 по версию 2.1.231 Claude Code отказывался запускать замену даже когда запись совпадала с вашей учётной записью. До версии 2.1.226 Claude Code запускал замену независимо от того, совпадала ли запись с вашей учётной записью, и в версиях 2.1.224–2.1.226 создавал её под учётной записью, вошедшей на эту машину, никогда под другой учётной записью, без загрузки более ранних сообщений разговора в неё. До версии 2.1.200 Claude Code создавал новый сеанс после любого сбоя переподключения.

<h3 id="previous-session-is-unavailable">
  "Previous session is unavailable — run /remote-control to start a new one"
</h3>

Claude Code не смог восстановить предыдущий сеанс Remote Control и остановился вместо того, чтобы запустить новый самостоятельно. Вы можете увидеть это сообщение после возобновления разговора с `claude --resume` или `claude --continue`, или после того как Claude Code [переподключается самостоятельно после отключения](/docs/ru/errors#remote-control-couldnt-refresh-your-login).

Запустите `/remote-control` для запуска нового сеанса Remote Control под текущим входом; ваш локальный сеанс продолжает работать без Remote Control в то же время. Связанное сообщение `Remote Control could not verify the signed-in account — run /remote-control to reconnect` имеет то же исправление; Claude Code показывает его, когда вошедшая в систему учётная запись изменилась или не могла быть прочитана между её проверкой и переподключением. Если вы запустите `/remote-control` после `Previous session is unavailable` без перезагрузки Claude Code в первую очередь, Claude Code оставляет более ранние сообщения разговора вне нового сеанса.

При возобновлении Claude Code [запускает новый сеанс на его месте](#resume-outcomes) только если запись переподключения разговора называет учётную запись, которой принадлежал сеанс, потому что сервер сообщает о сеансе, который вы удалили, и сеансе, принадлежащем другой учётной записи, одинаково. Claude Code до версии 2.1.227 не записывал эту учётную запись, и Claude Code не может проверить запись, когда не может прочитать ваш сохранённый вход. Claude Code до версии 2.1.232 показывал `Remote Control could not resume the previous session under the current login — run /remote-control to start fresh` вместо этого, в [другом наборе случаев](#reconnect-history).

<h3 id="remote-control-got-an-unexpected-server-response">
  "Remote Control got an unexpected server response"
</h3>

Сервер Remote Control принял запрос, но ответил в форме, которую эта версия Claude Code не смогла прочитать, при создании удалённого сеанса или получении его учётных данных. Повторная попытка на той же версии не удаётся таким же образом. Запустите `claude update`, а затем запустите `/remote-control` для переподключения. Это сообщение было добавлено в версии 2.1.225.

<h3 id="your-organization-requires-trusted-devices-for-remote-control-but-this-device-is-not-enrolled">
  "Your organization requires Trusted Devices for Remote Control, but this device is not enrolled"
</h3>

Ваша организация имеет включённые [Trusted Devices](#trusted-devices) и эта машина ещё не зарегистрирована. Запустите `/login` в Claude Code. Регистрация происходит как часть входа, и нет отдельной команды регистрации.

<h3 id="session-expired-for-trusted-device-check">
  "session expired for trusted-device check"
</h3>

Ваш вход старше 18 часов. Запустите `/login` в Claude Code, или подтвердите с помощью Face ID, Touch ID, Windows Hello или passkey, когда claude.ai или мобильное приложение вас попросит. Смотрите [Trusted Devices](#trusted-devices).
