# Продолжайте локальные сеансы с любого устройства с помощью Remote Control

> Продолжайте локальный сеанс Claude Code со своего телефона, планшета или любого браузера, используя Remote Control. Работает с claude.ai/code и мобильным приложением Claude.

<Note>
  Remote Control находится в исследовательском предпросмотре и доступен на всех планах. На планах Team и Enterprise он отключен по умолчанию до тех пор, пока администратор не включит переключатель Remote Control в [параметрах администратора Claude Code](https://claude.ai/admin-settings/claude-code).
</Note>

Remote Control подключает [claude.ai/code](https://claude.ai/code) или приложение Claude для [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) и [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude) к сеансу Claude Code, работающему на вашем компьютере. Начните задачу за столом, а затем продолжите её со своего телефона на диване или в браузере на другом компьютере.

Когда вы запускаете сеанс Remote Control на своем компьютере, Claude продолжает работать локально всё время, поэтому выполнение кода и доступ к файловой системе остаются на вашем компьютере. С помощью Remote Control вы можете:

* **Использовать полную локальную среду удалённо**: ваша файловая система, [MCP servers](/docs/ru/mcp), инструменты и конфигурация проекта остаются доступными, и ввод `@` автоматически дополняет пути файлов из вашего локального проекта
* **Работать с обеих поверхностей одновременно**: беседа и прогресс [subagents](/docs/ru/sub-agents) и [dynamic workflows](/docs/ru/workflows) остаются синхронизированными на всех подключённых устройствах, поэтому вы можете отправлять сообщения из терминала, браузера и телефона взаимозаменяемо. До версии 2.1.207 сеансы, размещённые на [Desktop app](/docs/ru/desktop), не отправляли прогресс subagents или workflows на подключённые устройства.
* **Отправлять изображения и файлы со своего телефона или браузера**: когда вы добавляете вложение в приложение Claude или на claude.ai/code, Claude Code загружает его на ваш компьютер и передаёт его Claude как ссылку на файл `@`, с подписью или без неё. До версии 2.1.202 Claude Code мог удалить вложение, отправленное без подписи, прежде чем оно достигло сеанса.
* **Пережить перебои**: если ваш ноутбук перейдёт в режим сна или сетевое соединение разорвётся, сеанс автоматически переподключится, когда ваш компьютер вернётся в сеть. Claude Code ставит в очередь обновления статуса от subagents и workflows во время восстановления соединения и доставляет их после восстановления. До версии 2.1.207 обновление, отправленное во время переподключения или обновления учётных данных, могло быть потеряно, поэтому подключённое устройство продолжало показывать завершённую задачу как выполняющуюся.

В отличие от [Claude Code в веб-версии](/docs/ru/claude-code-on-the-web), которая работает на облачной инфраструктуре, сеансы Remote Control работают непосредственно на вашем компьютере и взаимодействуют с вашей локальной файловой системой. Веб- и мобильные интерфейсы — это просто окно в этот локальный сеанс.

На этой странице рассматриваются настройка, способы запуска и подключения к сеансам, а также сравнение Remote Control с Claude Code в веб-версии.

<h2 id="requirements">
  Требования
</h2>

Перед использованием Remote Control убедитесь, что ваша среда соответствует этим условиям:

* **Подписка**: доступна на планах Pro, Max, Team и Enterprise. API ключи не поддерживаются. На планах Team и Enterprise владелец должен сначала включить переключатель Remote Control в [параметрах администратора Claude Code](https://claude.ai/admin-settings/claude-code).
* **Аутентификация**: запустите `claude` и используйте `/login` для входа через claude.ai, если вы ещё этого не сделали.
* **Конечная точка API**: недоступна на Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry. Начиная с версии 2.1.196, Remote Control также отключен, когда [`ANTHROPIC_BASE_URL`](/docs/ru/env-vars) указывает на хост, отличный от `api.anthropic.com`, например на [LLM gateway](/docs/ru/llm-gateway) или прокси. Отключите переменную, чтобы использовать Remote Control.
* **Доверие рабочей области**: запустите `claude` в каталоге вашего проекта хотя бы один раз, чтобы принять диалог доверия рабочей области.

</h2>

    ```text theme={null}
    /remote-control
    ```

    ```text theme={null}

    ```

    ```text theme={null}
    /remote-control
    ```

<h3 id="check-connection-status">
  Проверка статуса подключения
</h3>

В интерактивном сеансе терминала индикатор `/rc active` находится в нижнем колонтитуле под полем ввода, пока соединение активно, и скрывается, если терминал слишком узкий, чтобы его вместить. Текст индикатора является ссылкой на сеанс на claude.ai. Выберите его клавишей со стрелкой вниз и нажмите Enter, или запустите `/remote-control` снова, чтобы открыть панель статуса с URL сеанса и QR-кодом, который вы можете использовать для [подключения с другого устройства](#connect-from-another-device).

Если подключение не удаётся, появляется уведомление с причиной сбоя и индикатор исчезает из нижнего колонтитула. Запустите `/remote-control` снова, чтобы повторить попытку.

<h3 id="connect-from-another-device">
  Подключение с другого устройства
</h3>

После активации сеанса Remote Control у вас есть несколько способов подключиться с другого устройства:

* **Откройте URL сеанса** в любом браузере, чтобы перейти непосредственно к сеансу на [claude.ai/code](https://claude.ai/code).
* **Отсканируйте QR-код**, показанный рядом с URL сеанса, чтобы открыть его непосредственно в приложении Claude. С помощью `claude remote-control` нажмите пробел, чтобы переключить отображение QR-кода.
* **Откройте [claude.ai/code](https://claude.ai/code) или приложение Claude** и найдите сеанс по имени в списке сеансов. В мобильном приложении Claude нажмите **Code** в навигации, чтобы перейти к списку сеансов. Сеансы Remote Control показывают значок компьютера с зелёной точкой статуса при подключении.

Когда вы подключаетесь, устройство показывает любых подагентов и рабочие процессы, которые сеанс уже имеет, работающие в фоновом режиме. До версии 2.1.208 устройство, подключающееся к сеансу, размещённому в интерактивном терминале, не показывало подагентов и рабочие процессы, которые уже были запущены, пока один из них не запустился или не остановился.

Название удалённого сеанса выбирается в следующем порядке:

1. Имя, которое вы передали в `--name`, `--remote-control` или `/remote-control`
2. Название, которое вы установили с помощью `/rename`
3. Последнее значимое сообщение в существующей истории беседы
4. Автоматически сгенерированное имя вроде `myhost-graceful-unicorn`, где `myhost` — это имя хоста вашего компьютера или префикс, который вы установили с помощью `--remote-control-session-name-prefix`

Если вы не установили явное имя, название обновляется, чтобы отразить вашу подсказку после её отправки. Начиная с Claude Code версии 2.1.176, автоматически сгенерированные названия соответствуют языку вашей беседы или параметру [`language`](/docs/ru/settings#available-settings), если он настроен. Переименование сеанса из claude.ai или приложения Claude также обновляет локальное название, показанное в `claude --resume`.

Если в среде уже есть активный сеанс, вас спросят, продолжить ли его или начать новый.

Если у вас ещё нет приложения Claude, используйте команду `/mobile` внутри Claude Code, чтобы отобразить QR-код загрузки для [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) или [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude).

<h3 id="enable-remote-control-for-all-sessions">
  Включение Remote Control для всех сеансов
</h3>

Remote Control активируется только при явном запуске `claude remote-control`, `claude --remote-control` или `/remote-control`, если не включена автоподключение. Чтобы включить его автоматически для каждого интерактивного сеанса, запустите `/config` внутри Claude Code и установите **Enable Remote Control for all sessions** на `true`. Установите на `false`, чтобы никогда не автоподключаться, или оставьте без установки, чтобы следовать стандартному значению вашей организации. В приложении Desktop вы также можете переключить это в **Settings → Claude Code → Enable remote control by default**. В [расширении VS Code](/docs/ru/vs-code#use-the-prompt-box) тот же переключатель появляется как **Enable Remote Control for all sessions** в разделе Settings меню команд; требует Claude Code версии 2.1.203 или позже.

С этой настройкой каждый интерактивный процесс Claude Code регистрирует один удалённый сеанс. Если вы запустите несколько экземпляров, каждый получит свою собственную среду и сеанс. Чтобы запустить несколько одновременных сеансов из одного процесса, используйте [режим сервера](#start-a-remote-control-session) вместо этого.

<h2 id="connection-and-security">
  Подключение и безопасность
</h2>

Ваш локальный сеанс Claude Code выполняет только исходящие HTTPS запросы и никогда не открывает входящие порты на вашем компьютере. Когда вы запускаете Remote Control, он регистрируется в API Anthropic и опрашивает работу. Когда вы подключаетесь с другого устройства, сервер маршрутизирует сообщения между веб-клиентом или мобильным клиентом и вашим локальным сеансом через потоковое соединение.

Весь трафик проходит через API Anthropic через TLS, тот же транспортный протокол безопасности, что и любой сеанс Claude Code. Соединение использует несколько краткосрочных учётных данных, каждое из которых ограничено одной целью и истекает независимо.

Пока Remote Control подключен, стенограмма сеанса, включая ваши сообщения, ответы Claude и активность инструментов, хранится на серверах Anthropic. Сохраненная стенограмма синхронизирует беседу на всех ваших устройствах и позволяет сеансу переподключиться после разрыва сети. Выполнение и доступ к файловой системе остаются на вашем компьютере, а сохраненные стенограммы хранятся в соответствии с политикой [Использование данных](/docs/ru/data-usage).

Чтобы полностью отключить Remote Control, используйте параметр [`disableRemoteControl`](/docs/ru/settings#available-settings). Организации с требованиями соответствия, такими как Zero Data Retention, не могут включить Remote Control.

<h2 id="trusted-devices">
  Доверенные устройства
</h2>

<Note>
  Доверенные устройства в настоящее время находятся в бета-версии. Функции и возможности могут развиваться по мере совершенствования опыта.

  Доверенные устройства доступны на планах Team и Enterprise. Они отключены по умолчанию до тех пор, пока администратор не включит их.
</Note>

Доверенные устройства — это параметр на уровне организации, который требует от членов проверки своего устройства перед тем, как они смогут просматривать или управлять сеансами Remote Control из claude.ai, мобильных приложений Claude или Claude Desktop. Это связывает доступ Remote Control с известным устройством и недавней аутентификацией, а не просто с подписанной учётной записью.

Когда параметр включен, взаимодействие с сеансом Remote Control требует обоих следующих условий:

* **Зарегистрированное устройство**: каждый браузер, телефон или приложение для рабочего стола, которое член использует для Remote Control, регистрирует свои собственные учётные данные. Регистрация предлагается только вскоре после полного входа, поэтому устройство присоединяется к списку доверенных как часть реальной аутентификации, а не молча в фоновом режиме.
* **Недавний вход**: вход члена должен быть не старше 18 часов. Вместо входа каждый день члены подтверждают присутствие с помощью Face ID, Touch ID, Windows Hello или passkey. Этот биометрический шаг повышения уровня немедленно обновляет сеанс.

Биометрические проверки выполняются на устройстве через операционную систему или браузер, тот же механизм, что и вход с passkey. Anthropic никогда не получает и не хранит отпечатки пальцев, данные лица или любую другую биометрическую информацию. Хранятся только открытый ключ устройства и основные метаданные, такие как отображаемое имя, платформа и время регистрации.

Параметр применяется только к Remote Control. Обычный чат Claude, Claude Code в терминале и использование API не затронуты.

<h3 id="enable-trusted-devices-for-your-organization">
  Включение доверенных устройств для вашей организации
</h3>

Администраторы включают параметр из консоли администратора Claude Code.

<Steps>
  <Step title="Откройте параметры администратора Claude Code">
    Перейдите на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code). Переключатель **Require trusted devices** появляется под параметром Remote Control.
  </Step>

  <Step title="Включите Require trusted devices">
    Параметр применяется к каждому члену организации и к сеансам Remote Control, запущенным после включения переключателя. Сеансы, которые уже работали до включения переключателя, не защищены задним числом и продолжают работать без требования устройства до их завершения. Область действия для каждой команды или проекта недоступна.
  </Step>

  <Step title="Сообщите членам, чего ожидать">
    В первый раз, когда член просматривает или управляет новым сеансом Remote Control из браузера, телефона или приложения для рабочего стола после включения параметра, ему предлагается зарегистрировать это устройство. Предварительное уведомление избегает путаницы.
  </Step>
</Steps>

<h3 id="what-members-see">
  Что видят члены
</h3>

Регистрация — это одноразовый шаг для каждого устройства. После этого единственное видимое изменение — это случайный биометрический запрос.

* **Первое использование на каждом устройстве**: члену предлагается зарегистрировать устройство. Если его вход не свежий, он сначала входит через ваш обычный процесс, включая SSO, если настроен, а затем подтверждает регистрацию.
* **День за днём**: члены с зарегистрированным устройством и свежим входом не видят никаких запросов. Когда вход становится старше 18 часов, следующее взаимодействие Remote Control показывает один запрос Face ID, Touch ID, Windows Hello или passkey.
* **Незарегистрированные устройства**: сеансы Remote Control не могут быть просмотрены или управляться до регистрации устройства. Обычный чат Claude на этом устройстве не затронут.
* **Без аутентификатора платформы**: члены на машине без Face ID, Touch ID или Windows Hello могут использовать аппаратный ключ безопасности или войти снова вместо повышения уровня.
* **В терминале**: машина, на которой работает Claude Code, получает свои собственные учётные данные автоматически, когда разработчик входит в CLI. В терминале нет отдельного шага регистрации.

<h3 id="manage-enrolled-devices">
  Управление зарегистрированными устройствами
</h3>

Члены могут просматривать и отзывать свои собственные устройства из параметров учётной записи.

Откройте [claude.ai/settings/account](https://claude.ai/settings/account#trusted-devices) и найдите раздел **Trusted devices**, чтобы увидеть каждое зарегистрированное устройство с его именем, платформой и датой регистрации. Удаление устройства немедленно отзывает его учётные данные, и устройство может повторно зарегистрироваться позже после свежего входа. Учётные данные также истекают самостоятельно, если не обновляются, поэтому неиспользуемое устройство автоматически исчезает из списка доверенных.

Для потерянного или украденного устройства член удаляет его с этой страницы. Если член не может войти, администратор может использовать **Sign out everywhere** в консоли администратора, чтобы отозвать каждый сеанс и зарегистрированное устройство для этого члена, после чего член повторно регистрирует устройства, которые он всё ещё держит.

<h2 id="remote-control-vs-claude-code-on-the-web">
  Remote Control в сравнении с Claude Code в веб-версии
</h2>

Remote Control и [Claude Code в веб-версии](/docs/ru/claude-code-on-the-web) оба используют интерфейс claude.ai/code. Ключевое различие заключается в том, где работает сеанс: Remote Control выполняется на вашем компьютере, поэтому ваши локальные MCP servers, инструменты и конфигурация проекта остаются доступными. Claude Code в веб-версии выполняется в управляемой Anthropic облачной инфраструктуре.

Используйте Remote Control, когда вы находитесь в процессе локальной работы и хотите продолжить с другого устройства. Используйте Claude Code в веб-версии, когда вы хотите начать задачу без какой-либо локальной настройки, работать с репозиторием, который у вас не клонирован, или запустить несколько задач параллельно.

<h2 id="mobile-push-notifications">
  Мобильные push-уведомления
</h2>

Когда Remote Control активен, Claude может отправлять push-уведомления на ваш телефон.

Claude решает, когда отправить уведомление. Обычно он отправляет одно, когда завершается долгоживущая задача или когда ему нужно решение от вас для продолжения. Вы также можете запросить push в своей подсказке, например `notify me when the tests finish`. Помимо двух переключателей включения/отключения ниже, нет конфигурации для каждого события.

Чтобы настроить мобильные push-уведомления:

<Steps>
  <Step title="Установите мобильное приложение Claude">
    Загрузите приложение Claude для [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) или [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude).
  </Step>

  <Step title="Войдите с помощью своей учётной записи Claude Code">
    Используйте ту же учётную запись и организацию, которые вы используете для Claude Code в терминале.
  </Step>

  <Step title="Разрешите уведомления">
    Примите запрос разрешения на уведомления от операционной системы.
  </Step>

  <Step title="Включите push в Claude Code">
    В вашем терминале запустите `/config` и включите **Push when Claude decides** для проактивных уведомлений, **Push when actions required** для запросов разрешений и вопросов или оба варианта.
  </Step>
</Steps>

Если уведомления не приходят:

* Если `/config` показывает **No mobile registered**, откройте приложение Claude на своем телефоне, чтобы оно могло обновить свой токен push. Предупреждение исчезает при следующем подключении Remote Control.
* На iOS режимы Focus и сводки уведомлений могут подавлять или задерживать push-уведомления. Проверьте Settings → Notifications → Claude.
* На Android агрессивная оптимизация батареи может задержать доставку. Исключите приложение Claude из оптимизации батареи в системных параметрах.

Claude Code пропускает мобильные push-уведомления, пока вы печатаете или сосредоточены на подключённом терминале. Начиная с версии v2.1.181, вы можете установить [`CLAUDE_CLIENT_PRESENCE_FILE`](/docs/ru/env-vars) на путь файла-маркера, чтобы расширить это на любое время, когда вы находитесь у машины, даже в другом окне: уведомления пропускаются, пока файл существует. Настройте прослушиватель блокировки экрана или аналогичный инструмент для создания файла при разблокировке экрана и удаления его при блокировке экрана.

<h2 id="limitations">
  Ограничения
</h2>

* **Один удалённый сеанс на интерактивный процесс**: вне режима сервера каждый экземпляр Claude Code поддерживает один удалённый сеанс одновременно. Используйте [режим сервера](#start-a-remote-control-session) для запуска нескольких одновременных сеансов из одного процесса.
* **Локальный процесс должен продолжать работать**: Remote Control работает как локальный процесс. Если вы закроете терминал, выйдете из VS Code или иным образом остановите процесс `claude`, сеанс завершится.
* **Продолжительный сбой сети**: если ваш компьютер включен, но не может достичь сеть более чем примерно на 10 минут, сеанс истекает и процесс завершается. Запустите `claude remote-control` снова, чтобы начать новый сеанс.
* **Ultraplan отключает Remote Control**: запуск сеанса [ultraplan](/docs/ru/ultraplan) отключает любой активный сеанс Remote Control, потому что обе функции занимают интерфейс claude.ai/code и одновременно может быть подключена только одна.
* **Некоторые команды работают только локально**: команды, которые работают только в интерфейсе терминала, такие как `/plugin` или `/resume`, работают только из локального CLI, независимо от того, передаёте ли вы аргумент или нет. Следующие команды работают с мобильных устройств и веб-браузеров:
  * Команды с текстовым выводом: `/compact`, `/clear`, `/context`, `/usage`, `/exit`, `/usage-credits` (запускает текстовую форму вместо открытия диалога в CLI), `/recap`, `/reload-plugins`
  * `/model`, `/effort`, `/fast`, `/color` и `/rename`: передайте значение как аргумент, например `/model sonnet` или `/effort high`. С мобильных устройств и веб-браузеров `/model` и `/effort` принимают аргумент вместо выбора в терминале или ползунка.
  * `/mcp`, начиная с версии 2.1.166: с мобильного приложения возвращает текстовое резюме статуса сервера вместо открытия выбора. В веб-версии `/mcp` без аргументов открывает каталог [соединителей claude.ai](/docs/ru/mcp#use-mcp-servers-from-claude-ai) вместо возврата резюме. Подкоманды `reconnect`, `enable` и `disable` [](/docs/ru/commands#all-commands) работают с обеих версий. В отличие от локального CLI, `/mcp reconnect` без имени сервера переподключает каждый сервер, который не работает или требует аутентификации.
  * `/config`, начиная с версии 2.1.181: с мобильного приложения передайте `key=value` для установки параметра или запустите её без аргументов, чтобы вывести список ключей, которые вы можете установить. В веб-версии `/config` открывает раздел Claude Code ваших параметров и игнорирует текст после команды.

<h2 id="troubleshooting">
  Устранение неполадок
</h2>

<h3 id="remote-control-requires-a-claude-ai-subscription">
  "Remote Control requires a claude.ai subscription"
</h3>

Вы не аутентифицированы с помощью учётной записи claude.ai. Запустите `claude auth login` и выберите опцию claude.ai. Если в вашей среде установлена переменная `ANTHROPIC_API_KEY`, отключите её сначала.

До версии 2.1.206 запуск `/remote-control` при выходе из системы сообщал `Unknown command: /remote-control` вместо этого сообщения.

<h3 id="remote-control-requires-a-full-scope-login-token">
  "Remote Control requires a full-scope login token"
</h3>

Вы аутентифицированы с помощью долгоживущего токена из `claude setup-token` или переменной окружения `CLAUDE_CODE_OAUTH_TOKEN`. Эти токены ограничены только выводом и не могут устанавливать сеансы Remote Control. Запустите `claude auth login` для аутентификации с помощью полнофункционального токена сеанса вместо этого.

<h3 id="unable-to-determine-your-organization-for-remote-control-eligibility">
  "Unable to determine your organization for Remote Control eligibility"
</h3>

Ваша кэшированная информация об учётной записи устарела или неполна. Запустите `claude auth login` для обновления.

<h3 id="remote-control-is-not-yet-enabled-for-your-account">
  "Remote Control is not yet enabled for your account"
</h3>

Развёртывание Remote Control ещё не достигло вашей учётной записи, или ваши кэшированные права доступа устарели. Если вы недавно изменили план, запустите `claude auth logout`, а затем `claude auth login` для их обновления. Запустите `claude doctor` для просмотра того, какая проверка приемлемости не прошла. Конфликты переменных окружения, недостижимые проверки и политика организации каждая производят свои собственные сообщения, поэтому эта ошибка означает сам вентиль развёртывания.

<h3 id="couldn’t-verify-remote-control-eligibility">
  "Couldn't verify Remote Control eligibility"
</h3>

Claude Code не смог достичь сервиса флагов функций для проверки того, включен ли Remote Control для вашей учётной записи, обычно потому что вы находитесь в автономном режиме или прокси блокирует запрос. Повторите попытку, когда у вас будет доступ в сеть, или запустите `claude doctor` для получения подробностей. Связанное сообщение "Couldn't verify your organization's Remote Control policy" имеет ту же причину и то же решение. Оба сообщения были добавлены в v2.1.178.

<h3 id="remote-control-is-only-available-when-using-claude-via-api-anthropic-com">
  "Remote Control is only available when using Claude via api.anthropic.com"
</h3>

Сеанс не взаимодействует с API Anthropic напрямую, поэтому нет бэкенда claude.ai для сопряжения. Это происходит на Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry. Начиная с v2.1.196 это также происходит, когда [`ANTHROPIC_BASE_URL`](/docs/ru/env-vars) указывает на хост, отличный от `api.anthropic.com`, такой как [LLM gateway](/docs/ru/llm-gateway) или прокси, даже если вы входите с помощью claude.ai. Отключите `ANTHROPIC_BASE_URL` и перезагрузите сеанс для использования Remote Control.

<h3 id="remote-control-is-disabled-by-your-organization’s-policy">
  "Remote Control is disabled by your organization's policy"
</h3>

Эта ошибка имеет четыре различные причины. Запустите `/status` сначала для просмотра того, какой метод входа и подписку вы используете.

* **Вы аутентифицированы с помощью API ключа или учётной записи Console**: Remote Control требует OAuth claude.ai. Запустите `/login` и выберите опцию claude.ai. Если в вашей среде установлена переменная `ANTHROPIC_API_KEY`, отключите её.
* **Администратор не включил это для вашей организации**: Remote Control отключен по умолчанию на планах Team и Enterprise. Администратор может включить его на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code), включив переключатель **Remote Control**. Этот переключатель является параметром организации на стороне сервера.
* **Переключатель администратора неактивен**: ваша организация имеет конфигурацию хранения данных или соответствия, которая несовместима с Remote Control. Это не может быть изменено из панели администратора. Свяжитесь с поддержкой Anthropic для обсуждения вариантов.
* **Ошибка упоминает `disableRemoteControl`**: ваш IT администратор отключил Remote Control на этом устройстве через [управляемые параметры](/docs/ru/settings#settings-files), независимо от переключателя на уровне организации.

<h3 id="remote-credentials-fetch-failed">
  "Remote credentials fetch failed"
</h3>

Claude Code не смог получить краткосрочные учётные данные из API Anthropic для установления соединения. Запустите снова с `--verbose` для просмотра полной ошибки:

```bash theme={null}
claude remote-control --verbose
```

Распространённые причины:

* Не вошли в систему: запустите `claude` и используйте `/login` для аутентификации с вашей учётной записью claude.ai. Аутентификация с помощью API ключа не поддерживается для Remote Control.
* Проблема с сетью или прокси: брандмауэр или прокси может блокировать исходящий HTTPS запрос. Remote Control требует доступа к API Anthropic на порту 443.
* Ошибка создания сеанса: если вы также видите `Session creation failed — see debug log`, ошибка произошла ранее при настройке. Проверьте, что ваша подписка активна.

<h3 id="couldn’t-reconnect-to-your-remote-control-session">
  "Couldn't reconnect to your Remote Control session"
</h3>

Когда вы возобновляете разговор с `claude --resume` или `claude --continue`, Claude Code переподключается к сеансу Remote Control, записанному в этом разговоре. Это сообщение означает, что переподключение не удалось по причине, которая может быть временной, такой как сетевой сбой или ошибка сервера, поэтому Claude Code не может подтвердить, существует ли удалённый сеанс. Когда сервер подтверждает, что предыдущий сеанс больше не существует, Claude Code создаёт новый сеанс Remote Control без отображения этого сообщения.

Ваш локальный сеанс продолжает работать без Remote Control. Запустите `/remote-control` для повторной попытки подключения, или запустите Claude Code без `--resume` для создания нового сеанса Remote Control.

До v2.1.200 ошибка переподключения создавала новый сеанс Remote Control вместо отображения этого сообщения, что оставляло дополнительные сеансы в списке сеансов на claude.ai/code.

<h3 id="your-organization-requires-trusted-devices-for-remote-control-but-this-device-is-not-enrolled">
  "Your organization requires Trusted Devices for Remote Control, but this device is not enrolled"
</h3>

Ваша организация имеет [Доверенные устройства](#trusted-devices) включены и эта машина ещё не зарегистрирована. Запустите `/login` в Claude Code. Регистрация происходит как часть входа, и нет отдельной команды регистрации.

<h3 id="session-expired-for-trusted-device-check">
  "session expired for trusted-device check"
</h3>

Ваш вход старше 18 часов. Запустите `/login` в Claude Code, или подтвердите с помощью Face ID, Touch ID, Windows Hello или passkey, когда claude.ai или мобильное приложение вас попросит. См. [Доверенные устройства](#trusted-devices).

<h2 id="choose-the-right-approach">
  Выберите правильный подход
</h2>

Claude Code offers several ways to work when you're not at your terminal. They differ in what triggers the work, where Claude runs, and how much you need to set up.

|                                                          | Trigger                                                                                        | Claude runs on                                                                               | Setup                                                                                                                                | Best for                                                      |
| :------------------------------------------------------- | :--------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------ |
| [Dispatch](/docs/en/desktop#sessions-from-dispatch)           | Message a task from the Claude mobile app                                                      | Your machine (Desktop)                                                                       | [Pair the mobile app with Desktop](https://support.claude.com/en/articles/13947068)                                                  | Delegating work while you're away, minimal setup              |
| [Remote Control](/docs/en/remote-control)                     | Drive a running session from [claude.ai/code](https://claude.ai/code) or the Claude mobile app | Your machine (CLI or VS Code)                                                                | Run `claude remote-control`                                                                                                          | Steering in-progress work from another device                 |
| [Channels](/docs/en/channels)                                 | Push events from a chat app like Telegram or Discord, or your own server                       | Your machine (CLI)                                                                           | [Install a channel plugin](/docs/en/channels#quickstart) or [build your own](/docs/en/channels-reference)                                      | Reacting to external events like CI failures or chat messages |
| [Slack](/docs/en/slack)                                       | Mention `@Claude` in a team channel                                                            | Anthropic cloud                                                                              | [Install the Slack app](/docs/en/slack#setting-up-claude-code-in-slack) with [Claude Code on the web](/docs/en/claude-code-on-the-web) enabled | PRs and reviews from team chat                                |
| [Self-hosted environments](/docs/en/self-hosted-environments) | Start a [cloud session](/docs/en/claude-code-on-the-web) and pick your organization's environment   | Your organization's infrastructure                                                           | [Deploy runners](/docs/en/self-hosted-environments-quickstart), on Team and Enterprise plans                                              | Cloud sessions that must run inside your network              |
| [Scheduled tasks](/docs/en/scheduled-tasks)                   | Set a schedule                                                                                 | [CLI](/docs/en/scheduled-tasks), [Desktop](/docs/en/desktop-scheduled-tasks), or [cloud](/docs/en/routines) | Pick a frequency                                                                                                                     | Recurring automation like daily reviews                       |
