  <p className="digest-feature-lede">Ваши сеансы Claude Code теперь могут обмениваться сообщениями друг с другом. Claude обнаруживает ваши другие сеансы с помощью инструмента <code>ListAgents</code> и отправляет сообщения с помощью <code>SendMessage</code>, либо когда вы его об этом попросите, либо самостоятельно, например, когда изменение в одном сеансе влияет на работу другого. Сообщение — это текст, который Claude пишет для другого сеанса, никогда не ваша история разговора или файлы. Доступно на macOS и Linux. Требуется v2.1.224 или позже.</p>

  <p className="digest-feature-try">Имея два открытых сеанса на одной машине, попросите один из них передать что-то другому:</p>

  ```text title="Claude Code" wrap theme={null}
  Tell the session working on the payments API that users.name is now users.display_name
  ```

  <p className="digest-feature-try">Другой сеанс показывает строку <code>Message from</code> после того, как Claude прочитает сообщение; нажмите <code>Ctrl+O</code> для её развёртывания. Чтобы увидеть, какие сеансы может достичь Claude, выполните <code>/list-agents</code>.</p>

  <p className="digest-feature-lede">Самостоятельно размещённые окружения запускают облачные сеансы Claude Code на собственной инфраструктуре вашей организации, находясь в открытой бета-версии на планах Team и Enterprise. Выполните <code>claude self-hosted-runner</code> на ваших машинах или контейнерах, чтобы превратить их в runners. Когда кто-то выбирает ваше окружение при запуске сеанса с claude.ai, мобильных или настольных приложений или `claude --cloud`, этот сеанс запускается внутри вашей сети с доступом к вашим внутренним сервисам. Владелец включает <strong>Allow self-hosted environments</strong> в <a href="https://claude.ai/admin-settings/cloud-environments">параметрах администратора</a> в первую очередь.</p>

  <p className="digest-feature-try">Войдя как Владелец, выполните управляемую установку, которая проведёт вас через создание окружения и запустит runner:</p>

  ```bash terminal theme={null}
  claude self-hosted-runner setup
  ```

  <p className="digest-feature-try">Окружение показывает <strong>Healthy</strong> в параметрах администратора после регистрации runner.</p>

    <span className="digest-feature-pill">CLI</span>

  <p className="digest-feature-lede">Начиная с 14 августа, режим auto является режимом разрешений по умолчанию для новых сеансов на планах Pro, Max и Team. Если вы установили режим по умолчанию самостоятельно, он остаётся на месте, если вы не примете одноразовое предложение переключения, и режим по умолчанию, управляемый вашей организацией, не изменяется. Вы всё ещё можете переключать режимы в любое время. Уже действует на этих планах: классификаторы, которые вызывает режим auto, больше не учитываются в ваших лимитах использования.</p>

  <p className="digest-feature-try">Чтобы запустить каждый сеанс в режиме auto до переключения, установите его по умолчанию в параметрах пользователя:</p>

  ```json ~/.claude/settings.json {3} theme={null}
  {
    "permissions": {
      "defaultMode": "auto"
    }
  }
  ```

  <p className="digest-feature-try">Новые сеансы затем показывают <code>auto mode on</code> в строке состояния.</p>

  <a className="digest-feature-link" href="/docs/ru/permission-modes#eliminate-prompts-with-auto-mode">Требования и элементы управления режимом auto</a>
</div>

    <div>Маркетплейсы могут распространять плагин как <a href="/docs/ru/plugins/marketplace-reference#archive-plugin-source">zip-архив</a> с новым источником <code>archive</code>, загружаемый по HTTPS с опциональным пином SHA-256, поэтому установки работают без git или npm</div>
    <div><code>/review</code> теперь является псевдонимом <a href="/docs/ru/code-review#review-a-diff-locally"><code>/code-review</code></a>, и <code>/code-review</code> без уровня усилий повторно использует уровень, который вы вводили в последний раз</div>
    <div>Сеанс, который вы копируете с помощью <a href="/docs/ru/agent-view#copy-the-session-with-%2Ffork"><code>/fork</code></a>, теперь вносит свои изменения кода в собственный worktree вместо checkout исходного сеанса</div>
    <div>Плагины, которые вы устанавливаете из <a href="/docs/ru/plugins/install#install-a-plugin"><code>/plugin</code></a>, активируются в текущем сеансе, когда это безопасно; сводка установки сообщает <code>Plugin is now active.</code> или говорит вам выполнить <code>/reload-plugins</code></div>
    <div><a href="/docs/ru/agent-view#how-file-edits-are-isolated">Фоновые сеансы</a>, которые изменили код в worktree, теперь фиксируют и отправляют перед завершением, открывают черновик pull request только когда задача это требует, и следуют инструкциям git в вашем <code>CLAUDE.md</code></div>
    <div>Ограничение в 200 подагентов на сеанс удалено, поэтому долгоживущие сеансы больше не отказывают в новых подагентах; ограничения <a href="/docs/ru/sub-agents#concurrent-subagent-limit">параллелизма</a> и глубины по-прежнему применяются</div>
    <div>Проверенные параметры репозитория больше не могут включить <a href="/docs/ru/remote-control#enable-remote-control-for-all-sessions">автоподключение Remote Control</a>; установите <code>remoteControlAtStartup</code> в параметрах пользователя или управляемых параметрах вместо этого, и параметры проекта и локальные параметры могут только его отключить</div>
    <div><a href="/docs/ru/worktrees#how-claude-code-enforces-isolation">Изоляция worktree</a> теперь блокирует не только редактирование файлов, но также команды Bash и перенаправления git, которые достигают основного checkout, в каждом типе сеанса и в подагентах сеанса</div>

    <div>Hooks PreToolUse auto-allow больше не обходят ограничения инструментов во внутренних побочных задачах Claude Code, таких как резюме и компактирование</div>
