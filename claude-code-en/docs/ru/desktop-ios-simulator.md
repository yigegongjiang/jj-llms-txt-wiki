# Тестирование iOS приложений в симуляторе

> Claude Code Desktop открывает ваше приложение в панели iOS Simulator при сборке, запуске или проверке, с отдельным симулятором для каждой сессии.

<Note>
  Панель iOS Simulator находится в публичной бета-версии в Claude Code Desktop на macOS. Она доступна в планах Pro, Max, Team и Enterprise, за исключением организаций Enterprise с включённой конфигурацией HIPAA.
</Note>

Панель iOS Simulator показывает ваше приложение, работающее в Apple iOS Simulator рядом с вашей беседой в Claude Code Desktop. Когда Claude собирает, устанавливает, запускает или проверяет ваше приложение в симуляторе, панель открывается автоматически и транслирует экран устройства в реальном времени. Используйте её, чтобы наблюдать, как Claude запускает и тестирует ваше приложение, или чтобы самостоятельно взаимодействовать с приложением, пока Claude продолжает работать.

Панель симулятора управляет симулятором напрямую, поэтому ей не требуется [компьютерное управление](/docs/ru/desktop#let-claude-use-your-computer) и она никогда не захватывает ваш экран и не скрывает другие окна. Из CLI Claude получает доступ к iOS Simulator через [компьютерное управление](/docs/ru/computer-use#test-a-simulator-flow), которое управляет симулятором на вашем экране так же, как вы это делали бы с помощью мыши.

<h2 id="requirements">
  Требования
</h2>

Панель симулятора использует инструменты Apple для симулятора, которые не включены в приложение для рабочего стола. Перед началом сессии убедитесь, что у вас есть:

* Claude Desktop v1.24012.0 или позже
* Mac, так как Apple iOS Simulator работает только на macOS
* [Xcode](https://developer.apple.com/xcode/) с установленной платформой iOS, которая предоставляет устройства симулятора. Если Xcode ещё не показывает симуляторы, см. [Панель симулятора говорит, что симуляторы не найдены](#the-simulator-pane-says-no-simulators-were-found)
  * Используйте Xcode 26.x. Панель ещё не работает с Xcode 27, которая заменяет приложение Simulator на Device Hub. Если `xcode-select` указывает на Xcode 27 на вашем Mac, см. [Панель симулятора не работает с Xcode 27](#the-simulator-pane-fails-with-xcode-27)

<Note>
  На этой странице "устройство" относится к симулированному iPhone или iPad, одному из тех же устройств симулятора, которыми вы управляете в Xcode в разделе **Window → Devices and Simulators**, а не к физическому оборудованию.
</Note>

Панель симулятора доступна только в локальных сессиях. В [облачных](/docs/ru/desktop#run-long-running-tasks-in-the-cloud) и [SSH](/docs/ru/desktop#ssh-sessions) сессиях Claude работает на машине, которая не может получить доступ к симуляторам на вашем Mac.

<h2 id="run-your-app-in-the-simulator">
  Запуск вашего приложения в симуляторе
</h2>

Вам не нужна команда или настройка для открытия панели симулятора. Claude открывает её, когда запускает ваше приложение в симуляторе.

<Steps>
  <Step title="Откройте ваш iOS проект">
    В Claude Code Desktop откройте вкладку **Code** и начните сессию с папкой проекта вашего приложения в качестве [папки проекта](/docs/ru/desktop#start-a-session). Любой проект, который собирает приложение для iOS Simulator, подойдёт.
  </Step>

  <Step title="Попросите Claude запустить или протестировать приложение">
    Сформулируйте задачу вокруг запуска или проверки приложения. Например:

    ```text theme={null}
    Build the app and run it in the simulator to check the onboarding flow.
    ```
  </Step>

  <Step title="Наблюдайте приложение в панели симулятора">
    Когда приложение запускается в симуляторе, панель iOS Simulator открывается рядом с беседой. В первый раз, когда Claude использует устройство, приложение для рабочего стола просит вас разрешить это; см. [Предоставьте Claude доступ к устройству](#grant-claude-access-to-a-device). Claude устанавливает приложение, взаимодействует с ним и читает экран, чтобы проверить свои собственные изменения, пока вы наблюдаете.
  </Step>
</Steps>

Панель симулятора открывается всякий раз, когда Claude запускает приложение в симуляторе, в любой момент сессии. Когда ваш запрос касается просмотра приложения, например "выглядит ли новый экран правильно?", Claude запускает симулятор перед началом работы. После того как Claude исправит ошибку или изменит экран, попросите его проверить изменение: перезапуск приложения снова откроет панель, если она не открыта.

Панель симулятора показывает то устройство, на котором приложение фактически запустилось. Чтобы протестировать на конкретном устройстве, назовите его в своем запросе, например "запустите его на симуляторе iPhone SE", и Claude будет нацеливаться на это устройство при сборке и запуске.

Устройство, которое Claude загружает, также появляется в приложении Apple Simulator, и Claude может установить приложение на устройство, которое вы уже загрузили.

Вы также можете открыть панель симулятора самостоятельно. После того как сессия имеет подключённый симулятор или отредактировала файлы Swift, меню **Views** в панели инструментов сессии показывает запись **iOS Simulator**. Если панель ещё не показывает устройство, нажмите **Attach simulator** или выберите конкретное устройство из меню устройств рядом с ним; выбор выключенного устройства его загружает. Если Xcode или его симуляторы отсутствуют, панель показывает шаги настройки вместо этого и отмечает их по мере завершения.

<h2 id="control-the-simulator-yourself">
  Управляйте симулятором самостоятельно
</h2>

Панель симулятора интерактивна, а не только средство просмотра. Пока Claude работает или между задачами, вы можете:

* Касаться и проводить пальцем, щёлкая и перетаскивая на экран устройства
* Нажимать кнопки оборудования с теми же сочетаниями клавиш, что и приложение Apple Simulator: **Cmd+Shift+H** для Home, **Cmd+L** для блокировки, **Cmd+Up Arrow** и **Cmd+Down Arrow** для громкости
* Повернуть устройство на четверть оборота по часовой стрелке с помощью кнопки поворота или **Cmd+Right Arrow**
* Переключаться между устройствами, которые показывает панель, из меню устройств, которое перечисляет версию ОС каждого симулятора и загружено ли оно
* Сохранить снимок экрана с помощью **Cmd+S** или запись экрана с помощью **Cmd+R**, используя кнопки захвата панели или сочетания клавиш; файлы сохраняются на ваш Desktop
* Остановить трансляцию устройства без его выключения, нажав **Detach simulator**, что вернёт панель в состояние **Attach simulator**

Строка под названием устройства настраивает видеопоток от симулятора. Снизьте **Frame rate** или **Resolution**, если панель перегружает ваш Mac, переключайтесь между **Encoding** между H.264 и JPEG или отметьте **FPS**, чтобы отобразить частоту кадров, которую получает панель. Эти настройки изменяют способ отображения устройства панелью, а не способ работы приложения.

Вы и Claude управляете одним и тем же устройством, поэтому ваши касания изменяют состояние приложения, которое видит Claude. Чтобы Claude проверил конкретный экран, перейдите к нему, касаясь, затем попросите. Пока Claude управляет устройством, панель показывает значок **Claude is using this device** над экраном; воздержитесь от касания до тех пор, пока значок не исчезнет, чтобы результат отражал приложение, а не ваш ввод.

<h2 id="how-sessions-manage-devices">
  Как сессии управляют устройствами
</h2>

Каждое устройство принадлежит сессии, которая его запустила, поэтому [параллельные сессии](/docs/ru/desktop#work-in-parallel-with-sessions) не делят устройство: то, что вы видите в панели одной сессии, отражает работу этой сессии, а не другой. Переключение сессий на боковой панели переключает вид симулятора вместе с беседой, и переключение обратно возобновляет то же устройство, где оно остановилось. Если Claude работает с более чем одним устройством, каждое открывает свою собственную панель, до 4 на сессию.

Claude Code Desktop выключает симуляторы, которые он загрузил, как только они больше не используются: когда вы закрываете приложение, когда вы архивируете сессию или через 10 минут после отключения устройства от его панели. Устройства, которые вы загружаете самостоятельно, будь то из панели или в приложении Apple Simulator, никогда не выключаются автоматически. Чтобы выключить подключённое устройство прямо сейчас, используйте кнопку выключения в панели.

<h2 id="grant-claude-access-to-a-device">
  Предоставьте Claude доступ к устройству
</h2>

Claude просит ваше согласие перед управлением устройством, в то время как сборка приложения или открытие URL на нём следует режиму разрешений вашей сессии. Вы или ваша организация также можете полностью отключить доступ Claude.

<h3 id="allow-a-device-the-first-time">
  Разрешить устройство в первый раз
</h3>

В первый раз, когда Claude использует симулятор, приложение для рабочего стола просит вас разрешить это. Согласие охватывает управление этим устройством и снятие скриншотов с него, и вы даёте его один раз на устройство, а не один раз на сессию. Скриншоты Claude устройства отправляются в Anthropic и хранятся в соответствии с вашими обычными настройками хранения беседы, поэтому не входите в реальные учётные записи на устройстве, которое использует Claude.

После того как вы разрешите устройство, действия Claude на нём, такие как касание, ввод текста, запуск приложения и снятие скриншотов, выполняются без дополнительных подсказок. Они имеют такой же уровень доверия, как если бы вы щёлкали в панели, и они касаются только симулированного устройства, поэтому панель не требует разрешений macOS Accessibility и Screen Recording, которые требует компьютерное управление.

Если вы откажетесь, устройство всё ещё загружается и панель всё ещё работает для ваших собственных касаний; только доступ Claude остаётся отключённым. Чтобы передумать позже, нажмите **Let Claude use it** в панели.

<h3 id="actions-that-follow-your-permission-mode">
  Действия, которые следуют вашему режиму разрешений
</h3>

Два действия следуют [режиму разрешений](/docs/ru/permissions#permission-modes) вашей сессии вместо одноразового согласия:

* Открытие URL на устройстве, например для тестирования глубокой ссылки или загрузки страницы в Safari устройства, потому что URL может переносить данные с устройства.
* Сборка приложения, потому что `xcodebuild` запускает скрипты сборки вашего проекта на вашем Mac. Проверка уже выполняемой сборки не вызывает подсказку.

<h3 id="turn-off-simulator-access">
  Отключить доступ к симулятору
</h3>

Вы можете отключить доступ Claude к симулятору в настройках приложения для рабочего стола. Организации имеют два способа отключить его для всех:

* Параметр `disableMobileSimulatorTools` [управляемая настройка](/docs/ru/desktop#managed-settings) блокирует инструменты симулятора Claude. Панель симулятора остаётся пригодной для ваших собственных касаний, и параметр не может быть переопределён из приложения.
* Ключ политики `requireCoworkFullVmSandbox`, который запускает инструменты Claude внутри изолированной виртуальной машины вместо вашего Mac, отключает панель симулятора и инструменты симулятора Claude полностью, поэтому панель не может подключить устройство, пока он установлен.

Claude сообщит вам, когда применяется любой из них.

<h2 id="limitations">
  Ограничения
</h2>

Claude управляет только симулированными устройствами и не может управлять физическим iPhone или iPad. Чтобы протестировать на нём, запустите приложение на нём из Xcode самостоятельно, затем опишите то, что вы видите, или прикрепите снимок экрана к беседе, чтобы Claude мог работать с ним.

<h2 id="troubleshooting">
  Troubleshooting
</h2>

<h3 id="the-simulator-pane-doesn’t-open-when-claude-runs-the-app">
  Панель симулятора не открывается, когда Claude запускает приложение
</h3>

Claude может не распознать, что вы хотели запустить или протестировать приложение, или инструменты симулятора могут отсутствовать. Проверьте следующее:

* Явно укажите цель, например "запустите приложение в iOS Simulator и взаимодействуйте с потоком регистрации".
* Подтвердите, что Xcode и iOS симуляторы установлены и что ваша версия Xcode соответствует [требованиям](#requirements).
* Если ваша организация управляет Claude Code, [инструменты симулятора могут быть отключены политикой](#turn-off-simulator-access).
* Если вы находитесь в организации Enterprise с включённой конфигурацией HIPAA, панель симулятора вам недоступна.
* Панель симулятора требует Claude Desktop v1.24012.0 или позже. Откройте **Claude → Check for Updates**, затем перезагрузите приложение.

<h3 id="the-simulator-pane-says-no-simulators-were-found">
  Панель симулятора говорит, что симуляторы не найдены
</h3>

Если `xcode-select` указывает на Xcode 27, панель может сообщить об отсутствии симуляторов, даже если устройства существуют; см. [Панель симулятора не работает с Xcode 27](#the-simulator-pane-fails-with-xcode-27). В противном случае Xcode установлен, но не имеет iOS симуляторов для отображения. Панель симулятора показывает шаги настройки для выполнения и отмечает их по мере завершения каждого. Чтобы установить отсутствующую часть вручную, загрузите среду выполнения iOS симулятора из настроек Xcode или запустите `xcodebuild -downloadPlatform iOS`.

<h3 id="the-simulator-pane-fails-with-xcode-27">
  Панель симулятора не работает с Xcode 27
</h3>

Панель ещё не работает с Xcode 27, которая заменяет приложение Simulator на Device Hub. С выбранной Xcode 27 подключение устройства не удаётся или панель сообщает об отсутствии симуляторов, даже если устройства существуют.

Панель использует ту Xcode, на которую указывает `xcode-select`. Если Xcode 27 — ваша единственная установка, сначала установите Xcode 26.x рядом с ней. Затем выберите установку 26.x по её пути. Например, если она установлена как `/Applications/Xcode-26.4.app`:

```bash theme={null}
sudo xcode-select -s /Applications/Xcode-26.4.app
```

Запустите `xcode-select -p`, чтобы проверить, какая установка выбрана.
