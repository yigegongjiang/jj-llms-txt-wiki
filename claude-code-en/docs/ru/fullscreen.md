# Полноэкранный рендеринг

> Включите более плавный режим рендеринга без мерцания с поддержкой мыши и стабильным использованием памяти в длительных разговорах.

<Note>
  Полноэкранный рендеринг — это [исследовательский предпросмотр](#research-preview). Зависит ли [запуск в полноэкранном режиме или в классическом рендерере](#fullscreen-by-default) от вашей конфигурации. Выполните `/tui fullscreen` или `/tui default`, чтобы переключиться в текущем разговоре. Поведение может измениться на основе обратной связи.
</Note>

Полноэкранный рендеринг — это альтернативный путь рендеринга для Claude Code CLI, который устраняет мерцание, поддерживает использование памяти на плоском уровне в длительных разговорах и добавляет поддержку мыши. Он рисует интерфейс на буфере альтернативного экрана терминала, как `vim` или `htop`, и отображает только сообщения, которые в настоящее время видны. Это снижает объем данных, отправляемых на ваш терминал при каждом обновлении.

Разница наиболее заметна в эмуляторах терминала, где пропускная способность рендеринга является узким местом, таких как интегрированный терминал VS Code, tmux и iTerm2. Если позиция прокрутки вашего терминала прыгает в начало, пока Claude работает, или экран мигает при потоковой передаче выходных данных инструмента, этот режим решает эту проблему.

<Note>
  Термин полноэкранный описывает то, как Claude Code захватывает поверхность рисования терминала, так же как это делает `vim`. Это не имеет никакого отношения к максимизации окна терминала и работает при любом размере окна.
</Note>

<h2 id="enable-fullscreen-rendering">
  Включение полноэкранного рендеринга
</h2>

Выполните `/tui fullscreen` в любом разговоре Claude Code. CLI сохраняет параметр [`tui`](/docs/ru/settings-reference#tui) и перезапускает приложение в полноэкранном режиме с сохранением вашего разговора, поэтому вы можете переключаться во время сеанса без потери контекста. Выполните `/tui default` для переключения обратно на классический рендерер или `/tui` без аргументов, чтобы узнать, какой рендерер активен.

В [режиме чтения с экрана](/docs/ru/accessibility) Claude Code всегда использует классический рендерер, кроме присоединённых [фоновых сеансов](/docs/ru/agent-view), которые по-прежнему отображаются в полноэкранном режиме. Если вы выполните `/tui fullscreen` в любом другом сеансе, Claude Code выведет объяснение вместо переключения и не изменит сохранённый параметр `tui`.

Claude Code переносит следующее в перезапущенный сеанс:

* Разговор в том виде, в котором он отображается на экране. После [`/rewind`](/docs/ru/checkpointing#rewind-and-summarize) это означает:
  * Если вы выполнили перемотку назад в текущем сеансе, Claude Code перезапускается с точки перемотки, а не из более длинной стенограммы, сохранённой на диске. Например, если вы перемотали назад на три последних сообщения, перезапущенный сеанс откроется без них
  * Если вы перемотали назад до первого сообщения, Claude Code перезапускается с пустым разговором
* Ваш [режим разрешений](/docs/ru/permission-modes) и [уровень усилий](/docs/ru/model-config#adjust-effort-level)
* Модель, которую вы последний раз выбрали с помощью [`/model`](/docs/ru/model-config#setting-your-model)
* Правила, которые вы передали с помощью [`--allowed-tools` или `--disallowed-tools`](/docs/ru/cli-reference#cli-flags), и ваши флаги `--agent`, `--agents`, `--append-system-prompt` и `--system-prompt-snapshot`

Claude Code отказывается перезапускаться, если сеанс имеет ограничение, которое он не может передать перезапущенному процессу. Ограничения, которые он не может передать, включают:

* Флаги запуска, такие как замена [`--system-prompt`](/docs/ru/cli-reference#cli-flags), список разрешений [`--tools`](/docs/ru/cli-reference#cli-flags) или [`--setting-sources`](/docs/ru/cli-reference#cli-flags)
* Правила отказа или запроса, которые [обновление разрешений hook или SDK](/docs/ru/hooks#permission-update-entries) добавило только для этого сеанса

В этом случае Claude Code выводит [`Cannot switch renderers in this session`](/docs/ru/errors#cannot-switch-renderers-in-this-session) с объяснением причин. Он не переключается и ничего не сохраняет.

Вы также можете установить переменную окружения `CLAUDE_CODE_NO_FLICKER` перед запуском Claude Code:

```bash theme={null}
CLAUDE_CODE_NO_FLICKER=1 claude
```

О том, как параметр [`tui`](/docs/ru/settings-reference#tui) и переменная объединяются, когда оба установлены, см. в описании параметра. После [неудачного запуска полноэкранного режима](#fullscreen-renderer-didnt-finish-starting) Claude Code по-прежнему учитывает переменную, но не параметр. Команда `/tui` очищает `CLAUDE_CODE_NO_FLICKER` из перезапущенного процесса, чтобы вступил в силу параметр, который она записывает.

<h3 id="fullscreen-by-default">
  Полноэкранный режим по умолчанию
</h3>

Присоединённые [фоновые сеансы](/docs/ru/agent-view) отображаются в полноэкранном режиме, а другие сеансы в [режиме чтения с экрана](/docs/ru/accessibility) используют классический рендерер. В противном случае Claude Code запускает вас в рендерере из первой строки этой таблицы, которая соответствует вашей конфигурации:

| Ваша ситуация                                                                                                                                                                  | Рендерер, в котором вы начинаете    |
| :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------- |
| Вы установили [`CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`](/docs/ru/env-vars) или `CLAUDE_CODE_NO_FLICKER=0`                                                                          | Классический                        |
| Вы установили `CLAUDE_CODE_NO_FLICKER=1`                                                                                                                                       | Полноэкранный                       |
| Claude Code [отключил полноэкранный режим после неудачного запуска полноэкранного режима](#fullscreen-renderer-didnt-finish-starting) на этом компьютере                       | Классический                        |
| Вы находитесь в режиме интеграции [`tmux -CC`](#use-with-tmux) iTerm2 или подключены по SSH к Claude Code, работающему на Windows                                              | Классический                        |
| Вы сохранили параметр [`tui`](/docs/ru/settings-reference#tui)                                                                                                                      | Рендерер, который называет параметр |
| Ваш сеанс не [получает флаги функций от Anthropic](/docs/ru/env-vars#features-that-need-feature-flag-fetching), и Claude Code перестал предлагать диалог запуска на этом компьютере | Классический                        |
| Ваш сеанс не получает флаги функций от Anthropic, и первый запуск Claude Code на этом компьютере выполнял v2.1.239 или позже                                                   | Полноэкранный                       |
| Ваш сеанс получает флаги функций от Anthropic, и вы впервые использовали Claude Code 6 мая 2026 года или позже                                                                 | Полноэкранный                       |
| Что-либо ещё                                                                                                                                                                   | Классический                        |

Сеансы, которые не получают флаги функций, включают те, которые работают через [Amazon Bedrock](/docs/ru/amazon-bedrock), [Google Cloud's Agent Platform](/docs/ru/google-vertex-ai) или [Microsoft Foundry](/docs/ru/microsoft-foundry), а также те, у которых отключена телеметрия.

Если вы начинаете в классическом рендерере и не сохранили параметр `tui`, Claude Code может открыть диалог при запуске, предлагающий переключение:

* Если вы согласитесь, Claude Code перезапустится так же, как `/tui fullscreen`, перенося то же состояние сеанса, и сохранит параметр после того, как перезапущенный сеанс [успешно запустится](#fullscreen-renderer-didnt-finish-starting).
* Если вы выберете **Not now**, Claude Code больше не будет предлагать на этом компьютере.
* Claude Code перестаёт предлагать после того, как показал диалог на трёх запусках, независимо от ответа.

<h2 id="what-changes">
  Что изменилось
</h2>

Полноэкранная визуализация изменяет способ, которым CLI рисует на вашем терминале. Поле ввода остаётся зафиксированным в нижней части экрана вместо того, чтобы перемещаться при потоковой передаче выходных данных. Если поле ввода остаётся на месте, пока Claude работает, полноэкранная визуализация активна. В дереве визуализации сохраняются только видимые сообщения, поэтому память остаётся постоянной независимо от длины диалога.

Поскольку диалог находится в альтернативном буфере экрана вместо истории прокрутки вашего терминала, несколько вещей работают по-другому:

| До                                                                      | Сейчас                                                                                       | Подробности                                                     |
| :---------------------------------------------------------------------- | :------------------------------------------------------------------------------------------- | :-------------------------------------------------------------- |
| `Cmd+f` или поиск tmux для поиска текста                                | `Ctrl+o` для режима стенограммы, затем `/` для поиска или `[` для записи в историю прокрутки | [Поиск и просмотр диалога](#search-and-review-the-conversation) |
| Встроенное выделение и копирование нажатием и перетаскиванием терминала | Встроенное выделение, копирование автоматически при отпускании мыши                          | [Использование мыши](#use-the-mouse)                            |
| `Cmd`-клик для открытия URL                                             | `Cmd`-клик на macOS, `Ctrl`-клик в других местах                                             | [Использование мыши](#use-the-mouse)                            |

Если захват мыши мешает вашему рабочему процессу, вы можете [отключить его](#keep-native-text-selection), сохраняя визуализацию без мерцания.

<h2 id="use-the-mouse">
  Использование мыши
</h2>

Полноэкранная визуализация захватывает события мыши и обрабатывает их внутри Claude Code:

* **Щелкните в поле ввода подсказки**, чтобы расположить курсор в любом месте вводимого текста.
* **Щелкните предложение в списке команд `/` или файлов `@`**, чтобы принять его. При наведении курсора строка под ним выделяется.
* **Щелкните опцию в меню выбора**, чтобы выбрать её. Это касается запросов разрешений, `/model`, `/config` и других диалогов, которые показывают список опций. При наведении курсора на строку отображается указатель.
* **Щелкните опцию в меню множественного выбора**, чтобы переключить её, и нажмите кнопку отправки, чтобы подтвердить ваш выбор. Щелчок по строке свободного текста, например по строке `Other` в вопросе с несколькими вариантами ответов, фокусирует её поле ввода, чтобы вы могли ввести ответ. Требуется Claude Code v2.1.208 или более поздняя версия.
* **Щелкните значение параметра в панели `/config`**, чтобы изменить его, и прокручивайте список параметров колесом мыши. Требуется Claude Code v2.1.271 или более поздняя версия.
* **Прокручивайте меню выбора или множественного выбора колесом мыши**, когда оно содержит больше опций, чем может отобразить одновременно, например список `/model` в коротком окне терминала. Колесо прокручивает список, пока указатель находится над его опциями. Требуется Claude Code v2.1.280 или более поздняя версия.
* **Щелкните свёрнутый результат инструмента**, чтобы развернуть его и увидеть полный результат. Щелкните снова, чтобы свернуть. Вызов инструмента и его результат разворачиваются вместе. Щелкаемы только сообщения, которые имеют больше информации для отображения.
  * Щелчок также разворачивает результат команды оболочки `!`, будь то старый усечённый результат или строка прямого хода во время выполнения команды. Требуется Claude Code v2.1.257 или более поздняя версия.
* **Удерживайте `Cmd` на macOS или `Ctrl` на Linux и Windows и щелкните URL или путь к файлу**, чтобы открыть его. Простые URL-адреса `http://` и `https://` открываются в вашем браузере, а пути к файлам в результатах инструментов, например те, которые выводятся после Edit или Write, открываются в вашем приложении по умолчанию. Простой щелчок без модификатора не открывает ссылки, что соответствует поведению встроенного терминала.
  * Claude Code отображает сетевой путь (UNC), такой как `\\server\share\file.ts`, как простой текст без ссылки, потому что открытие сетевого пути может отправить ваши учётные данные Windows на хост, который он указывает.
  * Некоторые терминалы macOS перенаправляют `Cmd`+щелчок запущенному приложению вместо того, чтобы открывать ссылку самостоятельно, и протокол мыши терминала не имеет способа кодировать клавишу `Cmd`, поэтому Claude Code получает простой щелчок. В Ghostty и в Warp на macOS Claude Code это обнаруживает и позволяет простому щелчку на ссылке открыть её, а удержание `Cmd` по-прежнему работает.
  * В интегрированном терминале VS Code и аналогичных терминалах на основе xterm.js Claude Code полагается на собственный обработчик ссылок терминала, который использует тот же жест.
* **Щелкните и перетащите**, чтобы выбрать текст в любом месте разговора. Двойной щелчок выбирает слово, соответствуя границам слов iTerm2, так что путь к файлу выбирается как одна единица. Двойной щелчок по URL выбирает весь URL, включая схему. Тройной щелчок выбирает строку.
* **Прокручивайте колесом мыши**, чтобы перемещаться по разговору.

Выбранный текст автоматически копируется в буфер обмена при отпускании кнопки мыши. Чтобы отключить это, переключите Copy on select в `/config`.

Если Copy on select отключен, нажмите `Ctrl+Shift+c`, чтобы скопировать вручную. На терминалах, поддерживающих протокол клавиатуры kitty, таких как kitty, WezTerm, Ghostty и iTerm2, также работает `Cmd+c`. Если у вас активен выбор, `Ctrl+c` копирует вместо отмены.

При активном выборе удерживайте `Shift` и нажимайте клавиши со стрелками, чтобы расширить его с клавиатуры. `Shift+↑` и `Shift+↓` прокручивают область просмотра, когда выбор достигает верхнего или нижнего края. `Shift+Home` и `Shift+End` расширяют выбор до начала или конца текущей строки.

В обычном представлении подсказки то, что происходит с активным выбором, зависит от нажимаемой клавиши:

* **`Esc`**: Claude Code выполняет обычное действие клавиши, такое как прерывание выполняемого ответа или закрытие открытого диалога, и выбор остаётся выделенным.
* **`PgUp`, `PgDn`, `Ctrl+Home`, `Ctrl+End` или `Shift`, `Alt` или `Option`, или `Cmd`, `Win` или `Super` со стрелкой, `Home` или `End`**: выбор остаётся.
* **Любая другая клавиша, включая простые клавиши со стрелками, `Enter` и вводимые символы**: Claude Code очищает выбор.
* **Клавиша, привязанная к [`selection:clear`](/docs/ru/keybindings#scroll-actions)**: Claude Code очищает выбор, даже если клавиша — это `Esc` или другая клавиша, которая в противном случае сохраняет его. Действие не имеет привязки по умолчанию.

В [режиме стенограммы](#search-and-review-the-conversation) клавиши навигации и поиска, перечисленные там, также сохраняют выбор.

<h2 id="scroll-the-conversation">
  Прокрутка диалога
</h2>

Полноэкранная визуализация обрабатывает прокрутку внутри приложения. Используйте эти сочетания клавиш для навигации:

| Сочетание клавиш | Действие                                                            |
| :--------------- | :------------------------------------------------------------------ |
| `PgUp` / `PgDn`  | Прокрутка вверх или вниз на половину экрана                         |
| `Ctrl+Home`      | Переход к началу диалога                                            |
| `Ctrl+End`       | Переход к последнему сообщению и повторное включение автоследования |
| Колесо мыши      | Прокрутка на несколько строк за раз                                 |

Вы можете прокрутить назад к началу сеанса даже после [сжатия](/docs/ru/context-window#what-survives-compaction). Claude продолжает работать на основе сводки сжатия, но Claude Code сохраняет все предыдущие сообщения в полноэкранной прокрутке при повторных сжатиях.

На клавиатурах без выделенных клавиш `PgUp`, `PgDn`, `Home` или `End`, таких как клавиатуры MacBook, удерживайте `Fn` вместе со стрелками: `Fn+↑` отправляет `PgUp`, `Fn+↓` отправляет `PgDn`, `Fn+←` отправляет `Home`, и `Fn+→` отправляет `End`. `Ctrl+Fn+→` не достигает Claude Code на macOS, поэтому клавиатура MacBook по умолчанию не имеет рабочего сочетания для перехода в конец. Вместо этого используйте один из этих вариантов:

* Нажмите [кнопку перехода в конец](#auto-follow).
* Прокрутите до конца колесом мыши, чтобы возобновить следование.
* Переназначьте `scroll:bottom` на сочетание, которое может отправить ваша клавиатура.

Эти действия можно переназначить. См. [Действия прокрутки](/docs/ru/keybindings#scroll-actions) для полного списка имён действий, включая варианты с половиной страницы и полной страницей, которые не имеют привязки по умолчанию.

Пока вы прокручиваете вверх, тусклая строка заголовка в верхней части диалога показывает самый последний запрос, который прокрутился выше представления. Нажмите на строку, чтобы перейти к этому запросу.

<h3 id="auto-follow">
  Автоследование
</h3>

Прокрутка вверх приостанавливает автоследование, чтобы новый вывод не тянул вас обратно в конец. Кнопка `Перейти в конец` плывёт над нижним краем стенограммы, пока вы прокручиваете вверх, и показывает счётчик, например `3 новых сообщения`, когда поступает новый вывод. Нажмите её, нажмите `Ctrl+End` или прокрутите до конца, чтобы возобновить следование.

Пока автоследование приостановлено, представление также остаётся там, где вы его прокрутили, когда ответ заканчивает потоковую передачу.

Подсказка клавиатуры кнопки отражает то, что может отправить ваша клавиатура. На macOS она предлагает нажать, или `Fn+↓` для прокрутки, потому что `Ctrl+End` не достигает Claude Code с клавиатуры Mac. Переназначьте [`scroll:bottom`](/docs/ru/keybindings#scroll-actions) и кнопка покажет ваше сочетание на каждой платформе.

На терминале, слишком узком для полной метки, кнопка сокращает подсказку вместо переноса на строку стенограммы ниже.

Чтобы полностью отключить автоследование, чтобы представление оставалось там, где вы его оставили, откройте `/config` и установите Автопрокрутка на отключено. С отключённой автопрокруткой представление никогда не прыгает в конец самостоятельно. Запросы разрешений и другие диалоги, требующие ответа, всё равно прокручиваются в поле зрения независимо от этого параметра.

<h3 id="mouse-wheel-scrolling">
  Прокрутка колесом мыши
</h3>

Прокрутка колесом мыши требует, чтобы ваш терминал пересылал события мыши в Claude Code. Большинство терминалов делают это всякий раз, когда приложение это запрашивает. iTerm2 делает это параметром для каждого профиля: если колесо ничего не делает, но `PgUp` и `PgDn` работают, откройте Settings → Profiles → Terminal и включите Включить отчёты о мыши. Этот же параметр также требуется для работы щелчка для развёртывания и выделения текста.

Если прокрутка колесом мыши кажется медленной, ваш терминал может отправлять одно событие прокрутки на физический щелчок без множителя. Некоторые терминалы, такие как Ghostty и iTerm2 с включённой более быстрой прокруткой, уже усиливают события колеса. Другие, включая встроенный терминал VS Code, отправляют ровно одно событие на щелчок. Claude Code не может определить, какой из них.

Установите `CLAUDE_CODE_SCROLL_SPEED` для умножения базового расстояния прокрутки:

```bash theme={null}
export CLAUDE_CODE_SCROLL_SPEED=3
```

Значение `3` соответствует значению по умолчанию в `vim` и аналогичных приложениях. Параметр принимает любое положительное значение до 20, включая дробные значения ниже 1, такие как `0.25`, чтобы замедлить ускоренную прокрутку трекпада и колеса в терминалах, которые уже усиливают события колеса.

Чтобы интерактивно отрегулировать скорость прокрутки, запустите `/scroll-speed`. Диалог показывает линейку, по которой вы можете прокручивать, пока он открыт, чтобы вы могли почувствовать изменение немедленно. Нажимайте `←` и `→` для регулировки скорости, `r` для сброса на автоматически определённое значение по умолчанию и `Enter` для сохранения. Диалог переходит целыми числами до 10, а на терминалах, поддерживающих более точное управление, он также предлагает четвертьшаги вплоть до 0,25.

Команда записывает то же значение, которое устанавливает переменная окружения `CLAUDE_CODE_SCROLL_SPEED`, сохранённое в `~/.claude/settings.json`. Максимум диалога составляет 10: если вы установите более высокое значение через переменную окружения, диалог показывает 10, и сохранение из диалога сохраняет 10. Команда недоступна в терминале IDE JetBrains.

Отдельно от базовой скорости Claude Code ускоряет скорость прокрутки, когда вы быстро крутите колесо, поэтому быстрое вращение охватывает большее расстояние, чем одинаковое количество медленных щелчков. Чтобы отключить ускорение и сохранить постоянную скорость на щелчок, установите `wheelScrollAccelerationEnabled` на `false` в [`settings.json`](/docs/ru/settings-reference#all-settings). Этот параметр требует Claude Code v2.1.174 или позже.

<h3 id="scroll-in-the-jetbrains-ide-terminal">
  Прокрутка в терминале IDE JetBrains
</h3>

В терминале IDE JetBrains Claude Code применяет собственную обработку прокрутки и игнорирует `CLAUDE_CODE_SCROLL_SPEED`. Терминал отправляет события прокрутки с гораздо более высокой скоростью, чем другие эмуляторы, поэтому множитель, настроенный в другом месте, здесь перелетает.

В 2025.2 терминал также имеет ошибки прокрутки колесом, которые создают ложные стрелки и события неправильного направления. Claude Code обнаруживает их во время выполнения и автоматически их смягчает, поэтому прокрутка трекпада и колеса мыши работают без конфигурации. Для лучшего опыта прокрутки обновитесь до версии 2025.3 или позже. Claude Code показывает подсказку в первый раз, когда вы прокручиваете, если обнаруживает ошибку.

<h2 id="search-and-review-the-conversation">
  Поиск и просмотр диалога
</h2>

`Ctrl+o` переключается между обычным режимом подсказки и режимом стенограммы.

Для более спокойного представления, которое показывает только вашу последнюю подсказку, однострочное резюме вызовов инструментов с редактированием diffstats и финальный ответ, запустите `/focus`. Параметр сохраняется между сеансами. Запустите `/focus` снова, чтобы отключить его.

Режим стенограммы получает навигацию и поиск в стиле `less`:

| Клавиша                               | Действие                                                                                                                                   |
| :------------------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                                   | Открыть поиск. Введите текст для поиска совпадений, нажмите `Enter` для подтверждения, `Esc` для отмены и восстановления позиции прокрутки |
| `n` / `N`                             | Перейти к следующему или предыдущему совпадению. Работает после закрытия строки поиска                                                     |
| `j` / `k` или `↑` / `↓`               | Прокрутить на одну строку                                                                                                                  |
| `g` / `G` или `Home` / `End`          | Перейти в начало или конец                                                                                                                 |
| `{` / `}`                             | Перейти к предыдущей или следующей подсказке                                                                                               |
| `Ctrl+u` / `Ctrl+d`                   | Прокрутить на половину страницы                                                                                                            |
| `Ctrl+b` / `Ctrl+f` или `Space` / `b` | Прокрутить на полную страницу                                                                                                              |
| `Ctrl+o`, `Esc` или `q`               | Выйти из режима стенограммы и вернуться к подсказке                                                                                        |

Поиск `Cmd+f` вашего терминала и поиск tmux не видят диалог, потому что он находится в буфере альтернативного экрана, а не в собственном буфере прокрутки. Чтобы вернуть содержимое в ваш терминал, нажмите `Ctrl+o` для входа в режим стенограммы сначала, затем:

* **`[`**: записывает полный диалог в собственный буфер прокрутки вашего терминала со всеми развёрнутыми выходными данными инструментов. Диалог теперь является обычным текстом в вашем терминале, поэтому `Cmd+f`, режим копирования tmux и любой другой встроенный инструмент могут искать или выбирать его. Длительные сеансы могут на момент приостановиться во время этого процесса. Это продолжается до выхода из режима стенограммы с помощью `Esc` или `q`, что возвращает вас к полноэкранному отображению. Следующий `Ctrl+o` начинает заново.
* **`v`**: записывает диалог во временный файл и открывает его в `$VISUAL` или `$EDITOR`.

<h2 id="watch-your-changes-in-the-diff-panel">
  Смотрите ваши изменения на панели diff
</h2>

При полноэкранном отображении [`/diff`](/docs/ru/interactive-mode#review-changes-with-%2Fdiff) открывает панель рядом с беседой вместо средства просмотра, которое нужно закрывать, поэтому вы можете наблюдать, как изменения накапливаются во время работы Claude. На широком терминале панель также может открыться самостоятельно, как только Claude начнет редактировать файлы. [Панель diff](/docs/ru/interactive-mode#diff-panel) описывает, что она показывает, как держать её закрытой и как изменить, с чем она сравнивает.

<h2 id="clear-the-conversation">
  Очистить беседу
</h2>

Выполните `/clear` для начала новой беседы.

Если экран выглядит искажённым или частично пустым, нажмите `Ctrl+L` для перерисовки экрана. Перерисовка сохраняет беседу и ваш ввод на месте.

`Cmd+K` делает то же самое, что `Ctrl+L`, когда ваш терминал передает его в Claude Code. iTerm2 и Terminal.app обрабатывают `Cmd+K` самостоятельно и очищают свой собственный экран, а Claude Code обнаруживает очищенный экран и перерисовывает беседу. До версии 2.1.280, начиная с версии 2.1.260, нажатие `Ctrl+L` или `Cmd+K`, где оно достигает Claude Code, очищало экран при полноэкранной визуализации. До версии 2.1.238 двойное нажатие `Ctrl+L` в течение двух секунд выполняло `/clear`.

<h2 id="use-with-tmux">
  Использование с tmux
</h2>

Полноэкранная визуализация работает внутри tmux с тремя оговорками.

Прокрутка колесом мыши требует режима мыши tmux. Если ваш файл `~/.tmux.conf` еще не включает эту функцию, добавьте эту строку и перезагрузите конфигурацию:

```bash theme={null}
set -g mouse on
```

Без режима мыши события колеса переходят к tmux вместо Claude Code. Прокрутка с клавиатуры с помощью `PgUp` и `PgDn` работает в любом случае. Claude Code выводит одноразовую подсказку при запуске, если обнаруживает tmux с отключенным режимом мыши.

Полноэкранная визуализация несовместима с режимом интеграции tmux в iTerm2, который вы активируете с помощью `tmux -CC`. В режиме интеграции iTerm2 отображает каждую панель tmux как встроенное разделение, а не позволяет tmux рисовать на терминале. Буфер альтернативного экрана и отслеживание мыши там работают неправильно: колесо мыши ничего не делает, а двойной щелчок может повредить состояние терминала. Не включайте полноэкранную визуализацию в сеансах `tmux -CC`. Обычный tmux внутри iTerm2 без `-CC` работает нормально.

Релизы tmux до версии 3.6 включительно не реализуют синхронизированный вывод, поэтому в этих версиях вы можете видеть больше мерцания при перерисовке, чем при запуске Claude Code непосредственно в вашем терминале. Claude Code проверяет терминал на поддержку синхронизированного вывода при запуске и использует его, когда терминал об этом сообщает. Если вы видите мерцание в tmux, обновите tmux до последней версии или запустите Claude Code на отдельной вкладке терминала вне tmux.

<h2 id="keep-native-text-selection">
  Сохранение нативного выделения текста
</h2>

Захват мыши — это наиболее частый источник трений, особенно при работе через SSH или внутри tmux. Когда Claude Code захватывает события мыши, нативное копирование при выделении вашего терминала перестаёт работать. Выделение, которое вы делаете щелчком и перетаскиванием, существует внутри Claude Code, а не в буфере выделения вашего терминала, поэтому режим копирования tmux, подсказки Kitty и подобные инструменты его не видят.

Claude Code записывает выделение в буфер обмена вашей системы, и путь, который он использует, зависит от вашей конфигурации. В локальной сессии он запускает нативный инструмент буфера обмена:

* **macOS**: `pbcopy`
* **Linux**: `wl-copy` на Wayland или `xclip` или `xsel` на X11, в зависимости от того, что установлено. Claude Code записывает как буфер обмена, так и PRIMARY выделение, поэтому вставка средней кнопкой мыши работает.
* **Windows и WSL**: PowerShell `Set-Clipboard`

Внутри tmux он также записывает в буфер вставки tmux. Через SSH он переходит на escape-последовательности OSC 52. Внутри GNU screen Claude Code также копирует длинные выделения в буфер обмена. До версии v2.1.219, если вы копировали выделение длиннее примерно 570 символов, GNU screen выводил текст в кодировке base64 в окно. Claude Code выводит уведомление после каждого копирования, сообщая вам, какой путь был использован.

Некоторые терминалы блокируют OSC 52 по умолчанию. iTerm2 блокирует его, пока вы не включите Settings → General → Selection → Applications in terminal may access clipboard; запуск [`/terminal-setup`](/docs/ru/terminal-config) в iTerm2 включает это для вас.

Для одноразового нативного выделения клавиша, которую нужно использовать, зависит от вашего терминала:

* **Terminal.app**: `Fn`
* **iTerm2**: `Option`
* **VS Code, Cursor и Devin Desktop**: `Shift` или `Option` на macOS с включённой настройкой `terminal.integrated.macOptionClickForcesSelection`
* **Большинство других терминалов**: `Shift`

Удерживайте эту клавишу, пока щёлкаете и перетаскиваете. Ваш терминал сам обрабатывает выделение вместо того, чтобы передавать его в Claude Code, поэтому сочетания клавиш копирования, такие как `Cmd+C`, работают с тем, что вы выделили. Claude Code также показывает правильную клавишу в своей подсказке на экране.

Через SSH или внутри tmux Claude Code не всегда может определить терминал, с которого вы подключаетесь, поэтому подсказка перечисляет возможные клавиши.

Если вы полагаетесь на нативное выделение всё время, установите `CLAUDE_CODE_DISABLE_MOUSE=1`, чтобы отказаться от захвата мыши, сохраняя при этом отсутствие мерцания и плоскую память:

```bash theme={null}
CLAUDE_CODE_NO_FLICKER=1 CLAUDE_CODE_DISABLE_MOUSE=1 claude
```

С отключённым захватом мыши прокрутка с помощью клавиатуры с `PgUp`, `PgDn`, `Ctrl+Home` и `Ctrl+End` по-прежнему работает, и ваш терминал обрабатывает выделение нативно. Вы теряете щелчок для позиционирования курсора, щелчок для расширения вывода инструмента, щелчок по URL и прокрутку колеса внутри Claude Code.

Чтобы сохранить прокрутку колеса, но отключить обработку щелчков, перетаскивания и наведения, установите вместо этого `CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1`. Требуется Claude Code версии v2.1.195 или позже. `CLAUDE_CODE_DISABLE_MOUSE` имеет приоритет, когда установлены обе переменные.

С отключёнными щелчками Claude Code по-прежнему захватывает мышь, поэтому колесо и сенсорная панель прокручивают беседу, но левые щелчки ничего не делают внутри Claude Code. Вам по-прежнему нужно удерживать клавишу вашего терминала для нативного выделения щелчком и перетаскиванием. Щелчок правой кнопкой и вставка средней кнопкой продолжают работать на терминалах, которые их поддерживают.

<h2 id="troubleshooting">
  Troubleshooting
</h2>

<h3 id="stale-or-misplaced-text-on-screen">
  Устаревший или неправильно расположенный текст на экране
</h3>

Полноэкранная визуализация отправляет только ячейки, которые изменились между кадрами. Некоторые терминалы, чаще всего Windows Terminal и другие хосты на основе ConPTY, неправильно объединяют эти позиционированные записи и оставляют фрагменты более ранних выходных данных на экране до тех пор, пока вы не измените размер окна.

Установите [`CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1`](/docs/ru/env-vars), чтобы перерисовывать каждую ячейку на каждом кадре вместо отправки добавочных обновлений.

На Windows PowerShell:

```powershell theme={null}
$env:CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT = "1"
claude
```

На macOS или Linux:

```bash theme={null}
CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1 claude
```

На Windows Claude Code уже автоматически включает полную перерисовку для фоновых сеансов и [представления агента](/docs/ru/agent-view), поэтому вам нужно установить переменную только для интерактивного полноэкранного сеанса, который вы запустили напрямую.

<h3 id="fullscreen-renderer-didnt-finish-starting">
  `Claude Code's fullscreen renderer didn't finish starting last time` появляется при запуске
</h3>

Если полноэкранный сеанс на этом компьютере аварийно завершится до успешного запуска, Claude Code запустит ваш следующий сеанс в классическом средстве визуализации и выведет одну из двух строк. Сеанс считается успешно запущенным после того, как он нарисует свой первый кадр и затем либо проработает 10 секунд, либо вы завершите его с помощью `/exit`, Ctrl+C или Ctrl+D. Строка, которую вы видите, говорит вам, что Claude Code делает после этого сеанса:

* После одного неудачного запуска вы видите `Claude Code's fullscreen renderer didn't finish starting last time on this machine`. Claude Code пытается использовать полноэкранную визуализацию снова в следующем запущенном вами сеансе
* После двух неудачных запусков вы видите `Claude Code's fullscreen renderer has repeatedly failed to start on this machine`. Claude Code продолжает использовать классическое средство визуализации до тех пор, пока вы не обновите Claude Code или не запустите `/tui fullscreen`, и ничего не выводит в этих более поздних сеансах

Чтобы подтвердить, что неудачный запуск является причиной того, что вы находитесь в классическом средстве визуализации, запустите `/tui` без аргументов. Пока неудачный запуск является причиной, строка `Current renderer` это указывает.

Чтобы сохранить классическое средство визуализации, запустите `/tui default`, которое сохраняет параметр `tui` без перезагрузки. Чтобы попробовать полноэкранную визуализацию снова, запустите `/tui fullscreen`. Если этот сеанс также не завершит запуск, [сообщите о проблеме](#research-preview).

До версии 2.1.236 Claude Code продолжал запускать сеансы в полноэкранной визуализации после неудачного запуска.

<h4 id="how-claude-code-counts-failed-starts">
  Как Claude Code считает неудачные запуски
</h4>

* Сеансы, которые учитываются: только сеансы, которые запустились в полноэкранной визуализации, потому что ваш параметр `tui` это указывает, потому что вы приняли [диалог при запуске](#fullscreen-by-default), или потому что Claude Code запускает вас в полноэкранном режиме по умолчанию
* `CLAUDE_CODE_NO_FLICKER=1`: если вы установите это, Claude Code визуализирует этот сеанс в полноэкранном режиме даже после неудачного запуска и не считает его
* Сброс счетчика: Claude Code считает неудачные запуски для каждой версии Claude Code, и успешный полноэкранный запуск сбрасывает счетчик
* Диалог при запуске: если вы приняли диалог и перезапущенный сеанс аварийно завершился, Claude Code не выводит ни одну строку и не показывает диалог снова в этой версии Claude Code

<h2 id="research-preview">
  Research preview
</h2>

Fullscreen rendering — это функция исследовательского предпросмотра. Она была протестирована на распространённых эмуляторах терминала, но вы можете столкнуться с проблемами отрисовки на менее распространённых терминалах или необычных конфигурациях.

Если вы столкнулись с проблемой, запустите `/feedback` внутри Claude Code, чтобы сообщить о ней, или откройте проблему в [репозитории claude-code на GitHub](https://github.com/anthropics/claude-code/issues). Укажите название и версию вашего эмулятора терминала.

Чтобы отключить fullscreen rendering, запустите `/tui default` или отмените установку `CLAUDE_CODE_NO_FLICKER`, если вы включили её таким образом. Когда вы переключитесь обратно с помощью `/tui default`, Claude Code может сначала показать дополнительное приглашение обратной связи, спрашивающее, что заставило вас переключиться. Введите причину и нажмите `Enter`, чтобы отправить её, или нажмите `Esc`, чтобы пропустить. CLI в любом случае перезагружается в классический рендерер. Чтобы принудительно использовать классический рендерер независимо от сохранённого параметра `tui`, установите `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`. Классический рендерер сохраняет беседу в собственном буфере прокрутки вашего терминала, поэтому `Cmd+f` и режим копирования tmux работают как обычно.

Фоновые сеансы, открытые из [представления агента](/docs/ru/agent-view) или `claude attach`, всегда используют fullscreen rendering. Присоединяемый терминал входит в буфер альтернативного экрана для отображения сеанса, а классический рендерер не имеет там прокрутки или обработки мыши, поэтому параметр `tui` и `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN` к ним не применяются.
