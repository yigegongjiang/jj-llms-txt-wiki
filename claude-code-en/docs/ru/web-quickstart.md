# Начало работы с Claude Code в облаке

> Запустите Claude Code в облаке из браузера или мобильного приложения. Подключите репозиторий GitHub, отправьте задачу и просмотрите PR без локальной настройки.

<Note>
  Облачные сеансы доступны в планах Pro, Max и Team, а также для пользователей Enterprise с премиум-местами или местами Chat + Claude Code.
</Note>

Облачный сеанс запускает Claude Code на облачной инфраструктуре вместо вашей машины, управляемой Anthropic по умолчанию. Этот краткий старт запускает один с [claude.ai/code](https://claude.ai/code) в вашем браузере. Вы также можете запустить один из мобильного приложения Claude, приложения Desktop или вашего терминала с помощью `claude --cloud`.

Вам потребуется репозиторий GitHub для [начала работы](#connect-github). Claude клонирует его в изолированную виртуальную машину, вносит изменения и отправляет ветку для вашего просмотра. Сеансы сохраняются на всех устройствах, поэтому задача, которую вы начали на ноутбуке, готова к просмотру с телефона позже.

Облачные сеансы хорошо подходят для:

* **Параллельные задачи**: запускайте несколько независимых задач одновременно, каждую в своем сеансе и ветке, без управления несколькими worktrees
* **Репозитории, которые у вас нет локально**: Claude клонирует репозиторий заново в каждом сеансе, поэтому вам не нужно его проверять
* **Задачи, которые не требуют частого управления**: отправьте четко определенную задачу, займитесь чем-то другим и просмотрите результат, когда Claude закончит
* **Вопросы о коде и исследование**: поймите кодовую базу или проследите, как реализована функция, без локального клона

Для работы, которая требует вашей локальной конфигурации, инструментов или окружения, запуск Claude Code локально или использование [Remote Control](/docs/ru/remote-control) — лучший вариант.

<h2 id="how-sessions-run">
  Как работают сеансы
</h2>

Описанные ниже шаги относятся к сеансам, размещённым на серверах Anthropic. В [самостоятельно размещённой среде](/docs/ru/self-hosted-environments) клонирование и всё остальное выполняется на собственных средствах выполнения вашей организации, где границы сети, настройка и поведение отправки настраиваются оператором. Когда вы отправляете задачу:

1. **Клонирование и подготовка**: ваш репозиторий клонируется на управляемую Anthropic ВМ, и ваш [скрипт настройки](/docs/ru/cloud-environments#setup-scripts) запускается, если он настроен.
2. **Настройка сети**: доступ в интернет устанавливается на основе [уровня доступа](/docs/ru/cloud-environments#access-levels) вашего окружения.
3. **Работа**: Claude анализирует код, вносит изменения, запускает тесты и проверяет свою работу. Вы можете наблюдать и управлять на протяжении всего процесса или отойти и вернуться, когда это будет сделано.
4. **Отправка ветки**: когда Claude достигает точки остановки, он отправляет свою ветку на GitHub. Вы просматриваете diff, оставляете встроенные комментарии, создаете PR или отправляете еще одно сообщение, чтобы продолжить.

Сеанс не закрывается при отправке ветки. Создание PR и дальнейшие правки происходят в одном и том же разговоре.

<h2 id="compare-ways-to-run-claude-code">
  Сравнение способов запуска Claude Code
</h2>

Claude Code ведет себя одинаково везде. Что меняется, так это место выполнения кода и доступность вашей локальной конфигурации:

|                                               | Cloud session                                                                                                                | Local session                                                                                                                            | Local session с [Remote Control](/docs/ru/remote-control)                        |
| :-------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------- |
| **Код выполняется на**                        | Cloud VM, управляемой Anthropic по умолчанию                                                                                 | Вашей машине                                                                                                                             | Вашей машине                                                                |
| **Вы запускаете его из**                      | claude.ai/code, мобильного приложения Claude, приложения Desktop с выбранным **Cloud** или `claude --cloud`                  | Вашего терминала, вашей IDE или приложения Desktop с выбранным **Local**                                                                 | Вашего терминала, расширения VS Code или приложения Desktop                 |
| **Вы общаетесь из**                           | claude.ai, мобильного приложения или приложения Desktop                                                                      | Места, где вы его запустили                                                                                                              | claude.ai или мобильного приложения, а также из места, где вы его запустили |
| **Использует вашу локальную конфигурацию**    | Нет, только репозиторий                                                                                                      | Да                                                                                                                                       | Да                                                                          |
| **Требует GitHub**                            | Да, или [отправьте локальный репозиторий](/docs/ru/claude-code-on-the-web#send-local-repositories-without-github) через `--cloud` | Нет                                                                                                                                      | Нет                                                                         |
| **Продолжает работать при отключении**        | Да                                                                                                                           | Нет                                                                                                                                      | Пока сеанс остается открытым на вашей машине                                |
| **[Режимы разрешений](/docs/ru/permission-modes)** | Принять правки, Plan, Auto                                                                                                   | Все режимы в терминале; см. [Переключение режимов разрешений](/docs/ru/permission-modes#switch-permission-modes) для IDE и приложения Desktop | Manual, Принять правки или Plan из claude.ai и мобильного приложения        |
| **Доступ в сеть**                             | Настраивается для каждого окружения                                                                                          | Сеть вашей машины                                                                                                                        | Сеть вашей машины                                                           |

Смотрите документацию [быстрого старта терминала](/docs/ru/quickstart), [приложения Desktop](/docs/ru/desktop) или [Remote Control](/docs/ru/remote-control) для настройки локальных сеансов.

<h2 id="connect-github">
  Подключение GitHub
</h2>

Подключение GitHub — это одноразовый процесс. Если вы уже используете GitHub CLI, вы можете [сделать это из терминала](#connect-from-your-terminal) вместо браузера.

<Note>
  На планах Team и Enterprise шаг **Sign in with GitHub** работает только после того, как [Owner](/docs/ru/server-managed-settings#access-control) вашей организации Claude включит коннектор GitHub в [**Admin settings > Connectors**](https://claude.ai/admin-settings/connectors). До этого момента этот шаг показывает "GitHub access is required for Claude Code on the web" вместо кнопки входа. После включения коннектора перезагрузите [claude.ai/code](https://claude.ai/code) и начните заново с первого шага. Второй переключатель, [Quick web setup](/docs/ru/claude-code-on-the-web#github-authentication-options) в [**Admin settings > Claude Code**](https://claude.ai/admin-settings/claude-code), является необязательным: при его включении `/web-setup` работает и встроенная настройка создает окружение для членов.
</Note>

<Steps>
  <Step title="Посетите claude.ai/code">
    Перейдите на [claude.ai/code](https://claude.ai/code) и войдите со своей учетной записью claude.ai.
  </Step>

  <Step title="Войдите с помощью GitHub">
    После входа claude.ai/code предложит вам подключить GitHub. Следуйте подсказке, и claude.ai/code отправит вас на страницу авторизации GitHub. Одобрите запрос авторизации, и GitHub вернет вас на claude.ai/code. Облачные сеансы работают с существующими репозиториями GitHub. Чтобы запустить новый проект, сначала [создайте пустой репозиторий на GitHub](https://github.com/new).

    С этим подключением сеанс может клонировать любой открытый репозиторий, но может работать в приватном репозитории только когда приложение Claude GitHub установлено на нем. [Установите приложение Claude GitHub](https://github.com/apps/claude/installations/new) на каждую учетную запись GitHub или организацию, чьи приватные репозитории вы хотите использовать. В организации GitHub владелец организации может потребоваться одобрить установку. Установка приложения также включает [Auto-fix](/docs/ru/claude-code-on-the-web#auto-fix-pull-requests), который позволяет Claude реагировать на сбои CI и комментарии рецензентов в pull requests в этих репозиториях.

    Если встроенная настройка предложит вам установить приложение Claude GitHub на этом этапе и вы предпочитаете сделать это позже, нажмите **Skip**.
  </Step>

  <Step title="Настройте ваше окружение по умолчанию">
    [Облачное окружение](/docs/ru/cloud-environments) — это сохраненная конфигурация, которая контролирует, какой доступ в сеть имеет Claude во время сеансов и что запускается при запуске сеанса. То, что происходит после подключения GitHub, зависит от вашего плана:

    * **Pro и Max**: встроенная настройка создает для вас окружение с именем **Default**.
    * **Team и Enterprise**: встроенная настройка показывает форму **Create your first cloud environment**. Оставьте предзаполненное имя и доступ в сеть без изменений и нажмите **Create & finish**, чтобы создать окружение **Default**. Если Owner включил [Quick web setup](/docs/ru/claude-code-on-the-web#github-authentication-options), встроенная настройка создает **Default** для вас вместо этого.

    **Default** использует [`Trusted` доступ в сеть](/docs/ru/cloud-environments#access-levels): сеансы получают доступ к [общим реестрам пакетов](/docs/ru/cloud-environments#default-allowed-domains) и другим доменам в списке разрешений, и ничему больше через сеть сеанса. Смотрите [Installed tools](/docs/ru/cloud-environments#installed-tools) для того, что доступно без какой-либо конфигурации.

    Для первого проекта окружение **Default** работает как есть. Чтобы изменить его доступ в сеть, добавить переменные окружения или запустить [скрипт настройки](/docs/ru/cloud-environments#setup-scripts) перед запуском сеансов, [отредактируйте его или создайте дополнительные окружения](/docs/ru/cloud-environments#configure-your-environment).
  </Step>
</Steps>

<h3 id="connect-from-your-terminal">
  Подключение из терминала
</h3>

Если вы уже используете GitHub CLI (`gh`), вы можете подключить GitHub для облачных сеансов из терминала. Это требует [Claude Code CLI](/docs/ru/quickstart). На планах Team и Enterprise `/web-setup` доступен только после того, как Owner включит [Quick web setup](/docs/ru/claude-code-on-the-web#github-authentication-options).

Когда вы запускаете `/web-setup`, Claude Code читает токен, который выводит `gh auth token`, просит вас подтвердить и отправляет токен в Anthropic. Anthropic хранит его в зашифрованном виде с вашей учетной записью claude.ai, и ваши облачные сеансы используют его для доступа к GitHub до тех пор, пока вы не [удалите его](#remove-the-web-setup-token). Облачный сеанс, который вы запускаете сами, может затем получить доступ к любому репозиторию, к которому может получить доступ этот токен, без установки приложения Claude GitHub. Потоки в [проекте](/docs/ru/claude-projects#set-up-github-access) по-прежнему требуют приложение Claude GitHub.

Если вы уже подключили GitHub в браузере, `/web-setup` предупредит вас, что продолжение заменит это подключение для ваших облачных сеансов.

<Note>
  Организации с включенным [Zero Data Retention](/docs/ru/zero-data-retention) не могут использовать `/web-setup` или другие функции облачных сеансов. Если GitHub CLI не установлен или не аутентифицирован, Claude Code открывает поток встроенной настройки браузера вместо этого.
</Note>

<Steps>
  <Step title="Аутентификация с помощью GitHub CLI">
    В вашей оболочке аутентифицируйте GitHub CLI, если вы еще этого не сделали:

    ```bash theme={null}
    gh auth login
    ```
  </Step>

  <Step title="Войдите в Claude">
    В Claude Code CLI запустите `/login` для входа со своей учетной записью claude.ai. Пропустите этот шаг, если вы уже вошли со своей учетной записью claude.ai. Аутентификация с помощью ключа API не считается. Чтобы проверить, запустите `/status` и подтвердите, что строка **Login method** показывает учетную запись claude.ai.
  </Step>

  <Step title="Запустите /web-setup">
    В Claude Code CLI запустите:

    ```text theme={null}
    /web-setup
    ```

    Подтвердите подсказку для отправки вашего токена `gh` на вашу учетную запись Claude. При успехе Claude Code выводит `Connected as <your-github-username>` и открывает [claude.ai/code](https://claude.ai/code) в вашем браузере. Если у вас еще нет облачного окружения, `/web-setup` создает его с доступом в сеть Trusted и без скрипта настройки. Вы можете [отредактировать окружение или добавить переменные](/docs/ru/cloud-environments#configure-your-environment) позже. После завершения `/web-setup` вы можете запускать облачные сеансы из терминала с помощью [`--cloud`](/docs/ru/claude-code-on-the-web#from-terminal-to-cloud) или настроить повторяющиеся задачи с помощью [`/schedule`](/docs/ru/routines).
  </Step>
</Steps>

<h4 id="remove-the-web-setup-token">
  Удалите токен `/web-setup`
</h4>

Чтобы удалить токен из вашей учетной записи Claude, отключите GitHub в [claude.ai/customize/connectors](https://claude.ai/customize/connectors). Отключение удаляет учетные данные GitHub, которые используют ваши облачные сеансы, независимо от того, поступили ли они из браузера или из `/web-setup`, поэтому облачные сеансы теряют доступ к GitHub до тех пор, пока вы не подключитесь снова. Ваш локальный `gh` остается вошедшим, и токен остается действительным на GitHub.

Чтобы аннулировать сам токен, отозвите его на GitHub. Если вы вошли в `gh` через браузер, токен принадлежит записи **GitHub CLI** в разделе [**Settings > Applications > Authorized OAuth Apps**](https://github.com/settings/applications) на GitHub, и отзыв этой записи также выходит из GitHub CLI на ваших машинах. Облачные сеансы затем теряют доступ к GitHub до тех пор, пока вы не запустите `gh auth login` и `/web-setup` снова.

<h2 id="start-a-task">
  Начните задачу
</h2>

С подключенным GitHub и созданным окружением вы готовы отправлять задачи.

<Steps>
  <Step title="Выберите репозиторий и ветку">
    На [claude.ai/code](https://claude.ai/code) или на вкладке Code в мобильном приложении Claude нажмите селектор репозитория под полем ввода и выберите репозиторий для работы Claude. Каждый репозиторий показывает селектор ветки. Измените его, чтобы запустить Claude с ветки функции вместо ветки по умолчанию. Вы можете добавить несколько репозиториев для работы с ними в одном сеансе.
  </Step>

  <Step title="Выберите режим разрешений">
    Раскрывающееся меню режима рядом с вводом показывает режим, в котором будет работать сеанс:

    * **Auto**: классификатор проверяет действия Claude вместо того, чтобы просить вас. Появляется, когда ваша организация разрешает режим auto и выбранная модель его поддерживает
    * **Accept edits**: Claude вносит изменения и отправляет ветку без остановки для одобрения
    * **Plan**: Claude предлагает подход и ждет вашего одобрения перед редактированием файлов

    Облачные сеансы не предлагают разрешения Manual или разрешения Bypass. Смотрите [полный список режимов разрешений](/docs/ru/permission-modes#available-modes) для того, что позволяет каждый из них.
  </Step>

  <Step title="Опишите задачу и отправьте">
    Введите описание того, что вы хотите, и нажмите Enter. Будьте конкретны:

    * Назовите файл или функцию: "Add a README with setup instructions" или "Fix the failing auth test in `tests/test_auth.py`" лучше, чем "fix tests"
    * Вставьте вывод ошибки, если у вас он есть
    * Опишите ожидаемое поведение, а не просто симптом

    Claude клонирует репозитории, запускает ваш скрипт настройки, если он настроен, и начинает работать. Каждая задача получает свой сеанс и свою ветку, поэтому вам не нужно ждать, пока одна закончится, прежде чем начать другую.
  </Step>
</Steps>

<h2 id="pre-fill-sessions">
  Предварительное заполнение сеансов
</h2>

Вы можете предварительно заполнить подсказку, репозитории и окружение для нового сеанса, добавив параметры запроса к URL [claude.ai/code](https://claude.ai/code). Используйте это для создания интеграций, таких как кнопка в вашем трекере проблем, которая открывает Claude Code с описанием проблемы в качестве подсказки.

| Параметр       | Описание                                                                                                                                                                                                     |
| :------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`       | Текст подсказки для предварительного заполнения в поле ввода. Также принимается псевдоним `q`.                                                                                                               |
| `prompt_url`   | URL для получения текста подсказки, для подсказок, которые слишком длинные для встраивания в строку запроса. URL должен разрешать кросс-источниковые запросы. Игнорируется, когда также установлен `prompt`. |
| `repositories` | Разделенный запятыми список слагов `owner/repo` для предварительного выбора. Также принимается псевдоним `repo`.                                                                                             |
| `environment`  | Имя или ID [окружения](#connect-github) для предварительного выбора.                                                                                                                                         |

URL-кодируйте каждое значение. Пример ниже открывает форму с уже выбранной подсказкой и репозиторием:

```text theme={null}
https://claude.ai/code?prompt=Fix%20the%20login%20bug&repositories=acme/webapp
```

<h2 id="review-and-iterate">
  Просмотр и итерация
</h2>

Когда Claude закончит, просмотрите изменения, оставьте отзыв на конкретных строках и продолжайте, пока diff не будет выглядеть правильно.

<Steps>
  <Step title="Откройте представление diff">
    Индикатор diff показывает добавленные и удаленные строки во всем сеансе, например `+42 -18`. Выберите его, чтобы открыть представление diff с списком файлов слева и изменениями справа.

    Diff по умолчанию сравнивает изменения сеанса с его базовой веткой. Чтобы сравнить с другой веткой, выберите **Compare against** и выберите одну.
  </Step>

  <Step title="Оставляйте встроенные комментарии">
    Выберите любую строку в diff, введите свой отзыв и нажмите Enter. Комментарии накапливаются до тех пор, пока вы не отправите следующее сообщение, затем они объединяются с ним. Claude видит "at `src/auth.ts:47`, don't catch the error here" вместе с вашей основной инструкцией, поэтому вам не нужно описывать, где проблема.
  </Step>

  <Step title="Создайте pull request">
    Когда diff выглядит правильно, выберите **Create PR** в верхней части представления diff. Вы можете открыть его как полный PR, черновик или перейти на страницу составления GitHub с сгенерированным названием и описанием.
  </Step>

  <Step title="Продолжайте итерацию после PR">
    Сеанс остается активным после создания PR. Вставьте вывод ошибки CI или комментарии рецензента в чат и попросите Claude их решить. Чтобы Claude автоматически отслеживал PR, смотрите [Auto-fix pull requests](/docs/ru/claude-code-on-the-web#auto-fix-pull-requests).
  </Step>
</Steps>

<h2 id="troubleshoot-setup">
  Устранение неполадок при настройке
</h2>

<h3 id="no-repositories-appear-after-connecting-github">
  После подключения GitHub не появляются репозитории
</h3>

Если вы подключили GitHub в браузере, сеансы могут клонировать любой публичный репозиторий, но приватный репозиторий появляется только когда приложение Claude GitHub установлено на учетной записи или организации, которая его владеет, и доступ к репозиториям в установке включает его. [Установите приложение Claude GitHub](https://github.com/apps/claude/installations/new) там или попросите владельца организации установить или одобрить его.

Если вы подключились с помощью `/web-setup`, сеансы получают доступ к каждому репозиторию, который может видеть ваш токен `gh`. Запустите `gh repo view OWNER/REPO` в вашей оболочке, чтобы проверить, что ваш вход GitHub CLI может видеть репозиторий, и запустите `/web-setup` снова, если вы переключили учетные записи `gh` с момента подключения.

<h3 id="the-page-only-shows-a-github-login-button">
  На странице отображается только кнопка входа GitHub
</h3>

Облачные сеансы требуют подключенной учетной записи GitHub. Подключитесь через поток браузера выше или запустите `/web-setup` из терминала, если вы используете GitHub CLI. Если вы предпочитаете вообще не подключать GitHub, смотрите [Remote Control](/docs/ru/remote-control) для запуска Claude Code на вашей машине и мониторинга его из браузера или телефона.

<h3 id="not-available-for-the-selected-organization">
  "Not available for the selected organization"
</h3>

Организациям Enterprise может потребоваться владелец для включения облачных сеансов. Свяжитесь с вашей командой учетных записей Anthropic.

<h3 id="/web-setup-says-not-signed-in-to-claude">
  `/web-setup` говорит "Not signed in to Claude"
</h3>

Если `/web-setup` отвечает "Not signed in to Claude. Run /login first.", CLI не имеет действительного входа в claude.ai. Это также может произойти, когда предыдущий вход истек. Запустите `/login`, войдите со своей учетной записью claude.ai, затем снова запустите `/web-setup`.

<h3 id="/web-setup-warns-that-your-token-doesn’t-have-the-workflow-scope">
  `/web-setup` предупреждает, что ваш токен не имеет области `workflow`
</h3>

Если `/web-setup` говорит, что ваш токен GitHub CLI не имеет области `workflow`, вы можете продолжить, но GitHub может отклонить некоторые отправки, сделанные с этим токеном, такие как отправки, которые изменяют файлы рабочих процессов GitHub Actions. Чтобы добавить область, запустите `gh auth refresh -s workflow` в вашей оболочке, затем снова запустите `/web-setup`.

<h3 id="web-setup-shows-no-commands-match-or-unknown-command">
  `/web-setup` показывает "No commands match" или "Unknown command"
</h3>

`/web-setup` работает внутри Claude Code CLI, а не в вашей оболочке. Сначала запустите `claude`, затем введите `/web-setup` в подсказке.

Если вы ввели его внутри Claude Code и меню команд показывает `No commands match "/web-setup"`, или отправка возвращает `Unknown command: /web-setup`, команда скрыта, потому что требование не выполнено. Причина обычно в том, что вы аутентифицированы с помощью ключа API или поставщика третьей стороны вместо подписки claude.ai. Запустите `/login` для входа со своей учетной записью claude.ai.

На планах Team и Enterprise команда скрыта по умолчанию: [переключатель быстрой веб-настройки](/docs/ru/claude-code-on-the-web#github-authentication-options) отключен до тех пор, пока владелец его не включит. Пока он отключен, [подключите GitHub из браузера](#connect-github) вместо этого.

Команда также скрыта в двух других случаях:

* Администратор отключил облачные сеансы для вашей организации. В этом случае отправка `/web-setup` возвращает [`Cloud sessions are disabled by your organization's policy`](/docs/ru/errors#cloud-sessions-are-disabled-by-your-organizations-policy). До версии 2.1.268 этот случай также возвращал `Unknown command: /web-setup`.
* Ваша организация Enterprise имеет [Zero Data Retention](/docs/ru/zero-data-retention) включенный, что делает облачные сеансы недоступными.

<h3 id="could-not-create-a-cloud-environment-or-no-cloud-environment-available-when-using-cloud">
  "Could not create a cloud environment" или "No cloud environment available" при использовании `--cloud`
</h3>

Функции облачного сеанса автоматически создают облачное окружение по умолчанию, если у вас его нет. Если вы видите "Could not create a cloud environment", автоматическое создание не удалось. Если вы видите "No cloud environment available", ваш CLI предшествует автоматическому созданию. В любом случае запустите `/web-setup` в Claude Code CLI, или добавьте окружение из [селектора окружения](/docs/ru/cloud-environments#configure-your-environment) на [claude.ai/code](https://claude.ai/code).

<h3 id="setup-script-failed">
  Скрипт настройки не удался
</h3>

Скрипт настройки завершился с ненулевым статусом, что блокирует запуск сеанса. Распространенные причины:

* Установка пакета не удалась, потому что реестр не находится на вашем [уровне доступа в сеть](/docs/ru/cloud-environments#access-levels). `Trusted` охватывает большинство менеджеров пакетов; `None` блокирует их все.
* Скрипт ссылается на файл или путь, который не существует в свежем клоне.
* Команда, которая работает локально, требует другого вызова на Ubuntu.

Для отладки добавьте `set -x` в начало скрипта, чтобы увидеть, какая команда не удалась. Для некритических команд добавьте `|| true`, чтобы они не блокировали запуск сеанса.

<h3 id="new-sessions-hang-or-time-out-during-setup">
  Новые сеансы зависают или истекает время ожидания во время настройки
</h3>

Если новые сеансы зависают на шаге скрипта настройки или не удаются с общей ошибкой контейнера перед завершением скрипта, скрипт, вероятно, превышает примерно пятиминутный бюджет времени для построения [кэша окружения](/docs/ru/cloud-environments#environment-caching). Тяжелые шаги, такие как извлечение больших образов Docker, синхронизация полных деревьев зависимостей или загрузка весов модели, часто превышают лимит, особенно когда они выполняются один за другим.

Чтобы исправить это, обрежьте скрипт так, чтобы он надежно завершался менее чем за пять минут:

* Запускайте независимые установки параллельно с `&` и финальным `wait` вместо их последовательного выполнения.
* Переместите самые большие загрузки из скрипта настройки в [SessionStart hook](/docs/ru/cloud-environments#setup-scripts-vs-sessionstart-hooks), который запускает их в фоновом режиме, чтобы сеанс стал пригодным для использования, пока они завершаются.
* Удалите длинные повторные попытки сна из скрипта настройки, так как зависший цикл повторных попыток учитывается в бюджете.

<h3 id="session-keeps-running-after-closing-the-tab">
  Сеанс продолжает работать после закрытия вкладки
</h3>

Это сделано специально. Закрытие вкладки или навигация не останавливает сеанс. Он продолжает работать в фоновом режиме до тех пор, пока Claude не закончит текущую задачу, затем переходит в режим ожидания. На боковой панели вы можете [архивировать сеанс](/docs/ru/claude-code-on-the-web#archive-sessions), чтобы скрыть его из списка, или [удалить его](/docs/ru/claude-code-on-the-web#delete-sessions), чтобы удалить его навсегда.

  Следующие шаги

Теперь, когда вы можете отправлять и просматривать задачи, эти страницы охватывают, что дальше: запуск облачных сеансов из терминала, планирование повторяющейся работы и предоставление Claude постоянных инструкций.

* [Использование Claude Code в веб-версии](/docs/ru/claude-code-on-the-web): полный справочник, включая телепортацию сеансов в ваш терминал, совместное использование сеансов и автоматическое исправление pull-запросов

* [CLAUDE.md](/docs/ru/memory): дайте Claude постоянные инструкции и контекст, которые загружаются в начале каждого сеанса
* Установите мобильное приложение Claude для [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) или [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude) для мониторинга сеансов с телефона. Из Claude Code CLI `/mobile` показывает QR-код для [claude.ai/mobile](https://claude.ai/mobile), который открывает правильный магазин приложений для вашего телефона.
