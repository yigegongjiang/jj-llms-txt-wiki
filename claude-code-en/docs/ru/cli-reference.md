# Справочник CLI

> Полный справочник по интерфейсу командной строки Claude Code, включая команды и флаги.

Если вы неправильно введете подкоманду, Claude Code предложит ближайшее совпадение и выйдет без запуска сеанса. Например, `claude udpate` выводит `Did you mean claude update?`.

Начиная с версии v2.1.199, `claude --dangerously-skip-permissions daemon <subcommand>` запускает подкоманду `daemon`. В более ранних версиях `daemon <subcommand>` рассматривалась как приглашение для нового интерактивного сеанса, поэтому подкоманда никогда не запускалась, когда флаг шел первым, что является распространенной настройкой, когда `claude` имеет псевдоним, включающий флаг. Только ведущий `--dangerously-skip-permissions` или `--allow-dangerously-skip-permissions` маршрутизирует к `daemon` таким образом; любой другой ведущий флаг по-прежнему запускает интерактивный сеанс.

<h2 id="cli-flags">

</h2>

Настройте поведение Claude Code с помощью этих флагов командной строки. `claude --help` не выводит каждый флаг, поэтому отсутствие флага в `--help` не означает, что он недоступен.

Проверяет, что каждый путь существует как каталог. Вы не можете добавить большинство [сетевых путей](/docs/ru/errors#working-directory-is-a-network-path), таких как `\\server\share`. <h3 id="system-prompt-flags">
  Флаги системного приглашения
</h3>

Claude Code предоставляет пять флагов для настройки системного приглашения. Четыре устанавливают его текст, и с `--system-prompt-snapshot` вы контролируете, сохраняет ли беседа текст, с которым она началась. Все пять работают как в интерактивном, так и в неинтерактивном режимах.

| Флаг                          | Поведение                                                                                                                                                                              | Пример                                                                     |
| :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| `--system-prompt`             | Заменяет весь запрос по умолчанию                                                                                                                                                      | `claude --system-prompt "You are a Python expert"`                         |
| `--system-prompt-file`        | Заменяет содержимым файла                                                                                                                                                              | `claude --system-prompt-file ./prompts/review.txt`                         |
| `--append-system-prompt`      | Добавляет к запросу по умолчанию                                                                                                                                                       | `claude --append-system-prompt "Always use TypeScript"`                    |
| `--append-system-prompt-file` | Добавляет содержимое файла к запросу по умолчанию                                                                                                                                      | `claude --append-system-prompt-file ./style-rules.txt`                     |
| `--system-prompt-snapshot`    | С `off`, перестраивает запрос при каждом запросе. С `on`, по умолчанию, повторно использует записанный запрос, где [применяется запись](#system-prompt-flags-in-resumed-conversations) | `claude --append-system-prompt "Draft rules" --system-prompt-snapshot off` |

`--system-prompt` и `--system-prompt-file` являются взаимоисключающими. Флаги добавления можно комбинировать с любым флагом замены.

Когда текст замены объединяет инструкции, которые одинаковы при каждом запуске, с контекстом, который изменяется при каждом запуске, добавьте строку, содержащую только `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` между инструкциями и контекстом. Claude Code разделяет приглашение в первой такой строке и удаляет эту строку, поэтому часть выше неё остаётся кэшированной, а часть ниже изменяется. Требует Claude Code v2.1.275 или позже. [Кэшировать статическую часть пользовательского приглашения](/docs/ru/agent-sdk/modifying-system-prompts#cache-the-static-part-of-a-custom-prompt) перечисляет конфигурации, где применяется разделение.

Выбирайте в зависимости от того, подходит ли стандартная идентичность Claude Code для вашей задачи. Используйте флаг добавления, когда Claude должен оставаться помощником по кодированию, который также следует вашим дополнительным правилам: инструкции для каждого вызова, форматирование вывода или контекст домена для скрипта `-p`. Добавление сохраняет стандартное руководство по инструментам, инструкции безопасности и соглашения кодирования, поэтому вы предоставляете только то, что отличается. Используйте флаг замены, когда поверхность, идентичность или модель разрешения отличаются от Claude Code, например некодирующий агент в конвейере, который не смотрит ни один человек. Замена удаляет весь стандартный запрос, включая руководство по инструментам и инструкции безопасности, поэтому вы берёте на себя ответственность за всё, что вашей задаче всё ещё нужно.

Для постоянных персон, которые вы можете переключать и делиться между проектом, используйте [стили вывода](/docs/ru/output-styles). Для соглашений проекта, которые Claude должен всегда соблюдать, используйте [CLAUDE.md](/docs/ru/memory). [Руководство Agent SDK по системным приглашениям](/docs/ru/agent-sdk/modifying-system-prompts#decide-on-a-starting-point) охватывает то же решение более подробно.

<h4 id="system-prompt-flags-in-resumed-conversations">
  Флаги системного приглашения в возобновлённых беседах
</h4>

По умолчанию Claude Code строит системное приглашение один раз, при первом запросе беседы, с текстом из любых флагов системного приглашения, применённых, и записывает его в сеанс. До компактирования беседы каждый более поздний запрос использует это записанное приглашение, включая после возврата к беседе с `--resume` или `--continue`. Если вы передаёте другой текст флага системного приглашения, или ничего, при этом более позднем запуске, он вступает в силу после компактирования беседы или когда вы начинаете новую беседу.

Вне [облачных сеансов](/docs/ru/cloud-environments), если вы запускаете Claude Code в [bare mode](/docs/ru/headless#start-faster-with-bare-mode), передав `--bare` или установив `CLAUDE_CODE_SIMPLE=1`, запись остаётся отключённой, если вы не передаёте `--system-prompt-snapshot on`. До v2.1.268 сеансы, которые не [получают флаги функций](/docs/ru/env-vars#features-that-need-feature-flag-fetching), включая сеансы на Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry, перестраивали запрос при каждом запросе и `--system-prompt-snapshot` не имел эффекта.

Чтобы перестроить запрос при каждом запросе вместо этого, например, пока вы итерируете его формулировку через запуски `--continue`, передайте `--system-prompt-snapshot off`. До v2.1.265 передача любого из флагов системного приглашения также отключала запись, если вы не передавали `--system-prompt-snapshot on`.
