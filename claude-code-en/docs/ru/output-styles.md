# Output styles

> Измените роль, тон и формат ответов Claude Code с помощью встроенного стиля вывода, такого как Concise или Explanatory, или напишите собственный стиль.

Output style — это набор инструкций, которые устанавливают роль Claude, тон и формат ответов для каждого ответа в сеансе. Claude Code включает четыре встроенных стиля помимо стиля по умолчанию, и вы можете написать свой собственный.

Используйте output style, чтобы изменить способ ответа Claude и работы с вами на протяжении всего сеанса, чтобы вам не нужно было повторять запрос в каждом приглашении. Например, встроенный стиль может сделать ответы короче, добавить объяснение каждого изменения или заставить Claude начать работу без задания рутинных вопросов. Пользовательский стиль также может превратить Claude в что-то другое, чем инженер-программист, например в помощника по написанию текстов или аналитика данных.

* Чтобы использовать встроенный стиль, выберите один из [встроенных output styles](#built-in-output-styles) и [переключитесь на него](#change-your-output-style).
* Чтобы написать свои собственные инструкции, [создайте пользовательский output style](#create-a-custom-output-style).

<Note>
  Output style дает Claude инструкции для выполнения. Это не гарантирует, что что-то всегда происходит или никогда не происходит. Некоторые потребности соответствуют другой функции:

  * Для того, что Claude должен знать о вашем проекте, используйте [CLAUDE.md](/docs/ru/memory).
  * Для чего-то, что должно происходить каждый раз, например форматирование после каждого редактирования или блокирование команды, используйте [hook](/docs/ru/hooks-guide).
  * Для skills, subagents и других опций см. [Choose between an output style and other features](#choose-between-an-output-style-and-other-features).
</Note>

<h2 id="built-in-output-styles">
  Встроенные output styles
</h2>

Claude Code начинает работу в стиле [**Default**](#default), его стандартном наборе инструкций для выполнения задач разработки программного обеспечения. Каждый из четырёх других встроенных стилей сохраняет эти инструкции и добавляет свои собственные.

В этой таблице показано, что изменяет каждый стиль в сеансе и когда его использовать:

| Стиль                       | Что изменяется                                                                                                    | Используйте, когда                                                                                                               |
| :-------------------------- | :---------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------- |
| [Proactive](#proactive)     | Claude начинает работу сразу же и делает разумные предположения вместо того, чтобы спрашивать о рутинных решениях | Вы хотите, чтобы Claude продолжал работать через рутинные решения, и вы исправите курс, если предположение окажется неправильным |
| [Concise](#concise)         | Ответы начинаются с результата и опускают преамбулу, повествование и резюме                                       | Ответы по умолчанию длиннее, чем вам нужно                                                                                       |
| [Explanatory](#explanatory) | Claude добавляет короткие блоки `Insight`, которые объясняют выбор, стоящий за написанным им кодом                | Вы знакомитесь с кодовой базой или хотите получить обоснование вместе с изменением                                               |
| [Learning](#learning)       | Claude объясняет свой выбор и оставляет небольшие фрагменты кода для самостоятельного написания                   | Вы хотите получить практику кодирования, пока задача всё ещё выполняется                                                         |

<h3 id="default">
  Default
</h3>

Default означает, что не выбран никакой output style. Claude Code не добавляет инструкции стиля, и Claude работает из стандартного системного приглашения Claude Code, которое написано для задач разработки программного обеспечения.

`default` появляется в списке `/output-style` вместе с другими стилями, поэтому вы [выбираете его так же](#change-your-output-style).

<h3 id="proactive">
  Proactive
</h3>

В стиле Proactive Claude начинает реализацию сразу же после отправки задачи. Он делает разумные предположения о рутинных решениях вместо того, чтобы останавливаться и спрашивать, и не переходит в режим плана, если вы не попросите план. Вы можете перенаправить его в любой момент.

Инструкции стиля также говорят Claude проверить с вами в разговоре перед действием, которое удаляет данные или изменяет общую или производственную систему. Эта проверка — это инструкция, которую Claude следует, и она отделена от запросов разрешения.

Переключение на стиль Proactive не изменяет ваш [режим разрешений](/docs/ru/permission-modes). Ваш режим разрешений по-прежнему решает, какие вызовы инструментов выполняются без запроса, поэтому запросы разрешения появляются так же, как они появлялись до переключения.

<h3 id="concise">
  Concise
</h3>

В стиле Concise первое предложение ответа указывает, что произошло или какой ответ. Claude опускает вводную часть, пошаговое повествование и закрывающее резюме, и отвечает на простой вопрос в одно-три предложения. Он выполняет инженерную работу так же тщательно, как в стиле Default. Требует Claude Code v2.1.237 или позже.

Claude по-прежнему пишет в полном объёме в этих случаях:

* **Всё, что вы просите**: когда вы просите объяснение или больше деталей, Claude отвечает в полном объёме.
* **Всё, что вам нужно для безопасного действия**: отчёты об ошибках, вывод неудачных тестов, предупреждения безопасности и подтверждения деструктивных действий сохраняют своё полное содержание.

<h3 id="explanatory">
  Explanatory
</h3>

В стиле Explanatory Claude выполняет задачу так же, как в стиле Default, и добавляет краткие объяснения того, почему он сделал выбор, который он сделал. Каждое объяснение появляется в разговоре, до или после кода, к которому оно относится, в блоке с меткой `Insight`. Объяснения не записываются в ваши файлы как комментарии.

Блок `Insight` содержит две или три точки о вашей кодовой базе или коде, который написал Claude, например, этот после добавления конечной точки API:

```text theme={null}
★ Insight ─────────────────────────────────────
- Каждый маршрут в этом репозитории проходит через обёртку withAuth, поэтому новая конечная точка получает проверки сеанса без собственного промежуточного ПО.
- Ограничения скорости устанавливаются для каждого маршрута в limits.ts, поэтому это изменение добавляет запись там, а не глобальное значение по умолчанию.
─────────────────────────────────────────────────
```

<h3 id="learning">
  Learning
</h3>

В стиле Learning Claude добавляет те же блоки `Insight`, что и [стиль Explanatory](#explanatory), и также просит вас написать часть кода. Claude сам обрабатывает рутинную реализацию. Когда он достигает фрагмента с реальным решением проектирования, такого как обработка ошибок, структура данных или бизнес-логика с более чем одним допустимым подходом, он оставляет несколько строк для вас.

Claude отмечает место комментарием `TODO(human)` в файле, а затем отправляет запрос, который говорит, что уже построено, что написать и что учесть:

```text theme={null}
● Learn by Doing

Context: The upload form is in place and calls validateFile() before accepting a file. Size and type checks work for images, but the switch statement has no handling for documents yet.

Your Task: In upload.js, implement the case "document" branch inside validateFile(). Look for TODO(human).

Guidance: Decide on a size limit for documents and whether the file extension has to match the MIME type. Return {valid: boolean, error?: string}.
```

Claude затем останавливается и ждёт. Напишите свой код в комментарии `TODO(human)` и скажите Claude, когда вы закончите. Claude отвечает с одним `Insight` о вашем коде и продолжает задачу.

<h2 id="change-your-output-style">
  Измените ваш output style
</h2>

Выберите стиль с помощью команды, меню или файла настроек. Команда и оба меню сохраняют ваш выбор в `.claude/settings.local.json` на [локальном уровне проекта](/docs/ru/settings).

* **`/output-style` command**: запустите `/output-style <style>` для переключения, например `/output-style concise`. Без аргумента команда выводит список доступных стилей и отмечает текущий.

  Команда также работает в [неинтерактивном режиме](/docs/ru/headless) и сеансах Agent SDK, а также из мобильного приложения или веб-версии через [Remote Control](/docs/ru/remote-control#limitations), где вы можете просмотреть и выбрать только [встроенные стили](#built-in-output-styles). Требуется Claude Code версии 2.1.269 или позже.
* **Terminal menu**: запустите `/config` и выберите **Output style**, чтобы выбрать стиль из меню.
* **VS Code extension**: откройте [меню команд](/docs/ru/vs-code#use-the-prompt-box) с помощью `/` и выберите **Output styles**, чтобы выбрать стиль, включая ваши пользовательские стили. Требуется Claude Code версии 2.1.257 или позже.
* **Desktop app**: установите поле `outputStyle` в файле настроек, например `.claude/settings.local.json`, файл, в который пишет меню терминала. Когда вы запустите `/config` там, Claude Code [открывает **Settings > Claude Code**](/docs/ru/desktop#what%E2%80%99s-not-available-in-desktop) вместо меню.

Чтобы установить стиль без меню, отредактируйте поле `outputStyle` непосредственно в файле настроек:

```json theme={null}
{
  "outputStyle": "Explanatory"
}
```

Значение чувствительно к регистру, поэтому пишите встроенные имена как `Proactive`, `Concise`, `Explanatory` и `Learning`. Значение, которое не совпадает точно с именем стиля, например `explanatory`, дает вам стиль Default. Команда `/output-style` игнорирует регистр.

Чтобы сделать стиль своим стилем по умолчанию во всех проектах, установите `outputStyle` в `~/.claude/settings.json`. Собственные файлы настроек проекта [имеют приоритет](/docs/ru/settings#settings-precedence) над этим значением.

Когда вы переключаете стили в середине сеанса, Claude использует новый стиль, начиная со следующего сообщения. Информацию о том, что стоит первое сообщение в prompt caching, см. в разделе [Изменение output style](/docs/ru/prompt-caching#changing-output-style). До версии 2.1.251 новый стиль применялся только после того, как вы запустили `/clear` или начали новый сеанс.

<h2 id="create-a-custom-output-style">
  Создайте пользовательский output style
</h2>

Пользовательский output style — это файл Markdown: frontmatter для метаданных, затем инструкции для Claude.

В расширении VS Code вы также можете создать файл из меню [**Output styles**](/docs/ru/vs-code#use-the-prompt-box) вместо того, чтобы писать его вручную. Это требует Claude Code версии 2.1.261 или позже.

<Steps>
  <Step title="Создайте файл Markdown">
    Сохраните его на одном из трех уровней. Имя файла становится именем стиля, если вы не установите `name` в frontmatter.

    * Пользователь: `~/.claude/output-styles`
    * Проект: `.claude/output-styles`
    * Управляемая политика: `.claude/output-styles` внутри [управляемого каталога настроек](/docs/ru/managed-settings#delivery-mechanisms)

    Output styles проекта загружаются из каждого `.claude/output-styles/` между рабочей директорией и корнем репозитория. Когда несколько из этих вложенных директорий определяют стиль с одинаковым именем, Claude Code использует тот, который находится ближе всего к рабочей директории.
  </Step>

  <Step title="Добавьте frontmatter и инструкции">
    Решите, сохранять ли встроенные инструкции Claude Code по разработке программного обеспечения. Установите `keep-coding-instructions: true`, если вы изменяете способ общения Claude, но все еще хотите, чтобы он кодировал так же. Исключите это, если Claude не будет заниматься разработкой программного обеспечения.

    Этот пример начинает каждое объяснение с диаграммы, сохраняя при этом поведение Claude при кодировании:

    ```markdown theme={null}
    ---
    name: Diagrams first
    description: Lead every explanation with a diagram
    keep-coding-instructions: true
    ---

    When explaining code, architecture, or data flow, start with a Mermaid diagram showing the structure, then explain in prose.

    ## Diagram conventions

    Use `flowchart TD` for control flow and `sequenceDiagram` for request paths. Keep diagrams under 15 nodes.
    ```
  </Step>

  <Step title="Переключитесь на ваш стиль">
    Запустите `/output-style <style>` в терминале или запустите `/config` и выберите ваш стиль в разделе **Output style**. Claude использует новый стиль, начиная со следующего сообщения. В терминале Claude Code читает файлы стилей при запуске, поэтому если вы создадите или отредактируете один во время работающего сеанса, перезагрузите Claude Code, чтобы применить изменение.
  </Step>
</Steps>

[Plugins](/docs/ru/plugins/manifest-reference) также могут поставляться с output styles в каталоге `output-styles/`.

<h3 id="frontmatter">
  Справочник Frontmatter
</h3>

Настройте output style с помощью YAML [frontmatter](/docs/ru/glossary#frontmatter) между маркерами `---` в начале файла. Все поля являются необязательными, и имена полей используют строчные слова, разделенные дефисами. Неправильно написанное поле игнорируется без ошибки. Если YAML не анализируется, стиль все равно загружается под своим именем файла без установленных полей; запустите `claude --debug`, чтобы увидеть ошибку анализа.

| Поле                       | Обязательно | Описание                                                                                                                                                                                                                                                                                                                                                 |
| :------------------------- | :---------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`                     | Нет         | Имя output style, отображаемое в средстве выбора `/config`. По умолчанию: имя файла                                                                                                                                                                                                                                                                      |
| `description`              | Нет         | Описание output style, отображаемое в средстве выбора `/config`                                                                                                                                                                                                                                                                                          |
| `keep-coding-instructions` | Нет         | Установите значение `true`, чтобы сохранить встроенные инструкции Claude Code по разработке программного обеспечения вместе с вашим стилем. По умолчанию: `false`                                                                                                                                                                                        |
| `force-for-plugin`         | Нет         | Только для output styles плагинов. Установите значение `true`, чтобы применить этот стиль автоматически всякий раз, когда плагин включен, без необходимости выбора пользователем. Переопределяет параметр `outputStyle` пользователя. Если несколько включенных плагинов установят это, Claude Code использует первый загруженный. По умолчанию: `false` |

<h2 id="choose-between-an-output-style-and-other-features">
  Выбор между output style и другими функциями
</h2>

Output style применяется к каждому ответу в сеансе. Это инструкция, которую следует Claude, поэтому ничто её не гарантирует. Когда то, что вам нужно, уже́ чем каждый ответ, или должно произойти без сбоев, другая функция подходит лучше.

Эта таблица соответствует тому, что вам нужно, функции, которая это делает:

| Вам нужно                                                                                                                               | Используйте                                                       | Почему это подходит                                                                                                       |
| :-------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| Каждый ответ в определённом стиле, длине или формате, или Claude в другой роли                                                          | An output style                                                   | Это применяется ко всему сеансу, и вы переключаете стили одной командой                                                   |
| Claude должен знать соглашения, команды и структуру вашего проекта                                                                      | [CLAUDE.md](/docs/ru/memory)                                           | Это содержит то, что Claude должен знать о кодовой базе, и остаётся загруженным независимо от выбранного стиля            |
| Инструкции для одного вида задачи, такой как контрольный список выпуска или процедура проверки                                          | A [skill](/docs/ru/skills)                                             | Claude загружает её только при вызове или совпадении задачи, поэтому она не влияет на несвязанные ответы                  |
| Что-то, что должно происходить каждый раз без исключения, например форматирование после каждого редактирования или блокирование команды | A [hook](/docs/ru/hooks-guide)                                         | Claude Code запускает hook сам при событии жизненного цикла, поэтому это не зависит от того, следует ли Claude инструкции |
| Помощник со своими инструкциями, моделью и инструментами для сосредоточенной задачи                                                     | A [subagent](/docs/ru/sub-agents)                                      | Он работает в отдельном контексте со своим собственным системным prompt и возвращает сводку в ваш разговор                |
| Дополнение к инструкциям Claude, которое вы передаёте при запуске Claude Code                                                           | [`--append-system-prompt`](/docs/ru/cli-reference#system-prompt-flags) | Это добавляется к системному prompt без удаления чего-либо                                                                |

Эти функции комбинируются. Например, вы можете использовать CLAUDE.md для того, что Claude должен знать, output style для того, как он отвечает, и hook для всего, что должно быть гарантировано. [Расширьте Claude Code](/docs/ru/features-overview) сравнивает остальные функции расширения.

<h2 id="how-output-styles-work">
  Как работают стили вывода
</h2>

Стиль вывода изменяет инструкции, которые Claude Code отправляет Claude.

* Claude Code отправляет инструкции активного стиля с каждым запросом.
* Пользовательские стили вывода исключают встроенные инструкции Claude Code по разработке программного обеспечения, такие как определение области изменений, написание комментариев и проверка работы, если только `keep-coding-instructions` не установлен на `true`.

Стили вывода применяются к основному диалогу и к [форку](/docs/ru/sub-agents#fork-the-current-conversation), который наследует полный диалог и системный prompt родителя. Другие [подагенты запускают свой собственный системный prompt](/docs/ru/sub-agents#what-loads-at-startup), поэтому стили не изменяют способ их ответов.

Использование токенов зависит от стиля. Инструкции стиля добавляют входные токены, хотя кэширование prompt снижает эту стоимость после первого запроса в сеансе.

Встроенные стили Explanatory и Learning по замыслу производят более длинные ответы, чем Default, что увеличивает выходные токены. Стиль Concise делает противоположное, инструктируя Claude по умолчанию держать ответы короткими. Для пользовательских стилей использование выходных токенов зависит от того, что ваши инструкции говорят Claude производить.
