# Интерактивный режим

> Полный справочник по сочетаниям клавиш, режимам ввода и интерактивным функциям в сеансах Claude Code.

<h2 id="keyboard-shortcuts">
  Сочетания клавиш
</h2>

<Note>
  Сочетания клавиш могут различаться в зависимости от платформы и терминала. В [полноэкранном режиме](/docs/ru/fullscreen) нажмите `?` в средстве просмотра стенограммы, чтобы увидеть доступные там сочетания клавиш.

  **Пользователи macOS**: сочетания клавиш с клавишей Option/Alt (`Alt+B`, `Alt+F`, `Alt+D`, `Alt+Y`, `Alt+P`) требуют настройки Option как Meta в вашем терминале. См. [Включение сочетаний клавиш Option на macOS](/docs/ru/terminal-config#enable-option-key-shortcuts-on-macos) для параметра в каждом терминале.
</Note>

<h3 id="make-ctrl-w-delete-back-to-whitespace">
  Границы слов в сочетаниях редактирования
</h3>

Сочетания слов `Alt+B`, `Alt+F`, `Alt+D`, `Option+Delete` и `Ctrl+Backspace` рассматривают слово как последовательность букв и цифр, поэтому пунктуация, такая как `_`, `.` и `/`, разделяет слова. С `src/utils/foo.ts` в подсказке повторные нажатия `Alt+B` останавливаются в начале `ts`, `foo`, `utils` и `src`.

`Ctrl+W` отличается: он игнорирует пунктуацию и удаляет назад до предыдущего пробела, поэтому одно нажатие удаляет все `src/utils/foo.ts`.

В тексте, написанном без пробелов, таком как китайский или японский, сочетания слов по-прежнему перемещают или удаляют одно слово за раз.

Эти соглашения readline применяются в Claude Code v2.1.261 и более поздних версиях. Параметр [`keybindingFlavor`](/docs/ru/settings-reference#keybindingflavor), который включал их в более ранних версиях, устарел и не имеет эффекта.

Вы не можете переназначить эти сочетания в [файле конфигурации сочетаний клавиш](/docs/ru/keybindings), в котором нет действий для них.

<h3 id="transcript-viewer">

Когда средство просмотра стенограммы открыто (переключается с помощью `Ctrl+O`), доступны эти сочетания клавиш. Запустите `/tui` без аргумента, чтобы проверить, какой рендерер активен. `Ctrl+E` можно переназначить через [`transcript:toggleShowAll`](/docs/ru/keybindings).

| `q`, `Ctrl+C`, `Esc` | Выход из представления стенограммы. Все три можно переназначить через [`transcript:exit`](/docs/ru/keybindings)                                                                                                                                        |

<h2 id="commands">
  Команды
</h2>

Введите `/` в Claude Code, чтобы увидеть доступные вам команды, или введите `/` с последующими буквами для фильтрации. Меню `/` содержит встроенные команды, включённые и созданные пользователем [skills](/docs/ru/skills), а также команды, предоставленные [plugins](/docs/ru/plugins/overview) и [MCP servers](/docs/ru/mcp#use-mcp-prompts-as-commands). Не все встроенные команды видны каждому пользователю, так как некоторые зависят от вашей платформы или плана, и [несколько доступных команд скрыты из меню по замыслу](/docs/ru/commands#how-the-command-menu-matches-what-you-type) и запускаются при вводе их полного имени.

В [полноэкранном режиме отображения](/docs/ru/fullscreen#use-the-mouse) команда `/` и списки предложений файлов `@` также реагируют на мышь: наведение выделяет строку, а клик принимает её.

Полный список команд, включённых в Claude Code, см. в [справочнике команд](/docs/ru/commands).

<h3 id="complete-a-command-mid-prompt">
  Завершение команды в середине подсказки
</h3>

Завершение команды также работает в середине подсказки: введите `/` после пробела, затем первые буквы имени, как в `run the tests, then /com`. Совпадают только команды, имена которых начинаются с этих букв, поэтому путь файла, такой как `/tmp/notes.md`, не открывает список. Claude Code запускает команду только когда команда [начинает ваше сообщение](/docs/ru/commands).

* **В [полноэкранном режиме отображения](/docs/ru/fullscreen)**: совпадения открываются в виде списка во время ввода, без выделенной строки, поэтому `Enter` по-прежнему отправляет вашу подсказку в том виде, в котором она введена. Нажмите `Tab` для вставки верхнего совпадения или выберите строку стрелками и `Enter`.
* **Вне полноэкранного режима**: остаток верхнего совпадения появляется как призрачный текст в вашем курсоре с подсчётом, например `+2`, когда совпадают несколько команд. Нажмите `Tab` для вставки единственного совпадения или для открытия списка, когда совпадают несколько, затем выберите строку стрелками и `Enter`.

В обоих режимах нажмите `Tab` на голом `/` в середине подсказки, чтобы вывести список всех команд.

Skill плагина совпадает и по его простому имени, поэтому `/deploy` находит skill с именем `myplugin:deploy-app`. Когда вы вставляете совпадение, Claude Code записывает полный `/myplugin:deploy-app`.

Claude Code сохраняет ваш режим vim и позицию курсора при переключении [средства просмотра стенограммы](#transcript-viewer) с помощью `Ctrl+O` или при открытии и закрытии панели, такой как `/config`. <h3 id="remap-insert-mode-key-sequences">
  Переназначение последовательностей клавиш в режиме INSERT
</h3>

Параметр [`vimInsertModeRemaps`](/docs/ru/settings-reference#viminsertmoderemaps) отображает двухклавишную последовательность режима INSERT на Escape, поэтому отображение, такое как `jj`, возвращает вас в режим NORMAL. Требует Claude Code v2.1.208 или более позднюю версию.

Следующий пример `~/.claude/settings.json` включает режим vim и отображает `jj` на Escape:

```json theme={null}
{
  "editorMode": "vim",
  "vimInsertModeRemaps": { "jj": "<Esc>" }
}
```

Каждый ключ состоит ровно из двух печатаемых символов, введённых последовательно, и `"<Esc>"` — единственная поддерживаемая цель. Записи с другой длиной или целью игнорируются.

Ввод первого символа последовательности вставляет его обычным образом. Нажатие второго символа в течение одной секунды удаляет этот ожидающий символ и переключается в режим NORMAL, оставляя оба символа вне вашего ввода. После окна в одну секунду или если следует другая клавиша, оба символа остаются как буквальный текст, поэтому вы всё ещё можете ввести слово, содержащее последовательность, сделав паузу между двумя клавишами.

Claude Code читает этот параметр из вашего файла пользовательских параметров, флага `--settings` и [управляемых параметров](/docs/ru/managed-settings) только. Записи в `.claude/settings.json` или `.claude/settings.local.json` проекта игнорируются, поэтому проверенный репозиторий не может переназначить ваши нажатия клавиш.

<h2 id="command-history">
  История команд
</h2>

Claude Code сохраняет историю введённых вами подсказок, и вызов с помощью стрелки вверх позволяет получить подсказки из предыдущих сеансов одного проекта:

* История ввода хранится для каждого рабочего каталога
* Выполнение `/clear` начинает новый сеанс: при вызове истории сначала отображаются подсказки нового сеанса, а затем подсказки из более ранних сеансов. Разговор из предыдущего сеанса сохраняется и может быть возобновлен.
* Если вы отправите одну и ту же подсказку дважды подряд, будет записана одна запись в истории, поэтому нажатие стрелки вверх переходит к предыдущей отличающейся подсказке
* Когда вы вызываете подсказку, которая включала вставленный текст, Claude Code отправляет полное содержимое вставки при повторной отправке. Если содержимое было [очищено](/docs/ru/claude-directory#cleaned-up-automatically), Claude Code не отправляет буквальную строку `[Pasted text #N]`; см. [Вставка большого содержимого](/docs/ru/terminal-config#paste-large-content) для информации о том, что происходит с подсказкой
* Расширение истории с помощью `!` отключено по умолчанию

<h3 id="reverse-search-with-ctrl-r">
  Обратный поиск с помощью Ctrl+R
</h3>

Нажмите `Ctrl+R` для интерактивного поиска в истории команд. В [полноэкранном режиме](/docs/ru/fullscreen) `Ctrl+R` открывает диалоговое окно поиска: введите текст для фильтрации, нажимайте `Up` и `Down` для перемещения по совпадениям и нажимайте `Ctrl+S` для переключения области поиска между этим сеансом, этим проектом и всеми проектами. Нажмите `Enter` или `Tab` для размещения совпадения в поле ввода подсказки или `Esc` для отмены. Шаги ниже описывают встроенный поиск классического средства визуализации:

1. **Начать поиск**: нажмите `Ctrl+R` для активации обратного поиска по истории
2. **Введите запрос**: введите текст для поиска в предыдущих командах. Поисковый термин выделяется в совпадающих результатах
3. **Навигация по совпадениям**: нажмите `Ctrl+R` снова для перемещения по более старым совпадениям
4. **Область поиска**: встроенный поиск всегда ищет подсказки из всех проектов
5. **Принять совпадение**:
   * Нажмите `Tab` или `Esc` для принятия текущего совпадения и продолжения редактирования
   * Нажмите `Enter` для принятия и немедленного выполнения команды
6. **Отмена поиска**:
   * Нажмите `Ctrl+C` для отмены и восстановления исходного ввода
   * Нажмите `Backspace` при пустом поиске для отмены

Встроенный поиск сканирует полную историю подсказок, начиная с самых новых, с дубликатами, свёрнутыми до самого нового вхождения. Диалоговое окно полноэкранного режима ищет всю историю подсказок в выбранной области, начиная с самых новых, с дубликатами, свёрнутыми до самого нового вхождения: самые последние подсказки отображаются немедленно, а совпадения из более старых подсказок заполняются по мере загрузки остальной истории Claude Code. Совпадающие подсказки отображаются с выделенным поисковым термином, поэтому вы можете найти и повторно использовать предыдущие вводы.

Принятие совпадения или отмена поиска вступают в силу немедленно, даже если Claude Code всё ещё загружает историю.

<h2 id="background-bash-commands">
  Фоновые команды Bash
</h2>

Claude Code поддерживает запуск команд Bash в фоне, позволяя вам продолжать работу во время выполнения долгоживущих процессов.

<h3 id="how-backgrounding-works">
  Как работает фоновое выполнение
</h3>

Когда Claude Code запускает команду в фоне, она выполняется асинхронно и немедленно возвращает идентификатор фоновой задачи. Claude Code может отвечать на новые запросы, пока команда продолжает выполняться в фоне.

Для запуска команд в фоне вы можете:

* Попросить Claude Code запустить команду в фоне
* Нажать `Ctrl+B` для перемещения обычного вызова инструмента Bash в фон. Пользователи Tmux должны нажать `Ctrl+B` дважды из-за префиксного ключа tmux.

**Ключевые возможности:**

* Вывод записывается в файл, и Claude может получить его с помощью инструмента Read
* Фоновые задачи имеют уникальные идентификаторы для отслеживания и получения вывода
* Фоновые задачи автоматически очищаются при выходе из Claude Code. На macOS и Linux при остановке фоновой задачи из [`/tasks`](/docs/ru/commands) или при выходе Claude Code процессы, отделённые от оболочки задачи, такие как запущенные под `setsid` или `timeout`, также останавливаются
* Если вы переводите сеанс в фон вместо выхода, ваши фоновые задачи продолжают работать в фоновом сеансе. См. [перевод работающего сеанса в фон](/docs/ru/agent-view#from-inside-a-session)
* Фоновые задачи автоматически завершаются, если вывод превышает 5 ГБ, с примечанием в stderr, объясняющим причину
* На macOS и Linux Claude Code завершает работающие фоновые задачи, когда операционная система сигнализирует о критической нехватке памяти, при условии, что сеанс был неактивен не менее 30 минут и не выполняется ни один ход или подагент. Требуется Claude Code v2.1.193 или позже
  * [Журнал отладки](/docs/ru/debug-your-config) указывает, почему задачи были остановлены, или почему событие нехватки памяти оставило их работающими
  * Установите [`CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP`](/docs/ru/env-vars) в `1`, чтобы отключить остановки при нехватке памяти
* Фоновые команды, принадлежащие [подагенту](/docs/ru/sub-agents), не имеют ограничения по времени, за исключением того, что команда, принадлежащая подагенту, работающему на переднем плане, заканчивается, когда этот подагент дает свой окончательный ответ; см. [Фоновые команды](/docs/ru/tools-reference#background-commands) в справочнике инструментов. До v2.1.218 ни очистка при нехватке памяти, ни прежнее ограничение в 60 минут на команды подагента не распространялись на команды, перемещённые в фон с помощью `Ctrl+B`

Чтобы отключить всю функциональность фоновых задач, установите переменную окружения `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` в `1`. См. [Переменные окружения](/docs/ru/env-vars) для получения подробной информации.

**Часто используемые фоновые команды:**

* Инструменты сборки (webpack, vite, make)
* Менеджеры пакетов (npm, yarn, pnpm)
* Средства запуска тестов (jest, pytest)
* Серверы разработки
* Долгоживущие процессы (docker, terraform)

<h3 id="shell-mode-with-prefix">
  Режим оболочки с префиксом `!`
</h3>

Запускайте команды оболочки напрямую без участия Claude, добавив префикс `!` к вашему вводу:

```bash theme={null}
! npm test
! git status
! ls -la
```

Режим оболочки:

* Добавляет команду и её вывод в контекст беседы
* Показывает прогресс и вывод в реальном времени
* Поддерживает то же самое фоновое выполнение `Ctrl+B` для долгоживущих команд
* Не требует интерпретации или одобрения команды Claude
* Поддерживает автодополнение на основе истории: введите частичную команду и нажмите `Tab` для завершения из предыдущих команд `!` в текущем проекте
* Поддерживает автодополнение пути к файлу в реальном времени начиная с v2.1.193 на всех платформах: введите токен, содержащий косую черту, такой как `./src/` или `~/`, чтобы увидеть раскрывающийся список соответствующих файлов и каталогов, затем нажмите `Tab` для принятия. Используйте косые черты на Windows тоже; раскрывающийся список вызывается `/`, а не `\`
* Выход с помощью `Escape`, `Backspace` или `Ctrl+U` на пустой строке ввода
* Вставка текста, начинающегося с `!`, в пустую строку ввода автоматически входит в режим оболочки, соответствуя поведению введённого `!`

Если ваш сеанс не входит в список сеансов, указанных в разделе [режим строгой песочницы](/docs/ru/sandboxing#the-unsandboxed-retry-escape-hatch), команды, которые вы вводите в режиме оболочки, выполняются вне [песочницы](/docs/ru/sandboxing) даже если вы включили песочницу, потому что песочница применяется к командам, которые запускает Claude.

Claude автоматически отвечает на вывод команды после того, как он попадает в стенограмму, поэтому вы можете запустить `! npm test` и получить объяснение ошибок без второго запроса. Ответ стоит столько же, сколько отправка обычного запроса. Чтобы восстановить более раннее поведение, когда вывод добавляется в контекст без ответа, установите [`respondToBashCommands`](/docs/ru/settings-reference#respondtobashcommands) в `false` в `settings.json`. До v2.1.186 режим оболочки всегда добавлял вывод в контекст без ответа.

<h2 id="queue-messages-while-claude-works">
  Ставьте сообщения в очередь, пока Claude работает
</h2>

Введите сообщение и нажмите `Enter` пока Claude работает. Claude Code ставит сообщение в очередь вместо прерывания хода, и отображает записи в очереди над полем ввода до их отправки. Вы можете ставить в очередь `!` [команды оболочки](#shell-mode-with-prefix) и большинство [команд](/docs/ru/commands) таким же образом, за исключением команд, таких как `/status`, которые Claude Code выполняет сразу же при их отправке.

Отправленные и поставленные в очередь сообщения отображаются серым цветом до тех пор, пока Claude не начнет на них отвечать, поэтому вы можете видеть, какие сообщения Claude еще не начинал обрабатывать.

<h3 id="when-claude-code-sends-what-you-queued">
  Когда Claude Code отправляет то, что вы поставили в очередь
</h3>

Когда Claude Code отправит запись из очереди, зависит от того, что вы поставили в очередь.

* Сообщения: если вы поставите сообщение в очередь, пока Claude выполняет вызовы инструментов, Claude Code передаст его Claude сразу же после завершения этих вызовов в рамках одного хода. Когда ход заканчивается с оставшимися в очереди сообщениями, они отправляются без дополнительного нажатия клавиши в порядке, в котором вы их набрали
* Команды и команды оболочки: Claude Code удерживает их до конца хода, затем выполняет их по одной, сохраняя порядок, в котором вы их поставили в очередь

Чтобы отправить то, что вы поставили в очередь, не дожидаясь завершения хода, нажмите `Ctrl+Enter`. Ваши сообщения из очереди отправляются сразу же, с вашим черновиком в очереди позади них, если вы что-то набрали. Требуется Claude Code v2.1.275 или позже.

Если вы поставили в очередь команду `!` оболочки перед вашими сообщениями, клавиша прерывает ход. В противном случае, что происходит с ходом, зависит от того, что Claude делает при нажатии клавиши:

* Выполнение команд оболочки, подагентов или другой работы, которая может перейти в [фоновый режим](#background-bash-commands): эта работа переходит в фоновый режим и продолжает выполняться, а Claude читает ваши сообщения в том же ходе
* Только написание ответа или выполнение чего-то, что не может перейти в фоновый режим: Claude Code прерывает ход и отправляет ваши сообщения дальше. До версии v2.1.281 клавиша прерывала ход в обоих случаях

В [режиме оболочки](#shell-mode-with-prefix) клавиша только ставит вашу команду в очередь. В терминалах, которые не сообщают о расширенных клавишах, `Ctrl+Enter` поступает как обычный `Enter` и ставит черновик в очередь; `Ctrl+X Ctrl+S` работает в любом терминале. Обе клавиши являются привязками действия [`chat:sendNow`](/docs/ru/keybindings#chat-actions).

Нажмите `Esc` для прерывания хода без отправки вашего черновика. Claude Code сохраняет то, что вы поставили в очередь, и отправляет это сразу же.

Claude Code выполняет некоторые команды сразу же при их отправке вместо того, чтобы ставить их в очередь, в том числе `/model`, `/effort` и `/fast`. Каждая из трех команд изменяет параметр: модель, уровень усилий или режим быстрой работы. То, применяет ли Claude Code новый параметр к ходу, над которым Claude уже работает, или только с вашего следующего хода, отличается в зависимости от команды:

* [`/model`](/docs/ru/model-config#setting-your-model): после подтверждения [предупреждения о кэше](/docs/ru/prompt-caching#switching-models), если Claude Code его показывает, Claude Code применяет ваше изменение к следующему запросу, который он делает в этом ходе
* [`/effort`](/docs/ru/model-config#adjust-effort-level): после подтверждения [предупреждения о кэше](/docs/ru/prompt-caching#changing-effort-level), если Claude Code его показывает, Claude Code применяет ваше изменение к следующему запросу, который он делает в этом ходе
* [`/fast`](/docs/ru/fast-mode#toggle-fast-mode): Claude Code сохраняет параметр режима быстрой работы, который был активен при начале хода, поэтому ваше изменение скорости применяется с вашего следующего хода. Если ваша текущая модель не поддерживает режим быстрой работы, его включение также [переключает вашу модель](/docs/ru/prompt-caching#turning-on-fast-mode), и Claude Code использует новую модель с ее следующего запроса в этом ходе

<h3 id="take-back-what-you-queued">
  Отмените то, что вы поставили в очередь
</h3>

Нажмите `Up` с первой строки поля ввода, чтобы отменить сообщения и команды из очереди. Claude Code удаляет их из очереди и помещает в поле ввода, по одному на строку, перед любым текстом, который вы набрали. Отредактируйте текст и нажмите `Enter`, чтобы поставить его в очередь снова как одну запись, или очистите поле ввода, чтобы удалить его.

Claude Code отменяет команды оболочки из очереди только когда поле ввода пусто и у вас нет ничего другого в очереди, и оно переключает поле ввода в режим оболочки при этом. В противном случае оно оставляет их в очереди, перечисленными с префиксом `!`, и выполняет их после завершения хода.

<h2 id="prompt-suggestions">
  Предложения подсказок
</h2>

Когда вы впервые открываете сеанс, Claude Code показывает затемненный пример команды в поле ввода подсказки, чтобы помочь вам начать работу. Он выбирает это из истории git вашего проекта, поэтому пример отражает файлы, над которыми вы недавно работали.

После ответа Claude Code может предложить вашу следующую подсказку на основе истории вашего разговора, например следующий шаг из многоэтапного запроса или естественное продолжение вашего рабочего процесса.

* Нажмите `Tab` или `Right arrow`, чтобы поместить предложение в поле ввода подсказки, затем `Enter` для отправки
* Начните вводить текст, чтобы отклонить его

Claude Code генерирует каждое из этих предложений следующей подсказки с помощью фоновой заявки к той же модели, которую использует ваш сеанс. Заявка учитывается в пределах использования вашего плана или в ваших затратах на API. Поскольку она повторно использует кэш подсказок разговора, это в основном чтение из кэша плюс несколько выходных токенов, поэтому дополнительные затраты минимальны.

<h3 id="when-claude-code-skips-suggestions">
  Когда Claude Code пропускает предложения
</h3>

В интерактивном режиме Claude Code по умолчанию отключает предложения подсказок и скрывает переключатель **Prompt suggestions** в `/config` в [сеансе, который не получает флаги функций](/docs/ru/env-vars#features-that-need-feature-flag-fetching), например на стороннем поставщике или через шлюз приложений Claude, и в [первом сеансе после установки или обновления](/docs/ru/env-vars#first-session-after-an-install-or-upgrade), флаги которого еще не поступили.

Claude Code также пропускает отдельные предложения в нескольких ситуациях, включая:

* Кэш подсказок холодный, чтобы избежать ненужных затрат
* После первого хода разговора в некоторых сеансах
* Предыдущий ответ закончился ошибкой
* Пока вы находитесь в Plan Mode
* Ваш аккаунт близок к лимиту использования или достиг его. Чтобы сохранить предложения включенными до достижения лимита, установите [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](/docs/ru/env-vars) в `true`. До версии 2.1.238 Claude Code пропускал их рядом с лимитом даже с переменной, установленной в `true`
* В [команде агентов](/docs/ru/agent-teams), в сеансах товарищей по команде по умолчанию. Сеанс лидера показывает предложения

В режиме печати Claude Code по умолчанию не генерирует предложения. Передайте [`--prompt-suggestions`](/docs/ru/cli-reference#cli-flags) с `-p "<prompt>" --output-format stream-json --verbose`, чтобы Claude Code выдал сообщение `prompt_suggestion` после каждого хода, который генерирует его. Генератор также пропускает очень короткие разговоры и холодные кэши подсказок здесь, поэтому один короткий запрос `-p` может не выдать ничего.

<h3 id="turn-prompt-suggestions-off">
  Отключение предложений подсказок
</h3>

Чтобы полностью отключить предложения подсказок, используйте любое из следующего:

* Отключите **Prompt suggestions** в `/config`
* Установите [`promptSuggestionEnabled`](/docs/ru/settings-reference#promptsuggestionenabled) в `false` в файле параметров
* Установите переменную окружения [`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`](/docs/ru/env-vars) в `false`, которая имеет приоритет над параметром:
  ```bash theme={null}
  export CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false
  ```

Чтобы отключить предложения подсказок во всей организации, установите `promptSuggestionEnabled` в `false` в [управляемых параметрах](/docs/ru/managed-settings). Также установите `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` в `false` под управляемым ключом [`env`](/docs/ru/settings-reference#env), чтобы пользователи не могли повторно включить их с помощью собственной переменной окружения.

<h2 id="emoji-shortcodes">
  Emoji shortcodes
</h2>

Введите `:` с последующим кодом emoji в поле ввода подсказки для вставки emoji. Требуется Claude Code v2.1.217 или более поздняя версия.

* Введите полный код, например `:heart:`, и Claude Code заменит его на ❤️ сразу же после ввода закрывающего `:`
* Введите `:` плюс минимум два символа названия, например `:hea`, чтобы открыть всплывающее окно предложений, затем нажмите `Tab` или `Enter` для вставки выделенного emoji

Код должен начинаться с начала ввода или следовать за пробелом, поэтому `:` внутри слова или URL не открывает предложения.

Чтобы отключить эту функцию, установите [`emojiCompletionEnabled`](/docs/ru/settings-reference#emojicompletionenabled) на `false` в `settings.json`. Это отключит как всплывающее окно предложений, так и встроенную замену.

<h2 id="check-spelling-as-you-type">
  Проверка орфографии во время ввода
</h2>

Claude Code может подчеркивать неправильно написанные слова в поле ввода подсказки во время ввода. Он проверяет только текст в поле ввода, никогда ответы Claude или ваши файлы. Он также ничего не проверяет, пока поле ввода находится в [режиме shell](#shell-mode-with-prefix), поиске истории `Ctrl+R` или [голосовом диктовании](/docs/ru/voice-dictation).

Проверка орфографии отключена по умолчанию, и Claude Code ничего не проверяет в [режиме чтения с экрана](/docs/ru/accessibility). Требуется Claude Code v2.1.235 или более поздняя версия.

<h3 id="prerequisites">
  Предварительные требования
</h3>

* Установите [aspell](https://github.com/GNUAspell/aspell), [hunspell](https://github.com/hunspell/hunspell) или [ispell](https://en.wikipedia.org/wiki/Ispell) и убедитесь, что он находится в вашем `PATH`. Claude Code запускает первый из трех найденных им на каждой платформе, включая `.cmd` shim, который установщик пакетов устанавливает на Windows.
* Чтобы проверить, находится ли программа в вашем `PATH`, запустите `aspell --version`, `hunspell --version` или `ispell -v` в вашем терминале. Ошибка "command not found" означает, что она еще не находится в вашем `PATH`.

<h3 id="turn-spell-checking-on-or-off">
  Включение или отключение проверки орфографии
</h3>

Claude Code читает параметр [`spellcheck`](/docs/ru/settings-reference#spellcheck) из трех мест и игнорирует его в файлах `.claude/settings.json` и `.claude/settings.local.json` проекта. Включите его в том месте, которое вы используете:

<Tabs>
  <Tab title="User settings">
    Добавьте `spellcheck` в `~/.claude/settings.json`. Это применяется в каждом проекте, который вы открываете, как и остальные ваши [пользовательские параметры](/docs/ru/settings#where-settings-live):

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```
  </Tab>

  <Tab title="Command line">
    Сохраните `spellcheck` в JSON файл, например `spellcheck.json`:

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```

    Затем передайте файл в `--settings`. Это применяется только к этому сеансу:

    ```bash theme={null}
    claude --settings spellcheck.json
    ```
  </Tab>

  <Tab title="Managed settings">
    Добавьте `spellcheck` в один из [источников управляемых параметров](/docs/ru/permissions#managed-settings) вашей организации. Это применяется ко всем пользователям, которые получают эти параметры, и они не могут их отключить:

    ```json theme={null}
    {
      "spellcheck": { "enabled": true }
    }
    ```
  </Tab>
</Tabs>

Чтобы проверить, включена ли проверка орфографии, введите неправильно написанное слово и пробел. Claude Code подчеркнет слово. Если этого не произойдет, см. [Когда Claude Code ничего не подчеркивает](#when-claude-code-underlines-nothing). Чтобы снова отключить проверку орфографии, установите `enabled` на `false` в том же месте или удалите `spellcheck`.

Чтобы выбрать, какую из трех программ запускает Claude Code, какой словарь он использует или цвет подчеркивания, добавьте любое из этих полей рядом с `enabled` в том же месте:

* `checker`: `aspell`, `hunspell` или `ispell`. Claude Code не переходит на другой checker, который вы назвали, и рассматривает любое другое значение как `auto`.
* `language`: имя словаря в форме вашего checker, например `en_GB`. Claude Code игнорирует любое значение, которое не является простым именем словаря, например путь или имя с пробелами, и checker использует свой словарь по умолчанию.
* `color`: имя цвета, например `yellow`, или значение `#rrggbb`, `#rgb`, `rgb(r,g,b)`, `ansi256(n)` или `ansi:<name>`. Claude Code использует цвет ошибки вашей темы по умолчанию и для любого значения, которое он не распознает.

Например, этот параметр `spellcheck` запускает hunspell со словарем `en_GB` и подчеркивает слова желтым цветом. Это работает одинаково в `~/.claude/settings.json`, в файле, который вы передаете в `--settings`, и в управляемых параметрах:

```json theme={null}
{
  "spellcheck": {
    "enabled": true,
    "checker": "hunspell",
    "language": "en_GB",
    "color": "yellow"
  }
}
```

Если в двух или более из трех мест есть параметр `spellcheck`, Claude Code использует только один из них: сначала управляемые параметры, затем `--settings`, затем пользовательские параметры. Он не объединяет поля из двух мест. Например, когда `--settings` устанавливает `spellcheck`, `language` в ваших пользовательских параметрах не имеет никакого эффекта.

<h3 id="what-claude-code-underlines">
  Что Claude Code подчеркивает
</h3>

Вскоре после того, как вы прекратите ввод, Claude Code подчеркивает слова, которые словарь не знает. Он оставляет слово, которое вы все еще вводите, в покое, пока вы не перейдете дальше, и никогда не изменяет ваш текст. Он также пропускает текст, который выглядит как код:

* Команды, такие как `/help`, упоминания `@`, URL-адреса, пути к файлам и флаги, такие как `--verbose`
* Слова с цифрами, подчеркиваниями или заглавной буквой после первой, и текст в обратных кавычках

Claude Code также пропускает китайский, японский, корейский, тайский, лаосский, кхмерский и мьянманский текст.

Claude Code не имеет собственного списка слов: слово считается неправильно написанным, когда это говорит ваш checker. Чтобы Claude Code перестал подчеркивать слово, добавьте слово в личный словарь вашего checker, следуя документации checker. Claude Code подхватит новое слово после перезагрузки.

<h3 id="when-claude-code-underlines-nothing">
  Когда Claude Code ничего не подчеркивает
</h3>

Claude Code ничего не подчеркивает, когда не может запустить checker:

* Checker не установлен, или тот, который вы назвали в `checker`, отсутствует
* Checker дважды подряд дает сбой при запуске или позже в сеансе. Claude Code перезапускает его после первого сбоя и прекращает проверку после второго, пока вы не перезагрузите Claude Code
* Checker требует более 15 секунд для ответа три раза. Каждый раз Claude Code оставляет слова, на которые он ждал, без отметок; после третьего раза он прекращает проверку, пока вы не перезагрузите Claude Code

Чтобы узнать, что произошло, запустите `claude --debug` с включенной проверкой орфографии и введите слово. Затем найдите строки `[spellcheck]` в журнале отладки в `~/.claude/debug/<session-id>.txt`. Одна строка называет программу, которую запустил Claude Code, или перечисляет те, которые он искал и не нашел. Более поздние строки говорят, почему он остановился. Ошибка отсутствующего словаря там означает, что checker не имеет словаря для вашего значения `language`, или нет словаря по умолчанию, когда `language` не установлен. Установите один или установите `language` на словарь, который у вас есть.

<h2 id="invisible-characters-in-prompts">
  Невидимые символы в подсказках
</h2>

Вставленный текст может содержать символы Unicode, которые терминал не отображает вообще, такие как символы тегов, двунаправленные управляющие символы и пробелы нулевой ширины, поэтому подсказка может содержать текст, который вы никогда не видите. Чтобы скопированный текст не содержал инструкций, которые ваш терминал не отображает, Claude Code удаляет эти символы при нажатии Enter, прежде чем что-либо отправлять. Он очищает как саму подсказку, так и содержимое любой свёрнутой [ссылки на вставленный текст](/docs/ru/terminal-config#paste-large-content), которую включает подсказка. Claude Code сохраняет соединители, которые используют персидский и индийский шрифты, а также селекторы внутри последовательностей эмодзи.

Если Claude Code что-то удалил, то нажатие Enter ничего не отправляет. Очищенная подсказка возвращается в поле ввода с уведомлением, например `Удалено 3 невидимых символа · просмотрите и нажмите Enter для отправки`, и повторное нажатие Enter отправляет текст в том виде, в котором он показан.

Когда вы передаёте подсказку в командной строке, например `claude "fix the login bug"`, или передаёте её в интерактивный сеанс, Claude Code не ждёт второго нажатия Enter. Он удаляет символы, показывает уведомление и отправляет очищенную подсказку. Если очищенная подсказка начинается с `/`, Claude Code помещает её в поле ввода для вашего просмотра и отправки.

<h2 id="review-changes-with-/diff">
  Просмотр изменений с помощью /diff
</h2>

Запустите `/diff`, чтобы просмотреть изменения в вашем рабочем дереве, не покидая Claude Code. Вы видите правки, которые Claude уже внёс, наряду со всем остальным, что вы ещё не зафиксировали.

В изменениях, которые `/diff` читает из git, подмодуль отображается как одна запись, и только когда изменяется коммит, на который он указывает; правки файлов внутри подмодуля там не отображаются.

В [полноэкранном режиме](/docs/ru/fullscreen) `/diff` открывает [панель diff](#diff-panel) рядом с беседой, которая остаётся открытой и обновляется во время вашей работы. В классическом рендере `/diff` открывает [средство просмотра diff](#diff-viewer) вместо приглашения, и вы закрываете его, когда закончите читать.

<h3 id="diff-panel">
  Diff panel
</h3>

Панель diff отображает изменённые файлы с количеством добавленных и удалённых строк и показывает diff каждого файла под списком. Claude Code обновляет её каждый раз, когда Claude редактирует файл или запускает команду shell. Чтобы закрыть её, запустите `/diff` снова или нажмите `✕` в её заголовке.

Для использования панели вам нужно:

* [Полноэкранный режим](/docs/ru/fullscreen)
* Репозиторий git
* Терминал шириной не менее 110 столбцов
* Claude Code версии 2.1.260 или позже

Когда панель не может открыться, `/diff` открывает средство просмотра diff вместо этого или сообщает вам причину.

Панель также открывается самостоятельно, как только Claude начинает редактировать файлы, если ваш терминал имеет ширину не менее 144 столбцов. После того как вы открыли её сами с помощью `/diff`, в последующих сеансах она открывается сразу же, как только Claude редактирует файл в любом терминале, достаточно широком для её размещения. Закройте панель, и она останется закрытой в этом сеансе и в последующих, пока вы снова не запустите `/diff`.

Пока панель открыта, вы можете:

* **Перейти к файлу**: нажмите на его строку в списке. Прокручивайте панель колесом мыши. Когда сам список файлов слишком длинный, чтобы поместиться, прокручивайте его с помощью `Alt+Up` и `Alt+Down`, или `Ctrl+Up` и `Ctrl+Down`.
* **Попросить Claude прокомментировать конкретные строки**: выберите их в панели мышью. Claude Code прикрепляет выделение к вашему следующему приглашению и показывает количество строк рядом с вводом, пока вы его не отправите.
  * Чтобы отправить приглашение без выделения, переместите курсор сразу после индикатора количества строк и нажмите `Backspace`, чтобы удалить его. Требуется Claude Code версии 2.1.271 или позже.
* **Показать файлы, которые панель пропускает**: список пропускает тестовые файлы и сгенерированные файлы и сворачивает изменения с предыдущего сеанса в одну строку внизу. Нажмите на любую строку счётчика, чтобы развернуть её.
* **Изменить, с чем панель сравнивает**: нажмите `Ctrl+X B`, чтобы переключаться между изменениями этого сеанса, вашими незафиксированными изменениями как одним списком и всем, что было с момента разветвления вашей ветки от ветки по умолчанию. Claude Code запоминает выбор для каждого проекта.

Чтобы привязать клавиши к этим действиям, см. [Действия панели diff](/docs/ru/keybindings#diff-panel-actions).

<h3 id="diff-viewer">
  Diff viewer
</h3>

Средство просмотра diff занимает место приглашения, пока вы его не закроете. Его представление **Current** показывает ваши незафиксированные изменения из git, или, когда их нет, то, что ваша ветка добавляет поверх ветки по умолчанию. Средство просмотра также имеет представление хода для каждого приглашения, после которого Claude редактировал файлы, показывая только эти правки. Claude Code создаёт представления хода из правок файлов Claude, а не из git, поэтому изменение, которое Claude вносит через команду shell, отображается только в Current.

Используйте эти клавиши в средстве просмотра:

* **Left и Right**: переключение между Current и представлениями хода.
* **Up и Down**: выбор файла.
* **Enter**: открыть diff выбранного файла. Прокручивайте его с помощью Up и Down, или PageUp и PageDown.
* **Esc**: вернуться из diff файла в список или закрыть средство просмотра из списка.

Чтобы переназначить эти клавиши, см. [Действия diff](/docs/ru/keybindings#diff-actions).

<h2 id="side-questions-with-/btw">
  Боковые вопросы с /btw
</h2>

Используйте `/btw` для задания вопроса о вашей текущей работе без добавления в историю разговора.

```
/btw what was the name of that config file again?
```

Claude отвечает на боковой вопрос на основе того, что уже находится в разговоре: ваши сообщения, его ответы и результаты инструментов, которые он собрал. Вы можете спросить о коде, который Claude уже прочитал, о решениях, которые он принял ранее, или о чём-либо ещё из сеанса. Более поздний боковой вопрос также видит ваши более ранние боковые вопросы: Claude Code воспроизводит последние 20 обменов с каждым запросом, пока вы их не очистите. Вопрос и ответ никогда не попадают в историю разговора. В терминале они появляются в закрываемом оверлее. Терминал хранит поток в памяти: нажмите `x` для очистки более ранних обменов, и они исчезнут при выходе из Claude Code.

В [панели чата расширения VS Code](/docs/ru/vs-code#use-the-prompt-box) `/btw` открывает панель вместо оверлея, описанного в этом разделе, и вы задаёте дополнительные вопросы прямо в панели. Поток панели сохраняется при перезагрузке окна согласно графику хранения, описанному на этой странице. Вам нужно расширение версии 2.1.227 или позже. Более ранние версии расширения не предлагают `/btw`.

* **Доступно во время работы Claude**: вы можете запустить `/btw` даже во время обработки Claude ответа. Боковой вопрос выполняется независимо и не прерывает основной ход. Он видит всё в разговоре до сих пор, кроме ответа, который Claude ещё пишет.
* **Без доступа к инструментам**: боковые вопросы отвечают только на основе того, что уже находится в контексте. Claude не может читать файлы, выполнять команды или искать при ответе на боковой вопрос. Если Claude всё же выводит вызовы инструментов как текст, ответ заканчивается примечанием о том, что ничего не было выполнено.
* **Один ответ**: в оверлее нет дополнительных ходов. Чтобы продолжить поток, задайте ещё один вопрос `/btw`. Чтобы продолжить с полным доступом к инструментам в локальном сеансе, нажмите `f` для разветвления этого вопроса и ответа в [фоновый подагент](/docs/ru/sub-agents#fork-the-current-conversation).
* **Низкая стоимость**: пока [кэш подсказок](/docs/ru/prompt-caching) разговора активен, боковой вопрос стоит немного больше, чем сам ответ.

Ваши пять самых новых более ранних боковых вопросов появляются как затемнённый список над текущим ответом с подсчётом любых более старых. Они остаются вне истории разговора.

Чтобы вернуться к оверлею после его закрытия, запустите `/btw` без вопроса. Оверлей снова откроется на вашем самом последнем обмене. До версии 2.1.212 `/btw` без вопроса выводил сообщение об использовании вместо этого.

После появления ответа оверлей принимает эти клавиши.

| Клавиша                      | Действие                                                                                                                                                                                                                                                                                                                                                                                                                        |
| :--------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Space`, `Enter`, `Escape`   | Закрыть ответ и вернуться к подсказке                                                                                                                                                                                                                                                                                                                                                                                           |
| `Up` / `Down`                | Прокрутить ответ                                                                                                                                                                                                                                                                                                                                                                                                                |
| `Shift+Left` / `Shift+Right` | Переходить между этим ответом и вашими более ранними ответами `/btw`. `Shift+Left` переходит к более старым ответам, а `Shift+Right` возвращается к текущему. `[` и `]` делают то же самое для терминалов, которые не сообщают `Shift` со стрелками. `Tab` / `Shift+Tab` циклируют через те же ответы. Требуется Claude Code версии 2.1.257 или позже. Между версиями 2.1.187 и 2.1.256 клавишами были простые `Left` / `Right` |
| `c`                          | Скопировать ответ в буфер обмена как необработанный Markdown. Используйте это вместо выделения мышью, которое захватывает жёсткий перенос терминала вместо исходного текста                                                                                                                                                                                                                                                     |
| `f`                          | Запустить [разветвлённый подагент](/docs/ru/sub-agents#fork-the-current-conversation), который наследует родительский разговор плюс этот вопрос и ответ, чтобы он мог продолжить с полным доступом к инструментам. Вы остаётесь в текущем сеансе и находите разветвление в [панели ниже вашей подсказки](/docs/ru/sub-agents#observe-and-steer-running-forks). Доступно только в локальных сеансах                                        |
| `x`                          | Очистить список более ранних обменов `/btw`, показанный над текущим ответом                                                                                                                                                                                                                                                                                                                                                     |

В присоединённом [фоновом сеансе](/docs/ru/agent-view#attach-to-a-session) `Left` отсоединяет и возвращает вас в представление агента, даже во время прибытия ответа. Боковой вопрос продолжает выполняться, пока вас нет. В следующий раз, когда вы присоедините к сеансу, оверлей снова откроется с боковым вопросом или с его ответом. До версии 2.1.257 `Left` там не отсоединял.

`/btw` видит ваш полный разговор, но не имеет инструментов. [Подагент](/docs/ru/sub-agents) имеет инструменты и начинает с подсказки, которую он получает, или, для [разветвления](/docs/ru/sub-agents#fork-the-current-conversation), с копии этого разговора. Используйте `/btw` для вопросов о том, что Claude уже знает из этого сеанса; используйте подагента для поиска чего-то нового.

<h2 id="task-list">
  Список задач
</h2>

Список задач — это контрольный список Claude: элементы, которые Claude создал для планирования многоэтапной работы, с индикаторами, показывающими, что ожидает выполнения, находится в процессе или завершено. Это отдельно от представления фоновых задач. Чтобы увидеть запущенные оболочки и подагентов, используйте [`/tasks`](/docs/ru/commands) вместо этого.

Список заполняется только в сеансах, которые имеют инструменты отслеживания задач, которые Claude Code предоставляет по умолчанию на [моделях Claude 3.x, Opus 4 через 4.7, Sonnet 4 через 4.6 и Haiku 4.5](/docs/ru/tools-reference#task-tool-availability). На любой другой модели, включая ID модели, который Claude Code не распознает, список остается пустым, если вы не согласитесь с `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` или одним из других способов в разделе [Доступность инструмента Task](/docs/ru/tools-reference#task-tool-availability). Когда сеанс имеет инструменты, список задач работает следующим образом:

* Нажмите `Ctrl+T` для переключения представления списка задач. Дисплей показывает до пяти задач одновременно. Когда Claude еще не создал никаких элементов контрольного списка, переключение не имеет видимого эффекта, потому что нечего отображать
* Если вы оставите список развернутым, Claude Code восстановит развернутое представление при следующем запуске в сеанс, который все еще содержит задачи, например с `--resume` или `--continue`. Когда список задач пуст, Claude Code запускает его в свернутом состоянии
* Чтобы увидеть все задачи или очистить их, попросите Claude напрямую: "show me all tasks" или "clear all tasks"
* Задачи сохраняются при сжатии контекста, помогая Claude оставаться организованным в более крупных проектах
* Чтобы поделиться списком задач между сеансами, установите `CLAUDE_CODE_TASK_LIST_ID` для использования именованного каталога в `~/.claude/tasks/`: `CLAUDE_CODE_TASK_LIST_ID=my-project claude`

<h2 id="session-recap">
  Краткое резюме сеанса
</h2>

Когда вы возвращаетесь в терминал после перерыва, Claude Code показывает однострочное резюме того, что произошло в сеансе до сих пор. Резюме генерируется в фоновом режиме после того, как прошло не менее трёх минут с момента последнего завершённого хода и терминал не в фокусе, поэтому оно готово, когда вы переключитесь обратно. Резюме появляются только после того, как в сеансе будет не менее трёх ходов, и никогда не появляются два раза подряд.

Запустите `/recap` для создания резюме по требованию. Claude Code ограничивает как автоматические резюме, так и вывод `/recap` до 400 символов. Чтобы отключить автоматические резюме, откройте `/config` и отключите **Session recap**.

Краткое резюме сеанса включено по умолчанию для каждого плана и поставщика. Резюме всегда пропускается в неинтерактивном режиме.

<h2 id="wait-for-a-usage-limit-to-reset">
  Ожидание сброса лимита использования
</h2>

Когда [лимит использования](/docs/ru/errors#youve-hit-your-session-limit) claude.ai останавливает Claude в середине задачи, Claude Code ждёт в открытой сессии и продолжает задачу самостоятельно после сброса лимита. Автоматическое продолжение включено по умолчанию в интерактивных сессиях, вошедших в систему с подпиской claude.ai. Требуется Claude Code v2.1.234 или позже.

Пока Claude Code ждёт, строка в нижней части сессии показывает, когда он продолжит:

```text theme={null}
Usage limit reached · continuing automatically at 3:45pm · esc to cancel
```

Держите сессию открытой. Что произойдёт дальше, зависит от того, как закончится ожидание:

* **При сбросе**: строка читается как `continuing shortly`, затем `Usage limit reset · continuing automatically`, и Claude Code отправляет Claude фиксированный запрос, чтобы продолжить задачу там, где она остановилась. Он не переотправляет ваше последнее сообщение.
* **После сна вашего компьютера**: если он спал более 30 минут и лимит сбросился во время сна, строка читается как `Your usage limit has reset · press enter to continue`. Нажмите `Enter` для продолжения. После более короткого сна Claude Code продолжает самостоятельно.
* **Раньше**: когда вы закончите добавлять [кредиты использования](/docs/ru/costs#add-usage-credits-to-your-subscription) с помощью `/usage-credits`, снова войдёте в систему после `/upgrade` или переключите модели с помощью `/model` во время ожидания, Claude Code проверяет, доступно ли использование снова, и продолжает немедленно, если оно доступно. Он не проверяет после обновления или покупки, которые вы совершаете в браузере самостоятельно. В разделе [`opusplan`](/docs/ru/model-config#opusplan-model-setting) и других параметрах модели, которые запускают режим плана на другой модели, Claude Code ждёт сброса вместо этого.

Продолженная задача работает как любой другой ход. Claude Code по-прежнему запрашивает [разрешения](/docs/ru/permissions) как обычно, поэтому задача может остановиться на запросе, пока вас нет. Если он снова достигнет лимита, Claude Code повторно активирует ожидание самостоятельно максимум два раза подряд, затем останавливается и показывает `Automatic continue stopped after repeated usage-limit hits · /rate-limit-options to try again`.

<h3 id="cancel-the-wait">
  Отмена ожидания
</h3>

Нажмите `Esc` при пустом запросе или `Ctrl+C`, пока отображается строка, или запустите [`/rate-limit-options`](/docs/ru/commands#all-commands) и выберите **Don't continue automatically**. Claude Code подтверждает строкой, которая начинается с `Automatic continue cancelled`.

После отмены ничего не продолжается, пока вы не отправите запрос или не выберете строку, которая начинается с **Wait here, then continue automatically** из `/rate-limit-options` снова. Claude Code не запускает ожидание самостоятельно снова для этого окна сброса; следующее окно сброса начинается заново.

Ожидание также заканчивается без продолжения задачи в этих случаях:

* **Вы отправляете запрос**: Claude Code запускает ваш запрос вместо ожидания.
* **Вы выходите из Claude Code**: ожидание не перезапускается при возобновлении сессии.
* **Разговор переходит в другие руки**: вы переключаете учётные записи с помощью `/login`, очищаете или отматываете разговор, `/resume` другую сессию, вытягиваете одну с помощью `/teleport`, перезапускаете с помощью `/tui` или передаёте сессию Claude Desktop, фоновой сессии или облаку.
* **Параметр отключается или сброс выходит за пределы 24 часов**: это заканчивает только ожидание, которое Claude Code запустил самостоятельно. Ожидание, которое вы выбрали из `/rate-limit-options`, продолжает отсчитываться.
* **Продолжение заблокировано**: [`UserPromptSubmit` hook](/docs/ru/hooks#userpromptsubmit), который блокирует запрос продолжения, или сбой перед его достижением модели, заканчивает ожидание. Claude Code сообщает вам, что продолжение не выполнилось. Отправьте запрос для продолжения.

<h3 id="start-a-wait-yourself">
  Начните ожидание самостоятельно
</h3>

Claude Code не запускает ожидание самостоятельно в этих случаях:

* **Сессии Remote Control и товарищей команды агентов**: человек у этого терминала всё ещё может запустить одну.
* **Сброс более чем на 24 часа в будущем**: еженедельный лимит может сброситься через дни.
* **Лимит Opus или Sonnet, пока вы запускаете модель вне этого семейства**: ваш следующий ход может не достичь этого лимита. [`opusplan`](/docs/ru/model-config#opusplan-model-setting) и другие параметры модели, которые запускают режим плана на ограниченном семействе, не получают это исключение.

В этих случаях и всякий раз, когда автоматическое продолжение отключено, Claude Code открывает меню параметров лимита использования один раз за окно сброса, когда вы достигаете лимита на своём собственном терминале. Выберите строку, которая начинается с **Wait here, then continue automatically**, чтобы начать ожидание. В сессии [Remote Control](/docs/ru/remote-control) или [команды агентов](/docs/ru/agent-teams) товарища запустите `/rate-limit-options` самостоятельно, чтобы открыть меню.

Claude Code вообще не предлагает ожидание в этих случаях:

* **Фоновые сессии и запуски `-p`**: строка меню недоступна.
* **Ключи API, облачные поставщики и выставление счётов на основе использования**: использование там измеряется за запрос, поэтому нет сброса для ожидания.
* **[LLM gateway](/docs/ru/llm-gateway#subscriptions-and-gateways) без сохранённого входа claude.ai**: Claude Code предлагает ожидание только при сохранённом входе claude.ai в качестве активного учётного данного.

<h3 id="turn-automatic-continue-off">
  Отключите автоматическое продолжение
</h3>

В `/config` отключите **Continue automatically at usage limit** или установите [`autoContinueAtUsageLimit`](/docs/ru/settings-reference#autocontinueatusagelimit) на `false` в ваших пользовательских параметрах. `/config autoContinueAtUsageLimit=false` также работает, включая с `-p`, но форма `key=value` не может включить его обратно, потому что параметр предоставляет автоматическое выполнение. Какие файлы параметров Claude Code читает для этого ключа, указано в [справочнике параметров](/docs/ru/settings-reference#autocontinueatusagelimit).

<h2 id="pr-review-status">
  Статус PR
</h2>

При работе над веткой с открытым pull request Claude Code отображает кликабельную ссылку PR в нижнем колонтитуле, например "PR #446". Ссылка имеет цветное подчеркивание, указывающее на состояние рецензии:

* Зелёный: одобрено
* Жёлтый: ожидание рецензии
* Красный: запрошены изменения
* Серый: черновик

Значок исчезает после слияния или закрытия pull request.

`Cmd+click` (macOS) или `Ctrl+click` (Windows/Linux) на ссылку, чтобы открыть pull request в браузере.

Статус обновляется сразу же после успешного выполнения `git push` или команды `gh pr`, которая изменяет pull request, такой как `gh pr create` или `gh pr merge`, в текущей сессии.

Claude Code отображает значок как гиперссылку даже когда не может обнаружить поддержку гиперссылок в вашем терминале, что часто происходит при подключении по SSH или в tmux. Установите [`FORCE_HYPERLINK=0`](/docs/ru/env-vars), чтобы отображать значок как обычный текст.

Когда вы установите [`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`](/docs/ru/env-vars), Claude Code не проверяет статус pull request или merge request.

<Note>
  Статус PR для репозиториев GitHub требует токена GitHub. Claude Code находит его на основе хоста удалённого репозитория:

  * **github.com**: `GH_TOKEN` или `GITHUB_TOKEN`, или токен, сохранённый командой `gh auth login`. Без него нижний колонтитул показывает `install gh for PR status`, если CLI `gh` не установлен, или `gh auth login for PR status`, если установлен
  * **Хост GitHub Enterprise, установленный как `GH_HOST`**: `GH_ENTERPRISE_TOKEN` или `GITHUB_ENTERPRISE_TOKEN`, или токен, сохранённый командой `gh auth login --hostname <host>`. Без него нижний колонтитул показывает те же подсказки
  * **Любой другой хост GitHub**: токен, сохранённый командой `gh auth login --hostname <host>`. Без него Claude Code не показывает значок и не показывает подсказку
</Note>

<h3 id="gitlab-merge-requests">
  GitLab merge requests
</h3>

Когда вы работаете над веткой с открытым GitLab merge request, Claude Code показывает кликабельный значок `MR !N` в нижнем колонтитуле на месте, где обычно находится ссылка на GitHub PR. `!N` — это собственный синтаксис GitLab для ссылки на merge request номер N. Цветное подчеркивание показывает состояние merge request:

* Зелёный: GitLab сообщает, что merge request можно объединить
* Жёлтый: любое другое открытое состояние
* Серый: черновик

Значок исчезает после слияния или закрытия merge request.

Он обновляется сразу же после успешного выполнения `git push` или команды `glab mr`, которая изменяет merge request, такой как `glab mr create` или `glab mr merge`, в текущей сессии.

Чтобы получить значок, вам нужно:

* Claude Code v2.1.234 или позже
* Удалённый репозиторий, который указывает на ваш хост GitLab, либо gitlab.com, либо самостоятельно управляемый экземпляр
* [`glab` CLI](https://gitlab.com/gitlab-org/cli) в вашем `PATH`, аутентифицированный с помощью `glab auth login`

Claude Code игнорирует переменные окружения токена `glab`, такие как `GITLAB_TOKEN`, при проверке статуса, поэтому вы не получите значок только от экспортированного токена. Claude Code также ищет `glab` и его вход один раз за сессию, поэтому перезагрузите Claude Code после установки `glab` или запуска `glab auth login`.

<h2 id="issue-reference-links">
  Ссылки на ссылки проблем
</h2>

Когда Claude упоминает проблему как `owner/repo#123`, вы можете щелкнуть ссылку, чтобы открыть её, при условии, что ваш терминал поддерживает гиперссылки. Если Claude Code не обнаружит поддержку гиперссылок в вашем терминале, установите [`FORCE_HYPERLINK`](/docs/ru/env-vars) на `1`, чтобы включить ссылки, или на `0`, чтобы оставить ссылки в виде обычного текста.

Вы получаете ссылку только для двухчастной формы `owner/repo#123`. Эти ссылки остаются обычным текстом:

* Простая `#123`
* Вложенный путь GitLab, такой как `group/subgroup/project#123`
* Любая ссылка внутри диапазона кода или блока кода

Claude Code создаёт ссылку для хоста репозитория, который он определяет из вашего git remote, а не для репозитория, который называет ссылка:

| Хост вашего репозитория                                              | Где ссылается `owner/repo#123`               |
| :------------------------------------------------------------------- | :------------------------------------------- |
| github.com, хост GitHub Enterprise или любой хост, не указанный ниже | `https://<host>/owner/repo/issues/123`       |
| gitlab.com                                                           | `https://gitlab.com/owner/repo/-/issues/123` |
| bitbucket.org, codeberg.org или gitea.com                            | Нет ссылки; ссылка остаётся обычным текстом  |
