# Claude Code Desktop в WSL

> Запуск сеансов Code внутри дистрибутива WSL 2 на Windows

На Windows вкладка Code может запускать сеанс внутри дистрибутива WSL 2 вместо самой Windows. Процесс Claude Code сеанса, его инструменты и git выполняются внутри дистрибутива, используя его цепочку инструментов Linux и собственные пути Linux, ту же среду, на которую нацелен ваш проект.

Используйте сеанс WSL, когда ваш репозиторий находится в файловой системе дистрибутива. Работа с этими файлами из Windows проходит через сетевую файловую систему, что медленно и нарушает отслеживание файлов; запуск сеанса внутри дистрибутива избегает обоих этих проблем.

<h2 id="requirements">
  Требования
</h2>

* Windows 10 или 11 с [WSL 2](https://learn.microsoft.com/windows/wsl/install). WSL 1 не поддерживается.
* По крайней мере один установленный дистрибутив (например, Ubuntu).
* `git` установлен внутри дистрибутива.

<h2 id="start-a-wsl-session">
  Запуск сеанса WSL
</h2>

<Steps>
  <Step title="Выберите дистрибутив">
    Запустите новый сеанс на вкладке Code и откройте средство выбора среды. Ваши установленные дистрибутивы WSL 2 появляются в разделе **WSL**. Выберите один.
  </Step>

  <Step title="Выберите папку">
    Сеанс запускается в домашнем каталоге дистрибутива. Используйте средство выбора папок для выбора папки проекта. Просмотр происходит внутри дистрибутива с путями Linux, такими как `/home/you/project`.
  </Step>

  <Step title="Доверьте папке">
    Первый сеанс в папке показывает диалог доверия рабочей области. Доверие предоставляется для каждого дистрибутива и папки; доверие папке в одном дистрибутиве не применяется к другому дистрибутиву или к тому же пути на Windows.
  </Step>
</Steps>

Первый сеанс в дистрибутиве занимает немного больше времени, пока Claude настраивается внутри него. Вы также можете открыть папку `\\wsl.localhost\...` из обычного средства выбора папок, и она снова откроется внутри этого дистрибутива.

Папки, которые вы недавно использовали, появляются в средстве выбора для каждого дистрибутива, поэтому повторное подключение к проекту — это один клик.

<h2 id="what-works-in-a-wsl-session">
  Что работает в сеансе WSL
</h2>

Параллельные сеансы, боковые чаты, визуальный просмотр различий, статус ветви и запроса на слияние, а также worktrees работают, поддерживаемые git и цепочкой инструментов внутри дистрибутива. "Открыть в редакторе" открывает VS Code, подключенный к дистрибутиву через [Remote - WSL](https://code.visualstudio.com/docs/remote/wsl).

Несколько функций еще недоступны в сеансах WSL: интегрированный терминал, соединители и плагины, разветвление сеанса, панель браузера файлов и предложения файлов при вводе `@` в компоновщик.

<h2 id="managed-devices">
  Управляемые устройства
</h2>

На устройствах, управляемых организацией, сеансы WSL могут быть недоступны. Если запуск сеанса завершается с сообщением об управлении устройством, это контролируется вашим администратором. Администраторы: см. [как параметры достигают устройств](/docs/ru/admin-setup#decide-how-settings-reach-devices) в руководстве по развертыванию.
