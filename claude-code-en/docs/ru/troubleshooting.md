# Troubleshooting

> Исправьте высокое использование CPU или памяти, зависания, auto-compact thrashing и проблемы поиска в Claude Code, и найдите нужную страницу для других проблем.

Эта страница охватывает проблемы производительности, стабильности и поиска после того, как Claude Code запущен. Для других проблем начните со страницы, которая соответствует тому, где вы застряли:

Если вы не уверены, какой применяется, запустите `/doctor` внутри Claude Code для автоматической проверки вашей установки, параметров, расширений и использования контекста; он предлагает исправления, которые может применить после вашего подтверждения. Если `claude` вообще не запускается, запустите `claude doctor` из вашей оболочки вместо этого. Запустите `/mcp` для проверки статуса MCP server.

<h2 id="performance-and-stability">
  Производительность и стабильность
</h2>

Эти разделы охватывают проблемы, связанные с использованием ресурсов, отзывчивостью и поведением поиска.

<h3 id="high-cpu-or-memory-usage">
  Высокое использование CPU или памяти
</h3>

Claude Code разработан для работы с большинством сред разработки, но может потреблять значительные ресурсы при обработке больших кодовых баз. Если вы испытываете проблемы с производительностью:

1. Используйте `/compact` регулярно, чтобы уменьшить размер контекста. Если он возвращает `Not enough messages to compact.`, разговор имеет слишком мало ходов для суммирования; это может произойти даже при полном контексте, когда одна большая вставка его заполнила
2. Закройте и перезагрузите Claude Code между основными задачами
3. Рассмотрите добавление больших директорий сборки в ваш файл `.gitignore`
4. Перезагрузитесь с помощью [`claude --safe-mode`](/docs/ru/cli-reference#cli-flags), чтобы проверить, является ли источником plugin, MCP server или hook. Это отключает все настройки на время сеанса; если использование снизится, см. [Debug your configuration](/docs/ru/debug-your-config#test-against-a-clean-configuration), чтобы найти, какой именно

Если использование памяти в куче сеанса превышает 2.5GB, появляется критическое предупреждение об использовании памяти. Чтобы освободить память, перезагрузите Claude Code и запустите [`claude --continue`](/docs/ru/cli-reference#cli-flags), чтобы возобновить разговор в новом процессе.

Вне [полноэкранного рендеринга](/docs/ru/fullscreen) запуск `/compact` также освобождает память. Предупреждение исчезает, как только использование памяти упадёт ниже 2.5GB.

Если использование памяти остаётся высоким после этих шагов, запустите `/heapdump`, чтобы записать два файла на `~/Desktop`: снимок кучи JavaScript с именем `<session-id>.heapsnapshot` и разбор памяти с именем `<session-id>-diagnostics.json`. Claude Code [скрывает команду из меню команд](/docs/ru/commands#how-the-command-menu-matches-what-you-type); введите её полностью. На Linux без папки Desktop файлы записываются в вашу домашнюю директорию.

<Warning>
  Файл `.heapsnapshot` содержит каждую строку в процессе, включая вашу полную беседу и учётные данные. Не прикрепляйте его к публичной проблеме и не делитесь им.
</Warning>

Команда также выводит сводку в разговор, показывая размер резидентного набора, кучу JS, буферы массивов и неучтённую нативную память, плюс любые индикаторы утечек, которые она обнаружила, такие как высокий темп роста памяти или необычно высокое количество открытых дескрипторов. Сводка указывает, находится ли большая часть памяти в куче JS, которую захватывает снимок, или в нативной памяти, которую он не захватывает.

Сделайте одно из двух с выводом:

* **Сообщите об этом**: откройте [GitHub issue](https://github.com/anthropics/claude-code/issues) и прикрепите только файл `-diagnostics.json`, который содержит статистику, лежащую в основе выведённой сводки, и не содержит содержимого разговора или учётных данных
* **Исследуйте это сами**: если сводка говорит, что большая часть памяти находится в куче JS, откройте файл `.heapsnapshot` в Chrome DevTools в разделе Memory → Load и отсортируйте по retained size, чтобы увидеть, что удерживает память

Если сводка говорит, что большая часть памяти находится в нативной памяти, снимок не может её показать; включите индикаторы утечек сводки в ваш отчёт вместо этого.

<h3 id="large-tables-are-cut-off-in-the-terminal">
  Большие таблицы обрезаются в терминале
</h3>

Таблица Markdown с более чем 200 строками отображает первые 200 строк, за которыми следует строка `… N more rows not shown`. Отображение ограничено только визуально: полная таблица остаётся в разговоре, и [`/copy`](/docs/ru/commands) копирует каждую строку. Для таблицы, которая слишком велика для чтения в терминале, попросите Claude записать её в файл вместо этого. До версии v2.1.208 Claude Code отображал каждую строку, поэтому возобновление сеанса, содержащего очень большую таблицу, могло зависнуть при её повторном отображении.

<h3 id="auto-compaction-stops-with-a-thrashing-error">
  Автоматическое сжатие останавливается с ошибкой thrashing
</h3>

Если вы видите `Autocompact is thrashing: the context refilled to the limit...`, автоматическое сжатие прошло успешно, но файл или вывод инструмента немедленно заполнили окно контекста несколько раз подряд. Claude Code останавливает повторные попытки, чтобы избежать траты вызовов API на цикл, который не делает прогресс.

Чтобы восстановиться:

1. Попросите Claude прочитать большой файл в меньших фрагментах, таких как конкретный диапазон строк или функция, вместо всего файла
2. Запустите `/compact` с фокусом, который удаляет большой вывод, например `/compact keep only the plan and the diff`
3. Переместите работу с большим файлом на [subagent](/docs/ru/sub-agents), чтобы она работала в отдельном окне контекста
4. Запустите `/clear`, если более ранний разговор больше не нужен

<h3 id="command-hangs-or-freezes">
  Команда зависает или не отвечает
</h3>

Если Claude Code кажется неотзывчивым:

1. Нажмите Ctrl+C, чтобы попытаться отменить текущую операцию
2. Если неотзывчив, вам может потребоваться закрыть терминал и перезагрузить

Перезагрузка не теряет вашу беседу. Запустите `claude --resume` в той же директории, чтобы продолжить сеанс.

<h3 id="garbled-or-corrupted-text-in-an-editor’s-integrated-terminal">
  Искажённый или повреждённый текст во встроенном терминале редактора
</h3>

Если символы отображаются как прямоугольники, размазанные линии или неправильные глифы при запуске Claude Code в интегрированном терминале VS Code, Cursor или Devin Desktop, причиной, вероятно, является GPU-рендерер терминала. Запустите `/terminal-setup` внутри Claude Code, чтобы установить `terminal.integrated.gpuAcceleration` на `"off"`, или установите это вручную в настройках вашего редактора и перезагрузите окно. Смотрите [Terminal configuration](/docs/ru/terminal-config) для других настроек, которые записывает `/terminal-setup`.

<h3 id="mouse-wheel-scrolls-one-line-at-a-time-in-fullscreen-rendering">
  Колесо мыши прокручивает по одной строке в полноэкранном рендеринге
</h3>

При [полноэкранном отображении](/docs/ru/fullscreen) Claude Code прокручивает сам разговор, а не оставляет это вашему терминалу. Если каждый поворот колеса перемещает меньше строк, чем вы хотите, запустите `/scroll-speed`, чтобы увеличить количество строк на один поворот и сохранить это, или установите переменную окружения `CLAUDE_CODE_SCROLL_SPEED`, кроме как в терминале IDE JetBrains, где Claude Code применяет собственную обработку прокрутки и ни один из них не вступает в силу. Смотрите [Mouse wheel scrolling](/docs/ru/fullscreen#mouse-wheel-scrolling) для значений, которые каждый принимает.

Чтобы двигаться быстрее без изменения скорости, нажмите `PgUp` и `PgDn`, чтобы прокручивать половину экрана за раз. Чтобы вернуть прокрутку вашему собственному буферу обратного хода терминала, запустите `/tui default`, чтобы переключиться на классический рендерер.

<h3 id="clipboard-commands-such-as-pbcopy-fail-inside-the-sandbox">
  Команды буфера обмена, такие как `pbcopy`, не работают внутри sandbox
</h3>

Когда [sandboxing](/docs/ru/sandboxing) включён, утилиты буфера обмена, такие как `pbcopy`, `xclip` и `wl-copy`, могут не достичь системного буфера обмена из внутри изолированной команды Bash, оставляя ваш буфер обмена неизменённым после того, как Claude передаёт текст в них.

Чтобы поместить вывод Claude в ваш буфер обмена, попросите Claude вывести содержимое в его ответе, затем запустите [`/copy`](/docs/ru/commands). `/copy` записывает в буфер обмена из самого процесса Claude Code, а не из изолированной команды, поэтому sandboxing не блокирует это. Он может копировать один блок кода вместо всего ответа, и он также записывает то, что он скопировал, в файл и выводит путь, что даёт вам резервный вариант, когда запись в буфер обмена не достигает вашего терминала, например через SSH.

Когда Claude передаёт текст в один из этих инструментов, добавление `pbcopy *`, `wl-copy *` или `xclip *` в [`excludedCommands`](/docs/ru/settings-reference#sandbox-excludedcommands) не выводит этот вызов из sandbox самостоятельно.

<h3 id="copied-text-doesn’t-reach-your-local-clipboard-over-ssh">
  Скопированный текст не достигает вашего локального буфера обмена через SSH
</h3>

Когда Claude Code работает на удалённой машине через SSH, он не может запустить инструмент буфера обмена на вашей локальной машине. Вне tmux, когда вы выбираете текст в [полноэкранном отображении](/docs/ru/fullscreen) или запускаете `/copy`, Claude Code отправляет текст в ваш терминал как последовательность escape-кода OSC 52 вместо этого. Ваш терминал решает, поместить ли его в буфер обмена. `/copy` сообщает `Copied to clipboard` независимо от того, достиг ли текст, и вне tmux уведомление о выборе читает `sent N chars via OSC 52`.

Некоторые терминалы не действуют на OSC 52. iTerm2 игнорирует это, пока вы не включите **Settings > General > Selection > Applications in terminal may access clipboard**, и macOS Terminal.app не поддерживает это.

Чтобы получить текст без OSC 52:

* Удерживайте клавишу собственного выбора вашего терминала, пока вы перетаскиваете, затем копируйте с помощью обычного сочетания клавиш вашего терминала, такого как `Cmd+C`. Клавиша — это `Fn` в Terminal.app и `Option` в iTerm2. [Keep native text selection](/docs/ru/fullscreen#keep-native-text-selection) перечисляет её для других терминалов.
* Установите [`CLAUDE_CODE_DISABLE_MOUSE=1`](/docs/ru/env-vars) на удалённой машине, чтобы ваш терминал обрабатывал выбор для всего сеанса.

<h3 id="search-and-discovery-issues">
  Проблемы с поиском и обнаружением
</h3>

Если инструмент Search, упоминания `@file`, пользовательские агенты или пользовательские skills не находят файлы, встроенный двоичный файл `ripgrep` может не работать на вашей системе. Установите пакет `ripgrep` вашей платформы и скажите Claude Code использовать его вместо этого:

<Tabs>
  <Tab title="macOS">
    ```bash theme={null}
    brew install ripgrep
    ```
  </Tab>

  <Tab title="Ubuntu/Debian">
    ```bash theme={null}
    sudo apt install ripgrep
    ```
  </Tab>

  <Tab title="Alpine">
    ```bash theme={null}
    apk add ripgrep
    ```

    `ripgrep` находится в репозитории community Alpine. Если `apk` сообщает, что пакет отсутствует, смотрите [Alpine Linux setup](/docs/ru/setup#alpine-linux-and-musl-based-distributions).
  </Tab>

  <Tab title="Arch">
    ```bash theme={null}
    pacman -S ripgrep
    ```
  </Tab>

  <Tab title="Windows">
    ```powershell theme={null}
    winget install BurntSushi.ripgrep.MSVC
    ```
  </Tab>
</Tabs>

Затем установите `USE_BUILTIN_RIPGREP` на `0`, либо в вашем [окружении](/docs/ru/env-vars), либо в блоке `env` вашего [`settings.json`](/docs/ru/settings-reference#all-settings):

```json theme={null}
{
  "env": {
    "USE_BUILTIN_RIPGREP": "0"
  }
}
```

Чтобы подтвердить, что переключение вступило в силу, запустите `claude doctor` в вашем терминале и проверьте, что строка Search показывает путь вашего системного ripgrep вместо `OK (bundled)`.

<h3 id="slow-or-incomplete-search-results-on-wsl">
  Медленные или неполные результаты поиска в WSL
</h3>

Штрафы производительности чтения диска при [работе с файловыми системами на WSL](https://learn.microsoft.com/en-us/windows/wsl/filesystems) могут привести к меньшему количеству совпадений, чем ожидается, при использовании Claude Code на WSL. Поиск всё ещё функционирует, но возвращает меньше результатов, чем на собственной файловой системе.

<Note>
  `claude doctor` показывает Search как OK в этом случае.
</Note>

**Решения:**

1. **Отправляйте более конкретные поиски**: уменьшите количество файлов, которые ищутся, указав директории или типы файлов: "Search for JWT validation logic in the auth-service package" или "Find use of md5 hash in JS files".

2. **Переместите проект на файловую систему Linux**: если возможно, убедитесь, что ваш проект находится на файловой системе Linux (`/home/`) вместо файловой системы Windows (`/mnt/c/`).

3. **Используйте нативный Windows вместо этого**: рассмотрите запуск Claude Code нативно на Windows вместо WSL для лучшей производительности файловой системы.

<h2 id="get-more-help">
  Получить дополнительную помощь
</h2>

Если вы испытываете проблемы, не охватываемые здесь:

1. Запустите `/doctor` для проверки установки и `/mcp` для проверки статуса MCP сервера
2. Используйте команду `/feedback` в Claude Code, чтобы сообщить о проблемах непосредственно в Anthropic
3. Проверьте [репозиторий GitHub](https://github.com/anthropics/claude-code) на известные проблемы
4. Спросите Claude напрямую о его возможностях и функциях. Claude имеет встроенный доступ к своей документации.

По вопросам учётной записи, выставления счетов или подписки обратитесь в службу поддержки Anthropic: войдите на [claude.ai](https://claude.ai) (пользователи Console: [platform.claude.com](https://platform.claude.com)), нажмите на ваши инициалы в нижнем левом углу и выберите **Получить помощь**. См. [Как получить поддержку](https://support.claude.com/en/articles/9015913-how-to-get-support) для полного процесса, включая информацию о том, кто может связаться с представителем поддержки на каждом плане.
