# Автоматизация работы с помощью рутин

> Переведите Claude Code на автопилот. Определите рутины, которые запускаются по расписанию, срабатывают при вызовах API или реагируют на события GitHub из облачной инфраструктуры.

<Note>
  Рутины находятся в исследовательском предпросмотре. Поведение, ограничения и поверхность API могут измениться.
</Note>

Рутина — это сохраненная конфигурация Claude Code: подсказка, один или несколько репозиториев и набор [коннекторов](/docs/ru/mcp), упакованные один раз и запускаемые автоматически. Рутины выполняются на облачной инфраструктуре, управляемой Anthropic, или в [самостоятельно размещаемой среде](/docs/ru/self-hosted-environments) вашей организации, когда они маршрутизируются туда, поэтому они продолжают работать, когда ваш ноутбук закрыт.

Каждая рутина может иметь один или несколько присоединенных триггеров:

* **Scheduled**: запуск по повторяющемуся расписанию, например ежечасно, ежедневно или еженедельно, или один раз в определенное будущее время
* **API**: срабатывание по требованию путем отправки HTTP POST на выделенную конечную точку рутины с токеном-носителем
* **GitHub**: автоматический запуск в ответ на события репозитория, такие как pull request или релизы

Одна рутина может объединять триггеры. Например, рутина проверки PR может запускаться ежедневно, срабатывать из скрипта развертывания и также реагировать на каждый новый PR.

Рутины доступны в планах Pro, Max, Team и Enterprise. Создавайте и управляйте ими на [claude.ai/code/routines](https://claude.ai/code/routines) или из CLI с помощью `/schedule`.

Владельцы Team и Enterprise могут отключить рутины для всех членов с помощью переключателя Routines на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code). При отключении существующие рутины перестают работать, и члены не могут создавать новые.

На этой странице рассматривается создание рутины, настройка каждого типа триггера, управление запусками и применение ограничений использования.

<h2 id="example-use-cases">
  Примеры использования
</h2>

Каждый пример сочетает тип триггера с типом работы, для которой подходят рутины: без присмотра, повторяемая и связанная с четким результатом.

**Обслуживание очереди задач.** Триггер расписания запускается каждый вечер в рабочие дни для вашего трекера проблем через коннектор. Рутина читает проблемы, открытые с момента последнего запуска, применяет метки, назначает владельцев на основе области кода, на которую ссылаются, и публикует сводку в Slack, чтобы команда начала день с упорядоченной очередью.

**Сортировка оповещений.** Ваш инструмент мониторинга вызывает конечную точку API рутины при превышении порога ошибок, передавая тело оповещения как `text`. Рутина извлекает трассировку стека, коррелирует ее с недавними коммитами в репозитории и открывает черновой pull request с предложенным исправлением и ссылкой обратно на оповещение. Дежурный инженер проверяет PR вместо того, чтобы начинать с пустого терминала.

**Пользовательская проверка кода.** Триггер GitHub запускается на `pull_request.opened`. Рутина применяет собственный контрольный список проверки вашей команды, оставляет встроенные комментарии по проблемам безопасности, производительности и стиля, а также добавляет сводный комментарий, чтобы человеческие рецензенты могли сосредоточиться на дизайне вместо механических проверок.

**Проверка развертывания.** Ваш конвейер CD вызывает конечную точку API рутины после каждого развертывания в production. Рутина запускает дымовые тесты для новой сборки, сканирует журналы ошибок на предмет регрессий и публикует решение (go или no-go) в канал релизов до закрытия окна развертывания.

**Дрейф документации.** Триггер расписания запускается еженедельно. Рутина сканирует объединенные PR с момента последнего запуска, отмечает документацию, которая ссылается на измененные API, и открывает PR обновления для репозитория документации, чтобы редактор мог его проверить.

**Портирование библиотеки.** Триггер GitHub запускается на `pull_request.closed`, отфильтрованный по объединенным PR в одном репозитории SDK. Рутина переносит изменение в параллельный SDK на другом языке и открывает соответствующий PR, сохраняя две библиотеки в синхронизации без необходимости человека переимплементировать каждое изменение.

<h2 id="create-a-routine">
  Создание рутины
</h2>

Создайте рутину из веб-версии на [claude.ai/code/routines](https://claude.ai/code/routines), из приложения Desktop или из CLI. Все три интерфейса записывают в один облачный аккаунт, поэтому рутина, которую вы создаете в одном, сразу же появляется в других. В приложении Desktop на вкладке **Code** нажмите **Routines** на боковой панели или в меню **More** боковой панели, затем **New routine**, и выберите **Cloud**; выбор **Local** вместо этого создает [локальную запланированную задачу Desktop](/docs/ru/desktop-scheduled-tasks), которая запускается на вашей машине, а не в облаке.

Форма создания настраивает подсказку рутины, репозитории, окружение, коннекторы и триггеры.

Рутины работают автономно как полные облачные сеансы Claude Code: нет выбора режима разрешений, и сеанс запускает команды shell, использует [skills](/docs/ru/skills), зафиксированные в клонированном репозитории, и вызывает любые коннекторы, которые вы включите, все без остановки для одобрения, кроме некоторых действий с [artifact](/docs/ru/artifacts).

То, что может достичь рутина, определяется выбранными вами репозиториями, [окружением](/docs/ru/cloud-environments) сетевого доступа и переменных, а также включенными коннекторами. Ограничьте каждый из них тем, что рутине действительно нужно.

Когда расписание рутины или **Run now** запускает запуск, Claude переиздает существующий artifact без запроса только когда все это верно:

* Вы можете редактировать artifact и он принадлежит вашей собственной организации
* Artifact не является общедоступным и не совместно используется с конкретными людьми или вашей организацией с последней версией, выбранной как версия, которую видят зрители
* Переиздание содержит только страницу, без вспомогательных файлов или чего-либо еще добавленного, и не заставляет перезаписать более новую версию
* Страница не содержит разрешение, которое выходит за пределы страницы, такое как [вызовы коннектора](/docs/ru/artifacts#pull-live-data-with-mcp-connectors)

Во всех остальных случаях, включая переиздание нового artifact, Claude сначала спрашивает. Когда работа рутины состоит в том, чтобы держать страницу в актуальном состоянии, дайте ей artifact, который вы уже опубликовали.

Рутины принадлежат вашему индивидуальному аккаунту claude.ai. Они не совместно используются с товарищами по команде и учитываются в дневном лимите запусков вашего аккаунта. Все, что рутина делает через вашу подключенную идентификацию GitHub или коннекторы, отображается как вы: коммиты и pull request несут вашего пользователя GitHub, а сообщения Slack, задачи Linear или другие действия коннектора используют ваши связанные аккаунты для этих сервисов.

<h3 id="create-from-the-web">
  Создание из веб-версии
</h3>

<Steps>
  <Step title="Откройте форму создания">
    Посетите [claude.ai/code/routines](https://claude.ai/code/routines) и нажмите **New routine**.
  </Step>

  <Step title="Назовите рутину и напишите подсказку">
    Дайте рутине описательное имя и напишите подсказку, которую Claude запускает каждый раз. Подсказка — это самая важная часть: рутина работает автономно, поэтому подсказка должна быть самодостаточной и явно указывать, что делать и как выглядит успех.

    Когда триггер срабатывает, сеанс получает сохраненную подсказку рутины в качестве назначенной задачи и выполняет ее, вместо того чтобы рассматривать ее как ненадежный контент, поступивший в середине разговора. Триггер только подтверждает, что подсказка была сохранена заранее авторизованным сеансом на вашем аккаунте, поэтому сработавшая подсказка не является живым вводом пользователя и не может служить одобрением или согласием на действия во время запуска. Контент, который сеанс получает во время запуска, сохраняет свою обычную обработку. До версии 2.1.213 сеанс получал ту же подсказку в виде ненадежного фонового уведомления и мог отказаться действовать в соответствии с ней.

    Ввод подсказки включает селектор модели. Claude использует выбранную модель при каждом запуске.
  </Step>

  <Step title="Выберите репозитории">
    Добавьте один или несколько репозиториев GitHub для работы Claude. Каждый репозиторий клонируется в начале запуска, начиная с ветви по умолчанию. Claude создает ветви с префиксом `claude/` для своих изменений.
  </Step>

  <Step title="Выберите окружение">
    Выберите [облачное окружение](/docs/ru/cloud-environments) для рутины. Окружения контролируют, к чему имеет доступ облачный сеанс:

    * **Network access**: установите уровень доступа в Интернет, доступный во время каждого запуска
    * **Environment variables**: предоставьте значения, которые может использовать Claude во время каждого запуска. Они [видны всем, кто использует окружение](/docs/ru/cloud-environments#what-carries-over-from-your-setup), поэтому в планах Pro и Max сохраняйте ключи для API, которые Claude вызывает во время запуска, как [API credentials](/docs/ru/cloud-environments#add-api-credentials) вместо этого. Этот раздел также содержит список запросов, которые никогда не получают учетные данные
    * **Setup script**: установите зависимости и инструменты, которые нужны рутине. Результат [кэшируется](/docs/ru/cloud-environments#environment-caching), поэтому скрипт не переустанавливается при каждом сеансе

    Предоставляется окружение **Default** с доступом в сеть **Trusted**, который позволяет только [набор по умолчанию](/docs/ru/cloud-environments#default-allowed-domains) реестров пакетов, API облачных провайдеров, реестров контейнеров и распространенных доменов разработки через сеть сеанса. Коннекторы, которые вы добавляете к рутине, достигают своих сервисов через серверы Anthropic, поэтому им не нужны изменения списка разрешений. Если вашей рутине нужно достичь ваших собственных сервисов напрямую или домена вне этого списка, отредактируйте [сетевой доступ](/docs/ru/cloud-environments#network-access) окружения перед запуском. Чтобы использовать отдельное окружение, [создайте его](/docs/ru/cloud-environments#configure-your-environment) сначала.
  </Step>

  <Step title="Выберите триггер">
    В разделе **Select a trigger** выберите, как запускается рутина. Вы можете выбрать один тип триггера или объединить несколько.

    <Tabs>
      <Tab title="Schedule">
        Выберите предустановленную частоту для повторяющегося запуска или запланируйте один одноразовый запуск в определенный момент времени. Смотрите [Add a schedule trigger](#add-a-schedule-trigger) для обработки часовых поясов, разброса, пользовательских интервалов cron и одноразовых запусков.
      </Tab>

      <Tab title="GitHub event">
        Выберите репозиторий, событие для реагирования и дополнительные фильтры. Смотрите [Add a GitHub trigger](#add-a-github-trigger) для полного списка поддерживаемых событий и полей фильтра.
      </Tab>

      <Tab title="API">
        Выберите **API** здесь, затем сохраните рутину. URL и токен генерируются после сохранения рутины, так как они зависят от ID рутины. Смотрите [Add an API trigger](#add-an-api-trigger) для копирования URL и генерации токена.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Проверьте коннекторы">
    В разделе **Connectors** в нижней части формы все ваши подключенные [MCP коннекторы](/docs/ru/mcp) включены по умолчанию. Удалите все, которые рутине не нужны: Claude может использовать каждый инструмент из включенного коннектора, включая операции записи, без запроса разрешения во время запуска.
  </Step>

  <Step title="Создайте рутину">
    Нажмите **Create**. Рутина появляется в списке и запускается в следующий раз, когда один из ее триггеров совпадает. Чтобы начать запуск немедленно, нажмите **Run now** на странице деталей рутины.

    Каждый запуск создает новый сеанс рядом с вашими другими сеансами, где вы можете увидеть, что сделал Claude, проверить изменения и создать pull request.
  </Step>
</Steps>

<h3 id="create-from-the-cli">
  Создание из CLI
</h3>

Запустите `/schedule` в любом сеансе, чтобы создать запланированную рутину в диалоговом режиме. Вы также можете передать описание напрямую, например для повторяющейся рутины как `/schedule daily PR review at 9am` или одноразовой как `/schedule clean up feature flag in one week`. Claude проходит через ту же информацию, которую собирает веб-форма, затем сохраняет рутину в ваш аккаунт. Команда также доступна под псевдонимом `/routines`.

Успешный старт выглядит как диалог: Claude задает уточняющие вопросы о расписании, репозиториях и подсказке перед сохранением. Если Claude вместо этого ответит, что вам нужно пройти аутентификацию или что он не может подключиться к вашему удаленному аккаунту claude.ai, рутина не была создана; смотрите [Troubleshooting](#troubleshooting).

`/schedule` в CLI создает запланированные рутины. Чтобы добавить триггер API, отредактируйте рутину в веб-версии на [claude.ai/code/routines](https://claude.ai/code/routines). Вы можете добавить [GitHub trigger](#add-a-github-trigger) из веб-версии или из CLI. Путь CLI требует Claude Code версии 2.1.225 или позже.

Рутина без триггера расписания, такая как запускаемая только вызовами API или событиями GitHub, не имеет времени следующего запуска, и CLI не показывает его, когда Claude сохраняет или обновляет рутину. До версии 2.1.211 CLI сообщал время следующего запуска в году 1 для этих рутин.

<h2 id="configure-triggers">
  Настройка триггеров
</h2>

Рутина запускается, когда один из ее триггеров совпадает. Вы можете присоединить любую комбинацию триггеров расписания, API и GitHub к одной рутине и добавлять или удалять их в любое время из раздела **Select a trigger** формы редактирования рутины.

<h3 id="add-a-schedule-trigger">
  Добавление триггера расписания
</h3>

Триггер расписания запускает рутину по повторяющемуся расписанию или один раз в определенное будущее время. Выберите предустановленную частоту в разделе **Select a trigger**: ежечасно, ежедневно, по рабочим дням или еженедельно. Времена вводятся в вашем локальном часовом поясе и преобразуются автоматически, поэтому рутина запускается в это время независимо от того, где находится облачная инфраструктура.

Запуски могут начаться на несколько минут позже запланированного времени из-за разброса. Смещение согласовано для каждой рутины.

Для пользовательского интервала, такого как каждые два часа или первое число каждого месяца, выберите ближайшую предустановку в форме, затем запустите `/schedule update` в CLI, чтобы установить конкретное выражение cron. Минимальный интервал — один час; выражения, которые запускаются чаще, отклоняются.

<h4 id="schedule-a-one-off-run">
  Планирование одноразового запуска
</h4>

Одноразовое расписание запускает рутину один раз в определенный момент времени. Используйте его, чтобы напомнить себе позже на неделе, открыть PR очистки после завершения развертывания или запустить последующую задачу, когда приходит изменение вышестоящего уровня. После запуска рутины она автоматически отключается, и веб-интерфейс отмечает ее как **Ran**. Чтобы запустить ее снова, отредактируйте рутину и установите новое одноразовое время.

Создайте одноразовый запуск из CLI, описав время на естественном языке. Claude разрешает фразу относительно текущего времени и подтверждает абсолютный момент времени перед сохранением.

```text theme={null}
/schedule tomorrow at 9am, summarize yesterday's merged PRs
```

```text theme={null}
/schedule in 2 weeks, open a cleanup PR that removes the feature flag
```

То же преобразование локального времени в UTC, что и для повторяющихся расписаний, применяется к одноразовым меткам времени.

Одноразовые запуски не учитываются в дневном лимите запусков рутины. Смотрите [Usage and limits](#usage-and-limits) для подробностей.

<h3 id="add-an-api-trigger">
  Добавление триггера API
</h3>

Триггер API дает рутине выделенную конечную точку HTTP. POST на конечную точку с токеном-носителем рутины запускает новый сеанс и возвращает URL сеанса. Используйте это для подключения Claude Code к системам оповещений, конвейерам развертывания, внутренним инструментам или везде, где вы можете сделать аутентифицированный HTTP запрос.

Триггеры API добавляются к существующей рутине из веб-версии. CLI в настоящее время не может создавать или отзывать токены.

<Steps>
  <Step title="Откройте рутину для редактирования">
    Перейдите на [claude.ai/code/routines](https://claude.ai/code/routines), нажмите рутину, которую вы хотите запустить через API, затем откройте меню рядом с названием рутины и выберите **Edit**.
  </Step>

  <Step title="Добавьте триггер API">
    Прокрутите до раздела **Select a trigger** ниже подсказки, нажмите **Add another trigger** и выберите **API**.
  </Step>

  <Step title="Скопируйте URL и сгенерируйте токен">
    Модальное окно показывает URL для этой рутины вместе с примером команды curl. Скопируйте URL, затем нажмите **Generate token** и сразу же скопируйте токен. Токен показывается один раз и не может быть получен позже, поэтому сохраните его в безопасном месте, таком как хранилище секретов вашего инструмента оповещений.
  </Step>

  <Step title="Вызовите конечную точку">
    Отправьте токен в заголовке `Authorization: Bearer` при POST на URL. Раздел [Trigger a routine](#trigger-a-routine) ниже показывает полный пример.
  </Step>
</Steps>

Каждая рутина имеет свой токен, ограниченный только запуском этой рутины. Чтобы повернуть или отозвать его, вернитесь в то же модальное окно и нажмите **Regenerate** или **Revoke**.

<h4 id="trigger-a-routine">
  Запуск рутины
</h4>

Отправьте POST запрос на конечную точку `/fire` с токеном-носителем в заголовке `Authorization`. Тело запроса принимает дополнительное поле `text` для контекста, специфичного для запуска, такого как тело оповещения или неудачный журнал, переданное рутине вместе с ее сохраненной подсказкой. Значение — это свободный текст и не анализируется: если вы отправляете JSON или другую структурированную полезную нагрузку, рутина получает ее как буквальную строку.

Значение `text` не достигает рутину как простое сообщение. Оно приходит завернутым в блок `<routine-fire-payload>`, который помечает его как ненадежные данные и говорит Claude не следовать инструкциям внутри него, если только собственная подсказка рутины не говорит об этом. То же самое обертывание применяется к тексту, предоставленному с помощью **Run now** в веб-интерфейсе.

Это означает, что сохраненная подсказка рутины должна явно согласиться действовать на текст fire: напишите подсказку, чтобы явно ссылаться на полезную нагрузку, например "Investigate the alert described in the routine-fire-payload block", или рутина будет рассматривать текст как инертный контекст. Любой, кто держит токен-носитель, может отправить `text`, поэтому обертка делает текст fire из утекшего токена помеченным как ненадежные данные, а не как прямые инструкции вашей рутине.

Пример ниже запускает рутину из shell. ID рутины и токен, показанные здесь, являются заполнителями: замените их на URL и токен, которые вы скопировали при [добавлении триггера API](#add-an-api-trigger), или запрос завершится с ошибкой аутентификации `401`:

```bash theme={null}
curl -X POST https://api.anthropic.com/v1/claude_code/routines/trig_01ABCDEFGHJKLMNOPQRSTUVW/fire \
  -H "Authorization: Bearer sk-ant-oat01-xxxxx" \
  -H "anthropic-beta: experimental-cc-routine-2026-04-01" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"text": "Sentry alert SEN-4521 fired in prod. Stack trace attached."}'
```

Успешный запрос возвращает тело JSON с новым ID сеанса и URL:

```json theme={null}
{
  "type": "routine_fire",
  "claude_code_session_id": "session_01HJKLMNOPQRSTUVWXYZ",
  "claude_code_session_url": "https://claude.ai/code/session_01HJKLMNOPQRSTUVWXYZ"
}
```

Откройте URL сеанса в браузере, чтобы наблюдать запуск в реальном времени, проверить изменения или продолжить разговор вручную.

<Warning>
  Конечная точка `/fire` поставляется под заголовком бета-версии `experimental-cc-routine-2026-04-01`. Формы запроса и ответа, ограничения скорости и семантика токенов могут измениться, пока функция находится в исследовательском предпросмотре. Критические изменения поставляются за новыми версиями заголовка бета-версии с датой, и две самые последние предыдущие версии заголовка продолжают работать, чтобы у вызывающих было время для миграции.
</Warning>

  Справочник API
</h4>

Для полного справочника API, включая все ответы об ошибках, правила валидации и ограничения полей, смотрите [Trigger a routine via API](https://platform.claude.com/docs/en/api/claude-code/routines-fire) в документации Claude Platform.

<h3 id="add-a-github-trigger">
  Добавление триггера GitHub
</h3>

Триггер GitHub запускает новый сеанс автоматически, когда совпадающее событие происходит в подключенном репозитории. Claude Code не переиспользует сеансы между событиями, поэтому два обновления PR создают два независимых сеанса.

<Note>
  Во время исследовательского предпросмотра события вебхука GitHub подлежат ограничениям в час для каждой рутины и для каждого аккаунта. События сверх лимита отбрасываются до сброса окна. Смотрите ваши текущие ограничения на [claude.ai/code/routines](https://claude.ai/code/routines).
</Note>

Приложение Claude GitHub должно быть установлено в репозитории, на который вы хотите подписаться, независимо от того, какую поверхность вы используете для настройки триггера.

* Настраивайте триггеры GitHub из веб-интерфейса, который предложит вам установить приложение, если оно отсутствует. Следуйте шагам ниже, чтобы настроить его из веб-версии.
* Из CLI сначала установите приложение со [страницы GitHub App](https://github.com/apps/claude), затем попросите Claude присоединить триггер GitHub к существующей рутине, например `/schedule add a GitHub trigger to my nightly review for pull requests opened in acme/webapp`. Путь CLI требует Claude Code v2.1.225 или позже. Когда Claude добавляет триггер, он отвечает ссылкой на рутину, которую запускает триггер.

<Steps>
  <Step title="Откройте рутину для редактирования">
    Перейдите на [claude.ai/code/routines](https://claude.ai/code/routines), нажмите рутину, затем откройте меню рядом с названием рутины и выберите **Edit**.
  </Step>

  <Step title="Добавьте триггер события GitHub">
    Прокрутите до раздела **Select a trigger**, нажмите **Add another trigger** и выберите **GitHub event**.

    <Note>
      Запуск `/web-setup` в CLI предоставляет доступ к репозиторию для клонирования, но не устанавливает приложение Claude GitHub и не включает доставку вебхука.
    </Note>
  </Step>

  <Step title="Настройте триггер">
    Выберите репозиторий, выберите событие из списка [supported events](#supported-events) и дополнительно добавьте фильтры. Сохраните триггер.
  </Step>
</Steps>

<h4 id="supported-events">
  Поддерживаемые события
</h4>

Триггеры GitHub могут подписаться на одну из следующих категорий событий. В каждой категории вы можете выбрать конкретное действие, такое как `pull_request.opened`, или реагировать на все действия в категории.

| Событие      | Срабатывает когда                                                               |
| :----------- | :------------------------------------------------------------------------------ |
| Pull request | PR открыт, закрыт, назначен, помечен, синхронизирован или иным образом обновлен |
| Release      | Релиз создан, опубликован, отредактирован или удален                            |

<h4 id="filter-pull-requests">
  Фильтрация pull request
</h4>

Используйте фильтры, чтобы сузить, какие pull request запускают новый сеанс. Все условия фильтра должны совпадать, чтобы рутина сработала. Доступные поля фильтра:

| Фильтр      | Совпадает                            |
| :---------- | :----------------------------------- |
| Author      | Имя пользователя GitHub автора PR    |
| Title       | Текст заголовка PR                   |
| Body        | Текст описания PR                    |
| Base branch | Ветвь, на которую нацелен PR         |
| Head branch | Ветвь, из которой исходит PR         |
| Labels      | Метки, применяемые к PR              |
| Is draft    | Находится ли PR в черновом состоянии |
| Is merged   | Был ли PR объединен                  |

Каждый фильтр сочетает поле с оператором: equals, contains, starts with, is one of, is not one of или matches regex.

Оператор `matches regex` проверяет все значение поля, а не подстроку в нем. Чтобы совпадать с любым заголовком, содержащим `hotfix`, напишите `.*hotfix.*`. Без окружающих `.*`, фильтр совпадает только с заголовком, который точно `hotfix` без ничего до или после. Для буквального совпадения подстроки без синтаксиса regex используйте оператор `contains` вместо этого.

Несколько примеров комбинаций фильтров:

* **Auth module review**: base branch `main`, head branch contains `auth-provider`. Отправляет любой PR, который касается аутентификации, сосредоточенному рецензенту.
* **Ready-for-review only**: is draft is `false`. Пропускает черновики, поэтому рутина запускается только, когда PR готов к проверке.
* **Label-gated backport**: labels include `needs-backport`. Запускает рутину портирования в другую ветвь только, когда мейнтейнер помечает PR.

<h2 id="manage-routines">
  Управление рутинами
</h2>

Нажмите рутину в списке, чтобы открыть ее страницу деталей. Страница деталей показывает репозитории рутины, коннекторы, подсказку, расписание, токены API, триггеры GitHub и список прошлых запусков.

<h3 id="view-and-interact-with-runs">
  Просмотр и взаимодействие с запусками
</h3>

Нажмите любой запуск, чтобы открыть его как полный сеанс. Оттуда вы можете увидеть, что сделал Claude, проверить изменения, создать pull request или продолжить разговор. Каждый сеанс запуска работает как любой другой сеанс: используйте меню раскрывающегося списка рядом с заголовком сеанса, чтобы переименовать, архивировать или удалить его.

<Note>
  Зеленый статус в списке запусков означает, что сеанс запустился и завершился без ошибки инфраструктуры. Это не означает, что задача в вашей подсказке выполнена успешно. Откройте запуск, чтобы прочитать стенограмму и подтвердить, что Claude действительно сделал. Заблокированные сетевые запросы, отсутствующие инструменты коннектора и сбои на уровне задачи отображаются там, а не в индикаторе статуса.
</Note>

<h3 id="edit-and-control-routines">
  Редактирование и управление рутинами
</h3>

Со страницы деталей рутины вы можете:

* Нажать **Run now**, чтобы начать запуск немедленно без ожидания следующего запланированного времени. Вы можете дополнительно предоставить текст, специфичный для запуска, который достигает рутину так же, как поле `text` триггера API.
* Использовать переключатель в верхней части страницы, чтобы приостановить или возобновить расписание. Приостановленные рутины сохраняют свою конфигурацию, но не запускаются, пока вы их не переактивируете.
* Открыть меню рядом с именем рутины и выбрать **Edit**, чтобы изменить имя, подсказку, репозитории, окружение, коннекторы или любые триггеры рутины. Раздел **Select a trigger** — это место, где вы добавляете или удаляете расписания, токены API и триггеры событий GitHub.
* Открыть то же меню и выбрать **Delete**, чтобы удалить рутину.

<h3 id="manage-routines-from-the-cli">
  Управление рутинами из CLI
</h3>

CLI поддерживает управление существующими рутинами. Запустите `/schedule list`, чтобы увидеть все рутины, `/schedule update`, чтобы изменить одну, или `/schedule run`, чтобы запустить ее немедленно.

Вы также можете спросить об истории запусков рутины, например `/schedule why did my nightly review do nothing this morning?`. Claude выводит список недавних запусков рутины с их статусом и ссылкой на [открытие каждого запуска в веб-интерфейсе](#view-and-interact-with-runs), и читает журнал запуска, чтобы объяснить, что произошло, включая ошибки инструментов, отказы в разрешении и окончательный результат. Требуется Claude Code v2.1.227 или позже.

<h3 id="repositories-and-branch-permissions">
  Репозитории и разрешения ветвей
</h3>

Рутинам нужен доступ GitHub для клонирования репозиториев. Когда вы создаете рутину из CLI с `/schedule`, Claude проверяет, имеет ли ваш аккаунт доступ GitHub для репозитория, из которого вы его запустили, и, если это не так, добавляет примечание настройки, указывающее, как предоставить доступ. Смотрите [GitHub authentication options](/docs/ru/claude-code-on-the-web#github-authentication-options) для двух способов предоставления доступа.

Если ваше соединение GitHub отсутствует или истекло, когда запуск должен произойти, рутина пропускает запуски до тех пор, пока вы не переподключитесь, в течение до 72 часов. Переподключитесь GitHub в течение этого окна, и рутина возобновится автоматически. После 72 часов без соединения рутина отключается, и вы включаете ее снова после переподключения GitHub.

Каждый репозиторий, который вы добавляете, клонируется при каждом запуске. Claude начинает с ветви по умолчанию репозитория, если ваша подсказка не указывает иное.

Claude отправляет свою работу в ветви с префиксом `claude/`, которые всегда принимаются. Когда ваша подсказка направляет Claude на отправку в другую ветвь, Claude Code сначала проверяет отправку и отклоняет ее, если выполняется любое из следующих условий:

* Ветвь защищена на GitHub
* У кого-то еще есть открытый pull request из этой ветви
* Ветвь содержит коммиты, созданные кем-то другим, чем вы

<h3 id="connectors">
  Коннекторы
</h3>

Рутины могут использовать ваши подключенные MCP коннекторы для чтения и записи во внешние сервисы во время каждого запуска. Например, рутина, которая сортирует запросы поддержки, может читать из канала Slack и создавать проблемы в Linear.

Коннекторы — это [интеграции claude.ai](/docs/ru/mcp#use-mcp-servers-from-claude-ai) на вашем аккаунте. MCP серверы, которые вы добавили локально в CLI с помощью `claude mcp add`, хранятся на вашей машине, а не на вашем аккаунте claude.ai, поэтому они не отображаются в списке коннекторов. Чтобы использовать один из этих серверов в рутине, добавьте его как коннектор на [claude.ai/customize/connectors](https://claude.ai/customize/connectors). Для рутины с одним репозиторием вы можете вместо этого объявить его в committed [`.mcp.json`](/docs/ru/mcp#project-scope), чтобы он был частью клонированного репозитория.

Когда вы создаете рутину, все ваши текущие подключенные коннекторы включены по умолчанию. Удалите все, которые не нужны, чтобы ограничить, к каким инструментам Claude имеет доступ во время запуска. Вы также можете добавлять коннекторы непосредственно из формы рутины.

Чтобы управлять или добавлять коннекторы вне формы рутины, посетите [claude.ai/customize/connectors](https://claude.ai/customize/connectors) или используйте `/schedule update` в CLI.

<h3 id="environments-and-network-access">
  Окружения и сетевой доступ
</h3>

Каждая рутина использует [облачное окружение](/docs/ru/cloud-environments), которое контролирует сетевой доступ, переменные окружения и скрипты настройки. Рутина наследует политику сетевого доступа окружения при каждом запуске.

Окружение **Default** использует **Trusted** сетевой доступ, который позволяет только [список разрешений по умолчанию](/docs/ru/cloud-environments#default-allowed-domains) через сеть сеанса. Запросы на этом пути к хостам вне списка разрешений завершаются с ошибкой `403` и `x-deny-reason: host_not_allowed`. Трафик MCP коннектора маршрутизируется через серверы Anthropic, а не на этом пути, поэтому коннекторы, которые вы добавляете в рутину, работают без добавления их хостов в **Allowed domains**. Удалите все коннекторы, которые вам не нужны, в разделе [Коннекторы](#connectors).

Чтобы разрешить дополнительные домены на одном из ваших собственных окружений, выполните следующие шаги. [Организационное общее окружение](/docs/ru/cloud-environments#organization-shared-environments) открывается в режиме только для чтения здесь, поэтому владелец изменяет его сетевой доступ со страницы **Cloud environments** в [параметрах администратора](https://claude.ai/admin-settings) вместо этого.

<Steps>
  <Step title="Откройте рутину для редактирования">
    На странице деталей рутины откройте меню рядом с именем рутины и выберите **Edit**.
  </Step>

  <Step title="Откройте селектор окружения">
    Ниже поля **Instructions** выберите значок облака, показывающий имя вашего окружения, например **Default**.
  </Step>

  <Step title="Откройте параметры окружения">
    Наведите указатель на окружение в списке и нажмите значок параметров, который появляется справа.
  </Step>

  <Step title="Измените уровень сетевого доступа">
    В диалоговом окне **Update cloud environment** измените **Network access** на **Custom** и введите ваши домены в **Allowed domains**. Установите флажок **Also include default list of common package managers**, чтобы сохранить [список разрешений по умолчанию](/docs/ru/cloud-environments#default-allowed-domains) вместе с вашими пользовательскими доменами. Выберите **Full** для неограниченного доступа.
  </Step>

  <Step title="Сохранить">
    Нажмите **Save changes**. Новая политика применяется со следующего запуска.
  </Step>
</Steps>

Смотрите [Network access](/docs/ru/cloud-environments#network-access) для подробной информации об уровнях доступа и списке разрешений по умолчанию.

<h2 id="usage-and-limits">
  Использование и ограничения
</h2>

Рутины снижают использование подписки так же, как интерактивные сеансы. В дополнение к стандартным ограничениям подписки, рутины имеют дневной лимит на количество запусков, которые могут начаться на аккаунт. Смотрите ваше текущее потребление и оставшиеся дневные запуски рутин на [claude.ai/code/routines](https://claude.ai/code/routines) или [claude.ai/settings/usage](https://claude.ai/settings/usage).

Когда рутина достигает дневного лимита или лимита использования вашей подписки, организации с включенными кредитами использования могут продолжать запускать рутины на измеренный перерасход. Без кредитов использования дополнительные запуски отклоняются до сброса окна. Включите кредиты использования на [claude.ai/settings/usage](https://claude.ai/settings/usage). На планах Team и Enterprise администратор включает их для организации на [claude.ai/admin-settings/usage](https://claude.ai/admin-settings/usage).

Разовые запуски не учитываются в дневном лимите рутин. Они снижают ваше обычное использование подписки как любой другой сеанс.

Пока ваша подписка приостановлена, ваши рутины ставятся на паузу и не запускаются. Как только ваша подписка снова активна, включите их обратно.

<h2 id="troubleshooting">
  Устранение неполадок
</h2>

<h3 id="schedule-returns-unknown-command">
  `/schedule` returns "Unknown command"
</h3>

CLI скрывает `/schedule`, когда одно из его требований не выполнено: меню команд показывает `No commands match "/schedule"` во время ввода. Отправка возвращает `Unknown command: /schedule`, за исключением случаев ниже, которые указывают на другой ответ.

Причина обычно одна из следующих:

* Вы аутентифицированы с помощью Console API key, [профиля Anthropic или учетных данных федерации](/docs/ru/authentication#anthropic-profiles-and-federation-credentials), или облачного провайдера, такого как Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry. `/schedule` требует входа с подпиской claude.ai. С Console API key или профилем и включенной загрузкой флагов функций отправка `/schedule` вместо этого показывает `/schedule is available with Claude for Enterprise — ask your admin about migrating from API-key access`. С входом облачного провайдера вы все еще видите `Unknown command: /schedule`. Если `ANTHROPIC_API_KEY` или `ANTHROPIC_AUTH_TOKEN` установлены в вашей оболочке, или `apiKeyHelper` установлен в `settings.json`, удалите их сначала, так как они имеют приоритет над входом claude.ai. Профиль или учетные данные федерации также имеют приоритет, поэтому отключите их тоже
* Вы полностью вышли из системы, без API key или других учетных данных. С включенной загрузкой флагов функций отправка `/schedule` показывает `/schedule requires a claude.ai subscription. Run /login to sign in with your claude.ai account.` До версии v2.1.268 сеанс без входа показывал то же сообщение Claude for Enterprise, что и Console API key
* Вы находитесь в облачном сеансе, где отправка `/schedule` отвечает, что команда недоступна в этой среде. Управляйте рутинами из [веб-интерфейса](https://claude.ai/code/routines) вместо этого
* Политика вашей организации отключает [облачные сеансы](/docs/ru/claude-code-on-the-web), на которых работают рутины. В этом случае отправка `/schedule` отвечает [`Cloud sessions are disabled by your organization's policy`](/docs/ru/errors#cloud-sessions-are-disabled-by-your-organizations-policy) вместо этого. До версии v2.1.268 она возвращала `Unknown command: /schedule`
* Владелец [отключил рутины](#routines-are-disabled-by-your-organizations-policy) для вашей организации Team или Enterprise. До версии v2.1.227 команда все еще появлялась в этом случае, и claude.ai отклонял рутину, когда Claude пытался создать или запустить ее

Если политика вашей организации не отключает рутины или облачные сеансы, вы можете создавать и управлять рутинами на [claude.ai/code/routines](https://claude.ai/code/routines) независимо от того, как настроен ваш CLI.

<h3 id="routines-are-disabled-by-your-organizations-policy">
  "Routines are disabled by your organization's policy"
</h3>

Владелец в вашей организации Team или Enterprise, вероятно, отключил переключатель **Routines** на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code). В Claude Code версии 2.1.227 или позже этот же переключатель также скрывает `/schedule` в CLI. Это серверное организационное параметр, поэтому его нельзя переопределить из вашей локальной конфигурации. Попросите владельца включить рутины для вашей организации.
