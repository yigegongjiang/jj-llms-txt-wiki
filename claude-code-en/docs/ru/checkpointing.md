# Checkpointing

> Отслеживайте, перематывайте и суммируйте правки и беседу Claude для управления состоянием сеанса.

Claude Code автоматически отслеживает правки файлов Claude по мере работы, позволяя вам быстро отменять изменения и возвращаться к предыдущим состояниям, если что-то пойдёт не так.

<h2 id="how-checkpoints-work">
  Как работает checkpointing
</h2>

По мере работы с Claude, checkpointing автоматически фиксирует состояние вашего кода перед каждым запросом, который вы отправляете и который начинает новый ход.

<h3 id="automatic-tracking">
  Автоматическое отслеживание
</h3>

Claude Code отслеживает все изменения, внесённые его инструментами редактирования файлов:

* Каждый запрос, который вы отправляете и который начинает новый ход, создаёт новый checkpoint
* Claude Code хранит снимки файлов для 100 самых последних checkpoints в сеансе. Удаление старого checkpoint удаляет файлы снимков, на которые не ссылается ни один оставшийся checkpoint, за исключением первого снимка каждого файла, который расширение VS Code использует в качестве базовой линии для различий сеанса.
* Claude Code сохраняет checkpoints с беседой, поэтому вы всё ещё можете запустить `/rewind` после возобновления сеанса
* Claude Code удаляет снимки файлов сеанса в [процессе очистки](/docs/ru/claude-directory#cleaned-up-automatically), по умолчанию примерно через 30 дней после последнего сохранения сеанса. Перемотка к checkpoint, снимки которого удалены, может завершиться ошибкой [`No files were restored`](/docs/ru/errors#no-files-were-restored). Чтобы сохранять снимки дольше, установите [`cleanupPeriodDays`](/docs/ru/settings-reference#cleanupperioddays).

<h3 id="rewind-and-summarize">
  Перемотка и суммирование
</h3>

Запустите `/rewind` или нажмите `Esc` дважды, когда поле ввода запроса пусто, чтобы открыть меню перемотки.

<Note>
  Если поле ввода запроса содержит текст, двойное нажатие `Esc` очищает его вместо открытия меню. Очищенный текст сохраняется в историю ввода, поэтому нажмите `Up`, чтобы вспомнить его после завершения работы в меню перемотки.
</Note>

Меню перемотки отображает каждый запрос, который вы отправили во время сеанса, за исключением [сообщений, которые присоединились к выполняющемуся ходу](#messages-sent-mid-turn-not-checkpointed). Выберите точку, на которой вы хотите действовать, затем выберите действие:

* **Восстановить код и беседу**: вернуть как код, так и беседу в эту точку
* **Восстановить беседу**: перемотать к этому сообщению, сохраняя текущий код
* **Восстановить код**: отменить изменения файлов, сохраняя беседу
* **Суммировать отсюда**: сжать беседу с этой точки вперёд в краткое резюме, освобождая место в context window
* **Суммировать до этого момента**: сжать беседу перед этой точкой в краткое резюме, сохраняя более поздние сообщения нетронутыми
* **Отмена**: вернуться к списку сообщений без внесения изменений

Два варианта восстановления кода появляются только тогда, когда выбранный checkpoint имеет отслеживаемые изменения файлов для отката. Если после этой точки не было захвачено никаких редактирований файлов, меню предлагает только **Восстановить беседу**, варианты суммирования и **Отмена**.

После восстановления беседы или выбора "Суммировать отсюда" исходный запрос из выбранного сообщения восстанавливается в поле ввода, чтобы вы могли переотправить или отредактировать его.

Выбор "Суммировать до этого момента" оставляет вас в конце беседы с пустым полем ввода. При любом варианте суммирования в беседе появляется маркер **Summarized conversation** в месте, где были сжаты сообщения.

<h4 id="rewind-past-a-cleared-conversation">
  Перемотка прошлой очищенной беседы
</h4>

Если вы запустили `/clear` ранее в том же процессе Claude Code, меню перемотки показывает дополнительную запись в верхней части списка с меткой `/resume <session-id> (previous session)`. Выберите её, чтобы возобновить беседу, которая была активна до запуска `/clear`. Запись доступна до тех пор, пока вы не выйдете из Claude Code или не возобновите другой сеанс.

<h4 id="guide-a-summary">
  Руководство для суммирования
</h4>

Суммирование не изменяет файлы на диске, и исходные сообщения остаются в стенограмме сеанса, поэтому Claude всё ещё может ссылаться на детали. Чтобы направить внимание суммирования, выделите опцию **Summarize** клавишами со стрелками и введите инструкции там, где в строке написано **add context (optional)**, затем нажмите `Enter`. Выбор опции с её номером выполняет суммирование немедленно без инструкций.

<Note>
  Суммирование держит вас в одном сеансе и сжимает контекст, как целевой `/compact`. Чтобы ответвиться и попробовать другой подход, сохраняя исходный сеанс нетронутым, используйте вместо этого [`/branch`](/docs/ru/sessions#branch-a-session) или `claude --continue --fork-session`.
</Note>

<h2 id="common-use-cases">
  Типичные случаи использования
</h2>

Checkpoints особенно полезны, когда:

* **Исследование альтернатив**: попробуйте различные подходы к реализации без потери вашей начальной точки
* **Восстановление после ошибок**: быстро отмените изменения, которые внесли ошибки или нарушили функциональность
* **Итерация функций**: экспериментируйте с вариантами, зная, что вы можете вернуться к рабочим состояниям
* **Освобождение места контекста**: суммируйте многословный сеанс отладки с середины вперёд, сохраняя ваши исходные инструкции нетронутыми

<h2 id="limitations">
  Ограничения
</h2>

<h3 id="bash-command-changes-not-tracked">
  Изменения команд Bash не отслеживаются
</h3>

Checkpointing не отслеживает файлы, изменённые командами Bash. Например, если Claude Code запускает:

```bash theme={null}
rm file.txt
mv old.txt new.txt
cp source.txt dest.txt
```

Эти изменения файлов не могут быть отменены через rewind. Отслеживаются только прямые правки файлов, сделанные через инструменты редактирования файлов Claude.

<h3 id="subagent-edits-not-restored">
  Правки subagent не восстанавливаются
</h3>

[Subagent](/docs/ru/sub-agents) вносит правки с помощью инструментов редактирования файлов Claude, но Claude Code обычно не фиксирует эти правки в checkpoints вашего сеанса. Восстанавливает ли rewind эти правки, зависит от того, как работает subagent:

* **Foreground forked skill**: [skill с `context: fork`](/docs/ru/skills#run-skills-in-a-subagent), который работает на переднем плане, редактирует вашу рабочую папку во время вашего хода, поэтому rewind восстанавливает его правки как обычно. Установите `background: false`, чтобы запустить fork на переднем плане; в некоторых ситуациях, [перечисленных на странице skills](/docs/ru/skills#run-skills-in-a-subagent), он запускается там независимо от этого параметра.
* **Любой другой subagent**: rewind не восстанавливает правки. Используйте git для их отката. Это включает forked skill, который работает в фоновом режиме (по умолчанию), и фоновый запуск [`/code-review --fix`](/docs/ru/code-review).

<h3 id="external-changes-not-tracked">
  Внешние изменения не отслеживаются
</h3>

Checkpointing отслеживает только файлы, которые были отредактированы в текущем сеансе. Ручные изменения, которые вы вносите в файлы вне Claude Code, и правки из других одновременных сеансов обычно не фиксируются, если они не изменяют те же файлы, что и текущий сеанс.

<h3 id="messages-sent-mid-turn-not-checkpointed">
  Сообщения, отправленные во время хода, не сохраняются в checkpoint
</h3>

Когда сообщение, которое вы [ставите в очередь, пока Claude работает](/docs/ru/interactive-mode#queue-messages-while-claude-works), достигает Claude в течение текущего хода, оно присоединяется к этому ходу вместо того, чтобы начать новый. Сообщение появляется в беседе, но Claude Code не создаёт для него checkpoint, и меню rewind его не отображает. Сообщение в очереди, которое Claude Code отправляет как свой собственный ход, получает checkpoint как обычно.

Чтобы удалить такое сообщение или отменить правки, которые Claude внёс после него, выполните rewind до подсказки, которая начала ход. Это выполнит rewind всего хода, включая работу, которую Claude выполнил до прибытия вашего сообщения.

<h3 id="symlinked-and-hard-linked-paths-not-restored">
  Пути с символическими и жёсткими ссылками не восстанавливаются
</h3>

Checkpointing не выполняет rewind для файлов с символическими или жёсткими ссылками. Когда вы выбираете **Restore code** или **Restore code and conversation** из меню `/rewind`, Claude Code пропускает любой отслеживаемый путь, который является символической или жёсткой ссылкой, и показывает предупреждение `Restored the code, but skipped N files`. Пропущенные файлы сохраняют своё текущее содержимое. Чтобы отменить изменения сеанса в одном из них, попросите Claude отменить правку или отредактируйте файл самостоятельно. Файлы конфигурации, которые менеджер dotfile создаёт как символические ссылки в вашем проекте, и файлы, которые pnpm создаёт как жёсткие ссылки, относятся к этой категории.

Чтобы увидеть, какие пути пропускает восстановление, включите отладочное логирование с помощью `/debug` перед восстановлением: отладочный журнал в `~/.claude/debug/<session-id>.txt` указывает каждый пропущенный путь. Для каждой причины пропуска и шагов восстановления см. [запись skipped-files в справочнике ошибок](/docs/ru/errors#restored-the-code-but-skipped-files).

<h3 id="not-a-replacement-for-version-control">
  Не замена для контроля версий
</h3>

Checkpoints предназначены для быстрого восстановления на уровне сеанса. Для постоянной истории версий и сотрудничества продолжайте использовать контроль версий, такой как Git, для коммитов, веток и долгосрочной истории.
