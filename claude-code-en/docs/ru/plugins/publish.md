# Публикация и распространение плагина

> Опубликуйте плагин Claude Code через собственный маркетплейс или маркетплейс сообщества Anthropic с предварительным контрольным списком и информацией о том, как пользователи получают обновления.

Публикация плагина Claude Code означает его размещение в маркетплейсе — каталоге JSON, который содержит список плагинов и указывает, откуда получить каждый из них, чтобы другие люди могли установить его по имени и получать ваши обновления. Вы можете запустить собственный маркетплейс или отправить свой плагин в маркетплейс сообщества Anthropic. Чтобы поделиться плагином без публикации, отправьте людям папку плагина или файл `.zip` для самостоятельной загрузки.

Эта страница предназначена для автора готового плагина, который готов поделиться им.

<Note>
  Следующие случаи рассматриваются на других страницах:

  * **Ваш плагин еще не готов**: начните с [Создание плагина](/docs/ru/plugins/create)
  * **Вы поддерживаете CLI или SDK с плагином в официальном маркетплейсе**: см. [Рекомендуйте свой плагин из вашего CLI](/docs/ru/plugins/cli-hints)
</Note>

Начните с [Выбор способа распространения](#choose-how-to-distribute), чтобы сравнить варианты распространения. Если вы уже знаете свой путь, перейдите к [Подготовка плагина к выпуску](#prepare-your-plugin-for-release), а затем следуйте разделу вашего маршрута, чтобы узнать, что сказать пользователям и как они получают ваши обновления.

<h2 id="choose-how-to-distribute">
  Выбор способа распространения
</h2>

Выберите вариант распространения в зависимости от того, кому нужно установить плагин:

| Маршрут                                                                  | Кто может установить                                                                                                 | Что вам нужно                                                                                                      | Получают ли пользователи ваши обновления автоматически? |
| :----------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------ |
| [Без маркетплейса](#share-a-plugin-without-a-marketplace)                | Люди, которым вы отправили папку плагина или файл `.zip`                                                             | Папка плагина                                                                                                      | Нет. Они загружают копию, которую вы отправили          |
| [Собственный маркетплейс](#publish-through-your-own-marketplace)         | Любой, кто может получить доступ к репозиторию, который может быть приватным, который может клонировать ваша команда | Репозиторий git или другой хост с файлом `.claude-plugin/marketplace.json`, который содержит список вашего плагина | Выключено                                               |
| [Маркетплейс сообщества Anthropic](#submit-to-the-community-marketplace) | Любой, кто добавит `anthropics/claude-plugins-community`                                                             | Отправка через форму отправки каталога плагинов                                                                    | Выключено                                               |

Автоматическое обновление — это параметр маркетплейса на стороне пользователя, который получает новые версии в фоновом режиме.

<h2 id="prepare-your-plugin-for-release">
  Подготовка плагина к выпуску
</h2>

Имя, версия, валидация и установка из маркетплейса определяют, будет ли выпуск работать для людей, которые его установят. Проверьте их перед первым выпуском и снова перед каждым последующим.

<Steps>
  <Step title="Выберите постоянное имя">
    Пользователи устанавливают, включают и настраивают ваш плагин по `name@marketplace`, поэтому переименованный плагин — это другой плагин для каждой существующей установки. Выберите имя в формате kebab-case, например `deploy-helper`, потому что `claude plugin validate` предупреждает о других формах, и рассматривайте его как постоянное. Установите `displayName` в `plugin.json` для метки, которую видят пользователи.
  </Step>

  <Step title="Решите, как вы будете версионировать">
    Если вы установите `version` в `plugin.json` и позже отправите коммиты без его изменения, `claude plugin update` выведет `<name> is already at the latest version (1.0.0).` и пользователи сохранят старую копию. Либо увеличивайте `version` при каждом выпуске, либо опустите его в маркетплейсе, размещенном на git, чтобы Claude Code использовал SHA коммита вместо этого. См. [Версии и обновления](/docs/ru/plugins/loading#versions-and-updates).
  </Step>

  <Step title="Валидация">
    В вашей оболочке выполните `claude plugin validate --strict ./your-plugin`. Чистый запуск выводит `✔ Validation passed`.

    * **В CI**: сохраняйте `--strict`, который также завершает запуск с кодом выхода 1 при предупреждениях, таких как неизвестное поле манифеста или отсутствующий `version`. Удалите `--strict`, если вы выбрали опустить `version` на предыдущем шаге.
    * **Пути**: валидация сообщает пути компонентов, которые не начинаются с `./`. Внутри команд hook и конфигов MCP сервера ссылайтесь на файлы как `${CLAUDE_PLUGIN_ROOT}/...`. См. [правила пути](/docs/ru/plugins/manifest-reference#path-rules).
  </Step>

  <Step title="Установите его из локального маркетплейса">
    В вашей оболочке добавьте локальный маркетплейс, который содержит список плагина с помощью `claude plugin marketplace add ./path-to-marketplace`, установите плагин из него и запустите сеанс, чтобы подтвердить, что он загружается.

    * Для наименьшего маркетплейса, который работает, см. [Создание маркетплейса](/docs/ru/plugins/create-marketplace).
    * Чтобы узнать, загружает ли установка ваш исходный каталог или кэшированную копию, см. [Плагины на месте и скопированные плагины](/docs/ru/plugins/loading#in-place-and-copied-plugins).
  </Step>

  <Step title="Заполните метаданные, которые видят пользователи">
    Установите `description`, `author`, `homepage` и `repository` в `plugin.json` и добавьте `README.md` в корень плагина. `homepage` должен анализироваться как URL. [Справочник манифеста](/docs/ru/plugins/manifest-reference#fields) содержит список каждого поля.
  </Step>

  <Step title="Запустите свой набор eval">
    Если у вас есть набор eval, запустите `claude plugin eval` в вашей оболочке. Он запускает тестовые случаи плагина и оценивает результаты, что выявляет регрессии при изменении плагина. См. [Тестирование плагинов с помощью eval](/docs/ru/plugin-evals).
  </Step>
</Steps>

<h2 id="share-a-plugin-without-a-marketplace">
  Поделитесь плагином без маркетплейса
</h2>

Если плагин находится в репозитории git, люди могут клонировать его и загрузить checkout, или запустить Claude Code из своей оболочки с `--plugin-url`, указывающим на файл `.zip`, который вы прикрепляете к выпуску. Чтобы получить вашу следующую версию, они вытягивают или загружают снова. Если он не находится в репозитории, отправьте им каталог или файл `.zip` из него. Они загружают его одним из двух способов:

* **Для одного сеанса**: они запускают Claude Code из своей оболочки с `claude --plugin-dir ./deploy-helper`, где путь — это клон, распакованная папка или сам файл `.zip`. См. [Флаги, которые загружают плагин для одного сеанса](/docs/ru/plugins/cli-reference#flags-that-load-a-plugin-for-one-session).
* **Для каждого сеанса**: они перемещают каталог плагина с его `.claude-plugin/plugin.json` под `~/.claude/skills/`, чтобы Claude Code [загружал его в каждом сеансе](/docs/ru/plugins/loading#find-where-a-plugin-came-from).

Добавление `.claude-plugin/marketplace.json` в тот же репозиторий — это то, что позволяет людям устанавливать по имени и обновляться с помощью команды; см. [Публикация через собственный маркетплейс](#publish-through-your-own-marketplace).

<h3 id="ship-a-plugin-with-your-own-tool">
  Отправьте плагин со своим собственным инструментом
</h3>

Если вы поддерживаете CLI или SDK, опубликуйте плагин в маркетплейсе и попросите ваш установщик или сообщение после установки запустить или вывести две команды, которые нужны пользователю: `claude plugin marketplace add <source>`, затем `claude plugin install <name>@<marketplace>`. Для обнаружения в сеансе, когда кто-то использует ваш инструмент, см. [Рекомендуйте свой плагин из вашего CLI](/docs/ru/plugins/cli-hints).

<h2 id="publish-through-your-own-marketplace">
  Публикация через собственный маркетплейс
</h2>

Ваш собственный маркетплейс — это файл `.claude-plugin/marketplace.json`, который содержит список вашего плагина, добавленный в репозиторий git. После того как файл находится в репозитории, плагин опубликован, без формы отправки. Вы можете сохранить файл в собственном репозитории плагина или в отдельном.

<h3 id="add-the-marketplace-file-to-your-repository">
  Добавьте файл маркетплейса в ваш репозиторий
</h3>

Чтобы опубликовать из собственного репозитория плагина, сохраните файл маркетплейса рядом с `plugin.json` в `.claude-plugin/`, с одной записью, чей `source` — это `"./"`, корень репозитория. Дайте записи то же `name`, что и `plugin.json`, согласно [Сохраняйте имя записи и имя манифеста одинаковыми](/docs/ru/plugins/create-marketplace#keep-the-entry-name-and-the-manifest-name-the-same):

```json .claude-plugin/marketplace.json theme={null}
{
  "name": "your-marketplace",
  "owner": { "name": "Your Name" },
  "plugins": [
    { "name": "deploy-helper", "source": "./" }
  ]
}
```

В вашей оболочке запустите `claude plugin validate .` в репозитории, чтобы проверить файл перед отправкой.

[Создание маркетплейса](/docs/ru/plugins/create-marketplace) охватывает макет с несколькими плагинами в одном репозитории.

<h3 id="control-who-can-install">
  Контролируйте, кто может установить
</h3>

Любой, кто может клонировать репозиторий, может установить из него, поэтому если репозиторий приватный, маркетплейс также приватный. Для хостов, отличных от репозитория git, см. [Размещение маркетплейса](/docs/ru/plugins/host-marketplace). Чтобы охватить всех в компании, включая людей, которые не используют git, см. [Развертывание для всей компании](/docs/ru/plugins/host-marketplace#roll-out-to-a-whole-company).

<h3 id="tell-users-how-to-install">
  Скажите пользователям, как установить
</h3>

Скажите своим пользователям добавить маркетплейс, а затем установить плагин из своей оболочки, заменив источник и имена на ваши:

* Добавьте маркетплейс один раз: `claude plugin marketplace add your-org/your-marketplace`, где аргумент — это сокращение GitHub `owner/repo`, URL или путь
* Установите плагин: `claude plugin install deploy-helper@your-marketplace`
* Или сделайте оба из сеанса: `/plugin install deploy-helper --marketplace your-org/your-marketplace`. Требуется Claude Code v2.1.275 или позже. См. [Добавьте маркетплейс и установите в одной команде](/docs/ru/plugins/install#add-a-marketplace-and-install-in-one-command)

<h3 id="ship-updates-to-users">
  Отправьте обновления пользователям
</h3>

Пользователи получают выпуск, когда они его запрашивают или когда для вашего маркетплейса включено автоматическое обновление:

* **По запросу**: `claude plugin update deploy-helper@your-marketplace` в оболочке пользователя обновляет маркетплейс и устанавливает новую копию, когда версия вашего плагина изменилась
* **Автоматическое обновление**: по умолчанию отключено для вашего маркетплейса. См. [Включите автоматическое обновление](/docs/ru/plugins/host-marketplace#turn-on-auto-update). После включения он делает то же самое, что `claude plugin update` с задержкой после запуска сеанса

[Установка плагинов](/docs/ru/plugins/install) охватывает команды на стороне пользователя, а [когда запускается автоматическое обновление](/docs/ru/plugins/loading#when-auto-update-runs) охватывает время.

<h2 id="submit-to-the-community-marketplace">
  Отправить в сообщество marketplace
</h2>

Сообщество marketplace Anthropic, `claude-community`, — это публичный marketplace, в котором перечислены плагины, отправленные через форму отправки каталога плагинов.

Пользователи добавляют сообщество marketplace в сеанс Claude Code с помощью `/plugin marketplace add anthropics/claude-plugins-community` и устанавливают его как `@claude-community`.

О том, чем сообщество marketplace отличается от официального marketplace, см. [Marketplaces Anthropic](/docs/ru/plugins/anthropic-marketplaces).

Чтобы отправить ваш плагин в сообщество marketplace, используйте одну из встроенных форм:

* **claude.ai**: [claude.ai/admin-settings/directory/submissions/plugins/new](https://claude.ai/admin-settings/directory/submissions/plugins/new)
* **Console**: [platform.claude.com/plugins/submit](https://platform.claude.com/plugins/submit)

Форма claude.ai требует организацию Team или Enterprise и разрешение Directory, которое по умолчанию имеют владельцы. Отдельные авторы, которые не являются частью организации Team или Enterprise, могут вместо этого использовать форму Console.

В вашей оболочке запустите `claude plugin validate ./your-plugin` локально перед отправкой, заменив `./your-plugin` на путь к каталогу вашего плагина. Когда валидация пройдена успешно, Claude Code выводит `✔ Validation passed`, или `✔ Validation passed with warnings`, если есть предупреждения. Предупреждения не приводят к сбою валидации; добавьте `--strict`, чтобы рассматривать их как ошибки.

Перечисленные плагины появляются в каталоге [`anthropics/claude-plugins-community`](https://github.com/anthropics/claude-plugins-community), в подавляющем большинстве случаев закреплённые на определённом коммите SHA.

Может быть задержка между отправкой и появлением вашего плагина в `marketplace.json`. Чтобы проверить, доступен ли ваш плагин для установки, найдите его имя в [каталоге сообщества](https://github.com/anthropics/claude-plugins-community/blob/main/.claude-plugin/marketplace.json).

Официальный marketplace, `claude-plugins-official`, не принимает отправки через эти формы. Если вы работаете с контактом партнёра Anthropic, попросите у них информацию о размещении в официальном marketplace.

<h2 id="ship-updates-renames-and-removals">
  Отправка обновлений, переименований и удалений
</h2>

<h3 id="release-a-new-version">
  Выпустите новую версию
</h3>

Если вы публикуете через собственный маркетплейс и ваш `plugin.json` устанавливает `version`, увеличьте его и отправьте. Пользователи, которые запускают `claude plugin update` или имеют включенное автоматическое обновление, получают новую версию, как описано в [Отправка обновлений пользователям](#ship-updates-to-users).

<h3 id="tag-a-release">
  Отметьте выпуск
</h3>

Отметьте выпуск в git, когда другие плагины объявляют диапазон версий на вашем, потому что эти диапазоны разрешаются против тегов. В противном случае вам не нужен тег.

Чтобы отметить, запустите `claude plugin tag` в вашей оболочке из каталога плагина. Он создает тег `{name}--v{version}`. Добавьте `--push`, чтобы отправить тег на `origin`. [Справочник `plugin tag`](/docs/ru/plugins/cli-reference#plugin-tag) содержит список его флагов.

<h3 id="rename-or-remove-a-plugin">
  Переименуйте или удалите плагин
</h3>

Никогда не изменяйте `name` опубликованного плагина. После переименования пользователи, которые уже установили его, теряют плагин, потому что их установка записана под старым именем. Запись `renames` в файле маркетплейса переносит их вместо этого. Измените `displayName`, когда вы хотите другую метку.

Если переименование неизбежно, используйте карту `renames` файла маркетплейса, чтобы существующие установки переносились вместо сбоя с [`Plugin "<name>" not found in marketplace`](/docs/ru/plugins/troubleshooting#plugin-not-found-in-marketplace). Чтобы удалить плагин из маркетплейса или получить полные детали `renames`, см. [Переименуйте или удалите плагин](/docs/ru/plugins/host-marketplace#rename-or-remove-a-plugin) на странице размещения. [Справочник маркетплейса](/docs/ru/plugins/marketplace-reference#top-level-fields) содержит поле.

<h2 id="declare-dependencies">
  Объявите зависимости
</h2>

Если ваш плагин нуждается в другом плагине из того же маркетплейса для включения, перечислите его в массиве `dependencies` в `plugin.json`. Каждая запись — это простое имя или объект с диапазоном semver `version`. Когда пользователь устанавливает ваш плагин, Claude Code также устанавливает и включает зависимость.

[Зависимости плагинов](/docs/ru/plugins/dependencies) охватывает синтаксис диапазона, кросс-маркетплейс зависимости и как пользователи удаляют зависимости, которые им больше не нужны.
