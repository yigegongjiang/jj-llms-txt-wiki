# Настройка сочетаний клавиш

> Настройте сочетания клавиш в Claude Code с помощью файла конфигурации keybindings.

Claude Code поддерживает настраиваемые сочетания клавиш. Запустите `/keybindings` для создания или открытия файла конфигурации в `~/.claude/keybindings.json`.

<h2 id="configuration-file">
  Файл конфигурации
</h2>

Файл конфигурации сочетаний клавиш — это объект с массивом `bindings`. Каждый блок указывает контекст и карту нажатий клавиш на действия.

<Note>Изменения в файле сочетаний клавиш автоматически обнаруживаются и применяются без перезагрузки Claude Code.</Note>

| Поле       | Описание                                                    |
| :--------- | :---------------------------------------------------------- |
| `$schema`  | Необязательный URL JSON Schema для автодополнения редактора |
| `$docs`    | Необязательный URL документации                             |
| `bindings` | Массив блоков привязок по контексту                         |

Этот пример привязывает `Ctrl+E` к открытию внешнего редактора в контексте чата и отменяет привязку `Ctrl+U`:

```json theme={null}
{
  "$schema": "https://www.schemastore.org/claude-code-keybindings.json",
  "$docs": "https://code.claude.com/docs/ru/keybindings",
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+e": "chat:externalEditor",
        "ctrl+u": null
      }
    }
  ]
}
```

<h2 id="contexts">
  Контексты
</h2>

Каждый блок привязки указывает **контекст**, где применяются привязки:

| Контекст          | Описание                                                                       |
| :---------------- | :----------------------------------------------------------------------------- |
| `Global`          | Применяется везде в приложении                                                 |
| `Chat`            | Основная область ввода чата                                                    |
| `Autocomplete`    | Меню автодополнения открыто                                                    |
| `Settings`        | Меню параметров                                                                |
| `Confirmation`    | Диалоги разрешений и подтверждений                                             |
| `Tabs`            | Компоненты навигации по вкладкам                                               |
| `Help`            | Меню справки видимо                                                            |
| `Transcript`      | Средство просмотра стенограммы                                                 |
| `HistorySearch`   | Режим поиска истории (Ctrl+R)                                                  |
| `Task`            | Выполняется фоновая задача                                                     |
| `ThemePicker`     | Диалог выбора темы                                                             |
| `Attachments`     | Навигация по вложениям изображений в диалогах выбора                           |
| `Footer`          | Навигация по индикатору нижнего колонтитула (задачи, команды, diff, артефакты) |
| `MessageSelector` | Выбор сообщения в диалоге перемотки и резюме                                   |
| `DiffDialog`      | Навигация по средству просмотра diff                                           |
| `DiffPanel`       | [Панель diff](/docs/ru/interactive-mode#diff-panel) открыта                         |
| `ModelPicker`     | Уровень усилий выбора модели                                                   |

| `Select`          | Универсальные компоненты выбора/списка                                         |
| `Plugin`          | Диалог plugin (обзор, обнаружение, управление)                                 |
| `Agents`          | [Представление Agent](/docs/ru/agent-view) (`claude agents`)                        |
| `Scroll`          | Прокрутка разговора и выделение текста в полноэкранном режиме                  |

<h3 id="confirmation-actions">
  Действия подтверждения
</h3>

Действия, доступные в контексте `Confirmation`:

| Действие                | По умолчанию   | Описание                                                                                                                                                                                                                                                                                                     |
| :---------------------- | :------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `confirm:yes`           | Enter          | Подтвердить действие                                                                                                                                                                                                                                                                                         |
| `confirm:no`            | Escape         | Отклонить действие                                                                                                                                                                                                                                                                                           |
| `confirm:previous`      | Up             | Предыдущий вариант                                                                                                                                                                                                                                                                                           |
| `confirm:next`          | Down           | Следующий вариант                                                                                                                                                                                                                                                                                            |
| `confirm:nextField`     | Tab            | Следующее поле                                                                                                                                                                                                                                                                                               |
| `confirm:previousField` | (не привязано) | Предыдущее поле                                                                                                                                                                                                                                                                                              |
| `confirm:toggle`        | Space          | Переключить выбор                                                                                                                                                                                                                                                                                            |
| `confirm:cycleMode`     | Shift+Tab\*    | Циклический перебор режимов разрешений. В подсказке разрешения файла закрывает открытое [поле комментария](/docs/ru/permissions#add-a-comment-when-you-answer-a-permission-prompt); если поле не открыто, выбирает вариант, который разрешает действие на остаток сеанса, когда подсказка предлагает этот вариант |

\*На Windows без режима VT (Node \<24.2.0/\<22.17.0, Bun \<1.2.23) по умолчанию используется Meta+M.

До v2.1.257 действие `confirm:toggleExplanation`, привязанное к `Ctrl+E` по умолчанию, показывало сгенерированное моделью объяснение команды в подсказках разрешений Bash и PowerShell.

Диалоги используют `confirm:yes` и `confirm:no` для принятия и отмены даже когда они не задают вопрос да или нет. Если вы привяжете простую букву, такую как `y` или `n`, в этом контексте, буква также действует на диалоги, которые никогда не показывают её как клавишу. Диалог, который показывает `y` и `n` как его клавиши, читает эти буквы сам и не требует привязки.

Этот пример привязывает `y` к `confirm:yes` и `n` к `confirm:no`:

```json theme={null}
{
  "bindings": [
    {
      "context": "Confirmation",
      "bindings": {
        "y": "confirm:yes",
        "n": "confirm:no"
      }
    }
  ]
}
```

С этими привязками `y` и `n` по-прежнему вводятся как буквы, пока [текстовое поле](#text-fields) имеет фокус.

До v2.1.280 `y` также была привязана к `confirm:yes` и `n` к `confirm:no` по умолчанию. Если вы создали свой `keybindings.json` с помощью `/keybindings` до v2.1.280, файл содержит обе привязки и они остаются в силе, пока вы не удалите эти две строки.

<h3 id="history-search-actions">
  Действия поиска истории
</h3>

Действия, доступные в контексте `HistorySearch`:

| Действие                   | По умолчанию | Описание                                          |
| :------------------------- | :----------- | :------------------------------------------------ |
| `historySearch:next`       | Ctrl+R       | Следующее совпадение                              |
| `historySearch:accept`     | Escape, Tab  | Принять выбор                                     |
| `historySearch:cancel`     | Ctrl+C       | Отменить поиск                                    |
| `historySearch:execute`    | Enter        | Выполнить выбранную команду                       |
| `historySearch:cycleScope` | Ctrl+S       | Циклический перебор области: сеанс, проект, везде |

Значения по умолчанию `historySearch:next`, `historySearch:accept`, `historySearch:cancel` и `historySearch:execute` применяются к встроенному поиску истории в классическом рендерере, который всегда ищет подсказки из всех проектов. `historySearch:cycleScope` вступает в силу только в [полноэкранном рендеринге](/docs/ru/fullscreen), где `Ctrl+R` открывает диалог поиска вместо этого и `Ctrl+S` циклирует его область. Другие клавиши диалога фиксированы и не могут быть переназначены: `Enter` или `Tab` помещает выделенное совпадение в ввод подсказки и `Esc` отменяет.

<h2 id="keystroke-syntax">
  Синтаксис нажатия клавиш
</h2>

<h3 id="modifiers">
  Модификаторы
</h3>

Используйте клавиши-модификаторы с разделителем `+`:

* `ctrl` или `control` - клавиша Control
* `shift` - клавиша Shift
* `alt`, `opt`, `option` или `meta` - клавиша Alt в Windows и Linux, клавиша Option в macOS
* `cmd`, `command`, `super` или `win` - клавиша Command в macOS, клавиша Windows в Windows, клавиша Super в Linux

Группа `cmd` обнаруживается только в терминалах, которые сообщают о модификаторе Super, таких как те, которые поддерживают протокол клавиатуры Kitty или режим `modifyOtherKeys` xterm. Большинство терминалов его не отправляют, поэтому используйте `ctrl` или `meta` для привязок, которые вы хотите использовать везде.

Например:

```text theme={null}
ctrl+k          Ctrl + K
shift+tab       Shift + Tab
meta+p          Option + P в macOS, Alt + P в других местах
ctrl+shift+c    Несколько модификаторов
```

<h3 id="uppercase-letters">
  Прописные буквы
</h3>

Claude Code анализирует названия клавиш без учёта регистра, поэтому `K` — это то же самое привязка, что и `k`, а `ctrl+K` — то же самое, что `ctrl+k`. Чтобы привязать Shift и букву, напишите `shift+k`.

<h3 id="non-us-keyboard-layouts">
  Раскладки клавиатуры, отличные от US
</h3>

Пишите названия клавиш сочетаний Ctrl как латинские символы, даже если ваша активная раскладка клавиатуры вводит другие символы.

То, как Claude Code сопоставляет нажатую вами клавишу с привязкой, зависит от типа раскладки:

* При использовании нелатинской раскладки, такой как кириллица, Claude Code сопоставляет сочетания Ctrl по позиции клавиши в раскладке US, когда терминал использует протокол клавиатуры Kitty и сообщает эту позицию. В таком терминале с активной русской раскладкой нажатие Ctrl и физической клавиши W запускает `ctrl+w`. В терминале, который не сообщает позицию, Claude Code сопоставляет то, что отправляет терминал для нажатия клавиши: код управления ASCII запускает латинское сочетание, а нажатие клавиши, которое приходит как кириллический символ, не соответствует никакой привязке
* При использовании раскладок, которые переставляют латинские буквы, такие как AZERTY, Claude Code сопоставляет букву, которую вводит клавиша, поэтому нажатие Ctrl и клавиши с надписью A запускает `ctrl+a`

До версии 2.1.247 нажатие сочетания Ctrl при использовании нелатинской раскладки не запускало его привязку в терминалах, которые используют протокол клавиатуры Kitty, таких как Ghostty, Kitty, WezTerm и iTerm2.

<h3 id="chords">
  Аккорды
</h3>

Аккорды — это последовательности нажатий клавиш, разделённые пробелами:

```text theme={null}
ctrl+k ctrl+s   Нажмите Ctrl+K, отпустите, затем Ctrl+S
```

Нажимайте каждое сочетание клавиш в течение 3 секунд после предыдущего. Если вы ждёте дольше, Claude Code отменяет аккорд и показывает краткое уведомление об этом.

<h3 id="special-keys">
  Специальные клавиши
</h3>

* `escape` или `esc` - клавиша Escape
* `enter` или `return` - клавиша Enter
* `tab` - клавиша Tab
* `space` - пробел
* `up`, `down`, `left`, `right` - клавиши со стрелками
* `pageup`, `pagedown` - клавиши Page Up и Page Down

<h2 id="unbind-default-shortcuts">
  Отмена привязки сочетаний по умолчанию
</h2>

Установите действие на `null` для отмены привязки сочетания по умолчанию:

```json theme={null}
{
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+s": null
      }
    }
  ]
}
```

Это также работает для привязок аккордов. Отмена привязки каждого аккорда, который использует префикс, освобождает этот префикс для использования в качестве привязки с одной клавишей. Аккорд в любом активном контексте сохраняет свой префикс зарезервированным, поэтому вы должны отменить привязку каждого аккорда в контексте, который его определяет.

Claude Code привязывает эти аккорды по умолчанию на префиксе `ctrl+x`: `ctrl+x ctrl+k`, `ctrl+x ctrl+e`, `ctrl+x enter`, `ctrl+x ctrl+a`, `ctrl+x ctrl+s` и `ctrl+x tab` в `Chat`, `ctrl+x ctrl+b` в `Task` и `ctrl+x b` в `DiffPanel`. Аккорд `ctrl+x enter` требует версии v2.1.247 или более поздней, `ctrl+x b`, `ctrl+x ctrl+a` и `ctrl+x tab` требуют версии v2.1.260 или более поздней, и `ctrl+x ctrl+s` требует версии v2.1.275 или более поздней.

Чтобы вернуть `ctrl+x` как привязку с одной клавишей, отмените привязку всех из них:

```json theme={null}
{
  "bindings": [
    {
      "context": "Task",
      "bindings": {
        "ctrl+x ctrl+b": null
      }
    },
    {
      "context": "DiffPanel",
      "bindings": {
        "ctrl+x b": null
      }
    },
    {
      "context": "Chat",
      "bindings": {
        "ctrl+x ctrl+k": null,
        "ctrl+x ctrl+e": null,
        "ctrl+x enter": null,
        "ctrl+x ctrl+a": null,
        "ctrl+x ctrl+s": null,
        "ctrl+x tab": null,
        "ctrl+x": "chat:newline"
      }
    }
  ]
}
```

Если вы отмените привязку некоторых, но не всех аккордов на префиксе, нажатие префикса всё ещё переводит в режим ожидания аккорда для оставшихся привязок.

<h2 id="text-fields">
  Текстовые поля
</h2>

Если вы привяжете простую букву, цифру или пробел, вы все равно сможете вводить этот символ в текстовое поле внутри диалога или панели. Одно из таких полей — это ответ `Other` на вопрос, который задает Claude. Пока поле имеет фокус, печатаемая клавиша, которую вы нажимаете без Ctrl, Alt или Cmd, переходит в поле, и Claude Code не сопоставляет ее с вашими сочетаниями клавиш.

Эти клавиши все еще выполняют свои сочетания клавиш, пока поле имеет фокус:

* Клавиши, которые не вводят символ, такие как Enter, Escape, Tab и клавиши со стрелками
* Любая клавиша, нажатая с Ctrl, Alt или Cmd
* Второй нажим [chord](#chords), уже выполняемого

В основной подсказке Claude Code сопоставляет каждую клавишу с активными контекстами, такими как `Chat`, и вводит клавишу только когда никакое сочетание клавиш ее не перехватывает.

<h2 id="vim-mode-interaction">
  Взаимодействие с режимом vim
</h2>

Когда включен режим vim через `/config` → Editor mode, сочетания клавиш и режим vim работают независимо:

* **Режим vim** обрабатывает ввод на уровне текстового ввода (движение курсора, режимы, движения)
* **Сочетания клавиш** обрабатывают действия на уровне компонента (переключение задач, отправка и т. д.)
* Клавиша Escape в режиме vim переключает INSERT в NORMAL режим; она не запускает `chat:cancel`
* Большинство сочетаний Ctrl+клавиша проходят через режим vim в систему сочетаний клавиш
* Клавиши vim не переназначаются через файл сочетаний клавиш. Чтобы сопоставить двухклавишную последовательность в режиме INSERT, такую как `jj`, с клавишей Escape, используйте параметр [`vimInsertModeRemaps`](/docs/ru/interactive-mode#remap-insert-mode-key-sequences)
* В режиме vim NORMAL `?` показывает меню справки (поведение vim)
* В режиме vim NORMAL `/` открывает поиск по истории, то же самое, что Ctrl+R в стандартном режиме

<h2 id="validation">
  Валидация
</h2>

Claude Code проверяет ваши сочетания клавиш и показывает предупреждения для:

* Ошибок разбора (неверный JSON или структура)
* Неверных имён контекстов
* Неверных значений действий, таких как действие, которое не является строкой или `null`
* Неизвестных имён действий, таких как опечатка зарегистрированного действия. Claude Code пропускает привязку и сохраняет любую привязку по умолчанию для этого ключа в силе. До версии 2.1.246 привязка с неизвестным именем действия молча отключала этот ключ
* Конфликтов зарезервированных сочетаний
* Дублирующихся привязок в одном контексте

Claude Code сообщает о предупреждениях при загрузке файла и записывает каждое в журнал отладки. Запустите Claude Code с [`--debug`](/docs/ru/cli-reference#cli-flags) для просмотра деталей.
