# Конфигурация модели

> Настройте, какую модель использует Claude Code, уровни усилий, расширенный контекст и окно auto-compact

<h2 id="available-models">
  Доступные модели
</h2>

Для параметра `model` в Claude Code вы можете настроить либо:

* **Псевдоним модели**
* **Имя модели**
  * Anthropic API: полное **[имя модели](https://platform.claude.com/docs/en/about-claude/models/overview)**
  * Amazon Bedrock: ARN профиля вывода
  * Microsoft Foundry: имя развёртывания
  * Google Cloud's Agent Platform: имя версии

Рекомендации по выбору модели и уровня усилий для различных типов работ см. в статье [Choosing a Claude model and effort level in Claude Code](https://claude.com/blog/claude-model-and-effort-level-in-claude-code) в блоге.

<Note>
  `ANTHROPIC_BASE_URL` изменяет, куда отправляются запросы, а не какая модель на них отвечает. Чтобы маршрутизировать Claude через шлюз LLM, см. [LLM gateways](/docs/ru/llm-gateway).
</Note>

<h3 id="model-aliases">
  Псевдонимы моделей
</h3>

Используйте псевдоним модели для выбора параметров модели без необходимости помнить точные номера версий:

| Псевдоним модели | Поведение                                                                                                                                                                                                                                                                                                                                     |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`default`**    | Специальное значение, которое очищает любое переопределение модели и возвращается к [стандартной модели для вашей учётной записи](#default-model-setting). Сам по себе не является псевдонимом модели                                                                                                                                         |
| **`best`**       | Использует модель, на которую разрешается [псевдоним `fable`](#fable-alias-resolution), если Fable доступна для вас, в противном случае ту же модель, что и `opus`                                                                                                                                                                            |
| **`fable`**      | Использует [модель Fable для вашего поставщика](#fable-alias-resolution) для ваших самых сложных и долгоживущих задач                                                                                                                                                                                                                         |
| **`sonnet`**     | Использует последнюю модель Sonnet для ежедневных задач кодирования                                                                                                                                                                                                                                                                           |
| **`opus`**       | Использует последнюю модель Opus для сложных задач рассуждения                                                                                                                                                                                                                                                                                |
| **`haiku`**      | Использует быструю и эффективную модель Haiku для простых задач                                                                                                                                                                                                                                                                               |
| **`sonnet[1m]`** | Использует Sonnet с [окном контекста в 1 миллион токенов](https://platform.claude.com/docs/en/build-with-claude/context-windows#context-window-sizes-by-model) для длительных сеансов. Не имеет эффекта, когда `sonnet` уже разрешается на Sonnet 5 с его встроенным окном 1M; за [шлюзом LLM](/docs/ru/llm-gateway) выбирает окно 1M для Sonnet 5 |
| **`opus[1m]`**   | Использует Opus с [окном контекста в 1 миллион токенов](https://platform.claude.com/docs/en/build-with-claude/context-windows#context-window-sizes-by-model) для длительных сеансов                                                                                                                                                           |
| **`opusplan`**   | Специальный режим, который использует `opus` во время режима плана, а затем переключается на `sonnet` для выполнения                                                                                                                                                                                                                          |

Версия, на которую разрешаются псевдонимы `opus` и `sonnet`, зависит от поставщика:

| Поставщик                                            | `opus`   | `sonnet`   |
| :--------------------------------------------------- | :------- | :--------- |
| Anthropic API                                        | Opus 5.5 | Sonnet 5   |
| [Claude Platform on AWS](/docs/ru/claude-platform-on-aws) | Opus 5.5 | Sonnet 4.6 |
| Amazon Bedrock, Google Cloud's Agent Platform        | Opus 5.5 | Sonnet 4.5 |
| Microsoft Foundry                                    | Opus 4.6 | Sonnet 4.5 |

<span id="fable-alias-resolution" />

Если вы не установили `ANTHROPIC_DEFAULT_FABLE_MODEL`, псевдоним `fable` разрешается на Fable 5.1, за исключением сеансов [Claude apps gateway](/docs/ru/claude-apps-gateway), где `fable` и `best` разрешаются на Fable 5. До версии 2.1.257 `fable` разрешался на Fable 5 на каждом поставщике.

Шлюз, который не настроен на обслуживание `claude-fable-5-1`, отклоняет запросы для этой модели. Чтобы использовать Fable 5.1 через шлюз, который его обслуживает, выберите его с помощью `/model claude-fable-5-1`.

Если псевдоним разрешается на более старую модель, более новые модели доступны путём явного выбора полного имени модели или установки `ANTHROPIC_DEFAULT_OPUS_MODEL` или `ANTHROPIC_DEFAULT_SONNET_MODEL`.

До версии 2.1.280 `opus` разрешался на Opus 5 в Anthropic API, Claude Platform on AWS, Amazon Bedrock и Google Cloud's Agent Platform начиная с версии 2.1.219. До версии 2.1.219 `opus` разрешался на Opus 4.8 в Anthropic API начиная с версии 2.1.154 и на Claude Platform on AWS, Amazon Bedrock и Google Cloud's Agent Platform начиная с версии 2.1.207. До версии 2.1.207 `opus` разрешался на Opus 4.7 на Claude Platform on AWS и на Opus 4.6 на Amazon Bedrock и Google Cloud's Agent Platform.

Псевдонимы указывают на рекомендуемую версию для вашего поставщика и обновляются со временем. Чтобы закрепить определённую версию, используйте полное имя модели, например `claude-opus-5-5`, или установите соответствующую переменную окружения, например `ANTHROPIC_DEFAULT_OPUS_MODEL`.

<Note>
  Opus 5.5 требует Claude Code версии 2.1.280 или позже. Opus 5 требует версии 2.1.219 или позже. Sonnet 5 требует версии 2.1.197 или позже. Запустите `claude update` для обновления.
</Note>

<h3 id="work-with-fable">
  Работа с Fable
</h3>

[Claude Fable 5.1](https://platform.claude.com/docs/en/about-claude/models/overview) и Claude Fable 5 — это наиболее мощные модели в Claude Code, подходящие для задач, которые занимают больше одного сеанса. Они поддерживают длительные автономные сеансы, исследуют перед действием и проверяют свою работу чаще, чем меньшие модели. Fable 5.1 — это более новый выпуск.

Ни одна из моделей Fable не является стандартной для типа учётной записи ни на одном плане или поставщике. Выберите одну явно:

* **Fable 5.1**: запустите `/model fable` или запустите с `claude --model fable`. В сеансах [Claude apps gateway](/docs/ru/claude-apps-gateway), где псевдоним разрешается на Fable 5, вместо этого запустите `/model claude-fable-5-1`.
* **Fable 5**: выберите её по ID модели. В Anthropic API запустите `/model claude-fable-5` или запустите с `claude --model claude-fable-5`. На других поставщиках используйте ID модели Fable 5 вашего поставщика или [закрепите её](#pin-models-for-third-party-deployments) с помощью `ANTHROPIC_DEFAULT_FABLE_MODEL`.

Если вы подключаетесь непосредственно к Anthropic API и ваши пользовательские параметры содержат `claude-fable-5` или `claude-fable-5[1m]` в качестве модели, например потому что вы выбрали Fable в средстве выбора `/model` до версии 2.1.257, Claude Code изменит это сохранённое значение на псевдоним `fable` или `fable[1m]` при первом запуске версии 2.1.257 или позже. Строка запуска модели показывает `(auto-updated)` один раз. Значение `claude-fable-5` в параметрах проекта, локальных или управляемых параметрах остаётся как есть.

Запросы, которые классификаторы безопасности модели Fable помечают, чаще всего в областях кибербезопасности и биологии, запускают [автоматический откат модели](#automatic-model-fallback).

Чтобы получить максимум от Fable:

* **Опишите результат, а не шаги**: дайте ей результат, который вы хотите, и позвольте ей спланировать путь. Чтобы она продолжала работать над этим результатом, [установите цель](/docs/ru/goal).
* **Дайте ей неоднозначные проблемы**: исследования первопричин, отладка сбоев и решения по архитектуре — это то, где дополнительное исследование и проверка окупаются.
* **Пропустите напоминания о проверке**: она проверяет свою собственную работу с меньшим количеством подсказок, поэтому напоминания о тестировании или проверке обычно не требуются.
* **Масштабируйте более крупные задачи**: дайте ей работу, которую вы обычно разбиваете на части. Она держит длительные сеансы без потери нити.

<Note>
  Fable 5.1 требует Claude Code версии 2.1.257 или позже. Если запрос для неё из более старой версии не удаётся, см. [Claude Code does not support this model](/docs/ru/errors#claude-code-does-not-support-this-model). Запустите `claude update` для обновления. Для доступности при нулевом сохранении данных см. [Model availability under ZDR](/docs/ru/zero-data-retention#model-availability-under-zdr).
</Note>

В Anthropic API средство выбора `/model` отображает модель Fable, если [`availableModels`](#restrict-model-selection) или [ограничения модели организации](#organization-model-restrictions) её не исключают. Когда ваша организация вообще не может использовать Fable, например при [нулевом сохранении данных](/docs/ru/zero-data-retention#model-availability-under-zdr), строка остаётся в средстве выбора неактивной с примечанием о причине.

<h4 id="fable-and-usage-credits">
  Fable и кредиты использования
</h4>

В зависимости от вашего плана и уровня места, использование Fable может выставляться в счёт [кредитам использования](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans) вместо использования включённых лимитов вашего плана. Когда это происходит, средство выбора `/model` показывает "Requires usage credits" в строке Fable. Для управления кредитами использования см. [Add usage credits to your subscription](/docs/ru/costs#add-usage-credits-to-your-subscription).

В интерактивных сеансах Claude Code показывает запрос согласия перед запросом Fable, который выставляет кредиты использования. Члены планов Enterprise с организационным выставлением счётов не видят запрос. Вы можете продолжить работу с Fable, используя кредиты использования, или переключиться на вашу модель по умолчанию. Вы также можете отклонить запрос:

* В средстве выбора `/model` вы сохраняете вашу текущую модель.
* Во время сеанса Claude Code продолжает ход на вашей модели по умолчанию.

После того как вы выберете продолжить работу с Fable, используя кредиты использования, Claude Code больше не показывает запрос.

В сеансе с подключённым [Remote Control](/docs/ru/remote-control), [фоновым сеансом](/docs/ru/agent-view) или сеансом товарища по [команде агентов](/docs/ru/agent-teams), никто не может быть у терминала, поэтому Claude Code удерживает запрос согласия во время сеанса до крайнего срока [`dialogExpiry`](/docs/ru/settings-reference#dialogexpiry), пять минут по умолчанию. Если никто не ответил к крайнему сроку, Claude Code завершает ход без отправки запроса и добавляет уведомление в стенограмму, которое также показывает клиент Remote Control. Ваш выбор модели не изменяется, и Claude Code снова запрашивает согласие при вашем следующем сообщении.

То, что вы можете делать во время ожидания запроса, зависит от сеанса:

* С подключённым Remote Control или в сеансе товарища нажмите любую клавишу у терминала, чтобы отменить крайний срок, и Claude Code ждёт вашего ответа.
* В фоновом сеансе ответьте до крайнего срока.
* Если вы отправите новое сообщение от удалённого клиента до того, как кто-нибудь напечатает у терминала, Claude Code завершит ход таким же образом, и ваше новое сообщение начнёт следующий ход. После того как кто-нибудь напечатает у терминала, Claude Code продолжает ждать ответа и ставит ваше новое сообщение в очередь позади него.

В [неинтерактивном режиме](/docs/ru/headless) с флагом `-p` и через Agent SDK Claude Code никогда не показывает запрос согласия. Когда запрос Fable там выставляет кредиты использования, Claude Code выставляет его без запроса.

<h3 id="setting-your-model">
  Установка вашей модели
</h3>

Вы можете настроить вашу модель несколькими способами, перечисленными в порядке приоритета:

1. **Во время сеанса**: используйте `/model <alias|name>` для немедленного переключения или запустите `/model` без аргумента, чтобы открыть средство выбора. См. [когда Claude Code просит вас подтвердить переключение](/docs/ru/prompt-caching#switching-models)
2. **При запуске**: запустите с `claude --model <alias|name>`
3. **Переменная окружения**: установите `ANTHROPIC_MODEL=<alias|name>`
4. **Параметры**: настройте постоянно в файле параметров, используя поле `model`
5. **[Стандартная для новых сеансов](#set-a-default-model-for-new-sessions)**: установите `ANTHROPIC_DEFAULT_MODEL=<alias|name>`

`/model` сохраняет ваш выбор как стандартный для новых сеансов, записывая поле `model` в ваши пользовательские параметры. В средстве выбора:

* `Enter`: переключить модель и сохранить как вашу стандартную
* `s`: переключить модель только для этого сеанса и оставить вашу стандартную без изменений. Чтобы использовать другую клавишу, переназначьте [`modelPicker:thisSessionOnly`](/docs/ru/keybindings#model-picker-actions)

Ввод `/model <name>` напрямую ведёт себя как `Enter`. Чтобы переключиться только для этого сеанса, откройте средство выбора с `/model` и нажмите `s` в строке модели.

Если вы переключаете модели с `/model`, переключение также достигает [подагентов, которые наследуют модель основного разговора](/docs/ru/sub-agents#choose-a-model), потому что Claude Code разрешает их модель из той, которую использует ваш сеанс, когда Claude их запускает. Переключитесь на Opus перед тем, как Claude делегирует исследование или тестовые запуски одному из них, и эта работа также будет выполняться на Opus. Чтобы сохранить пользовательского подагента на меньшей модели, установите `model` в его определении.

Если вы установите модель с `/model` в [неинтерактивном режиме](/docs/ru/headless), с флагом `-p`, ваш выбор применяется только к текущему сеансу и не сохраняется как ваша стандартная; `/model` в этом режиме требует Claude Code версии 2.1.205 или позже. Параметры проекта и управляемые параметры по-прежнему имеют приоритет и переприменяются при следующем запуске. [Стандартная модель организации](#organization-default-model), которую ваш администратор настроил для переопределения выбора пользователя, также переприменяется при следующем запуске.

В версиях 2.1.144 по 2.1.152 `/model` применялся только к текущему сеансу, а `d` в средстве выбора сохранял стандартную.

Флаг `--model` и переменная окружения `ANTHROPIC_MODEL` применяются только к сеансу, который вы запускаете с ними. Чтобы запустить разные модели в разных терминалах одновременно, запустите каждый с его собственным флагом `--model` вместо переключения с `/model`.

Цены в средстве выбора `/model` появляются, когда Claude Code разговаривает с Anthropic API, непосредственно или через [шлюз LLM](/docs/ru/llm-gateway), который его проксирует, и цена в строке — это цена модели, которую выбирает эта строка. На [поставщиках третьих сторон](/docs/ru/third-party-integrations), таких как Amazon Bedrock, и на [шлюзе Claude apps gateway](/docs/ru/claude-apps-gateway), ваш поставщик или шлюз определяет, что вы платите, поэтому строки средства выбора не показывают цену. Цена — это только метка отображения; она не влияет на то, какую модель выбирает строка, или что выставляет ваш поставщик. До версии 2.1.206 [Claude Platform on AWS](/docs/ru/claude-platform-on-aws) и сеансы шлюза показывали цены списка Anthropic, и строка могла показывать цену другой модели, чем та, которую она выбирала.

Возобновлённые сеансы, запущенные с `claude --resume`, `--continue` или средством выбора `/resume`, сохраняют модель, которую они использовали при сохранении стенограммы, независимо от текущего параметра `model`. Если восстановленная модель была снята с производства или исключена [`availableModels`](#restrict-model-selection), сеанс переходит к нормальному порядку приоритета. Это предотвращает изменение модели при возобновлении из-за выбора `/model` другого сеанса. На поставщиках, которые используют ID развёртывания, специфичные для поставщика, а не ID моделей Anthropic, такие как Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry, модель стенограммы вообще не восстанавливается, и сеанс разрешает свою модель через нормальный порядок приоритета.

Модель, которую вы выбираете для нового запуска с `--model` или `ANTHROPIC_MODEL`, по-прежнему имеет приоритет над восстановленной моделью. Начиная с версии 2.1.195, также переменная семейства [`ANTHROPIC_DEFAULT_OPUS_MODEL`](#environment-variables). [`ANTHROPIC_DEFAULT_MODEL`](#set-a-default-model-for-new-sessions) может тоже, при условиях, перечисленных в её разделе.

Когда активная модель при запуске поступает из параметров проекта или управляемых параметров, а не из вашего собственного выбора, заголовок запуска показывает, какой файл параметров её установил. Запустите `/model` для переопределения; параметр проекта или управляемый параметр переприменяется при следующем запуске. На платформах, которые встраивают Claude Code и устанавливают [`CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`](/docs/ru/env-vars), конфигурация модели хоста имеет приоритет над управляемыми параметрами модели, в то время как управляемый список разрешений `availableModels` остаётся в силе, если только хост не предоставляет свой собственный; [Exceptions to managed settings precedence](/docs/ru/settings#exceptions-to-managed-settings-precedence) говорит, какие ключи и переменные переопределяет хост.

Если вы или ваша организация настроите [PreModelSwitch hooks](/docs/ru/hooks#premodelswitch), они запускаются перед применением запрошенного переключения и могут его заблокировать или попросить вас подтвердить.

Когда Claude Code не может определить, какие PreModelSwitch hooks доставляют [управляемые плагины](/docs/ru/settings-reference#enabledplugins) вашей организации, например потому что управляемый плагин не загрузился, он отказывает в переключении вместо его применения, и он проверяет снова при каждой новой попытке. См. [Model switch was blocked by a PreModelSwitch hook](/docs/ru/errors#model-switch-was-blocked-by-a-premodelswitch-hook) для сообщения и восстановления.

Когда вы переключаете модели через метод [Agent SDK](/docs/ru/agent-sdk/overview) `setModel()` или с устройства, подключённого через [Remote Control](/docs/ru/remote-control), или приложение, такое как [Desktop app](/docs/ru/desktop), которое переключает Claude Code CLI для вас, Claude Code проверяет, что строка — это та, которую он распознаёт, перед её сохранением. Эта проверка требует Claude Code версии 2.1.200 или позже. Проверка выбора Remote Control требует Claude Code версии 2.1.260 или позже на вашей машине. В Anthropic API Claude Code распознаёт:

* псевдоним модели
* запись из средства выбора `/model`
* любое имя, которое начинается с `claude-`
* значение, которое вы сами настроили как [пользовательский вариант модели](#add-a-custom-model-option) или в [`modelOverrides`](#override-model-ids-per-version)

Claude Code отклоняет неузнанную строку с `Model "<name>" is not a recognized model id.` и сеанс сохраняет свою текущую модель, вместо сохранения строки и отказа при следующем запросе. См. [справку по ошибкам](/docs/ru/errors#model-is-not-a-recognized-model-id) для шагов восстановления.

Проверка запускается только в Anthropic API. На Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, [Claude Platform on AWS](/docs/ru/claude-platform-on-aws) и за [шлюзом LLM](/docs/ru/llm-gateway) или пользовательским `ANTHROPIC_BASE_URL`, ваш поставщик или шлюз определяет имена моделей, поэтому Claude Code пропускает любую строку без проверки. Проверка также не охватывает флаг `--model`, переменную окружения `ANTHROPIC_MODEL` или параметр `model`; неправильно введённое значение там производит [There's an issue with the selected model](/docs/ru/errors#theres-an-issue-with-the-selected-model) при первом запросе вместо этого. Claude Code по-прежнему может написать [строку диагностики неузнанной модели](/docs/ru/errors#unrecognized-model-id-on-a-request) во время запроса на каждом поставщике.

Когда запрошенная модель имеет запланированную дату снятия с производства или автоматически переназначается на более новую версию, Claude Code показывает предупреждение, которое называет запрошенную модель. Интерактивные сеансы показывают его как уведомление при запуске. Начиная с версии 2.1.182, то же предупреждение записывается в stderr в [неинтерактивном режиме](/docs/ru/headless) при использовании формата вывода текста по умолчанию. Проверка также охватывает `model`, установленный в [frontmatter подагента](/docs/ru/sub-agents). Предупреждение stderr подавляется для `--output-format json` и `stream-json`; прочитайте фактическую модель из поля `modelUsage` [сообщения результата](/docs/ru/headless#get-structured-output) вместо этого.

Например, запустите сеанс на Opus:

```bash theme={null}
claude --model opus
```

Затем переключите модели из сеанса:

```text theme={null}
/model sonnet
```

Пример файла параметров:

```json theme={null}
{
    "permissions": {
        "allow": ["Bash(npm run lint)"]
    },
    "model": "opus"
}
```

<h4 id="set-a-default-model-for-new-sessions">
  Установка стандартной модели для новых сеансов
</h4>

Установите `ANTHROPIC_DEFAULT_MODEL=<alias|name>` для выбора модели, на которой ваши сеансы запускаются по умолчанию. Требует Claude Code версии 2.1.236 или позже.

Claude Code запускает новый сеанс на модели переменной только когда ни один из этих не выбирает модель:

* Флаг `--model`
* `ANTHROPIC_MODEL`
* Значение `model` в любом файле параметров, включая выбор, который вы сохраняете с `/model`
* [Стандартная модель организации](#organization-default-model)

Выбор, который вы сохраняете с `/model`, имеет приоритет над переменной при последующих запусках тоже. С установленным `ANTHROPIC_MODEL` вместо этого Claude Code возвращается к модели переменной при следующем запуске, независимо от того, что вы сохранили с `/model`.

Claude Code также разрешает опцию Default на модель переменной, если не применяется стандартная модель организации. Когда опция Default разрешается на модель переменной, строка Default в средстве выбора `/model` показывает метку Set by ANTHROPIC\_DEFAULT\_MODEL.

Claude Code игнорирует переменную в этих случаях, и опция Default разрешается как если бы вы её не установили:

* Вы установили её на `default`, `inherit`, `opusplan` или `haiku`
* [`enforceAvailableModels`](#enforce-the-allowlist-for-the-default-model) включена
* [`availableModels`](#restrict-model-selection) или [ограничения модели организации](#organization-model-restrictions) исключают модель
* Модель недоступна для вашей учётной записи

Когда новый сеанс запустится на модели переменной, сеанс, который вы возобновляете с `claude --resume`, `--continue` или средством выбора `/resume`, также запустится на ней. Claude Code не восстанавливает модель, сохранённую в стенограмме этого сеанса. В противном случае Claude Code не использует переменную, когда вы [возобновляете сеанс](#setting-your-model).

<h4 id="a-new-session-starts-on-a-different-model-than-you-picked">
  Новый сеанс запускается на другой модели, чем вы выбрали
</h4>

Когда вы выбираете модель с `/model` и ваш следующий сеанс запускается на чём-то другом, это обычные причины:

* **Вы выбрали её для одного сеанса.** Нажатие `s` в средстве выбора, запуск с `--model` и запуск `/model` в неинтерактивном режиме все применяются к текущему сеансу и оставляют вашу сохранённую стандартную без изменений.
* **Что-то с более высоким приоритетом устанавливает модель.** Значение `model` в параметрах проекта или управляемых параметрах, `ANTHROPIC_MODEL` в вашей оболочке или [стандартная модель организации](#organization-default-model), которую ваш администратор установил для переопределения выбора пользователя, применяется снова при каждом запуске. Ваш выбор `/model` по-прежнему сохранён; он лишь уступает по приоритету. Когда параметры проекта или управляемые параметры устанавливают модель, заголовок запуска называет файл.
* **Claude Code не смог сохранить ваш выбор.** `/model` записывает `model` в `~/.claude/settings.json`. Если вы не можете писать в этот файл, например потому что другой инструмент его генерирует или связывает его с копией только для чтения, модель, которую вы выбрали, длится для сеанса, и следующий запуск читает старое значение. Установите `model` в инструменте, который генерирует файл, или сделайте файл доступным для записи. См. [A change you made in Claude Code is lost in new sessions](/docs/ru/settings#a-change-you-made-in-claude-code-is-lost-in-new-sessions).
* **Вы возобновили сеанс.** Сеанс, который вы возобновляете с `claude --resume` или `--continue`, обычно [сохраняет модель, которую он использовал](#setting-your-model), вместо вашей текущей стандартной.

<h2 id="restrict-model-selection">
  Ограничение выбора модели
</h2>

Администраторы предприятия могут использовать `availableModels` в [управляемых или политических параметрах](/docs/ru/managed-settings) для ограничения того, какие модели могут выбирать пользователи. Записи соответствуют семейству моделей, такому как `sonnet`, префиксу версии, такому как `claude-sonnet-4-5`, или полному идентификатору модели, такому как `claude-sonnet-4-5-20250929`. Префикс версии также соответствует более поздним идентификаторам моделей, которые расширяют его еще одним сегментом, поэтому `claude-fable-5` разрешает как Fable 5, так и Fable 5.1, а `claude-fable-5-1` разрешает только Fable 5.1.

На платформах, которые встраивают Claude Code и устанавливают [`CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`](/docs/ru/env-vars), конфигурация модели хоста имеет приоритет над управляемыми параметрами модели, в то время как управляемый список разрешений `availableModels` остается в силе, если только хост не предоставляет свой собственный; [Исключения из приоритета управляемых параметров](/docs/ru/settings#exceptions-to-managed-settings-precedence) указывает, какие ключи и переменные переопределяет хост.

Когда установлен `availableModels`, список разрешений применяется везде, где пользователь может указать модель:

* **Модель основной сессии**: `/model`, флаг `--model`, переменная окружения `ANTHROPIC_MODEL`, параметр `model`, [`ANTHROPIC_DEFAULT_MODEL`](#set-a-default-model-for-new-sessions) и модель, восстановленная при [возобновлении сессии](#setting-your-model)
* **Разрешение псевдонимов**: переменные окружения `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL` и `ANTHROPIC_DEFAULT_FABLE_MODEL` не могут перенаправить разрешенный псевдоним на модель вне списка
* **Быстрый режим**: команда `/fast` отказывает переключаться, когда это неявно переключилось бы на модель Opus вне списка, с сообщением "is not in your organization's allowed models"
* **Модели подагента и товарища**: поле `model` в [подагенте](/docs/ru/sub-agents#choose-a-model) frontmatter, параметр `model` инструмента Agent, модели товарищей [команды агентов](/docs/ru/agent-teams#specify-teammates-and-models), `CLAUDE_CODE_SUBAGENT_MODEL` и, в v2.1.197 и более ранних версиях, средство выбора модели в мастере `/agents`&#x20;
* **Модели навыков и команд**: frontmatter `model` в [навыках и командах](/docs/ru/skills)
* **Модель советника**: настроенный параметр [`advisorModel`](/docs/ru/advisor) и флаг `--advisor`
* **Модель фонового агента**: модель, выбранная в [средстве выбора диспетчеризации](/docs/ru/agent-view)

На Anthropic API и [Claude Platform on AWS](/docs/ru/claude-platform-on-aws) псевдоним семейства моделей, `opus`, `sonnet`, `haiku` или `fable`, разрешается в его обычную модель, когда список разрешений разрешает эту модель. Когда список разрешений блокирует эту модель, Claude Code подставляет самую новую версию семейства, которую разрешает список разрешений, и показывает уведомление с названием как запрошенной, так и подставленной моделей. С `["sonnet", "claude-opus-4-6"]`, например, как `/model opus`, так и `--model opus` выбирают Claude Opus 4.6, самую новую разрешенную версию Opus. До v2.1.205 псевдоним, самая новая выпущенная версия которого была вне списка, отклонялась или заменялась как любой другой заблокированный выбор, даже когда список разрешал более старую версию.

Подстановка требует разрешенную версию для приземления: когда список разрешений не разрешает никакую версию семейства псевдонима, псевдоним следует поведению отклонения и замены ниже, как любое другое заблокированное значение.

Claude Code обрабатывает любой другой заблокированный выбор в соответствии с тем, где была установлена модель:

* **`/model`**: Claude Code отклоняет переключение с ошибкой
* **Флаг `--model`, `ANTHROPIC_MODEL` или параметр `model`**: Claude Code заменяет значение при запуске с предупреждением, называющим как запрошенную, так и подставленную модели, и сессия начинается на модели по умолчанию
* **[`ANTHROPIC_DEFAULT_MODEL`](#set-a-default-model-for-new-sessions)**: Claude Code игнорирует переменную
* **Переопределение подагента или товарища**: Claude Code запускает подагента или товарища на резервной модели, а не отказывает в запросе. См. [Выбор модели](/docs/ru/sub-agents#choose-a-model) для резервной копии подагента и [Указание товарищей и моделей](/docs/ru/agent-teams#specify-teammates-and-models) для резервной копии товарища.

  В интерактивных сессиях Claude Code предупреждает вас, когда он подставляет модель подагента, либо этой резервной копией, либо подстановкой самой новой разрешенной версии выше, называя запрошенную и подставленную модели; он не сообщает о резервной копии товарища.

  Где работает подстановка самой новой разрешенной версии выше, заблокированный псевдоним семейства следует ей вместо этого. До v2.1.222 псевдоним отступал как любое другое заблокированное значение на каждом поставщике
* **Переопределение навыка или команды**: Claude Code игнорирует переопределение, включая заблокированный псевдоним семейства, и навык или команда запускаются на модели сессии. Навык или команда, которая [запускается в подагенте](/docs/ru/skills#run-skills-in-a-subagent), следует поведению подагента выше вместо этого
* **Параметр `advisorModel`**: советник отключен для сессии
* **Флаг `--advisor`**: Claude Code выходит с ошибкой при запуске. В [фоновой сессии](/docs/ru/agent-view) он запускает сессию без советника вместо выхода

Claude Code скрывает исключенные модели из средства выбора `/model`. Полный идентификатор модели в списке, который не имеет встроенной строки средства выбора, такой как более старая версия, которую список закрепляет, появляется в средстве выбора `/model` как его собственная помеченная строка, если только Claude Code не заменяет встроенные параметры на [`modelPicker`](/docs/ru/settings-reference#modelpicker) линейку. До v2.1.199 такой идентификатор был выбираемым только путем ввода `/model <id>`.

Изменения модели, которые Claude Code делает от вашего имени, проверяются таким же образом:

* **[Цепочки резервных моделей](#fallback-model-chains)**: записи вне списка разрешений удаляются
* **Обновления режима Plan**: на Anthropic API и Claude Platform on AWS обновление, такое как [`opusplan`](#opusplan-model-setting) на исключенную модель, использует самую новую разрешенную версию семейства обновления. На поставщиках с идентификаторами моделей, специфичными для поставщика, и когда никакая версия не разрешена, обновление пропускается и планирование продолжается на модели сессии
* **[Автоматический резервный вариант модели](#automatic-model-fallback)**: резервный вариант, целевой объект которого исключен, не запускается, поэтому помеченный запрос заканчивается отказом вместо этого
* **[Классификатор режима Auto](/docs/ru/permission-modes#eliminate-prompts-with-auto-mode)**: значение по умолчанию Claude Sonnet 5 классификатора применяется только когда список разрешений разрешает Sonnet 5. Когда он исключен, классификатор запускается на модели сессии, которую список разрешений уже управляет, или на модели Opus, когда сессия запускается на [модели Fable](#work-with-fable). На поставщиках, отличных от Anthropic API, этот резервный вариант Opus запускается на модели Opus поставщика по умолчанию без консультации со списком разрешений. Требуется Claude Code v2.1.210 или позже
* **[Быстрый режим](/docs/ru/fast-mode)**: включение быстрого режима отказывается, когда модель, на которой сессия будет запускаться впоследствии, находится вне списка разрешений

```json theme={null}
{
  "availableModels": ["sonnet", "haiku"]
}
```

<h3 id="surface-coverage">
  Охват поверхности
</h3>

Каждая поверхность применяет полученный ею список разрешений. Какой механизм доставки достигает каждой поверхности, отличается:

| Механизм доставки                                                                      | CLI и IDE   | Локальные сессии Desktop | Веб-, мобильные и облачные сессии                                                                                                                                                                                                                                            | Agent SDK и неинтерактивные | Cowork                     |
| :------------------------------------------------------------------------------------- | :---------- | :----------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------- | :------------------------- |
| [Управляемые параметры сервера](/docs/ru/server-managed-settings) из консоли администратора | Применяется | Применяется              | Применяется                                                                                                                                                                                                                                                                  | Применяется                 | Не доставляется            |
| [MDM или файлы управляемых параметров](/docs/ru/managed-settings#delivery-mechanisms)       | Применяется | Применяется              | Не доставляется в средах, размещенных Anthropic; в [самостоятельно размещенных средах](/docs/ru/self-hosted-environments) применяется из образа runner согласно [как Claude Code объединяет управляемые источники](/docs/ru/managed-settings#how-claude-code-combines-managed-sources) | Применяется                 | Применяется где развернуто |

* Облачные сессии на [Claude Code в веб](/docs/ru/claude-code-on-the-web), включая те, которые вы запускаете из приложения Desktop, по умолчанию запускаются на управляемых Anthropic виртуальных машинах: параметры, развернутые на вашем устройстве, не достигают их, поэтому доставляйте список разрешений через управляемые параметры сервера. Сессии, которые ваша организация маршрутизирует в [самостоятельно размещенную среду](/docs/ru/self-hosted-environments), запускаются на вашем собственном вычислении и также читают файл управляемых параметров в образе runner. [Как Claude Code объединяет управляемые источники](/docs/ru/managed-settings#how-claude-code-combines-managed-sources) указывает, когда этот файл применяется. Переключение модели в середине сессии в облачной сессии отклоняется, когда запрошенная модель исключена списком разрешений. Когда список `availableModels` в ваших управляемых параметрах сервера не пуст, сервер отклоняет запрос пользователя на запуск облачной сессии на модели, которую список исключает.
* Cowork, вкладка агентской работы в приложении Claude Desktop, запускает свои сессии на Claude Code, но по замыслу не получает управляемые параметры сервера из консоли администратора claude.ai. Файл управляемых параметров применяется к сессиям Cowork, когда он присутствует там, где запускается сессия; удаленные сессии Cowork запускаются на управляемых Anthropic виртуальных машинах, где развернутый на устройстве файл отсутствует.
* Сессии на [поставщиках третьих сторон](/docs/ru/server-managed-settings#platform-availability), таких как Amazon Bedrock, Agent Platform Google Cloud, Microsoft Foundry и [Claude Platform on AWS](/docs/ru/claude-platform-on-aws), не получают управляемые параметры сервера, поэтому доставляйте список разрешений через MDM или файлы управляемых параметров там.
* Доставка, управляемая сервером, также требует, чтобы сессия аутентифицировалась с помощью [подходящего входа или ключа](/docs/ru/server-managed-settings#platform-availability). Флоты, которые генерируют ключи только через скрипт [`apiKeyHelper`](/docs/ru/settings-reference#apikeyhelper), должны доставлять список разрешений через MDM или файлы управляемых параметров.
* Вкладка Desktop Code также размещает [сессии SSH](/docs/ru/desktop#ssh-sessions), которые читают файл управляемых параметров с удаленного хоста, на котором они запускаются. См. [Управляемые параметры Desktop](/docs/ru/desktop#managed-settings).
* Средства выбора модели на claude.ai и в приложении Desktop скрывают или затемняют модели, исключенные списком разрешений вашей организации. Состояние средства выбора — это удобство для пользователей; оно не применяет список разрешений.

<h3 id="default-model-behavior">
  Поведение модели по умолчанию
</h3>

Сам по себе `availableModels` оставляет параметр Default на [значении по умолчанию runtime](#default-model-setting) системы для учетной записи, пока вы также не установите [`enforceAvailableModels`](#enforce-the-allowlist-for-the-default-model). Если это значение по умолчанию — это модель, которую вы намереваетесь ограничить, установите `enforceAvailableModels` также.

Пустой массив `availableModels` никогда не включает применение Default-модели: с `availableModels: []`, именованные выборы моделей блокируются, но модель Default для типа учетной записи остается пригодной для использования независимо от `enforceAvailableModels`.

<h3 id="enforce-the-allowlist-for-the-default-model">
  Применение списка разрешений к модели Default
</h3>

Установите `enforceAvailableModels: true` рядом с непустым `availableModels` в управляемых параметрах, чтобы расширить список разрешений на параметр Default. Это требует Claude Code v2.1.175 или позже.

```json theme={null}
{
  "availableModels": ["sonnet", "haiku"],
  "enforceAvailableModels": true
}
```

Параметр Default разрешается в значение по умолчанию типа учетной записи или в [модель по умолчанию организации](#organization-default-model), когда администратор установил одну. Когда эта модель не находится в списке разрешений, параметр Default вместо этого разрешается в первую запись `availableModels`, которая называет разрешенную, доступную модель, и строка Default средства выбора `/model` показывает эту модель. Это применяется везде, где достигается значение по умолчанию: запуск сессии, выбор Default в `/model`, ключевое слово `"default"` в [цепочках резервных моделей](#fallback-model-chains) и резервный вариант, используемый при удалении исключенного выбора.

`enforceAvailableModels` переназначает параметр Default только когда `availableModels` непуст. С `availableModels: []`, модель Default для типа учетной записи остается пригодной для использования, поэтому параметр не может заблокировать пользователей из каждой модели. Когда `availableModels` непуст, но ни одна запись не разрешается в разрешенную и доступную модель, применение пропускается и Default разрешается в значение по умолчанию типа учетной записи с предупреждением, видимым только под `--debug`. Сохраняйте по крайней мере одну гарантированно доступную запись в списке, чтобы избежать этого.

Развертывайте оба ключа вместе в источнике управляемых параметров с наивысшим рейтингом, который вы доставляете. По умолчанию Claude Code читает только этот источник, поэтому пара, размещенная в файле управляемых параметров, игнорируется, когда консоль администратора доставляет какие-либо параметры; при выборе слияния в [как Claude Code объединяет управляемые источники](/docs/ru/managed-settings#how-claude-code-combines-managed-sources), Claude Code все еще игнорирует карту `modelOverrides` из источника, ранжированного ниже того, который устанавливает `availableModels`.

<h3 id="control-the-model-users-run-on">
  Управление моделью, на которой работают пользователи
</h3>

Параметр `model` — это начальный выбор, а не применение. Он устанавливает, какая модель активна при запуске сессии, но пользователи все еще могут открыть `/model` и выбрать Default, который разрешается в [значение по умолчанию runtime](#default-model-setting) системы независимо от того, что установлено в `model`, если только [`enforceAvailableModels`](#enforce-the-allowlist-for-the-default-model) не перенаправляет его.

Чтобы полностью управлять опытом модели, объедините эти параметры:

* **`availableModels`**: ограничивает, какие именованные модели пользователи могут переключать
* **`enforceAvailableModels`**: расширяет список разрешений `availableModels` на параметр Default, поэтому Default не может разрешиться в модель вне списка
* **`model`**: устанавливает начальный выбор модели при запуске сессии
* **`ANTHROPIC_DEFAULT_SONNET_MODEL`** / **`ANTHROPIC_DEFAULT_OPUS_MODEL`** / **`ANTHROPIC_DEFAULT_HAIKU_MODEL`** / **`ANTHROPIC_DEFAULT_FABLE_MODEL`**: управляют тем, на что разрешаются псевдонимы `sonnet`, `opus`, `haiku` и `fable`, и какую версию использует [значение по умолчанию типа учетной записи](#default-model-setting)

Этот пример запускает пользователей на Sonnet 4.5, ограничивает средство выбора Sonnet и Haiku и гарантирует, что Default разрешается в модель в списке разрешений, а не в значение по умолчанию уровня:

```json theme={null}
{
  "model": "claude-sonnet-4-5",
  "availableModels": ["claude-sonnet-4-5", "haiku"],
  "enforceAvailableModels": true,
  "env": {
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-sonnet-4-5"
  }
}
```

Без `enforceAvailableModels` или блока `env` пользователь, который выбирает Default в средстве выбора, получает [значение по умолчанию runtime](#default-model-setting) вместо версии, закрепленной в `model`. Два параметра охватывают разные области: `enforceAvailableModels` делает Default послушным списку разрешений, в то время как блок `env` закрепляет, на какую версию разрешается разрешенный псевдоним, такой как `sonnet`. Используйте `enforceAvailableModels` отдельно, когда ограничения семейств моделей достаточно; добавьте блок `env`, когда вам также нужно закрепить конкретную версию.

<h3 id="merge-behavior">
  Поведение слияния
</h3>

Когда управляемые параметры, которые применяет Claude Code, определяют `availableModels`, этот список один применяется, кроме [платформы хоста, которая предоставляет свой собственный](/docs/ru/settings#exceptions-to-managed-settings-precedence): записи в параметрах пользователя, проекта или локальных параметрах не могут расширить его, и Claude Code никогда не объединяет `availableModels` между управляемыми источниками либо; [как Claude Code объединяет управляемые источники](/docs/ru/managed-settings#how-claude-code-combines-managed-sources) указывает, какой список источника применяется. В противном случае списки из параметров пользователя, проекта и локальных параметров [объединяются и дедублицируются](/docs/ru/settings#settings-precedence) как другие параметры массива. До Claude Code v2.1.175 записи из областей с более низким приоритетом объединялись с управляемым списком, а не заменялись им.

В пределах эффективного списка запись, называющая конкретную модель в семействе, будь то префикс версии или полный идентификатор модели, отключает запись подстановочного знака семейства: `["sonnet", "claude-sonnet-4-5"]` разрешает только версии Sonnet 4.5, а не каждую модель Sonnet.

<h3 id="mantle-model-ids">
  Идентификаторы моделей Mantle
</h3>

Когда включена [конечная точка Amazon Bedrock Mantle](/docs/ru/amazon-bedrock#use-the-mantle-endpoint), записи в `availableModels`, которые начинаются с `anthropic.`, добавляются в средство выбора `/model` как пользовательские параметры и маршрутизируются на конечную точку Mantle. Это исключение из сопоставления псевдонимов, описанного в [Закрепление моделей для развертываний третьих сторон](#pin-models-for-third-party-deployments). Параметр все еще ограничивает средство выбора перечисленными записями, и идентификатор Mantle встраивает имя семейства, поэтому он считается конкретной записью и отключает подстановочный знак семейства: рядом с любыми идентификаторами Mantle перечислите префиксы версий или полные идентификаторы, которые вы хотите сохранить выбираемыми. См. [Поведение слияния](#merge-behavior).

<h3 id="organization-model-restrictions">
  Ограничения модели организации
</h3>

Администраторы организации на планах Claude Enterprise ограничивают, какие модели могут запускать члены, отключая отдельные модели в консоли администратора claude.ai. Это ограничение доставляется с правами учетной записи, когда Claude Code аутентифицируется, отдельно от любого списка `availableModels` в параметрах, и сервер независимо применяет то же ограничение при создании сессии. Требуется Claude Code v2.1.187 или позже.

Ограничение применяется, когда член входит или использует свой собственный ключ API. Учетные данные в области организации, такие как ключи служб организации, не привязаны к пользователю, поэтому ограничение не применяется к ним.

Claude Console не имеет управления ограничением модели. Организации без плана Claude Enterprise, включая те, члены которых аутентифицируются через Anthropic API, ограничивают модели с помощью [`availableModels`](#restrict-model-selection) в [управляемых параметрах](/docs/ru/managed-settings) вместо этого, добавляя [`enforceAvailableModels`](#enforce-the-allowlist-for-the-default-model) для охвата параметра Default. [Охват поверхности](#surface-coverage) указывает, как каждая поверхность получает и применяет эти параметры.

Ограниченная модель скрыта из средства выбора `/model`. Выбор ее по имени с помощью `--model`, переменной окружения `ANTHROPIC_MODEL` или параметра `model` показывает уведомление `Model "<name>" is restricted by your organization's settings. Using <model> instead.` и сессия запускается на разрешенной модели. Ввод `/model <name>` для ограниченной модели отклоняется с `Model '<name>' is restricted by your organization's settings. Run /model to choose a different model.` и сессия сохраняет свою текущую модель.

[Псевдоним семейства моделей](#restrict-model-selection), такой как `opus`, разрешается в его обычную модель, когда организация его разрешает. Когда организация ограничивает эту модель, Claude Code подставляет самую новую версию семейства, которую организация разрешает, с тем же уведомлением подстановки. `/model <alias>` отклоняется только когда каждая версия его семейства ограничена; псевдоним, установленный с помощью `--model`, `ANTHROPIC_MODEL` или параметра `model`, все еще заменяется при запуске в этом случае. До v2.1.205 псевдоним семейства подставлялся или отклонялся на основе только его самой новой выпущенной версии, даже когда была разрешена более старая версия.

Ограничения применяются на уровне организации или по ролям:

* Отключение модели на уровне организации удаляет ее для каждого члена.
* Доступ на уровне ролей предоставляет разные модели разным пользовательским ролям, и член, который имеет несколько ролей, может использовать любую модель, которую разрешает одна из его ролей.
* Модели Haiku всегда доступны и не могут быть отключены, поэтому каждый член сохраняет по крайней мере одну пригодную для использования модель.
* Изменение доступа вступает в силу на новых запросах в течение примерно минуты; средство выбора `/model` отражает это при следующем запуске сессии.

Оба ограничения применяются вместе: модель выбираемая только когда она разрешена `availableModels` и не ограничена организацией. Ограничения организации достигают сессий на Anthropic API и развертываниях [LLM gateway](/docs/ru/llm-gateway) только; на любом другом поставщике используйте `availableModels` вместо этого.

<h2 id="organization-default-model">
  Модель по умолчанию для организации
</h2>

Администраторы организации на планах Claude Enterprise могут установить модель по умолчанию для членов Claude Code из консоли администратора claude.ai для всей организации или для каждой пользовательской роли. Когда модель установлена, опция Default разрешается в эту модель. Требуется Claude Code v2.1.196 или позже.

Строка Default в средстве выбора `/model` показывает имя организационного значения по умолчанию с меткой Org default. Метка читается как Org default независимо от того, установил ли администратор значение по умолчанию для всей организации или для вашей роли. Значение по умолчанию для роли охватывает членов этой пользовательской роли и имеет приоритет над организационным значением по умолчанию; когда несколько ваших ролей устанавливают разные значения по умолчанию, применяется наиболее мощная модель.

Организационное значение по умолчанию является отправной точкой, а не ограничением. Эти выборы имеют приоритет над ним:

* флаг `--model` и переменная окружения `ANTHROPIC_MODEL`
* значение `model` в [управляемых параметрах](/docs/ru/managed-settings) или предоставленное через `--settings`
* значение `model` в ваших пользовательских, проектных или локальных параметрах, включая модель, которую вы сохраняете с помощью `/model`

Администраторы также могут настроить организационное значение по умолчанию для переопределения выбора пользователя. При включении переопределения оно имеет приоритет над значением `model` в пользовательских, проектных и локальных параметрах, поэтому модель, которую вы сохраняете с помощью `/model`, применяется для текущего сеанса, а организационное значение по умолчанию возвращается при следующем запуске. Когда ваш выбор отличается, `/model` показывает `Your organization's default (<model>) applies on restart`. Флаг `--model`, `ANTHROPIC_MODEL`, управляемые параметры и `--settings` по-прежнему имеют приоритет даже при включенном переопределении. Переопределение доступно для ограниченного набора организаций; обратитесь к команде вашего аккаунта Anthropic для получения информации о доступности.

Чтобы ограничить, какие модели могут выбирать члены, используйте вместо этого [ограничения модели организации](#organization-model-restrictions) или [`availableModels`](#restrict-model-selection).

Claude Code читает организационное значение по умолчанию один раз при запуске, поэтому значение по умолчанию, которое администратор изменяет во время сеанса, вступает в силу при следующем запуске.

Когда организационное значение по умолчанию не переопределяет выбор пользователя, первый интерактивный запуск после изменения администратором очищает ключ `model` из ваших пользовательских параметров один раз, чтобы применилось новое значение по умолчанию. Это не изменяет ничего другого в файле, и модель, которую вы сохраняете с помощью `/model` после этого запуска, сохраняется.

Организационное значение по умолчанию проходит эти проверки ограничений перед его принятием:

* [`availableModels`](#restrict-model-selection) сам по себе не применяется к организационному значению по умолчанию, поэтому организационное значение по умолчанию вне списка разрешений по-прежнему применяется. Когда также установлен [`enforceAvailableModels`](#enforce-the-allowlist-for-the-default-model), организационное значение по умолчанию вне списка разрешений переназначается первой записи списка разрешений, как и любое другое Default
* организационное значение по умолчанию, которое [ограничения модели организации](#organization-model-restrictions) запрещают для вашего аккаунта, заменяется самой новой разрешенной моделью в его семействе или моделью с более низкой стоимостью, когда каждая версия ее ограничена
* организационное значение по умолчанию, которое вообще недоступно для вашего аккаунта, пропускается, и опция Default разрешается так, как это было бы [без организационного значения по умолчанию](#default-model-setting)

Начиная с v2.1.199, когда организационное значение по умолчанию является другим семейством моделей от обычного значения по умолчанию типа вашего аккаунта, средство выбора `/model` сохраняет отдельную строку для этого обычного семейства, чтобы вы все еще могли переключиться на него для сеанса. В версиях v2.1.196 по v2.1.198 эта строка отсутствует в средстве выбора.

Организационное значение по умолчанию достигает только сеансов, аутентифицированных с помощью Anthropic API. Чтобы установить значение по умолчанию где-либо еще, включая развертывания [LLM gateway](/docs/ru/llm-gateway), используйте вместо этого ключ `model` в [управляемых параметрах](/docs/ru/managed-settings).

<h2 id="organization-effort-limits">
  Ограничения уровня усилий организации
</h2>

Ваша организация может ограничить [уровень усилий](#adjust-effort-level) двумя способами. В плане Claude Enterprise администраторы организации устанавливают ограничения уровня усилий для каждой роли, описанные ниже. В любом плане и у любого поставщика, включая Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry, управляемый параметр [`maxEffortLevel`](/docs/ru/settings-reference#maxeffortlevel) ограничивает усилия на стороне клиента. Когда оба ограничения применяются к модели, действует более низкий лимит.

Администраторы организации в планах Claude Enterprise могут установить максимальный [уровень усилий](#adjust-effort-level) для каждой модели для каждой пользовательской роли, наряду с ограничениями модели на уровне роли [организации](#organization-model-restrictions). Уровни выше лимита не предлагаются в средстве выбора `/effort`, а указание более высокого уровня с помощью `--effort` или `/effort` выполняется на уровне лимита вместо этого. В интерактивных сеансах и обычных текстовых запусках `--print` предупреждение указывает запрошенные и применённые уровни; при выводе `json` или `stream-json` или в фоновых агентах ограничение применяется без уведомления. Ограничения действуют для каждой модели, поэтому переключение моделей может изменить доступные уровни. Когда несколько ваших ролей предоставляют одну и ту же модель, применяется наименее ограничивающий лимит. Требуется Claude Code v2.1.195 или более поздняя версия.

Ограничения уровня усилий доставляются вместе с [ограничениями модели организации](#organization-model-restrictions) и достигают одних и тех же сеансов.

<h2 id="special-model-behavior">
  Специальное поведение модели
</h2>

<h3 id="default-model-setting">
  Параметр модели `default`
</h3>

Поведение `default` зависит от типа вашей учетной записи:

* **Pro, Max, Team, Enterprise и Anthropic API**: по умолчанию Opus 5.5
* **Claude Platform on AWS, Amazon Bedrock и Google Cloud's Agent Platform**: по умолчанию Opus 5.5
* **Microsoft Foundry**: по умолчанию Sonnet 4.5

До версии 2.1.280 `default` разрешался в Sonnet 5 на Pro и Team Standard, а в Opus 5 на Max, Team Premium, Enterprise, Anthropic API, Claude Platform on AWS, Amazon Bedrock и Google Cloud's Agent Platform с версии 2.1.219. До версии 2.1.219 `default` разрешался в Opus 4.8 на Anthropic API, Max, Team Premium и Enterprise с оплатой по мере использования с версии 2.1.154, а также на Claude Platform on AWS, Amazon Bedrock и Google Cloud's Agent Platform с версии 2.1.207. До версии 2.1.207 `default` разрешался в Opus 4.7 на Claude Platform on AWS и в Sonnet 4.5 на Amazon Bedrock и Google Cloud's Agent Platform.

Когда администратор установил [модель по умолчанию организации](#organization-default-model), `default` разрешается в эту модель вместо стандартного значения для типа учетной записи выше. Требуется Claude Code версии 2.1.196 или позже. `default` также может разрешаться в модель, которую вы установили с помощью [`ANTHROPIC_DEFAULT_MODEL`](#set-a-default-model-for-new-sessions), при условиях, указанных в его разделе.

Когда управляемые параметры [применяют список разрешений для модели Default](#enforce-the-allowlist-for-the-default-model) и стандартное значение для типа учетной записи отсутствует в `availableModels`, `default` разрешается в принудительный Default вместо стандартного значения для типа учетной записи выше. Когда применяются оба условия, модель по умолчанию организации сначала заменяет стандартное значение для типа учетной записи, а затем применяется принудительное значение: модель по умолчанию организации в списке разрешений сохраняется, а модель вне списка разрешается в принудительный Default.

Модели Fable не являются стандартным значением для типа учетной записи ни на одном плане или поставщике. Выбор одной с помощью `/model` сохраняет ее как выбранную модель в параметрах пользователя, поэтому более поздние сеансы начинаются с нее. Для одноразового изменения, которое Claude Code вносит в сохраненный выбор Fable 5 в версии 2.1.257, см. [Работа с Fable](#work-with-fable).

<h3 id="opusplan-model-setting">
  Параметр модели `opusplan`
</h3>

Псевдоним модели `opusplan` обеспечивает автоматизированный гибридный подход:

* **В режиме плана**: использует `opus` для сложного рассуждения и решений по архитектуре
* **В режиме выполнения**: автоматически переключается на `sonnet` для генерации кода и реализации

Это сочетает рассуждение Opus для планирования с эффективностью Sonnet для выполнения.

Фаза Opus в режиме плана использует то же окно контекста, что и параметр модели `opus`, а фаза выполнения использует то же окно, что и `sonnet`. Когда `opus` и `sonnet` разрешаются в модели, которые работают с [окном контекста 1M](#extended-context) по умолчанию, как это делают текущие модели на Anthropic API, обе фазы работают с ним. Чтобы запросить контекст 1M для обеих фаз, где они этого не делают, [установите модель](#setting-your-model) на `opusplan[1m]`, например с помощью `/model opusplan[1m]`. Установка с помощью `/model` требует Claude Code версии 2.1.265 или позже; в более ранних версиях используйте флаг `--model` или параметр `model` вместо этого.

Когда [`availableModels`](#restrict-model-selection) исключает новейший Opus, но разрешает более старую версию, например `["sonnet", "claude-opus-4-6"]`, `opusplan` использует новейший разрешенный Opus для планирования и остается только на Sonnet, когда исключены все версии Opus. Сеанс Haiku, который обычно обновляется до Sonnet в режиме плана, аналогично использует новейший разрешенный Sonnet и остается на Haiku только когда исключены все версии Sonnet. До версии 2.1.205 режим плана оставался на модели сеанса всякий раз, когда исключалась новейшая версия семейства обновлений, даже когда список разрешений разрешал более старую версию.

Подстановка более старой разрешенной версии применяется на Anthropic API и [Claude Platform on AWS](/docs/ru/claude-platform-on-aws). На Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry и Mantle, развертывания которых используют специфичные для поставщика идентификаторы моделей, режим плана остается на модели сеанса всякий раз, когда модель обновления исключена.

Для гибридного подхода, при котором Claude решает во время выполнения задачи, когда обратиться ко второй модели, а не переключаться на границе плана, см. [инструмент advisor](/docs/ru/advisor).

<h3 id="fallback-model-chains">
  Цепочки резервных моделей
</h3>

Когда основная модель перегружена, недоступна или возвращает другую неповторяемую ошибку сервера, Claude Code может переключиться на резервную модель вместо отказа в запросе. Ошибки аутентификации, выставления счетов, ограничения скорости, размера запроса и транспорта, а также [отказ в соответствии с проверкой политики вашей организации](/docs/ru/errors#automatic-retries), никогда не вызывают переключение; они следуют обычной обработке повторных попыток и ошибок.

Настройте одну или несколько резервных моделей, и Claude Code попробует их по порядку, показывая уведомление при переключении. Переключение длится только для текущего хода, поэтому ваше следующее сообщение сначала попробует основную модель снова. Claude Code ограничивает цепочки тремя моделями после удаления дубликатов и игнорирует дополнительные записи.

Установите цепочку для одного сеанса с флагом `--fallback-model`, который принимает список, разделенный запятыми:

```bash theme={null}
claude --fallback-model sonnet,haiku
```

Чтобы сохранить цепочку между сеансами, установите `fallbackModel` в [параметрах](/docs/ru/settings) как массив:

```json theme={null}
{
  "fallbackModel": ["claude-sonnet-5", "claude-haiku-4-5"]
}
```

Флаг `--fallback-model` имеет приоритет над параметром `fallbackModel`. Каждая запись принимает имя модели или псевдоним, и `"default"` расширяется до модели по умолчанию.

Claude Code не подтверждает цепочку при запуске, и `/status` не отображает ее. Уведомление, показываемое при переключении, является первым видимым признаком того, что резервная модель настроена.

Когда запрос переходит в режим отказа, Claude Code пробует каждую запись по порядку, пока одна не примет ее. Запись, которая также не может быть достигнута, например снятая с производства модель, закрепленная в параметрах, переходит в режим отказа к следующей таким же образом. Claude Code удаляет два типа записей перед этим проходом:

* **Вне списка разрешений**: Claude Code удаляет любую запись, не разрешенную [`availableModels`](#restrict-model-selection), когда читает цепочку.
* **Меньшее окно контекста во время компактирования**: цепочка также охватывает [компактирование](/docs/ru/context-window#what-survives-compaction), но Claude Code не будет переходить в режим отказа на модель с меньшим окном контекста, чем у основной, так как суммирование там сначала отрежет часть разговора. Если все резервные модели меньше, компактирование показывает исходную ошибку и вы можете повторить попытку.

Claude Code также применяет цепочку к [подагентам](/docs/ru/sub-agents). Когда запрос подагента переходит в режим отказа, Claude Code пробует ваши настроенные резервные модели по порядку, и подагент продолжает работу на модели, которая принимает запрос. Модель вашего сеанса не изменяется. До версии 2.1.247 отказ, который охватывает цепочка, завершал подагента.

<h3 id="automatic-model-fallback">
  Автоматический резервный вариант модели
</h3>

Этот раздел охватывает резервный вариант на основе содержимого из моделей Fable, Opus 5.5 и Opus 5. Для резервного варианта на основе доступности, когда модель перегружена или недоступна, см. [Цепочки резервных моделей](#fallback-model-chains).

Модели Fable, Opus 5.5 и Opus 5 работают с классификаторами безопасности, которые чаще всего отмечают содержимое кибербезопасности и биологии. Когда классификатор отмечает запрос и отмеченная категория имеет резервную модель, Claude Code повторно запускает запрос на этой модели и показывает уведомление в стенограмме. Для этих двух категорий резервная модель зависит от того, какая модель отказала:

* **Fable 5.1, Fable 5 и Opus 5.5**: запросы, отмеченные биологией, повторно запускаются на Opus 5, а запросы, отмеченные кибербезопасностью, повторно запускаются на Opus 4.8.
* **Opus 5**: запросы, отмеченные кибербезопасностью, повторно запускаются на Opus 4.8. Запросы, отмеченные биологией, заканчиваются отказом, потому что Opus 5 запускает свои собственные классификаторы биологии без резервной модели.

На Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry Claude Code разрешает эти цели через ваше развертывание, и если вы установите `ANTHROPIC_DEFAULT_OPUS_MODEL`, категории, которые имеют резервный вариант, повторно запускаются на закрепленной модели; см. [Включение резервного варианта на Bedrock, Agent Platform и Foundry](#enable-fallback-on-bedrock-agent-platform-and-foundry).

После резервного варианта сеанс продолжается на резервной модели. Чтобы вернуться к исходной модели, запустите [`/model`](#setting-your-model).

Резервный вариант на основе категории требует Claude Code версии 2.1.219 или позже. До версии 2.1.219 каждый отмеченный запрос Fable 5 повторно запускался на модели Opus по умолчанию вашего поставщика, и Opus 5 не был источником резервного варианта.

Резервная модель проверяется против [`availableModels`](#restrict-model-selection). Когда она заблокирована, резервный вариант не происходит. Отказ показывается как обычная ошибка, и модель сеанса не изменяется.

<h4 id="check-what-triggered-fallback">
  Проверка того, что вызвало резервный вариант
</h4>

Резервный вариант может быть вызван при первом запросе сеанса, прежде чем вы отправите что-либо необычное, потому что первый запрос содержит контекст рабочей области, такой как содержимое вашего CLAUDE.md и статус git. Репозиторий, содержащий материал по безопасности или биологии, может активировать классификатор только на этом контексте.

Чтобы проверить, являются ли настройки триггером, запустите сеанс с `claude --safe-mode`, который отключает настройки, такие как CLAUDE.md, skills, MCP серверы и hooks. Статус Git и имена каталогов не являются настройками и по-прежнему включены.

<h4 id="ask-before-switching">
  Запрос перед переключением
</h4>

Чтобы решить, что происходит каждый раз, когда запрос отмечается, вместо автоматического переключения, запустите `/config` и отключите **Switch models when a message is flagged**, или установите [`switchModelsOnFlag`](/docs/ru/settings-reference#switchmodelsonflag) на `false` в файле параметров. Отмеченный запрос затем приостанавливает сеанс с двумя вариантами: переключиться на резервную модель или отредактировать подсказку и повторить попытку на текущей модели.

Некоторые случаи ведут себя иначе:

* Когда отмеченная категория не имеет резервной модели, такой как флаг биологии на Opus 5, Claude Code не показывает подсказку и запрос заканчивается отказом.
* Если обе модели отмечают один и тот же запрос, вы можете отредактировать подсказку и повторить попытку, или начать новый сеанс.
* На мобильных сеансах [Claude Code в веб-браузере](/docs/ru/claude-code-on-the-web) редактирование и повторная попытка не поддерживаются. Переключите модели или продолжите сеанс из браузера рабочего стола или приложения рабочего стола.
* В [неинтерактивном режиме](/docs/ru/cli-reference#cli-flags) и интеграциях SDK, которые не могут показать подсказку, отмеченный запрос завершает ход с отказом.
* Когда цель резервного варианта заблокирована [`availableModels`](#restrict-model-selection), Claude Code не показывает подсказку. Отмеченный запрос заканчивается отказом, так же как автоматический резервный вариант, когда цель заблокирована.

<h4 id="enable-fallback-on-bedrock-agent-platform-and-foundry">
  Включение резервного варианта на Bedrock, Agent Platform и Foundry
</h4>

На [Amazon Bedrock](/docs/ru/amazon-bedrock), [Google Cloud's Agent Platform](/docs/ru/google-vertex-ai) и [Microsoft Foundry](/docs/ru/microsoft-foundry) идентификаторы моделей специфичны для поставщика, поэтому автоматический резервный вариант работает только когда Claude Code может идентифицировать обе задействованные модели:

* Claude Code должен распознавать текущую модель как источник резервного варианта. Fable 5.1 и Fable 5 распознаются, когда идентификатор модели содержит `claude-fable-5`, соответствует значению `ANTHROPIC_DEFAULT_FABLE_MODEL` или сопоставляется с [`modelOverrides`](#override-model-ids-per-version). Opus 5.5 и Opus 5 распознаются по их идентификатору модели поставщика или сопоставлению [`modelOverrides`](#override-model-ids-per-version).
* Резервная модель должна разрешаться в вашем развертывании. Если вы установите `ANTHROPIC_DEFAULT_OPUS_MODEL`, отмеченные запросы повторно запускаются на этой модели для каждой категории, которая имеет резервный вариант; флаг биологии на Opus 5 по-прежнему заканчивается отказом. Если вы не установите его, запросы, отмеченные кибербезопасностью, повторно запускаются на записи Opus 4.8 в списке моделей поставщика, а запросы, отмеченные биологией, из модели Fable или Opus 5.5 на записи Opus 5.

Если какая-либо модель не может быть идентифицирована, Claude Code не переключается автоматически. Отмеченный запрос заканчивается сообщением об отказе, и вы можете переключить модели с помощью [`/model`](#setting-your-model) и повторить попытку. Установка `ANTHROPIC_DEFAULT_FABLE_MODEL` на идентификатор вашей модели Fable включает распознавание Fable. Установка `ANTHROPIC_DEFAULT_OPUS_MODEL` на идентификатор модели Opus дает отмеченным категориям цель резервного варианта, если только закрепление не называет модель вне семейства Opus или модель, которая отказала; затем Claude Code не переключается и отказ остается в силе.

<h4 id="security-research-and-biology-workloads">
  Исследование безопасности и рабочие нагрузки биологии
</h4>

Рабочие нагрузки в наступательной безопасности или биологии, включая тестирование на проникновение, упражнения Capture the Flag (CTF) и кодовые базы, смежные с биологией, часто вызывают резервный вариант, часто при первом запросе. Для существенной работы по биологии на Fable 5.1, Fable 5 или Opus 5.5 Claude Code перемещает сеанс на Opus 5 при первом отмеченном запросе, и более поздние запросы, отмеченные биологией, заканчиваются отказами там, потому что Opus 5 не имеет резервного варианта биологии. На Opus 5 вы получаете эти отказы с первого отмеченного запроса.

Это ожидаемая маршрутизация для этих областей, а не флаг учетной записи. Если вашей организации требуется возможность класса Fable для этой работы, обратитесь к команде учетной записи Anthropic о программах доверенного доступа.

<h3 id="adjust-effort-level">
  Регулировка уровня усилий
</h3>

[Уровни усилий](https://platform.claude.com/docs/en/build-with-claude/effort) управляют адаптивным рассуждением, которое позволяет модели решать, нужно ли и сколько думать на каждом шаге в зависимости от сложности задачи. Более низкие усилия быстрее и дешевле для простых задач, в то время как более высокие усилия обеспечивают более глубокое рассуждение для сложных проблем.

Доступные уровни усилий зависят от модели. Модели, не указанные здесь, не поддерживают усилия:

| Модель                                          | Уровни                                  |
| :---------------------------------------------- | :-------------------------------------- |
| Fable 5.1 и Fable 5                             | `low`, `medium`, `high`, `xhigh`, `max` |
| Opus 5.5, Opus 5, Sonnet 5, Opus 4.8 и Opus 4.7 | `low`, `medium`, `high`, `xhigh`, `max` |
| Opus 4.6 и Sonnet 4.6                           | `low`, `medium`, `high`, `max`          |

Если вы установите уровень, который активная модель не поддерживает, Claude Code переходит на наивысший поддерживаемый уровень на или ниже установленного. Например, `xhigh` работает как `high` на Opus 4.6. Ваша организация или ваши собственные параметры также могут ограничивать уровни, которые предлагает модель; см. [Ограничения усилий организации](#organization-effort-limits).

С параметром [`ultracode`](/docs/ru/settings-reference#ultracode) отключенным, Claude Code разрешает уровень усилий сеанса в этом порядке, принимая первый применимый:

1. Явный выбор: переменная окружения [`CLAUDE_CODE_EFFORT_LEVEL`](/docs/ru/env-vars#variables), запуск с `--effort` или `/effort` в сеансе ([неинтерактивный `/effort` имеет более узкий эффект](#non-interactive-effort))
2. Ваши параметры: уровень, который вы сохранили для модели или ключ [`effortLevel`](/docs/ru/settings-reference#effortlevel), с приоритетом между ними и между файлами параметров, указанным в [`modelSettings`](/docs/ru/settings-reference#modelsettings)
3. Уровень усилий модели по умолчанию: `high` на каждой модели, которая поддерживает усилия, за исключением того, что Opus 5.5 по умолчанию имеет `medium`, Opus 4.7 по умолчанию имеет `xhigh` и, когда ваша организация устанавливает уровень усилий по умолчанию для своей [модели по умолчанию организации](#organization-default-model), этот уровень является стандартным при запуске этой модели

Opus 5.5 начинает с `medium`, если один из источников выше не устанавливает уровень для него, и верхний уровень `effortLevel` в файле параметров пользователя не считается для Opus 5.5. Этот ключ — это более старая форма, которую `/effort` писал перед тем, как Claude Code сохранял уровни для каждой модели: он продолжает применяться там, где применялся раньше, на Opus 5, Fable 5.1 и более ранних моделях, в то время как Opus 5.5 и модели, выпущенные после него, начинают со своего собственного стандарта, пока вы не выберете уровень для них с помощью `/effort` или средства выбора `/model`. Верхний уровень `effortLevel` в параметрах проекта, локальных или управляемых параметрах, или переданный с `--settings`, применяется к каждой модели.

Когда вы устанавливаете `low`, `medium`, `high` или `xhigh` в интерактивном сеансе на вашей машине, вы выбираете, как долго это длится, подтверждая это:

* `Enter` в ползунке `/effort` или средстве выбора `/model`, или уровень, введенный после `/effort`: сохраните уровень как стандартный и примените его в более поздних сеансах
* `s` в ползунке `/effort` или средстве выбора `/model`: примените уровень только к этому сеансу. Требуется Claude Code версии 2.1.257 или позже

Claude Code сохраняет уровень для каждой модели под ключом [`modelSettings`](/docs/ru/settings-reference#modelsettings) в параметрах пользователя, поэтому каждая модель сохраняет свой собственный уровень.

`max` — это самый глубокий уровень рассуждения. Если вы не установите его через переменную окружения `CLAUDE_CODE_EFFORT_LEVEL`, Claude Code применяет `max` только к текущему сеансу.

<Note>
  Уровень, который вы выбираете из управления усилиями на телефоне или в браузере, подключенном через [Remote Control](/docs/ru/remote-control#what-connected-devices-see), применяется только к этому сеансу.
</Note>

<span id="non-interactive-effort" />

Когда вы устанавливаете уровень с `/effort` в запуске [`-p`](/docs/ru/headless), Claude Code применяет его только к этому сеансу и не сохраняет его как стандартный.

Меню `/effort` также предлагает `ultracode`. Ultracode — это параметр Claude Code, а не уровень усилий модели: он отправляет `xhigh` модели и дополнительно имеет Claude оркестрирует [динамические рабочие процессы](/docs/ru/workflows) для существенных задач. Для того, где это можно установить постоянно, см. параметр [`ultracode`](/docs/ru/settings-reference#ultracode).

Вы можете включить ultracode через любое из следующего:

* **`/effort`**: запустите `/effort ultracode` или выберите его из меню
* **Флаг `--effort`**: запустите с `claude --effort ultracode`, который запускает сеанс с усилиями `xhigh` и включенным ultracode
* **Параметр `ultracode`**: установите [`"ultracode": true`](/docs/ru/settings-reference#ultracode) в файле параметров, с `--settings` или в запросе управления Agent SDK. Запрос [`applyFlagSettings()`](/docs/ru/agent-sdk/typescript#applyflagsettings) также принимает `effortLevel: "ultracode"`
* **Средство выбора `/model`**: переместите ползунок усилий на `ultracode` с помощью клавиш со стрелками, пока вы выбираете модель. Claude Code включает его для текущего сеанса, даже когда вы сохраняете эту модель как стандартную

Передача `ultracode` флагу `--effort` или значению Agent SDK `effortLevel` требует Claude Code версии 2.1.203 или позже. До версии 2.1.203 `--effort ultracode` печатал `Unknown --effort value 'ultracode'` и сеанс начинался с усилиями по умолчанию.

Сохраненный параметр `effortLevel` и переменная окружения `CLAUDE_CODE_EFFORT_LEVEL` не принимают `ultracode`. Когда `CLAUDE_CODE_EFFORT_LEVEL` установлен на уровень, отличный от `xhigh`, запросы работают на этом уровне, и оркестрация рабочего процесса ultracode остается неактивной. Выбор ultracode затем показывает предупреждение, что переменная окружения переопределяет усилия для сеанса.

<span id="when-ultracode-is-available" />

Ultracode недоступен, когда:

* [Рабочие процессы отключены](/docs/ru/workflows#turn-workflows-off)
* Модель не поддерживает усилия `xhigh`
* [Ограничение усилий](#organization-effort-limits) ниже `xhigh` применяется к модели

В этих случаях `--effort ultracode` запускает сеанс с отключенным ultracode, на наивысшем уровне усилий, который модель и любое ограничение позволяют, вплоть до `xhigh`.

<h4 id="choose-an-effort-level">
  Выбор уровня усилий
</h4>

Каждый уровень торгует расходом токенов против возможности. Стандартный уровень подходит для большинства задач кодирования; регулируйте, когда вы хотите другой баланс.

| Уровень     | Когда его использовать                                                                                                                                               |
| :---------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `low`       | Зарезервируйте для коротких, ограниченных, чувствительных к задержкам задач, которые не требуют интеллекта                                                           |
| `medium`    | Снижает использование токенов для работы, чувствительной к затратам, которая может пожертвовать некоторым интеллектом. Стандартный на Opus 5.5                       |
| `high`      | Балансирует использование токенов и интеллект. Стандартный на каждой модели, кроме Opus 5.5 и Opus 4.7                                                               |
| `xhigh`     | Более глубокое рассуждение при более высоких расходах токенов. Стандартный на Opus 4.7                                                                               |
| `max`       | Может улучшить производительность на сложных задачах, но может показать убывающую отдачу и склонен к чрезмерному размышлению. Протестируйте перед широким внедрением |
| `ultracode` | Параметр Claude Code, который планирует [динамический рабочий процесс](/docs/ru/workflows) для каждой существенной задачи с рассуждением `xhigh` для каждого сообщения    |

Шкала усилий откалибрована для каждой модели, поэтому одно и то же имя уровня не представляет одно и то же базовое значение между моделями.

<h4 id="use-ultrathink-for-one-off-deep-reasoning">
  Использование ultrathink для одноразового глубокого рассуждения
</h4>

Включите `ultrathink` в любое место вашей подсказки, чтобы запросить более глубокое рассуждение на этом ходе без изменения параметра усилий сеанса. Claude Code распознает ключевое слово и добавляет встроенную инструкцию. Уровень усилий, отправленный в API, не изменяется. Claude Code передает другие фразы, такие как "think", "think hard" и "think more", как обычный текст подсказки и не распознает их как ключевые слова.

<h4 id="set-the-effort-level">
  Установка уровня усилий
</h4>

Вы можете изменить усилия через любое из следующего:

* **`/effort`**: запустите `/effort` без аргументов, чтобы открыть интерактивный ползунок, `/effort`, за которым следует имя уровня, чтобы установить его напрямую, или `/effort auto`, чтобы очистить сохраненный уровень для активной модели. Вы можете запустить его, пока Claude работает, и после подтверждения [предупреждения о кэше](/docs/ru/prompt-caching#changing-effort-level), если Claude Code показывает его, Claude Code применяет новый уровень к следующему запросу в ходе
* **В `/model`**: используйте клавиши со стрелками влево/вправо, чтобы отрегулировать ползунок усилий при выборе модели
* **Флаг `--effort`**: передайте имя уровня, чтобы установить его для одного сеанса при запуске Claude Code
* **Переменная окружения**: установите `CLAUDE_CODE_EFFORT_LEVEL` на имя уровня или `auto`
* **Параметры**: установите уровень для каждой модели в [`modelSettings`](/docs/ru/settings-reference#modelsettings) или установите [`effortLevel`](/docs/ru/settings-reference#effortlevel) на `low`, `medium`, `high` или `xhigh` как стандартный для моделей без одного. `max` не принимается как уровень ни в одном ключе, и `ultracode` имеет свой собственный ключ [`ultracode`](/docs/ru/settings-reference#ultracode)
* **С подключенного устройства**: в сеансе [Remote Control](/docs/ru/remote-control#what-connected-devices-see) выберите уровень из управления усилиями на вашем телефоне или в браузере. Уровень применяется только к текущему сеансу. Требуется Claude Code версии 2.1.234 или позже
* **Frontmatter skill и subagent**: установите `effort` в файле markdown [skill](/docs/ru/skills#frontmatter-reference) или [subagent](/docs/ru/sub-agents#supported-frontmatter-fields), чтобы переопределить уровень усилий при запуске этого skill или subagent

Frontmatter усилия применяются, когда этот skill или subagent активен, переопределяя уровень сеанса, но не переменную окружения. [`maxEffortLevel`](/docs/ru/settings-reference#maxeffortlevel) или [ограничение усилий организации](#organization-effort-limits) по-прежнему ограничивает уровень, на котором работает skill или subagent.

Если вы установите `effortLevel` в [управляемых параметрах](/docs/ru/managed-settings), Claude Code применяет его на этапе параметров [порядка разрешения усилий](#adjust-effort-level), и пользователи все еще могут изменять уровень с помощью `/effort` или `--effort`. Чтобы держать пользователей на или ниже уровня, установите [`maxEffortLevel`](/docs/ru/settings-reference#maxeffortlevel).

Ползунок усилий появляется в `/model`, когда выбрана поддерживаемая модель. Текущий уровень усилий также показывается в заголовке сеанса рядом с именем модели, например "with low effort", поэтому вы можете подтвердить, какой параметр активен, без открытия `/model`. Нижний колонтитул также кратко показывает уровень усилий при запуске и при его изменении.

<h4 id="adaptive-reasoning-and-fixed-thinking-budgets">
  Адаптивное рассуждение и фиксированные бюджеты размышления
</h4>

Адаптивное рассуждение делает размышление необязательным на каждом шаге, поэтому Claude может быстрее реагировать на обычные подсказки и зарезервировать более глубокое размышление для шагов, которые от него выигрывают. Если вы хотите, чтобы Claude думал чаще или реже, чем производит текущий уровень, вы можете сказать об этом прямо в своей подсказке или в `CLAUDE.md`; модель реагирует на это руководство в рамках своего параметра усилий.

Модели Fable, Sonnet 5 и Opus 4.7 и позже всегда используют адаптивное рассуждение. Режим фиксированного бюджета размышления и `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING` не применяются к ним.

На Opus 4.6 и Sonnet 4.6 вы можете установить `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING=1`, чтобы вернуться к предыдущему фиксированному бюджету размышления, контролируемому `MAX_THINKING_TOKENS`. См. [переменные окружения](/docs/ru/env-vars).

<h3 id="extended-thinking">
  Расширенное размышление
</h3>

Расширенное размышление — это рассуждение, которое Claude выдает перед ответом. На моделях, которые поддерживают [адаптивное рассуждение](#adjust-effort-level), уровень усилий является основным управлением тем, сколько размышления происходит; параметры ниже включают или отключают размышление и управляют тем, как оно отображается. С отключенным размышлением на Anthropic API Claude Code отправляет усилия `high` вместо более высокого уровня моделям, которые он знает [не принимают эту комбинацию](/docs/ru/errors#effort-isnt-available-with-thinking-turned-off), такие как Opus 5.

| Управление                            | Как его установить                                                                                                                                                                                                                                                                                                                                                                                                               |
| :------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Переключение для текущего сеанса      | Нажмите `Option+T` на macOS или `Alt+T` на Windows и Linux                                                                                                                                                                                                                                                                                                                                                                       |
| Установка глобального стандартного    | Запустите `/config` и переключите режим размышления. Сохранено как `alwaysThinkingEnabled` в `~/.claude/settings.json`                                                                                                                                                                                                                                                                                                           |
| Отключение через переменную окружения | Установите [`MAX_THINKING_TOKENS=0`](/docs/ru/env-vars), что отключает размышление на Anthropic API, кроме Opus 5.5 и моделей Fable. На [сторонних поставщиках](/docs/ru/third-party-integrations) Claude Code опускает параметр `thinking` вместо этого, и модели адаптивного рассуждения все еще могут думать. Другие значения применяются только с [фиксированным бюджетом размышления](#adaptive-reasoning-and-fixed-thinking-budgets) |

Вы не можете отключить размышление на Opus 5.5 или моделях Fable. Переключение сеанса, `alwaysThinkingEnabled` и `MAX_THINKING_TOKENS=0` не имеют эффекта там, и модель решает на каждом шаге, сколько думать на основе уровня усилий.

Claude Code сворачивает вывод размышления по умолчанию. Нажмите `Ctrl+O`, чтобы переключить подробный режим и увидеть рассуждение как серый курсивный текст. Интерактивные сеансы на Anthropic API получают отредактированные блоки размышления по умолчанию, поэтому установите `showThinkingSummaries: true` в [параметрах](/docs/ru/settings), если вы хотите, чтобы полные резюме были доступны при расширении. Вам выставляется счет за все сгенерированные токены размышления, даже когда они свернуты или отредактированы.

<h3 id="extended-context">
  Расширенный контекст
</h3>

Fable 5.1, Fable 5, Sonnet 5, Opus 4.6 и позже, а также Sonnet 4.6 поддерживают [окно контекста в 1 миллион токенов](https://platform.claude.com/docs/en/build-with-claude/context-windows#context-window-sizes-by-model) для длительных сеансов с большими кодовыми базами.

На Anthropic API Fable 5.1, Fable 5, Sonnet 5 и Opus 4.7 и позже работают с окном 1M по умолчанию на каждом плане, включая Pro. Вы не выбираете вариант `[1m]` или не включаете кредиты использования для окна 1M на этих моделях. Использование Fable само по себе может выставляться в счет кредитов использования на некоторых планах; см. [Fable и кредиты использования](#fable-and-usage-credits).

Opus 4.6 и Sonnet 4.6 достигают 1M только через их вариант `[1m]`, и доступ к этому варианту зависит от вашего плана. На планах Max, Team и Enterprise, включая как места Team Standard, так и Team Premium, Opus 4.6 с контекстом 1M включен в вашу подписку. Sonnet 4.6 с контекстом 1M требует [кредитов использования](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans) на каждом плане подписки, включая Max.

| План                               | Opus 4.6 с контекстом 1M                                                                                            | Sonnet 4.6 с контекстом 1M                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Max, Team и Enterprise             | Включено в подписку                                                                                                 | Требует [кредитов использования](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans) |
| Pro                                | Требует [кредитов использования](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans) | Требует [кредитов использования](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans) |
| API и оплата по мере использования | Полный доступ                                                                                                       | Полный доступ                                                                                                       |

Claude Code проверяет эти требования плана только при прямом подключении к Anthropic API. Если вы указываете `ANTHROPIC_BASE_URL` на [LLM gateway](/docs/ru/llm-gateway#subscriptions-and-gateways) и ваш сохраненный вход claude.ai остается активным учетным данным, Claude Code не проверяет кредиты использования вашего плана. Параметры `[1m]` остаются доступными в `/model`, и шлюз решает, успешен ли запрос. До версии 2.1.229 Claude Code отклонял `/model sonnet[1m]` в этой конфигурации, когда не мог подтвердить кредиты использования на учетной записи.

Чтобы отключить контекст 1M, установите `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`. Claude Code удаляет варианты модели 1M из средства выбора модели. На моделях с собственным окном 1M, таких как Sonnet 5 и модели Fable, он также рассматривает модель как имеющую окно контекста 200K:

* С включенным автоматическим компактированием сеансы компактируются на границе 200K через [автоматическое компактирование](#set-the-auto-compact-window). Установка окна автоматического компактирования выше 200K не снимает удержание, потому что Claude Code ограничивает это окно окном контекста модели.
* С отключенным автоматическим компактированием сеансы останавливаются на границе 200K с [ошибкой ограничения контекста](/docs/ru/errors#prompt-is-too-long) вместо компактирования.

До версии 2.1.223 Claude Code удерживал только сеансы Sonnet 5, Opus 4.8 и Opus 5 на 200K. См. [переменные окружения](/docs/ru/env-vars).

Окно контекста 1M использует стандартное ценообразование модели без премии за токены сверх 200K. Для планов, где расширенный контекст включен в вашу подписку, использование остается покрытым вашей подпиской. Для планов, которые получают доступ к расширенному контексту через кредиты использования, токены выставляются в счет кредитов использования.

Если ваша учетная запись поддерживает контекст 1M, параметр появляется в средстве выбора `/model` в последних версиях Claude Code. Если вы его не видите, попробуйте перезагрузить сеанс.

Вы также можете использовать суффикс `[1m]` с псевдонимами моделей или полными именами моделей:

```text theme={null}
# Используйте псевдоним opus[1m] или sonnet[1m]
/model opus[1m]
/model sonnet[1m]

# Или добавьте [1m] к полному имени модели
/model claude-opus-4-8[1m]
```

<h4 id="sonnet-5-context-window">
  Окно контекста Sonnet 5
</h4>

На Anthropic API Sonnet 5 всегда работает с окном контекста 1M. Нет варианта 200K, нет суффикса `[1m]` для выбора и нет требуемых кредитов использования ни на одном плане. Сеансы автоматически компактируются перед заполнением окна, примерно на 967K токенов по умолчанию; установите [`CLAUDE_CODE_AUTO_COMPACT_WINDOW`](/docs/ru/env-vars), чтобы выбрать другой порог.

Две конфигурации бюджетируют окно на 200K вместо этого:

* **LLM gateway**: когда `ANTHROPIC_BASE_URL` указывает на [шлюз](/docs/ru/llm-gateway), Claude Code не может проверить поддержку 1M. Чтобы использовать полное окно, выберите Sonnet 5 (1M context) в средстве выбора модели, которое сопоставляется с `sonnet[1m]`.
* **`CLAUDE_CODE_DISABLE_1M_CONTEXT=1`**: удерживает сеансы на каждой модели с собственным окном 1M на окне 200K; см. [Расширенный контекст](#extended-context) для того, как удержание применяется. Полезно для развертываний, которым нужно ограничить контекст.

<h2 id="context-window-and-auto-compaction">
  Контекстное окно и auto-compact
</h2>

Окно auto-compact определяет, насколько полным может быть контекстное окно перед тем, как Claude Code выполнит компактирование разговора. Информацию о том, что сохраняется и удаляется при каждом механизме компактирования, см. в разделе [What survives compaction](/docs/ru/context-window#what-survives-compaction).

<h3 id="set-the-auto-compact-window">
  Установка окна auto-compact
</h3>

Вы можете установить окно auto-compact в трёх местах:

* **Для этого сеанса и последующих**: выполните `/autocompact` с значением, например `/autocompact 500k`. Claude Code сохраняет его в ваши пользовательские параметры как [`autoCompactWindow`](/docs/ru/settings-reference#autocompactwindow) и применяет к текущему сеансу; если область параметров с более высоким приоритетом [settings scope](/docs/ru/settings#settings-precedence), такая как управляемые параметры, устанавливает этот ключ, команда сохраняет ваше значение, но сеанс сохраняет окно этой области, и команда об этом сообщает. Выполните `/autocompact auto`, чтобы вернуться к окну, оптимизированному для вашей модели.
* **Для одного запуска**: передайте [`--autocompact`](/docs/ru/cli-reference#cli-flags) при запуске Claude Code. Флаг переопределяет ваш сохранённый параметр для этого запуска без его изменения, и `claude --autocompact auto` запускает сеанс с оптимизированным окном, даже если ваш сохранённый параметр имеет значение. В отличие от `/autocompact`, флаг не переопределяется областью параметров с более высоким приоритетом, такой как управляемые параметры.
* **В скриптах и облачных окружениях**: установите [`CLAUDE_CODE_AUTO_COMPACT_WINDOW`](/docs/ru/env-vars). Пока она установлена, она имеет приоритет над командой, флагом и параметром, и `/autocompact` сообщает об переопределении вместо изменения окна.

Команда и флаг принимают размер окна от 100K до 1M токенов в любой из этих форм:

* Простой подсчёт токенов, например `200000`
* Суффикс `k` или `M`, например `500k` или `1M`
* Простое число от 100 до 1000, означающее тысячи, поэтому `200` устанавливает 200 000

Переменная окружения принимает только простой подсчёт токенов. Claude Code ограничивает окно контекстным окном модели.

<h3 id="default-auto-compact-thresholds">
  Пороги auto-compact по умолчанию
</h3>

Если вы не установите окно auto-compact, Claude Code выполняет компактирование, когда разговор достигает предела контекста модели, за исключением этих сеансов:

* [Cloud sessions](/docs/ru/claude-code-on-the-web) выполняют компактирование по мере приближения разговора к пределу модели
* Sonnet 4.6 и Opus 4.6 без [extended context](#extended-context) выполняют компактирование на границе 200K, как и Opus 4.8 и более поздние версии при работе с контекстным окном 200K, например на Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry
* Когда вы установите [`CLAUDE_CODE_DISABLE_1M_CONTEXT=1`](/docs/ru/env-vars), модели с собственным окном 1M, такие как Sonnet 5 и модели Fable, выполняют компактирование на границе 200K
* Модели, работающие с собственным окном 1M, такие как Sonnet 5, модели Fable и Opus 4.7 и более поздние версии на Anthropic API, выполняют компактирование перед заполнением окна, примерно на 967K токенов по умолчанию. На Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry раздел [Pin models for third-party deployments](#pin-models-for-third-party-deployments) указывает, какие модели работают с этим окном; для конфигураций, которые бюджетируют Sonnet 5 на 200K, см. [Sonnet 5 context window](#sonnet-5-context-window)
* Сеансы на ID модели, которую Claude Code не распознаёт, такие как псевдоним [LLM gateway](/docs/ru/llm-gateway), выполняют компактирование при контекстном окне, которое Claude Code предполагает для ID; см. [Correct the window for a gateway or custom model ID](#correct-the-window-for-a-gateway-or-custom-model-id)

<h3 id="correct-the-window-for-a-gateway-or-custom-model-id">
  Исправление окна для шлюза или пользовательского ID модели
</h3>

На [LLM gateway](/docs/ru/llm-gateway) или другом пользовательском развёртывании Claude Code может предполагать контекстное окно для ID модели, которое отличается от реального окна модели, независимо от того, разрешает ли оно ID в модель Claude. Установите [`CLAUDE_CODE_MAX_CONTEXT_TOKENS`](/docs/ru/env-vars) на окно, которое Claude Code должен предполагать вместо этого.

Применение переменной зависит от ID. Claude Code рассматривает ID как поставщика или пользовательское написание, когда оно не начинается с `claude-`, в любом регистре, или когда оно содержит суффикс, который Claude Code удаляет при чтении ID, например дату `@YYYYMMDD`, используемую на Google Cloud's Agent Platform. До версии 2.1.259 Claude Code не учитывал удалённый суффикс, поэтому нераспознанный ID `claude-` с суффиксом даты рассматривался как простое имя `claude-`.

Нераспознанный поставщик или пользовательское написание, то же написание с `[1m]` и все остальные ID — это три отдельных случая:

* Если Claude Code не может разрешить поставщика или пользовательское написание в модель, которую он распознаёт, и ID не содержит `[1m]`, переменная применяется напрямую и упреждающее компактирование продолжается при объявленном окне.
* Если Claude Code не может разрешить поставщика или пользовательское написание в модель, которую он распознаёт, и ID содержит `[1m]`, в любом регистре, Claude Code предполагает окно 1M для него и переменная не применяется самостоятельно. Чтобы исправить окно, сохраняя упреждающее компактирование, также установите [`CLAUDE_CODE_DISABLE_1M_CONTEXT=1`](/docs/ru/env-vars). С установленной переменной Claude Code размещает ID как то же написание без `[1m]`, поэтому `CLAUDE_CODE_MAX_CONTEXT_TOKENS` применяется, когда он применялся бы к этому неразмеченному написанию.

  С объявленным окном выше 200K Claude Code затем показывает [startup warning](/docs/ru/errors#the-200k-limit-isnt-enforced), что предел 200K не применяется. Предупреждение ожидается в этой конфигурации.
* Если ID разрешается в модель, которую Claude Code распознаёт, или ID является простым именем `claude-` без суффикса для Claude Code, чтобы удалить его, в любом регистре, переменная вступает в силу только когда вы также установите [`DISABLE_COMPACT`](/docs/ru/env-vars), что отключает все компактирование.

  Например, ID, который содержит имя модели Claude, которое Claude Code знает, такое как `anthropic/claude-opus-4-8`, `us.anthropic.claude-…-v1:0` или датированный `claude-sonnet-4-5@20250929`, разрешается в эту модель. Это включает ID, которые также содержат `[1m]`: Claude Code разрешает `claude-opus-4-8[1m]` в Opus 4.8 даже с установленным `CLAUDE_CODE_DISABLE_1M_CONTEXT`.

Для ID модели, которую Claude Code не распознаёт, установите [`CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1`](/docs/ru/env-vars), чтобы Claude Code выполнял компактирование только после того, как API отклонит разговор с [too-long error Claude Code recognizes](/docs/ru/errors#prompt-is-too-long). Claude Code не запускает это восстановление, когда шлюз [rewrites the error](/docs/ru/llm-gateway-connect#troubleshoot-gateway-errors) на формулировку, которую Claude Code не распознаёт.

<h2 id="checking-your-current-model">
  Проверка вашей текущей модели
</h2>

Вы можете увидеть, какую модель вы используете в настоящее время, в двух местах:

* В [строке состояния](/docs/ru/statusline), если у вас она настроена
* В `/status`, который также отображает информацию вашей учетной записи

<h2 id="add-a-custom-model-option">
  Добавление пользовательского варианта модели
</h2>

Используйте `ANTHROPIC_CUSTOM_MODEL_OPTION` для добавления одной пользовательской записи в средство выбора `/model` без замены встроенных псевдонимов. Это полезно для тестирования идентификаторов моделей, которые Claude Code не указывает по умолчанию. Для развертываний шлюза LLM Claude Code может заполнять средство выбора из конечной точки `/v1/models` шлюза, когда установлено значение `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`, поэтому эта переменная требуется только в том случае, если обнаружение отключено или не возвращает нужную вам модель. См. [обнаружение модели шлюза](/docs/ru/llm-gateway-protocol#model-discovery).

Чтобы вместо этого перечислить несколько моделей в собственном порядке и под выбранными вами метками, установите [`modelPicker`](/docs/ru/settings-reference#modelpicker). Его запись указывает, какие строки средство выбора сохраняет, когда эта комбинация заменяет встроенную.

Этот пример устанавливает все три переменные, чтобы сделать развертывание Opus с маршрутизацией через шлюз выбираемым. Claude Code читает переменные окружения при запуске, поэтому запустите экспорты перед запуском `claude` или перезагрузите существующий сеанс, чтобы их применить:

```bash theme={null}
export ANTHROPIC_CUSTOM_MODEL_OPTION="my-gateway/claude-opus-5-5"
export ANTHROPIC_CUSTOM_MODEL_OPTION_NAME="Opus via Gateway"
export ANTHROPIC_CUSTOM_MODEL_OPTION_DESCRIPTION="Custom deployment routed through the internal LLM gateway"
```

`ANTHROPIC_CUSTOM_MODEL_OPTION_NAME` и `ANTHROPIC_CUSTOM_MODEL_OPTION_DESCRIPTION` являются необязательными:

* Если вы опустите имя, запись показывает имя модели, когда Claude Code [распознает идентификатор](#customize-pinned-model-display-and-capabilities), и идентификатор модели в противном случае.
* Если вы опустите описание, Claude Code использует `Custom model (<model-id>)`.

Claude Code перечисляет пользовательскую запись после встроенных записей, и любые строки [`modelPicker`](/docs/ru/settings-reference#modelpicker), которые вы добавляете, появляются после неё.

Claude Code пропускает валидацию для идентификатора модели, установленного в `ANTHROPIC_CUSTOM_MODEL_OPTION`, поэтому вы можете использовать любую строку, которую принимает ваша конечная точка API.

Когда установлено значение [`availableModels`](#restrict-model-selection), включите пользовательский идентификатор модели в список разрешений. В противном случае Claude Code фильтрует пользовательскую запись из средства выбора и отклоняет выбор `--model` для неё, как и для любой другой исключённой модели.

Пользовательский идентификатор, который встраивает имя семейства, такой как `my-gateway/claude-opus-5-5`, считается конкретной записью для этого семейства и отключает его подстановочный знак, поэтому также перечислите версии, которые вы намереваетесь оставить выбираемыми. См. [Поведение слияния](#merge-behavior).

Каждое значение должно быть полным именем модели или эквивалентным идентификатором для вашего поставщика API. Чтобы выбрать модель, на которой начинаются ваши сеансы, установите [`ANTHROPIC_DEFAULT_MODEL`](#set-a-default-model-for-new-sessions), которую эта таблица опускает.

| `ANTHROPIC_DEFAULT_SONNET_MODEL` | Модель для использования для `sonnet`, или для `opusplan` при неактивном Plan Mode.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL`  | Модель для использования для `haiku`, или [фоновой функциональности](/docs/ru/costs#background-token-usage)                                                                                                                                                                                                                                                                                                                                                                                                               |
| `CLAUDE_CODE_SUBAGENT_MODEL`     | Модель по умолчанию для [subagents](/docs/ru/sub-agents#choose-a-model), [agent team](/docs/ru/agent-teams#specify-teammates-and-models) товарищей по команде и [workflow](/docs/ru/workflows) агентов, которым не назначена модель другим способом. <h3 id="pin-models-for-third-party-deployments">
  Закрепление моделей для развертываний третьих сторон
</h3>

При развертывании Claude Code через [Amazon Bedrock](/docs/ru/amazon-bedrock), [Google Cloud's Agent Platform](/docs/ru/google-vertex-ai), [Microsoft Foundry](/docs/ru/microsoft-foundry) или [Claude Platform on AWS](/docs/ru/claude-platform-on-aws) закрепите версии моделей перед развертыванием для пользователей.

Без закрепления Claude Code использует псевдонимы моделей, такие как `fable`, `opus`, `sonnet` и `haiku`, которые разрешаются в встроенный идентификатор модели по умолчанию для каждого поставщика. Это значение по умолчанию может отставать от последнего выпуска Anthropic, и модель, на которую оно указывает, может быть еще не включена в учетную запись пользователя. Когда значение по умолчанию недоступно, пользователи Amazon Bedrock и Google Cloud's Agent Platform видят уведомление и сеанс переходит на более раннюю версию модели по умолчанию, или на модель Sonnet по умолчанию, когда значение по умолчанию является моделью Opus и нет доступной версии Opus. Пользователи Microsoft Foundry видят ошибки вместо этого, потому что Microsoft Foundry не имеет эквивалентной проверки при запуске.

На Amazon Bedrock и Google Cloud's Agent Platform пользователь, который запускает сеанс на конкретной версии Sonnet или Opus, например с `--model`, `ANTHROPIC_MODEL` или параметром `model`, закрепляет эту версию как значение по умолчанию сеанса для соответствующего псевдонима: проверка при запуске пропускает встроенное значение по умолчанию, которое оно заменяет, и не показывает уведомление о переключении. До версии 2.1.211 проверка выполнялась и могла показать уведомление даже когда модель сеанса была явно настроена.

<Warning>
  Установите переменные окружения модели на конкретные идентификаторы версий как часть вашей начальной настройки. Закрепление позволяет вам контролировать, когда ваши пользователи переходят на новую модель.
</Warning>

Используйте следующие переменные окружения с идентификаторами моделей, специфичными для версии, для вашего поставщика:

| Поставщик                     | Пример                                                               |
| :---------------------------- | :------------------------------------------------------------------- |
| Amazon Bedrock                | `export ANTHROPIC_DEFAULT_OPUS_MODEL='us.anthropic.claude-opus-4-8'` |
| Google Cloud's Agent Platform | `export ANTHROPIC_DEFAULT_OPUS_MODEL='claude-opus-4-8'`              |
| Microsoft Foundry             | `export ANTHROPIC_DEFAULT_OPUS_MODEL='claude-opus-4-8'`              |

Применяйте тот же шаблон для `ANTHROPIC_DEFAULT_FABLE_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` и `ANTHROPIC_DEFAULT_HAIKU_MODEL`. Для текущих и устаревших идентификаторов моделей во всех поставщиках см. [Обзор моделей](https://platform.claude.com/docs/en/about-claude/models/overview). Чтобы обновить пользователей до новой версии модели, обновите эти переменные окружения и переразверните.

Чтобы включить [расширенный контекст](#extended-context) для закрепленной модели, добавьте `[1m]` к идентификатору модели в `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` или `ANTHROPIC_DEFAULT_FABLE_MODEL`:

```bash theme={null}
export ANTHROPIC_DEFAULT_OPUS_MODEL='claude-opus-4-8[1m]'
```

С суффиксом `[1m]` контекстное окно 1M применяется ко всему использованию закрепленного псевдонима, включая фазу Opus в режиме плана [`opusplan`](#opusplan-model-setting) и [subagents](/docs/ru/sub-agents#choose-a-model), чей frontmatter `model` называет псевдоним.

* Claude Code удаляет суффикс перед отправкой идентификатора модели вашему поставщику.
* Добавляйте `[1m]` только когда базовая модель [поддерживает контекст 1M](https://platform.claude.com/docs/en/build-with-claude/context-windows#context-window-sizes-by-model).
* Суффикс читается для каждой переменной, а не для каждой модели. На Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry идентификатор модели без `[1m]` в одной переменной использует контекст 200K, даже если другая переменная устанавливает ту же модель с суффиксом. Sonnet 5 всегда работает с окном 1M на этих поставщиках и никогда не требует суффикса.

<Note>
  Список разрешений `availableModels`, доставленный через [MDM или управляемый файл параметров](/docs/ru/managed-settings#delivery-mechanisms), все еще применяется при использовании поставщиков третьих сторон; [параметры, управляемые сервером, не доставляются туда](/docs/ru/server-managed-settings#platform-availability).

  Фильтрация соответствует псевдониму модели, такому как `opus`, префиксу версии, такому как `claude-opus-4-8`, или полному идентификатору модели в форме поставщика. Префиксы, специфичные для поставщика, такие как `us.anthropic.`, не удаляются, поэтому для разрешения конкретной модели укажите ее полный идентификатор в форме поставщика, или отобразите его через [`modelOverrides`](#override-model-ids-per-version). Для закрепленной модели этот идентификатор — это значение, которое вы установили в его переменной `ANTHROPIC_DEFAULT_*_MODEL`. Любой суффикс `[1m]` удаляется как из записи списка разрешений, так и из запрашиваемой модели перед сопоставлением.
</Note>

<h3 id="customize-pinned-model-display-and-capabilities">
  Настройка отображения и возможностей закрепленной модели
</h3>

Когда вы закрепляете модель у поставщика третьей стороны, ее строка в средстве выбора `/model` показывает имя модели по умолчанию, если Claude Code распознает закрепленный идентификатор, и необработанный идентификатор в противном случае:

* **Распознано**: точный идентификатор модели, которую Claude Code знает, такой как его идентификатор Anthropic API или форма вашего поставщика или шлюза, с суффиксом `[1m]` или без него. Закрепите `us.anthropic.claude-sonnet-4-5-20250929-v1:0` и строка будет читаться как `Sonnet 4.5`.
* **Не распознано**: любой другой идентификатор, такой как ARN профиля вывода приложения или версия модели, которую Claude Code не знает, если только запись [`modelOverrides`](#override-model-ids-per-version) не отображает модель на эту точную строку. На Microsoft Foundry имена развертывания определяются пользователем, поэтому Claude Code никогда не распознает закрепленный идентификатор там, отображенный или нет, и строка показывает имя развертывания по умолчанию.

Когда строка показывает имя модели, ее описание по умолчанию включает закрепленный идентификатор, чтобы вы все еще могли видеть, какой идентификатор закреплен.

Claude Code также может не распознать, какие функции поддерживает закрепленная модель. Вы можете установить отображаемое имя и описание самостоятельно и объявить возможности с помощью вспомогательных переменных окружения для каждой закрепленной модели.

Эти переменные вступают в силу у поставщиков третьих сторон, таких как Amazon Bedrock, Google Cloud's Agent Platform и Microsoft Foundry. Переменные `_NAME` и `_DESCRIPTION` также вступают в силу, когда `ANTHROPIC_BASE_URL` указывает на [LLM gateway](/docs/ru/llm-gateway). Они не имеют эффекта при прямом подключении к `api.anthropic.com`.

| Переменная окружения                                  | Описание                                                                                                                                                                                                                              |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_DEFAULT_OPUS_MODEL_NAME`                   | Отображаемое имя для закрепленной модели Opus в средстве выбора `/model`. Когда не установлено, строка показывает имя модели, если Claude Code распознает закрепленный идентификатор, и закрепленный идентификатор в противном случае |
| `ANTHROPIC_DEFAULT_OPUS_MODEL_DESCRIPTION`            | Отображаемое описание для закрепленной модели Opus в средстве выбора `/model`. Когда не установлено, строка показывает описание по умолчанию, которое начинается с `Custom Opus model`                                                |
| `ANTHROPIC_DEFAULT_OPUS_MODEL_SUPPORTED_CAPABILITIES` | Разделенный запятыми список возможностей, которые поддерживает закрепленная модель Opus                                                                                                                                               |

Те же суффиксы `_NAME`, `_DESCRIPTION` и `_SUPPORTED_CAPABILITIES` доступны для `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`, `ANTHROPIC_DEFAULT_FABLE_MODEL` и `ANTHROPIC_CUSTOM_MODEL_OPTION`.

Claude Code включает функции, такие как [уровни усилий](#adjust-effort-level) и [расширенное мышление](#extended-thinking), путем сопоставления идентификатора модели с известными шаблонами. Идентификаторы, специфичные для поставщика, такие как ARN Amazon Bedrock или пользовательские имена развертывания, часто не соответствуют этим шаблонам, оставляя поддерживаемые функции отключенными. Установите `_SUPPORTED_CAPABILITIES`, чтобы сообщить Claude Code, какие функции фактически поддерживает модель:

| Значение возможности   | Включает                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| `effort`               | [Уровни усилий](#adjust-effort-level) и команду `/effort`                                    |
| `xhigh_effort`         | Уровень усилий `xhigh`                                                                       |
| `max_effort`           | Уровень усилий `max`                                                                         |
| `thinking`             | [Расширенное мышление](#extended-thinking)                                                   |
| `adaptive_thinking`    | Адаптивное рассуждение, которое динамически распределяет мышление на основе сложности задачи |
| `interleaved_thinking` | Мышление между вызовами инструментов                                                         |

Когда установлена `_SUPPORTED_CAPABILITIES`, Claude Code включает перечисленные возможности и отключает неперечисленные для соответствующей закрепленной модели. Когда переменная не установлена, Claude Code возвращается к встроенному обнаружению на основе идентификатора модели.

Этот пример закрепляет Opus на пользовательский ARN модели Amazon Bedrock, устанавливает понятное имя и объявляет его возможности:

```bash theme={null}
export ANTHROPIC_DEFAULT_OPUS_MODEL='arn:aws:bedrock:us-east-1:123456789012:custom-model/abc'
export ANTHROPIC_DEFAULT_OPUS_MODEL_NAME='Opus via Bedrock'
export ANTHROPIC_DEFAULT_OPUS_MODEL_DESCRIPTION='Opus 4.7 routed through a Bedrock custom endpoint'
export ANTHROPIC_DEFAULT_OPUS_MODEL_SUPPORTED_CAPABILITIES='effort,xhigh_effort,max_effort,thinking,adaptive_thinking,interleaved_thinking'
```

<h3 id="override-model-ids-per-version">
  Переопределение идентификаторов моделей для каждой версии
</h3>

На платформах, которые встраивают Claude Code и устанавливают [`CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`](/docs/ru/env-vars), конфигурация модели хоста имеет приоритет над управляемыми параметрами модели, в то время как управляемый список разрешений `availableModels` остается в силе, если только хост не предоставляет свой собственный; [Исключения из приоритета управляемых параметров](/docs/ru/settings#exceptions-to-managed-settings-precedence) говорит, какие ключи и переменные переопределяет хост.

Переменные окружения уровня семейства выше настраивают один идентификатор модели для каждого псевдонима семейства. Если вам нужно отобразить несколько версий в одном семействе на различные идентификаторы поставщика, используйте вместо этого параметр `modelOverrides`.

`modelOverrides` отображает отдельные идентификаторы моделей Anthropic на строки, специфичные для поставщика, которые Claude Code отправляет API вашего поставщика. Когда пользователь выбирает отображаемую модель в средстве выбора `/model`, Claude Code использует ваше настроенное значение вместо встроенного значения по умолчанию.

Это позволяет администраторам предприятия маршрутизировать каждую версию модели на конкретный ARN профиля вывода Amazon Bedrock, имя версии Google Cloud's Agent Platform или имя развертывания Microsoft Foundry для управления, распределения затрат или региональной маршрутизации.

Установите `modelOverrides` в вашем [файле параметров](/docs/ru/settings#where-settings-live):

```json theme={null}
{
  "modelOverrides": {
    "claude-opus-4-7": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/opus-prod",
    "claude-opus-4-6": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/opus-46-prod",
    "claude-sonnet-4-6": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/sonnet-prod"
  }
}
```

Ключи должны быть идентификаторами моделей Anthropic, как указано в [Обзоре моделей](https://platform.claude.com/docs/en/about-claude/models/overview). Для датированных идентификаторов моделей включите суффикс даты точно так, как он там отображается. Неизвестные ключи игнорируются.

Чтобы остановить строку диагностики `[claude-code:unrecognized_model]` [diagnostic line](/docs/ru/errors#unrecognized-model-id-on-a-request) для идентификатора, такого как псевдоним шлюза, добавьте запись с этим идентификатором в качестве его значения.

Переопределения заменяют встроенные идентификаторы моделей, которые поддерживают каждую запись в средстве выбора `/model`. На Amazon Bedrock записи `modelOverrides` имеют приоритет над любыми профилями вывода, которые Claude Code автоматически обнаруживает при запуске. Claude Code передает значения, которые уже являются специфичными для поставщика, такие как ARN профиля вывода Amazon Bedrock или имена развертывания Microsoft Foundry, поставщику как есть.

Переопределения также применяются, когда вы передаете идентификатор модели Anthropic непосредственно через `--model`, переменную окружения `ANTHROPIC_MODEL` или переменную окружения `ANTHROPIC_DEFAULT_*_MODEL`. На Amazon Bedrock, Google Cloud's Agent Platform и [Mantle](/docs/ru/amazon-bedrock#use-the-mantle-endpoint) идентификатор модели Anthropic без записи `modelOverrides` разрешается в тот же идентификатор, специфичный для поставщика, что и строка средства выбора `/model` для этой версии, когда поставщик поддерживает эту версию. Mantle поддерживает подмножество версий. Для идентификатора модели Anthropic вне этого подмножества Claude Code отправляет необработанный идентификатор Mantle без отображения, если только запись `modelOverrides` не охватывает его. До версии 2.1.200 значения `--model` и переменных окружения достигали поставщика как есть без прохождения через карту переопределений.

`modelOverrides` работает вместе с `availableModels`. Список разрешений оценивается по идентификатору модели Anthropic, а не по значению переопределения, поэтому запись, такая как `"opus"` в `availableModels`, продолжает совпадать, даже когда версии Opus отображаются на ARN. Когда `enforceAvailableModels` установлен в управляемых параметрах, принудительное значение Default разрешается через `modelOverrides` из [управляемых параметров](/docs/ru/managed-settings#how-claude-code-combines-managed-sources) только. Отображение администратора, такое как версия, закрепленная на ARN профиля вывода, соблюдается в принудительном Default. Переопределения из параметров пользователя или проекта не влияют на него.

Когда `availableModels` установлен в [управляемых параметрах](/docs/ru/managed-settings), только `modelOverrides` из управляемых параметров применяются к идентификатору модели Anthropic, переданному непосредственно через `--model` или переменные окружения выше. Claude Code игнорирует переопределения в параметрах пользователя или проекта для этих идентификаторов и никогда не разрешает идентификатор, который исключает управляемый список, через `modelOverrides` из любого источника параметров. Это ограничение управляемого источника требует Claude Code версии 2.1.200 или позже. См. [Ограничение выбора модели](#restrict-model-selection) для того, как обрабатываются заблокированные идентификаторы.

<h3 id="prompt-caching-configuration">
  Конфигурация кэширования подсказок
</h3>

Claude Code автоматически использует [кэширование подсказок](/docs/ru/prompt-caching) для оптимизации производительности и снижения затрат. Вы можете отключить кэширование подсказок глобально или для конкретных уровней моделей:

| Переменная окружения            | Описание                                                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `DISABLE_PROMPT_CACHING`        | Установите на `1` для отключения кэширования подсказок для всех моделей. Имеет приоритет над параметрами для каждой модели |
| `DISABLE_PROMPT_CACHING_HAIKU`  | Установите на `1` для отключения кэширования подсказок только для моделей Haiku                                            |
| `DISABLE_PROMPT_CACHING_SONNET` | Установите на `1` для отключения кэширования подсказок только для моделей Sonnet                                           |
| `DISABLE_PROMPT_CACHING_OPUS`   | Установите на `1` для отключения кэширования подсказок только для моделей Opus                                             |
| `DISABLE_PROMPT_CACHING_FABLE`  | Установите на `1` для отключения кэширования подсказок только для моделей Fable                                            |

Чтобы выбрать TTL кэша для основного разговора и для subagents отдельно, см. [выберите TTL самостоятельно](/docs/ru/prompt-caching#choose-the-ttl-yourself). Для того, что вызывает промах кэша, см. [Как Claude Code использует кэширование подсказок](/docs/ru/prompt-caching).
