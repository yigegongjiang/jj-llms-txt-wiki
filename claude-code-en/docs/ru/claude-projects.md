# Позвольте Claude координировать текущую работу с помощью Projects

> Предоставьте Claude набор связанной работы в одном разговоре и позвольте ему координировать параллельные облачные сеансы, которые совместно используют репозитории, инструкции и память.

<Note>
  Projects находятся в публичной бета-версии на планах Pro и Max и постепенно развертываются, начиная с аккаунтов, которые использовали [облачные сеансы](/docs/ru/claude-code-on-the-web) и не имеют существующих проектов в claude.ai chat или Cowork. Они еще недоступны на планах Team и Enterprise. Если **Projects** не отображается на боковой панели в [claude.ai/code](https://claude.ai/code) или на вкладке Code [настольного приложения](/docs/ru/desktop), развертывание еще не достигло вашего аккаунта, и вы можете [присоединиться к списку ожидания](https://claude.com/form/projects). [Запуск агентов параллельно](/docs/ru/agents) содержит список того, что вы можете использовать в то время.
</Note>

Project — это один текущий разговор, в котором Claude координирует поток связанной работы для вас. Вы говорите ему, что нужно сделать, и он запускает поток для каждой задачи.

Каждый поток обычно является [облачным сеансом](/docs/ru/claude-code-on-the-web): Claude Code, работающий в облаке, а не на вашей машине. Когда задаче требуется что-то, что есть только на вашем компьютере, вы можете попросить Claude запустить этот поток на вашем компьютере вместо этого через [Remote Control](/docs/ru/remote-control). Потоки работают параллельно и вы можете проверить их и направить их со своего телефона. Облачные потоки продолжают работу после того, как вы закроете ноутбук.

Без проекта запуск нескольких сеансов означает самостоятельное координирование: вы решаете, над чем работает каждый, повторяете одинаковый контекст в начале каждого и проверяете, какой завершился или требует ответа. С проектом вместо этого вы:

* **Отправляете работу в одно место**: вставляйте отчет об ошибке, трассировку стека или список задач в разговор, когда они появляются. Claude запускает поток для каждого элемента работы или передает его потоку, уже работающему в этой области, и отвечает на быстрые вопросы на месте.
* **Устанавливаете контекст один раз**: каждый новый поток начинается с инструкций проекта, поэтому правило, которое вы указываете один раз, например какую ветку выбрать, достигает все потоки.
* **Уходите и возвращаетесь к завершенной работе**: когда вы вернетесь через час или на следующее утро, панель **Overview** показывает, какие потоки завершены, какие pull request готовы к проверке и какой поток ждет вашего ответа.

Если вы уже знаете работу, которую хотите запустить в проекте, переходите прямо к [Создание проекта](#create-a-project).

<h2 id="when-to-use-a-project">
  Когда использовать проект
</h2>

Проект стоит создавать, когда работа имеет цель, которая выходит за рамки одного сеанса и продолжает создавать задачи. Эти виды работ хорошо подходят для проекта:

* **Одна цель в нескольких репозиториях**: "Обновить каждый сервис на новую конфигурацию lint." Claude может запустить поток для каждого репозитория, каждый с собственным pull request, и панель [**Overview**](#see-what-needs-you-in-overview) показывает, какие готовы к проверке.
* **Область, которую вы постоянно пополняете**: ошибки, трассировки стека и запросы на проверку для одного сервиса, вставляемые в разговор по мере их поступления. Ошибка, которую вы просите Claude запомнить после одного исправления, находится в [памяти проекта](#give-a-project-standing-context) для следующей.
* **Сборка или миграция больше, чем сеанс**: "Построить то, что описывает `docs/spec.md`" или "Перенести приложение с устаревшего ORM." Работа разбивается на потоки, каждый берет часть, решения, которые вы просите Claude запомнить в начале, достигают более поздние потоки, и изменения спецификации и ошибки, которые вы находите во время сборки, попадают в один разговор.
* **Работа, которая не является кодом**: папка контрактов или экспорт билетов поддержки, к которым вы постоянно возвращаетесь с новыми вопросами, например "найти десять наиболее распространенных ошибок интеграции в этих билетах." Загрузите документы вместо добавления репозитория, и потоки доставляют каждый отчет как файл на вкладке [**Library**](#see-what-needs-you-in-overview) проекта.

В любом из них вы можете отправить пакет задач, попросить Claude начать без вашего подтверждения, уйти и найти потоки, которые вам нужны, в разделе [**Waiting on you**](#see-what-needs-you-in-overview) когда вы вернетесь, или попросить Claude поставить часть работы по расписанию как [routine](/docs/ru/routines). Если это ваша ситуация, [создайте проект](#create-a-project).

<h3 id="when-something-else-fits-better">
  Когда что-то другое подходит лучше
</h3>

Потоки работают с репозиториями GitHub и с файлами, папками и папками Google Drive, которые вы загружаете в проект, а не с файлами или инструментами, которые существуют только на вашей машине. Если задача требует вашей машины, попросите Claude запустить её поток там через [Remote Control](/docs/ru/remote-control). [Ограничения](#limitations) перечисляют, что для этого требуется. Что-то другое подходит лучше в этих случаях:

* **Одна задача, которая подходит в сеанс**: "Исправить нестабильный тест входа." Запустите [облачный сеанс](/docs/ru/claude-code-on-the-web) самостоятельно.
* **Работа, где каждая задача требует вашей машины**: локальная база данных, эмулятор устройства или API за вашим VPN. Используйте локальный сеанс или [agent view](/docs/ru/agent-view) для запуска нескольких одновременно. Если работе нужны только локальные файлы, загрузите их в проект вместо этого.
* **Одна задача, которая повторяется по расписанию без разговора вокруг нее**: "Отправить отчет о зависимостях каждый понедельник." Создайте [routine](/docs/ru/routines) самостоятельно.
* **Несколько человек дают Claude работу и направляют его вместе в канале Slack**: см. [Claude Tag](https://claude.com/docs/claude-tag/overview).

Проект использует те же лимиты плана, что и другие сеансы Claude Code, и использует их быстрее. [Использование и стоимость](#usage-and-cost) охватывает то, что использует ваш план и как его снизить.

<h2 id="how-a-project-is-organized">
  Как организован проект
</h2>

Проект — это один координирующий разговор с Claude плюс потоки, которые он запускает для выполнения работы. Вот его части:

* **Разговор проекта**: один долгоживущий сеанс, где Claude действует как координатор. Он берет то, что вы отправляете, решает, что становится потоком, и отслеживает каждый запущенный поток. Он видит, что потоки сообщают обратно, а не каждый шаг, который они предпринимают.
* **Потоки**: рабочие. Каждый — это отдельный сеанс с собственным контекстным окном, который выполняет одну часть работы и сообщает обратно в разговор, когда завершается. Облачный поток работает на собственной ветке и открывает pull request, когда работа это требует.
* **С чего начинает каждый облачный поток**:
  * Репозитории и файлы проекта, плюс его [инструкции и память](#give-a-project-standing-context)
  * `CLAUDE.md` и skills в [каждом из репозиториев проекта](#what-threads-pick-up-from-your-repositories), и в проекте с одним репозиторием также правила разрешений и hooks этого репозитория
  * [Connectors](#get-skills-plugins-connectors-and-tools-into-threads) на вашем аккаунте claude.ai
  * [Облачная среда](#choose-an-environment-for-threads), которая устанавливает его сетевой доступ, переменные окружения, учетные данные API и установленные инструменты
* **Панель Overview**: где вы [видите все потоки сразу](#see-what-needs-you-in-overview) и какие из них вам нужны. Его другие вкладки — **Library** для добавленных вами файлов и файлов, созданных потоками, **Pull requests** для открытых потоками, и **Routines** для запланированной работы в проекте.

Облачные потоки не берут ничего из настройки Claude Code на вашей машине. [Получить skills, plugins, connectors и инструменты в потоки](#get-skills-plugins-connectors-and-tools-into-threads) охватывает, как дать им то, что им иначе не хватает.

<h2 id="create-a-project">
  Создание проекта
</h2>

Вы создаете и используете проекты в [claude.ai/code](https://claude.ai/code), на вкладке Code настольного приложения или в мобильном приложении Claude для [iOS](https://apps.apple.com/us/app/claude-by-anthropic/id6473753684) и [Android](https://play.google.com/store/apps/details?id=com.anthropic.claude). В браузере и настольном приложении есть два способа начать проект:

* **С нуля**, когда вы знаете поток работы, который хотите запустить в Claude: откройте диалог **New project** и назовите его. [Запуск нового проекта с нуля](#start-a-new-project-from-scratch) проходит через диалог.
* **Из облачного сеанса, который уже выполняет работу**: выберите **Continue as a project** из меню этого сеанса, и Claude предлагает настройку проекта на основе того, что делал сеанс. См. [Запуск из существующего облачного сеанса](#start-from-an-existing-cloud-session).

В любом случае сначала [проверьте предварительные условия](#check-the-prerequisites).

<h3 id="check-the-prerequisites">
  Проверка предварительных условий
</h3>

Перед созданием проекта проверьте ваш план, настройку GitHub и то, что нужно работе для достижения:

* **План**: вы на Pro или Max и **Projects** отображается на вашей боковой панели.
* **GitHub, если проект будет работать с кодом**: ваш код находится на github.com, а не на GitHub Enterprise Server, GitLab или Bitbucket, ваш подключенный аккаунт GitHub имеет доступ на push к нему, и Claude GitHub App установлено на нем. Если вы подключили GitHub с помощью [`/web-setup`](/docs/ru/web-quickstart#connect-from-your-terminal), этот токен позволяет вашим другим облачным сеансам достичь репозитория, но недостаточно для облачных потоков проекта, которым нужно Claude GitHub App. [Настройка доступа GitHub](#set-up-github-access) содержит шаги.
* **Сеть, учетные данные и инструменты**: для облачных потоков они поступают из [облачной среды](#choose-an-environment-for-threads) проекта. Среда по умолчанию уже достигает [общих реестров пакетов](/docs/ru/cloud-environments#default-allowed-domains), поэтому проверьте это только если работе нужны другие домены, секрет или инструмент, который не предустановлен. Если работе нужен MCP server, проверьте, что он отображается как подключенный в ваших [claude.ai connectors](https://claude.ai/customize/connectors).

<h3 id="start-a-new-project-from-scratch">
  Запуск нового проекта с нуля
</h3>

Запуск проекта с нуля означает открытие диалога **New project**, назначение потока работы и опционально предоставление ему цели и репозиториев и файлов, над которыми он работает. Требуется только имя, поэтому вы можете создать проект первым и заполнить остальное по мере развития работы.

<Steps>
  <Step title="Откройте Projects">
    В [claude.ai/code](https://claude.ai/code) или на вкладке Code настольного приложения выберите **Projects** на левой боковой панели, затем выберите **New project**. В браузере вы также можете перейти прямо на [claude.ai/code/projects/browse](https://claude.ai/code/projects/browse).
  </Step>

  <Step title="Заполните диалог New project">
    Ограничьте проект одним потоком работы, который вы будете постоянно добавлять, например всем, что требуется для поддержания одного API под его целевой задержкой. [Когда использовать проект](#when-to-use-a-project) содержит больше примеров. Затем заполните поля диалога:

    * **Name**: как проект отображается в списке **Projects**.
    * **Goal** (опционально): одна строка того, что вы пытаетесь сделать, например "Держать p95 задержку API ниже 200 мс". Claude в разговоре работает над этим. Без цели Claude работает из задач, которые вы отправляете, и вы можете добавить цель позже в **Project settings > General**.
    * **Context** (опционально): репозитории GitHub, над которыми работает этот проект, плюс любые файлы, папки или папки Google Drive, которые потоки должны читать. Нажмите **Add** для каждого. Добавьте репозитории, которые нужны большинству задач, а не каждый, который работа может затронуть; [Решение, какие репозитории добавить](#decide-which-repositories-to-add) охватывает выбор, и вы можете добавить больше позже в **Project settings > Environment**.

    Постоянные правила того, как потоки должны работать, идут в [инструкции проекта](#give-a-project-standing-context), которые вы устанавливаете после создания проекта.
  </Step>

  <Step title="Создайте проект">
    Нажмите **Create project**. Разговор проекта открывается с полем сообщения внизу, где вы описываете работу для Claude.

    На вашем первом проекте Claude делает ход самостоятельно сразу после создания проекта, если вы не отправите сообщение первым. Этот ход использует ваш план. В нем Claude может:

    * Запустить один поток, который исследует репозиторий без изменений и предложить следующие шаги, если проект имеет репозиторий, который он может читать.
    * Опубликовать **Setup recommendations**, полученные из ваших недавних облачных сеансов: репозитории для добавления, routines для создания и потоки, которые он может запустить. Каждый рекомендуемый репозиторий и routine включены по умолчанию. Отключите те, которые вам не нужны, затем нажмите **Update setup** для добавления остальных, или игнорируйте рекомендации и опишите работу самостоятельно.
  </Step>
</Steps>

Проект теперь указан в разделе **Projects** на боковой панели, и его разговор открыт. [Ваш первый пакет](#your-first-batch) охватывает то, что нужно настроить перед отправкой ему работы.

<h3 id="start-from-an-existing-cloud-session">
  Запуск из существующего облачного сеанса
</h3>

Если у вас уже есть облачный сеанс, выполняющий работу, которая принадлежит проекту, откройте меню сеанса на боковой панели и выберите **Continue as a project** или **Move to project**:

* **Continue as a project** создает новый проект с названием сеанса и открывает его. Claude читает сеанс и публикует **Setup recommendations** в разговоре для вашего подтверждения. Исходный сеанс остается в вашем списке сеансов, и если он был в середине хода, он продолжает работу, поэтому остановите его самостоятельно, если вы не хотите, чтобы оба работали одновременно. Если вы используете баннер **Set up project**, который может появиться над полем сообщения облачного сеанса, результат тот же, за исключением того, что работающий ход сеанса останавливается после открытия проекта.
* **Move to project** переносит работу сеанса в существующий проект. Он публикует сообщение в разговоре этого проекта, прося Claude прочитать сеанс и продолжить с того, где он остановился, и новая работа продолжается в собственных потоках проекта. Исходный сеанс остается в вашем списке сеансов, без изменений.

<h3 id="set-up-github-access">
  Настройка доступа GitHub
</h3>

Большинство настроек GitHub происходит один раз, а не для каждого проекта. Вы подключаете свой аккаунт GitHub к Claude один раз, и Claude GitHub App устанавливается один раз для каждого репозитория или один раз для всей организации GitHub, если вы даете ей все репозитории. Вы возвращаетесь к этим шагам, когда добавляете репозиторий, который Claude GitHub App еще не охватывает, или один в организации GitHub, которая требует SSO.

<Steps>
  <Step title="Подключите свой аккаунт GitHub">
    Если вы раньше не использовали claude.ai/code, ваше первое посещение проведет вас через подключение GitHub; см. [Подключение GitHub](/docs/ru/web-quickstart#connect-github). В противном случае используйте один из [вариантов аутентификации GitHub](/docs/ru/claude-code-on-the-web#github-authentication-options).
  </Step>

  <Step title="Установите Claude GitHub App на репозитории проекта">
    Установите [Claude GitHub App](https://github.com/apps/claude) и предоставьте ей репозитории, которые будет использовать проект. На репозитории, принадлежащем организации GitHub, только владелец организации может завершить установку; если вы не являетесь одним из них, GitHub отправляет владельцу запрос на установку и проект не может использовать репозиторий, пока они его не одобрят.
  </Step>

  <Step title="Авторизуйте SSO для организаций, которые его требуют">
    Если организация GitHub требует SAML SSO, переподключите GitHub и авторизуйте Claude app для этой организации. До тех пор приватные репозитории этой организации не отображаются в диалоге **New project** или **Project settings > Environment**.
  </Step>
</Steps>

Когда один из этих шагов неполный, диалог **New project** и страница проекта называют отсутствующий шаг и ссылаются на то, где вы его завершаете. Завершите шаг там, затем нажмите **Check again**, если диалог это предлагает. Если репозиторий все еще отсутствует в списке после этого, откройте установку Claude GitHub App на GitHub в [github.com/settings/installations](https://github.com/settings/installations) для личного аккаунта и подтвердите, что репозиторий указан в разделе **Repository access**. Для сообщений об ошибках, которые поток или проект сообщают, когда доступ все еще неправильный, см. [Ошибки доступа к репозиторию](#repository-access-errors).

<h2 id="work-in-a-project">
  Работа в проекте
</h2>

Предоставляйте Claude работу через разговор проекта: задачи по одной или несколько сразу, плюс обновления и свободные мысли по мере их появления. Claude маршрутизирует каждое сообщение, и потоки выполняют работу и сообщают обратно.

<h3 id="your-first-batch">
  Ваш первый пакет
</h3>

Перед отправкой новому проекту пакета работы настройте его так, чтобы первые потоки вернулись так, как вы хотите:

1. [Напишите инструкции проекта](#write-project-instructions): краткое описание, с которого начинает каждый поток, например какую ветку выбрать, как поток проверяет свою работу и что требует вашего одобрения.
2. Отправьте один небольшой кусок реальной работы или запустите один из потоков, которые Claude предложил, и откройте поток, когда он завершится, чтобы увидеть, как он сообщает обратно и что он сделал на своей ветке. Если он что-то неправильно предположил или не мог достичь то, что ему нужно, [Потоки угадали или застопорились вместо того, чтобы спросить](#threads-guessed-or-stalled-instead-of-asking) охватывает, где это исправить.
3. Проверьте **Thread model** и **Thread effort** в **Project settings > General**. Новый проект запускает каждый поток на Opus с высокой интенсивностью, что использует ваш план быстрее; [Выбор моделей и позволить Claude управлять контекстом](#choose-models-and-let-claude-manage-context) охватывает альтернативы.
4. Попросите Claude [предложить потоки перед их запуском и запустить несколько одновременно](#tune-how-claude-runs-a-project), и отпустите эти лимиты, когда несколько потоков вернутся так, как вы хотите.

<h3 id="send-work-and-read-results">
  Отправляйте работу и читайте результаты
</h3>

Claude решает, куда идет каждое сообщение, которое вы отправляете в разговор:

* Быстрый вопрос обычно получает ответ в разговоре.
* Новая работа идет в новый поток или в поток, уже работающий в этой области, и Claude говорит вам, какой. Каждый новый поток отображается под вашим сообщением как карточка: коробка с названием и статусом потока, которую вы нажимаете, чтобы открыть поток.
* Несколько несвязанных задач в одном сообщении становятся отдельными потоками.

Если Claude маршрутизирует что-то иначе, чем вы хотели, скажите об этом. [Настройка того, как Claude запускает проект](#tune-how-claude-runs-a-project) перечисляет вещи, которые вы можете ему сказать, например повторное использование существующего потока для последующих действий или ответ на месте вместо запуска потока.

Полные результаты потока остаются в потоке, и вы открываете его карточку в разговоре, чтобы прочитать их. Файлы, которые создал поток, также находятся на вкладке **Library** в **Overview**.

Иногда Claude предлагает потоки вместо их запуска в списке **Suggested threads**. Нажмите стрелку на предложении, чтобы запустить этот поток. Когда их несколько, кнопка под списком запускает все их.

<h3 id="review-a-thread’s-pull-request">
  Проверка pull request потока
</h3>

Когда поток изменяет код, вот что он делает, если вы не скажете иное:

* **Branch**: работает на новой ветке, начиная с ветки по умолчанию репозитория.
* **Pull request**: открывает один, когда вы просите, и может открыть один самостоятельно для исправления ошибки или другого конкретного изменения.
* **После открытия**: наблюдает за pull request с включенным [auto-fix](/docs/ru/claude-code-on-the-web#auto-fix-pull-requests), независимо от того, включен ли auto-fix для ваших других облачных сеансов. Он отправляет исправления, когда CI не работает, обращается к комментариям проверки и отвечает в потоке, когда проверки проходят и pull request готов для вас.

Когда поток отправил ветку или открыл pull request, его карточка в разговоре может показать кнопку для следующего шага:

* **Resolve conflicts**, **Fix CI**, **Address comments** и **Merge it** отправляют эту инструкцию потоку как сообщение от вас, поэтому вы можете подсказать потоку самостоятельно вместо ожидания его реакции на pull request.
* **Review PR** открывает pull request на GitHub.
* **Create PR** появляется, когда неактивный поток отправил ветку, но не открыл pull request. Нажатие на нее создает pull request из этой ветки напрямую, а не отправляет потоку инструкцию открыть один.

Чтобы изменить, когда потоки открывают pull request, например только когда вы просите, или какую ветку они начинают, скажите об этом в задаче или в [инструкциях проекта](#write-project-instructions).

<h3 id="see-what-needs-you-in-overview">
  Посмотрите, что вам нужно в Overview
</h3>

Панель **Overview** рядом с разговором отслеживает потоки проекта. Она уже открыта в первый раз, когда вы открываете новый проект. Кнопка **Overview** в заголовке проекта закрывает и открывает ее заново и показывает точку, когда поток ждет вас.

В настольном приложении вы также получаете уведомление рабочего стола, когда Claude публикует в разговоре, поток попадает в ошибку или потоку нужен ваш ввод, поэтому вам не нужно держать проект открытым, чтобы узнать. Чтобы также получить один каждый раз, когда поток завершает ход, или отключить их для проекта, выберите **Notifications** в меню боковой панели проекта. Эти уведомления только для рабочего стола: в браузере проверьте точку на кнопке **Overview**.

Вкладка **Threads** панели группирует потоки по состоянию:

| Группа               | Что в ней                                                                                                                                                                                                                              |
| :------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ready for review** | Потоки, чей pull request открыт и ожидает проверки                                                                                                                                                                                     |
| **Waiting on you**   | Потоки, которые нуждаются в вашем ответе или одобрении, или которые не прошли                                                                                                                                                          |
| **Working**          | Потоки, которые все еще работают                                                                                                                                                                                                       |
| **Landing**          | Потоки, чей pull request одобрен или поставлен в очередь на слияние                                                                                                                                                                    |
| **Idle**             | Потоки, которые завершены и ничего не ждут                                                                                                                                                                                             |
| **Resolved**         | Потоки, отмеченные как выполненные: вами из меню потока, Claude после того, как вы сделали последний шаг, например слияние его pull request, или автоматически через неделю без активности. Вы можете переоткрыть один из того же меню |

Другие вкладки панели — **Library** для добавленных вами файлов и папок и файлов, созданных потоками, **Pull requests** после открытия потоками любых, и **Routines** для [routines](/docs/ru/routines), которые Claude установил из этого проекта.

<h3 id="open-a-thread-when-you-need-control">
  Откройте поток, когда вам нужен контроль
</h3>

Нажмите карточку потока в разговоре или его строку в **Overview**, чтобы открыть его транскрипт в панели Overview. Оттуда вы можете:

* Прочитать, что сделал Claude, шаг за шагом.
* Направить задачу, написав в собственное поле сообщения потока. Сообщение там идет прямо в этот поток, в то время как последующее действие в разговоре проекта достигает его только, когда Claude соответствует последующему действию этому потоку.
* Ответить на подсказку разрешения, на которую ждет поток.
* Прервать поток с помощью **Stop**, который заменяет кнопку отправки, пока поток работает, или нажав Esc.

<h3 id="choose-models-and-let-claude-manage-context">
  Выбор моделей и позволить Claude управлять контекстом
</h3>

Установите модели и интенсивность в **Project settings > General**. Новый проект запускает Opus везде с высокой [интенсивностью](/docs/ru/model-config#adjust-effort-level) для потоков и низкой интенсивностью для разговора:

* **Thread model** и **Thread effort** применяются к потокам. Чтобы использовать другую модель для одной задачи, попросите это в задаче; для уже работающего потока используйте выбор модели этого потока.
* **Coordinator model** и **Coordinator effort** применяются к Claude в разговоре проекта.

Вы не управляете контекстными окнами в проекте. Потоки автоматически компактируются, и разговор работает из недавних сообщений, недавних потоков и памяти проекта, а не из полной истории, поэтому он продолжается столько, сколько работает проект. Поместите все, что никогда не должно быть потеряно, в [память проекта](#give-a-project-standing-context). Если один поток перерастает свой контекст, он показывает [Claude ran out of context on this turn](#context-limit).

<h3 id="tune-how-claude-runs-a-project">
  Настройка того, как Claude запускает проект
</h3>

Скажите Claude в разговоре, сколько потоков запускать одновременно, когда публиковать обновления и когда открывать pull request. Если Claude координирует так, как вы не хотите, скажите об этом. Например, вы можете сказать:

* "Предложить потоки и ждать моего одобрения перед их запуском" или "Запустить их сейчас без просьбы подтверждения"
* "Запускать максимум два потока одновременно" или "Повторно использовать существующий поток для последующих действий в той же области"
* "Публиковать более короткие обновления" или "Публиковать только когда что-то завершается или блокируется"
* "Дать мне обновление статуса по каждому потоку"
* "Выполнить эту задачу с меньшей моделью"
* "Не открывать pull request, пока я не видел план"
* "Скажи мне, что не так в этих репозиториях и ничего не исправляй", когда вы хотите пройти через выводы перед тем, как любой из них станет потоком
* "Ответить здесь вместо запуска потока", когда Claude запускает поток для чего-то, что вы имели в виду как быстрый вопрос

Claude сохраняет предпочтения, подобные этим, в [память проекта](#give-a-project-standing-context) самостоятельно и следует им в более поздних потоках. Это инструкции, которым Claude следует, а не принудительные параметры, поэтому лимит потоков, который вы даете таким образом, не является жестким ограничением. Добавьте один в инструкции проекта, когда вы хотите, чтобы он был сформулирован точно и применен к каждому потоку с самого начала.

<h3 id="unblock-a-thread-waiting-on-approval">
  Разблокировка потока, ожидающего одобрения
</h3>

Потоки работают в [auto mode](/docs/ru/permission-modes#eliminate-prompts-with-auto-mode), когда модель потока это поддерживает, поэтому большинство вызовов инструментов работают без вашего запроса. Когда потоку нужно ваше одобрение, подсказка находится внутри этого потока и поток ждет, пока вы ответите там. Сказание Claude в разговоре проекта идти дальше не достигает его.

Каждое одобрение охватывает эту подсказку или остаток этого потока, если вы выберете более широкий вариант. Чтобы позволить каждому потоку запускать определенные команды без запроса или блокировать некоторые, добавьте [правила разрешений](/docs/ru/permissions) в `.claude/settings.json` репозитория. Потоки применяют их только в проекте с одним репозиторием; см. [Что потоки берут из ваших репозиториев](#what-threads-pick-up-from-your-repositories).

<h2 id="give-a-project-standing-context">
  Предоставление проекту постоянного контекста
</h2>

Память проекта, инструкции проекта и репозитории, файлы и среда проекта переносят контекст через потоки. Вы устанавливаете каждый один раз.

| Контекст                   | Что он переносит                                                                                                                                                                                                        | Как вы его устанавливаете                                                                                                                                                                        |
| :------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Память проекта             | Заметки, которые Claude хранит о проекте, такие как требования, решения и ошибки, хранящиеся как файлы. Каждый облачный поток читает файл индекса `MEMORY.md` при запуске и открывает другие файлы, когда они ему нужны | Попросите Claude в разговоре проекта или любом облачном потоке запомнить требование, решение или ошибку, или забыть одно. Читайте, редактируйте и удаляйте файлы в **Project settings > Memory** |
| Инструкции проекта         | Текст, отправляемый каждому новому потоку и Claude в разговоре проекта, до 16 000 символов. [Напишите инструкции проекта](#write-project-instructions) охватывает, что в него поместить                                 | **Project settings > Memory > Project instructions**, или попросите Claude изменить инструкции                                                                                                   |
| Репозитории, файлы и среда | Репозитории, которые клонирует каждый облачный поток, папки и файлы, которые он может читать в `/mnt/project-files`, и облачная среда, в которой он работает                                                            | Репозитории и среда в **Project settings > Environment**, или попросите Claude в разговоре добавить репозиторий в проект. Файлы и папки из **Add** на вкладке **Library** в **Overview**         |

**Project settings > Memory** перечисляет эти файлы в разделе **Auto memory**, потому что Claude пишет их сам, пока работает в проекте. Они отделены от [auto memory](/docs/ru/memory), которую Claude Code хранит на вашей машине, даже несмотря на то, что оба используют индекс `MEMORY.md`. Память проекта также отделена от файлов `CLAUDE.md` в репозиториях проекта. Каждый облачный поток все еще читает эти файлы `CLAUDE.md` из своего клона при запуске, поэтому поместите инструкции о репозитории в его `CLAUDE.md` и заметки о проекте в память проекта.

<h3 id="write-project-instructions">
  Напишите инструкции проекта
</h3>

Инструкции проекта — это краткое описание, с которого начинает каждый новый поток. Нажмите значок шестеренки в заголовке проекта, чтобы открыть **Project settings**, затем перейдите в **Memory > Project instructions**. Полезное краткое описание охватывает:

* Для чего предназначен проект
* Где происходит работа: какие репозитории, какую ветку начать, как назвать pull requests
* Как поток проверяет свою работу перед тем, как назвать это выполненным
* Что делать, когда что-то, что ему нужно, отсутствует
* Что требует вашего одобрения в первую очередь

Например:

```text theme={null}
Этот проект держит p95 задержку для API платежей ниже 200 мс: профилирование, исправления запросов и кэширования, и обновления зависимостей, которые с ними идут, в репозитории payments-api.

- Ветвитесь от main и откройте один черновик pull request для каждого потока.
- Перед тем, как назвать работу выполненной, запустите `make test` и `make lint` и вставьте строки сводки в ваше финальное сообщение.
- Если вы не можете достичь что-то, что вам нужно, например репозиторий, секрет, API или connector, скажите точно, что отсутствует в вашем первом сообщении и остановитесь. Не подменяйте, не имитируйте и не угадывайте.
- Не объединяйте, не выполняйте force-push и не изменяйте конфигурацию CI без моего запроса в потоке.
```

Правила об одном репозитории, такие как его команды сборки, принадлежат `CLAUDE.md` этого репозитория, который каждый облачный поток читает, когда репозиторий является частью проекта. Когда работа идет, когда вы исправляете поток, также скажите Claude запомнить исправление: оно идет в [память проекта](#give-a-project-standing-context) и более поздние облачные потоки начинают с ним.

<h3 id="decide-which-repositories-to-add">
  Решение, какие репозитории добавить
</h3>

Репозитории, которые вы добавляете в проект, поступают со всем в них, их код, `CLAUDE.md` и skills, в каждом облачном потоке. Репозитории, которые вы не добавляете, все еще в пределах досягаемости: облачный поток может добавить один к себе, когда его задача это требует. Большинство проектов используют оба:

* **Добавьте его в проект**, в диалоге **New project**, в **Project settings > Environment**, или попросив Claude в разговоре добавить его в проект. Каждый облачный поток с этого момента клонирует его и начинает с его `CLAUDE.md` и skills загруженными, независимо от того, касается ли задача его. Переход от одного репозитория к нескольким также изменяет то, что потоки берут из `.claude/settings.json` каждого репозитория; см. [Что потоки берут из ваших репозиториев](#what-threads-pick-up-from-your-repositories).
* **Оставьте его и позвольте потокам добавить его, когда это необходимо.** Облачный поток, чья задача требует репозитория, который проект не имеет, может добавить его к себе, и заметка в потоке говорит, что он был добавлен только в этот поток. Клон происходит в середине задачи, поэтому `CLAUDE.md` и skills этого репозитория не были там, когда поток начался. Следующий поток начинает без него. Репозиторий, добавленный таким образом, требует те же [предварительные условия](#check-the-prerequisites), что и репозиторий проекта: Claude GitHub App установлено на нем и доступ на push из вашего аккаунта GitHub.

Проект вообще не требует репозитория. Его облачные потоки все еще могут исследовать, писать документы и писать и запускать код в собственной песочнице, и они доставляют файлы на вкладку **Library**. Любой из его облачных потоков все еще может добавить репозиторий к себе, когда задача это требует.

Когда проект имеет репозитории, Claude может добавлять только репозитории от владельца GitHub, который проект уже использует, независимо от того, добавляет ли он один в проект или поток добавляет один к себе. Чтобы привести репозиторий от другого владельца, добавьте его в проект самостоятельно в **Project settings > Environment**.

Для проекта, охватывающего много репозиториев, например одну функцию с кодом сервера, веб, мобильного и рабочего стола, добавьте один или два репозитория, которые почти каждая задача касается, и назовите остальные в [инструкциях проекта](#write-project-instructions), чтобы Claude знал, где находится остальной код. Облачные потоки затем начинают маленькими и вытягивают другие репозитории только для задач, которые их требуют.

<h3 id="what-threads-pick-up-from-your-repositories">
  Что потоки берут из ваших репозиториев
</h3>

Каждый облачный поток клонирует каждый репозиторий в проекте и загружает `CLAUDE.md` и skills из всех них. Правила разрешений, hooks и `env` поступают только из `.claude/settings.json` в директории, где поток начинается: внутри репозитория, когда проект имеет один, и выше клонов, когда он имеет несколько, где файл ни одного репозитория не читается для них.

| В каждом репозитории                                                      | Один репозиторий                                                                                                                                  | Несколько репозиториев                                                        |
| :------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------- |
| `CLAUDE.md`                                                               | Загружается при запуске потока                                                                                                                    | Загружается из каждого репозитория при запуске потока                         |
| Skills, agents и команды в `.claude/`                                     | Загружаются                                                                                                                                       | Загружаются из каждого репозитория                                            |
| Plugins, включенные в `.claude/settings.json`                             | Не загружаются. Добавьте plugin в **Project settings > Plugins** вместо этого                                                                     | Не загружаются. Добавьте plugin в **Project settings > Plugins** вместо этого |
| Правила разрешений, hooks и `env`, определенные в `.claude/settings.json` | Применяются к потоку, кроме ключей `env`, которые [ни один облачный сеанс не соблюдает](/docs/ru/cloud-environments#what-carries-over-from-your-setup) | Не применяются                                                                |

В проекте с несколькими репозиториями каждый клон прикреплен к потоку как [дополнительная директория](/docs/ru/memory#load-from-additional-directories) с включенной загрузкой `CLAUDE.md`, что является причиной того, что `CLAUDE.md` и skills каждого репозитория загружаются при запуске, даже несмотря на то, что поток начинается выше них. В таком проекте поместите постоянные правила в инструкции проекта и дайте потокам переменные окружения через [облачную среду](#choose-an-environment-for-threads).

<h3 id="choose-an-environment-for-threads">
  Выбор среды для потоков
</h3>

Каждый новый облачный поток начинается в [облачной среде](/docs/ru/cloud-environments) проекта. Среда устанавливает, какие домены могут достичь потоки, какие переменные окружения они имеют, какие учетные данные API добавляются в их запросы и что скрипт настройки устанавливает перед началом Claude. Облачные потоки используют среду по умолчанию, размещенную Anthropic, пока вы не выберете одну в **Project settings > Environment**.

Если облачным потокам нужно достичь внутреннего API или приватного реестра пакетов, или нужен токен, который ваша машина обычно держит, измените среду, а не проект: см. [Сетевой доступ](/docs/ru/cloud-environments#network-access), [Добавить учетные данные API](/docs/ru/cloud-environments#add-api-credentials) и [Скрипты настройки](/docs/ru/cloud-environments#setup-scripts).

<h3 id="get-skills-plugins-connectors-and-tools-into-threads">
  Получить skills, plugins, connectors и инструменты в потоки
</h3>

Облачные потоки не имеют skills, MCP servers, plugins и инструментов, установленных только на вашей машине. Поток, который Claude запускает на вашей машине через [Remote Control](/docs/ru/remote-control), использует то, что установлено там. Чтобы сделать каждый из них доступным для облачных потоков:

* Skills, subagents и команды: зафиксируйте их в репозитории, который вы добавили в проект, например skill в `.claude/skills/<skill-name>/SKILL.md`. Каждый облачный поток клонирует каждый репозиторий в проекте и загружает `.claude/skills/`, `.claude/agents/` и `.claude/commands/` из каждого из них, поэтому skill, зафиксированный в одном репозитории, доступен в каждом облачном потоке. Облачные потоки также загружают skills, которые вы включаете для вашего аккаунта claude.ai.
* Plugins: добавьте их в **Project settings > Plugins**; они загружаются в каждый новый облачный поток. Plugins, которые репозиторий объявляет в его `.claude/settings.json`, [не загружаются в облачные потоки](/docs/ru/cloud-environments#what-carries-over-from-your-setup).
* MCP servers: облачные потоки получают свои MCP инструменты из connectors на вашем аккаунте claude.ai, которые являются MCP servers, которые вы подключаете один раз в [claude.ai/customize/connectors](https://claude.ai/customize/connectors) или через ссылку **Manage connectors** в **Project settings > Environment**. Каждый облачный поток может использовать все их без настройки для каждого проекта. Разговор проекта сам по себе не имеет connectors, поэтому отправляйте работу, которая требует один, как задачу для облачного потока. В проекте с одним репозиторием облачные потоки также загружают MCP servers из [`.mcp.json`](/docs/ru/cloud-environments#what-carries-over-from-your-setup) этого репозитория. [Как connectors достигают Claude Code](/docs/ru/mcp#how-connectors-reach-claude-code) перечисляет правила для облачных сеансов и параметры, которые отключают connectors.
* Инструменты командной строки и пакеты: установите их в [скрипт настройки](/docs/ru/cloud-environments#setup-scripts) среды.

Чтобы увидеть, какие connectors имеет работающий облачный поток в claude.ai/code, откройте поток и выберите **Connectors** из меню **+** рядом с его полем сообщения. Отключение connector там удаляет его из этого потока и сохраняет это как ваше значение по умолчанию для аккаунта, поэтому новые облачные потоки и чаты claude.ai начинают без него, пока вы его не включите снова. Облачный поток подхватывает connector, который вы добавляете или переподключаете после следующего сообщения, которое вы ему отправляете.

<h2 id="project-settings-reference">

Вы изменяете параметры проекта в claude.ai/code или в настольном приложении, а не в `settings.json`. Откройте **Project settings** из **Settings** в меню боковой панели проекта или из значка шестеренки в заголовке проекта.

Параметры сохраняются по мере их изменения; текстовое поле, которое вы редактируете, например цель или инструкции, показывает **Save changes** и **Discard** до тех пор, пока вы его не покинете. Изменения инструкций, репозиториев, plugins и среды в **Project settings** достигают новые потоки, а не уже работающие потоки.

<h3 id="pause-archive-or-delete-a-project">
  Пауза, архивирование или удаление проекта
</h3>

Все три элемента управления находятся в нижней части **Project settings > General**:

* **Pause**: останавливает все сразу. Каждый работающий поток и разговор прерываются, новые потоки не запускаются, routines не работают, и проект не принимает сообщения, пока вы его не возобновите. Нажмите **Resume** в том же месте или на баннере выше поля сообщения проекта; приостановленный поток продолжает работу, когда вы отправляете ему сообщение после этого.
* **Archive**: скрывает проект из боковой панели и архивирует его потоки, что останавливает любой поток, который работал или наблюдал за pull request. Routines в проекте не работают, пока он архивирован. Чтобы вернуть проект, откройте его со страницы Projects и нажмите **Unarchive**. Его потоки остаются архивированными, пока вы не разархивируете их отдельно из списка сеансов.
* **Delete**: постоянно удаляет проект вместе с его потоками, его памятью и его файлами, и отключает routines проекта. Это не может быть отменено. Ветки и pull request, которые потоки отправили на GitHub, не затрагиваются.

<h2 id="usage-and-cost">
  Использование и стоимость
</h2>

Использование проекта считается против тех же [лимитов плана](/docs/ru/errors#youve-hit-your-session-limit), что и ваши другие сеансы Claude Code, и проект не может потратить больше этих лимитов самостоятельно.

Поток, который достигает лимита вашего плана, ждет и продолжает самостоятельно, когда лимит сбрасывается, поэтому работа, которую вы оставили работающей, начинает использовать ваше следующее окно использования без сообщения от вас. [Поток достиг лимита использования](#usage-limit-reached) охватывает то, что вы видите, как его остановить и один случай, который не ждет.

Работа выходит за пределы лимитов вашего плана только если вы включили [usage credits](/docs/ru/costs#add-usage-credits-to-your-subscription) для вашего аккаунта. Поток не может включить их для вас.

<h3 id="what-draws-on-your-plan">
  Что использует ваш план
</h3>

Проект использует ваши лимиты быстрее, чем один сеанс, и на плане Pro в частности вы должны ожидать достичь ваш лимит раньше в дни, когда вы запускаете один. Это части проекта, которые используют ваш план:

* **Работающие потоки**: каждый — это полный сеанс, и несколько могут работать одновременно. Нет фиксированного числа; Claude запускает столько, сколько требует работа, и лимит, который вы [просите](#tune-how-claude-runs-a-project), — это предпочтение, а не ограничение. Принудительный лимит — 200 новых потоков в день во всех ваших проектах.
* **Разговор**: Claude использует токены самостоятельно, читая то, что сообщают потоки и решая, что делать дальше.
* **Потоки, наблюдающие за pull request**: неактивный поток просыпается и использует ваш план снова, когда CI не работает или приходит комментарий проверки на его pull request. Чтобы остановить это, попросите в потоке остановить наблюдение за pull request.

Проект без работающих потоков, без наблюдаемых pull request и без новых сообщений не использует ваш план, пока он сидит неактивным, и архивированный проект тоже.

<h3 id="see-and-reduce-a-project’s-usage">
  Посмотрите и уменьшите использование проекта
</h3>

Откройте **Usage** в **Project settings**, чтобы увидеть использование токенов по потокам и по моделям, и сколько пошло в разговор проекта. Чтобы снизить его:

* Последующее действие, направленное в поток, который был неактивным дольше, чем [время жизни кэша](/docs/ru/prompt-caching#cache-lifetime), час на Pro и Max в пределах лимитов вашего плана, перечитывает весь разговор этого потока перед тем, как что-то делать. Для новой работы, просьба Claude запустить свежий поток может использовать меньше, чем возрождение большого старого.
* Для работы, которая не требует самую большую модель, [выберите меньшую модель или более низкий уровень интенсивности](#choose-models-and-let-claude-manage-context) для потоков, разговора или обоих.
* Попросите Claude в разговоре проекта запускать меньше потоков одновременно или отвечать на маленькие вопросы самостоятельно вместо запуска потока.

<h2 id="how-projects-relate-to-other-claude-code-features">
  Как проекты связаны с другими функциями Claude Code
</h2>

Несколько функций Claude Code позволяют более чем одному сеансу работать одновременно, поэтому запуск работы параллельно — это не само по себе то, для чего предназначен проект. В проекте Claude запускает и отслеживает сеансы вместо вас, и каждый начинается с одних и тех же инструкций. Вот как каждая соседняя функция соединяется с проектом:

* **Claude Tag**: [Claude Tag](https://claude.com/docs/claude-tag/overview) — это Claude в каналах Slack вашей команды, на планах Team и Enterprise. Любой в канале может дать ему работу, все в канале видят и направляют его, и он использует соединения, которые администратор установил для этого канала. Проект — это только ваш: вы единственный, кто отправляет ему работу или видит его потоки, он использует ваш собственный доступ GitHub и connectors, и он на Pro и Max. [Как Claude Tag отличается от Cowork и Claude Code](https://claude.com/docs/claude-tag/concepts/how-it-works#how-claude-tag-differs-from-cowork-and-claude-code) имеет рядом.
* **Cloud sessions**: каждый поток — это [облачный сеанс](/docs/ru/claude-code-on-the-web), если вы не попросите Claude запустить его на вашей машине. В любом случае Claude запускает и отслеживает его вместо вас. Облачный сеанс, который вы запустили самостоятельно, может стать проектом или питать один через [**Continue as a project** или **Move to project**](#start-from-an-existing-cloud-session).
* **Routines**: когда вы просите запланированную работу в проекте, Claude создает [routine](/docs/ru/routines), которая работает как потоки в этом проекте и отображается на его вкладке **Routines**. Routines, которые вы создаете вне проекта, продолжают работать самостоятельно.
* **Local sessions и agent view**: сеанс, который вы запускаете самостоятельно в вашем терминале, IDE или локальной среде настольного приложения, не может быть добавлен в проект. Проект достигает вашей машины только путем запуска потока там через [Remote Control](/docs/ru/remote-control). [Agent view](/docs/ru/agent-view) — это экран для отслеживания нескольких локальных сеансов, которые вы запустили самостоятельно; он не имеет координатора.
* **Worktrees**: [worktree](/docs/ru/worktrees) дает каждому локальному сеансу свою рабочую копию репозитория, поэтому параллельные сеансы на вашей машине не перезаписывают друг друга. Облачным потокам они не нужны: каждый клонирует свои репозитории в свою облачную песочницу и работает на своей ветке.
* **Agent teams**: [agent team](/docs/ru/agent-teams) — это один сеанс, который запускает сеансы товарищей для одной задачи, на вашей машине или внутри облачного сеанса, и заканчивается этой задачей.
* **Projects в claude.ai chat и Cowork**: [более ранний опыт Projects](https://support.claude.com/en/articles/9517075-what-are-projects), который группирует разговоры и справочные файлы без потоков или координатора. Эти проекты продолжают работать так, как они работают сегодня, пока переработанный опыт не достигнет их.

[Запуск агентов параллельно](/docs/ru/agents) сравнивает эти варианты рядом.

<h2 id="limitations">
  Ограничения
</h2>

* Projects доступны в claude.ai/code, в настольном приложении и в мобильном приложении Claude, но не в CLI терминала или через Amazon Bedrock, Google Cloud's Agent Platform или Microsoft Foundry. Команда [`claude project`](/docs/ru/cli-reference) CLI, которая управляет локальным состоянием Claude Code для директории, не связана.
* Потоки проекта — это [облачные сеансы](/docs/ru/claude-code-on-the-web) или сеансы на вашей собственной машине через [Remote Control](/docs/ru/remote-control), с Anthropic в качестве поставщика модели в обоих случаях. [Безопасность](/docs/ru/security) и [Использование данных](/docs/ru/data-usage) охватывают, как облачные сеансы изолированы и что сохраняется, а [Connection and security](/docs/ru/remote-control#connection-and-security) охватывает, как поток на вашей машине подключается и что хранится.
* Вы не можете добавить сеанс, который вы запустили сами на вашей машине, в проект. Чтобы позволить проекту запустить поток на вашей машине, подключите папку, в которой он должен работать, через [Remote Control](/docs/ru/remote-control#requirements): включите Remote Control в **Settings > Claude Code** в настольном приложении Claude или запустите `claude remote-control` в папке и оставьте его работающим. Эта машина должна иметь Claude Code v2.1.280 или позже. Проект также не может запустить поток на вашей машине, пока в ваших настройках claude.ai включена опция **Require trusted devices**.
* Песочница потока приостанавливается между ходами и возобновляется, когда поток продолжает. Если песочница не может быть возобновлена, поток продолжает с свежего клона, поэтому незафиксированные изменения могут быть потеряны. На долгих задачах попросите Claude зафиксировать и отправить работу в процессе.
* Проект принадлежит одному пользователю. Вы не можете поделиться проектом или его потоками с другим пользователем, и транскрипты потоков не имеют опции поделиться, которую имеют другие облачные сеансы. Нет элементов управления на уровне организации для проектов во время бета-версии.
* Поток принадлежит одному проекту, который его запустил. Вы не можете переместить или скопировать поток в другой проект или переместить его отдельно. [**Move to project**](#start-from-an-existing-cloud-session) идет только в другую сторону: он переносит работу облачного сеанса в проект.

<h2 id="troubleshooting">
  Troubleshooting
</h2>

Для подсказок настройки GitHub в диалоге **New project**, см. [Настройка доступа GitHub](#set-up-github-access).

<h3 id="a-thread-looks-stuck">
  Поток выглядит застрявшим
</h3>

Claude не публикует каждый шаг, который делает поток, поэтому поток, который показывает как работающий без новых сообщений в разговоре проекта, обычно все еще работает. Новый облачный поток также подготавливает свою [облачную среду](/docs/ru/cloud-environments) перед началом Claude, поэтому его первое обновление занимает момент. Откройте поток, чтобы прочитать его транскрипт. Если поток ждет подсказку разрешения, ответьте там.

<h3 id="threads-guessed-or-stalled-instead-of-asking">
  Потоки угадали или застопорились вместо того, чтобы спросить
</h3>

Когда несколько потоков возвращаются, имея предположено что-то неправильно, обошли отсутствующий доступ или остановились с "blocked", причина обычно одна и та же пробел в настройке проекта, а не проблема с каждой задачей. Отсортируйте, какие потоки звучат правильно, перед тем, как вы что-то исправляете:

1. Попросите Claude в разговоре: "Для каждого открытого потока, перечислите, что вы просили его сделать, что он предположил или не мог достичь, и на что он ждет." Claude читает каждый поток и отвечает в разговоре.
2. Для потоков, которые начались с неправильного предположения, откройте поток из **Overview** и отметьте его разрешенным из его меню, или скажите ему, что делать вместо этого в его поле сообщения. Его ветка и любой pull request остаются на GitHub, пока вы их не удалите.
3. Исправьте пробел один раз, в [инструкциях проекта](#give-a-project-standing-context) или [среде](#choose-an-environment-for-threads), затем отправьте один поток перед отправкой остальной работы снова как новые потоки.

<h3 id="claude-hasnt-responded">
  Claude не ответил
</h3>

Разговор проекта показывает баннер "Claude hasn't responded", когда Claude работает, но его ответы не достигают проекта. Нажмите **Restart Claude** на баннере или перейдите в **Project settings > General** и нажмите **Restart** в строке **Restart Claude**. Claude переподключается к разговору; любой ответ, который он был в процессе написания, потеряется, и потоки не затрагиваются.

<h3 id="repository-access-errors">
  Ошибки доступа к репозиторию
</h3>

Три сообщения означают, что поток или проект не может достичь один из своих репозиториев. Потокам проекта требуются [предварительные условия GitHub](#check-the-prerequisites) даже когда ваши другие облачные сеансы клонируют один и тот же репозиторий без проблем.

* **"Couldn't start the session — Claude doesn't have GitHub access to this project's repository"**, сообщено перед запуском потока, когда Claude GitHub App не установлено на этом репозитории, приостановлено или не связано с аккаунтом GitHub, который вы подключили.
* **"Unable to access your repository"**, сообщено потоком, когда его клон не работает: GitHub отклонил клон, репозиторий не был найден под названием, которое имеет проект, или ветка, с которой потоку было предложено начать, не существует.
* **"Claude can't access"** репозиторий, показано, когда вы сохраняете репозитории в диалоге **New project** или **Project settings**. Сообщение продолжается со ссылкой на установку и ссылкой на переподключение. Используйте ссылку на установку, если Claude GitHub App не на этом репозитории, и ссылку на переподключение, если она есть, так как GitHub App может быть установлено на GitHub без связи с аккаунтом, который вы подключили к Claude. Если сообщение говорит, что GitHub App приостановлено или не включает этот репозиторий, следуйте его ссылке на GitHub, чтобы это исправить.

Чтобы исправить любой из них, нажмите кнопку, которую предлагает сообщение, например **Install GitHub App** или **Select repositories on GitHub**, затем **Check again**. Когда блок находится на стороне организации GitHub, например владелец, который не одобрил приложение или IP allow list, который исключает Claude, сообщение показывает ссылку **See how to fix** вместо этого. Если нет кнопки, следуйте [Настройка доступа GitHub](#set-up-github-access), затем отправьте другое сообщение для повтора.

<h3 id="usage-limit-reached">
  Поток достиг лимита использования
</h3>

Когда поток или разговор проекта достигает пятичасового или еженедельного лимита вашего плана, он продолжает повторять попытки самостоятельно и продолжает, когда лимит сбрасывается. Пока он ждет, поток показывает **Service is busy** с "Claude is still retrying and will continue automatically." Вам не нужно ничего делать, чтобы работа продолжилась. Если вы предпочитаете, чтобы он не использовал ваше следующее окно использования, нажмите **Stop** в потоке или [приостановите проект](#pause-archive-or-delete-a-project), чтобы удержать каждый поток. Поток, который запустила routine, не ждет: его ход останавливается с ошибкой лимита, и вы отправляете ему сообщение после сброса лимита.

[Ошибки лимита использования](/docs/ru/errors#youve-hit-your-session-limit) объясняют лимиты и когда они сбрасываются.

<h3 id="additional-usage-credits-are-required">
  Требуются дополнительные usage credits
</h3>

Поток или разговор проекта сделал запрос, который ваш план охватывает только с usage credits, например один к модели или размеру контекста, который ваш план не включает, и usage credits не включены для вашего аккаунта. [Добавить usage credits к вашей подписке](/docs/ru/costs#add-usage-credits-to-your-subscription) охватывает, кто может их включить или купить на каждом плане. Когда credits доступны, отправьте другое сообщение для повтора.

<h3 id="context-limit">
  Другие сообщения
</h3>

Эти сообщения называют свою собственную причину. Таблица дает следующий шаг для каждого.

| Сообщение                                                                                   | Что делать                                                                                                                                                                                                                            |
| :------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| "Unable to connect to repository" с "Claude couldn't reach GitHub to fetch your repository" | Подождите момент, затем отправьте другое сообщение для повтора                                                                                                                                                                        |
| "Unable to connect to repository" с "Claude couldn't access your repository or environment" | Ваш аккаунт GitHub требует доступ на push к репозиторию, и среда должна все еще существовать. Проверьте оба в **Project settings > Environment**, затем повторите                                                                     |
| "Couldn't show the setup proposal"                                                          | Приложение, которое у вас открыто, старше, чем **Setup recommendations**, которые Claude отправил. Обновите страницу или перезагрузите настольное приложение, или попросите Claude предложить настройку снова                         |
| "The project's environment was removed"                                                     | Выберите другую среду в **Project settings > Environment**; изменение применяется к новым потокам                                                                                                                                     |
| "Setup script failed"                                                                       | Нажмите **Edit setup script** на ошибке, исправьте скрипт в среде, затем отправьте другое сообщение. [Setup script failed](/docs/ru/web-quickstart#setup-script-failed) перечисляет общие причины                                          |
| "Claude ran out of context on this turn"                                                    | Поток заполнил свое контекстное окно. Если сообщение говорит, что поток продолжает в свежем сеансе, он продолжает самостоятельно; в противном случае попросите Claude в разговоре проекта запустить новый поток для оставшейся работы |
| "Reached the turn limit"                                                                    | Поток достиг ограничения на шаги для одного сообщения, которое устанавливает [`CLAUDE_CODE_MAX_TURNS`](/docs/ru/env-vars). Отправьте другое сообщение для продолжения, или повысьте или удалите эту переменную там, где она установлена    |
