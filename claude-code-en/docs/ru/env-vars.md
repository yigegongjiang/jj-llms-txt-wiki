# Переменные окружения

> Справочник переменных окружения, которые управляют поведением Claude Code.

Переменные окружения могут управлять поведением Claude Code, таким как выбор модели, аутентификация, маршрутизация запросов и переключатели функций. Многие из этих же поведений также можно настроить через [файл параметров](/docs/ru/settings), [флаг CLI](/docs/ru/cli-reference) или команду в сессии, такую как `/model`.

На этой странице рассматривается, как:

* [Установить переменные окружения](#set-environment-variables) в вашей оболочке или в файле параметров
* [Проверить, какое значение применяется](#precedence), когда поведение можно установить несколькими способами
* [Найти переменные, которые читает Claude Code](#variables)

<h2 id="set-environment-variables">
  Установить переменные окружения
</h2>

Переменная, которую вы установите в своей оболочке, действует только для этого сеанса терминала, а переменная в файле параметров применяется каждый раз, когда запускается `claude`.

<h3 id="in-your-shell">
  В вашей оболочке
</h3>

Установите переменную перед запуском `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Чтобы установить её для каждого сеанса, добавьте строку `export` в `~/.bashrc`, `~/.zshrc` или файл профиля вашей оболочки.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Чтобы установить её для каждого сеанса, запустите `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` и откройте новый терминал.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Чтобы установить её для каждого сеанса, запустите `setx API_TIMEOUT_MS "1200000"` и откройте новый терминал.
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  В файлах параметров
</h3>

Добавьте переменные под ключом `env` в файл `settings.json`. Claude Code читает их непосредственно из файла при запуске, поэтому они вступают в силу независимо от того, как был запущен `claude`.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

Выбранный вами файл определяет, к кому применяются переменные:

| Файл                          | Применяется к                                                                            |
| :---------------------------- | :--------------------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | Вам, в каждом проекте                                                                    |
| `.claude/settings.json`       | Всем, кто работает в проекте, проверено в системе управления версиями                    |
| `.claude/settings.local.json` | Вам, только в этом проекте (добавьте его в ваш gitignore, если вы создадите его вручную) |
| Управляемые параметры         | Всем в вашей организации, развёрнуто администратором                                     |

См. [Файлы параметров](/docs/ru/settings#settings-files), чтобы узнать, где находится каждый файл, и [Приоритет параметров](/docs/ru/settings#settings-precedence), чтобы узнать, как они объединяются, когда более одного устанавливает одну и ту же переменную.

<h2 id="precedence">
  Приоритет
</h2>

Когда одно и то же поведение имеет как переменную окружения, так и поле параметров, переменная окружения имеет приоритет. Например, `ANTHROPIC_MODEL` переопределяет параметр `model`, а `CLAUDE_CODE_AUTO_CONNECT_IDE` переопределяет `autoConnectIde`. Поле параметров применяется, когда переменная окружения не установлена.

Когда одна и та же переменная установлена как в вашей оболочке, так и в файле параметров в блоке `env`, применяется значение из файла параметров. Claude Code записывает каждую запись `env` в переменные окружения процесса при запуске, заменяя значение, унаследованное из оболочки. Несколько переменных обрабатываются специально; [параметр `env`](/docs/ru/settings#available-settings) содержит список исключений.

Между файлами параметров значения `env` следуют [приоритету параметров](/docs/ru/settings#settings-precedence), поэтому управляемая запись параметров переопределяет ту же переменную в пользовательских или проектных параметрах.

То, как переменная окружения взаимодействует с флагами CLI и командами в сессии, варьируется в зависимости от функции: `--model` и `/model` переопределяют `ANTHROPIC_MODEL`, а `CLAUDE_CODE_EFFORT_LEVEL` переопределяет `/effort`. Когда переменная взаимодействует с другим источником конфигурации, её строка в списке [Переменные](#variables) указывает приоритет или ссылается на страницу, которая это документирует.

Claude Code читает переменные окружения при запуске, поэтому изменения вступают в силу при следующем запуске `claude`.
