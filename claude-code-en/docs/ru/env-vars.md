# Переменные окружения

> Справочник по переменным окружения, которые управляют поведением Claude Code.

Переменные окружения могут управлять поведением Claude Code, такие как выбор модели, аутентификация, маршрутизация запросов и переключатели функций. Многие из этих же поведений также можно настроить через поле [файла параметров](/docs/ru/settings), [флаг CLI](/docs/ru/cli-reference) или команду в сеансе, такую как `/model`.

На этой странице рассматривается, как:

* [Установить переменные окружения](#set-environment-variables) в вашей оболочке или в файле параметров
* [Проверить, какое значение применяется](#precedence), когда поведение можно установить несколькими способами
* [Найти переменные, которые читает Claude Code](#variables)
* [Посмотреть, какие функции перестают работать](#features-that-need-feature-flag-fetching), когда переменная отключает получение флагов функций

<h2 id="set-environment-variables">
  Установка переменных окружения
</h2>

Переменная, установленная в вашей оболочке, действует только в течение этого сеанса терминала, а переменная в файле параметров применяется каждый раз при запуске `claude`.

<h3 id="in-your-shell">
  В вашей оболочке
</h3>

Установите переменную перед запуском `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    Чтобы установить её для каждого сеанса, добавьте строку `export` в `~/.bashrc`, `~/.zshrc` или файл профиля вашей оболочки.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    Чтобы установить её для каждого сеанса, выполните `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` и откройте новый терминал.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    Чтобы установить её для каждого сеанса, выполните `setx API_TIMEOUT_MS "1200000"` и откройте новый терминал.
  </Tab>
</Tabs>

Строка присваивания ничего не выводит при успехе, поэтому подтвердите, что переменная установлена, выведя её в той же оболочке перед запуском `claude`:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    echo $API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    echo $env:API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    echo %API_TIMEOUT_MS%
    ```
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  В файлах параметров
</h3>

Добавьте переменные под ключом `env` в файл `settings.json`, создав файл, если его ещё нет. Claude Code читает их непосредственно из файла, поэтому они вступают в силу независимо от того, как был запущен `claude`. Работающий сеанс применяет новые и изменённые значения к своему окружению при сохранении файла, но функция, которая читает свои переменные один раз при запуске, такая как [мониторинг OpenTelemetry](/docs/ru/monitoring-usage), сохраняет свои значения при запуске до перезапуска. Удаление переменной из файла не отменяет её в работающем сеансе; удаление вступает в силу при следующем запуске `claude`.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

Выбранный вами файл определяет, к кому применяются переменные:

| Файл                          | Применяется к                                                                                                                        |
| :---------------------------- | :----------------------------------------------------------------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | Вам, в каждом проекте                                                                                                                |
| `.claude/settings.json`       | Всем, кто работает в проекте, проверено в системе управления версиями                                                                |
| `.claude/settings.local.json` | Вам, только в этом проекте, игнорируется git, когда Claude Code сохраняет параметр; добавьте его в gitignore, если создадите вручную |
| Управляемые параметры         | Всем в вашей организации, развёрнуто администратором                                                                                 |

См. [Файлы параметров](/docs/ru/settings#where-settings-live) для информации о том, где находится каждый файл, и [Приоритет параметров](/docs/ru/settings#settings-precedence) для информации о том, как они объединяются, когда более одного устанавливает одну и ту же переменную.

<h2 id="precedence">
  Приоритет
</h2>

Некоторые поведения имеют как переменную окружения, так и выделенный ключ параметров, и то, какой из них Claude Code читает первым, отличается для каждого ключа. Для `ANTHROPIC_MODEL` и `CLAUDE_CODE_AUTO_CONNECT_IDE` Claude Code сначала читает переменную и использует параметр `model` или `autoConnectIde` только когда переменная не установлена. Для пары, которую вы устанавливаете, проверьте строку переменной ниже и запись ключа в [справочнике параметров](/docs/ru/settings-reference).

Когда одна и та же переменная установлена как в вашей оболочке, так и в блоке `env` файла параметров, применяется значение из файла параметров. Claude Code записывает каждую запись `env` в переменные окружения процесса, заменяя значение, унаследованное из оболочки. [Параметр `env`](/docs/ru/settings-reference#when-claude-code-applies-env-values) указывает, когда он их применяет. Несколько переменных имеют специальную обработку; [параметр `env`](/docs/ru/settings-reference#env) перечисляет исключения.

В файле параметров вы можете установить переменную, но не можете удалить её. Чтобы переопределить переменную, которую вы не можете отменить, например устаревшую `CLAUDE_CODE_USE_VERTEX`, экспортированную профилем оболочки, который вы не контролируете, установите её на пустую строку в блоке `env`: `"CLAUDE_CODE_USE_VERTEX": ""`. Claude Code рассматривает пустое значение как неустановленное для выбора поставщика. Подпроцессы по-прежнему наследуют пустое значение.

Между файлами параметров значения `env` следуют [приоритету параметров](/docs/ru/settings#settings-precedence), поэтому управляемая запись параметров переопределяет ту же переменную в пользовательских или проектных параметрах.

То, как переменная окружения взаимодействует с флагами CLI и командами в сеансе, варьируется в зависимости от функции: `--model` и `/model` переопределяют `ANTHROPIC_MODEL`, в то время как `CLAUDE_CODE_EFFORT_LEVEL` переопределяет `--effort` и `/effort`. Когда переменная взаимодействует с другим источником конфигурации, её строка в списке [Переменные](#variables) указывает приоритет или ссылается на страницу, которая это документирует.

Claude Code читает переменные окружения оболочки при запуске, поэтому изменения в них вступают в силу при следующем запуске `claude`. Переменные, установленные под ключом `env` в файлах параметров, переприменяются к работающему сеансу при изменении файла, за исключением только при запуске, описанном в [В файлах параметров](#in-settings-files).

<h2 id="variables">
  Переменные
</h2>

Числовые переменные, такие как таймауты, бюджеты токенов и количество повторов, принимают научную нотацию и написание с разделителями цифр в дополнение к простым цифрам, за исключением случаев, когда в строке переменной указано, что она принимает только простые цифры. Например, Claude Code читает `2e3` как 2000 и `64_000` как 64000. До версии 2.1.211 эти написания могли молча установить гораздо меньшее значение, например `1e6` установить таймаут на 1.

<Note>
  Для переменных, которые включают или отключают поведение, установите `1` или `true` для включения и `0` или `false` для отключения, в любом регистре.

  Некоторые переменные читают только то, установлены ли они вообще, поэтому любое непустое значение, включая `0`, включает поведение, а отключить поведение можно, отменив установку переменной или установив её на пустое значение. Эти переменные работают таким образом:

  * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
  * `DISABLE_TELEMETRY`
  * `DISABLE_ERROR_REPORTING`
  * `CLAUDE_CODE_TMUX_TRUECOLOR`
  * `FALLBACK_FOR_ALL_PRIMARY_MODELS`
  * `IS_DEMO`

  Одна другая переменная имеет свое собственное правило: `FORCE_HYPERLINK` читает число, поэтому только `0` отключает его. Каждая строка переменной также указывает свое собственное правило.
</Note>

<h2 id="features-that-need-feature-flag-fetching">
  Функции, требующие получения флагов функций
</h2>

Claude Code включает некоторые функции через флаги функций, которые он получает от Anthropic. Claude Code пропускает это получение в следующих сеансах:

* Сеанс, в котором вы установили `DISABLE_GROWTHBOOK`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK` или `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`; строка каждой переменной в [таблице переменных](#variables) указывает, какие значения отключают получение
* Сеанс на [поставщике третьей стороны](/docs/ru/third-party-integrations), таком как Amazon Bedrock, Claude Platform на AWS, Agent Platform Google Cloud или Microsoft Foundry, если только платформа-хост, встраивающая Claude Code, не установит `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
* Сеанс [шлюза приложений Claude](/docs/ru/claude-apps-gateway)

Когда получение отключено, вы не можете:

* [Запускать сеансы в режиме auto по умолчанию](/docs/ru/permission-modes#which-mode-a-session-starts-in) на планах Pro, Max и Team
* Иметь расширение VS Code [читающее файлы параметров для режима разрешений при запуске](/docs/ru/permission-modes#switch-permission-modes)
* Запускать [`/auto-mode-setup`](/docs/ru/auto-mode-config#generate-environment-entries) для создания записей `autoMode.environment`
* Использовать [Remote Control](/docs/ru/remote-control#requirements)
* [Отправлять сообщения сеансам за пределами этой машины](/docs/ru/cross-session-messaging#message-sessions-on-other-machines); обмен сообщениями между сеансами на этой машине работает с отключённым получением
* Запускать [`claude import` или команду `/import`](/docs/ru/cli-reference#cli-commands)
* Запускать [`/skill-doctor`](/docs/ru/skills#find-unused-skills) или открывать его отчёт на вкладке **Stats** в `/plugin`
* Синхронизировать [skills](/docs/ru/skills#where-synced-skills-load) и [plugins](/docs/ru/plugins-reference#synced-plugins), включённые для вашей учётной записи claude.ai, в сеансы терминала
* Использовать [инструмент советника](/docs/ru/advisor#requirements)
* Читать или отвечать на [комментарии к артефакту](/docs/ru/artifacts#collect-comments-on-an-artifact)
* Иметь Claude Code, зондирующий серверы соединителя claude.ai для [MCP протокола версии 2026-07-28](/docs/ru/mcp#mcp-client-runtimes), если вы не установите `MCP_PROTOCOL_NEGOTIATION=auto`
* Получить [инструмент PowerShell](/docs/ru/tools-reference#powershell-tool) по умолчанию для учётных записей claude.ai и Console на Windows с установленным Git Bash; Claude Code маршрутизирует команды оболочки через Git Bash, если вы не установите `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`. На Windows без Git Bash инструмент остаётся включённым
* Получить [отзыв, составленный Claude](/docs/ru/tools-reference#sendfeedback-tool-behavior), который Claude Code включает через полученный флаг
* Иметь Claude [обрабатывающий большие вставки как вставленный, а не введённый текст](/docs/ru/terminal-config#how-claude-treats-pasted-text); содержимое за заполнителем `[Pasted text #N]` достигает Claude без отметки
* Иметь Claude Code [исключающий инструменты MCP, чья схема входных данных будет отклонена API](/docs/ru/mcp#tools-with-invalid-input-schemas); он отправляет схему в любом случае, и запрос, который её включает, завершается с ошибкой [400, указывающей инструмент по его позиции](/docs/ru/errors#tool-input-schema-is-invalid)

<h3 id="first-session-after-an-install-or-upgrade">
  Первый сеанс после установки или обновления
</h3>

В вашем первом сеансе после установки Claude Code или обновления до версии, которая добавляет функцию, [функция с флагом](#features-that-need-feature-flag-fetching) может отсутствовать, и сеанс может запуститься в режиме Manual на плане, который в противном случае запускается в режиме auto. Claude Code получает флаги во время этого сеанса, поэтому оба они присутствуют в вашем следующем сеансе.

После свежей установки в неинтерактивном сеансе, таком как `claude -p`, Agent SDK или расширение VS Code, Claude Code всё ещё может получить флаги перед тем, как он [выбирает режим разрешений при запуске](/docs/ru/permission-modes#which-mode-a-session-starts-in).
