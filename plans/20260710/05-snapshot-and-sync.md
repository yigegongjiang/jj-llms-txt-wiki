# 阶段 5：快照提交与多站点同步

## 目标

将抓取结果接入完整快照事务，实现 README 规定的全部/指定站点同步、CLI 临时覆盖、旧文件清理、失败保留和进度输出。

## 前置状态

- 阶段 4 已通过验收。
- 单站点抓取器可将完整结果写入指定临时目录并返回分类报告。

## 行为契约

- `sync` 无站点参数时同步配置中的全部站点；有名称时只同步该站点。
- 未知站点或空站点配置返回非零，不静默成功。
- 生效顺序为 CLI 参数、配置值、内置默认值；CLI 覆盖只影响当前进程，不回写配置。
- 全部站点按配置名称排序并逐站执行；请求并发只发生在单站点内部。
- 每个站点在 `output_dir` 下创建同级临时目录，名称带站点名和随机后缀；不创建 `.cache`。
- 抓取成功且无 failure 后才提交：
  1. 将现有站点目录 rename 为同级临时备份。
  2. 将新临时目录 rename 为正式站点目录。
  3. 成功后删除备份；第二步失败则恢复备份。
- 临时目录与正式目录位于同一文件系统；正常成功或失败路径都清理临时项。
- 新快照不复制旧文件，因此远端 `404`、`410` 或不再被引用的 Markdown 会自然删除。
- 单个站点失败时保留其旧快照并继续其他站点；最终汇总存在失败时退出非零。
- `indicatif` 输出到 stderr；动态队列使用 spinner/计数，不伪造未知总量。非 TTY 时仍输出最终文本摘要。

## 实现任务

- 在 `Cargo.toml` 添加 `tempfile` 和 `indicatif`。
- 新增 `src/snapshot.rs`：
  - 在输出根目录创建站点临时目录。
  - 提交、回滚、清理和错误上下文。
  - 仅操作当前站点的正式/临时目录。
- 新增 `src/progress.rs`，将抓取事件转换为进度显示；抓取器不直接依赖终端。
- 新增 `src/sync.rs`：
  - 解析目标站点集合和有效抓取参数。
  - 逐站调用 crawler 和 snapshot。
  - 汇总成功/失败并映射进程退出码。
- 将阶段 4 的单站点临时 CLI 收敛为最终接口：

```text
llms-wiki sync [SITE] [--concurrency <N>] [--interval <DURATION>]
```

- 确保输出根目录与站点目录按需创建，且站点名已经过阶段 2 校验。

## 测试

- 首次同步创建站点目录。
- 第二次同步替换内容并删除已失联、`404`、`410` 和不再引用的文件。
- `429`、`5xx`、超时或写入失败后旧快照逐字节不变。
- 模拟第二次 rename 失败，确认旧目录恢复且无正常错误路径的临时项残留。
- 同步全部站点时，一个成功、一个失败：成功站点更新，失败站点保留，进程非零。
- 指定站点只触碰对应目录。
- CLI override 生效但配置文件字节不变。
- 输出根目录不存在、路径不可写、正式目录不是目录等错误。
- 成功和失败后均不存在 `.cache`。
- TTY 和非 TTY 的最终摘要不丢失站点名及计数。

## 验收

```bash
llms-wiki sync
llms-wiki sync anthropic
llms-wiki sync --concurrency 2 --interval 1s
```

- 三种 README 命令形式均按契约执行。
- 输出目录严格保持 `<output_dir>/<site>/<URL path>`。
- 成功同步后目录是本次完整快照，不含旧文件。
- 失败同步后旧完整快照仍可用。
- 正常返回后输出根目录仅有正式站点目录，不含 `.cache` 或临时目录。
- 全局质量门槛通过。

## 本阶段不做

- 不提供跨站点原子事务。
- 不并行同步多个站点。
- 不保留历史快照、持久化队列或缓存。
- 不增加 TUI。
