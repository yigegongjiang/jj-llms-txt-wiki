# 平台介绍与常见问题解答 (FAQ)
欢迎使用商米 **TMS (Terminal Management System，终端管理系统)** 私有化部署指南。本篇文档旨在帮助系统管理员和技术支持人员了解 TMS 系统的整体架构、运行要求以及在部署过程中最常遇到的技术问题与解决方案。
* * *
## 1. 什么是商米 TMS？
**TMS (Terminal Management System)** 是商米为合作伙伴和企业客户提供的 **POS 终端及商米智能设备私有化管理平台** 。它继承了商米云端管理平台的核心技术能力，让您能够在企业自身的私有网络或专属云服务器上，对所有的商米设备进行完全自主的安全管理。
### 1.1 核心服务组件说明
商米 TMS 的整体运行依赖以下几个关键组件协同工作：
  * **TMS Web 平台** ：企业管理员的操作后台，用于应用分发、OTA 升级、设备监控与配置下发等。
  * **TMS API 服务** ：处理业务逻辑的核心接口服务，包括终端接入鉴权、应用商店接口、日志收集等。
  * **EMQX 消息队列** ：高并发的 MQTT 消息中间件，专用于维持商米设备与后台之间的加密长连接及实时指令下发。
  * **数据库与缓存（MySQL & Redis）**：用于持久化存储设备状态、配置数据及系统日志，以及快速缓存会话信息。
  * **WebRTC 控制服务 (coturn)** ：为商米特有的远程控制、设备协助功能提供 STUN/TURN 穿透和音视频数据流转发。

## 2. 常见问题解答 (FAQ)
### 2.1 基础架构与环境准备
#### Q：推荐在哪些操作系统上部署 TMS？需要做哪些基础配置？
**A** ：为了保证 TMS 系统在高并发和长期运行下的稳定性，我们推荐使用以下环境：
  * **推荐操作系统** ：**Ubuntu 20.04/22.04 LTS** (官方验证且推荐)，也支持 CentOS 7/8、RedHat 7/8。
  * **系统内核调优要求** ：由于 EMQX 和 WebRTC 的并发长连接数较高，您**必须** 在部署前调优系统的最大文件打开数限制（`nofile` 改为 `65535` 以上），并开启 Linux 内核的 IP 转发功能（`ip_forward`）。具体配置脚本请参考[环境准备与单机服务部署](https://docs.sunmi.com/zh-CN/cicmeghjk546/xzzmeghjk546)。


#### Q：云端部署与物理机房部署在文件存储上有何区别？
**A** ：在集群部署（高可用）模式下，各台服务器的 TMS 容器需要访问相同的物理磁盘，以确保 `apk` 软件包、`ota` 升级包等上传资源的一致性。
  * **物理机房（私有化部署）** ：通常需要由您自主搭建并配置 **NFS** 共享服务器（服务端与客户端挂载）。
  * **云服务器（AWS、阿里云、腾讯云等）** ：我们**强烈推荐直接使用云服务商提供的共享文件存储服务** （如 AWS EFS、阿里云 NAS、腾讯云 CFS）。这无需手动维护复杂的 NFS 服务，且天生具备高可用、易扩容的特性。详情请参见[集群高可用部署方案](https://docs.sunmi.com/zh-CN/cicmeghjk546/xzzreghjk568)。


* * *
### 2.2 数据库与数据存储
#### Q：数据库和缓存是否支持 PaaS 云服务？
**A** ：**完全支持** 。在生产环境中部署时，我们强烈推荐使用云厂商提供的托管型 PaaS 数据库及缓存服务（例如：阿里云 RDS MySQL / Redis，AWS RDS / ElastiCache）：
  * **MySQL 要求** ：版本建议为 **8.0.x** （或 5.7.x 版本），必须提前创建好 `cpt_tms` 数据库。
  * **Redis 要求** ：版本建议为 **6.x** 或更高，支持单机、主从或哨兵/集群模式。
  * **协助部署准备** ：如果商米技术人员需要远程协助您导入 `tms.sql` 初始化结构，请提前准备好相关的连接地址、端口、账户密码，并确保这些服务允许来自 TMS 宿主机的网络访问。


* * *
### 2.3 域名、证书与安全网络
#### Q：部署 TMS 必须准备域名和 HTTPS 证书吗？
**A** ：**是的** 。为了保障金融设备和系统交互的绝对安全，商米设备在与后台通信时，强制要求采用 HTTPS 加密接口以及 MQTT (MQTTS/SSL 8883 端口) 加密长连接。 因此，您必须提前准备好用于配置 SSL 证书的证书文件（可为多域名单证书，或单域名通配符证书）。
#### Q：如果无法申请很多个子域名该怎么办？
**A** ：标准的域名方案要求如下四个独立的子域名：
  1. **Web 平台** ：`tms.example.com`
  2. **API 服务** ：`tms-api.example.com`
  3. **EMQX 长连接** ：`tms-emqx.example.com`
  4. **远程控制 (WebRTC)** ：`tms-webrtc.example.com`


**单域名方案** ： 如果您不便申请多个子域名，可以使用 **同一个主域名** （如 `tms.example.com`），配合不同的端口（如 443、8088、18083）来区分不同的服务。详情请参考[Nginx 负载均衡配置](https://docs.sunmi.com/zh-CN/cicmeghjk546/xzzieghjk579)中的单域名选配方案。
#### Q：为什么远程协助 (WebRTC) 服务需要单独设置，并且配置要求高？
**A** ：远程桌面控制基于 WebRTC 技术。为了使不在同一局域网下的终端设备与控制台建立点对点连接，必须通过 STUN/TURN（即 coturn 服务）进行穿透或中转数据。 这要求服务器对外开放 `3478` 端口的 **TCP 与 UDP 监听** 。如果网络防火墙限制了 UDP 通信，远程控制功能可能无法正常使用。

### 2.4 运维管理与常见报错
#### Q：启动 EMQX 时容器报错 `emqx kernel pid terminated` 并自动退出，如何处理？
**A** ：这通常是因为宿主机的主机名（Hostname）不合法或设置成了 `localhost`。EMQX 在启动时会根据主机名创建 Erlang 节点。如果遇到该报错，请将宿主机的主机名更改为其他非 `localhost` 的合法名称，然后重新启动 EMQX 容器。
#### Q：部署后启动时发现 Docker 网段与局域网/内网网段冲突，如何解决？
**A** ：Docker 默认的 Bridge 网桥网段（`172.17.x.x` 或 `172.18.x.x`）可能会与您企业内部的局域网网段重叠，导致网络路由异常。 您可以通过修改 `/etc/docker/daemon.json` 中的 `bip` 配置来改变默认网桥的子网。具体的修复方法可以参考[常见问题与故障排查](https://docs.sunmi.com/zh-CN/cicmeghjk546/xzrqeghjk513)。
#### Q：如何验证部署是否成功？怎样测试长连接加密证书是否生效？
**A** ：
  * **平台验证** ：在外部浏览器输入配置 of Web 访问域名，若能正常打开 TMS 登录界面，表明前端和通用 API 部署成功。
  * **长连接证书验证** ：我们推荐使用 Linux 命令行工具 `mosquitto_sub` 或图形化测试客户端 **MQTT X** ，指定证书并尝试通过 8883 端口订阅主题。详细测试指令见[部署验证与连接测试](https://docs.sunmi.com/zh-CN/cicmeghjk546/xzzzeghjk557)。
